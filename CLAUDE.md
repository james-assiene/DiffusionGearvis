# CLAUDE.md — local_astra

An on-device voice-and-vision assistant inspired by research demos like Google's Project Astra: DiffusionGemma on vLLM (RTX 5090) + Kyutai STT + Pocket TTS (CPU) + screen/camera perception (browser tab in v1, native daemon later) + memory-lite (SQLite+FTS5), orchestrated by the Conductor (replaces Unmute's handler; design derived from Unmute, no code copied; thinking always on; two output channels: spoken + an A2UI generative-UI surface; pixel-first perception; a denoising view fed by the vLLM plugin's per-step tap). Design lives in `docs/01-design.md`, architecture in `docs/02-architecture.md`, tests in `docs/03-test-plan.md`. **Read the doc for the component you touch before touching it.**

## How work happens here (non-negotiable)

Every feature and non-trivial fix goes through **planner → test-author → implementer → reviewer → verifier**, as separate agents with fresh context (`.claude/agents/`). Nothing is committed on "tests pass" — that is the implementer's claim; the reviewer and verifier decide whether it means anything. The full protocol is `docs/09-agent-workflow.md`; the skills `/plan`, `/implement`, `/review`, `/verify` run it. Skip the protocol only for typos, comments, renames and mechanical refactors with no behavioural change. If unsure whether something qualifies, it does not.

- One task per branch (`git switch -c T-NNNN-<slug>`; hooks read the task id from the branch name). Tasks live in `docs/tasks/<id>.md` with acceptance criteria and the files they own. Two agents never edit the same file concurrently.
- Tests are written by the test-author from the task's acceptance criteria before implementation exists. **The implementer never edits `tests/`** (enforced by hook). If a test looks wrong, say so to the reviewer; do not work around it.
- Show evidence, not claims: paste the test command and its output in every report. A report without command output is incomplete.
- Any command that spends GPU time or writes to `artifacts/` is reviewed (`/launch`) **before** it runs, and never runs against a dirty tree.
- Bugs that escape become, in this order: a failing test, an eval case in `tests/eval/`, and — if systemic — a line in `.claude/rules/` or a hook. Fix the spec/task too (see `docs/09`).
- After two failed corrections in a session, stop and `/clear`; rewrite the task instead of stacking fixes.

Pending tests: a test marked `pending(task="T-NNNN")` is the acceptance test of a task that is not implemented yet; the suite runs it as strict xfail (so it stays green, and a stub that accidentally satisfies it fails loudly). The test-author removes the marker when `/implement T-NNNN` starts. Never add `pending` to make a red test green.

## Project rules that are not derivable from the code

- Python ≥ 3.11, `uv`, `ruff`, `mypy --strict` on `local_astra/` (the plugin under `plugin/` is excluded: it runs inside the vLLM container). Pydantic v2 for every contract in `local_astra/contracts/`; wire formats are documented in `docs/02-architecture.md` §5 and changing one means changing the fake in `tests/fakes/` in the same PR. Service interfaces are the `runtime_checkable` protocols in `contracts/protocols.py`.
- The turn machine (`conductor/turn_machine.py`) is pure: `step(state, event) -> (state, commands)`, time arrives as `Tick` events. No I/O, no clocks, no asyncio in that module. Invariants in `docs/02-architecture.md` §4 are Hypothesis properties; never weaken them to make a test pass.
- Never voice text the LLM has not committed (diffusion drafts can change) and never voice a canvas that ends inside an unclosed thought. Never store assistant *thinking* in history; store only what was spoken.
- Fixed pre-rendered clips are system audio, not LLM text, and they never enter history (James, 2026-10-28; T-0178, T-0179, T-0182). These are the honest-ending clips `out_of_steps`, `not_finished` and `lost_thread`, and `still_working` only during long live tool loops. The filler clips `ack` and `hmm` are off by default.
- Pixel-first: the model sees pixels by default; DOM/PDF-text/cells/accessibility assists are HUD checkboxes, off unless the user turns them on, and every turn logs which were on. The shown channel is an A2UI v0.9.1 surface validated before rendering; the denoising view shows the real per-step canvases from the plugin tap, never a fake trajectory presented as real.
- All services bind to loopback only. A test asserts zero non-loopback sockets; do not add network calls. **Scoped exception, web search (James, 2026-10-26/27; T-0111b, T-0125):** only `local_astra/search/ddgs_backend.py` may open an outbound connection, in-process, through the pinned `ddgs` package. It may reach only the search hosts of its keyless `ENGINES` (duckduckgo, then brave, then mojeek; `ALLOWED_HOSTS`), never following a redirect, and never behind a proxy. Search is **on by default in `--tools live`** (`--search off` turns it off), and in dry-run only with `--search ddgs`. Only `cli._search_backend` constructs it, once per process. `tests/unit/test_search_egress_scope.py` fences it, and `make search-live` (opt-in, `ASTRA_LIVE_SEARCH=1`, needs network and `strace`) audits its connects. Results are untrusted text, and the injection risk is stated, not solved. **Brave Search API fallback (James, 2026-10-27; T-0163):** only if `~/.config/diffusion_gearvis/brave_api_key` is a regular file (not a symlink) owned by the user with no group or other permissions, holding one key, `local_astra/search/brave_api.py` may also connect, in-process through `httpx`, to `https://api.search.brave.com` only, and only after every keyless engine has refused a search; never following a redirect, never behind a proxy; the key goes only in the `X-Subscription-Token` header and is never printed or logged (logs say "configured" or "not configured"). A file that fails these checks gives one stderr line and search stays keyless. **Scoped exception, web (T-0160, James 2026-10-26):** in a live session (unless `--no-web`), the agent browser's own page traffic may reach public `https` hosts on port 443, only through the session's egress proxy (`local_astra/computer/egress_proxy.py`, bound to 127.0.0.1). The proxy resolves each host once and refuses loopback (other than the start-page origin), private, link-local, CGNAT, multicast, reserved and documentation addresses, every other port, and plain `http`. No service binds beyond loopback. `off`, `dry_run`, live with `--no-web`, and the fast suite never touch the network through this path.
- Versions of vLLM, torch, CUDA, driver, moshi-server and the Gemma 4 chat template are pinned in `services/versions.lock`. Changing one is its own task with a bench run.
- Latency, VRAM and duplex budgets (`docs/01-design.md` §8–9, `docs/03` §7) are tests. A regression > 10 % fails CI; do not raise a threshold without a `docs/tasks/` entry explaining why.
- State the whole regime beside every number you report (profile, canvas length, steps, model versions, headset vs speakers, n, seed).

## Observed mistakes (curated; add via PR, keep short; details live in `.claude/rules/`)

- Measuring latency while another agent edits `local_astra/` → unattributable numbers. `git status` clean first.
- Asserting `Σ p == 1` style tautologies in tests → vacuous. The reviewer mutation-tests for this.
- Quoting a number without its regime (profile, canvas, versions, n, seed) → cannot be compared later.
- Toggling thinking per request → the whole prefix cache misses (`<|think|>` is the first system token).
- Gating on a spoken prefix before every tool call → the wrong target for routine steps (H-T104, docs/01 D16).
