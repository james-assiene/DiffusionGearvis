## Goal

`uv run diffusion_gearvis session` (any `--tools` mode) serves the HUD page itself and prints the paste-ready URL.

Confirmed in source at 611068bb: `--serve-hud` is a `store_true` flag, default off (`cli.py` 3341-3345); a real start binds only with it (2964-2973) through `serve_hud(services)` (613-630); a taken port prints `astra hud: cannot bind …` and **exits the session with 1**, closing the search backend first (T-0125 amendment 4 (c)); `--dry-run` prints `astra session: the HUD page would be served at <url>` as its last line only with the flag (2929-2930); `hud_static.HudStaticServer` binds `127.0.0.1` only; the `hud` subcommand (3370-3371, 633-647) is separate.

After this task the session serves the page unless `--no-serve-hud`; `--serve-hud` still parses and does nothing more; a busy HUD port prints one line and the session runs on.

## Acceptance criteria

1. **Default on, every mode.** A real `session` start with neither flag binds one HUD static server through the single `HudStaticServer(hud_static.HUD_DIR, services.hud_port)` site, in tools `off`, `dry_run`, `live` (web and `--no-web`), with and without `--silent`/`--no-mic`, and prints exactly once on stdout `astra session: the HUD page is at <hud_static.page_urls(services)[0]>` (the full `http://127.0.0.1:<hud_port>/?ws=ws://127.0.0.1:<conductor_port>/v1/realtime`).
2. **Placement.** At a real start the HUD line (stdout, or criterion 5's stderr line) is the first start-up line after `astra session: regime: …`; the bind still happens before the regime line. Under `--dry-run`, `astra session: the HUD page would be served at <url>` is printed exactly once, as the last stdout line.
3. **Opt-out.** `--no-serve-hud` constructs no `HudStaticServer` and prints no HUD line (real start and `--dry-run`). Negative: with `--no-serve-hud`, stdout, stderr, exit code, the described `Session` keywords and the number of graphs built are byte-identical to BASE with neither flag, for every row of the existing differentials.
4. **Compatibility.** `--serve-hud` is accepted alone or with any flag and behaves like no flag; both flags → last wins (`BooleanOptionalAction`), never a usage error; `--help` names both, default on.
5. **Busy port never ends the session.** If constructing the server raises `OSError`, the session prints exactly one stderr line starting `astra session: `, naming `127.0.0.1:<hud_port>`, saying the port is in use, that if a Gearvis HUD is serving there the page is at `<url>` (full URL), and that the session continues without its own HUD server; it continues; exit code unchanged by the HUD; no traceback; no retry and no other port (T-0028 criterion 19 kept); the search backend is **not** closed. Spec change superseding T-0125 amendment 4 (c) / reviewer A's "static server failure exits with its code" row.
6. **Lifetime.** The served HUD lives for the session and is closed on every exit (normal return, Ctrl-C (T-0040), start-up failure after the bind, e.g. T-0111g B5); afterwards `hud_port` is free; on the busy path nothing is closed or touched.
7. **Loopback only (negative).** The only new listener is `127.0.0.1:<hud_port>`; `test_session_no_egress.py`, `test_hud_server_no_egress.py` and doctor `net.loopback` stay green unchanged; no browser opened; no outbound connection; no probe of the busy port.
8. **`hud` subcommand unchanged (negative):** same URLs, messages and exit codes as BASE, including exit 1 with `astra hud: cannot bind …`.
9. **One construction site (negative).** `test_hud_static.py::test_the_cli_builds_the_server_with_the_shipped_default` stays green unchanged.
10. **Docs.** `README.md`'s "Then start a session and serve the page" block shows `uv run diffusion_gearvis session` (no `--serve-hud`), names `--no-serve-hud`, and says a busy 1420 is reported and the session keeps running. docs/02 §9's port-table row (line ~493) becomes "served by `session` by default (`--no-serve-hud`), or `hud`" — orchestrator at merge.
