**The protocol is not skippable.** The diff is not one sentence: it changes the text of every prompt the assistant sends, it adds a schema migration to a database that exists on the human's disk with real rows in it, and the failure being fixed is the assistant making a false claim about the present.

## Goal

The human opened a fresh session, shared nothing, and asked "Make a flat looking UI." The prompt that reached the engine contained two messages: the system message, and one user message consisting of a `[memory]` block of three captions followed by the request. **There was no image in the prompt at all** — zero `ImagePart`s — and the three captions had been written by the captioner during earlier conversations about a calculus textbook the human had shared roughly an hour before. The model's own thought begins: *"The user wants a 'flat looking UI' based on the provided screenshots of a calculus textbook page"* — it read a recollection as a provided screenshot, because in the prompt the two are typographically identical: a bare caption line under a bare header, in the user message, where current context lives. It then built a surface about vector calculus and said aloud *"I have organized the key concepts from the calculus problems into this flat list for you."* Nothing of the sort was on screen. After this task, a remembered thing is marked as remembered — labelled, dated, and stated in the prompt to be a recollection and not the current screen — a prompt with no image in it says plainly that nothing is visible and what to do about that, and a query that matches the store only through a word like "a" recalls nothing at all. Cross-session recall is **kept**: it is G4, S4 and E4, and the product is meant to be usable the next morning. What is removed is the ambiguity, not the memory.

### Design questions, answered (these are the rulings the implementer works to)

**D1 — scope: relevance and age, not the session.** Recall stays cross-session. Scoping it to the session would delete the Astra moment ("what time was that flight", asked twenty minutes later, docs/01 S4 / docs/03 E4) and would not have prevented tonight's failure anyway — an in-session caption presented as present perception is the same lie. Three bounds instead, in order of how much they contribute: (i) **relevance** — the store must not return a hit whose only matched term is one that nearly every episode matches (group B; today the failing query scored `0.0` and was ranked purely by recency, i.e. `search` degenerated to "the three newest episodes"); (ii) **age, shown** — every surviving hit carries its age in the prompt (group A/C); (iii) **session identity, recorded** — an episode remembers which session it was captured in, so "earlier in this conversation" and "in an earlier conversation" can be told apart (group B writes the column, C uses it). A hard recency cutoff is deliberately *not* added: retention (docs/02 §2.6, 7 days) already bounds the store, and a cutoff that hides a relevant memory is a silent failure where a dated one is an honest answer. The cutoff number is ambiguity Q2 for the human.

**D2 — marking: label at read time, in the prompt, structurally.** Each recollection line carries (a) an age, (b) a marker naming it as something seen earlier and not now, under (c) a block header that states the same thing in a sentence. Rewriting captions in the past tense **at write time** is rejected as the primary mechanism, and the reasons are worth keeping: it cannot fix the three captions already in the human's database, it depends on a generative model complying with a style instruction (unverifiable in the fast suite, a `/launch` to check), and it puts the safety property in the place where it cannot be tested cheaply. Read-time labelling is deterministic, applies retroactively to every row already stored, and is pinned by unit rows. The captioner prompt may still be revised later; it is a non-goal here (Q3).

**D3 — no current frame: say so, do not suppress.** Suppressing recall when nothing is visible would turn off memory in exactly the situation it exists for — the user asking about something that is *not* on screen. The prompt instead states, in the user turn, that no screen or camera image is attached to this turn and that the model cannot see anything right now. Group A derives this from the prompt itself (no `ImagePart` anywhere), which needs no clock and no call-site change, so it ships without waiting for `session.py`.

**D4 — constraining the answer: the minimum belongs here, the tuning does not.** One sentence, emitted with the no-image statement, telling the model to say it cannot see and not to describe a recollection as if it were on screen. It belongs here because you cannot state "nothing is visible" without saying what follows from it, and because it is query-dependent (it must appear only on the turns where it is true). Everything broader — wording in the system prefix, a bluffing eval, the Q8 "refusal to bluff" rubric — is a different task and must not be done here: the system prefix is the prefix-cached block T-0044 owns and is still owed a token count under `/launch`.

### Group A — the prompt cannot present a recollection as sight

1. **The origin turn, rebuilt, no longer reads as perception.** Given exactly the inputs of turn `t1` — `history=()`, `frame=None`, all assists off, `transcript="Make a flat looking UI."`, and the three origin-fixture hits — `PromptBuilder.full(...)` returns a prompt in which: (a) there are **zero** `ImagePart`s; (b) an explicit no-image statement appears in the user message *before* the recollection block, naming that no screen or camera image is attached to this turn; (c) **every** caption line begins with the recollection marker constant; (d) the block header is a sentence stating these are things seen earlier and not the current screen. Asserted on the exact text of the parts, not on a substring of the whole prompt. *(Reproduces the origin; docs/01 §"Answer what you can actually see"; `.claude/rules/conductor.md` — the model is never given a claim it cannot support.)*
2. **The no-image statement appears exactly when it is true — both directions pinned.** Four rows, each asserting presence *and* absence of the constant: (i) a current frame attached → **absent**; (ii) `frame=None` but a history frame resolved to pixels → **absent**; (iii) `frame=None`, history present only as caption lines → **present**; (iv) `frame=None`, no history → **present**. *(A guard needs a row for being too wide as well as one for being absent — `.claude/rules/tests.md`. Too wide here means the assistant tells a human who is sharing their screen that it cannot see: strictly worse than the bug being fixed, and row (i)/(ii) are what find it.)*
3. **The recollection block is framed and marked, or it is not there.** With ≥ 1 hit: header sentence present, every line marked. With 0 hits: no header, no marker, no blank block — `full()`'s text parts are exactly what they are today minus the memory part. The header, the line marker and the no-image statement are **module-level named constants** that the tests read; no literal is buried in an f-string that a test copies. *(Nothing outside `prompt_builder.py` reads `MEMORY_HEADER` today — verified by grep over `local_astra/` and `tests/` — so it may be renamed.)*
4. **Age is carried as an argument and rendered by a pure function.** `full()` and `fit()` accept a keyword-only `now_ms: int | None = None`, threaded to the block builder. A pure `relative_age(ts_ms, now_ms)` renders a human phrase with **hand-computed boundary rows**: below 60 s, minutes, hours, "yesterday", days. `prompt_builder.py` imports no clock (criterion 11).
5. **An unknown age says unknown, and never implies recency.** With `now_ms=None` every line carries a phrase meaning *earlier, time not known* — not "just now", not an omitted slot that leaves the line looking current. *(This is the state production is in until group C wires the clock, so it is the state the human will actually see first; it must be honest on its own.)*
6. **A future or negative age cannot render.** An episode whose `ts_ms` is greater than `now_ms` (clock skew, a replayed log) renders as the "just now"/unknown phrase, never "−3 minutes ago" and never a raised exception. *(Adversarial; the most likely crash-in-front-of-the-human in this diff.)*
7. **The order and the seam are unchanged.** The suffix order is: no-image statement (when emitted) → TutorState → recollections → assists → transcript; `prefix_len` is unchanged; `prefix.shares_prefix_with(full)` still holds; the recollection block is still after the pixels and before the transcript (T-0020 ruling A1, `tests/unit/test_prompt_budget.py::test_the_memory_block_goes_after_the_pixels_and_before_the_history_text` stays green).
8. **The framing is spent with the thing it frames.** When `fit()` drops the last memory hit, the header, the marker and every line disappear together — no orphan header, no "recollections:" with nothing under it — and `trimmed["memory_hits"]` is unchanged in meaning. The no-image statement is part of the current turn and is **never** spent. *(T-0020 ruling A1, rung 2.)*
9. **The added text is bounded.** The no-image block ≤ 240 code points and the per-line marker ≤ 48 code points, asserted numerically against the constants, so a turn with three hits adds under ~400 code points to a 14 336-token budget. *(Structural bound, explicitly **not** a token claim — T-0044 ruling A2's distinction.)*

### Group B — the store does not recall on a stopword

12. **The failing query recalls nothing.** With the origin fixture ingested, `search(MemoryQuery(text="Make a flat looking UI."))` returns `[]`. 14. **The rule is document-frequency-based and corpus-size independent.** The same rejected query is rejected at corpus sizes 3 and 400, and the same accepted query is accepted at both. ## Implementation notes

- **`prompt_builder.py` is pure and must stay so** (its own docstring, `.claude/rules/conductor.md`): no clock, no I/O, no per-call state. `now_ms` arrives as an argument; `relative_age` is a function of two integers. The prefill prefix and the final request's prefix must stay byte-identical — everything this task adds lives in the **query-dependent suffix**, after the image, so prefix caching is untouched (D9, B11). Do **not** put any of this in `system_message()`: that is the cached block T-0044 owns and still owes a token count for.
- **The "can it see" predicate.** Group A derives it from the assembled prompt (is there any `ImagePart` in any message?) rather than from `frame is not None`, on purpose: `_assemble` legitimately omits the current frame's pixels when they already ride on the newest history image (D9/B9), so `frame is not None` and "there are pixels in this prompt" are different questions, and only the second one is answerable inside this module. The conservative consequence — with a history image but no current frame the prompt says nothing rather than saying how old that image is — is criterion 22, group C's.
- **Thumbnails are the next version of this bug, not a fix for it.** D8 says the top-3 JPEGs are attached so the model re-reads them; T-0005 amendment B4 deferred that and it is still deferred. When it lands, three unlabelled images of a calculus textbook will sit in the user turn next to the current frame and the marking done here will be worthless unless each thumbnail carries its own adjacent age-and-recollection text part. Say so in the follow-up; criterion 11 pins that this task adds none.
- **bm25 and IDF.** FTS5's bm25 computes `log((N-n+0.5)/(n+0.5))` per term and clamps a non-positive result to ~0, so a term present in every document contributes nothing and, in a small corpus, *all* hits score exactly `0.0` — which is what happened: ranking fell through to the recency tie-break and `search` returned the three newest episodes for a query about a flat UI. A raw score floor is therefore corpus-size dependent (criterion 14). `fts5vocab` (`'row'` type: term, doc count) over `episodes_fts` gives post-stemming document frequencies in one query and is the obvious tool; the implementer chooses. Whatever the rule, it must not become a hardcoded English stop list — the tokenizer is `porter unicode61` and the design is not English-only.
- **The query text is a spoken transcript, never FTS syntax** (store docstring). Any new expression building goes through `_match_expression`'s quoting; a document-frequency probe must quote its term the same way.
- **The migration.** The store opens in WAL with `busy_timeout=250`; run the migration inside `__init__` in one transaction, guarded by `PRAGMA user_version`, before the first query. The ingest hot path (0.015 ms median, measured T-0009) is on the reflex lane's 20 ms budget — do not add per-ingest work.
- **Illustrative shape only** — the implementer chooses the words, the tests pin the constants, not this prose:
  ```
  [screen]
  No screen or camera image is attached to this turn: you cannot see anything right now. If you
  are asked what you see, say that nothing is being shared. Never describe anything below as if
  it were on the screen.

  [recollections — things seen in earlier moments, not the current screen]
  - about an hour ago: a screenshot of a page from a calculus textbook …
  ```
