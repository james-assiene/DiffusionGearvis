## Goal

`tests/unit/test_session_reground_budget.py::test_equal_budget_identical_to_group_a` (T-0132 B6) fails about 2 % of the time on an idle box and about 7 % under heavy load, at every worker count.

**Root cause (planner, reproduced at f34a09c; the files involved are identical to main a58e343):**
- The only values that differ are `log[87].data.session_log` (a `turn.record`) and `records[0].session_log`. The turn line names its session log file, and `SessionLog._pick_path` names that file `YYYYMMDD-HHMMSS-<pid>.jsonl` from `datetime.now()` (`local_astra/telemetry/session_log.py:303`).
- The two runs, `plain` and `same`, are about 50 ms apart. When they fall on either side of a wall-clock second, the file names differ. Under load the runs take longer, so this happens more often.
- `_normalised` masks the run directory, so the path becomes `<run>/logs/<timestamp>-<pid>.jsonl`, but the timestamp stays.
- T-0143 reviewer B's attribution to `stt_frames_fed` is refuted. The capture pump is on the `ScriptedClock` (`FakeAudioIO._cap_produce`). The value was 43 in both runs in every forced-straddle repetition, and no diff touched it in 450 repetitions.

After this task:
- The row masks exactly each run's own log path, as `test_session_tools_off_golden.normalise` already does for the golden and differential rows (`<log>`).
- It proves that the masked string is the run's own log path.
- It stays deterministic under any load.
- It keeps every other byte compared, B5's keys and the capture counters included.

The product's log naming is not a bug: two sessions in one second and one directory get a `-2` suffix. It is not changed here.

## Acceptance criteria

1. **The row ignores which second each run started in (B6, T-0132 O-2).** With the two runs forced to have different log file names, the row passes. The forcing is checked by a premise: the two runs' log basenames differ. Before the fix the forced run fails every time (5/5 measured).
2. **The mask is exact.** `_normalised` replaces only the string `str(rig.log.path)` of the run being normalised. It does not use a regex, does not remove the `session_log` key and does not mask other paths. The replacement happens before the run-directory replacement. A premise asserts that each run's turn line `session_log` equals that run's own `str(rig.log.path)`. A second premise asserts that the token occurs in the normalised `records` and `log`, so the mask is not vacuous.
3. **The mask is not too wide** (the too-wide guard, `.claude/rules/tests.md`). A deterministic pure row checks `_normalised` on stub rigs, with no session involved:
   - The stubs differ only in the timestamp of their own log file name: equal.
   - One stub's turn line names a log path that is not its own `log.path`: not equal.
   - The stubs differ in one `stt_frames_fed` value: not equal. The capture counters stay compared.
   - The stubs differ in one request body: not equal.
4. **B6 keeps its power (negative: nothing else is normalised).** Each of the reviewer's mutations M1 to M4 below reddens the row:
   - M1, a budget or body leak, reddens `bodies` or `pass2`.
   - M2, a key added to `log` or `records` only when `reground_llm` is given, reddens `log` or `records`.
   - M3, `stt_frames_fed` moved by one only on the `same` run, reddens `records`.
   - M4, `_normalised` removing `session_log` instead of replacing the exact path, reddens criterion 3's "not its own path" case.
5. **Negative: nothing outside the owned file changes.**
   - `git diff main...HEAD --stat` lists only the owned files.
   - No `local_astra/` file changes, and the turn machine is untouched.
   - No assertion of the module is removed: `git diff main...HEAD -- tests/ | grep -E "^-[^-]" | grep assert` shows only rewrites that are at least as strict, and the module's assertion count does not fall.
   - The `distinct` half of the row (B3: an equal-budget second client is never used) is unchanged.
6. **Stability bar (the verifier).**
   - 300 consecutive green repetitions of the row under the load regime below. Before the fix: 20/300 red under that load, 3/150 red idle. P(300 green | unfixed) ≈ 1e-9.
   - 150 green idle.
   - 5/5 green with the straddle forced.
   - Three `make fast-parallel` runs, plus one serial fast-suite run, with the row green in all of them.
7. **Docstrings are accurate.** `_normalised`'s docstring states exactly what is masked: session id, run directory, the run's own log path, `git_commit`. It says that nothing else is dropped, with the wall-clock reason for the log path. The row's docstring says the same.
