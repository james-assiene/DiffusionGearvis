# T-0048 — STT latency: move Kyutai STT to the GPU (and stop the CPU backlog from growing)

**Status:** planned 2026-09-16 · **Blast radius:** high (group B touches the engine's memory budget and the audio path) · **Groups:** A (feed gating, CPU-only) · B (device + KV budget + bench, `/launch`, two reviewers) · C (profiles, doctor, docs) · **Blocked on an ownership transfer for group B — see Owned files.** **Rescoped 2026-09-16 by the T-0051 diagnosis.** (a) `local_astra/conductor/stt_client.py` passes to **T-0051 group B**. (b) **The device half is now evidenced rather than planned**: on the GPU, word delivery lag measured 874–923 ms and the end-of-turn echo **473–482 ms** against 3034 ms on the CPU, with **no backlog growth across a 787 s session** — which is the thing the feed gate was invented to prevent. What remains here is the *deliberate* device selection, the KV-pool change and the bench. (c) **Group A is narrowed and reordered**: it is the CPU-fallback insurance, it lands **after T-0051**, and it must carry a row proving the backstop still fires with the gate on — a gate that skips unvoiced audio stops the fed-audio clock, and T-0051's corrected backstop is measured in that clock, so gating could otherwise stop the endpointer firing at all. (d) Group C should additionally assert the device the profile *asks for*: tonight's recogniser came up on the GPU only because the environment variable was unset, and nothing noticed.

## Goal

Tonight (2026-09-16, human at the desk) the spoken path worked and the transcript arrived **≈ 20 s after the human stopped speaking**. The cause is not the LLM and not the network: the capture pump feeds the STT server continuously from session start (T-0032 criterion 1, required by T-0007a ruling A14 — the server echoes a `Marker` only while audio keeps arriving), the server runs at **RTF ≈ 1.3 on CPU** (100–108 ms per 80 ms audio step, 2026-09-14 audit), so its backlog grows ≈ 0.3 s per second of *session* time whether or not anybody speaks. After a minute of an open session the server is ~18 s behind, and the end-of-turn flush — the marker echo — sits behind that backlog. Measured on this box: mark() → echo **3034 ms** after only ~10 s of fed audio (census run 3). After this task the end-of-turn flush is bounded by the model, not by session age: Kyutai STT runs on the GPU (RTF ≪ 1), the engine's KV pool shrinks from 4 GiB to 2.5 GiB so that GPU STT fits above the ≥ 3 GiB sampler floor (docs/02 §7), and the capture pump feeds the server only voiced stretches plus a stated margin — so that even on the CPU fallback, and even if the GPU path regresses, the backlog cannot grow without bound. `ASTRA_STT_CPU=1` stays as the documented fallback; nothing here deletes the CPU path.

**This is not a one-sentence diff and the protocol is not skippable**: it changes the engine's memory budget, the audio feed path and a service's device, and it produces numbers that go into `PROGRESS.md` under *Runs*.

**Options assessed and rejected as the primary fix** (recorded so they are not re-litigated): (b) CPU with `batch_size 1` + pinned cores — the measured deficit is RTF 1.3, i.e. ≥ 30 % that must come out of a single-stream decode; `batch_size` 2 → 1 does not plausibly buy 30 % and the fix would be measured, not argued — kept only as part of the fallback regime in group B criterion 15; (c) a different CPU-real-time streaming recogniser (sherpa-onnx streaming zipformer, published RTF ≈ 0.1 on a desktop CPU, with its own endpointing) — a new `SttClient` implementation, its own wire format, its own endpointer, its own eval: a multi-day task, **named here as the fallback if GPU STT cannot fit** and not started; (d) other GPU streaming ASR (NVIDIA Parakeet/Canary streaming via NeMo, ~1.2 GiB — cheaper in VRAM than Kyutai's 2.5 GiB) — a later option, the right one if the KV pool cannot be shrunk without losing B11.

## Acceptance criteria

Numbered continuously across groups; a group is a branch.

### Group A — feed gating (no GPU, no VRAM change)

1. **The gate is pure.** A new module decides per capture frame whether the frame is fed to the STT client, from the frame's own samples and an explicit state, with no clock, no I/O, no asyncio and no logging side effects (`.claude/rules/conductor.md`: "reflex-lane models run on CPU threads … never block the event loop"; the same purity rule the turn machine has, docs/02 §4). The session calls it; the session does not contain the decision. *Checkable:* a unit module imports it with `time`, `asyncio` and `socket` poisoned.
2. **A silent session feeds (almost) nothing.** Over a 5-minute stream of below-threshold frames the gate emits at most `pre_roll_ms` + one frame of audio. This is the criterion that kills tonight's mechanism: fed audio, and therefore the backlog, no longer grows with session age. (Origin: PROGRESS *Decisions pending the human* — "STT on CPU cannot keep real time"; T-0007a A14.)
3. **Hold-open beats the gate, always.** While the turn is in `ENDPOINTING`, or while any marker is outstanding, or for `hangover_ms` after a voiced offset, every frame is fed regardless of voicing — T-0032 criterion 1 / T-0007a ruling A14: a pump that stops feeding never sees the flush. *Checkable as a Hypothesis property over arbitrary frame/flag sequences:* no frame is ever skipped while `hold_open` is set.
4. **Speech is not clipped.** A pre-roll ring of ≥ 300 ms is flushed ahead of the first voiced frame, and feeding continues ≥ `asr_delay_in_tokens × 80 ms (= 480 ms) + EOT_SILENCE_MS (800 ms) + margin` after the last voiced frame, so both the server's algorithmic delay and the endpointer's step-clock backstop (`reflex/turn_predictor.py`) still see the silence they need. *Checkable live (group B arms):* on the fixture utterance set, no word present in the ungated transcript is missing from the gated transcript.
5. **A backlog backstop that does not depend on the voicing decision.** The STT client exposes a truthful `stt_backlog_ms` (fed-audio clock minus the server's own position, derived from `Step.step_idx × 80 ms`, **not** from `SttStepEvent.t_ms`, which is the fed clock — see Implementation notes), and the gate closes (except under criterion 3) once the backlog exceeds a stated bound, saying so once. *Hypothesis property:* for any frame sequence and any voicing verdicts, the modelled backlog stays ≤ bound + one utterance. This is the criterion that survives the most likely failure of an RMS gate — a fan, a noisy room or a DC offset that holds the gate open for ever.
6. **Word times survive a gap.** Because skipped audio never reaches the server, the server's audio timeline and the capture clock diverge by the skipped duration. The client's `start_time`/`stop_time` mapping (`_base_ms + server_seconds`) accounts for accumulated skipped audio: after a 30 s gate-closed stretch, a word the server places at its time *X* lands at capture time *X* + 30 s. *Negative:* the session still never retimes frames (docs/02 §4 spec delta T-0021 (3)) — the correction lives in the client, which owns the mapping.
7. **The turn line says what was done.** `stt_frames_fed` (exists), `stt_frames_gated`, `stt_backlog_p95_ms`, and the gate's on/off state in the regime (CLAUDE.md: never a number without its regime).
8. **Negative for group A.** `conductor/turn_machine.py`, `reflex/turn_predictor.py`'s constants (`EOT_SILENCE_MS`, `EMA_*`, `MIN_SPEECH_MS`, `PAUSE_HEAD_INDEX`), `local_astra/bench/thresholds.py` and `tests/` selection are unchanged; `SttStepEvent.t_ms` keeps its current meaning (the fed-audio clock) — its honesty is a recorded finding, not a change here.

## Implementation notes

- **Why feeding is continuous today, and why it must stay continuous at the end of a turn.** T-0007a census runs 2 and 3: with audio stopped, the server near-stalls (it does not chew its backlog) and the `Marker` is never reached; with silence fed continuously the echo arrives when the step clock reaches the marker. T-0032 criterion 1 encodes this. The feed gate is therefore *not* "stop feeding at end of speech" — it is "do not feed the arbitrary silence between utterances"; the end of an utterance is the one place feeding must continue (criterion 3).
- **The time-base landmine.** `stt_client.py` maps word times as `_base_ms + start_time_seconds × 1000`, where `_base_ms` is the `t_ms` of the *first* fed frame. That mapping is only correct while every captured frame is fed. Skipping frames is exactly what the gate does, so without criterion 6 every word after the first gap is stamped early by the total skipped duration — and the endpointer, the turn record and B3's "last word" column all read those stamps. Do not "fix" this by feeding silence instead of skipping: feeding silence is what makes the backlog grow.
- **`SttStepEvent.t_ms` is the fed-audio clock, not the server's position** (`stt_client.py:416` stamps steps with `_audio_clock_ms`). On a backlogged server the two differ by the backlog — which is why the backlog must be derived from `Step.step_idx` (× 80 ms of audio per step; census: 90 steps for 10.4 s fed) and not from the event's own timestamp. Changing the event's meaning would move T-0032's endpointer semantics and is **out of scope**: record it as a finding in the module docstring. One existing row pins the current meaning (`tests/unit/test_stt_client.py:238`, "the fed-audio clock"); it stays green.
- **The KV arithmetic, and what may not be inferred from it.** `services/vllm.sh`'s comment block is the reference: at bf16, 25 of 30 layers are sliding-window capped at 1024, so their cost is a constant; the pool axis is linear and trustworthy (3/4/5 GiB → 1.26/1.68/2.10× at 16384), the length axis is not; the boot at 4 GiB measured **1.93× / 31,605 tokens / 26.8 GiB**. Shrinking `--max-model-len` frees **nothing** — the budget is a fixed byte count. Scaling the measured 1.93× on the pool axis gives ≈ 1.21× at 2.5 GiB; the modelled axis gives ≈ 1.05×. Both are above 1.0×, but not by much: criterion 10 exists because a pool that cannot hold one `max_model_len` sequence does not boot at all.
- **Consequence for the prefix cache, stated plainly** (criterion 16): at ≈ 1.05–1.2 full contexts, cross-turn prefix reuse is comfortable at realistic prompt sizes (a 1120-token image bucket + history + transcript is a few thousand tokens) and is tight only when the D9 anticipatory prefill and the live generate are both near the 14,336-token prompt budget (T-0020). `--max-num-seqs 3` was never backed by KV for three full-length sequences (it was 1.93 contexts at 4 GiB); it becomes ~1.1. The flag does **not** change here — changing it is a versions.lock line and a separate task.
- **Do not lower the floor.** `VRAM_FLOOR_MIB = 3 * 1024` exists because the denoising sampler transient (`canvas × vocab × fp32 × ~10`) is *not profiled by vLLM* (docs/02 §7, docs/01 §9). Every tempting shortcut in this task — "2.6 GiB free is nearly 3" — is refused by that sentence.
- **Measure with a clean tree, and only through `/launch`.** Anything under `scripts/gpu/` is GPU-spending by definition (`.claude/rules/gpu-services.md`, T-0016): the harness needs a token and a clean tree, and its run gets a *Runs* line in `PROGRESS.md`. The engine restart itself needs only a clean tree (D2), but the measurement does not.
- **Loopback only**: the STT container keeps `--network host` with the server bound to 127.0.0.1:8080, the HF cache stays mounted `:ro` (a container writing it as root is what broke pocket-tts once), and the `/logs` mount stays absolute.
- **Gate placement.** The pure decision belongs in `reflex/` (it is a reflex-lane signal); the session owns only the ring buffer, the hold-open flags and the counters. Do not put the decision inside `_pump_capture`'s loop body as an inline RMS test — criterion 1 is what makes the noisy-room behaviour testable at all.

  moshi's ~0.5 s lag means such words arrive after the gate has already shut.

- **A13 (the KV pool stays at 4 GiB for now, and the bench is rescoped — human decision 2026-09-16).** Ruling A2 had the human choosing
  2.5 GiB to make room for the recogniser on the GPU. The recogniser is now there and a full reply completed with **1.9 GiB free**, so the
  premise of the shrink is gone: nothing has demonstrated a need for it, and shrinking costs real prefix-cache headroom (about 1.9 full-length

  **But tonight does not settle it, for a reason worth stating precisely.** The orchestrator predicted an out-of-memory failure and was wrong
  for two separate reasons, only one of which is the design's. First, free device memory is **not the pool the sampler draws from**: the
  engine's 26.9 GiB is a reserved arena, and a transient is served from inside it by recycling blocks, never from the free memory outside. The
  engine had been up nine hours and had already served requests, so that arena was warm and correctly shaped. Second, the 2.5 GiB figure in
  docs/02 §7 assumes roughly **ten** simultaneous copies of a canvas-sized logits tensor; one copy is 256 × 262144 × 4 B = **0.25 GiB**, so the
  floor is ten times a number nobody has measured.
  **The untested case is a cold engine booting with the recogniser already resident** — exactly what the next restart does, and the moment the
  arena must be grown from the driver rather than recycled. The human has scheduled that test **after T-0051**.
  **So the bench changes purpose:** it was to confirm a smaller pool still boots; it should instead **measure the sampler's actual peak
  transient**, which nobody has ever done. If the real figure is two or three copies, the floor is about a gibibyte and this question closes.
  If it is ten, the pool shrinks and we will know why.

- **A14 (a row T-0048 group A's gate must keep green — from the T-0051 group A review).** The corrected backstop takes a word's arrival as
  `max(the last step's time, the word's own end)`, because a hole in the step stream otherwise makes a word look as though it arrived long ago

  note. This task's file previously recorded only the other direction — that a gate must not stop the backstop firing at all — and the review
  found the early-cut direction written nowhere a T-0048 implementer would read.
