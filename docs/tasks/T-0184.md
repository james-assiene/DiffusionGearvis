## Goal

**The problem today:**
- GenUI cards are generic A2UI trees of Text, Row and Column.
- The median card is about 344 tokens, usually two 256-token canvases.
- Every bracket is another chance for corruption.

**The change:** T-0184 adds seven **semantic components**, each with its own designed look:
- `Stat`;
- `StatTiles`;
- `Comparison`;
- `Bars`;
- `Steps`;
- `Source`;
- `Actions` (label-only buttons).

The model writes **one component holding data**, and the HUD lays it out in the approved look, in both themes. A 3-bar chart costs about 111 tokens.

**Option (a), a custom A2UI v0.9.1 catalog** (catalogId `gearvis:cards/v2`, H-T184-4):
- **Unchanged:** the gate, the wire, the CLAUDE.md rule "The shown channel is an A2UI v0.9.1 surface validated before rendering", and docs/01 D12 ("basic catalog plus our own").
- **Already wired:** `A2UIValidator(catalog=…)` and `known_catalog_ids`, and `createEngine({catalogIds})` in the HUD.
- **Why not (b):** a non-A2UI format would replace the gate and the honesty rows and change a CLAUDE.md rule, to save only about 35 tokens per card.

**Rollout:**
- The model learns the components from a second UI prompt block, no longer than today's.
- A pre-registered GPU A/B compares the two blocks.
- The default switches only on James's ruling after the A/B.

**Nothing is interactive.**

## Acceptance criteria

### Group A — the v2 catalog

**A1. The catalog file.**
- `local_astra/ui/schemas/cards_v2/catalog.json` is self-contained, with catalogId `gearvis:cards/v2`.
- `$defs/anyComponent` is a `oneOf` over every basic-catalog component, copied verbatim, plus the seven v2 kinds.
- Each v2 kind has `unevaluatedProperties: false`.
- Refs are local, or into `common_types.json`, so `fixer_schema.components_array_schema` derives a salvage schema.
- A drift row pins the copied basic definitions as JSON-equal to `schemas/a2ui_v0_9_1/catalog.json`.

**A2. The seven kinds.** All strings are the model's own. There are no URLs, path bindings or function calls.

| Kind | Required | Optional |
|---|---|---|
| `Stat` | `label`, `value` | `detail`; `icon` ∈ {sun, partlyCloudy, cloud, rain, storm, snow, fog, wind, night} |
| `StatTiles` | `tiles` ≥ 1 of `{title, value}` | per tile `secondary`, `percent` (number 0–100), `highlight` (bool) |
| `Comparison` | `columns` ≥ 2 of `{title}`; `rows` ≥ 1 of `{label, cells}` | per column `badge`; `highlight` (int ≥ 0) |
| `Bars` | `bars` ≥ 1 of `{label, value}`, value a number ≥ 0 | `title`, `unit` |
| `Steps` | `steps` ≥ 1 of `{title}` | per step `detail` |
| `Source` | `text` | — |
| `Actions` | `labels`: 1–3 non-empty strings | — |

- A `Comparison` cell is a string or `{text, tone}`, where tone ∈ {ok, warn}.
- The only `maxItems` is on `Actions`.
- The v2 kinds are leaves: they hold no child ids.

**A3. The validator.**
- `a2ui_schema` exposes `CARDS_V2_CATALOG_ID` and a v2 loader.
- `A2UIValidator(catalog=<v2>)` validates every exemplar in `tests/fixtures/a2ui/cards_v2_exemplars.jsonl` with zero errors.
- `component_kinds` is the basic kinds plus the seven.

**A4. Adversarial.** The v2 validator rejects each of these:
- an extra prop;
- `Bars.value` given as the string `"828"`;
- a negative value;
- `percent: 140`;
- `tone: "error"`;
- an unknown `icon`;
- `Actions.labels` with 4 entries, or containing `""`;
- a v2 kind carrying `child` or `children`.

**A5. Negative.**
- `A2UIValidator()` with no argument is byte-identical to today: the basic catalog, the same kinds, and the same verdicts on the T-0164 census.
- Nothing under `local_astra/conductor/` or `hud/` changes.

### Group B — the renderer and components (HUD only)

**B1. The catalog on the page.**
- `hud/src/ui/a2ui.js` gains `CARDS_V2_CATALOG_ID` and remains the only HUD file that names a catalog id (T-0164 A7).
- `index.js` creates the engine with both ids.
- Any other id renders nothing (T-0164 B3).
- This amends T-0164 A1 by name.

**B2. Per-surface kinds.**
- The v2 kinds render only on a v2 surface.
- On a basic surface they render nothing and log once.
- Basic kinds render as today on a v2 surface.

**B3. The look,** per the approved mockup spec, checked by Chrome computed style in both themes.
- **Card frame:**
  - radius 20 px, 1 px border, padding 22–24 px, `--card-shadow`;
  - in dark, a vertical gradient within ΔE00 ≤ 3 of `#1b2030` → `#171a22`, and a border within ΔE00 ≤ 3 of `rgb(255 255 255/0.08)` composited;
  - in light, derived equivalents (H-T184-5).
- **`Stat`:**
  - the label is 12 px, muted, letter-spaced, and shown exactly as written;
  - the value is 56 px with tabular numbers;
  - a condition line;
  - an inline SVG glyph; an unknown or absent icon draws nothing.
- **`StatTiles`:**
  - an equal-width row that wraps in a narrow slot;
  - each tile shows its title, then value plus secondary;
  - `percent` draws a thin bar plus a `<percent>%` label;
  - `highlight` gives an accent tint.
- **`Comparison`:**
  - a label column plus one column per entry in `columns`;
  - a badge pill in the column header;
  - the `highlight` column is tinted;
  - toned cells are pills in `--ok`/`--ok-soft` or `--warn`/`--warn-soft`.
- **`Bars`:**
  - a column of labels;
  - bars on one scale from 0 to the largest value, with tick labels;
  - the largest bar (the first, on a tie) in the accent gradient (`--spark`), the rest muted;
  - the value plus the model's `unit` at each bar's end;
  - the model's order is kept.
- **`Steps`:** an ordered list with an ordinal marker, title and detail.
- **`Source`:** a chip with a glyph and the model's text.
- **`Actions`:** one `<button type="button">` per label, ≥ 44 px tall; the first is primary, the rest secondary.

**B4. The words are verbatim, and nothing is synthesised beyond a closed list.** This extends T-0164 A4 and amends A5/C3 by name (H-T184-1).
- Every model string on a reachable v2 component appears as `textContent`, byte-equal and in tree order.
  - That includes every Comparison cell. Extra cells become columns with no header; missing cells render empty.
- The rendered text is exactly the model's strings plus these derived strings:
  - (i) `String(value)` next to the unit for a Bars value;
  - (ii) Bars tick numbers;
  - (iii) `"<percent>%"`;
  - (iv) step ordinals `1…n`.
- No word is ever synthesised. "Recommended" appears only if the model wrote it as a `badge`, and "From a web search" only if it is in `Source.text`.
- **Adversarial:** the T-0164 A4 strings, placed in every text role, render literally.

**B5. Nothing is interactive** (James 2026-10-28; ruling 2026-10-17).
- No `input`, `select`, `textarea`, `[contenteditable]` or positive `tabindex` inside a v2 component. Only `Actions` buttons are focusable.
- An `Actions` click sends exactly one `astra.ui.action` with `name == "__gate.clicked"` and `context == {label, a2ui: {sourceComponentId, timestamp}}`, byte-identical to a gate-made Button with that label (T-0164 B4).
- Any other click, key or focus sends nothing.
- Older cards stay `inert`.

**B6. Morph.**
- Re-applying an identical v2 canvas makes zero DOM mutations.
- When `Bars` grows by one bar, the existing rows' nodes stay `===`, and widths are rewritten only when the maximum changes.
- A kind change replaces only that subtree.

**B7. Edge cases render with no throw, no NaN and no overflow:**
- all bars 0 (no division by zero);
- a single bar;
- a 1e12 value;
- an out-of-range `highlight` (no column tinted);
- 1 tile and 4 tiles;
- `percent` 0 and 100.

**B8. Contrast** (WCAG 2.1, both themes, `data-theme` and the emulated system theme).
- Every text role clears 4.5:1 against what is actually behind it. The 56 px value, as large text, needs 3:1.
- Bar fills, progress fills, the secondary button's boundary and the focus ring clear 3:1 against their neighbour.
- **Adversarial:** a mutant that paints muted bars in the card colour turns the row red.

**B9. No overflow** at 1280×800, 1440×900, 1920×1080, 1000×800 and 420×900.
- Nothing inside `[data-a2ui-root]` is wider than its slot. Only the comparison table may scroll, and only inside the card.
- The document never scrolls at ≥ 1100 px.
- Stress cases:
  - 12 bars with 60-character labels;
  - a 5-column comparison;
  - 4 tiles with 12-digit values;
  - a 10,000-character word in every role.

**B10. Evidence.** `scripts/demo/hud_screens.py --genui-v2` writes `genui-v2-{dark,light}.png`: every exemplar kind, plus the three mockup boards rebuilt from v2 payloads, cropped to the card. The orchestrator views them, then James.

**B11. Negatives.**
- The T-0164 census cards still render. `ui_render.test.mjs` and `ui_engine.test.mjs` stay green, except the rows amended by name.
- No new egress:
  - no `@font-face`, `@import` or `url(` (T-0128 criterion 2);
  - glyphs only via `createElementNS`;
  - only loopback requests are made.
- These are byte-identical to B's base, pinned by a fixed-ref row: `hud/styles.css`, `bridge.js`, `action.js`, `fence.js`, `hud/src/panels/**`, `hud/src/main.js`, `hud/index.html`, `hud/src/protocol.js`, `local_astra/**`, `tests/fakes/**`.

## Implementation notes

1. **One validator per catalog, picked by the surface's `createSurface`.** Never merge the catalogs: that would make C2 impossible.
2. **The catalog file must be self-contained.** `fixer_schema._localise` follows only local refs, so a cross-file ref silently degrades salvage. Copy the basic definitions; A1's drift row guards the copy.
3. **The block, example and advertised tuple are literals.** Their order is part of the prefix bytes. Never name `<channel|>`.
4. **Budget arithmetic** (offline tokenizer, rev 2ea8372): v1 is 500 tokens, with a 144-token example. A v2 3-bar example is about 111 tokens. The block fits under 1,870 code points only once the interactive kinds and the "There is no table, chart…" sentence go, and that sentence is false now anyway.
5. **The renderer lays out; it never writes words.** Only the four derived strings are allowed.
   - Ticks are "nice" numbers from 0 to the max, ≤ 5 of them.
   - Use `String(n)`, never `toLocaleString`.
   - Ordinals and "%" are text nodes, not `::before`.
6. **Theme without touching `styles.css`.**
   - `card.css` uses tokens only, with no colour literals and no theme blocks (T-0164 B5; T-0128 criterion 9).
   - Use `color-mix(in srgb, var(--…) N%, var(--…))`.
   - The T-0164 C2 follow-up (a control in a nested tile at 2.96:1 in dark) applies to Actions buttons in a tile.
7. **Root unwrap** (H-T164-8) applies to v2.
8. **Landmines:**
   - the reduced-motion block in every computed-style row;
   - strip strings and comments in source scans;
   - literal SHAs for scope pins;
   - activation in one commit;

## Group C amendment after reviewer A (2026-10-28)

- **C9. The first catalog wins for the turn.** The turn's catalog is the `catalogId` of its first `createSurface`. A later `createSurface` naming a different id does not change it, which matches the HUD's "Surface already exists". The rows:
