## Goal

After a barge-in the page still shows the whole answer the assistant was about to give, as if all of
it had been heard. This task makes the page honest: the Conductor publishes, once per playback run,
which utterances were actually rendered to the device and where the cut fell, and the spoken pane
dims and strikes through the tail nobody heard while keeping it visible. The truth already exists
server-side — T-0006's `played_ms`/`played_text` (whole sources for what finished, a word-boundary
prefix with the 100 ms guard band for what did not) and T-0007's history, which stores only the
played prefix plus `[interrupted]` — it has simply never been on the wire (docs/02 §4: "the HUD may
show unspoken text struck through"). The second, smaller half is the transcript pane's loose end
from the same family: after T-0028 ruling A17 a turn that ends without reaching THINKING (barge-in
in ENDPOINTING, an aborted turn) gets no `astra.transcript(final=true)` at all, so the page keeps a
partial line typing forever under a dead turn id (ruling A19). This task closes it.

**The three groups are ordered.** Group A (the wire and the pure splitter) has no dependency and no
contended file and goes first, because B and C both build on the models it adds. Group B (the
session's publication point and the transcript close) and group C (the page) are disjoint in files
and may run in parallel afterwards, by different agents. **Each group is its own `/implement`
session**; if an implementer is past a day of work at the end of a group, stop and report rather
than stacking the next one.

## Acceptance criteria

Numbered per group. Each is checkable by a named test in "Tests to write".

### Group A — the wire and the splitter

1. **A new server→client message.** `local_astra/contracts/protocol.py` gains
   `AstraSpokenPlayed` (`type == "astra.spoken.played"`) with `turn_id: str`, `played_ms: int
   (ge=0)` and `utterances: list[PlayedUtterance]`, where `PlayedUtterance` carries
   `utterance_id: str`, `played_text: str`, `played_words: int (ge=0)` and `complete: bool`. It is
   added to `AstraMessage`, `ASTRA_MESSAGE_TYPES` and `SERVER_TO_CLIENT`, and round-trips through
   `contracts/codec.encode`/`decode` unchanged (docs/02 §5; CLAUDE.md's wire-format rule). It is
   **not** added to `CLIENT_TO_SERVER`: a page that sends it is refused as `wrong_direction` by the
   existing ingress path (T-0028 criterion 3).
2. **`AstraSpoken` is untouched** *(negative)*. `AstraSpoken.text` stays the TTS-normalised text as
   handed to TTS (T-0028 ruling A1); no `source`, no `played_text`, no `played_ms` field is added to
   it, no field is renamed or removed, and `PROTOCOL_VERSION` stays `1` — adding a message type is
   backward compatible, an old page ignores an unknown `astra.spoken.played` through the existing
   default branch of `hud/src/state.js`.
3. **The splitter is a pure function.** `local_astra/conductor/played_split.py` exposes
   `split_played(utterances: Sequence[tuple[str, str]], played_text: str) -> list[PlayedUtterance]`,
   taking the run's published `(utterance_id, source)` pairs in publication order and the run's
   `played_text` from the terminal event. No I/O, no clock, no asyncio, no import of
   `conductor.session` (the same discipline as `turn_machine.py`, docs/02 §4).
4. **Conservation.** For any run whose `played_text` was produced by T-0006's rule,
   `"".join(e.played_text for e in split_played(...)) == played_text`, each `e.played_text` is a
   word-prefix of that utterance's source, `e.played_words == len(e.played_text.split())`, and
   `e.complete` is true iff the entry covers the whole source. Cross-checked against
   `tests/fakes/audio.py::played_text` as an independent oracle (the fake computes the
   concatenation from sources and word timings; the splitter must invert it).
5. **Under-report, never over-report** (docs/02 §4 invariant: "the history never contains assistant
   text that was not played"; the same asymmetry T-0006 spec-delta (2) fixed). If `played_text`
   cannot be reconciled with the sources — in particular the **no-separator boundary merge**,
   `"Hello."` + `"World."` → `"Hello.World."`, and the whitespace-normalised partial
   (`" ".join(words[:n])`, which is not always a literal substring of the source) — the entry where
   reconciliation fails and every entry after it is `played_text=""`, `played_words=0`,
   `complete=False`. `split_played` never returns a `played_text` that is not a prefix of its own
   source, and never returns `complete=True` for an entry the concatenation did not fully cover.
6. **Entries are monotone.** Once an entry is not `complete`, no later entry has non-empty
   `played_text` — audio is rendered in order (T-0006 `_played_text` breaks at the first incomplete
   item), so a "played, unplayed, played" pattern is a bug, not a state.
7. *(negative)* `conductor/turn_machine.py`, `contracts/events.py`, `conductor/audio_io.py`,
   `conductor/executor.py` and `conductor/hud_server.py` are not modified. `PlaybackStopped` /
   `PlaybackDrained` keep exactly today's fields; `played_text` keeps exactly today's meaning; the
   new message is not added to the endpoint's droppable set (T-0028: only `astra.turn.state` may be
   dropped on overflow — losing this message leaves the pane permanently wrong).

### Group B — the session publishes it, and the transcript stops dangling

8. **One message per run.** On each `PlaybackStopped` / `PlaybackDrained` the session publishes
   exactly one `astra.spoken.played` for the run that just ended, carrying that run's `played_ms`
   and one entry per utterance the session published as `astra.spoken` in that run, in publication
   order, with matching `utterance_id`s and the closing turn's `turn_id` (I3; docs/02 §4 row
   `INTERRUPTED | playback.stopped`).
9. **Nothing during playback** *(negative)*. No `astra.spoken.played` is published on any other
   event: not per audio block, not per utterance start, not on `Tick`. A turn with two playback runs
   produces two messages, a turn with one produces one, a run that published no utterance (a
   clip-only run, `source=""`) produces none.
10. **The wire equals history.** For a barge-in, the concatenation of the published entries'
    `played_text` is byte-identical to the `played_text` the same event carried into
    `TruncateHistoryToPlayed` / `note_truncation` — the pane and the history tell the same story
    (docs/02 §4 invariant; I3's "history contains exactly the played prefix").
11. **A clean drain marks everything heard.** After `PlaybackDrained` following a full run, every
    entry has `complete=True` and `played_words == len(source.split())`; the page dims nothing.
12. **Clips are invisible here.** An acknowledgement clip (`session.play_clip`, `source=""`, never
    published as `astra.spoken`) contributes no entry, and a clip that was cut short can only cause
    *under*-reporting of the utterances after it, never a wrong prefix (criterion 5).
13. **The dangling partial is resolved: final-at-close.** A turn that published at least one
    `astra.transcript(final=false)` and ends (the turn-close row in `Session._rotate_turn`) without
    ever having published a final gets exactly one `astra.transcript(final=true)` carrying the
    **closing turn's** `turn_id` and the closing turn's words — not the next turn's — published
    before any message belonging to the next turn. *(Justification for this choice over an explicit
    turn-aborted marker: the page's reducer already means "freeze this line, the next partial starts
    a new one" by `final`, so this needs no new wire type, no codec change, no fake change and no
    page change; an aborted turn's question is in fact complete as heard — the user stopped talking
    — and the turn-level fact that it was interrupted is already on the wire as
    `astra.turn.state(INTERRUPTED)`, which the spoken pane already marks. A marker would add a
    fourth transcript state to a pane with a two-state vocabulary for a purely cosmetic
    distinction.)*
14. **No walk-back and no second final** (T-0028 rulings A17/A19). A turn that already published
    `final=true` at the flush / ENDPOINTING→THINKING row publishes no second final at close; a turn
    that published nothing at all (no words) publishes nothing at close; a final is never followed
    by a partial for the same turn id.
15. **The ui-opened turn's pin** (A19's owed coverage note, taken over from T-0020): a turn opened
    by `astra.ui.action` publishes exactly **one** `astra.transcript(final=true)` whose text is the
    `[ui] <name> <context>` prompt, before its first `astra.spoken`. (The implementation does it
    twice today; this criterion pins it to once.)
16. *(negative)* The session's over-long-prompt path, the prompt builder, the executor table, the
    machine's command set and `turns.jsonl`'s schema are unchanged; no new event type is submitted
    to the machine; no clock is read other than the injected `self.clock`; the fast suite is green
    apart from the four named parity pins (see "Implementation notes").

### Group C — the page

17. **The reducer carries played state.** `hud/src/state.js` reduces `astra.spoken.played` into the
    existing `spoken` groups: each matching utterance gains `{ played_words, complete, played_text }`.
    `reduce` stays pure (no mutation of the state handed in, no clock of its own beyond the `nowMs`
    argument).
18. **Nothing is invented.** A `played` entry for an `utterance_id` or `turn_id` the page has never
    seen creates no group, no line and no text; the state is returned unchanged. A *later*
    `astra.spoken` for an utterance that already carries played state **clears** that state (the cut
    was measured against the text that was played; a new text has not been measured) — the page must
    never strike a string it did not receive a measurement for.
19. **The unheard tail is shown, not hidden.** `hud/src/panels/spoken.js` renders, inside the
    existing `[data-utterance-id]` element, the words from index `played_words` onward inside a
    `[data-unplayed]` element: `complete === true` → no `[data-unplayed]` element at all;
    `played_words === 0` → the whole utterance inside it; no played state → today's rendering,
    unchanged. The full text is always present in the DOM — dimmed and struck, never removed
    (docs/02 §4: "the HUD may show unspoken text struck through").
20. **The style says "not heard".** `hud/styles.css` gives `[data-unplayed]` a line-through and
    reduced opacity, and the played part neither.
21. **Whitelist parity.** `hud/src/protocol.js`'s `SERVER_TO_CLIENT` and its per-type field list
    mirror `contracts/protocol.py` exactly (the existing parity tests are the check).
22. *(negative)* **No timing-derived strike-through.** With no `astra.spoken.played` on the socket,
    nothing is ever dimmed no matter how much time elapses, how many `astra.turn.state(INTERRUPTED)`
    messages arrive, or how long an utterance is. The comments in `state.js` and `spoken.js` that
    today forbid faking this ("must not be faked from timing") are replaced by the real
    implementation, not by a clock. `hud/src/main.js`, `hud/index.html` and
    `hud/src/panels/transcript.js` are not modified.

## Implementation notes

- **Landmine 1 — the two texts.** `AstraSpoken.text` is the *TTS-normalised* text (T-0028 A1);
  `played_text` is built from the *committed source* strings (docs/02 §4 spec delta (2) from
  T-0006). They are different strings. The only reason a word index transfers between them is that
  `_partial_text` refuses to produce a prefix at all unless the source token count equals the
  rendered word count. Therefore `played_words` is always a valid cut in the displayed text — but
  only because of that rule. Do not add a code path that produces a partial prefix under any other
  condition, and do not make the page string-match `played_text` against the text it displays.
- **Landmine 2 — the concatenation has no separator.** `audio_io._played_text` and
  `tests/fakes/audio.py::played_text` both `"".join(...)` whole sources, and word-normalise only the
  partial. Any splitter that works token-wise gets the boundary case wrong (test row above).
- **Landmine 3 — order of the close.** Criterion 13's final must be published with the closing
  turn's id and words. `Session._rotate_turn` runs after the machine has stepped; `self._state` may
  already be the next turn. The `_closing` log the session already keeps for `commit_history` is the
  precedent.
- **Landmine 4 — `_transcript_final` is a fence, not a trigger** (T-0028 A17). It exists to stop a
  final being walked back; criterion 13 must not be implemented by publishing the final earlier.
- **Four existing green tests go red on purpose**, and that is a spec change, not test
  accommodation: `tests/contract/test_assist_protocol.py` (`len(SERVER_TO_CLIENT) == 9`),
  `tests/unit/test_hud_constants_parity.py` (the js/python lists), `tests/hud/protocol.test.mjs`
  (the dispatch list) and, if it enumerates types, `tests/contract/test_protocol_codec.py`. They are
  pins on the protocol inventory; the inventory is what this task changes, so the **test-author**
  updates them in the same PR (the implementer must not — hook-enforced). The spec being changed is
  docs/02 §5's message list; the `/spec` delta above is the record. Any *other* red test is a
  behaviour bug, not a pin to update.
- `.claude/rules/`: the conductor rules (pure machine, one publish seam, injected clock only) and
  the test rules (no `Σp == 1` tautologies — criterion 10's row is the one at risk) apply. The
  loopback-only scan and the "no new network call" rule are unaffected; this adds no socket.
- The new message must **not** be droppable on outbox overflow (T-0028's egress policy): a dropped
  `astra.spoken.played` leaves the pane permanently claiming the user heard the whole answer. No
  edit to `hud_server.py` is needed to achieve this — that is the point of criterion 7.
- Message size: entries are at most one per utterance per run; a 60-utterance run at 200 chars each
  is ~24 KB against `MAX_MESSAGE_BYTES` (8 MiB). No chunking needed, no truncation policy needed.

## Regime

For every measured or timed criterion: profile `lean`; virtual clock in the unit and egress tests
(no wall-clock sleeps, no real audio device); `tests/fakes/audio.py` for playback, `HudStub` for the
socket; n = 1 and deterministic per row, Hypothesis default profile with the repo seed for
`test_split_played_inverts_the_fake_audio_oracle`. CDP row: Chrome 147.0.7727.101 on the dev box,
the `?source=canvas` synthetic capture, real-time CDP polling (not `--virtual-time-budget`, per the
module docstring), page served over loopback http, one browser launch for the module. No GPU, no
`/launch`, no bench threshold: this task reports no latency, VRAM or duplex number, and must not
change any (criteria 9 and 16 are the guard — one extra message per playback run, none during it).
Versions as pinned in `services/versions.lock`; node ≥ 18 for the `.mjs` rows.
