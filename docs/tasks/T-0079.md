## Goal
H2 replaced the BFCL selection rule after the grid was recorded. The new rule is: among eligible cells with score ≥ best − 0.05, take the
fewest mean steps; on a tie, take the larger entropy bound. A reviewed, deterministic CPU tool reads the recorded b2 campaign and writes new frozen
BFCL files for both grid arms with full provenance. The four frozen files (BFCL new, Sudoku unchanged) are then published byte for
byte under `docs/cd/`, so T-0071c can load them with `calibration.load_frozen(path, task=, arm=)`. No GPU run, no test-cut contact.

## Acceptance criteria
1. **Rule (H2).** `scripts/cd_reselect.py` selects per arm from `grids[<arm>].cells` of a T-0071b campaign JSON.
   - **Pool:** cells with `eligible` true, `stopped` null and `n` equal to the cut size (100); any other cell is never chosen and never sets "best".
   - **Threshold:** a cell qualifies iff `score ≥ best − 0.05`, computed exactly. Use integer counts `k = score·n` (refuse if `score·n` is not an integer within 1e-9) and compare `Fraction(k, n) ≥ Fraction(k_best, n) − Fraction(1, 20)`. The boundary is inclusive.
   - **Choice:** the qualifying cell with the fewest `mean_steps`, then the larger `entropy_bound`.
   - **Unresolved tie:** a tie that remains after both keys makes the tool refuse (exit 2, nothing written). It never invents a third key.
2. **H2's numbers reproduce.** On the recorded campaign (`campaign-bfcl.json`, sha256
   `9e1479b939efe847c9d310eeb1c4f848e466693e085529602e5ddcb5e1f9d5a8`):
   - `perstep_mar` → eb 1.0 / ct 0.005 (exact 0.52, 6.88 steps);
   - `perstep_mar_qargmax` → eb 0.3 / ct 0.005 (0.52, 7.99 steps).
   The oracle is the H2 text in `docs/tasks/T-0071b.md`, not the tool.
3. **Frozen files.** One file per grid arm, written with `calibration.freeze` (so `content_sha256` is set). Names follow
   `calibration.default_path`: `calibration-bfcl.json` and `calibration-bfcl-perstep_mar_qargmax.json`. The content keeps every field of
   the T-0071b frozen files: `task`, `cut: "dev"`, `arm`, the knobs, `expected_commit` (the campaign's, 067ee04…), `limit`,
   `stock_reference` (copied from the campaign), and `chosen_stats` (`score`, `n`, `mean_steps_per_canvas`, `stopped`, and
   `mean_accepted_per_step`, recomputed read-only through `scripts/gpu/cd_campaign.py::cell_stats` on the campaign's `engine.log`).
   Provenance fields are added:
   - `rule` (the H2 rule text);
   - `decision` = `{by: "human", date: "2026-10-08", ref: "docs/tasks/T-0071b.md#H2"}`;
   - `source_campaign` = `{path, sha256}` of the input;
   - `superseded` = `{path, sha256, entropy_bound, confidence_threshold, score, mean_steps}` of the pre-registered file it replaces
     (d70f5888… / 42c689a3…);
   - `grid_results` (that arm's cells, as recorded);
   - `reselected_by` (tool path and the git commit it ran at).

   `load_frozen(p, task="bfcl", arm=<arm>)` returns H2's knobs. Calling it with the other grid arm raises `ValueError`. `perstep_mar_sc` and
   `perstep_mar_qargmax_sc` load their base arm's file (`CALIBRATION_SOURCE`).
4. **Deterministic bytes.** Two runs on the same inputs, decision date and commit write byte-identical files. No wall-clock timestamps.
5. **Publication (C8).** Four files are committed under `docs/cd/`:
   - the two BFCL files, byte-identical to the tool's output under `logs/t0079-reselect-<sha>/`;
   - `calibration-sudoku.json` (sha256 `19acb78058815fa018391aea3c12fc0bbc86aec631e6d17293c489680040c69a`), copied byte for byte from the b1 evidence;
   - `calibration-sudoku-perstep_mar_qargmax.json` (sha256 `ae89b553115762991c1805278be6d97efa68d0250cc8160deb8b4703f28d7b55`), copied byte for byte from the b1 evidence.

   All four load with `load_frozen(task=, arm=)`. The Sudoku knobs stay at eb 0.3 / ct 0.005 (H2: pre-registered picks kept).
6. *Negative:* no change to `local_astra/eval/cd/**`, `scripts/gpu/cd_campaign.py` or `plugin/**`. The input campaign, engine
   log and the original b2 frozen files under the launch worktree's `logs/` are byte-identical after the run, because the tool opens
   them read-only. No request is sent to any server. The tool refuses `--task sudoku` (H2 keeps Sudoku), refuses an existing output path,
   and refuses a campaign whose `cut` is not `dev`.

- Reuse `calibration.freeze`/`load_frozen`, read-only. Don't re-implement `content_sha256`.
- Artifact paths inside the campaign are relative to the launch worktree root. The tool takes `--evidence-root`
  (`.claude/worktrees/t0071b-launch2`), `--campaign`, `--engine-log`, `--out-dir logs/t0079-reselect-<sha>`, `--task bfcl`,
  `--decision-date`.

  the choice). Then copy byte for byte into `docs/cd/` in a separate commit. The verifier re-runs the tool and diffs bytes.

- Calibration ran with `enable_thinking=false` and the `channel_header=True` grammar. That regime stays attached to the files. Applying
  these knobs to the thinking-on product (T-0080) is an assumption that T-0080 measures, not a property of this file.
