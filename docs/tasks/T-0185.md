## Goal

CPython 3.11 refuses to convert an integer string longer than `sys.get_int_max_str_digits()` digits (4300 by default). On a model canvas holding such a literal, the gate fails in two ways. Both were reproduced on 7646b8b6.

**It raises `ValueError` on two paths:**
- **The strict parse.** `_repair` → `parse_concatenated_json` → `raw_decode`. This covers whole canvases and canvases cut after the literal, because the decoder reaches the number before the cut.
- **The strict re-parse after the bracket repair.** `_fix_unguided`, line 1032, catches only `json.JSONDecodeError`. Repro: a stray `]` before the literal; the bracket repair makes one edit, then the re-parse raises.

That breaks T-0108 criterion 9, and in a live session it breaks the `ui` commit handler.

**It quietly turns the number into a string on the json_repair path.** json_repair 0.63.4's `parse_number` catches the `ValueError` and returns the digits as a `str`. Repro: a bare key forces the json_repair path, and `updateDataModel.value.level` holds a 4301-digit literal. The result is a surface, `complete=True`, with the value as a 4301-character string. The same canvas with a 310-digit literal is refused under T-0184 C10.

**After this task:**
- the gate returns a `GateResult` for every digit count, on every path;
- an over-limit integer is refused exactly as C10 refuses an integer beyond the float range (which `JSON.parse` would read as `Infinity`);
- the rest of the surface is handled as for any invalid component;
- no process-wide interpreter setting changes;
- every input the gate handles today without raising gives a field-equal `GateResult`.

## Acceptance criteria

Throughout, the **literal** is an integer literal with no fraction and no exponent, of `D` digits with an optional leading `-`; the sign does not count toward the limit. The **limit** is the interpreter's `sys.get_int_max_str_digits()`, 4300 by default. **The control** is the same canvas with the literal replaced by a 310-digit literal of the same sign (`10**309`-class), which BASE parses and C10 refuses. "Verdict" means T-0184's `_verdict`: every `GateResult` field, with the report reduced to `ok`, so the wording of errors is ignored.

1. **The gate never raises, strict path (T-0108 criterion 9; T-0184 C10 follow-up).**
   - `UiGate().gate(...)` returns a `GateResult` when the literal has D ∈ {4301, 10^5} digits, signed and unsigned, with `final` True and False, on both catalogs (basic v0.9.1 and `gearvis:cards/v2`).
   - Placements in a component: a number role (basic `Slider.value`, v2 `Bars.value`); a string role (`Text.text`); an unknown property; the component `id`; a `children` entry.
   - Placements in the envelope: an extra `createSurface` property; `updateComponents.surfaceId`; `updateDataModel.value`, both bare and nested.
   - No exception of any type escapes.
2. **The gate never raises on the two repair paths.** The same placements, reached through (a) the strict re-parse after the bracket repair (a stray `]` before the literal, where the bracket repair alone makes the text parse) and (b) the json_repair path (a bare, unquoted key before the literal, and a canvas cut inside the literal or right after it). Each returns a `GateResult`.
3. **Cut canvases never raise and stay grounded (T-0108 criterion 6; T-0184 C3).** Take a full two-message canvas carrying a 4301-digit literal in `Slider.value` and build its cuts: every character offset within 50 of the literal's start and end, and every 64th offset elsewhere. Each cut goes through a fresh gate with `final=False`. Each call returns, and every emitted string value is a substring of the cut (T-0108 grounding).
4. **Refused like a beyond-float integer (C10 semantics).**
   - **Number roles and the envelope:** for every criterion-1 placement and every criterion-2(a) placement, the verdict equals the control's verdict. So a component with the literal is emitted nowhere, is in `lost` and `resample`, `complete` is False, and the rest of the surface is emitted. A message that carries the literal outside its components gives no surface.
   - **String roles at a cut:** where the gate's existing salvage turns a number in a string role into text (BASE behaviour for every number, including 12 digits, `NaN` and `Infinity`), the verdict agrees with the control on: surface present, the emitted component ids, `lost`, `resample`, `complete`, `root`, `unreachable` and the repair counts. Any emitted string coming from the literal is exactly the literal's characters as written.
5. **No quiet conversion to a string on the json_repair path (adversarial; red at BASE).**
   - The criterion-2(b) placements in `updateDataModel.value` (nested and bare) and in a number role give the control's verdict. At BASE the nested data-model case gives a surface with `complete=True`, so this row is red there.
   - No emitted message anywhere carries a `str` of 4301 or more digits that the canvas wrote as a bare number.
6. **The behaviour follows the interpreter's limit and hard-codes no number.**
   - With `PYTHONINTMAXSTRDIGITS=640` (the minimum), a subprocess gate on a 641-digit literal returns, and its verdict equals the control's.
   - With `PYTHONINTMAXSTRDIGITS=0` (unlimited), a subprocess gate on a 4301-digit literal gives the same verdict as the in-process gate at the default limit.
7. **No process-wide change (negative).**
   - `sys.get_int_max_str_digits()` is the same before and after every criterion-1 to criterion-5 call.
   - A source row finds no `set_int_max_str_digits`, no `PYTHONINTMAXSTRDIGITS` and no `int_max_str_digits` under `local_astra/`, except the existing read in `local_astra/toolcall/native.py`.
8. **The result is safe to log.** For every adversarial row: `json.dumps` of the `GateResult` snapshot succeeds at the default limit (the session log writes these fields); no emitted value is an `int` beyond the float range or a non-finite float (T-0184 `_beyond_double` is empty); no problem or schema-error string contains the literal's digits (C10's message already never prints the integer).
9. **Too-wide guard: these inputs stay exactly as at BASE.** Each verdict is field-equal (every field, wording included) to the frozen BASE gate:
   - a 4300-digit literal at the default limit, signed and unsigned, in a component and in the envelope;
   - a run of 4301 or more digits inside a JSON string (`"text": "777…"`), which renders verbatim;
   - a 4301-digit literal with a fraction or exponent (`7…7.5`, `7…7e5`), which is a float, so the parse gives `inf` and C10 refuses it as at BASE;
   - json_repair's other number-to-string conversions (for example `1,000` in an object on the json_repair path);
   - `10**308`, `1e308` and `sys.float_info.max`: T-0184's `test_c10_too_wide_guard_largest_finite_values_still_pass` stays green, unmodified.
10. **BASE behaviour is unchanged for every stored trial (differential; negative).**
    - **(a) Fast rows.** Over the T-0164 census (`tests/fixtures/a2ui/genui_census_20261027.jsonl`, both basic id spellings) and the stored Q12 sample (`tests/fixtures/a2ui/q12_trials_sample.jsonl`), the live gate and `tests/unit/_frozen_ui_gate_t0185.py` give field-equal `GateResult`s, run in order, one fresh gate pair per trial (the T-0184 C1 harness shape).
    - **(b) Full corpus ("fulldiff").** An opt-in integration row runs every `ui` commit of every stored `trials.jsonl` (under `logs/*/` and `.claude/worktrees/*/logs/*/`) through the live gate and the frozen BASE gate, in order, one fresh gate pair per trial. It asserts 0 diffs and prints the trial, call and diff counts (at T-0184 C: 827 trials, 2988 calls, 21 files). With no stored trials it skips and says so.
    - **(c) Replay (T-0184 C7 shape).** `scripts/replay_ui_gate.py` over every session log on this box that has a `ui` commit gives byte-identical output and exit status at BASE and TIP. The reviewer pastes the empty diff.
    - Rows (a) and (b) are green at BASE by construction (unmarked).
11. **`A2UIValidator.validate_text` never raises on the literal either.** For criterion 1's canvases it returns a `SurfaceReport` with `ok=False` on both catalogs. On every input it parses today its result is unchanged; the criterion-10(a) fixtures go through `validate_text` field-equal to BASE.
12. **Bounded.**
    - The gate on a canvas with a 10^5-digit literal takes ≤ 1 s, median of 5, serial. Printed by the integration module, not a fast-suite row.
    - The new fast-suite rows add ≤ 5 s serial in total, subprocesses included.

## Implementation notes

1. Where the fix lives is the implementer's choice, inside the owned files. The contract is criterion 4: the result equals what the gate does with a beyond-float integer. Whatever form the refused value takes, it must reach `_FiniteOnly` / `_non_finite_errors` as something C10 already refuses. No new refusal path with its own problem wording.
2. No `int`, `str`, `repr`, `json.dumps` or f-string of an over-limit int may happen anywhere on the gate path, not only in the parser: jsonschema builds messages with `repr(instance)`; `_salvage_one` calls `json.dumps([component])` (its `except ValueError` would hide this as "salvage did nothing"); problem strings format ids with f-strings. So the over-limit int must never enter the parsed tree, or every one of those places must be audited. The criterion 1 placements (`id`, `children`, string role) are there to reach them.
3. json_repair 0.63.4 does not raise on such a literal; it returns the digits as a `str` (`json_repair/parse_number.py`, `except ValueError: return number_str`). Grounding cannot catch this, because the digits appear in the raw canvas. json_repair also returns `1,000` and similar as strings; that is BASE behaviour and must not change (criterion 9).
4. The limit is per interpreter and can be changed by `-X int_max_str_digits` or `PYTHONINTMAXSTRDIGITS`. Read it; never set it (criterion 7). The sign is not counted; the minimum non-zero value is 640, and 0 means unlimited.
5. `UI_FENCE_MAX_CHARS` is 8192 (`llm_client.py:91`), so a live canvas can carry a 4301-digit literal but not a 10^5-digit one. The gate's contract is "any `str`" anyway, which is why the 10^5 rows exist.
6. The differential oracle must stay BASE. `_frozen_ui_gate_t0185.py` is a verbatim copy, and it imports `parse_concatenated_json` from the live `local_astra.ui`; if the implementer changes that function, a plain copy would test TIP against TIP. So the frozen module also carries BASE's `parse_concatenated_json` verbatim and rebinds its module-level name to it; its pin row covers both parts. `_frozen_ui_gate_t0184.py` stays untouched.
7. Must be preserved: T-0108 criteria 1, 6 and 9; T-0184 C9a (the catalog locks at the first surface the gate emits); the `.claude/rules/conductor.md` rule that only validated surfaces render. Do not catch broad exceptions around the gate to "never raise": that hides the next bug and fails criterion 4.
8. Rule line for the orchestrator (systemic, second instance after T-0084b M2), for `.claude/rules/conductor.md`: "A parser of model text must survive an integer literal past `sys.get_int_max_str_digits()`, on every parse path including the fallback, and must never change the limit; json_repair returns such a literal as a string (T-0185)."
9. The `ui_gate.py` module docstring's "No non-finite number" paragraph says an over-limit literal is refused the same way.
