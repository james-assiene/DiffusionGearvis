## Goal

**Evidence** (James's sessions 2026-10-29: `logs/sessions/20261029-203137-2891648.jsonl`, `20261029-201813-2716251.jsonl`, `20261029-191225-1527834.jsonl`):
1. **Amazon search after Enter showed only the header.** This is the navigation case; T-0203 fixes it.
2. **After a scroll, lazy-loaded content shifted the layout, and the model clicked volume 8 instead of 7.** The model thinks for several seconds between the screenshot and the click, so the click lands on a layout that moved since the frame it reasoned about.
3. **Client-rendered results paint after `domcontentloaded`.** `settle()` (DCL plus two rAF) and T-0203's follow both return before they paint.

**What changes.**
- **The pre-click guard (B).** Before an executed `click_at` or `type_at` dispatches anything, the executor checks whether the page under the click point changed since the frame the model is acting on. It uses two independent signals:
  - Chromium's own layout-shift records near the point (CDP; page script cannot forge or hide them);
  - a pixel comparison of a small fresh crop around the point against the same region of that frame.

  If the page moved, the call is refused with the existing freshness reason, nothing is dispatched, and the session's T-0187 path shows a fresh frame at the next step. A misclick becomes one extra step.
- **The visual settle (C).** Before an action's after-frame is kept, the executor takes screenshots on a short schedule until two consecutive ones match on a coarse grid, ignoring regions that change on every frame. The cap is bounded. The ordinary cost is one extra screenshot about 100 ms later.
- **Network quiet, logging first (D).** The driver counts the document/XHR/fetch/script requests started during the action, plus same-document URL changes. At first it only logs what a wait would have cost.
- **A truthful label at the cap (E, optional).** This is a measured change to the model's input.

No fixed wait is added anywhere: every new wait is woken by a signal and capped.

**Threat model** (the guard must fail safe):
- **Signals.** No init script and no page-visible global. The layout-shift signal comes from CDP `PerformanceTimeline` events on a driver-owned CDP session; page script cannot read, forge or suppress them, only cause real shifts.
- **What the shift signal misses.** Shifts of sources beyond Chromium's 5-per-entry cap (read as whole-viewport, A-R1), CSS `transform` moves (not reported by the Layout Instability API), shifts inside cross-origin iframes, and pages where CDP enabling fails. The pixel crop is the always-on fallback for all of these.
- **Denial of service.** A hostile page that animates near every target is bounded by the refusal cap (B4). After the cap the click goes through as at BASE, which is today's behaviour, and is noted.
- **Both signals unavailable.** The click proceeds as at BASE and is noted. The guard never fails the action.
- **Out of scope:** a compromised renderer, and injected text in page pixels (stated in CLAUDE.md, not solved).

## Acceptance criteria

### Group A — driver signals (`runtime.py`; nothing calls them until B/C)

- **A1. Region screenshot.** `async def screenshot_region(self, x: float, y: float, w: float, h: float) -> bytes`.
  - It returns one JPEG (quality `JPEG_QUALITY`, `scale="css"`, not full page) of the active page's viewport, clipped to the rectangle in viewport CSS px.
  - The clip is clamped to the viewport. It raises `ValueError` when nothing of the rectangle is inside the viewport, and `RuntimeError` when there is no active page.
  - It dispatches no input, does not scroll, and evaluates no script.
  - Its pixels equal the same region of `screenshot()` on a static page: mean absolute luma difference ≤ 3 (JPEG noise only).
- **A2. Layout-shift recorder.** The driver records Chromium's layout-shift entries for the active page from CDP `PerformanceTimeline.timelineEventAdded` (`eventTypes: ["layout-shift"]`), on a CDP session it owns.
  - **What is kept:** only geometry, namely each source's `previousRect`/`currentRect` in viewport CSS px, plus an arrival counter. `nodeId` is ignored and never resolved.
  - **`shift_mark() -> object`** is synchronous and opaque; it carries the driver, the generation, the page and the counter.
  - **`shifts_since(mark) -> tuple[tuple[float, float, float, float], ...] | None`** is synchronous and returns the rects (x, y, w, h) of every entry that arrived after `mark` on the same page. It returns `None` when:
    - the recorder is not armed on that page;
    - arming failed;
    - the mark is foreign, or from another generation or page;
    - there is no active page.
  - **Bounded memory:** at most `MAX_SHIFT_ENTRIES = 256` entries. If entries since `mark` were dropped, it returns one rect covering the whole viewport, so an overflow reads as moved everywhere, never as quiet.
  - It never raises.
- **A3. Arming.** `async def arm_shift_recorder(self) -> bool` enables the recorder on the active page.
  - It is idempotent per page and costs at most one CDP round trip per page, bounded by `SHIFT_ARM_TIMEOUT_S = 0.5`.
  - It returns `False` on failure. `Exception` never propagates; `CancelledError` does.
  - A page reached by a cross-document navigation keeps reporting shifts (re-arm on commit if R1 shows it is needed).
  - A relaunch drops everything.
- **A4 (negative).** These are unchanged:
  - `settle()`, `navigation_mark`, `navigated_since`, `follow_navigation`, `main_frame_urls` and `layout_metrics()`'s answers;
  - the launch arguments and the init scripts (`test_no_new_page_script` stays green);
  - every existing unit and browser row.

  `PerformanceTimeline.enable` is the only new CDP method. No page text, title, URL or DOM node is read.

### Group B — the pre-click guard (`executor.py`; after Merge T-0203-b and Merge T-0204-a; on by default)

- **B1. References.**
  - The guard runs only when the driver's class has `screenshot_region`, `arm_shift_recorder`, `shift_mark` and `shifts_since`. The real driver has them; every existing fake lacks them.
  - Each own frame registered by `_register` keeps a guard reference: a luma copy of the kept screenshot at CSS-px geometry, taken before the `policy` downscale, and the `shift_mark()` read right after that screenshot.
  - At most `PRECLICK_REF_FRAMES = 4` references are kept, oldest dropped first.
  - Arming happens before the kept screenshot of every own capture, at most one round trip per page.
- **B2. The check.**
  - **When it runs:** for an executed `click_at`/`type_at` planned on a screen frame (not the overview-frame path). It runs after `ensure()`, every refusal check and `_front`, and before the first `mouse_move` (also before `_dispatch_guarded`'s click). It is enabled by the module constant `PRECLICK_GUARD = True`, read at call time.
  - **Inputs:**
    - the reference of `inv.frame.phash`;
    - `shifts_since(ref.mark)`;
    - `screenshot_region` of the box of half-size `PRECLICK_HALF_PX = 64` around the click point.
  - **The page moved iff** either:
    - (a) a returned rect (previous or current) intersects the point's box grown by `PRECLICK_SHIFT_MARGIN_PX = 40`; or
    - (b) the share of 8×8 blocks of the crop whose mean absolute luma difference from the reference exceeds `PRECLICK_BLOCK_DELTA = 16` is at least `PRECLICK_CHANGED_SHARE = 0.10`.
  - The whole check is bounded by `PRECLICK_TIMEOUT_S = 0.3`.
- **B3. Refusal.** On "moved" the outcome is `refused`.
  - The reason is `MOVED_REASON`, a new executor constant whose text equals `session.FRESHNESS_REASON` byte for byte (a test pins both sides, as in T-0187).
  - No mouse, keyboard or scroll call is made. No frame is registered, and `latest_frame` is unchanged.
  - Through a real `Session`, with no `session.py` change, the next step carries a fresh browser frame (T-0187's `new_frame_refused` path).
- **B4. Loop bound.**
  - After `MAX_MOVED_REFUSALS = 2` "moved" refusals in a row in the same `turn_id`, the next guarded call is not checked. It runs as at BASE and is noted `"result": "allowed_after_cap"`.
  - The run is reset by an executed `click_at`, `type_at`, `scroll`, `press_key`, `wait` or `page_overview` of the turn, or by a new `turn_id`.
  - Refusals for other reasons neither count nor reset.
- **B5. Fail open to BASE.** The click proceeds exactly as at BASE and is noted `"result": "unavailable"` when:
  - there is no reference for the phash;
  - the region screenshot raises or times out;
  - `shifts_since` gives `None` and the pixel comparison could not run.

  When `shifts_since` gives `None` but the crop ran, the pixel signal alone decides. `CancelledError` propagates, with nothing dispatched or registered.
- **B6. Note.** Each check that did not end in a plain "not moved" calls `on_note` once with exactly:
  `{"what": "live click: page moved check", "result": "refused"|"allowed_after_cap"|"unavailable", "shift": bool|None, "changed_share": float|None, "ms": int}`

  It carries no URL, host, title, phash or coordinates. A raising `on_note` is swallowed, and no `resolved` key is added.
- **B7 (negative).**
  - These make BASE's driver calls and outcomes:
    - `scroll`, `press_key`, `wait`, `page_overview`, `google_search`;
    - the overview-frame click/type;
    - dry-run and `off`;
    - every action on a driver class without the B1 capability.
  - On a static page a guarded click adds exactly one `screenshot_region` call and the synchronous `shifts_since` read. Its `ToolOutcome`, `action`, `resolved` keys and after-frame are BASE's.
  - With `PRECLICK_GUARD = False`, the real driver's call sequence is BASE's.
- **B8. Cost.** On real Chromium (loopback, headless, a static 1280×800 page), the guard's added wall time per click has a median ≤ 60 ms and a p90 ≤ 100 ms (n = 20; B-R3: was 50 ms, chosen not measured; three compositor frames measured).
- **B9. Real Chromium on loopback.** Fixture `tiles.html` is a grid of distinctly coloured, numbered tiles. Each tile's click handler records its number for the test (the test reads it; the model never does).
  1. **Lazy insert above.** The page inserts a 300 px block above the grid after the frame is captured. `click_at` at tile 7's coordinates in that frame is `refused` with `MOVED_REASON`, and no tile records a click. The row first shows at BASE (guard off) that a wrong tile is clicked.
  2. **Transform move** (no layout-shift entry): refused by pixels.
  3. **Static page:** executed, and tile 7 is recorded.
  4. **Adversarial false positives.** Each of these is executed, not refused:
     - a focused input with a blinking caret at the click point (`type_at`);
     - a spinner animating 200 px away;
     - a block inserted far below the point, outside the margin.
  5. **An animated region under the point:** refused twice, and the third call is executed with the `allowed_after_cap` note.
  6. **CDP unavailable** (arming forced to fail): rows 1 and 3 keep their verdicts by pixels.
- **B10. Spec change, not a test workaround.** For the real driver's `click_at`/`type_at`, B supersedes:
  - T-0203 B6/B8.6 "exact BASE Playwright calls";
  - T-0200 C10 "a normal page gives … one screenshot";
  - T-0202 B10 "a normal page's `click_at` makes the same driver call sequence".

  The test-author re-pins those rows to "BASE plus one `screenshot` with a `clip`", citing T-0204 B10.

### Group C — the visual settle (`executor.py`; after Merge T-0204-b; on by default)

- **C1. Where it runs.**
  - It is enabled by `STABLE_SCREEN = True` (read at call time) and gated on the B1 driver capability.
  - It runs in the action path's capture (`_take("action", …)`), after T-0200's blank loop has kept a non-blank capture or spent its budget.
  - It covers the after-frame of `click_at`, `type_at`, `press_key`, `scroll` and `wait`, the overview-frame action, T-0203 B2's late re-capture, and the guarded-type stop capture.
  - It does not run in `frame()` or `page_overview` (H-T204-6).
- **C2. The rule.**
  - **Schedule:** shots at offsets `STABLE_SCHEDULE_S = (0.1, 0.25, 0.5)` after the previous shot; after the last offset, the last interval repeats until the cap.
  - **Comparison:** each shot is compared with the previous one on the luma grid of T-0200's `BLANK_GRID_W = 64` box downscale. A cell differs when |Δ| > `STABLE_CELL_DELTA = 6`.
  - **Stable** means at most `STABLE_MAX_CELLS = 4` differing cells. From the third shot on, a cell that also differed in the previous pair counts as animation and is ignored.
  - **Kept capture:** the last shot, registered once, with the extent from the metrics read around it.
  - **Bounds:** `STABLE_CAP_S = 1.0` from the first shot, never past T-0200's `deadline`, each shot bounded as in T-0200's RV1.
- **C3. Cost on ordinary actions** (ruling a). On a static loopback page an executed action takes exactly 2 screenshots. The added wall time has a median ≤ 0.20 s and a p90 ≤ 0.25 s (n = 20).
- **C4. In-progress shifts are waited out.** Fixture `lazy_scroll.html`: after a scroll, the page inserts a 120 px block above the viewport content every 80 ms for 400 ms (scroll anchoring off).
  - The after-frame's pixels at a probe point are the final layout's colour.
  - The settle took ≥ 3 shots.
  - The wall time of the whole `execute()` is ≤ `STABLE_CAP_S` + 0.4 s (C-R4: under C-R1 the inserts between shots 2 and 3 hold that pair, so the settle runs to the cap; was 0.4 s + 0.6 s).
- **C5. Animations do not hold it.** A page that is static except for a 300×250 block changing every 100 ms is stable within 4 shots, with a wall time ≤ 0.8 s.
- **C6. Bounded on a never-stable page.** A full-viewport noise canvas gives `executed` within `STABLE_CAP_S` + 0.3 s, and its note says `"stable": false`. With `ACTION_TIMEOUT_S` patched to 1.5 s it still ends `executed`.
- **C7. Composition.**
  - T-0200 retakes a blank first capture before the settle starts.
  - T-0203's follow runs before the capture.
  - **Adversarial (T-0203 R1's miss):** a JS submit fired 120 ms after Enter is now caught by T-0203 B2's late read. The after-frame shows the new page and `navigated` is `True`; at BASE with T-0203 B this was missed 5/5.
- **C8. Identity.**
  - Only the kept capture is registered (`_own`, `_extents`, `_latest`, `frame_after`).
  - An intermediate shot's phash is not an own frame: a `click_at` carrying it is refused.
  - B's guard reference is the kept shot's.
- **C9. Note.** A settle that took more than 2 shots or hit the cap calls `on_note` once with exactly:

### Group D — network quiet and same-document change (after Merge T-0204-c; `NETWORK_QUIET = "shadow"` by default)

- **D1. Driver.** The existing `request`/`requestfinished`/`requestfailed`/`framenavigated` listeners also keep, per adopted page:
  - the in-flight requests of resource type `document`, `xhr`, `fetch` and `script`, with start sequence numbers;

  - **`network_state(mark) -> dict | None`** (synchronous) gives `{"inflight": int, "quiet_ms": int, "same_document": bool}`. It counts only requests started after the T-0174 mark and in flight for less than `NET_STALL_S = 1.0`.

## Implementation notes

- **Pixel-first.** The driver keeps geometry (rects) and counts only. The model sees nothing new: the refusal reuses `FRESHNESS_REASON`'s exact text (H-T204-1). Notes carry no URL, host, title or phash.
- **CDP, not init scripts.** The recorder runs on a driver-owned CDP session. Reusing the `layout_metrics` session is fine if its drop-on-failure rule still re-arms. `PerformanceTimeline` is experimental: R1 confirms the event shape and coordinate frame before B relies on them.
- **References before the downscale.** `_register` holds the kept CSS-scale JPEG before `policy.target_size`, and the crop is compared in CSS px. Key references by phash, because the session may reuse `latest_frame`.
- **Shift mark timing.** Take the shift mark after the kept screenshot returns. A shift that happened just before the screenshot can cause a rare extra refusal. This is accepted and bounded by B4.
- **Settle cost.** Decode in reduced/draft mode as T-0200's `blank_frame` does. Take no shot past `deadline`, and never catch `CancelledError`.
- **What the settle cannot see.** A pause followed by a later paint passes the settle. That is the job of D, T-0202's `wait` and B's guard; say so in the docstring.
- **Constants** are "chosen, not measured", module-level and read at call time.
- **Tests.** No tautological asserts. Expected pixels come from fixture colours chosen by hand.
