## Goal

S4 ("add the cheapest item") is 0/20 in every arm of T-0132 and T-0134, with 0 scrolls.
- The thoughts list the six deals visible at 1280×800 and pick the $11.50 enamel mug.
- The cheapest item, the $4.75 cotton tea towel, is below the fold.
- Telling the model the page continues did not help: arm C's "about 0.5 screens below" clause left S4 at 0/20.

The human ruled on 2026-10-23 (James): next for S4 is a **page overview tool**.

This task adds `page_overview()`, a no-argument tool offered only in live and only when opted in.
- **Called:** the executor captures the whole page (Playwright full-page screenshot, CSS scale), scaled to fit the viewport. The next step request shows that picture once, before the current frame, with a fixed fact label.
- **Coordinates:** the overview is never a frame the executor accepts coordinates against, so a click "on" it cannot happen; click and type coordinates always refer to the browser screen.
- **Pixel-first:** it is pixels of the agent's own browser, which fits pixel-first. It is not a DOM, text or accessibility assist.
- **Speech:** no narration is added.

Then a locked 2-arm A/B decides whether it ships: the T-0134c default against the default plus `page_overview`.

**Tool-set route (planner ruling R-p).** It is a separate optional file, `local_astra/toolcall/tools_v1_overview.json`: v1's five declarations, deep-equal and in v1's order, plus `page_overview`.
- `tools_v1.json` and its sha bbfc53cc… do not move. Every harness pin, the repair payloads' `tools_sha256` check (`live.load_payloads`) and the T-0134/T-0135 refusals still compare against v1.
- The new file has its own sha, pinned in its tests and in group B's arm B.
- tools_v2 (T-0111h) was rejected: it would tie S4 to five other tools and their A/B.
- A live-only declaration injected in code was rejected: the set would have no sha to state beside a number.

## Acceptance criteria

### Group A1 — capture, tool file and judge (CPU)

**A1. The tool file.**
- `tools_v1_overview.json` validates through `tools.load(path)`, and `tools.TOOLS_V1_OVERVIEW_PATH` names it.
- Its first five declarations deep-equal `tools.load().declarations`, in order. Its sixth is `page_overview`:
  - `parameters` is `{"type": "object", "properties": {}, "additionalProperties": false}`;
  - its description states facts, not instructions. It is exactly: `Shows one picture of the whole web page, scaled down to fit the screen, so you can see what lies beyond the visible part. The picture is for looking only: click_at and type_at coordinates always refer to the browser screen.` (≤ 300 characters; the reviewer checks that it gives no "when to use" instruction).
- `tools_v1.json` is byte-identical, sha256 `bbfc53ccdd80a390e55a7550805ee5aa78309287f7a1171c091f67d9db9cd707`.

**A2. The judge.**
- `live.classify(tool_text, tool_set=None)` and `live.repair_verdict(text, tool_set=None)`: `None` means `tools.load()`, and every BASE verdict is unchanged for every input.
- With the overview set, `<|tool_call>call:page_overview{}<tool_call|>` is `valid` with arguments `{}`.
  - `call:page_overview{x:1}` is `refused` (schema).
  - A not-valid `page_overview` draft is never `repairable`: it has no payload.
- `load_payloads` is unchanged and still keyed on v1's sha. The CD parity test `tests/cd/unit/test_toolcall_live_parity.py` stays green unedited.

**A3. The capture (`BrowserToolExecutor`, `page_overview`).**
- **Driver:** a new method on the driver's class, `async full_page_screenshot(max_height_css: int) -> bytes`, in `runtime.PlaywrightDriver`. It is a JPEG at CSS scale, `full_page=True`, clipped to the top `max_height_css` CSS px. It dispatches no input and does not scroll.
- **Executor:** `execute(page_overview)` follows the same rules as other non-search actions: the `ensure()` checks, the page-serial refusal, `ACTION_TIMEOUT_S`, the end-when-closed refusal and the restart rule. It reads `layout_metrics` before and after the capture.
  - **Page fits:** if `content_height ≤ 1.05 × viewport_height`, it returns `executed` with action `the whole page fits on the browser screen; no overview was taken`, and no image.
  - **Otherwise:** it returns `executed`, with action `showed the whole page (about {s:.1f} screens tall{C}) as a picture before the screen`, where `s = content_height / viewport_height` and `{C}` is `, top {MAX_OVERVIEW_SCREENS:.1f} screens shown` when clipped. `MAX_OVERVIEW_SCREENS = 4`.
  - `resolved["overview"]` is an opaque id, and `overview_of(id) -> Frame | None` returns the scaled frame once (the second read is `None`).
  - **Scaling:** aspect is kept, the image fits within the viewport's CSS size, and it is never upscaled. The `screen_max` policy applies as for frames.
- **Metrics:** if the two metric reads differ, or `scroll_y` changed, the outcome is `failed` (`the page moved during the overview`) and no image is kept.
- **Unavailable:** a driver class without `full_page_screenshot` or `layout_metrics` gives `refused` (`page overview is not available`); nothing is dispatched (the T-0134 O-2 pattern).
- **Not an own frame:** the overview frame is never registered as an own frame. It is not in the own-frame registry, `extent_of`, or `latest_frame`. A coordinate call whose frame identity is the overview's phash is `refused` like any foreign frame. The overview's phash is salted the same way, so it never equals an own frame's.
- **Echo:** the action strings follow `echo` only where coordinates appear, and they have none.

**A4. Pixel-first and the fence.** The capture reads no page text, title, URL or DOM content: only pixels and the CDP layout metrics. The A4a hostile fixture of T-0134 (spoofed `scrollY`/`innerHeight`/`scrollingElement`) still gives the true height and the true fit/clip decision.

### Group A2 — session, cli and logging (CPU, after T-0135, T-0134c and T-0142 merge)

**A5. Offering it.**

- `cli.page_overview_of(profile, args, mode)` resolves the flag, else the key, else the default, with a source.

**A6. Judging it.** The session judges every pass-1 tool commit with `live.classify(text, tool_set=<the kit's set>)`. The kit carries its `ToolSet`; `ToolKit` gains an optional field whose default is `None`, meaning v1.

**A7. Where the picture goes** (a new pure helper in `loop.py`, `place_overview(prompt, frame, text) -> Prompt`). The step request built right after an executed `page_overview` that returned an image shows it in the final user message as `ImagePart(overview)` followed by `TextPart(OVERVIEW_LABEL)`, placed **immediately before the current frame's `ImagePart`**.
- It is applied after `show_current_image`, on the frame wherever that function put it.
- `OVERVIEW_LABEL` is exactly `[Whole page, scaled to fit one screen: about {s:.1f} screens tall{C}. The next image is the browser screen.]`.
- The rest of the placement:
  - `_sent_identity`, `swap_newest_image` and `label_current_image` still act on the current frame, which stays the newest image;
  - T-0134's screen label (when on) still follows the current frame;
  - the overview appears in that one request only, never in a later step, the prefill, the captioner, ReGround pass 2, history, an `Episode` or the HUD;
  - it is never in a continuation (T-0115 Q5);
  - the settled step's `screenshot` payload is computed without the overview, so it says `"unchanged"`, and the label (if on) reads "your last action did not change it".

**A8. When it is refused** (by the session, before dispatch, `refused` with a fixed reason, nothing captured):
- the turn is blind (no image this turn): `no screen this turn`;
- the step request would carry more than `PromptBudget.max_images` (4) images with the overview: `no image slot for an overview`.

A `page_overview` call from a kit that does not offer it is judged as at BASE (`refused`, "no tool name").

**A9. Never spoken, never stored.**
- The overview label and the action string never reach a `TtsSpeak`, history, the HUD, an `Episode` or `machine.events()`.
- No narration is added; the speaking policy for computer use is unchanged.
- History stores only what was spoken.

**A10. Logging.**

- When it is not offered, no key is added.
- A request that carries an overview gains an `llm.request` key `overview: {"phash", "screens", "clipped", "width", "height"}`.
- No new span and no new log kind.

**B5. Decision rule (proposed; H-T140-1).**
- **Order:** P1 failed → `inconclusive`; P2, P3, P6, P7 or configuration → `void`; stopped early → `incomplete`.
- **Eligibility (changed from T-0134 C6b, so that one timeout cannot decide the run):** an arm is ineligible on the engine clause only when more than 2 of its 100 trials end on an engine error (transport, HTTP or timeout).
  - Each such trial, and each T-0142 `degenerate` end, counts as a failed trial in every metric.
  - The safety and acceptance clauses are as in T-0134.
- **Adopt the overview (`overview`)** only if all of these hold:
  - S4(B) − S4(A) ≥ 5 (of 20);
  - success(B) ≥ success(A) − 3 (of 100);
  - non-S4 false claims(B) ≤ non-S4 false claims(A) + 2 (of 80);
  - over-clicks(B) ≤ over-clicks(A) + 2 (of 60).
- **Otherwise:**
  - `overview unused` when S4 overview-call turns in B are under 5/20: the tool was not called, so its effect was not tested;
  - else `no change`.
- Boundaries compare with a 1e-9 tolerance.
- **Power, stated in the report:**
  - 5/20 vs 0/20 is Fisher p ≈ 0.047;
  - at n = 100 and p ≈ 0.65 the standard error is about 4.8 pp;
  - the false-claim and over-click margins of +2 are non-inferiority guards for an action that never clicks.
- Adopting a default is T-0140b, a one-line `cli` change after the human's ruling.
