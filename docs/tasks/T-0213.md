## Goal

James asked for this: "make it easy for the user to modify the settings from the UI even after they ran the command line".

Today every output-quality setting (action outcome, ReGround, visual tokens, guidance, and so on) is fixed when the Session is constructed (`cli.py:2412-2563`, `session.py:1971-2199`), so trying a different value means stopping `diffusion_gearvis session` and relaunching. After this task:
- the HUD's existing Settings gear (`hud/index.html:40-62`, `hud/src/main.js:317-369`) opens a panel listing every setting the project has measured or offered;
- each item shows:
  - its current value and source (default, profile, flag, changed in UI);
  - what it is;
  - when it is useful and when it is not, citing the A/B that measured it;
  - its kind: **next turn** (changeable from the panel), **next turn + cold prefix** (changeable, the first turn after it is slower), or **relaunch** (read-only, with the exact command);
- changeable settings are validated by the same rules `Profile` enforces at load and applied at the next turn boundary, never mid-turn;
- every change is logged with old → new, source and turn index, and every turn line carries the settings revision and a sha of the system message;
- the user can add their own instructions to the system prompt in a bounded, fixed-position block, and reset it;
- the safety rules, the tool-call format and `<|think|>` stay out of reach.

The single source of truth for the explanations is the data module `local_astra/settings_catalog.py`. The panel renders it and the docs quote it, so the two cannot drift.

## Acceptance criteria

### Group A1 — the catalog, the pure settings model, the instructions block

**A1-1. Catalog as data.** `local_astra/settings_catalog.py` defines a frozen `SettingEntry` per catalog row (§ catalog below) with:
- `key`, `label`, `group`, `kind` ∈ {`next_turn`, `next_turn_cold`, `relaunch`, `fixed`};
- `v1_changeable: bool`, `values` (the allowed values), `flag` (the exact CLI spelling), `profile_key | None`;
- `what` (≤ 2 sentences), `useful_when`, `not_useful_when`, `evidence` (task id plus a one-line result with its regime tag), `cost`.

It imports nothing from `conductor/`, `computer/` or `search/`.

**A1-2. Drift guard (catalog ↔ code).**
- Every `Profile` field that is a session/quality setting (`config.py:358-444`) and every `diffusion_gearvis session` flag (`cli.py:3326-3586`) is either a catalog `key` or in an explicit `NOT_A_SETTING` tuple with a reason (for example `--data-dir`, `--sink`, `--dry-run`, `--serve-hud`).
- A new flag or field in neither fails a test.
- Every `values` tuple equals its config constant (`VISUAL_TOKENS`, `LIVE_FEEDBACK_CHOICES`, `ACTION_ECHOES`, `LIVE_GUIDANCE_VERSIONS`, `SEARCH_CHOICES`).
- Every `default` equals the `LIVE_DEFAULT_*`/`DEFAULT_*` constant in `config.py:41-122`.

**A1-3. Pure validation reuses the load rules.**
- `local_astra/conductor/live_settings.py` defines `LiveSettings`, a frozen snapshot of the v1-changeable values plus `user_instructions: str` and `rev: int`.
- `validate(current, changes, *, mode, web) -> (LiveSettings | None, refusals)` applies a change set **atomically**: all or nothing.
- It refuses an unknown key, a `relaunch`/`fixed`/`later` key, a wrongly typed value (the `type(v) is bool` / `type(v) is int` strictness of `config.py:451-640`), and every cross-rule `Profile` enforces:
  - `action_outcome` with `live_feedback = off`;
  - `overview_frame` with `reground`, `auto_overview` or `page_overview`;
  - `reground_visual_tokens` with ReGround off.
- The refusal text is the config module's own `*_refusal()` string. No rule is re-implemented.
- A valid set returns `rev + 1`; an empty or no-op set returns the same rev.
- No I/O and no clock.

**A1-4. The instructions block.**
- `prompt_builder.PromptBuilder` gains `user_instructions: str | None = None`.
- When it is non-empty, `system_message()` appends, as the **last** part, `USER_INSTRUCTIONS_HEADER + "\n" + text`. `USER_INSTRUCTIONS_HEADER` is a literal: "The user's own instructions follow. Apply them unless they conflict with anything above."
- `validate_instructions(text) -> str | None` refuses:
  - more than `MAX_USER_INSTRUCTIONS = 1000` code points, after stripping surrounding whitespace;
  - control characters other than `\n`;
  - any substring of the pinned chat template's special-token texts (`<|`, `|>`, `<turn`, `turn|>`, `<|think|>`, `<|tool_call>`, `<|image|>`; the list is read from the template pin, see Q4).
- **Negative:** with `None` or `""`, `system_message()` is byte-identical to BASE in every mode (off, dry_run, live, each guidance version). `<|think|>` stays the first system token: the thinking flag still rides on the template kwarg, untouched.

**A1-5. Negative (A1).** `cli.py`, `session.py`, `turn_machine.py`, `contracts/**` and `hud/**` are byte-identical.

### Group A2-apply — changing a setting (server; blast radius high)

**A2a-1. Contract.** `AstraSettingsSet` (client→server, `astra.settings.set {rev: int, changes: dict[str, value], stop_turn: bool = False}`) joins `CLIENT_TO_SERVER`. Unknown fields are malformed.

**A2a-2. Route.**
- `hud_server.route` hands the message to the session on the one pump.
- A stale `rev` (≠ current) is refused with `refused=[{key:"*", reason:"stale"}]` and changes nothing.
- The session replies to every client with `astra.settings.state`.

**A2a-3. Apply only at a boundary (the core invariant).**
- A validated change becomes `pending`. It is applied when the machine is IDLE with no live generate, prefill, tool execution or ReGround pass (`MachineState.active_generate is None`, `active_prefill is None`, no running `_executions`).
- If that holds when the change arrives, it applies at once.
- With `stop_turn = true` and a turn in flight, the session first submits the same stop `astra.turn.stop` uses (T-0193), then applies at IDLE.
- **Every request of one turn carries one settings revision.** The prefill and the generate of a turn render byte-identical system messages, and their `mm_processor_kwargs` are identical.
- No change is applied between a turn's steps, its ReGround pass 2 or its completion check.

**A2a-4. What applying does.**
- It sets the Session attributes (`session.py:2151-2199`) and `VllmClient.visual_tokens` (`llm_client.py:212,266`) on the main client and the caption client.
- It rebuilds `self.prompts` with the new `tool_guidance` (via `cli._tool_guidance`'s logic, passed in as a callable or a precomputed table, never importing `cli`) and `user_instructions`.
- It switches ReGround's pass-2 client.
- It keeps history, frames, memory, assists, the log toggle, the browser and its page. Nothing is published as a reset.

**A2a-5. Logging.**
- The session log gains the kind `settings.change`, one record per applied set: `{rev, changes: {key: {old, new}}, source: "ui", turn_seq, applied_at: "immediate"|"after_turn"|"after_stop", system_sha12_old, system_sha12_new}`.
- `user_instructions` is logged as its sha12 and length only, never its text (Q5).
- A refused set writes one `note {what: "settings refused", refusals}`.
- The next turn line carries the new `settings_rev`, `system_sha12` and `instructions_edited`.

**A2a-6. Not toggled per request.** No setting changes `thinking`. `<|think|>` stays first. The panel offers no thinking switch, and the catalog row explains why.

**A2a-7. Negative (A2-apply).**
- Without an `astra.settings.set`, every golden from A2r-5 is byte-identical.
- `turn_machine.py` is byte-identical (no new event or command).
- No `TtsSpeak` is caused by a settings change.
- Thinking never enters history.
- No clip enters history.
- Memory is untouched (`forget_since` is never called).

## Implementation notes

**Where things live today:**
- Session settings are constructor attributes (`session.py:1971-2199`). Their cross-checks raise in `__init__` (`session.py:2006-2128`). The apply path must enforce the same rules: A1-3 runs before anything is mutated.
- The system message is `persona + CLOSE_THE_THOUGHT + SPOKEN_STYLE + UI block (+ NATIVE_TOOL_INSTRUCTIONS + tool_guidance)` (`prompt_builder.py:630-646`). The persona is `DEFAULT_SYSTEM_PROMPT` (`session.py:171-174`, via `SessionConfig.system_prompt`, `session.py:940`).
- The guidance text depends on the version, on web mode and on the wait tool (`cli._tool_guidance`, `cli.py:1647`). Under `--no-web`, v3 and v4 carry v2's text (`prompt_builder.py:85-125`).
- ReGround's second client exists only when the crop budget differs from the main budget (`cli.py:2437-2445`). For a runtime switch, `cli` pre-builds it whenever the mode is live: one more HTTP client, no request. `Session.aclose` already closes it.
- `visual_tokens` is a plain attribute read per request (`llm_client.py:212,266`). The caption client shares `llm` (`session.py:2226-2231`).
- Safety is code, not prompt: the card/password guard (`computer/executor.py:356-359,1335`, `fence.py`), ask-first (`toolcall/ask_first.py`), the egress fence and the checkout stop. No edit to the system message can weaken them. Say so in the UI (C-2), and do not invent a "locked safety paragraph".
- Restart (T-0162) resets in place (`RESET_CLEARS`/`RESET_KEEPS`) and wipes memory. Settings must not reuse it (H-T213-1).
- Precedent for a runtime session switch handled outside the machine: `AstraLogToggle` (`hud_server.py:1084`). Follow its shape.

**Constraints:**
- The turn machine stays pure and untouched. The boundary check lives in `session.py`.
- Changing the system message, the tool set or the image budget costs a cold prefix once. Changing it per request would cost it every turn (CLAUDE.md, the `<|think|>` rule). Hence A2a-3.
- A setting that would silently do nothing is refused, never accepted (`.claude/rules/conductor.md:15`). Outside live, every live-only row is shown read-only with the reason.
- All model and catalog strings are set with `textContent`. No network. Fonts and icons are system-only.
- Never log the instructions text (it may hold personal data); log its sha and length.
- Do not edit tests to fit behaviour. If a golden must move for the hello insertion, that is the named spec change in A2r-5.

**The system-prompt design (chosen: a bounded user block, not raw editing).**
- **Editable:** one "Your instructions" block, appended last with a fixed header, ≤ 1000 code points, with no chat-template special-token text.
- **Visible but not editable:** the persona, `CLOSE_THE_THOUGHT`, `SPOKEN_STYLE`, the UI block, `NATIVE_TOOL_INSTRUCTIONS` and the guidance. Raw editing is rejected, because these parts are pinned by tests and A/Bs (T-0055, T-0174, T-0191, T-0201) and the native tool-call format depends on them.
- **Reset to default** sends an empty string; the system message is then byte-identical to BASE.
- **Fixed for the session:** the block changes only through Apply at a boundary, and each turn line records `system_sha12` and `instructions_edited`.
- Editable persona/name: later (D), pending James's view (Q3).
