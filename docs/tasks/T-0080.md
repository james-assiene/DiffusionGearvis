## Human design (2026-10-08, agreed)
The assistant answers unconstrained, with thinking on as always. If it wants a tool, its answer contains a tag (`<cc>`; `<genui>` reserved). A second
request then applies CD with the grammar selected by the tag. Latency matters. The human expects the constrained pass to mostly adjust the model's
own draft, so fast settings should suffice. This program measures that expectation rather than assuming it.

## Goal
Make the two-pass tool-call mode measurable and then choosable.
- (a) The v1 tool schemas, a pure router and a call scorer that are runtime-safe, plus the tool grammars with the thought-handling variants and their |S|.
- (b) A small eval set of the real tools and a two-pass driver.
- (c) One reviewed GPU launch that picks, by a pre-registered latency-aware rule:
  - how the constrained pass handles the always-on thought;
  - which grammar scope it uses;
  - which decoding arm it uses: `end_projection`, `perstep_mar` or `perstep_mar_qargmax` at the T-0079 knobs, or "only when the draft is invalid".
- (d) Later, on main: the conductor uses the result.

## Thought handling (design; c chooses among T1, T2 and T4)
Facts from the pinned template (sha 36e3a42e…):
- With thinking on, the prompt ends `<|turn>model\n` and the model writes `<|channel>thought\n…<channel|>` and then the answer.
- `<|channel>` = 100 and `<channel|>` = 101 are single ids (diffgemma-fa SPEC §3.6).
- `strip_thinking` removes thoughts from assistant content. An assistant `reasoning` field is rendered only with `tool_calls`.
- The plugin's automaton starts at `A_0` at the first generated token, so the grammar must cover everything the pass-2 output contains.

The variants:
- **T1 — regenerate the thought.** Same prompt as pass 1. Grammar = `100 · Σ_name{1,8} · 107 · FREE* · 101 · ["<cc>"] · CALL`, with
  FREE = every id except 100, 101, the end ids, PAD and 105. Cost: the thought is re-denoised under per-step CD on every canvas. Risk
  (SPEC §3.6): the joint decoder chooses where `101` falls, so the split point is logged.
- **T2 — forced empty thought.** Same prompt, so the prefix cache is warm by construction. Grammar = the existing header
  (`channel_header=True` admits `100 45518 107 101`) `· ["<cc>"] · CALL`. One canvas. Pass 2 carries none of pass 1's reasoning
  except through a seeded draft (T-0081).
- **T4 — continue after the tag.** Pass-2 messages = pass-1 messages plus a final assistant message whose content is pass 1's committed
  answer text up to and including `<cc>` (no thought, so `strip_thinking` leaves it intact). Send `continue_final_message: true,
  add_generation_prompt: false`. Grammar = `CALL` with no header. The prefix is identical up to `<|turn>model\n`.
- **T3 (rejected for now) — continue with the thought in the prompt.** This needs a per-request `chat_template` override, which is a
  change to the pinned template and a server flag (`services/vllm.sh`), so it would be its own task (question Q5).
- **Rejected:** thinking off for pass 2 (`<|think|>` is the first system token, so the whole prefix cache misses; CLAUDE.md), and the
  thought as a literal in the grammar (|S| ≈ thought length; bucket 512).
