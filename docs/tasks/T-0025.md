its panel seam) and T-0012 (merged 7d5eb15, `AssistState` / `AstraAssistToggle` / `AstraFrameText` /

## Goal
T-0012 gave the Conductor one honest authority for non-pixel assists — all off, ingress-filtered,
frozen per turn, logged in `turns.jsonl` — but nothing on the screen can turn one on, and nothing
tells the user which are on. This task adds the other half: an assist panel that mounts through
T-0008's `panels.js` seam, shows one row per `AssistFlags` kind, sends `astra.assist.toggle` when the
user ticks a box, renders the badge **the server sent** (never one the page computed), and gates
every outbound `astra.frame.text` behind the last server-confirmed flag set, rate-limited in lockstep
with the frame pipeline and size-capped. The honesty rule the whole task exists for: with no box
ticked, no assist text leaves the page — not buffered, not queued, not "just once at startup"
(docs/01 D12a, `.claude/rules/perception-memory.md`, CLAUDE.md "off unless the user turns them on,
and every turn logs which were on"). It also records, in code and in the panel, the platform fact
that a browser tab cannot read another tab's DOM: kinds with no extractor are disabled with their
reason instead of being tickable into a regime the page cannot honour.

## Acceptance criteria

Positive:

1. **It mounts through the seam and cannot break the page.** `hud/src/assists/index.js` exports
   `mount(host)`; `mountPanels()` (T-0008 criterion 10) reports it in `mounted`, and the other two
   specs stay in `missing`. `mount({})` — no `document`, no `send`, no `subscribe` — returns without
   throwing, renders nothing and sends nothing, so a host that predates this seam degrades instead of
   taking the socket down (T-0008 criterion 10: "a loader that throws is caught and leaves every
   other panel and the socket working").
2. **One row per kind, in `AssistFlags` field order.** The panel renders exactly four rows, keyed
   `data-assist-kind` ∈ `page_text, pdf_text, cells, at_spi` in that order (T-0012 amendment A3:
   the order is `AssistFlags` declaration order, mirrored here from
   `local_astra/contracts/perception.py`), each with a checkbox, `data-assist-on`,
   `data-assist-available` and `data-assist-reason`.
3. **On-ness comes from the server, never from the click.** A row reads `data-assist-on="true"` only
   after an `astra.assist.state` whose `flags[kind]` is true. Clicking a box sends the toggle and
   marks the row *pending*; if no echo arrives the row stays off. (docs/02 §5: `astra.assist.state`
   is "the echo of the effective assist flags".)
4. **The badge is the server's string, verbatim.** `[data-assist-badge]`'s text equals
   `astra.assist.state.badge` character for character. The panel contains no code that builds a badge
   from flags — `AssistFlags.badge()` lives in Python and there is exactly one derivation of it
   (T-0012 criterion 8). *Checkable:* a state message whose `badge` disagrees with its `flags`
   (the wire permits it) renders the server's `badge` and the server's `flags`, and the page invents
   no reconciliation.
5. **No confirmed flag → no assist text, ever.** This is the headline negative expressed as
   behaviour: with no `astra.assist.state` received, or one with all flags false, the panel's send
   function is never called with an `astra.frame.text`, whatever an extractor returns and however
   often it is offered. The gate keys on the confirmed flags, not on the DOM checkbox and not on a
   locally optimistic copy. (CLAUDE.md pixel-first; T-0012 criterion 11.)
6. **Unticking purges immediately, on the page too.** Unticking sends the toggle, stops extraction
   for that kind, and drops any text already extracted or queued for it: text extracted while a kind
   was on must not reach `send` after the untick, even if the send was already scheduled. This is the
   page-side mirror of T-0012 criterion 4 / ruling A11 ("unticking purges immediately, including from
   the in-flight turn's payload").
7. **Rate-limited alongside frames, single-flight, drop-not-queue.** At most one `astra.frame.text`
   per kind per `1000 / MAX_FPS` ms, where `MAX_FPS` is *imported from* `hud/src/frames.js` (T-0008's
   value, itself pinned against `perception/policy.MAX_FPS` by
   `tests/unit/test_hud_constants_parity.py`) — the panel defines no second rate constant. A slow
   extractor causes a drop, never a queue; at no point are two extractions in flight for one kind.
   Sent/dropped counters are displayed (`data-assist-sent`, `data-assist-dropped`).
8. **A kind with no extractor cannot be turned on.** Each row is `data-assist-available="false"` with
   a human-readable `data-assist-reason` unless an extractor is registered for the *live* capture
   source; an unavailable row's checkbox is disabled and no click path on it produces an
   `astra.assist.toggle` that sets its flag true. v1 registers **exactly one** extractor: `page_text`
   over the synthetic canvas source (`?source=canvas`), whose text the page itself drew and therefore
   genuinely knows. `pdf_text`, `cells` and `at_spi` — and `page_text` over a real
   `getDisplayMedia`/`getUserMedia` stream — register none, and their reason names why (a browser tab
   cannot read another tab's DOM; those kinds arrive with the native daemon, docs/01 D6, M2+).
9. **Size cap, honestly marked.** Text longer than `MAX_TEXT_BYTES` (UTF-8, panel constant, 32 KiB)
   is truncated at a code-point boundary and carries the in-band marker `TRUNCATION_MARKER` at its
   end, and the truncation is counted. `AstraFrameText` has no `truncated` field and adding one is a
   contract task, so the marker is in `text` where the model can see it; a silent truncation, which
   would let the model claim it read a whole document, is the failure this criterion forbids.
10. **The wire is the contract's.** Every message the panel emits decodes through the real
    `local_astra.contracts.codec.decode` into `AstraAssistToggle` / `AstraFrameText`: the toggle
    carries all four booleans explicitly (a whole flag set, never a per-kind merge — T-0012
    implementation notes), `AstraFrameText.source` equals the live capture's source and `ts_ms` is the
    extraction time in ms. The panel's own whitelist `ASSIST_CLIENT_TYPES` is exactly
    `["astra.assist.toggle", "astra.frame.text"]` and is a subset of `protocol.CLIENT_TO_SERVER`.
11. **End to end into `AssistState`.** Driving the real page in headless Chrome against
    `tests/fakes/hud_server.HudStub`: with no box ticked the stub records zero `astra.frame.text`;
    after the stub echoes `page_text: true`, the recorded messages, decoded by the production codec
    and fed to a fresh `local_astra.perception.assists.AssistState`, yield `texts_for()` containing
    the page's sentinel under `page_text` and nothing else, and `state.dropped` is all zeros. The
    page and the Conductor half are shown to agree through the codec, not through a JS mirror of it.

## Implementation notes

- **The seam is the whole reason this task is separate.** Read T-0012's "Ownership collision" section
  before starting: it predicted this file set. `main.js` gains `send`/`subscribe` on the host and
  nothing else; if the panel wants anything more from the page, stop and return to the planner rather
  than growing the diff.
- **The whitelist is not widened.** `protocol.js` `CLIENT_TYPES` is T-0008's statement about T-0008's
  code and two tests pin it. The panel declares its own `ASSIST_CLIENT_TYPES` and validates its own
  egress against it; `main.js` hands out the raw `socket.send` and never names an assist type.
- **Keep the pure part DOM-free** (`gate.js`), exactly as T-0008 keeps `state.js`/`protocol.js`
  importable in node; DOM lives in `index.js` and the extractor registry. Inject `send`, `now` and
  the extractor set — that is what makes criteria 5–9 testable without a browser.
- **Contracts are frozen and strict** (`extra="forbid"`): an extra field on `astra.frame.text` is a
  `Malformed` on the server and an `astra.error` back, not a warning. Send exactly the contract's
  fields.
- **`AssistFlags` field order is the kind order** (`ASSIST_KINDS = tuple(AssistFlags.model_fields)`,
  `perception/assists.py`), and the badge spellings (`dom`, `pdf`, `cells`, `a11y`) are **not** field
  names. Do not build a mapping from one to the other in JS; the page never needs it (criterion 4).
- **Landmine, `line-through`:** `tests/hud/state.test.mjs` fails on any `line-through` /
  `text-decoration: line-through` / `<s>` anywhere under `hud/`, because the played/unplayed
  distinction is a named T-0007 spec gap. Style a disabled row with opacity or a dimmed label.
- **Landmine, the 60 s horizon:** see criterion 16. The server keeps the newest text per kind within
  60 s **of the turn's timestamp**; a page that sends once is pixel-only again a minute later while
  the badge still says otherwise.
- **Landmine, bytes vs UTF-16 units:** T-0008 ruling R11. Use `TextEncoder` for the cap.
- **Loopback only, no build step, no dependency.** `.claude/rules/perception-memory.md` and T-0008
  criterion 12. The panel injects its own `<style>`; it does not edit `styles.css`.
- `hud/` is excluded from ruff and mypy — there is no automated style gate on the JS. Keep it small
  and boring; the reviewer reads it.
- Do not edit a test to fit the implementation. The three T-0008 test amendments in "Owned files" are
  **specified here, in advance, with their new predicates**; anything beyond them is a finding for the
  reviewer (CLAUDE.md).
