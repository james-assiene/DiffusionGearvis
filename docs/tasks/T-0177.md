## Goal

In a live session the user chooses what Gearvis looks at with a combo box in the "What I see" pane: "Gearvis's browser" (the default, as today) or "Shared screen" (the tab, window or camera the HUD is sharing).

**The session is the source of truth.**
- Each request's images are published to the HUD as the exact bytes sent to the model.
- The panel shows those images and nothing else, in every mode.
- So the panel can no longer show one feed while the model sees another.

**When "Shared screen" is chosen:**
- The user turn carries the shared frame, labelled as the user's shared screen and not as the browser.
- Browser actions still act on the agent browser. After the first browser action, or after a click/type refused for being read off the shared image, the step images follow the browser, and the panel follows them.
- Live features that reason about browser frames never treat a shared frame as one: coordinates, freshness, the repeat guard, outcome comparison, overview frames and page facts.

**Unchanged:**
- The system prompt and thinking.
- Every request body under the browser source.
- Non-live model input.

## Acceptance criteria

### Group A: the wire, the choice, and step 1

**A1. Wire contract** (docs/02 §5 spec delta; the fake is changed in the same PR). Three strict `Contract` models go in `contracts/protocol.py`, are added to `AstraMessage`, `ASTRA_MESSAGE_TYPES` and the direction sets, and are mirrored with field tables in `hud/src/protocol.js`. All are decoded strictly: an unknown field means the message is malformed.

- **`astra.vision.select`** (client to server only): `source: Literal["browser", "shared"]`.
- **`astra.vision.state`** (server to client only):
  - `source: Literal["browser","shared"]`, the current choice;
  - `choices: list[Literal["browser","shared"]]`;
  - `replay: bool = False`.
- **`astra.vision.frame`** (server to client only):
  - `turn_id: str`;
  - `step: int ≥ 1`;
  - `source: Literal["browser","shared"]`, the source of the images actually sent;
  - `blind: bool`;
  - `images: list[VisionImage]`, at most `Budget.max_images`;
  - `history_images: int ≥ 0`;
  - `replay: bool = False`.
- **`VisionImage`:**
  - `identity: str`;
  - `kind: Literal["window","screen","camera","overview"]`;
  - `width ≥ 1`, `height ≥ 1`;
  - `jpeg_b64: str | None`. It is null only when the message would exceed `codec.MAX_MESSAGE_BYTES`, and then `omitted: "too_large"` is set.

`blind: true` with non-empty `images` is malformed. The codec round trip in `tests/contract/test_protocol_codec.py` passes unchanged.

**A2. The fake.** `tests/fakes/hud_server.py` learns the three types: it records `astra.vision.select`, and `vision_script(...)` builds state and frame messages.

**A3. The choice belongs to the session.**
- `Session` holds one vision choice; in live it defaults to `"browser"`.
- `hud_server.route` hands `astra.vision.select` to `session.apply_vision_select(message)`, behind the hello fence (`no_hello` before hello).
- In live, every routed select publishes one `astra.vision.state` to every connection, redundant ones included (T-0043 echo). The page's combo comes from the echo, never from the click.
- A change of choice writes one `vision.select {from, to}` record. A redundant select writes none.
- Outside live, a select changes nothing. It publishes `astra.error(code="vision_source_unavailable")` to the sender only, and no state is ever published.

**A4. Hello.**
- In live, the hello reply gains `astra.vision.state` as its last message, after everything T-0037/T-0043/T-0162 put there.
- Outside live, every hello reply is byte-identical to BASE.

**A5. Frozen per turn.** The choice is read once, when the turn opens, at the same point the assist flags are frozen (`_frozen_turn`). A select during an open turn is echoed and applies from the next turn.

Adversarial row: select "shared" during THINKING of a browser turn; that turn's later step requests carry no shared frame.

**A6. Step 1 under "shared"** (supersedes H-T111c-5 for this choice only). In live, with the turn's choice `shared`:
- `snapshot_frame` takes the frame from `perception.get_frame(<shared source>, at_ms)` and never calls the live browser's `frame()` for that snapshot.
- HUD scene changes append shared frames under T-0059's rules.
- `<shared source>` is the `Source` of the newest HUD frame (screen, window or camera), else `config.source` (H-T177-5).
- If there is no frame, or the frame dates from before the last reset, the turn is blind: the existing no-image wording, and no fallback to the browser.
  - Adversarial row: the browser has a distinctive frame ready, and its bytes appear in no request body.
- `FrameGeometry.source` is the frame's own `Source`, never `WINDOW`.

Under `browser`, B6 stands verbatim: a distinctive HUD frame's bytes appear in no body.

**A7. The shared label.** When a step's current image is a shared frame, the final user message carries one `TextPart` right after it, through `loop.label_current_image`:
- `SHARED_LABEL_SCREEN = "[This screenshot is the user's shared screen now, not your browser; click_at and type_at cannot act on it.]"` (screen or window);
- `SHARED_LABEL_CAMERA = "[This image is the user's camera now, not your browser; click_at and type_at cannot act on it.]"` (camera).

Rules for the label:
- It is placed whatever `live_feedback` is.
- It never contains "browser screen", an extent clause or an outcome clause.
- It does not match T-0174 A2's forward-pointing regex.
- It never appears on a prefill, a caption request or a ReGround pass-2 body.
- The `llm.request` record's `live_label.text` is this text.

**A8. Overview never touches a shared step 1.** With the turn's choice `shared`:
- `_decide_overview_frame` dispatches nothing, counts `refused`, and notes `overview frame: shared screen`.
- `auto_overview` refuses the same way, before capture.
- `page_overview` called while the current image is shared settles `refused` with `SHARED_OVERVIEW_REASON`.
- The turn line's overview count keys are unchanged.

**A9. Negative: the browser source and non-live are byte-identical to BASE.** A differential over BASE..TIP, ignoring only the A10 `vision_source` key, covers:
- prefill, generate and step bodies;
- turn lines;
- `llm.request` records.

It runs in three regimes:
- live, browser, no select ever;
- live after a select to shared and back to browser between turns;
- off and dry_run with HUD frames.

The system message bytes are identical across browser and shared turns (the prefix property; `<|think|>` first).

**A10. Logged per turn (live only).**
- The turn line gains `vision_source: "browser" | "shared"`.
- `frame_source` keeps `"window"` or `"none"` under browser. Under shared it reads the frame's `Source` value, or `"none"` when blind.
- Non-live turn lines are unchanged.

**A11. Assists and egress unchanged.**
- T-0111g B14 stands under both sources in live (H-T177-6).
- No new socket. The zero-non-loopback test and the scoped egress exceptions are untouched.

### Group B: step images, refusals, the feature fences, and the published frame (after Merge T-0177-a)

**B1. Follow the action** (H-T177-3). With the turn's choice `shared`:
- After an executed `scroll`, `press_key`, `click_at` or `type_at`, step k+1 shows the browser frame through T-0111g B8's swap.
  - The shared image is replaced, never kept beside it: the model never sees both images in one message.
  - The label is the browser label set (`LABEL_UPDATED` or `LABEL_UNCHANGED`, per `live_feedback`).
- A `google_search` or a refused non-coordinate call leaves the shared image and its label in place.
- Once the step image is a browser frame, the rest of the turn behaves exactly like a browser turn.
- The next turn starts again from the frozen choice. An action never changes the choice itself.

**B2. Coordinates read off a shared image.** A `click_at` or `type_at` whose request's current image is a shared frame is refused before ReGround pass 2, the T-0137 guard and `execute`:
- The refusal is `refused` with `SHARED_FRAME_REASON = "the image you read those coordinates from is the user's shared screen, not your browser; click_at and type_at act only on your browser"`.
- Nothing is dispatched, and no `tool.reground` request is sent. The card is `refused` with the same reason.
- Step k+1 shows a fresh browser frame (B8's failed/timeout path, bounded by `LIVE_FRAME_TIMEOUT_MS`), labelled `LABEL_NOW` and never `LABEL_UPDATED`, with no outcome clause.
- If no fresh frame can be taken, the shared image stays and a note is written.
- Ask-first (T-0107a) and decline (T-0107e) keep precedence.

Rows in both directions:
- Too wide: a click on the browser frame after a switch is executed.
- Not caught: a click read off the shared image at step 1 is refused with this reason, not with B9's.

**B3. Freshness.**
- B9 is unchanged for browser frames.
- The executor's `frame not from this browser` check is not weakened.

**B4. Outcome comparison (T-0136).**
- An action is measured only when its before and after frames are both browser frames.
- Otherwise it is unmeasured with the new reason `shared_frame`, which goes in the note only.

**B5. Page facts (T-0174 B1/B2).**
- These facts appear only on executed browser actions.
- A row asserts that a shared step-1 request carries no `page` or `screenshot` fact before any action.

**B6. Repeat guard (T-0137).**
- `_guard_screen` returns `None` for a call whose image is a shared frame. Shared frames never count as screen visits.
- Adversarial row: three step-1 clicks off the same shared frame, across three turns, produce no `recurring` stop.

**B7. The published frame** (the panel's only source, in all modes). For each of these requests the session publishes one `astra.vision.frame`, but only when the request's `(source, [image identities], blind)` differs from the last one published:
- the turn's prefill;
- the step-1 generate;
- each tool step;
- a T-0172 re-ask;
- a T-0171 resend;
- a degenerate retry.

How the frame is built and published:
- It is built from the same `Prompt` object the request body is built from.
- `images` are the final user message's `ImageParts`, in order. A frame riding on a held history image is included instead.
- **Key row:** each `jpeg_b64` decodes to exactly the bytes of the body's corresponding data URL.
- A blind request publishes `blind: true, images: []`.
- No frame is published for the captioner, a ReGround pass-2 crop (H-T177-7) or a pre-reset turn.
- The session log's `wire.out` record is redacted. A row asserts that no base64 of the frame appears in the log file.

**B8. Droppable.**
- Each connection's outbox holds at most one unsent `astra.vision.frame`; a newer one replaces it.
- It is never the reason a connection is closed, or a non-droppable message is refused (the T-0128c canvas pattern).

**B9. Hello and reset.**
- The hello reply's last message is the latest `astra.vision.frame` since the last reset, with `replay: true`. In live this comes after A4's state. If there is none, it is absent, so a non-live hello with no frame stays byte-identical to BASE.
- A reset clears the slot.
- The choice survives a reset (T-0162 D-3).

**B10. Negative.**
- A9's differential still holds at B's merge.
- The only new wire output under browser and non-live is `astra.vision.frame`.

### Group C: the HUD (after Merge T-0177-a; concurrent with B)

**C1. The combo box.** A `<select data-vision-source>` in the "What I see" pane, labelled "Looking at", with these options:
- `browser`: "Gearvis's browser";
- `shared`: "Shared screen", or "Shared camera" for a camera capture.

Behaviour:
- It is rendered only after an `astra.vision.state` arrives, so it never shows outside live.
- Its value is always the last echo.
- `shared` is disabled unless a capture is running.
- Changing it sends `astra.vision.select`.

**C2. Auto-switch on Share** (H-T177-1, ruled).
- After a user-initiated Share starts a capture in a live session, the page sends `select shared` once.
- A capture started by `?source=canvas|synthetic` at load never auto-switches. Adversarial row: the existing live HUD rigs keep the browser source.
- When the capture stops while shared is the echoed choice, the page sends `select browser`. Stopping covers Mute, `m`, the reset's stop, and the track's `ended` event.

**C3. The panel shows the session's frame** (H-T177-2, ruled).
- `#preview` shows only `astra.vision.frame` images: the newest large, the earlier ones as thumbnails.
- It is never fed by the local capture: `encode` no longer touches `#preview`.
- A blind frame shows "No image was sent for this question".
- With no frame yet, live shows "Nothing sent yet: Gearvis looks when you ask", and other modes show the existing T-0154 empty text.
- A reset clears the panel.
- This supersedes the T-0008 local thumbnail.

**C4. The caption.** `[data-capture-caption]` describes the image shown: `<source name> · <W>x<H> · turn <id> step <k>`, plus `· +N earlier images` when `history_images > 0`.
- The source names are "Gearvis's browser", "Shared screen", "Shared camera" and "Page overview".
- With no frame, the caption is empty.
- This supersedes T-0154 A6.
- `#capture-size`, the frame counters and the Share button keep reporting the capture.
- The `.live` badge shows only while the newest panel image is shared and a capture is running.

**C5. Negative.**
- Nothing else on the page changes.
- No requests go off loopback.
- The only new message the page sends is `astra.vision.select`.

## Group B review rulings (2026-10-28, orchestrator, after reviewers A and B)

- **B-R1. A reset forgets the published key.** After a reset, the first request that carries an image publishes it even when its capture identity equals the last one published before the reset (a static start page after `reset_page`). A row pins it.
- **B-R2. LABEL_NOW is read once.** After a shared refusal, step k+1 is labelled `LABEL_NOW`; the next executed browser step returns to `LABEL_UPDATED` with its outcome clause. A row pins step k+2.
- **B-R3. The refused step's payload.** A `shared_refused` step's payload keeps `screenshot: "updated"` when a fresh browser frame replaced the shared image (`loop.screenshot_payload`'s definition: the next step's image was replaced), and `"unchanged"` when none could be taken. It never calls `_guard_outcome`: an earlier guard step's `no_change`/`outcome` is never rewritten by a refused call. T-0187 reuses this.
- **B-R4. The B2 refusal comes before the T-0137 guard.** A refused shared call never enters the repeat guard's steps or the turn line's `repeat_guard` counts.
