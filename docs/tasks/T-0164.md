## Goal

James sees GenUI cards in the HUD thread that look like the "Option A" column of the approved mockup (`genui-mock/mock-{dark,light}.png`, committed by C as a fixture):
- one quiet card on the HUD's own tokens in both themes;
- headings, body text and captions on the page's type scale;
- key/value rows with a hairline between them;
- lists with hairlines between rows;
- nested Cards as tonal tiles;
- form fields with the label above the control;
- choice pickers as chips;
- buttons on the tonal pair.

To get there, the vendored `@a2ui/lit` 0.11.0 renderer and its shadow DOM are replaced by a small renderer of our own (`hud/src/ui/render.js` plus `engine.js`). It walks the component tree that `UiGate` validated and `protocol.js` decoded, renders light DOM through `textContent` only, morphs each surface in place canvas after canvas, and keeps the form data model and the action round-trip exactly as `action.js` defines them today.

What does not change:
- the wire, the Conductor, the gate, the prompt;
- the honesty rules: only validated surfaces render; the model's words are shown verbatim; nothing is invented (H-T154-6 "style only"; ruling 2026-10-17 "cards are illustrations, gate-made buttons only send their label back"); older cards are inert (H-T154-4);
- the loopback-only guarantee.

The vendored bundle and its build tooling are then deleted (group D).

## Acceptance criteria

Each criterion names the design or test-plan item it serves. "The fixture" is `tests/fixtures/a2ui/genui_census_20261027.jsonl` (see Tests to write).

### Group A — the renderer core (new files only, not wired)

A1. **Engine contract, compatible with the bridge.** `hud/src/ui/engine.js` builds a processor that `hud/src/ui/bridge.js` drives **unchanged** (T-0024 criteria 4 and 7, T-0154 B5):
- `processMessages([message])` applies one A2UI message.
- It throws per message, as the vendor did, on: a second `createSurface` for an existing id; an `updateComponents` or `updateDataModel` for an unknown surface; a `createSurface` whose `catalogId` is not `GATE_CATALOG_ID`. The last one renders nothing; the bridge logs it.
- `onSurfaceCreated(handler)` hands `{ id }` to the handler, synchronously, inside the `createSurface` call.
- The engine exposes `dataModelFor(surfaceId)`. It returns the surface's data model iff that surface's `createSurface.sendDataModel` is `true`, and `null` otherwise. This is the vendor's `getClientDataModel()` semantics, read from the bundle on 2026-10-27, and what `AstraUiAction.data_model` carries today.
- `render.js` and `engine.js` import in node with no document; there is no DOM access at module top level (T-0024 criterion 2).

A2. **Every advertised kind renders.** All 15 kinds in `ui_instructions.ADVERTISED_ORDER` render from real props: Text (variants h1–h5, body, caption), Column, Row, List, Card, Divider, Icon, Tabs, Modal, Button, CheckBox, ChoicePicker, TextField, Slider and DateTimeInput. The props are those of `local_astra/ui/schemas/a2ui_v0_9_1/catalog.json`. The prompt promises exactly these 15 kinds to the model, so a kind the page cannot draw is a broken promise (T-0044 criterion 3).

A3. **The fallback for the rest is nothing.** `Image`, `Video`, `AudioPlayer`, any kind not in the catalog, a `FunctionCall` value and a template `ChildList` (`{path, componentId}`) render nothing. None of these appears in the census. Each produces exactly one log line per (surface, kind) per page, not one per canvas. The siblings of such a component still render (H-T164-3, H-T164-6).

A4. **Verbatim, through `textContent` only.** For every surface in the fixture, the rendered card contains, as `textContent` (or as `value`/`placeholder` for inputs), every string the model wrote on a component reachable from `root`, byte-equal, and in tree order. The oracle is the fixture's `expected_texts`, computed by the test-author in Python from the gate's own reachability and never from the JS. Adversarial strings each render as that exact string and create no element: `<img src=x onerror=alert(1)>`, `</div><script>`, `&amp;`, `**bold**` (markdown stays literal, as today: H-T164-4), a newline, RTL text, an emoji, and a 10 000-character word. "Never render an unvalidated surface" and "the model's words verbatim" come from CLAUDE.md and T-0154 C1.

A5. **Nothing synthesised.** The rendered text of a card is exactly the multiset of the model's strings: Text, button labels, option labels, tab titles, field labels. No other non-whitespace character appears. A surface with no `root` yet renders an empty card frame that carries `data-a2-empty` and no words. The vendor's "Loading surface…" is retired (H-T154-6). Adversarial: the t9 card renders 10 strings (title plus 9 rows), 0 checkboxes and 0 numbers the model did not write.

A6. **Dangling references and cycles.** A child id that no component defines renders nothing, and its siblings render in order. This is today's `test_a_dangling_child_reference_keeps_the_siblings_and_synthesises_nothing`, moved down to the unit layer. The following each terminate and render each component at most once on any root-to-leaf path, logging one line:
- `a → b → a`;
- a self-reference;
- a Card whose `child` is its own ancestor;
- a 200-deep chain past the depth bound;
- a 10 000-child Row.

The gate's topology check should prevent cycles. The renderer does not rely on it (defence in depth).

A7. **Morph in place, not re-creation** (T-0154 B4 and B6, T-0024 criterion 7 as amended).
- Per surface, the card root node is the same object (`===`) across every canvas.
- Per component id, its DOM node is the same object across canvases while its kind is unchanged. A kind change replaces only that component's subtree.
- Re-applying an identical canvas performs **zero DOM mutations**: no element is created, no child is inserted, moved or removed, and no `textContent`, attribute or `value` is written. Adversarial: count with the fake DOM in node, and with a `MutationObserver` in Chrome (B).
- A canvas that adds k components creates nodes only for those k.
- A reference the model no longer makes detaches its node.

A8. **The user's state survives a morph.** A later canvas that re-sends a component unchanged does not overwrite any of these:
- text typed into a TextField with a literal `value`, with focus and selection kept;
- a chip picked in a ChoicePicker;
- a ticked CheckBox;
- a moved Slider;
- a chosen date;
- the selected Tab.

Adversarial: type in the flight card's "Origin city", deliver the next 5 canvases of that surface, and the typed text, the caret and `document.activeElement` are unchanged.

A9. **The data model and bindings** (Q11's renderer round trip).
- `updateDataModel` at `/` or at a nested path updates every path-bound value: Text `{path}` and input `{path}`. A missing `value` deletes the key, per v0.9.1.
- A user edit to a path-bound input writes the new value at that path: TextField and DateTimeInput a string, ChoicePicker the **list** of selected option values, CheckBox a boolean, Slider a number.
- Literal-valued inputs keep their state locally and write nothing.
- The engine provides `drop(surfaceId)`, which removes a surface's DOM and state; this is the hook T-0162 D will call. It is tested here and wired by nobody in this task.
- Adversarial (quiz fixture): pick option `b` on q1 and `a` on q3, then click "Check answers". The action's resolved `context.answers` is `{"q1": ["b"], "q3": ["a"]}`, and `dataModelFor("lesson_1")` holds the same answers, because the quiz sets `sendDataModel: true`. The same edits on a surface without `sendDataModel` give `dataModelFor(...) === null`.

A10. **Actions** (T-0024 criterion 9, through `action.js` **unchanged**). A click on a Button whose `action` is `{event: {name, context}}` calls `onAction` exactly once with `{name, surfaceId, sourceComponentId, timestamp, context}`:
- `surfaceId` is the id inside the messages, i.e. the gate's rewritten `turn-…`;
- `timestamp` is an ISO-8601 string from `Date.prototype.toISOString`;
- `context` is resolved one level deep: a `{path}` value becomes the data-model value, and a literal passes through verbatim.

The gate's `__gate.clicked` with `{label}` arrives verbatim. Negative (adversarial for "a handler that sends on anything"): none of these calls `onAction`:
- a Button with no `action`, or with a `functionCall` action;
- typing, picking a chip, ticking, sliding;
- switching tabs, opening a Modal;
- a keyboard focus change;
- scrolling.

A11. **No network and no markup sinks.**
- The renderer creates no `img`, `picture`, `source`, `video`, `audio`, `iframe`, `object`, `embed`, `link`, `script`, `style` or `a` element.
- It sets no `src`, `srcset`, `href`, `action`, `formaction`, `poster` or `on*` attribute, and no style value containing `url(`.
- It never calls `attachShadow`.

Adversarial: an `Image` whose url is `https://example.com/x.png`, a `data:` URL, and a Text holding a URL, all with a fake DOM whose `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `setHTMLUnsafe`, `attachShadow` and `src`/`href` setters throw a named assertion. A source scan of `hud/src/ui/**` (strings and comments stripped) finds none of `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `setHTMLUnsafe`, `document.write`, `DOMParser`, `createContextualFragment`, `attachShadow`, `eval`, `Function(`, `fetch(`, `XMLHttpRequest`, `WebSocket`, `EventSource` or `sendBeacon`. The page stays loopback-only (CLAUDE.md, T-0024 criterion 10).

A12. **Accessibility semantics.**
- Buttons and chips are `<button type="button">`.
- A ChoicePicker is a group of keyboard-operable options with `role="radio"`/`aria-checked` for `mutuallyExclusive` and `aria-pressed` (or checkbox semantics) for `multipleSelection`. The mock's `aria-pressed` inside a `radiogroup` is not copied.
- Every input has an accessible name taken from the model's own words: a Row-supplied label (a `<label>` element) or the component's `label` (`aria-label`). The page invents no name.
- Tabs expose `tablist`/`tab`/`aria-selected`, and arrow keys move between tabs.

A13. **Negative.** `hud/src/ui/bridge.js`, `action.js`, `fence.js`, `a2ui.js`, `index.js`, `card.css` and `style.css`, plus `hud/vendor/**`, are byte-identical to the group's base. `tests/hud/ui_bridge.test.mjs`, `ui_action.test.mjs` and `ui_fence.test.mjs` are unchanged and green. The page renders exactly as before; A wires nothing.

### Group B — the swap (the page uses our renderer)

B1. **The page renders with our engine.** `hud/src/ui/index.js` mounts `engine.js` behind the unchanged `bridge.js` and `action.js`. The newest-surface rule (`isRendered`) and the per-surface `data-ui-canvas-idx` stay as they are. `dataModel()` now reads `engine.dataModelFor(bridge.surfaceId())`.

Over a full `test_hud_ui_surface` session (CDP, real Chrome):
- no request for any path under `/vendor/`;
- zero `<a2ui-surface>` elements;
- `Element.prototype.attachShadow` is called 0 times (instrumented before page scripts);
- every card is light DOM: `[data-ui-surface] > [data-a2ui-root]`.

This amends T-0024 criterion 1 ("the renderer is the vendored bundle") by name.

B2. **T-0154's thread rules hold, re-keyed by name** from `<a2ui-surface>` to `[data-a2ui-root]`:
- B4: one root per surface id, in the card slot of the turn its id names, or in a loose article;
- B5: per-surface canvas order;
- B6: 50 further messages leave the same root, article, slot and action-card nodes `===`;
- B8: older wrappers are `inert`, and both a synthetic click and a CDP click on an older card send nothing;
- B10: a reconnect replay adds no card;
- B11: with `./ui/index.js` absent or throwing, the thread still renders text and action cards.

Adversarial (Chrome): a `MutationObserver` on t1's root records **0 mutations** while the stub re-sends t1's last canvas 3 times (A7 in the browser).

B3. **Only validated surfaces render (T-0024 criterion 4, adversarial, kept).** These render nothing and create no `[data-a2ui-root]`: A2UI JSON smuggled through spoken text, an unknown message type, a malformed `astra.ui.surface`, and a `createSurface` with a foreign `catalogId`.

B4. **The action round trip is the same on the wire.** A CDP mouse click on the newest card's gate button sends exactly one `astra.ui.action`, which the production codec (`local_astra.contracts.codec.decode`) decodes. Its fields:
- `name == "__gate.clicked"`;
- `context.label` equals the model's label;
- `context.a2ui` holds `sourceComponentId` (the button id) and an ISO `timestamp`;
- no other top-level key.

The quiz's "Check answers" sends a resolved `context.answers`, and `data_model` is the surface model. In the rehearsal session (real `HudServer` and `Session`, fake LLM), the click opens a second turn whose transcript is byte-equal to the one pinned today (`[ui] __gate.clicked {"label":…}`).

B5. **One light-DOM card sheet.** `hud/src/ui/card.css` is rewritten for the renderer's own classes. It is loaded once per page from the page's own origin (a `<link>` added in `mount()`, or the existing CSS-module seam adopted into the document), never per surface. It holds tokens only (no colour literal, no fallback), no `content:` string, and no `text-transform` on model text.

`hud/src/ui/style.css` (the `--a2ui-*` bindings) is deleted, and `injectBasicCatalogStyles` and the per-shadow-root adoption go with it. This amends T-0154 C1 by name: "adopted into each surface's shadow root" becomes "one page sheet; no shadow root exists". As a working baseline, B ports the mock's option-A sheet as is; C tunes it to parity.

B6. **No egress and no audio, behaviourally** (T-0024 criterion 10). Over every Chrome session in B's modules, `Network.requestWillBeSent` sees only loopback URLs. No `<audio>` element and no `AudioContext` is constructed.

B7. **Wire and Conductor unchanged (negative).** `git diff <BASE>..<TIP> -- local_astra/ tests/fakes/ hud/src/protocol.js hud/src/panels/thread.js services/` is empty. `BASE` and `TIP` are pinned literals per `.claude/rules/tests.md`. `UiGate`, the prompt block, the contracts and the codec are untouched.

## Implementation notes

1. **What the vendor did that you must keep** (read from `@a2ui/lit`/`web_core` 0.11.0 on 2026-10-27; see `hud/vendor/a2ui-v0_9.bundle.js` while it exists):
   - per-message throws: `Catalog not found`, `Surface … already exists`;
   - `getClientDataModel()` includes only surfaces with `sendDataModel`;
   - `resolveAction` resolves context values **one level deep**;
   - `dispatchAction` builds `{name, surfaceId, sourceComponentId, timestamp: new Date().toISOString(), context}`;
   - the `Text` with no markdown renderer shows raw text.

   `bridge.js`'s comments describe the throw sites it is built around. Do not change `bridge.js`; satisfy it.
2. **The mock is a reference for the look, not the code to ship.** `genui-mock/mock.src.html` is a useful starting point and fine to adapt, but it has known gaps that the criteria close:
   - it re-renders from scratch (A7, A8);
   - its Button hands the component to `onAction` instead of the action shape (A10);
   - inputs are not bound to the data model (A9);
   - it loads `data:` and same-origin images (A3, A11);
   - its chips put `aria-pressed` inside a `radiogroup` (A12);
   - TextField uses its label only as a placeholder, with no accessible name (A12, C2);
   - Tabs use `replaceChildren` on each switch: inside the renderer's own subtree this is allowed (T-0154 note 2), but the selected tab must survive morphs (A8);
   - `.ga-kv + .ga-kv` uses a `margin-top: -12px` hack (C1 measures the result, not the hack).
3. **Root unwrap.** Like the mock, a root that is a Card, or a Column holding exactly one Card, renders into the card frame instead of drawing a card inside the card (H-T164-8). The frame is the page's, as `.card-wrap` is today; it holds no words.
4. **Morph strategy is yours.** A keyed reconcile by component id is the obvious shape. Constraints: never `replaceChildren` on the thread, an article, the slot or the wrapper (T-0154 B6 and note 2), and never write a property whose value is unchanged (A7 counts writes). User-edited input values belong to the user until the model changes that component's own `value` prop to something new. For a path-bound input the data model is the source of truth, and a later `updateDataModel` wins.
5. **The DOM hooks tests key on (the contract):**
   - `[data-ui-surface]` and `[data-ui-canvas-idx]` on the wrapper (unchanged);
   - `[data-a2ui-root]` on the card root;
   - `data-a2-id` (component id) and `data-a2-kind` on every component's outer element;
   - `data-a2-empty` on a rootless card.

   Class names are free. Component ids go into attributes through `setAttribute` only.
6. **Load order and degradation.** `mount()` must still never throw, and must still return `{mounted: false}` with one log line when there is no document or no `cardSlot` (T-0154 B11). The renderer has no async load step any more, so the "bundle did not load" branch goes away. Keep the same-origin, no-new-transport rule for the sheet (T-0024 criterion 3).
7. **Older cards** stay `inert` on the wrapper (H-T154-4). Their inputs keep what the user did, as history.
8. **Theme.** Only tokens from `hud/styles.css`, which resolve through `data-theme`; there are no theme blocks in `card.css` except the mock's two `:root[data-theme="light"]` fill swaps. If C2 needs a token value changed, C stops: `styles.css` is not owned.
9. **Icons.** Use a small inline-SVG set built with `createElementNS`, for the names the catalog lists that you choose to support. An unknown name renders nothing. The vendor's ligature font was never installed (today an Icon shows its name as text), so this is not a regression.
10. **Landmines.**
    - The rules/tests.md reduced-motion block for any Chrome row that reads computed style right after a change.
    - A source-grep guard matches prose: strip strings and comments.
    - Scope pins use literal SHAs.
    - Activation is three things in one commit: remove `pending`, set Status, and name the modules here.
    - Chrome rows run serially per module (one Chrome).
    - `test_hud_ui_surface.py` documents real-time CDP polling (T-0008 R3).
11. **Effort.** A is about 2 days (renderer plus about 30 node rows). B is about 2 days, mostly the re-keys. C is about 1.5 days. D is about half a day. A's test-author and implementer can start today with no file conflicts.
