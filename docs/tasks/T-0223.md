## Goal

A demo set for the education demo: ten one-page student attempts (5 maths, 5 physics; first/second-year university), each written out as a plausible student solution with exactly one realistic mistake, rendered to look handwritten (handwriting font, ink colour, lined paper, slight jitter, hand-drawn diagrams), saved as one PDF and as one PNG per page. Then a report-only GPU run shows each page to Gearvis as a shared screen with a typed question and records whether its answer locates the planted mistake.

The problems are our own wording (no textbook text is copied). Group A is CPU only; group B spends GPU time through `/launch`.

## The ten attempts (ground truth)

Each attempt is 6–12 lines, solved the way a student would, with the mistake in one line and the rest consistent with it (the wrong final answer follows from the mistake).

| id | problem | the mistake (ground truth) | correct result |
|---|---|---|---|
| M1 | ∫ x·e^{2x} dx by parts | takes v = 2e^{2x} (differentiates instead of integrating dv = e^{2x} dx) | (x/2)e^{2x} − (1/4)e^{2x} + C |
| M2 | tangent line to y = sin(x²) at x = √π | derivative written as cos(x²), the chain-rule factor 2x missing | slope −2√π |
| M3 | area between y = x and y = x² on [0, 1], with a sketch of the region | integrates x² − x (lower minus upper) and reports the area as −1/6 | 1/6 |
| M4 | eigenvalues of [[2, 1], [1, 2]] | characteristic polynomial written (2−λ)² + 1 (sign of the off-diagonal product), so concludes complex eigenvalues | λ = 1 and 3 |
| M5 | y′ = 2y, y(0) = 3, with a sketch of the solution | from ln y = 2x + C writes y = e^{2x} + C (an added constant instead of a factor), so y(0) = 3 gives C = 2 and y = e^{2x} + 2 | y = 3e^{2x} |
| P1 | block on an incline (angle θ = 30°, μ_k = 0.2, m = 2 kg) sliding down, with a free-body diagram | normal force written N = mg instead of mg cos θ, so friction and the acceleration are wrong | a = g(sin θ − μ cos θ) ≈ 3.2 m/s² |
| P2 | ball thrown horizontally at 5 m/s from a 20 m cliff, time to land and distance, with a trajectory sketch | puts the horizontal 5 m/s into the vertical equation (20 = 5t + ½gt²), giving t ≈ 1.6 s and x ≈ 7.9 m | t ≈ 2.02 s, x ≈ 10.1 m |
| P3 | equivalent resistance of R1 = 6 Ω in series with (R2 = 3 Ω ∥ R3 = 6 Ω), and the current from 12 V, with a circuit diagram | adds the parallel pair as 3 + 6 = 9 Ω | R_eq = 8 Ω, I = 1.5 A |
| P4 | Atwood machine with m1 = 3 kg and m2 = 5 kg, acceleration and tension, with a pulley diagram | divides the net force by m2 only (forgets the whole system's mass) | a = g/4 ≈ 2.45 m/s², T ≈ 36.8 N |
| P5 | pendulum (L = 1 m) released at 45° from vertical, speed at the bottom, with a diagram | height drop taken as L cos θ instead of L(1 − cos θ) (at 60° both give 0.5 m, so 45° is used) | v = √(2gL(1 − cos 45°)) ≈ 2.40 m/s |

## Acceptance criteria

**Group A — content and rendering (CPU).**
1. `demos/handwritten/attempts.json` holds the ten attempts: id, title, the problem statement, the attempt lines (each line a string with its own mistake flag, exactly one line flagged), the ground-truth mistake in one sentence, the correct result, a list of judge keywords for group B (words or symbols a correct diagnosis must mention, pre-registered here, e.g. P1: `["cos", "normal"]`), and a list of `false_blame_keywords` (phrases that would mean a correct line was blamed).
2. `scripts/demo/render_handwritten.py` renders each attempt to `demos/handwritten/out/<id>.png` (at least 1600 px wide, legible) and all ten to `demos/handwritten/out/attempts.pdf`, one page each, in that order: a handwriting font (open licence, vendored with its licence file under `demos/handwritten/fonts/`), dark-blue ink, a lined-paper background, small per-line jitter in position and angle, the problem statement printed at the top in a plain font (as a worksheet would), and the diagrams drawn in a hand-drawn style (matplotlib's xkcd mode or equivalent). It is deterministic (fixed seed): two runs give byte-identical PNGs. It runs with `uv run --with matplotlib --with pillow python scripts/demo/render_handwritten.py` (no new project dependency).
3. Every attempt's arithmetic is consistent with its one mistake, and every correct result in the table is right (the test checks the numbers it can: P1–P5 and M3–M5 by computation).
4. Nothing under `local_astra/` changes.

**Group B — the GPU check (report-only, `/launch`).**
5. A harness shows each page to a real Session as a shared-screen frame (the HUD frame path, at the 1120 visual-token default), types "Here's my attempt. Can you check it and tell me where I went wrong?", with the user instructions "You are a patient tutor. Point to the line with the mistake and explain why it is wrong, then give the corrected step." set through the settings path (T-0213), and records the spoken answer, n = 3 per page (30 turns), search off, tools off.
6. A turn **locates** the mistake when its answer contains every judge keyword of its page (case-insensitive) and does not call a correct line wrong (pre-registered "false-blame" keywords per page, listed in attempts.json). The report gives per page k/3 located, the verbatim answers, latency (time to first spoken word, p50/max), and the full regime. Report-only: no bar; the reading line says how many of the ten pages were located in at least 2 of 3 turns.
7. The run follows the binding harness lessons (synthetic run dir for the eval rows; not-run = errored; regime fields; provisional marks).
