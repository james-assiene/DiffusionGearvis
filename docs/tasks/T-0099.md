## Goal
The H-T84-2 repair (one seeded constrained native T4 pass 2 on an invalid native draft that names a v1 tool; T-0091
`live.repair_request`/`repair_verdict`, wired by T-0092c, span `tool.repair`) has never fired on a real draft. Re-judging every recorded
native pass-1 draft with `live.classify` (planner, 2026-10-14): 0 invalid of 170 routed (131 offline in T-0084e/f, 39 live at 4b0bd92);
rule-of-three 95 % upper bound ≈ 1.8 % per draft. The only invalid drafts on record are `<cc>` format (dev 3, test 12), which cannot be fed
to the native repair without rewriting them. Offline, forced repair on valid drafts was already measured (T-0084f test
`cd_always:native/T4/named/perstep_mar+seed`: pass 2 equalled the draft 80/80, e2e p50/p90 438.6/577.4 ms).

This task adds `scripts/gpu/t0099_repair_live.py`, running two arms through a real `Session` in one boot:
- **arm S (stress):** 30 new pre-registered honest requests whose natural answer is out of schema, k = 3 each — the model's own invalid
  drafts, the real repair on them, its latency and failure modes;
- **arm F (forced):** the 40 dev tool cases with the repair forced on already-valid drafts — the repair's floor latency and agreement on
  the live path, and a barge-in during a repair on the real engine.
Nothing under `local_astra/` changes; the forcing is a harness-scoped patch (H-T99c).

## Acceptance criteria
Notation: *invalid draft* = pass 1's kept `tool` commit judged `repairable` by the **unpatched** `live.classify`, re-run by `build_report`
over the logged commit text — never read from the session's `tool.call` record.

1. **The stress set** `tests/eval/toolcall_stress/cases.jsonl` (test-author; human-approved H-T99a; pinned by sha256 in its `MANIFEST.json`
   and in the harness): 30 cases in six categories —
   - **K-in (6):** an in-enum key asked in another spelling ("hit Return", "press Esc", "press control-c", "press the spacebar", "press page
     down", "press the down arrow"); gt = the enum combo;
   - **K-out (6):** a key not in the enum ("press F5", "save with Ctrl+S", "reopen the closed tab with Ctrl+Shift+T", "Alt+F4", "Ctrl+F",
     "zoom in with Ctrl+Plus"); no gt; expected outcome: no executed action;
   - **S-extra (4):** a scroll with an amount or target ("scroll down three pages", "scroll to the very bottom", "scroll up 500 pixels",
     "scroll back to the top"); gt = the direction;
   - **T-hard (6):** `type_at` text with double quotes, a backslash, braces, a newline, accents or emoji, and one text ≥ 400 characters; gt =
     the dev target's bbox, the text and `press_enter`, as `score.exact`;
   - **C-pixel (4):** "click at pixel (x, y)" on a 1280×800 screen with x > 999 or y > 999 in pixels; gt = the bbox of the element at that
     pixel;
   - **U-under (4):** "type X into the field" with no Enter instruction; *rescued* = valid, inside the bbox, text equal; `press_enter`
     reported, not scored (pre-registered here).
   Screens and targets come **only from the dev split**; no test-split screen; no case reuses an existing case's user text.
2. **The run** (`main`): one boot, concurrency 1, typed turns, one fresh `Session` per (case, repetition, arm), built as T-0093 builds it
   (real `VllmClient`; fake STT, TTS at 300 ms/word, audio and perception; the case's screen as the frame; no recollections); every session
   tools-on `native:bbfc53ccdd80:dry_run`, repair on. Order: arm S (30 cases in file order × k = 3, repetition-major), then arm F (40 dev
   tool cases in file order). No tools-off arm. Refusals (exit 2, before any socket) are T-0093's, plus: the stress file is not the pinned
   one.
3. **Forcing is scoped to arm F (H-T99c).** Per arm-F session the harness replaces `local_astra.toolcall.live.classify` with a wrapper that
   returns `Verdict("repairable", name, arguments, "forced: valid draft (T-0099 arm F)", query_problem)` when the real verdict is `valid`,
   and the real verdict otherwise; the original is restored in a `finally`. The manifest records `forced: true|false` per session. After the
   run `live.classify is` the original object.
4. **Barge-in during a repair (arm F).** On arm-F cases that spoke a prefix at 4b0bd92 (in run order), a `UserSpeechOnset` is submitted once
   the turn is SPEAKING **and** the live generate is the turn's repair request, until 3 are delivered (delivered = `outcome ==
   "interrupted"`, the line carries a call, and the session log shows the repair request aborted). Fewer than 3 makes this row "unread"; it
   does not void the run.
5. **Hard gates (H-T99b; read only if all hold, reported per arm).**
   - **G1 run valid:** every line `native:bbfc53ccdd80:dry_run`; no repair-off note; 0 `error` outcomes, 0 timeouts, 0 session failures;
     exactly one turn line per session; the forced marker only in `forced: true` sessions.
   - **G2:** nothing but the spoken prefix is voiced (T-0093 J4/J17), and no `TtsSpeak` source comes from a repair request's commits (R9).
   - **G3:** 0 `ToolExecute` on interrupted turns. **G4:** 0 `ToolExecute` before the turn's own drain. **G5:** 0 stale terminals reached
     the machine.
   - **G6:** at most one `tool_repair` request per turn.
   - **G7:** no `ToolExecute` for a call whose final status is `refused`, `repair_failed`, `repair_timeout` or `cancelled`; every executed
     call with `source == "repair"` is schema-valid under `tools_v1`, re-judged from the log.
   - **G8:** every repair ends with a verdict before its 3000 ms deadline, or as `repair_timeout` with its abort logged; none open at
     session close.
6. **Reported, pre-registered, not gated.** Arm S: (a) yield = invalid drafts / routed tool turns, by category and by parse reason;
   nameless or refused drafts, unrouted turns and turns with no call counted separately; (b) repairs fired; (c) outcomes by final status
   (J6); (d) `tool.repair` p50/p90 (nearest-rank, J9) with n; (e) rescue rate = repaired-to-valid / repairs fired, Wilson 95 %;
   (f) rescue-exact = repaired-valid and exact (U-under by criterion 1's rule) / repairs fired on gt-bearing categories; (g) **coercion** =
   K-out turns whose repair produced a valid call, with the combo chosen; (h) action latency p50/p90 for repaired calls. Arm F: repairs
   fired / routed; agreement (repaired call equals the draft); exact against gt; `tool.repair` p50/p90 with n, labelled "floor on valid
   drafts, not repair latency on invalid drafts"; repair_timeout count; criterion 4's row.
7. **Reading rules (H-T99b).** Rescue and rescue-exact are **read** only with ≥ 10 repairs fired on gt-bearing arm-S turns; otherwise
   "insufficient yield (n = …)", the yield with its upper bound, and no conclusion on rescue. Arm-F numbers never enter an arm-S figure. A
   forced repair is never counted as an invalid draft, a repair on an invalid draft, or a rescue.
8. **Adversarial: no leak of the forcing.** In arm S, a repair whose pass-1 draft re-judges `valid` voids the run (`integrity: repair on a
   valid draft outside arm F`); so does an arm-S `tool.call` record carrying the forced marker.
9. **Report.** `build_report(run_dir)` reads only `turns.jsonl`, `sessions/*.jsonl` and `manifest.json`; `render_markdown` writes
   `report.md`; the harness writes `report.json`. The regime block records the commit, the live system prompt's sha256 (from the first
   session's `llm.request`), the stress-set sha, the tools sha, k, the arm sizes and T-0093's engine regime keys.
10. **Negative.** Over the task's closed range (`BASE..TIP` from its merge commit, per `.claude/rules/tests.md`) zero diff under
    `local_astra/`, `services/`, `tests/fakes/`, `tests/eval/toolcall/`, `scripts/gpu/t0093_toolcall_live.py` and
    `scripts/locked/t0093_live.sh`; `local_astra/bench/thresholds.py` and `docs/03-test-plan.md` unchanged; the T-0093 gates and H-T96
    unchanged.
11. **Write-up.** `docs/cd/toolcall-repair-live.md` holds the Method and this pre-registration **before** the run; Results and the regime
    table are appended after it, every number with its regime.

## Implementation notes
- **Elicited vs fabricated.** Arm S's drafts are the model's own on honest out-of-schema requests: real repair on real errors, under a
  deliberately shifted input distribution — the arm-S yield is **not** a production invalid-rate estimate (that bound is 0/170). Arm F is
  the seeded path's floor on the live path. Corrupting drafts in a mock is plumbing only (smoke row), never in the doc's numbers.
- **The forcing seam.** `Session._judge_tool` calls `live.classify` through the module attribute (`session.py:105`, `:1933`);
  `repair_verdict` calls `_judge` directly, so the repair's own verdict is never forced. Patch per arm-F session; restore in `finally`. No
  session flag (that would be its own high-blast task).
- **Reuse, no edit.** Import from `t0093_toolcall_live.py`: `_MeteredLlm`, `_PlaybackOnly`, `_CaseMemory`, `_fake`, `_wait_idle`,
  `check_loopback`, `read_metrics`, `_NoRedirect`/`_OPENER`, `_Turn`, `_voiced`, `_executes_before_drain`, `_stale`, `_percentile`,
  `_dist`. Write your own case loader and runner; do not reuse `_one`. H-T96's prefix gate does not apply; do not write `prefix_ids.jsonl`.
- **Landmines.** guard_bash blocks bash commands naming `scripts/gpu` and `scripts/locked`: Edit tool, `git commit -a`, never indirection;
  the smoke row calls `main` in-process. Loopback only. No `seed` on the diffusion path: repetitions are independent samples. A ≥ 400-char
  `type_at` text may not fit the repair (`repair_request` cuts the seed at 256; `REPAIR_OPTIONS.max_tokens` 256): expected refused or
  repair_failed, never a truncated execute (G7); the write-up reports it as a repair limit. Every `query_problem` stays log-only (H7).
- **Ownership hook:** each owned path sits alone at the start of its bullet.
- **No GPU run in implementation.** The run is a separate `/launch` after H-T99a and after T-0098b ships.
