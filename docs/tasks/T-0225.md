# T-0225 — A prompt library for "Your instructions to Gearvis"

**Status:** merged 2026-11-01 at 2ca43fe6 (tip a7e73407); was in progress (impl dbaec300, tests activated 4e14552a). **R-1 (verifier flake, root-caused):** a rig race, not a product bug: `Page.until` in `tests/integration/test_hud_rehearsal.py` treats an evaluate exception (`{"__exception__": ...}`, truthy) as "condition met", so `connected()` can return before the HUD loaded and the first gear click lands before main.js attached its listener. Fix in the shared rig: `until` never counts an exception as success, and `connected()` is null-safe; the rig module joins the owned files (James, 2026-11-01: "it would be good to have some prompt library: 1) the default 2) the education tutor 3) the ai gaming companion 4) the browser use specialist. A user should have the possibility to create, save and reuse their own prompt.")

## Goal

The Settings panel's "Your instructions to Gearvis" box (T-0213 C) gains a library: four built-in prompts and the user's own saved prompts. Choosing one fills the box; **Apply** works exactly as today (`astra.settings.set {user_instructions}`, applied at the next turn). Saving stores the box's text under a name in the page's own storage (this browser, this HUD address), so it is there next time. No server, wire, prompt-builder or logging change: the library only fills the box.

## The built-in prompts (exact text)

1. **Default** — empty text (no added instructions; same as Reset to default).
2. **Education tutor** — "You are a patient tutor. When I show you my work, find the line with the mistake, point to it, and explain why it is wrong. Ask me a guiding question before giving the fix, then give the corrected step and the correct final answer. Speak in plain words, not symbols, and keep each reply short."
3. **Gaming companion** — "You are my gaming companion. I share my game screen with you. Answer out loud in one or two short sentences, like a friend sitting next to me. Read what is on the screen before you answer. When I ask what to do, give one clear plan and the reason. Do not use your own browser. Use google_search only for game facts you are not sure about, and say where you found them."
4. **Browser specialist** — "When I ask you to do something on a website, do it yourself in your own browser, one step at a time, and check the screen after each step. Do not narrate every click. When you are done, tell me in one sentence what you did and what you see. If you are stuck, say what is blocking you. Always ask me before buying, sending, posting or deleting anything."

Each is under the 1000-character limit and passes `prompt_builder.validate_instructions`.

## Acceptance criteria

1. Under the instructions box, a **Prompt** picker lists the four built-ins (in that order, marked built-in) followed by the user's saved prompts (alphabetical). Choosing one fills the textarea with its text; nothing is sent until **Apply**. The box's current state (draft, pending, refusal) behaves exactly as in T-0213 C.
2. **Save as…** stores the current textarea text under a name the user types (1–60 characters, trimmed); saving under an existing user name replaces it after an in-page confirmation (no `window.confirm`); built-in names cannot be overwritten. **Delete** removes the selected user prompt after an in-page confirmation; built-ins cannot be deleted.
3. Storage: `localStorage` under one key (`gearvis.prompts.v1`, a JSON list of `{name, text}`); every read and write wrapped so a blocked or corrupt store leaves the built-ins working and shows one inline note ("Saved prompts are unavailable in this browser"). At most 50 user prompts; texts over the limit cannot be saved (the counter and the existing inline reason apply).
4. All text set via `textContent`; names and texts are never interpreted as HTML. Keys typed in the name field do not reach HUD shortcuts.
5. Negative: no new client→server message; the wire protocol, `hud/src/protocol.js`, `hud/src/ws.js`, `hud/vendor/**` and all `local_astra/**` are byte-identical; the settings panel's other controls are unchanged; the page requests nothing off loopback.
7. **Export / Import** (James, 2026-11-01: "Middle option looks good, do it"). **Export** downloads the user's saved prompts (not the built-ins) as `gearvis-prompts.json` (`{"version": 1, "prompts": [{"name", "text"}]}`) through a blob link, entirely in the page. **Import** reads such a file from a file picker (`<input type=file accept="application/json,.json">`, max 256 KB); valid entries (name rules, text ≤ 1000 code points, no special-token strings) are merged into the saved prompts, an imported name that already exists replaces it only after one in-page confirmation for the whole import, built-in names are skipped, and the 50-prompt cap applies; an invalid file changes nothing and shows its reason inline. A summary line says how many were added, replaced and skipped.
6. README: one short paragraph under "Settings" naming the four built-ins and how to save your own (stored in this browser).
