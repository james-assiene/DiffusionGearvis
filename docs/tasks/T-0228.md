# T-0228 — the search tool is named `web_search`, not `google_search`

**Status:** planned 2026-11-01 (James: "Instead of google_search, the name of the search tool should be web_search"). **Ruling (James, 2026-11-01): after the release.** v0.1 ships with `google_search`; T-0228 starts after 2026-11-02. Order: A (CPU), then B (harness), then C (GPU run, `/launch`). On a C FAIL, A is reverted.

**Cost (planner probe, scratch copy of b4b121c1, repo untouched):**

- **Files:** about 35 product and doc files; about 95 test files.
- **Trial rename:** 575 Python tests failed across 83 modules, plus 21 HUD node tests. `tests/cd` and `tests/eval` stayed green. The integration and browser suites were not run.
- **Repair payloads:** they rebuild on CPU in seconds. `web_search` gets 38 automaton states (`google_search` had 41), bucket 64 for both.
- **Tokens:** with the pinned tokenizer both names are three tokens (`google _ search` / `web _ search`). The pinned chat template names no search tool.
- **Effort:** about 1.5 days of agent work for A, about 0.5 day for B.
- **GPU:** 60–90 minutes for C.

## Goal

The model is offered a search tool named `web_search` and calls it. The session answers through the existing search backend. The HUD, the guidance and the settings help all say `web_search`. Nothing else changes in the tool set, the request bodies or the behaviour.

Old session logs and recorded fixtures still say `google_search` and stay readable. Replays and the HUD's tool display map the old name to the new one for display and judging. The live judge never aliases: a model that emits `google_search` after the rename is refused and counted.

## Acceptance criteria

**Group A (CPU, the rename):**

1. `tools.SEARCH_TOOL == "web_search"` (a new constant in `toolcall/tools.py`), and every product comparison against the search tool name reads it. No `"google_search"` string literal is left in `local_astra/` outside `toolcall/legacy/` and the `LEGACY_TOOL_NAMES` table; a grep test checks this.
2. The four search-on sets (`tools_v1.json`, `tools_v1_overview.json`, `tools_v1_wait.json`, `tools_v1_overview_wait.json`) declare `web_search`. Each is byte-identical to its HEAD (b4b121c1) version except for the name string; the description, schema and order are unchanged. Each set's sha is pinned anew in one place.
3. Negative: the four `*_nosearch.json` files are byte-identical to HEAD and keep their shas (e.g. `tools_v1_nosearch.json` b22b9b74…). The T-0215 rule still holds with `web_search`: nosearch is the on-set minus the search tool, the rest byte-identical and in order.
4. `payloads/native_T4.json` is regenerated by `scripts/build_toolcall_payloads.py` (its only writer). `live.load_payloads()` accepts it:
   - the manifest's `tools_sha256` equals the new v1 sha;
   - there is one payload per v1 name, including `web_search`, with bucket ≤ 128;
   - a default `--tools live` kit has repair on (not `PayloadStale`).

   `CALIBRATION_SHA256` is unchanged (the calibration is BFCL-only).
5. `live.classify`:
   - a valid `call:web_search{query:…}` is `valid`;
   - a malformed `web_search` draft is `repairable`;
   - `call:google_search{…}` is `refused` with `no tool name`, and is never repaired, executed or aliased (H-T228-1);
   - with search off, `web_search` is refused with `NOT_DECLARED` (T-0215 R-1, unchanged).
6. Session (docs/02, T-0114/T-0125). A `web_search` call goes to `kit.search`. It behaves exactly as `google_search` did: the results, cap, card, held `proposed` card, 10 000 ms deadline, "search did not answer" text, and the T-0111g B8 "search leaves the screen alone" kind. Only the name changes, in `tool.call` records, on the wire and in the HUD.
   - The two executors keep `dry_run` for the search tool only.
   - `score.exact`/`query_problem` apply the keyword rule to `web_search`.
   - `score`'s tool-syntax check (T-0086 S5) matches both `web_search` and `google_search`.
7. Prompt text says `web_search` in:
   - `S_SOURCE_GUIDANCE`;
   - the "Gaming companion" built-in prompt (`hud/src/settings/prompts.js`, T-0225);
   - the settings-catalog help, the config/CLI refusal messages and `--help`.

   The v1–v3 guidance texts are byte-identical to HEAD (they do not name the tool). With search off, v4 still drops S_SOURCE (T-0215). `scripts/gen_readme_options.py --check` passes, so README.md is regenerated.
8. The warm-up (T-0092) warms `web_search` with the same query (`weather`) and the same record tag scheme.
9. HUD: the Tools pane and the tool-call panel show `web_search "…"` (cut at 60) and the `N results (…)` summary. A replayed old record with `name: "google_search"` renders the same way under the old name; it does not fall back to the generic row.
10. Replays:
    - `scripts/replay_thought_calls.py` maps a logged `google_search` tail through `tools.LEGACY_TOOL_NAMES` before `classify`, and reports `legacy_name: true` on that row. Its verdicts on `tests/fixtures/t0135` are HEAD's.
    - Negative: `replay_completion_check.py`, `replay_announced_calls.py`, `replay_live_guidance.py`, `replay_screen_reminder.py`, `replay_degeneracy.py` and `replay_ui_gate.py` give byte-identical output at HEAD and at the tip on every fixture they have.
11. `local_astra/toolcall/legacy/` holds byte-exact frozen copies of HEAD's four search-on sets and of `native_T4.json`. `tools.load_legacy(...)` reads them with the same validation. Nothing in a live session loads them; a grep test checks that only `scripts/gpu/t0228_*`, `scripts/replay_*` and tests reference them.
12. Negative:
    - On the same fake-LLM script, every `llm.request` body of a default live session differs from HEAD's only in the search tool's name: inside `tools`, and inside `S_SOURCE` when v4 is chosen. The guard, canvas, options and image list are equal (differential test, T-0111g/T-0136 pattern).
    - The turn machine, speech gate and egress fences are untouched.
    - `test_search_egress_scope.py` passes unmodified.
13. Docs:
    - one `docs/02` spec delta (T-0228) records the rename, the new shas, the legacy dir and H-T228-1;
    - `docs/03` line 175 says `web_search`;
    - historical deltas and task files stay as written.

**Group B (CPU, the GPU A/B harness, report-only):**

14. `scripts/gpu/t0228_search_name_ab.py` and `scripts/locked/t0228_search_name_ab.sh` compare two arms:
    - **L:** the legacy kit from `toolcall/legacy/`, payloads included.
    - **W:** the HEAD kit.

    Everything else is HEAD's: guidance v3, lean, live defaults. Before any socket, P-A checks that L's and W's bodies differ only by the name and that both kits have repair on; if not, exit 2. The parts:
    - **E:** the T-0080 eval search slice (30 search + 20 no-tool cases), through pass 1 and the live judge (the T-0093 path). An arm's expected name is its own search tool's name.
    - **R:** T-0209 R1, 6 turns per arm, with `t0209_rtx_run.SEARCH_TOOL` read from the arm's kit.
    - **W:** the warm-up record for the search tool, from both arms.
15. The decision rule, pre-registered. PASS iff all of these hold:
    - W exact on the 30 search cases ≥ L exact − 2;
    - W calls naming `google_search` (undeclared) ≤ 1/30;
    - W false searches on the 20 no-tool cases ≤ L + 1;
    - W R1 turns with ≥ 1 executed search ≥ L − 1 (of 6);
    - the warm-up is ok in both arms.

    FAIL otherwise. On FAIL, A is reverted (one revert commit) and the follow-up is planned. The report puts Wilson 95 % intervals beside every count. The harness's fast tests run fake-LLM trials, including an adversarial case: an arm W whose model emits `google_search` is counted as undeclared, not as a success.

**Group C:** James runs `/launch` on group B at a clean tree, and the decision line goes in PROGRESS.

## Implementation notes

- **`ToolKit.web_search` is an existing field: the backend label (`"ddgs"`), not the tool name.** After the rename, `kit.web_search is not None and call.name == "web_search"` invites mistakes. Compare against `tools.SEARCH_TOOL`. Do not rename the field: it appears in `Regime.tools` `:search` and in session-log records, so renaming it changes the wire. Reviewers check every `web_search` hit in `session.py`.
- **Payloads.** Regenerate them only through `scripts/build_toolcall_payloads.py` (`uv run --all-extras --group cd …`; CPU, seconds); `tests/cd/unit/test_toolcall_live_parity.py` is its oracle. Every automaton sha changes, not only the search tool's; this is expected.
- **The sha is the version** (`tools.py`: version = sha256 of the bytes). Do not add a "v2" file family: renaming in place plus `legacy/` keeps one code path. Every turn line's `tools_version` changes, so numbers before and after are different regimes; the docs/02 delta says so.
- **The live judge must not alias** (`.claude/rules/` conductor: never silently rewrite model output into an action). `LEGACY_TOOL_NAMES` is for log readers and display only.
- **Thinking.** The thinking prefix and `<|think|>` are untouched. Thinking stays on; nothing is toggled per request.
- **Eval cases.** `tests/eval/toolcall/cases.jsonl` is generated by `build.py` from `cases_src.py`, so relabel there and regenerate MANIFEST. The T-0080 historical numbers were scored against the old labels, which mean the same thing. The set was approved at H-T80, so this needs James's OK (H-T228-2).
- **Browser suites.** Run `make browser`, `browser-suite`, `browser-handoff`, `browser-rtx`, `browser-demo` and `browser-live` before merge; the probe did not cover them.
- **Saved prompts.** User-saved prompts in a browser's localStorage may still say `google_search`. They are free text, so this is acceptable, but the README Settings note mentions it.

**Rulings for James:**

- **H-T228-1:** live does not alias. An emitted `google_search` is refused, not quietly converted.
- **H-T228-2:** the eval cases are relabelled, which changes the cases sha. The cases are human-approved and pinned by MANIFEST.
