# T-0064 — The automaton wire artifact and the `astra_cd_*` request contract

**Status:** done (merged at b170f45; status corrected 2026-10-23 from 'in progress', T-0147 audit: no implementation in flight) · earlier: in progress · **Blast radius:** medium · **Branch:** `T-0064-cd-wire` · **Depends on:** T-0063; the T-0015
Owned-files narrowing (T-0062)

## Goal
A compiled automaton and the choice of arm reach the sampler inside the engine as `vllm_xargs` values: a versioned,
content-addressed, size-capped payload plus a small set of `astra_cd_*` keys. The encoder and the Pydantic contract live
in `local_astra`. A numpy-only decoder and validator lives in the plugin, because the container has no `local_astra`.
A malformed or misspelt request is refused with a reason code and never silently decoded as unconstrained.

## Acceptance criteria
1. `local_astra/contracts/cd.py` defines `CdRequest`:
   - `mode ∈ {end_projection, perstep_mf, perstep_mar}`
   - `self_conditioning ∈ {model, constrained}` (`constrained` only with a `perstep_*` mode)
   - `automaton` (string payload) and `automaton_sha256`
   - optional `entropy_bound > 0`, `confidence_threshold > 0`, and `max_bucket ∈ {16,…,512}`
   - `record_tag`: a caller-chosen string (1–64 chars, `[A-Za-z0-9_.:-]`), required. vLLM v0.29.0 renames requests
     internally to `{external}-{uuid:.8}` (`input_processor.py:279`) and `DiffusionSampler.add_request` never sees
     the request id, so this tag is the only join key between a response and its `ASTRA_CD` records.

   `.to_xargs()` emits only keys prefixed `astra_cd_`, with JSON scalar values that
   `contracts/llm.py`'s existing `vllm_xargs` validator accepts unchanged.
2. **Round trip.** Encode in `local_astra` → xargs → `json.dumps`/`loads` → plugin `parse_cd_xargs`. The decoded arrays
   equal the compiled automaton's arrays exactly (dtype and values) for every automaton of T-0063's four cuts and for
   hand-built NFAs with parallel overlapping edges.
3. **Integrity.** Each of the following yields a typed `CdRequestError` with a stable reason code and never a partial
   object:
   - sha mismatch
   - truncated or invalid base64
   - unknown format version
   - `vocab_size ≠ 262144`
   - `tokenizer_hash ≠` the pinned hash
   - `n_states_bucket` above `max_bucket` or above 512
   - a missing array
   - a structural-invariant violation
4. **Typo-proof (adversarial).**
   - Any `astra_cd_*` key not in the schema raises an error; `astra_cd_mdoe` is refused and never ignored.
   - `astra_cd_*` keys present without `astra_cd_mode` raise an error.
   - No `astra_cd_*` keys returns `None` (unconstrained).
   - Non-CD keys (`astra_tap`, others) are ignored.
5. **Size.** The encoded payload is capped at 1 MiB and larger payloads are refused with a reason. The p50 and max over
   T-0063's cuts are reported.
6. **Record schema.** `contracts/cd.py` also defines `CdCanvasRecord`, complete here so T-0067, T-0068 and T-0070 only
   emit or read it and never edit it:
   - `record_tag`, `arm`, `canvas_idx`, `committed_ids` (valid length), `state_set_after`, `in_final`, `steps`,
     `bucket`, `stop_pos`, `error` (reason code or null)
   - per-step arms: `mean_accepted_per_step`
   - `end_projection`: `shadow_argmax_ids`, `argmax_in_language`, `map_equals_argmax` (null for other arms)

   The plugin's record emitter produces a JSON object that this model validates; a numpy-only mirror of the field
   list lives in `cd/record_schema.py` in the plugin, and a contract test asserts the two field sets are equal.
7. *Negative:* the plugin modules `cd/automaton.py` and `cd/xargs.py` import only stdlib and numpy (derived by AST).
   They import no `torch` and no `local_astra`. `local_astra/contracts/llm.py` is unchanged.

## Rulings (orchestrator, 2026-09-29, after the test-author's report)
- W1. The API the tests fix (`tests/cd/_wire_support.py`): `CdRequest(mode, self_conditioning, automaton,
  automaton_sha256, record_tag, entropy_bound=None, confidence_threshold=None, max_bucket=None)`; `to_xargs()` emits
  `astra_cd_<field>` for set fields only; `automaton` ≤ 1<<20 chars; `max_bucket ∈ {16,32,64,128,256,512}`;
  `automaton_sha256` = lowercase hex sha256 of the payload's ASCII bytes. `local_astra.decoding.artifact`:
  `encode_automaton(compiled) -> str` (no cap), `pack_payload`/`unpack_payload` raw codec; meta carries at least
  `format_version, vocab_size, tokenizer_hash, n_states, n_states_bucket`; the wire carries all 14 arrays (6
  automaton + 8 `ClassTables`). Plugin: `parse_cd_xargs(extra_args) -> CdSpec | None`, `CdRequestError.reason` from
  the fixed code list (`sha_mismatch, bad_encoding, unknown_format_version, vocab_size_mismatch,
  tokenizer_hash_mismatch, bucket_too_large, missing_array, structure, payload_too_large, unknown_key, missing_mode,
  missing_key, bad_value`); `cd/record_schema.py` exposes a literal `RECORD_FIELDS`. Check order: unknown keys before
  missing mode; size cap before decoding; sha before any cache lookup; bucket limit re-checked per request.
- W2. "Parallel overlapping edges" means same source, overlapping labels, different destinations. The compiler never
  emits duplicate (src, dst) pairs (vendored structural invariant), so the wire refuses them as `structure`.
- W3. Automata above bucket 512 in T-0063's cuts are refused as `bucket_too_large`, not round-tripped (decision 5).
  BFCL round-trips run on the pretty-whitespace baseline; the standard-JSON-whitespace variant (decision 11) is
  added to the round-trip when T-0070 warms that cache.
- W4. A typo inside the `astra_cd_` prefix makes a non-CD key and is ignored (criterion 4). Accepted risk; T-0070's
  runner builds requests only through `CdRequest.to_xargs()`, never by hand.
- W5. Defaults and pins: `self_conditioning` defaults to `model`; `automaton_sha256` must be 64-char lowercase hex
  at the contract level; `mean_accepted_per_step` is null for `end_projection`; the record's `arm` is the mode —
  T-0070 derives `perstep_mar_sc` from its own request (joined by `record_tag`), the record does not encode it; an
  `is_dfa` flag that the arrays contradict is refused as `structure`.
- W6. The "emitter produces JSON the model validates" row belongs to T-0067 (no emitter here); T-0064 carries the
  field-set equality row and JSON-validation rows in the emitter's shape.
- W7. `tests/cd/_compile_cache.py` leaves `local_astra/decoding/artifact.py` out of its source digest, so adding
  the codec does not invalidate the compile cache.

- W8. (review, 2026-09-29) Error records must be representable for every `CdRequestError`, including ones with no
  valid mode or tag (`missing_mode`, `unknown_key`, bad `record_tag`, bad `mode`): `CdCanvasRecord.arm` and
  `record_tag` are required keys but nullable, and null only when `error` is set. Decoder hardening is part of
  decision 7 (loud, never fatal): a declared npy shape larger than its entry, a deflate entry that decompresses past
  its declared size, and classes no edge uses (`np.unique(class_id).size != n_classes`) are refused before any large
  allocation or Python loop over classes; `MemoryError` never escapes the decoder.
- W9. (after the W8 rows) The size-lie rule is strict: an entry must end exactly at its declared size — trailing
  compressed data (the `crc-of-prefix` case) is refused as `bad_encoding`, not only a CRC-betrayed lie. An unknown
  extra array may be refused as `structure` or `bad_encoding` (T-0067 treats both as the same class). A non-null
  `record_tag` must always match the pattern, error record or not; an error record for a bad tag carries null.

## Implementation notes (implementer, 2026-09-29; refreshed after W8/W9)
- Encoding, format version 1: standard base64 of a ZIP (deflate 9, fixed timestamps, sorted entries, so equal
  automata give equal strings) holding `meta.json` and one `<name>.npy` per array (`allow_pickle=False`). The
  encoder is `local_astra/decoding/artifact.py`; the plugin restates the format in `cd/automaton.py`. Change both
  together and bump `FORMAT_VERSION`.
- Container decoding (`bad_encoding`, all before any large allocation): strict base64; no duplicate entries,
  only `meta.json` and `*.npy`; declared uncompressed sizes summed ≤ 256 MiB; each entry is inflated by the
  plugin itself from the local header's compressed bytes (not `ZipFile.open`, which stops at the declared size
  and would hide trailing data), never past `file_size + 1`, and must end exactly at `file_size` with no unused
  or unconsumed input and a matching CRC (W8, W9); each `.npy` header's declared byte count must fit the bytes
  present before `read_array` allocates; `MemoryError` and every codec exception become `bad_encoding`.
- Then meta: `format_version`, `vocab_size`, `tokenizer_hash`, `n_states_bucket` > 512 (`bucket_too_large`),
  missing arrays (`missing_array`). Everything else is `structure`: bucket on the ladder; unknown arrays; dtypes and
  1-d shapes of all 14 arrays; `1 ≤ n_states < bucket`; array lengths vs bucket, `n_edges`, `n_classes`; edges
  within the real states and classes; `edge_class == class_id`; every class used by some edge
  (`np.unique(class_id).size == n_classes`, W8, checked before any per-class loop); unique `(src, dst)`; no
  final/start state in the padding and at least one of each; both CSR tables well-formed, rows strictly increasing,
  `class_size` consistent with each table's polarity, SUM and MAX tables describing the same set per class; `d`
  equal to a recomputed reverse BFS; `is_dfa=True` checked on tokens (vendored
  `_assert_outgoing_labels_are_disjoint`). Decoded automata are cached by sha (LRU 64); arrays are read-only; the
  per-request `max_bucket` is re-checked on every hit.
- `CdRequest` also checks that `automaton_sha256` is the sha of `automaton` (cheap, and a mismatched request
  could only be refused later by the plugin). `CdCanvasRecord`: every field is a required key (null where it does
  not apply); `record_tag` and `arm` are null only on error records, and a non-null `record_tag` always matches the
  pattern (W8, W9); `error` is any `[a-z][a-z0-9_]*` code so T-0067 can add runtime codes without editing the
  contract; `stop_pos < len(committed_ids)`; `state_set_after` below `bucket` when `bucket` is set.
- Criterion 5 (CPU; BFCL = `BFCL_BASELINE_OPTIONS`, pretty whitespace; Sudoku 4x4; tokenizer cc8d3a0c; model rev
  2ea8372; dgfa 27c7d0d; all automata of each cut, including buckets > 512): bfcl_test n=130 p50 54 056 B max
  84 524 B; bfcl_dev n=100 p50 54 796 B max 81 320 B; sudoku_test n=250 p50 4 400 B max 4 412 B; sudoku_dev n=100
  p50 4 402 B max 4 416 B. Cap 1 048 576 B. Decode + validate on the BFCL test cut (n=116 with bucket <= 512,
  one CPU run, measured before the W8/W9 hardening): p50 2.8 ms, max 17.4 ms.
