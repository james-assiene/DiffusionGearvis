## Why
T-0071b b2 (BFCL calibration, PROGRESS 2026-10-07) stopped at the stack check: stop (d) "unconstrained BFCL schema valid < 0.40 after 30
records" fired at 11/30 = 0.367. The stack was not broken: 29/30 outputs parsed, 20/30 were exact calls by BFCL's scoring, and the first 10
records scored identically to B13 at abe2922 (9/10 valid). 12 of the 19 schema-invalid rows are exact calls on two function families
(live_simple_141–157) where the plain model sets an optional argument to a value outside its schema (e.g. `"unit": "shell"` where `unit` is an enum `seconds|milliseconds`; the scorer allows extra keys, so it is the out-of-enum value that fails) — a real model error that constrained
decoding exists to prevent, not a broken stack. The 0.40 floor was set (T-0070) before the plain model was measured beyond 10 records.

**Human decision (2026-10-07):** for BFCL, (d) checks the **parse rate** instead of schema-valid: fire when fewer than 40 % of the first 30
unconstrained records parse (same window, same floor). Sudoku's (d) (solved < 0.50 after 30) is unchanged.
