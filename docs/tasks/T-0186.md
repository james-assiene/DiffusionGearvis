# T-0186 — Tests never inherit a git repo selector

**Status:** done 2026-10-28, merged at 89654839 (reviewer APPROVE at 5c5dd8f1, verifier MERGE; the full fast suite with GIT_DIR/GIT_WORK_TREE exported at a victim left the victim and main byte-identical). Open follow-up, not filed: `subprocess.run("git …", shell=True, env={…GIT_DIR…})` reaches the audit hook as `/bin/sh`, so only the session-wide strip covers it. Applying the os.system first-word parse to `[sh, "-c", cmd]` would close it.

## Goal

On 2026-10-28 a reviewer ran the fast suite with `GIT_DIR` exported, pointing at the main repo, so that the git-range rows would run in a `git archive` copy. `tests/unit/test_protect_paths_hook.py` builds its sandbox with `git init <tmp>` and an env of `{**os.environ, …}`. With `GIT_DIR` set, the sandbox's git commands acted on the repo `GIT_DIR` names: its `git commit -qm init` committed the sandbox tree onto `main`, authored `protect-test`, and the main repo's config was found with `core.worktree` pointing at a scratch directory. (Review note: on git 2.43 a plain `GIT_DIR=<v> git init <dir>` did not reproduce the `core.worktree` write, so which command wrote it is not pinned. The ref damage reproduces, and the rows check refs and config byte for byte, so they catch either.) The orchestrator undid it: `git config --unset core.worktree`, then `git reset --mixed e45f39a5` (the stray commit was 941b0278, never pushed). Until then every agent's path hook resolved the wrong top-level and refused all edits.

It had happened before. The 168 `protect-test` commits on `scratch-no-task-id`, dated 2026-10-22, are the same leak; that branch was later pushed to the private backup.

The fix is session-wide, not per test: about 20 test modules spawn `git` with an inherited env.

## Acceptance criteria

1. **The session strips git's repo selectors at conftest import.** `tests/conftest.py` removes `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE` and `GIT_CEILING_DIRECTORIES` from `os.environ` before any test or fixture runs. Every child inherits the stripped env.
   - This runs alongside the T-0175 home jail and does not weaken it.
2. **The spawn guard refuses a git child that still names a repo.** The T-0175 audit-hook spawn guard (`tests/_home_jail.py`) also refuses any spawn whose argv[0] basename is `git` and whose env carries `GIT_DIR` or `GIT_WORK_TREE`. The refusal message names the variable. A test that genuinely needs one must pass `-C`/`--git-dir` on the command line instead.
3. **The protect-paths sandbox cannot touch the real repo.** `test_protect_paths_hook.py`'s `GIT_ENV` drops the same variables explicitly; this is belt and braces beside criterion 1.
   - **Adversarial row:** with `GIT_DIR` and `GIT_WORK_TREE` set to a throwaway "victim" repo (never the real one) in a subprocess pytest run of the sandbox fixture, the victim's config has no `core.worktree`, its HEAD does not move, and the sandbox has its own `.git`.
4. **The rows have power.**
   - Removing criterion 1's strip (with criterion 3's drop also removed) turns the adversarial row red.
   - Removing criterion 2's git clause turns its row red.
5. **Too-wide guard.** A git spawn that passes `-C <dir>` or `--git-dir=<dir>` on its argv, with no git env var, is allowed. A non-git spawn with `GIT_DIR` in its env is allowed by criterion 2: criterion 1 has already stripped the variable.
6. **No real-repo writes in the fast suite.** Run the fast suite with `GIT_DIR=<victim>/.git GIT_WORK_TREE=<victim>` exported. The victim repo's refs, config and reflog are byte-identical before and after, and so are the main repo's.
7. **Docs.** `.claude/rules/tests.md` gains one line: never export `GIT_DIR` or `GIT_WORK_TREE` to run the suite; git-range rows skip in an archive copy by design.
