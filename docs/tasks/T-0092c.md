## Goal
With `tools = dry_run`, the session:
- judges pass 1's `tool` commit and hands the machine `LlmDone(tool=…)`;
- runs the H-T84-2 repair when the machine asks;
- dry-runs a valid call when the machine says the turn completed uninterrupted and drained;
- publishes every step to the HUD card, the session log and the turn record;
- never voices or stores anything but the spoken prefix.

With `tools = off`, nothing changes, and T-0092b's golden stays green, unedited.

## Acceptance criteria
1. **Detection.** At the end of pass 1's stream, with a `tool` commit:
   - **Judging.** `v = live.classify(tool.text)`.
     - The call id is deterministic per turn: `f"{turn_id}-call"`, never a clock.
     - When repair is off (T-0092b criterion 2), a `repairable` verdict becomes `refused`, with reason `"repair off: <reason>"`.
   - **The event.** The session hands the machine `LlmDone(request_id, tool=ToolDraft(call_id, status, name, arguments, reason,
     source="draft"))`. Without a `tool` commit, `LlmDone` carries no tool, byte-identical to tools-off.
   - **What the session keeps:**
     - `draft = router.route(tool.text).draft_call_text`. A row proves it equals `route(D).draft_call_text` on the parity fixtures.
     - `stop_id = tool.stop_id`, from `Commit.stop_id`. Never `stop_reason`, never re-derived.
     - `spoken_prefix = drop_special_literals("".join(pass-1 answer commit texts))`, per the T-0088 E11 note.
   - **Publish.** One `astra.tool.call`:
     - `proposed` for a `valid` or `repairable` verdict;
     - `refused` for a `refused` verdict, with `name=""` and `arguments={}` when the call is nameless;
     - `query_problem` when it is set (H7: logged only, it never blocks).
   - The machine trusts `status` (T-0089).
2. **Repair** (on `ToolRepairStart`; T-0089 R2–R7 and T7).
   - **Task.** The repair runs in its own task, registered so that `LlmAbort(repair id)` cancels it (`_generate[...]`, `_RequestIds`;
     T-0005 M5/B13). It never blocks the pump.
   - **Publish** `repairing`.
   - **Steps:**
     1. `ids = await llm.tokenize(draft.rstrip())` (T-0091 F1).
     2. `p2 = live.repair_prompt(pass1_prompt_as_sent, spoken_prefix)`. If this returns a `Refusal`, the session hands the machine
        `LlmDone(repair_id, tool=refused(reason="continuation_guard: <template|marker>"))` and sends no generate.
     3. `req = live.repair_request(name, ids, stop_id, record_tag=<engine id>, payloads, calibration)`.
     4. `llm.generate(p2, repair_engine_id, live.REPAIR_OPTIONS, cd=req)`.
   - **The verdict.** The repair's output is its `tool` commit (T-0088 criterion 7, the continuation case; E4).
     - `v2 = live.repair_verdict(tool.text)`, then `LlmDone(repair_id, tool=ToolDraft(call_id, v2…, source="repair"))`.
     - With no `tool` commit, the tool is `refused("no tool commit")`.
   - **Commits are never voiced.** No repair commit (`thought`, `tool` or anything else) is submitted as `LlmCommit`, so none reaches
     the speech gate. All of them are logged: `llm.commit` with the repair request id. Thinking is logged, never stored.
   - **Errors.** Any exception from tokenize, prompt building, request building or generate becomes `LlmError(repair_id)`. Per R7 the
     spoken prefix keeps playing.
   - **Request log.** One `llm.request {phase: "tool_repair", request_id, attempt_id, options, cd: <the CdRequest dump without
     automaton, with automaton_sha256>, prompt}`.
   - **`pass1_prompt_as_sent`** is the exact `Prompt` object pass 1 sent, including after an over-long retry.
3. **Execution** (on `ToolExecute`).
   - **The invocation.** `ToolInvocation(call_id, turn_id, name, arguments, source, frame)`.
     - `frame` is the `FrameGeometry` of the newest image part in the prompt pass 1 actually sent (after T-0059 de-duplication),
       looked up by phash.
     - It is `None` when that prompt carried no image.
     - It is never taken from `_turn_frames()` at execute time.
   - **Run.** `outcome = await executor.execute(inv)`, awaited inline. The dry run does no I/O; an executor that does is a later task.
   - **Publish** `dry_run` or `refused`, with `action` and `reason`.
   - **Executor exception.** Publish `refused(reason="executor error")` and log an `error`.
4. **Cancel** (on `ToolCancel`; Q-c).
   - **Statuses:**
     - `refused` and `repair_failed` publish `refused`, with the verdict's reason or the repair error;
     - `interrupted`, `takeover`, `error`, `disconnected` and `repair_timeout` publish `cancelled`, with the cancel reason.
   - **One final message per call.** Each `call_id` gets exactly one final message: `dry_run`, `refused` or `cancelled`. `proposed`
     and `repairing` are intermediate.
   - **Closing turn.** When the command arrives in the closing tuple, the handlers write to the closing turn's log (`self._closing`,
     as `commit_history` does).
5. **Executor handlers.** With `tools = dry_run`, the `tool_repair_start`, `tool_execute` and `tool_cancel` handlers in `executor.py`
   call the session (criteria 2–4). With `off`, they stay the inert `note`, so
   `test_session_loop.py::test_t0089_tool_commands_have_named_inert_handlers` stays green, unedited, on the tools-off rig.
6. **Speech and history** (H4, H8; .claude/rules/conductor.md).
   - **Spoken prefix.** The concatenated `TtsSpeak.source` over the turn equals `drop_special_literals(router.route(D).spoken_prefix)`,
     where D is the host decode. This holds for:
     - the click-01 content;
     - the google_search content with no sentence;
     - the stray-close content (T-0087 e/key-02).
   - **Never voiced.** No `TtsSpeak.text`, and no `source` of a `TtsSpeak` with non-empty `text`, contains any of:
     - a `SPECIAL_TOKENS` literal;
     - `call:`;
     - any argument value of the call.
   - **History.** `HistoryTurn.assistant_spoken` is the played text only. It never holds a literal, `call:` or an argument value. This
     includes the case where a literal is spliced across two answer commits (the E11 note).
   - **No spoken sentence.** Nothing extra is voiced.
7. **Telemetry.**
   - **Session log.**
     - `session_log.KINDS` gains `tool.call`.
     - One record per published `astra.tool.call`, carrying the same `status` plus `{call_id, source, name, arguments, parse,
       schema_valid, query_problem, repair_ms, action, reason, resolved, spoken_prefix}`.
     - `repair_ms` is measured from session clock to session clock.
   - **Turn record.** `TurnRecord.tool` holds the final state of the turn's call, or None.
   - **Spans.** `SPAN_NAMES` gains:
     - `tool.repair`: from `ToolRepairStart` handled to the repair's `LlmDone`/`LlmError` submitted;
     - `tool.execute`: from `ToolExecute` handled to the outcome.
   - The `llm.done` span stays pass 1's; the repair's `LlmDone` never overwrites it, because T-0093 reads it.
8. *Negative.*
   - At most one live generate plus one prefill at every step, with the repair counted (the I8 shape over fakes).
   - A call is never executed in an interrupted turn, or before the turn's own drain. The session's drain gate stays.
   - The executor is never called with `tools = off`.
   - No non-loopback socket.
   - google_search is never executed beyond the dry-run description (H2).
   - **Unchanged files:**
     - `turn_machine.py` (`TURN_MACHINE_SHA256`);
     - `contracts/**`;
     - `llm_client.py`;
     - `toolcall/**`;
     - `tool_executor.py`;
     - `hud_server.py`.
   - T-0092b's tools-off golden stays green, unedited.

## Implementation notes
- **Where to take tool commits.** Where the `Commit` exists, in `_run_generate`, as `_note_commit_fence` does. Never re-derive them from
  canvas text.
- **Draft from the router.** The draft comes from `router.route` (imported, as `llm_client` does), so eval parity holds by construction.
  Do not copy twopass.
- **Call id.** The repair keeps `ToolDraft.call_id` (T7).
- **The `llm.done` span.** The `LlmDone` branch of `_note_event` must not move the `llm.done` span on the repair's `LlmDone`.
- **Rules:**

  - one clock per duration;
  - thinking is logged, never stored or published.
- **Landmines.** The same `session.py` source-grep landmines as T-0092b apply (`tokenizer`, `/ 4`, `_segment`).

## Rulings after review (orchestrator, 2026-10-12; both reviewers REQUEST CHANGES at 96f1d88)
- **I10. The answer cleaner never crosses a thought boundary** (reviewer 1, finding 1, HIGH).
  - **The defect.** With tools on, text held back from one commit was released inside the next commit. This mixed `thought_open=True`
    and `thought_open=False` text, so a canvas ending inside an unclosed thought was voiced. That breaks a CLAUDE.md absolute.
  - **The rule.**
    - Only `thought_open=False` answer commits go through the cleaner. `thought_open=True` commits are submitted unchanged.
    - Held text keeps the flag of the commit it came from.
    - The end-of-stream tail commit is `thought_open=False`, because it holds only voiced-commit text.
- **I11. A card always ends with exactly one final** (reviewer 1, finding 2).
  - **Publishing `proposed`.** The detection publish (`proposed`, or `refused` at detection) happens on the pump side when the machine
    accepts `LlmDone(tool)`, that is when its `request_id == before.active_generate`. It is not published from the generate task.
  - **Turn close.** When a turn closes, any of its calls without a final get `cancelled` with the reason `turn closed`.
- **I12. Tighter hold-back** (reviewer 1, finding 3).
  - **The rule.** Hold from the first `<` that comes after the last character that is either `>` or outside the union of the literals'
    character sets. Such a character can never be deleted, so no literal can span it.
  - **Evidence.** Reviewer 1 fuzzed it: 0 failures in 40 000 cases. It releases "Since 3 < 5, the first step" at once. Text in maths answers
    must not wait for pass 1 to end.
- **I13. Rows (test-author).**
  - From reviewer 1:
    - P4, the thought splice: no unclosed-thought text is ever voiced or stored, with tools on and with tools off.
    - P1, a takeover before the machine accepts the draft: the card ends `cancelled`, never stuck at `proposed`.
    - P3/M8, the end-of-stream flush.
    - P2/M6a, the frame at judge time: a snapshot taken during pass 1 is not used.
    - M7, a nested splice `'<tool|<|t'` / `'ool>'`.
    - M21, a stale judge.
    - P5, a maths answer: the first sentences are voiced before pass 1 ends.
    - M27, `repair_ms` and the `tool.repair` span on the error path.
    - M26, an empty cleaned commit is not submitted.
  - From reviewer 2:
    - **Tools-off handlers are inert.** Run the three tool commands with `kit=None` and the log on. Assert: no `astra.tool.call`, no
      submitted event, and exactly one `note` each.
    - **Exact keys.** The `tool.call` record keys are exact (`==`).
    - **The bind wrapper.** It treats `""` as non-loopback.
    - **`cli` reads the tool set once.** Use a spy whose second call returns a different version.
- **I14 (on the test-author's ambiguities at a76da1b).**
  - **A thought boundary flushes the hold.**
    - If a `thought_open=True` commit follows text held back from a voiced commit, the cleaner first releases that text as a
      `thought_open=False` answer commit, then submits the thought commit unchanged.
    - It then starts empty.
  - **P1.** If the machine never accepts the draft, the card may never be shown. Otherwise it ends `cancelled("turn closed")`. Either is
    accepted, and a card never ends without a final.
  - Ambiguities 4–7 are accepted as stated.
- **I15 (re-review at fc4fe5f). Supersedes I14's flush-and-reset.**
  - **Why I14 was wrong.** The machine builds the committed answer and history from all `thought_open=False` commits concatenated, so a
    thought commit in between is not a boundary. Flushing and resetting there let a special literal be spliced across the thought, into
    speech `source` and history. Example: `Press <|tool` / thought / `_call> now. ` stored `Press <|tool_call> now. `.
  - **The rule now.**
    - A `thought_open=True` commit is submitted unchanged and bypasses the cleaner.
    - The hold is neither flushed nor reset.
    - `spoken_prefix` is `drop_special_literals` over the concatenation of all voiced texts.
  - I10 still holds: held text only ever comes from voiced commits.
  - **Rows (test-author):**
    - a held tail across a thought: `Press <b` / thought / `ack> now. ` → `Press <back> now. `;
    - the splice across a thought: `Press <|tool` / thought / `_call> now. ` → no literal in any source or in history;
    - `_close_calls` called directly on a shown card, as reviewer 2's probe did: one `cancelled("turn closed")`, recorded, before the
      record is written.
