# T-0084 — Native Gemma 4 tool-call format as a fourth two-pass variant (umbrella)

**Status:** planned 2026-10-09 · **Blast radius:** high overall (a–d medium; e and f high, since they use the GPU) · **Depends on:** T-0080
(Q3: "the native `<|tool_call>` token is a follow-up"), T-0081b, T-0082a/b (merge order), T-0082c (GPU order) · **Human request:** 2026-10-09.

## Goal
Add the model's own tool-call format as a fourth variant beside `<cc>`, both for pass 1 and for pass 2 (T1/T2/T4). Measure it against the
`<cc>` baseline with the pre-registered T-0080c rule on dev first.

A native pass 1 looks like `…spoken…<|tool_call>call:NAME{k:v,…}<tool_call|>` + stop 50, with the declarations sent through the request's
`tools` field. The test split runs only if native wins on dev and the human approves reusing it.

Scope is computer control only. GenUI and tool responses are out of scope, but the design leaves room for both (notes below).

## Implementation notes
- **Sub-tasks:**
  - T-0084a: native grammar in `decoding/toolcall.py`.
  - T-0084b: parser, name and `tools` field in a new `toolcall/native.py`.
  - T-0084c: native format in the two-pass driver.
  - T-0084d: comparison rule, report, CLI and locked script.
  - T-0084e: dev launch.
  - T-0084f: conditional test launch.
- **The router stays untouched.** T-0082a's `rescore` refuses an artifact if re-routing changes `draft_name`, and the T-0080c test artifact
  holds a native-tag case. So the native name lives in `native.draft_name()` and is used for native rows only. Moving it into `Route` is a
  later router row (T-0080d), after T-0082c's evidence is final.
- **The pinned template fixes the format** (template sha `36e3a42e…`):
  - Calls render as `<|tool_call>call:NAME{key:value,…}<tool_call|>`.
  - Keys are dictsorted. Values come from `format_argument`: integers as bare digits, booleans as `true`/`false`, strings wrapped in `<|"|>`
    (id 52) and unescaped. No whitespace appears anywhere.
  - Ids: 48 `<|tool_call>`, 49 `<tool_call|>`, 52 `<|"|>`, and 46/47 around each declaration.
  - **Stop ids are {1, 106, 50}.** 49 is not a stop: the model ends a call with 49 and then writes 50 `<|tool_response>`.
  - Declarations render in the system turn as `<|tool>declaration:NAME{…}<tool|>`. Numeric bounds, `minLength` and `additionalProperties`
    are not rendered, so the native system prompt keeps the 0–999 coordinate sentence.
  - `reasoning` renders only with `tool_calls`, as `<|channel>thought\n…\n<channel|>` followed directly by `<|tool_call>`.
- **Comparability.** Both formats run in one boot at one SHA, paired by case, on the same eval set (cases `460cd1c3…`), split, knobs, CL,
  steps and thinking. Only the format differs: the prompt instructions, where the declarations live, the call syntax and the grammar. These
  differ jointly, and the report says so.
- **Room for GenUI (not built).** A native tool `render_surface(surface: object)` could be routed by name. The A2UI payload's automaton
  would be far above the 128-state live gate, so per-step CD does not apply; the payload would be validated after commit by the A2UI
  validator.
- **Room for tool responses (not built).** Stop 50 is `<|tool_response>`. A multi-step loop appends an assistant message with `tool_calls` and
  a `tool` message. `native.parse_call` returns the OpenAI `function` shape so it can feed that loop. A v1 parse refuses a second call.

## Human decisions (2026-10-09): all defaults, QN1–QN10
- **QN1 Baseline.** A fresh `<cc>` arm in the same boot and SHA, paired by case. Stored cc numbers appear only as a cross-boot sanity line.
- **QN2 Dev rule.** Step 1 is the T-0080c stage-1 rule and picks native θ_n. Step 2 is the T-0080c stage-2 rule over cc + native at
  tolerance 0.10. Final-level ties go to cc. "Native wins" means the chosen policy is native.
- **QN3 `tool_choice`.** `"none"`: tools are rendered and the server's parser is bypassed. Prompt guards prove the declarations arrived.
- **QN4 Parser leniency.** Whitespace allowed, key order free, `<tool_call|>` required, bare values only JSON literals, duplicate keys
  refused, nothing but whitespace after the close. Parse-failure reasons are always reported.
- **QN5 T1 thought.** Ids 48 and 49 are excluded from the thought's free region.
- **QN6 Native seed.** The T-0081b re-encode with T = `<|tool_call>` for T1/T2 and "" for T4, plus R2.
- **QN7 Wrong tag.** A native-format answer using `<cc>` scores as an invalid call (`wrong_tag`), with no pass 2. cc rows are unchanged.
- **QN8 Native system prompt.** The human approves the wording at H-T84-0, before T-0084e.
- **QN9 Test launch.** Only if native wins dev and after H-T84-1: both formats fresh in one boot, at θ_n, four arms each, tolerance 0.05,
  run once.
- **QN10 Adoption.** Even a native test win is a recommendation; the human decides at H-T84-2.

## H-T84-0 (human, 2026-10-10)
The native system prompt and the comparison rule (T-0084d criterion 1) are approved as written. QN7 is amended: a `wrong_tag` gets the
native picker plus a constrained pass 2, like an invalid draft (T-0084d criterion 7), so both formats are treated the same.

## H-T84-2 (human, 2026-10-11): ADOPT NATIVE
The default tool-call policy becomes **`cd_on_invalid:native/T4/named/perstep_mar+seed`**:
- a schema-valid native draft (`<|tool_call>call:…<tool_call|>` parsed by `native.parse_call`) is sent as written, which on test is
  identical to the measured winner `draft_only:native` (74/80, 227/352 ms);
- an invalid native draft gets one seeded constrained native pass 2. That is the seed arm, whose search queries were clean; the unseeded T4
  CD wrote garbage queries.

This replaces H-T82's `cd_on_invalid:T1/named/end_projection`.

**Caveat:** no native draft was invalid in 120 dev and test cases, so the fallback path is unmeasured on real invalid drafts.
