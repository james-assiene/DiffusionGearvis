# T-0086 — The google_search `exact` rule also requires a plausible query; offline re-score of the stored tool-call artifacts

**Status:** done (2026-10-11; verified at b4b8cbe); planned 2026-10-11 · **Blast radius:** medium (one reviewer, who also re-derives the re-score tables) · **Branch:** `T-0086-search-exact`
from `main` (4c7dfdc) · **Depends on:** nothing in flight · **Ordering:** part A (scorer) before part B (re-score).
This amends T-0080a criterion 3. It does not change any recorded decision (H-T80c, H-T82, H-T84, H-T84-1, H-T84-2).

## Goal
Today `score.exact` counts a google_search call as correct when every ground-truth keyword is a substring of the query. The T-0084f review
found unseeded native T4/T2 constrained calls writing the leaked thought plus call syntax into the query, e.g.

    " best hiking trails near Zermatt. I should use the `google_search` tool for this.1callcall:google_search{query:\[best hiking trails near Zermatt"

These scored exact on 19/20 per cell on test and 10/10 on dev, and on dev they decided θ_n = T4.

After this task a google_search call is exact only when the keywords are present **and** the query is plausible (criterion 2), exposed as
`score.query_problem(query) -> str | None`. A new CPU script re-scores every stored tool-call artifact (pass 1 and pass 2) and reports
old against new, with the counterfactual output of each recorded selection.

**Pre-registration caveat:** the rule was written after reading the stored queries, so the re-score is a counterfactual on data already
seen. The criteria are justified from what a search query is. The implementer must not tune them on the artifacts; any change goes back to
the planner.

## Acceptance criteria

### Part A: `local_astra/toolcall/score.py`
1. **The new exact rule.** For `google_search`, `exact(call, gt)` is True iff:
   - the existing keyword rule holds (unchanged);
   - **and** `query_problem(query) is None`.
   
   Every other tool and branch is unchanged. Malformed arguments score False and never raise.
2. **`query_problem(query: str) -> str | None`** is public, pure and total.
   - It works on `n` = NFC, whitespace runs collapsed to one space, stripped, case-folded (the same as the keywords).
   - It returns the first failing reason in this order, or None:
     - `"empty"`;
     - `"too long"`: more than 32 space-separated words;
     - `"control character"`: Unicode category `Cc` or `Cf`, checked after normalisation (so tabs and newlines are whitespace);
     - `"markup"`: any of `{ } [ ] < > \ | `` ` ``;
     - `"tool syntax"`: contains `call:` or any v1 tool name (`google_search`, `click_at`, `type_at`, `scroll`, `press_key`);
     - `"narration"`: a first-person agent clause followed by a search-act verb, matched anywhere and not anchored to a word start on the left.
   - The narration clause is one of `i will`, `i'll`, `i should`, `i must`, `i need to`, `i have to`, `i am going to`, `i'm going to`,
     `let me`, followed by one of `search`, `google`, `look up`, `use`, `call`, `query` and a word end. U+2019 counts as `'`.
   - User-style first-person queries are **not** narration: `i will survive lyrics`, `how do i replace a bike chain`, `i need a hero lyrics`.
3. **Every ground-truth reference query passes:** for all 30 `google_search` cases in `cases.jsonl`, `query_problem` is None and
   `exact(reference_call, gt)` is True. Non-search reference calls are unchanged.
4. **Tightening only:** new `exact` implies the 4c7dfdc `exact` for every input, and they are equal for every non-google_search call.
5. **Purity and the import fence (T-0080a criterion 6):** stdlib, `jsonschema` and `local_astra.toolcall.tools` only; no I/O. The docstring
   states the rule.

### Part B: `scripts/cd_toolcall_rescore_exact.py` (new)
6. **The tool.**
   - **Invocation:** `--evidence-root <dir> --artifact <rel> --sha256 <hex> --out-dir <new dir>`, with `main(argv) -> int`. CPU only,
     read-only inputs.
   - **Output:** writes `report-rescore-exact.{json,md}`. Exit 2 with `REFUSED:` and nothing written on any refusal.
   - **Pass-1 rows:** via `twopass.rescore`.
   - **Pass-2 rows:** `exact` recomputed from the stored `call` (None means False).
   - **Ground truth:** `cases.jsonl` at the recorded sha.
7. **Consistency refusals.**
   - Non-google_search rows: new == stored.
   - google_search rows: new == (stored and `query_problem(query) is None`).
   
   Any violation refuses, naming the case, cell and pass.
8. **Report** (per artifact):
   - every `derive` policy, old against new exact (overall and google_search);
   - flipped rows per cell and pass;
   - a `query_problem` reason histogram over the flipped rows;
   - the counterfactual selection for the artifact's own rule (`select` for cc-only, `select_format` for mixed), old beside new, labelled
     "counterfactual; not a decision". Where the cells were not run: `not computable (cells not run: …)`.
   - the caveat.
9. **Run and write-up.** The tool runs once per artifact at the merge SHA on a clean tree, on the six artifacts in the Regime, into
   `logs/t0086-rescore-<sha>/`.
   - A new `docs/cd/toolcall-rescore-exact.md` (from the reports only) gives per artifact:
     - old and new exact per policy;
     - which recorded choices would flip: T-0080c stage 1 and 2, T-0082c stage 2, T-0084e θ_n and winner, T-0084f winner;
     - the regime;
     - the caveat;
     - "decisions stand as recorded unless the human rules otherwise".
   - One pointer section is appended to `docs/cd/toolcall-native.md`.
10. *Negative.*
