## Goal

The T-0111g live smoke (ca9576f) succeeded on 4/25 turns. The logs show three causes:
- Clicks on 121×41 px buttons land 12–25 px below them. At the engine's default of 280 soft tokens per image, one token spans about 61 page px.
- The model claims success when the screen did not change.
- S4 never scrolls before answering about the whole page.

This task adds four things:
- **(A)** A per-request visual-token budget, as a profile setting that is logged on every turn.
- **(B)** ReGround, ported from cua-diffusion-gemma: a second, never-voiced request on a crop around the first point, made inside the live execute stage.
- **(C)** Two live-only system-prompt sentences: check the post-action screenshot before claiming success, and scroll before answering about a whole page.
- **(D)** A locked GPU A/B over budget {280, 560, 1120} × ReGround {off, on}, with C in every arm. That is 6 arms × 5 tasks × n = 5 = 150 typed turns, with the decision rule for the production default pre-registered here.

With every new setting at its default (budget unset, ReGround off), `off` and `dry_run` stay byte-identical to BASE, and `live` differs only by the C sentences. The production default is changed later, from D's result.

## Acceptance criteria

### Group A — the visual-token budget (plumbing)

**A1. Config.**
- `Profile` gains `visual_tokens: Literal[280, 560, 1120] | None = None` and `reground: bool = False`.
- `None` means "send nothing", i.e. the engine default: 280 for this checkpoint (`processor_config.json` `max_soft_tokens: 280`).
- Any other value is refused at load, naming the three allowed values. That includes 70, 140, 0 and `"1120"` as a string.
- `reground = true` with `tools != "live"` is refused at load, naming `live`. It must not be a silent no-op (`.claude/rules/conductor.md`, "a subsystem that silently disables itself").

**A2. Request body** (docs/02 §5 wire format). `VllmClient(..., visual_tokens: int | None = None)`.
- **When set,** every body built by `request_body` carries `"mm_processor_kwargs": {"max_soft_tokens": N}`. That covers prefill, generate, tool step, repair, caption and reground, so a prefill and its generate always agree. The multimodal hash includes the processor kwargs (`multimodal/processing/inputs.py` in v0.29.0), so if they disagreed the image would miss the prefix cache.
- **When `None`,** the body is byte-identical to BASE.
- No other key changes. The value is never routed through `LlmOptions` or `vllm_xargs`.

**A3. Wiring and logging.**
- `--visual-tokens {280,560,1120}` overrides the profile.
- `cli` passes the value to `VllmClient`. The session receives it only for logging.
- When it is set, every turn line in every mode gains `visual_tokens: N`, and the `--dry-run` line gains ` visual_tokens=N`. When it is unset, both are byte-identical to BASE.
- Do not add the budget to the `Regime` contract. A new `Regime` field would change every `off` line and break the T-0111g differential.

**A4. Policy reconciliation.** `perception/policy.py` gains:
- `ENGINE_DEFAULT_SOFT_TOKENS = 280`;
- `SUPPORTED_SOFT_TOKENS = (280, 560, 1120)`;
- a pure `expected_soft_tokens(width, height, budget) -> int`, mirroring the processor's resize rule:
  - the unit is patch 16 × pooling 3 = 48;
  - scale = sqrt(budget·9 / patches);
  - floor each side to the unit;
  - tokens = min(patches / 9, budget).

Hand-computed values: 1280×800 → 273 / 522 / 1092. A 512×320 crop gives the same, because the processor scales it up.

`MAX_SCREEN_VISUAL_TOKENS` stays 1120, and the `test_perception_policy.py` pins stay green. The module docstring and that constant's docstring stop claiming the engine uses 1120. They say it is the bucket's target, reached only with `visual_tokens = 1120`.

**A5. Negative (differential).** With `visual_tokens` unset and `reground` off, `off` and `dry_run` sessions match BASE f30365d exactly: request bodies, `turns.jsonl` lines, session-log records, HUD messages and `--dry-run` lines. `live` matches too, except for the C sentences in the system message.

### Group C — live guidance (behaviour fixes)

**C1. Two sentences, live only.** `PromptBuilder` gains `tool_guidance: str | None = None`. When it is set and tools are on, it is appended after `NATIVE_TOOL_INSTRUCTIONS`, last in the system message. `cli` sets it to a new constant `LIVE_TOOL_GUIDANCE` when `tools = live`, and only then.

The text is at most 400 code points and says two things. The implementer words them; the reviewer checks the meaning.
- **(a)** After an action, the next screenshot shows the screen as it is now. Before saying an action worked, check that the new screenshot shows its effect (e.g. the cart count changed). If it does not, try again or say it did not work.
- **(b)** When asked about a whole page (the cheapest item, every item, a list), scroll to see the rest of the page before answering.

It must not ask for per-step narration and must not add a confirmation request. This follows the speaking-policy and autonomy rulings: ask only for pay, send or delete.

**C2. Cache prefix.** The text is a literal, identical in every turn and process, and sits in the cached system message. It does not change with thinking.

**C3. Negative.**

**C4. No payload change.** Live step payloads stay `{action, status, screenshot}` exactly as T-0111g B8 ships them (ruling R-c).

### Group B — ReGround (live only, `reground = true`)

**B1. Where it runs.** ReGround runs in `session._run_execute`, after T-0111g's B9 freshness check and before `executor.execute`.
- It applies to `click_at` and `type_at` in `live` only.
- It never applies to `scroll`, `press_key` or `google_search`; those are logged as `skipped_no_point`.
- The turn machine still sees exactly one `ToolExecute` and exactly one `ToolResult`, as today. Nothing in the machine changes.

**B2. Pass 2.**
- **The crop** is cut from the call's own frame bytes, looked up by capture identity (`_frame_bytes`). It is zoom 0.4 of the frame (512×320 at 1280×800), centred on pass 1's pixel point (`to_pixels`) and clamped inside the frame, then JPEG-encoded at its native size.
- **The prompt** is the exact prompt that produced the call, with one change: the image whose identity is the call's frame is replaced by the crop. Everything else is byte-identical: system, tools, history, the continuation and the C sentences. This is the faithful port; ruling R-a covers the §5.2 limit.
- **The request** is one `llm.generate` with its own engine id. Its body carries the session's budget (A2).
- **Isolation.** Pass 2's commits never reach the machine, the speech gate, TTS, history, the HUD spoken pane or any `Episode`.
- **Logging.** It is logged as `llm.request` with `phase: "reground"`, `step` and `attempt_id`. A `tool.reground` record carries:
  - `p1`, `p2`, `crop` (`x0, y0, w, h`), `outcome` and `ms`;
  - pass 2's tool text, truncated to 512 characters.

  Its thought text is never logged outside `llm.commit`-style session-log records; the implementer may skip logging it entirely.

**B3. Outcomes and fallbacks.** Every outcome is counted.

| Outcome | When | What executes |
|---|---|---|
| `ok` | Pass 2 parses (`native.parse_call` + `score.schema_valid`) as the same tool name, with x and y. | Pass 1's call, with only x and y replaced by pass 2's point mapped back to the full frame's 0–999. Name, `text` and `press_enter` stay pass 1's. |
| `pass2_unparseable` | No call, or an invalid call. | Pass 1 |
| `pass2_no_point` | A coordinate-free call (`scroll`, `press_key`, `google_search`). | Pass 1. The keyboard rule is ported as observed but not executed (R-b). |
| `pass2_other_tool` | A different coordinate tool. | Pass 1 |
| `pass2_timeout` | No result within `REGROUND_TIMEOUT_MS` on the session clock (0 < value ≤ `TOOL_EXEC_TIMEOUT_MS // 2`). The pass-2 request is aborted. | Pass 1 |
| `error` | The pass-2 request raised. | Pass 1 |
| `skipped_no_point` | B1's non-coordinate tools. | The call, unchanged |

**B4. Mapping is exact.** For every frame size, zoom 0.4 and every pass-2 point:
- the full-frame pixel that the executor's `to_pixels` produces from the mapped 0–999 value is within 1 px of `crop_x0 + to_pixels(x2, crop_w)`, and likewise for y;
- the mapped value is always in 0–999.

**B5. Freshness and identity hold.**
- The invocation's `frame` (geometry and phash) is the full own frame's, never the crop's.
- The crop is never registered in `_frame_bytes` or `_frame_geometry`, and never becomes any call's geometry.
- B9 is checked again after pass 2, just before `execute`. If the newest own frame changed in between, the call is refused with T-0111g's `FRESHNESS_REASON` and nothing is dispatched.
- The session takes no `frame()` during ReGround.

**B6. Concurrency** (docs/02 §4 P4, at the engine). A pass-2 request starts only after the step's generate stream has ended, and never overlaps a generate or a repair of the same session. The engine therefore sees at most one generate plus one prefill, with the pass-2 request counting as the generate.

**B7. Cancellation.**
- A barge-in or `tool.cancel` during pass 2 cancels the execute task and aborts the pass-2 engine id (`llm.abort`). Nothing is dispatched, and no `ToolResult` is submitted after the cancel.
- The execute deadline `TOOL_EXEC_TIMEOUT_MS` covers pass 2 plus the action.
- Closing the turn also aborts a live pass 2.

**B8. What the user sees.** The tool card and the result payload's `action` describe the action actually executed, i.e. the regrounded point. Pass 1's point appears only in the session log. Live payload keys are unchanged (C4).

**B9. Logging.**
- With `reground = true`:
  - the turn line gains `reground: {"requests": n, "ok": n, "fallback": n, "ms": [..]}`;
  - the live `--dry-run` line gains ` reground=on`;
  - `telemetry/spans.py` gains `tool.reground`.
- With `reground = false`, nothing is added: no request, no key, no record.

**B10. Negative.**
- With `reground = false`, live request bodies and records match the A/C state exactly. A reground bomb on the fake LLM is never touched.
- Ask-first and honour-no (T-0107a/e) calls are never regrounded and never executed.
- No reground runs in `dry_run`.

### Group D — the GPU A/B (report-only plus a pre-registered decision rule)

**D1. Harness.** `scripts/gpu/t0131_grounding_ab.py` imports T-0111g's harness rather than copying it: `TASKS`, `score`, `LoopMeter`, `sentinel_hits`, `url_leaks`, `log_complete`, `non_loopback_sockets`, `turn_records`. `TASK_TABLE_SHA256` is therefore the T-0111g value.
- `ARMS = ((280, False), (280, True), (560, False), (560, True), (1120, False), (1120, True))`.
- 150 turns in one order, shuffled jointly with seed 0 over (arm, task, repeat), so the arms are interleaved and time drift is spread across them.
- Each turn is a fresh `Session` with `tools = live`, headless, with `visual_tokens` set explicitly in every arm (including 280) and `reground` per arm.
- It refuses with exit 2, before any socket opens, on every T-0111g refusal and on an arm-table sha other than the pinned one.

**D2. Pre-flight probes.** These run before any arm turn. Any probe failure aborts with exit 3 and writes a void report.
- **P1, the budget takes effect.** For each budget, `/tokenize` (chat form, with `mm_processor_kwargs`) a fixed 1280×800 frame prompt with and without its image. The difference must be `expected_soft_tokens(1280, 800, N)` plus at most 4 image-delimiter tokens, i.e. 273/522/1092 (+0–4). The 512×320 crop must give the same. If any budget comes in below expectation, it is "not honoured": the run aborts and the T-0131b contingency applies (Open questions).
- **P2, the 1120 load.** One single-image generate at 1120 must return 200 and leave the engine healthy. Free VRAM is sampled every 200 ms throughout the run (`nvidia-smi`, read-only), and the minimum is reported per arm.
- **P3, a text-only request carrying the kwarg,** returns 200.

**D3. Metrics per arm.** All are report-only.
- **Success:** per task out of 5, and total out of 25.
- **Click metrics.** For every executed `click_at`/`type_at`, the harness reads, in the agent page just before dispatch, the boxes of the task's intended elements on the current page and `elementFromPoint` at the click. The read happens inside `_Watch.execute`, outside timed spans, with a read-only `page.evaluate`.
  - **Hit rate:** the click falls inside an intended box.
  - **Click error:** the distance in px to the nearest intended box (0 if inside), as p50, p95 and mean.
  - **Intended targets,** by DOM text and role. The pages themselves do not change.
    - S1: the search box, the "Blue mug" result, and the blue mug's "Add to cart".
    - S2: the blue mug's "Add to cart".
    - S3: the name, email and message fields, and Send.
    - S5: the cheapest item's "Add to cart".
    - S4: none expected; any click is reported.
  - **Paired comparison:** in ReGround-on arms, pass 1's counterfactual point is scored the same way.
- **Steps:** steps per turn, statuses and refusal reasons, plus the number of scrolls per S4/S5 turn.
- **False claims:** turns that are not a success but end with a voiced answer and no question asked. This is a proxy for "claims success", and it is hand-read before the write-up.
- **Latency:** step first-commit and done, p50/p95, with reground requests excluded.
- **Reground cost:** requests, outcome counts, latency p50/p95, and the extra execute time per coordinate step.
- **Prefix cache:** hit and query tokens per step, from `/metrics` deltas.
- **Turn wall time.**
- **VRAM:** the minimum free MiB.
- **Acceptance:** every request returns 200, retries and reground included.
- **Safety counts,** each expected 0: every T-0111g safety count, plus two new ones:
  - `reground_voiced`: any pass-2 text in `TtsSpeak.source`, history or the HUD spoken pane;
  - `reground_other_tool_executed`.

**D4. Safety layer kept.**
- The sentinel scan covers every forwarded body, reground included.
- The eval coverage row maps `llm.request` phases to scan labels:
  - `prefill` → `prefill:`;
  - `generate`, `tool_step` and `reground` → `generate:` (`LoopMeter` labels every non-repair generate `generate:`);
  - `tool_repair` → `repair:`.

  Every attempt must appear in `scanned_requests`.
- Log integrity: `log_complete`.
- The run stops after 3 consecutive errored turns.

**D5. Decision rule** (pre-registered; the numbers await H-T131-1).
- **Eligibility.** An arm is eligible only if all of these hold:
  - acceptance is 100 %, every safety count is 0, and the engine stayed up;
  - total success is at least the best arm's minus 3 (of 25);
  - hit rate is at least the best arm's minus 0.10;
  - step done p95 is at most 1.5 s;
  - in ReGround-on arms, reground latency p50 is at most 1.0 s.
- **Choice.** Among eligible arms, pick the fewest visual tokens, then ReGround off over on.
- **"No change"** if no arm is eligible, or if the best arm beats 280/off by at most 2 of 25 (noise at n = 5 per task).
- **"Inconclusive"** if P1 failed.

The report states the outcome label. Adopting a default is a later task.

**D6. Locked script.** `scripts/locked/t0131_grounding_ab.sh`:
- uses T-0111g's boot regime verbatim, with `services/vllm.sh` unchanged and one boot;
- keeps the port, container, dirty-tree and one-run-per-SHA refusals;
- refuses unless a `Merge T-0131` commit is an ancestor of HEAD;
- runs under `timeout 90m`;
- writes `logs/t0131-grounding-ab-<sha7>/`.
