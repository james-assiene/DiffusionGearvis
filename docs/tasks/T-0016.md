# T-0016 — guard_bash.sh detects GPU commands by effect, not by spelling

**Status:** merged 2026-09-13 (third review MERGE) · **Blast radius:** high (the hook is the only automated gate on GPU spend) · **Depends on:** none

## Goal
`.claude/hooks/guard_bash.sh` stops deciding what is a GPU/artifact command by matching substrings
anywhere in the raw command text. After this task it (a) catches GPU-spending commands that do not
happen to contain a magic word, and (b) stops blocking innocuous commands that merely *mention*
one inside a quoted string or heredoc body. The failing tests are already written:
`tests/unit/test_guard_bash_hook.py`, marked `pending(task="T-0016")`.

## Why (both defects observed live, 2026-09-13)

**A — false negative, the serious half.** The trigger is
`(astra[[:space:]]+bench|local_astra\.eval\.run|vllm[[:space:]]+serve|moshi-server|nohup[[:space:]]|…artifacts/)`.
This command sent two image-inference requests to a live vLLM engine — real GPU time —

```
bash /home/user/demos/local_astra/scripts/x3_prefix_cache.sh 2>&1 | tee …/logs/x3-prefix-cache.log
```

and matched **none** of it, because it tees into `logs/` rather than `artifacts/`. So it consumed
no launch token **and skipped the dirty-tree check entirely**. The gate we relied on all session
was not actually in front of the experiment that mattered most. Any future harness script has the
same hole by default: the rule rewards not naming things.

**B — false positive.** The patterns match anywhere in the command text, including inside quoted
strings and heredoc bodies, so describing a GPU command is treated as running one. Real blocked
commands this session, all of which should have been allowed:
- `git commit -F - <<'MSG' … MSG` whose message contained the literal `nohup ` (documenting the
  launch skill).
- the same, whose message quoted the error text `vllm serve: error: argument …`.
- a read-only `grep` whose *search pattern* contained `astra bench`.
- a `curl` using the max-time flag followed by an `nvidia-smi` query-gpu flag — blocked because the
  `-m gpu` pytest clause (`-m[[:space:]]*['"]?[^'"]*\bgpu\b`) matches the `-m` inside `--max-time`
  and then finds `gpu` inside `--query-gpu` later in the string. Found by the launch-reviewer
  2026-09-13 while reviewing an unrelated command. Fails closed, so a nuisance not a hole — but
  the clause must be anchored to a genuine pytest `-m` argument rather than any `-m`-ish substring.
- **a Bash call whose only purpose was to add the case above to this file.** The hook blocked the
  documentation of its own defect, because the text quoted the offending flags. Fifth instance in
  one session; recorded because it is the clearest possible statement of why matching command
  *text* rather than command *effect* is the wrong primitive.

B is not merely annoying: it trains everyone to reword commit messages to appease a regex, which
is exactly the habit that makes people work around a safety gate rather than with it.

## Drafted fix (review this before implementing — it is a sketch, not a spec)

Two independent changes; either can land without the other.

**1. Scan a normalised command, not the raw string.** Before matching, strip heredoc bodies and
quoted spans, so the patterns see only the executable shape of the command. The hook already
shells out to `python3` elsewhere, so this is a small filter rather than heroic bash:

```bash
scan=$(printf '%s' "$cmd" | python3 -c '
import re, sys
s = sys.stdin.read()
s = re.sub(r"<<-?\s*([\x27\"]?)(\w+)\1.*?^\2", " ", s, flags=re.S | re.M)  # heredoc bodies
s = re.sub(r"\x27[^\x27]*\x27|\"(?:[^\"\\\\]|\\\\.)*\"", " ", s)           # quoted spans
print(s)')
```
then match `$scan` instead of `$cmd`. Risk to weigh: a real GPU command written *inside* quotes —
`sg docker -c "… vllm serve …"` — would stop matching, and that is exactly how we launch. So the
stripping must keep `sh -c` / `bash -c` / `sg … -c` payloads. Simplest correct rule: strip
heredoc bodies always, strip quoted spans **except** when the quote is the argument of `-c`.
Whoever implements this should decide whether that exception is worth the complexity or whether
heredoc-stripping alone fixes every observed case (it fixes 2 of the 3).

**2. Detect by effect.** Add triggers that do not depend on the author choosing a word:
- `docker[[:space:]]+run` together with `--gpus` — catches any direct container run.
- a path convention: any command referencing `scripts/gpu/` is GPU-spending by definition. Move
  `scripts/x3_prefix_cache.sh` to `scripts/gpu/` as part of this task, and state the convention in
  `.claude/rules/gpu-services.md` so new harnesses land there by default.
- optionally, any `curl`/`http` to the engine ports (8001/8002/8080/8081). Weigh this: it would
  also catch read-only `/metrics` and `/v1/models` polling, which we do constantly and which
  spends nothing. Probably scope it to `POST`, or leave it out and rely on the path convention.

The path convention is the load-bearing half. Spelling-based detection failed because it asks the
author to remember; a directory is structural and survives someone writing a new script.

## Open decisions (raised by the test-author; resolve before implementing)

**D1 — RESOLVED 2026-09-13 (implementer): keep heredoc bodies fed to an interpreter.** A
heredoc body is blanked *unless* the command outside the body names an interpreter (`bash`, `sh`,
`sg`, `ssh`, `docker`, `python`, `uv`, `eval`, `source`, `exec`, …), in which case the body is
scanned in full. The test is structural, not positional, so it also holds for `cat <<SH | bash`,
where the interpreter appears after the delimiter: the substitution keeps the remainder of the
delimiter's own line and blanks only from the newline to the terminator. That detail is easy to get
wrong — the first version of this fix swallowed `| bash` along with the body and made the launch
invisible; it was caught by probing the normaliser, not by the suite. Cost of the decision: a commit
whose *non-body* text happens to name an interpreter has its body scanned, so it can still be
refused for quoting a GPU command. That fails closed, is rarer than the defect-B cases, and is the
price of not re-opening defect A. No third mechanism was added: the `scripts/gpu/` convention is the
backstop here, not the primary.

*Original question, for the record:* **D1 — the defect-B cure re-opens defect A through heredocs.** "Strip heredoc bodies always"
means `bash <<'SH' … vllm serve … SH` becomes invisible to the hook: a GPU launch hidden in
exactly the construct we taught the guard to ignore. The `-c`-payload exception sketched above
covers `sh -c` / `sg … -c` but not heredoc-fed `bash`. Decide explicitly: strip heredoc bodies
only for commands whose program is not a shell, keep scanning heredocs fed to an interpreter, or
accept the hole and rely on the `scripts/gpu/` convention. The test-author deliberately did not
write this as a regression test, because as drafted the fix would fail it.

**D2 — RESOLVED 2026-09-13 (human): clean-tree check only, no reviewer pass.** Starting a
service requires a clean tree and is recorded in `PROGRESS.md` *Runs*, but does not need a
`launch-reviewer` pass. Full `/launch` stays for commands that produce numbers (bench, eval,
measurement harnesses). Rationale: the hazard is not that an engine was started, it is measuring
later against a tree that was dirty when it started — the cheap invariant catches that, while a
review cycle on every service start is the friction that trains people to route around the gate
(four instances of exactly that happened in the session which found these defects). This splits
the hook's two bundled functions: cheap invariants (clean tree, single-use token, Runs entry) vs
expensive pre-flight review. Implement as a second, lighter trigger class.

*Original question, for the record:* does starting a service need `/launch`? `uv run astra up --profile lean` and
`systemctl --user start astra-vllm` both start the engine and take VRAM, so *by effect* they
belong in the blocked set. But CLAUDE.md's own Commands section lists `astra up` as a routine
command. **The spec contradicts itself and this is a human call**, not something to resolve in the
hook. No test was written either way. If routine, say so in the rules file so the exemption is
deliberate rather than accidental.

**D3 — RESOLVED 2026-09-13 (implementer): accepted, scoped to inference endpoints carrying a
request body.** The trigger fires when the command names `/v1/chat/completions`, `/v1/completions`,
`/v1/embeddings` or `/v1/responses` *and* carries `-X POST` / `--request POST` / `-d` / `--data*` /
`--json`. Both halves are needed: the endpoint alone would block `rg /v1/chat/completions`, and the
body alone would block every `curl -d` we run. `GET /v1/models` and `/metrics` stay free, pinned by
`test_polling_the_engine_for_status_is_allowed`.

*Original question, for the record:* **D3 — the engine-POST trigger.** `tests/unit/test_guard_bash_hook.py::test_a_post_to_the_running_engine_needs_a_launch_token`
is pending and is a deliberate over-reach beyond this task's sketch: a hand-typed
`curl -X POST /v1/chat/completions` spends exactly the GPU time the x3 harness spends. If the
implementer declines it, that is a decision recorded here — not a test deleted quietly. The
paired guard `test_polling_the_engine_for_status_is_allowed` pins the other direction: `GET
/v1/models` and `/metrics` must stay free.

**D4 — `--gpus all` in the test helper is unnecessary (found 2026-09-13).** The launch-reviewer
executed `tests/container_scripts/astra_shim_probe.py` in the pinned image with no GPU attached and
it ran to completion: importing `diffusion_gemma` does not need a device, because the
`@torch.compile` decorator only wraps at import time. So the GPU flag in `run_probe`
(`tests/vllm_container.py`) buys nothing, and it is the sole coupling between the shim tests and a
live engine — dropping it removes the VRAM-contention question permanently. That file belongs to
the test-author, so it is recorded here rather than edited in passing, and the helper's docstring
states the wrong rationale for the flag, which should be corrected in the same change.

**D5 — the interactive rungs now need a launch token, and that is friction (raised by the
implementer 2026-09-13; needs a human call). SUPERSEDED by ruling D5 below: option 2 was chosen and
the two files now live in `scripts/demo/`.** `scripts/gpu/ask.py` and `scripts/gpu/_listen.py`
lived under the convention, so `uv run python scripts/gpu/ask.py "…"` was blocked without a token —
and the token is single-use, so twenty demo questions cost twenty approvals. They do spend GPU time,
so exempting them *by name* would be exactly the spelling-based thinking this task removes, and no
exemption was added. Two candidate resolutions, neither implemented here because the token mechanism
is explicitly out of scope for this task:
1. a session-scoped approval for the light class (a token that survives until the tree changes),
   which keeps the clean-tree invariant — the part D2 says actually matters — and drops the per-run
   friction; or
2. a sibling directory (`scripts/demo/`) for hand-driven tools that only *use* an engine somebody
   else already launched, leaving `scripts/gpu/` for anything that produces numbers.
Option 1 fits D2's reasoning better: the hazard is measuring against a tree that was dirty, not the
number of times a human asked the model what is on their screen.

Note also that D2's ruling still requires a *token* for a service start (only the reviewer pass is
dropped). That reading is forced by the existing regression tests: `test_vllm_serve_without_a_token_is_blocked`
and the `docker-run-gpus` case both demand a refusal on a clean tree with no token, so a
"clean-tree check only, no token" reading of D2 cannot be implemented without breaking them.

**D4 — untouched, still for the test-author.** `tests/vllm_container.py` is not in this task's owned
files, so `run_probe`'s `--gpus all` flag and its docstring are unchanged here.

## Note on how this was found
Not by review — by the hook failing to fire during a real GPU experiment, noticed only because the
launch-reviewer was asked to confirm the guard's behaviour as a side question. Both defects had
been present since the scaffold. The lesson worth keeping: a gate nobody has tried to walk past is
not known to work, and this one was walked past accidentally, repeatedly, by its own author.

## Rulings after review (2026-09-13, orchestrator under the human's autonomy grant — override welcome)

**D5 — RULED: interactive demo scripts are ungated, in `scripts/demo/`.** `scripts/gpu/ask.py` and
`scripts/gpu/_listen.py` move to `scripts/demo/`. They send one request to an engine that is
already running and produce no number anyone will quote; gating them cost one `/launch` review per
spoken question, which is the friction that gets a hook disabled. `scripts/gpu/` keeps its meaning
— harnesses that spend GPU time to produce a measurement — and stays gated. No name-based
exemption anywhere: the directory is the rule. The human set the demo as tonight's priority and
ruled D2 the same way for service starts; if they disagree, moving two files back reverses it.

**I1 — `cd scripts/gpu && ./x3…` must be blocked.** A `cd`/`--directory` into `scripts/gpu` (or
`scripts/locked`) counts as the trigger. Agents in this repo write `cd X && …` on every call.

**I2 — `scripts/locked/` joins the convention.** `/launch` step 2 copies long scripts there and
runs from there; a re-run after the token is spent must not be invisible.

**I9 — read-only work under `scripts/gpu/` must be allowed** (`ruff check`, `bash -n`,
`py_compile`, `--help`, `cat`): the trigger requires the path to be the interpreter's first
non-flag argument, or the command word to be an execution rather than a lint/read prefix. The
rules text already promises this; the hook must keep the promise.

**I8 — D2 is recorded as NOT implemented.** The change only alters a refusal message; no
mechanism issues a token without a reviewer pass, and `.claude/skills/launch/SKILL.md` is unowned
by this task. D2's mechanism (a light token class for service starts) is a follow-on that owns the
skill file. Do not describe D2 as done.

**I4–I7 — residual edges, documented not fixed:** an inline `python -c` inference request, a
quoted redirect into `artifacts/`, CDI `--device nvidia.com/gpu`, and a GPU script outside the
convention all pass. One line each in `.claude/rules/gpu-services.md`; the guard is a speed bump.

**T1–T3 (test-author):** pin the D1 direction (a heredoc-fed interpreter must stay blocked — the
implementer chose strict, and a mutation to blank-always leaves 29 green); fix the vacuous

## Rulings after the second review (2026-09-13, verdict REVISE — one blocking)

**I10 — a quoted gated path is still a gated path (blocking).** `bash "scripts/gpu/x3.sh"`,
`bash 'scripts/gpu/x3.sh'`, `bash "$TOP/scripts/gpu/x3.sh"`, `cd scripts/gpu && bash "x3.sh"`,
`bash "scripts/locked/x3.sh"` are all ALLOWED today because `scan = unquote(...)` blanks the quoted
span before `runs_gated` looks. Derive `gated` from `resolve_cd(bodyless)` (quotes kept, heredoc
bodies blanked) — `bare()` already strips quote characters per token — and keep the `-c` payload
exception as is. Test-author: quoted-path rows in `GPU_SPENDING` for each of the five spellings.
**I11 — `timeout N` joins `WRAP`** (an ordinary spelling; one token). `source`/`.` of a harness is
added too — it runs the file in the current shell. The rest of the indirection family (`cat | bash`,
`bash < file`, `xargs`, `find -exec`, `make <target>`, `eval "$(cat …)"`, `docker exec`, symlink)
stays a documented residual: `.claude/rules/gpu-services.md` gains one sentence saying indirection
of any kind defeats the path trigger — the hook is a speed bump, not a sandbox.
**I12 — D2 is what the human decided: service starts need a clean tree, not a token.** The branch
newly gates `uv run astra up` and `systemctl --user start astra-*` behind a token while the message

reviews. Ruling: `astra up` / `systemctl --user start astra-*` require **only** the clean-tree check
(dirty tree → BLOCKED naming the dirty paths; clean → ALLOWED, no token, no PROGRESS entry). The
message and `.claude/rules/gpu-services.md` say exactly that. Test-author: both directions for both
spellings (the trigger is untested today — deleting it leaves 56/56 green).
