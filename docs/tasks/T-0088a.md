## Goal
Give the conductor what reading B needs to read native tool calls on the host:
- the frozen special-token and stop tables of the pinned tokenizer;
- a stdlib-only incremental detokeniser of the pinned `tokenizer.json`. It reads the decoder only, and turns streamed token ids into
  exactly the text the pinned HF tokenizer would decode (`skip_special_tokens=False`);
- a speech gate that trims or drops every special token, so that no special token can be voiced on any path.

Nothing on the live path changes yet: no request, prompt or commit differs from `main`.

## Acceptance criteria
1. **Tables** (`toolcall/special_tokens.py`, stdlib only).
   - `SPECIAL_TOKENS`: the frozen tuple of the pinned tokenizer's added tokens that have `special: true`, in id order. There are 24 at
     `cc8d3a0c…`.
   - `SPECIAL_IDS`: the matching mapping from id to literal.
   - `STOP_IDS = frozenset({1, 106, 50})`. This is the pinned `generation_config.json` `eos_token_id`, and equals `replay.STOP_IDS`.
     T-0087 q5 saw 50 on 20/20 tool streams and 106 on 4/4 chat streams.
   - `drop_special_literals(text)` deletes every `SPECIAL_TOKENS` literal, repeating until none is left, because one deletion can splice
     a new literal. This is the same rule as `router._drop_channel_markers`.
   - A cd-group row proves all three tables against the pinned files.
2. **Detokeniser** (`toolcall/detok.py`, stdlib only).
   - **Loading.** `HostDetokenizer.load()` reads `tokenizer.json` of rev `2ea8372…` from the local HF cache, using the same path rule as
     `decoding.vocab.snapshot_dir`, restated here because the conductor must not import `decoding`. It raises, naming the file and the
     reason, if any of these hold:
     - the sha256 is not `cc8d3a0c…`;
     - the model is not BPE with `byte_fallback: true`;
     - the decoder is not exactly `Sequence[Replace("▁"→" "), ByteFallback, Fuse]`;
     - the special added tokens are not `SPECIAL_TOKENS`.

     A constructor that takes an explicit path and expected sha exists for fixtures. Nothing touches the network.
   - **Decoding.** For every id sequence, `decode(ids)` equals `tokenizers.Tokenizer.decode(ids, skip_special_tokens=False)` on the
     pinned file. That includes byte-fallback runs, invalid and truncated UTF-8, and specials next to byte runs. The cd differential is the
     oracle.
   - **Incremental decoding.** `stream()` returns an object with `feed(ids) -> str` and `finish() -> str`. For every partition of an id
     sequence into chunks, `"".join(feed(c) for c in chunks) + finish()` equals `decode(all ids)`.
     - A byte-fallback run split by a chunk boundary is held back until it can be decoded.
     - A special id is a single piece and is never split.
   - **Unknown ids.** An id outside the vocabulary raises `UnknownTokenId`; the detokeniser never guesses.
   - **No host encoding.** Seed tokenisation stays the engine's `/tokenize` (H9; q10 was 10/10).
   - **Linear time.** 4096 ids fed one id per `feed` take under 50 ms in total on CPU (median of 5). This guards linear time: re-decoding
     the whole prefix on each chunk fails it.
3. **Speech gate** (`speech_gate.py`).
   - **Trimmed.** `<turn|>`, `<eos>`, `<|tool_response>` and `<|tool_call>` mark the end of what may be spoken, and `<|channel>` marks a
     thought. Each trims the text the way the existing EOS rule (A2) does.
   - **Dropped.** Every other `SPECIAL_TOKENS` literal is deleted in place, including:
     - `<channel|>`, `<tool_call|>` and `<|"|>`;
     - `<|turn>`, `<|tool>`, `<tool|>` and `<tool_response|>`;
     - `<|image>`, `<|image|>`, `<image|>`, `<|audio>`, `<|audio|>`, `<audio|>` and `<|video|>`;
     - `<pad>`, `<bos>`, `<unk>` and `<mask>`.
   - **Never voiced.** No `Sentence.text` ever contains a `SPECIAL_TOKENS` literal.
   - **Conservation.** A1 (byte-exact) holds. A refused or trimmed source travels with `text=""` (A20).
   - **Tool segment.** A `Commit(segment="tool")` fed to the gate raises `GateInputError`. The existing `!= "answer"` check already
     covers this; a row pins it.
   - *Negative.* For committed text with no `SPECIAL_TOKENS` literal, the output equals `main`'s, including the existing `<end_of_turn>`
     and `<|endoftext|>` trims.
4. *Negative.*
   - `detok.py` and `special_tokens.py` import nothing beyond the stdlib: no `tokenizers`, `local_astra.decoding`, torch, numpy or
     outlines. The existing toolcall AST fence covers them, and a fresh-interpreter row also checks `tokenizers`.
   - The conductor still imports no cd module (the `test_cd_isolation` probe, unedited).
   - Unchanged:
     - `llm_client.py` and `contracts/**`;
     - in `toolcall/`: `router.py`, `native.py`, `score.py` and `tools.py`;
     - `eval/**`, `decoding/**` and `plugin/**`;
     - `pyproject.toml` and `uv.lock` (no new dependency).
   - Every existing row of `test_speech_gate.py` and `test_speech_gate_voice_guard.py` stays green, unedited.

## Rulings (orchestrator, 2026-10-12, on the test-author's questions)
- **D1. `<|think|>`** is trimmed: main's A3 rule, and what the unedited `test_speech_gate.py` requires.
- **D2. Dropped literals** are deleted with nothing. Neither the gate nor `drop_special_literals` inserts a space.
- **D3. Constructor and errors.**
  - The constructor is `HostDetokenizer(path, expected_sha256)`, both positional.
  - Every refusal raises `ValueError`, or a subclass of it, naming the file and the reason.
  - A missing file may raise `OSError` or `ValueError`.
- **D4. Byte runs.** A byte run is held until a non-byte piece arrives or `finish()` is called, even when it is already valid UTF-8. HF
  renders an invalid run as one U+FFFD per byte, so emitting early can break equality with the oracle.
- **D5. Unknown ids.** The host raises on an unknown id, whereas `tokenizers` silently drops it. This divergence is intended, and the cd
  row pins it.
- The test-author's fixture extras are accepted: the streams' ordered ids, the oracle texts and the fragment pieces.
- **D6 (at fbc442f).** "Never voiced" outranks parity with main.
  - **Where they conflict.** Main's path rewrite can create a special literal from special-free prose: `</eos>` becomes `<eos>`, and
    likewise for pad, bos, unk and mask.
  - **The rule.** The gate drops any literal left after normalisation. It differs from main only where main would have voiced a special
    literal.
  - **Rows (test-author).** One row per such input.

## Implementation notes
- Byte-fallback semantics follow HF `ByteFallback`. Consecutive `<0xNN>` pieces form one byte run. How an invalid run renders is whatever
  the cd differential shows, not whatever `bytes.decode("utf-8", "replace")` does. Added tokens are emitted verbatim, outside the
  Replace/ByteFallback chain. Check both against the oracle; do not assume them.
- Loading costs about 0.2 s (`json.load` of a 31 MB file; the regime is under *Regime*). It happens once, at construction, and never
  inside a turn. T-0092 constructs the detokeniser at session start when `tools = dry_run`.
- `SPECIAL_TOKENS` stays a literal tuple, so the speech gate never depends on a file being present.
- Rules to respect:
  - `.claude/rules/conductor.md`: what is spoken is filtered where speech is produced, and a refusal conserves bytes with `text=""`.
  - `.claude/rules/gpu-services.md`: nothing here talks to the engine.

## Rulings after review (orchestrator, 2026-10-12; reviewer 2 APPROVE, reviewer 1 REQUEST CHANGES for tests only, at 82cd908)

  includes `</turn|>`, `</channel|>`, `</tool|>`, `</image|>` and `</audio|>`. A literal created this way is always **dropped**, even

- **Rows (test-author):**
  - **Splice trims.** Exact rows for the four splice inputs, for example `"Hi <|chan<channel|>nel> there. Done."` →
    `[('…', 'Hi'), ('Done.', '')]`. Each checks the exact spoken text, and that every later sentence has `text == ""` (the latch).
  - **D2 at the gate.** One exact, unsquashed row: `"Hel<pad>lo world."` speaks `"Hello world."`. Also update the module docstring
    that still calls the choice unspecified.
  - **D6:** a `</turn|>` row.
  - **The differential on D6 sentences** asserts the exact relation `g.text == " ".join(drop_special_literals(w.text).split())`.
  - **Mixed prose and literal:** one row combining prose brackets with a real literal, `"Write <turn> here.<pad> Ok."`, keeps
    `<turn>`.
  - **Atomic `feed`.** `feed([byte, word, bad])` raises, and afterwards `feed([word]) + finish()` equals the decode of `[word]` alone.
  - **`finish()` twice.** A second `finish()` returns `""`.
