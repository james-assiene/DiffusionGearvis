# T-0216b — a received frame never drops the connection or kills the session log

**Status:** merged 2026-10-31 at fea21b87 (tip a3e5aaab); was in progress (impl 276688bc + tests 503bd87a combined) (2026-10-31; found by the T-0216 reviewer, probes in the session scratchpad `p16/probe2.py`, `p16/probe3.py`).

## Goal

T-0216 made `codec.decode` total. Two paths after it still break on frames a client can send:

- **F1.** `HudConnection._log_wire_in` (`local_astra/conductor/hud_server.py:812`) calls `decoded.model_dump(mode="json")`. For a Realtime-typed frame nested about 255–992 deep, pydantic-core's serializer raises `ValueError: Circular reference detected (depth exceeded)`. `_serve_connection` swallows it and closes the socket: a dropped connection with no `astra.error`, contradicting `receive`'s docstring ("nothing a client can send raises").
- **F2.** `SessionLog._emit` (`local_astra/telemetry/session_log.py:530`) catches only `OSError` around `handle.write`. A frame carrying a lone surrogate (`{"type":"x","a":"\ud800"}`, or `astra.text` with `"a\ud800"`; browsers' `JSON.stringify` emits such escapes) decodes fine, `json.dumps(ensure_ascii=False)` succeeds, and the write raises `UnicodeEncodeError`. The writer task dies: later rows never reach disk, and `Session.aclose` re-raises.

## Acceptance criteria

1. F1: `receive` on a Realtime-typed frame nested at any depth from 1 to the parser's limit (list and dict) does not raise and keeps the connection open. The frame is handled as it is today, and its `wire.in` row is still written: a digest/fallback form is fine when the payload cannot be serialized, and it carries no payload text.
2. F2: a record containing a lone surrogate is written as one valid UTF-8 JSON line (the surrogate escaped), the writer keeps running, every later record reaches disk, and `aclose` does not raise.
3. Negative: every record that serializes today is written byte-identically (the session-log byte-identity differentials stay green). Nothing about `astra.*` handling, the turn machine or the codec changes.
