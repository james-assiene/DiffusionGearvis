## Goal

**Confirmed in source:** `type_at`'s plan is click, then `keyboard.type(text)`, then Enter (`executor.py` 805-822 and 1081-1108; `_dispatch_guarded` 1003-1035). Nothing selects or clears the field.

In t12 the model typed `photopy` into `/web.html`'s address field (the agent browser has no URL bar). The page refused it: there is no dot (`web.html` 45-47), and the field kept the text. Each later `type_at` of `https://www.photopea.com` appended to it:
- the field read `photopyhttps://www.photopea.com…`;
- the scheme regex then read `photopyhttps:` as the scheme and the page refused that too (`web.html` 48-53);
- the result was ten `navigated:false` calls (s4-s14).

It succeeded only after the model clicked, pressed Ctrl+A and Backspace, and retyped (s15-s18).

After this task, `type_at` into a focused single-line text input replaces the field's content. Multi-line and rich editors are not wiped.

## Acceptance criteria

1. **Replace.** When the post-click focused-field read (T-0160 B-3, `focused_field`) reports `tag == "input"` with `type` in {`text`, `search`, `url`, `email`, `tel`, `number`, empty}, and the field is not a secret field, the executor selects all (the existing `Ctrl+A` chord) before typing. Typing then replaces the selection. `resolved` gains `"replaced": true`.
2. **No wipe.** Focus on a `textarea`, a contenteditable element, `body`, an opaque element, or an unreadable focus never gets a select-all. Text is typed at the caret as today, or refused as today.
3. **Secret fields.** Unchanged: nothing is typed, there is no select-all, and the reason and `typed: 0` stay as they are.
4. **Model-facing text unchanged.** The executed `action` string, the tool response the model sees, `tools_v1.json` and `tools_v1_overview.json` are byte-identical. No `clear` argument (H-T189-1). The tools sha is pinned in 38 + 13 files and in the cached system prefix.
5. **Unguarded drivers.** A driver without `focused_field`, outside web mode (BASE fakes), has an identical dispatch sequence.
6. **Reproduction.** On the real `/web.html` (loopback, headless Chromium):
   - `type_at "photopy"` then `type_at "https://<fixture host>"` navigates on the second call;
   - before the fix it does not navigate.
7. **Spec change named.** Existing rows that pin the exact keystroke sequence of `type_at` into a text input under a focus-reading driver are re-read under this criterion by the test-author, never loosened. Candidates: `test_computer_web_executor.py`, `test_t0174_navigated_executor.py`, `test_computer_executor.py`, the T-0160 browser modules. The list is recorded in this file at activation.

## Implementation notes

- Use the one focus read the guarded path already makes. Do not add a second DOM read or any page script. Nothing from the read reaches the model; this keeps to the pixel-first rule.
- Keep the existing `COMBOS["Ctrl+A"]` chord and `_release` on cancellation. A held Control must be released on any exit (criterion 11 of T-0111c).
- Out of scope: the repeat guard did not stop the ten repeats. Confirmed in source: the step's `no_change` comes from `updated` (`session.py` 3602, 3647), which compares capture identities, a sha256 of the JPEG bytes (`_capture_identity`, 626-629). The appended text changed pixels each time, and frame phashes from s9 to s14 were identical (`254a268f0bb13671`). So every repeat read `screenshot: updated`, `no_change` stayed False, and `MAX_NO_CHANGE_REPEATS` never triggered. The screen visits on that phash formed two runs (s7-s8 and s10-s15), under `MAX_SCREEN_VISITS = 3`. That fix is T-0190 (H-T189-3), not this task.
