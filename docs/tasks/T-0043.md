# T-0043 — Session logging: a per-session debug log behind a HUD checkbox, on by default

**Status:** done (merged at c02fdc3; status corrected 2026-10-23 from 'in progress', T-0147 audit: no implementation in flight) · earlier: in progress 2026-09-16 — **group B** (tests activated at this commit, implementer next); **group A merged**; group C (the summary tool) planned. three groups, ordered (A → B, C after A) · blast radius **medium** (one reviewer; escalation trigger in §7) · **starts after T-0041 merges** (`local_astra/cli.py`) **Criterion 17 is partly unmet and must not close as done on it:** the opening record carries the process id and the path, not the session id, commit, profile, regime or lock digest (ruling B10, sharpened by the group B review — the session id is what joins two files from one session across a toggle).

## 1. Goal

Tonight (2026-09-15, the human at the desk) the model was asked to illustrate something with A2UI, said it had, and nothing appeared on the page. Every `turns.jsonl` line says `ui_valid: null` — i.e. no `ui` segment ever reached the gate — and *nothing anywhere recorded the raw canvases*, so the three hypotheses (the model never emitted a `ui` segment; it emitted one that `split_segments` did not recognise as one; the gate or the `request_id` guard in `_note_event` dropped it silently) cannot be told apart after the fact. This task gives every session a per-session debug log: one JSONL file per session under `logs/sessions/`, written by a bounded non-blocking writer that never touches the pump, holding every HUD wire message in both directions, every machine event and the commands it produced, every LLM request and every canvas/commit/segment **as received from the backend**, the UI gate's verdicts, TTS utterances and played reports, the endpointer's decisions, and the turn record — with screen pixels never written (size + phash only). It is controlled by a HUD checkbox "Log this session", **on by default**, over a new `astra.log.toggle` / `astra.log.state` wire pair that mirrors the assist-toggle precedent, with a `--no-log` / `--log-dir` CLI override, the path printed at session start and carried on every `turns.jsonl` line. A small `scripts/demo/session_log_summary.py` turns a log into one line per turn — input, the raw canvases' segment tags, whether a `ui` segment appeared, the gate's verdict — which is the command that would have answered tonight's question in one shot.

Explicitly in scope and easy to get wrong: **the model's thinking IS logged.** The project rule "never store assistant *thinking* in history" (CLAUDE.md, `.claude/rules/conductor.md`) is about the conversation history the model is shown and about what is spoken and published; it is not a prohibition on recording what happened. Thought canvases are exactly what one analyses when an answer goes wrong, so they go in the log verbatim — and stay out of history, out of `astra.spoken`, out of TTS and out of the HUD panes, as they are today.

Non-goals: no rotation, no retention policy, no compression, no log shipping, no change to the turn machine, no change to what is spoken or published, no per-turn logging of screen pixels, no second copy of the audio.

## 2. Acceptance criteria

Each is independently checkable by a test or a bench threshold. Group letters refer to the ordering under **Owned files**.

**Group A — the writer, the taps, the turn line, the CLI**

1. `local_astra/telemetry/session_log.py` provides `SessionLog`, which writes `logs/sessions/<YYYYMMDD-HHMMSS>-<pid>.jsonl` (directory from `--log-dir`, default `supervisor.log_dir() / "sessions"`, created if absent; `logs/` is already gitignored, so the file is ungitted by inheritance — a criterion asserts `git check-ignore` agrees). One JSON object per line, UTF-8, `\n`-terminated, each line flushed before the next is written, so the file is readable line-by-line **while the session is still running**. Satisfies docs/02 §8 (observability).
2. Every record carries the same envelope: `seq` (0-based, strictly increasing, no gaps), `t_ms` (int, milliseconds since the file opened, from a monotonic source, **non-decreasing across the file**), `wall` (ISO-8601 local time with UTC offset, stamped when the record was *offered*, not when it was written), `session_ms` (the session clock's `now_ms` when the caller knows it, else `null` — this is what joins a record to a `turns.jsonl` span), `kind`, `turn_id` (or `null`) and `data`. `kind` comes from a closed vocabulary declared in one place: `log.started`, `log.stopped`, `dropped`, `wire.in`, `wire.out`, `machine.step`, `llm.request`, `llm.commit`, `llm.done`, `ui.gate`, `tts.utterance`, `tts.played`, `stt.decision`, `turn.record`, `error`, `note`. A record whose kind is outside it is a programming error caught by the record contract, not written.
3. `SessionLog.record(kind, data, *, turn_id=None, session_ms=None)` is **synchronous, total and never blocks**: it is not a coroutine, it performs no I/O and no `json.dumps`, it retains no reference to a caller-owned mutable object (it snapshots), it never raises for any input — a value that cannot be serialised becomes an `error` record naming the kind and the offending path, never an exception on the pump. A bounded queue (`maxsize` default 4096) is offered with `put_nowait`; on overflow the record is **dropped and counted** (the HUD-outbox discipline of T-0028), and the next successfully written record is preceded by one `dropped` record carrying `{"count": k, "since_seq": n}` so a gap is always visible in the file. Memory is bounded: after 10 000 offers with the writer task never scheduled, `qsize() <= maxsize` and no other unbounded container has grown.
4. A single writer `asyncio.Task` owns the file: started from `Session.start()`, drained-then-closed from `Session.aclose()` under a bounded timeout. Any `OSError` from the file (permission, disk full, a `--log-dir` that is a file) **disables logging for the rest of the session, publishes the new state, prints one line, and does not end the session**: the turn under way completes and its `turns.jsonl` line still appears with `session_log: null`.
5. **Redaction is structural, not field-name-based.** The redactor walks the dumped record tree and replaces (a) any base64 JPEG payload and (b) any `data:` URL, wherever it occurs — `astra.frame.jpeg_b64`, a `Prompt` image part's `url`, an A2UI `AnnotatedImage` source inside `AstraUiSurface.messages`, a string field like `title` that happens to hold one — with `{"redacted": "image", "bytes": n, "digest": "<8 hex of sha256>", "phash": "<hex>|null", "mime": "…"}`. No file written by this task ever contains a base64 JPEG (`/9j/`), the substring `data:image`, or any PCM. Satisfies docs/02 §9 (privacy) and the pixel-first rule that screen contents are never persisted outside the memory store's thumbnails.
6. **Thinking is logged.** A `thought` commit appears in the log with its full text, and a positive test asserts it does — the redaction of criterion 5 must not be over-broad. At the same time the existing guarantees hold with zero change: no thought text in history, in `astra.spoken`, in a `TtsSpeak`, or in anything `HudServer.publish` fans out (the T-0036/T-0037 thought-leak scan is extended over the logging rows and stays green).
7. Both wire directions are recorded by the transport, regardless of whether a page is attached: `HudConnection.receive` writes one `wire.in` per inbound frame — **including** malformed, `no_hello`, wrong-direction and oversized ones — carrying `{"n_bytes": len(raw), "outcome": "astra|unknown|realtime|malformed", "msg": <redacted wire-form dump or the decode error>}`; an oversized (up to 8 MiB) message contributes its byte count and its outcome and **never its body**. `HudServer.publish` writes one `wire.out` per published message with the wire-form dump and `n_bytes`; a message an outbox refused is recorded with `"dropped": true` rather than as sent. Frames still reach `BrowserFrameSource` byte-identically (the tap neither consumes nor mutates).
8. The pure machine's inputs and outputs are recorded at the one `machine.step` call site: one `machine.step` record per step, `{"event": <E.* dump>, "state_before": …, "state_after": …, "turn_seq_before/after": …, "commands": [<C.* dumps>]}`. `turn_machine.py` has zero diff and gains no import (architecture §4: the machine is pure; the tap is the session's, on the session's side of the call).
9. Every LLM request is recorded before it is sent: `llm.request` with `{"phase": "generate|prefill", "request_id", "attempt_id", "options": <LlmOptions dump>, "xargs", "prompt": <redacted Prompt dump>, "drop_history_turns", "prompt_tokens": <the engine's count when known>}`. The prompt's text parts are verbatim; its image parts are redacted per criterion 5.
10. **The item tonight needed:** every `Commit` yielded by the backend is recorded as `llm.commit` — `{"request_id", "canvas_idx", "segment", "text" (untruncated), "thought_open"}` — at the point it is received in `_run_generate`, *before* `self.submit`, so a commit the session later drops is still in the log. `llm.done` and the retry/error paths are recorded likewise.
11. Every UI-gate verdict is recorded: `ui.gate` with `{"canvas_idx", "ok", "repairs", "resamples", "surface_emitted", "surface_messages": n, "problems": [...], "raw_len"}`. When a commit with `segment == "ui"` is **not** gated (the `request_id != active_generate` branch of `_note_event`, or no open turn), a `ui.gate` record with `"gated": false` and the reason is written instead. Consequence, and the headline acceptance test: **for any turn, the log alone distinguishes the three states** — (a) no `ui` segment was ever committed, (b) a `ui` segment was committed and no surface was emitted, with the gate's own problems list, (c) a surface was emitted.
12. Speech and listening are recorded: `tts.utterance` at `enqueue_speech` (`utterance_id`, `text`, `source`, `kind`), `tts.played` at `_publish_played` (the per-utterance played report), `stt.decision` at the endpointer's decision (EMA, the pause-head vector, the reason, `t_eot_ms`) and the per-turn STT counters at turn close. STT words and steps arrive as machine events and are covered by criterion 8; their `prs` vectors are written in full (they are four floats).
13. `turn.record` carries the complete `TurnRecord` dump at `_write_record`, so a log stands alone for analysis, and `error` records carry every exception the session swallows today (`_safely`, `LlmError`, `SttError`, `TtsError`, `HudError` commands) with the `what` string and the exception repr.
14. `TurnRecord` gains `session_log: str | None = None` — the absolute path of the log file this turn was recorded in, or `None` when logging was off for that turn. It is a top-level field, not an `extras` key (a bench reader must not have to guess), every other field is unchanged, and a `turns.jsonl` line written before this task still parses.
15. `astra session` gains `--no-log` (start with logging off) and `--log-dir DIR`; `run_session` prints one line naming the exact log path (or that logging is off), and `--dry-run` / `describe_graph` reports `log=<path>` or `log=off`. With `--no-log` no file is created in the log directory at all.

**Group B — the wire toggle and the checkbox**

16. `contracts/protocol.py` gains `AstraLogToggle(type="astra.log.toggle", on: bool)` in `CLIENT_TO_SERVER` only, and `AstraLogState(type="astra.log.state", on: bool, path: str | None, records: int, dropped: int, bytes: int, error: str | None)` in `SERVER_TO_CLIENT` only; both are in `AstraMessage` and `ASTRA_MESSAGE_TYPES`, the round-trip test is parametrised over them unchanged in shape, and the two direction sets stay disjoint and jointly cover every model. A **new pair**, not a field on `AstraAssistToggle`: the log flag is not an assist, must not enter `AssistFlags`, the assist badge or `Regime` (a turn's regime says what the model could see, not whether we were debugging).
17. `HudServer.route` handles `astra.log.toggle` after the hello fence like every other client message (`no_hello` before it, `counts["routed"]` after) and hands it to the session, which turns logging on or off and publishes one `astra.log.state` **to every connection**. Turning it **off** writes a final `log.stopped` record (`{"reason": "toggled off", "records", "dropped", "bytes"}`), drains and closes the file; turning it **on** opens a **new** file with a new timestamp and writes `log.started` (session id, pid, git commit, profile, regime, versions.lock digest). Toggling is idempotent: a second "on" while on changes nothing and opens no second file.
18. `HudServer.hello_reply` yields the log state as its **third** message — after the assist state and the turn state, before the journal replay — so a (re)connecting page starts from the server's truth. The replay bound and everything else about T-0037's reply are unchanged, and the ordering is pinned by a test.
19. `hud/src/log/index.js` + `hud/src/log/gate.js` mount through the existing `panels.js` seam and render a single checkbox "Log this session" plus the server's path string verbatim and the record/drop counters. Following the T-0025 precedent exactly: the checkbox's checked state comes from the server's `astra.log.state` echo and **never** from the click; a clicked-but-unechoed box says "waiting for the server"; **before any `astra.log.state` has arrived the panel renders the state as unknown, never as on** (a page that claims a session is being logged when it is not is the failure this criterion exists for). The panel declares `LOG_CLIENT_TYPES = ["astra.log.toggle"]` and emits nothing else. It inserts its own element and its own `<style>`; `hud/index.html`, `hud/styles.css`, `hud/src/main.js` and `hud/src/state.js` are not touched.
20. `hud/src/protocol.js` gains `astra.log.state` in `SERVER_TO_CLIENT` with its field table (so the page decodes it strictly, as it does every other server message). This **changes a spec mirror**, and the parity pins in `tests/unit/test_hud_constants_parity.py` that assert `SERVER_TO_CLIENT` has zero diff (written as scope fences by T-0008/T-0039) are updated to the new set with a comment naming T-0043. `CLIENT_TYPES` stays T-0008's two entries — the toggle is the panel's egress, as `astra.text` and `astra.assist.toggle` are.

**Group C — the tool**

21. `scripts/demo/session_log_summary.py <log.jsonl>` prints one block per turn: turn id, `input` (voice/text/ui), the question text, the raw canvases in order as segment tags with lengths (e.g. `thought(412) thought(388) answer(96) ui(1204)`), **whether a `ui` segment appeared**, the gate's verdict for each (`surface emitted` / `rejected: <first problems>` / `not gated: <reason>`), what was spoken, the outcome, and the number of records dropped inside that turn's span. `--turn <id>` dumps that turn's raw canvases in full. It lives in `scripts/demo/` and is therefore ungated (T-0016 ruling D5); it opens no socket and spends no GPU.
22. The tool is total on damaged input: a truncated final line (the session was killed mid-write) is reported as such and every complete line is still summarised; an unknown `kind` is counted, not fatal; a missing or empty file exits non-zero with a named reason.

Confirm the fake in the report rather than assuming it.
- **The pump never blocks.** `record()` is called from inside `Session._handle`, from `HudConnection.receive` and from `HudServer.publish` — all on the event loop. Snapshot-and-offer only; `json.dumps`, the file write and the flush belong to the writer task. The HUD outbox (`Outbox.offer`) is the shape to copy: never blocks, never raises, drops and counts. The one difference: a session-log overflow must never close a socket — this is telemetry, and the session survives losing it.
- **Redaction before the queue, not in the writer.** The pump owns the only reference to the frame bytes at the moment of the tap; deferring redaction means carrying a base64 megabyte through the queue, which is precisely the bounded-memory criterion's failure mode. Redact by replacing with `len()` + digest at offer time, so the queue holds only small objects.
- **Known landmines.** `.claude/rules/conductor.md`: the machine is pure — no logging import, no side effect inside `turn_machine.py`; the tap goes on the session's side of `machine.step`. `.claude/rules/tests`: do not assert tautologies — "the log is valid JSON" is not evidence, "the `ui` verdict distinguishes the three states" is. The reviewer will mutation-test criteria 10, 11 and 5. `.claude/rules/gpu-services.md` and `/launch`: the Chrome integration row spends no GPU and writes only under `tmp_path`, so it is not a launch item; the live-session evidence run in §6 is.
- **`--no-log` is the start state, not a lock.** The page may still turn logging on afterwards; the user at the page is the same person who typed the flag. A locked variant (`--no-log --lock`) is not in v1 and is recorded as ambiguity 6.
- **Where the taps go, concretely** (so the implementer does not have to rediscover them): `Session._handle` (machine.step), `_run_generate`'s `async for commit` loop and its retry/error arms (llm.request/commit/done/error), `_run_prefill` (llm.request phase=prefill), `_gate_surface` and the `segment == "ui"` branch of `_note_event` (ui.gate, both the gated and the not-gated case), `enqueue_speech` (tts.utterance), `_publish_played` (tts.played), `_on_decision` (stt.decision), `_write_record` (turn.record), `_safely` (error), `HudConnection.receive` (wire.in), `HudServer.publish` (wire.out). ## 8. Ambiguities for the orchestrator or the human

1. **Rotation and retention.** v1 writes one file per session with no rotation and no cap; a long session on a busy day could reach hundreds of MiB. Proposal: record the byte count in `log.stopped` and revisit with a real number from the first week. `astra forget --since` does **not** delete session logs today — is that acceptable (they hold no pixels, but they do hold every question and answer verbatim)?
2. **`t_ms` vs `session_ms`.** Two clocks are carried per record (monotonic-since-open, and the session clock when known) because spans in `turns.jsonl` are on the session audio clock and a test's `ScriptedClock` can jump. If the human prefers one, `session_ms` is the joinable one and `t_ms` is the honest one; the task keeps both.
3. **The 5 MiB/turn ceiling and the 4096-record queue depth** are chosen, not measured. The first live run's numbers (§6) decide whether they stay.
4. **Sampling params.** The log records the session's `Prompt` and `LlmOptions`, not the exact JSON body `VllmClient.request_body` sends. A tap inside `llm_client.py` would record the literal body but adds a second file and a second owner; proposed as a follow-up task if the first analysis session wants it.
5. **Audio.** No PCM is logged. If a listening-path mystery needs it later, that is its own task with its own privacy paragraph — not a widening of this one.
6. **`--no-log` is not a lock** (the page can turn logging on). If the human wants a hard off, say so and it becomes a one-line criterion in group B.
7. **Where the file lives.** `logs/sessions/` under the repo root (via `supervisor.log_dir()`), not `~/.local/share/local_astra/`. Rationale: it is a developer artefact, it is already gitignored, and it sits beside `logs/vllm.log` where one is already looking. Say if it should follow the user-data convention instead.
8. **Does `astra up` start anything that should log?** No — only `astra session` has a session. The services keep their own `logs/<service>.log`. If the human wants the summary tool to interleave them, that is a follow-up.

### Group B rulings

- **B1 (where the file goes when the session started with logging off — ruled).** `--no-log` means "start with it off", **not** "there is no
  directory": the notes already say it is not a lock. So the session carries the **resolved log directory** (the `--log-dir` value or the
  default) regardless of whether logging starts on, and the toggle opens there. Do not make the toggle inherit a directory from whatever
  happens to be lying around, and do not make `--no-log` a state the page cannot leave — a checkbox that cannot be ticked is worse than no
  checkbox. This needs its own row, which the test-author correctly declined to invent a seam for.
- **B2 (an idempotent toggle still publishes — the test-author's reading is right, ratified).** One `astra.log.state` per **routed
  message**, not per change. The alternative leaves criterion 19's checkbox saying "waiting for the server" for ever after a redundant
  click, which is the same class of defect as the checkbox that reports its own click: the page would be showing a state the server never
  contradicted. Cheap to publish, and it makes the page's rule simple — every toggle gets an answer.
- **B3 ("a new timestamp" cannot be asserted literally, ratified).** The name has one-second resolution and the writer disambiguates with a
