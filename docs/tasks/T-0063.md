# T-0063 — The constraint compiler on the host: vendored diffgemma-fa compiler, HF-tokenizer vocabulary, BFCL/Sudoku grammars at parity with the JAX baseline, and the `cd` test environment

**Status:** done (merged at 7244fef; status corrected 2026-10-23 from 'in progress', T-0147 audit: no implementation in flight) · earlier: in progress · **Blast radius:** medium · **Branch:** `T-0063-cd-compile` (from `T-0062-perstep-cd`) · **Depends
on:** — (the human regenerates `uv.lock`; the human supplies BFCL data, see Implementation notes)

## Goal
On the host CPU, `local_astra` can compile the exact grammars the JAX baseline used into token automata over the
**HF tokenizer of the pinned model revision**. For BFCL-Live simple that means the JSON grammar with the
whitespace-tolerant ("pretty") separators, the optional fence, case-insensitive enums, expanded wildcards, the channel
header, stop-token augmentation and the unscored `ACC --Σ--> ACC` tail. For Sudoku 4×4 it means the grammar that pins
the givens. Every automaton reports |S| and its bucket, and passes a configurable size gate. The torch and outlines
dependencies live in a non-default `cd` dependency group run by `make cd-test`, so main's environment, fast suite and
budget do not change.

## Acceptance criteria
1. `pyproject.toml` gains `[dependency-groups] cd` containing:
   - `outlines-core`, pinned to the version diffgemma-fa ran at 27c7d0d
   - `tokenizers`
   - `torch`, CPU build from an explicit pytorch-cpu uv index, pinned to the torch version inside
     `vllm/vllm-openai:v0.29.0`

   `uv sync --group cd` installs them. `make cd-test` runs
   `ASTRA_CD_TESTS=1 uv run --all-extras --group cd pytest tests/cd -q -m "not gpu"` (`--all-extras` because pytest is in the `dev` extra: a bare `uv run --group cd` syncs an environment without it). `tests/cd/conftest.py` skips collection of
   `tests/cd` unless `ASTRA_CD_TESTS=1`; with it set and the group absent, the sentinel row **fails** (it does not
   pass empty). (docs/07 §0, "port implications")
2. *Negative:* `uv sync --all-extras` installs none of torch, outlines-core or tokenizers. Nothing collected by
   `tests/unit tests/contract` imports them. Importing `local_astra`, `local_astra.cli` and every
   `local_astra.conductor.*` module leaves `local_astra.decoding`, `torch` and `outlines_core` absent from
   `sys.modules`.
3. **Vendoring is auditable.**
   - `local_astra/decoding/_vendor/dgfa_compile/` is diffgemma-fa `diffgemma_fa/compile/` at commit `27c7d0d`.
   - `local_astra/decoding/_vendor/PROVENANCE.md` lists the commit, the sha256 of every vendored file, and every
     deviation (import-path rewrites, and replacing the `gemma` SentencePiece tokenizer with the HF one) with a reason.
   - A test recomputes the sha256 of every file PROVENANCE marks "unmodified" and fails on drift.
4. **The vocabulary comes from `tokenizer.json`** of `nvidia/diffusiongemma-26B-A4B-it-NVFP4` rev `2ea8372…`, and the
   file's sha256 is recorded as `tokenizer_hash`.
   - The vocabulary has 262 144 ids.
   - The ids agree with diffgemma-fa's Phase 0 facts: `<|channel>`=100, `<channel|>`=101, `"\n"`=107,
     `thought`=45518, EOS=1, `<turn|>`=106, `<|tool_response>`=50.
   - Reserved ids {0, 1, 50, 100, 101, 105, 106} are absent from every grammar alphabet.
5. **Grammar parity with the JAX baseline, by replay** of preserved diffgemma-fa emissions (text → HF tokenisation →
   automaton):
   - all 130 rows of `exp_e5_grammar130_map` are accepted
   - on `eval_bfcl_live_simple_unconstrained_sample`, `task_sudoku_unconstrained` and `task_sudoku_j0map`, acceptance
     equals the recorded `accepted` flag on every row

   Any mismatch fails the test and lists the row. Mismatches are never waived by count.
6. The fraction of unconstrained Sudoku emissions accepted by the compiled Sudoku automaton is produced by a named
   function. It must equal an independent `re.fullmatch` of `sudoku_regex` on the answer region, over all 250 records of the
   preserved unconstrained artifact; the task report records the number. (The "45/58" figure in diffgemma-fa comes
   from a 58-row subset and is not re-derivable from this artifact; do not target it.)
7. **Size report and gate.** `compile_report(records)` returns per-record `n_states`, `bucket`, `is_dfa`, `n_classes`,
   `k_max`, `max_neg_size`, payload bytes (after T-0064) and build seconds, for the BFCL test cut (130), the BFCL dev
   cut (130–229) and both Sudoku cuts.
   - `gate(automaton, max_states)` raises a named `TooLarge` above the limit. The live-path default is 128 (docs/07
     §0); the evaluation passes 512.
   - *Negative:* no API drops a record silently. A record above 512 yields a typed result the harness must count.
8. **Structure.**
   - Every compiled automaton passes the vendored `_assert_structural_invariants`.
   - The stop set equals `eos_token_id` of the pinned `generation_config.json` ([1, 106, 50]).
   - After acceptance the tail accepts any id sequence, including PAD and every stop id (SPEC §3.5 traps 3–4).
9. **Determinism.** Compiling the same record twice yields byte-identical arrays. The cache key includes the
   tokenizer hash, compiler version and all grammar options.

## Implementation notes
- Prefer vendoring over depending: diffgemma-fa has no `pyproject.toml`, and its `vocab.py` imports the JAX `gemma`
  package. Human decision 4 allows vendoring. Keep vendored code unmodified wherever possible; deviations go in
  PROVENANCE.
- Grammar options must equal the baseline artifact's: `whitespace="pretty"`, `fence=True`, `ci_enums=True`,
  `expand_wildcard=True`, channel header per SPEC §3.6 (`100 · Σ_name{1,8} · 107 · 101`). Read Sudoku's exact
  `sudoku_regex(...)` arguments from diffgemma-fa `eval/run_tasks.py`. **Open question:** the row separator in that
  call was not checked; the preserved unconstrained text contains `\n` between rows.
- The header models thinking **off** (an empty thought). That is correct for the evaluation (T-0070) and wrong for the
  conductor, where thinking is always on. Name this in `grammars.py`'s docstring.
- **Open question (human):** the BFCL v4 data is not on this box. `bfcl_data.py` points at a dead VM path and records
  no gorilla commit. The human fetches `BFCL_v4_live_simple.json` and `possible_answer/BFCL_v4_live_simple.json` into
  `tests/fixtures/cd/bfcl/` and names the commit in the MANIFEST. Until then criteria 5 and 7 cannot be proved for
  BFCL. Do not substitute another split.
- **Open question:** the torch version in the pinned image was not checked. Read it with a read-only
  `docker run --rm <image> python3 -c 'import torch;print(torch.__version__)'` (no `--gpus`) and record it in
  PROVENANCE.
- The preserved compile report (`bfcl_compile_report.json`, stock grammar) shows a median of 97 states, 17 % of
  schemas in bucket 256 and 7 % in bucket 512. Expect the whitespace-tolerant grammar with the header to be larger.
  Report it; do not gate the evaluation at 128.

## Rulings (orchestrator, 2026-09-29, after the test-author's report)
- A1. `BFCL_BASELINE_OPTIONS` includes `nonempty_strings` (the baseline artifact has it); six options, not five.
- A2. `ci_enums` and the pretty whitespace (`PRETTY_WS`) live in diffgemma-fa `eval/run.py`, not the vendored
  `compile/`; `grammars.py` ports them, with provenance.
- A3. The reserved-id exclusion applies inside the grammar region after `<channel|>`; in the channel header only PAD
  and the stop ids are forbidden (the vendored header alphabet admits 105). Revisit only if a replay disagrees.
- A4. Criterion 6's figure is 239/250 over the preserved unconstrained Sudoku artifact (the test-author's
  independent oracle), pinned in the test.
- A5. The BFCL parity check compares ids and function names; the preserved rows carry no question text.
- A6. `make cd-test` is expected to take 30–60 min serially (BFCL compiles 2–5 s, a `type: any` schema ~150 s).
  The recipe stays as criterion 1 states; verifiers budget for it.


## Implementation report (implementer, 2026-09-29)
Regime: CPU only (32-core host, other agents' jobs running concurrently); outlines-core 0.2.14; tokenizers
0.23.2; torch 2.13.0+cpu; `tokenizer.json` sha256 `cc8d3a0c…bfe0f`; model rev `2ea8372…`; diffgemma-fa
`27c7d0d`; tree = the implementer commit on `T-0063-cd-compile-impl`. Grammar options = `BFCL_BASELINE_OPTIONS`;
header 8 name tokens; stop set [1, 106, 50].
- **Criterion 6:** `report.sudoku_answer_acceptance` accepts **239 / 250** preserved unconstrained Sudoku
  emissions (`task_sudoku_unconstrained`, seed 0), equal row by row to `re.fullmatch(sudoku_regex, answer_region)`.
- **Criterion 7, sizes** (`compile_report(..., max_states=512)`, |S| includes the 11 header states and ACC):
  - BFCL test cut (n = 130): median |S| 161, min 56, max 1135. Buckets {64: 1, 128: 27, 256: 59, 512: 29,
    1024: 12, 2048: 2}. 28 / 130 are ≤ 128. **14 / 130 exceed 512** and come back as `TooLargeRecord`:
    `live_simple_44-18-0`, `45-18-1`, `48-21-0`, `49-21-1`, `51-23-0`, `52-23-1`, `70-34-0`, `71-35-0`,
    `106-63-0`, `110-67-0`, `111-67-1`, `112-68-0`, `117-73-0` (1035), `122-78-0` (1135). Median build 10.5 s
    with 10 parallel workers; the two `type: any` schemas take 185–215 s.
  - BFCL dev cut (n = 100, records 130–229): median |S| 132, min 70, max 704. Buckets {128: 35, 256: 35, 512: 29,
    1024: 1}. 1 / 100 exceeds 512 (`live_simple_165-98-0`, 704).
  - Sudoku (test 250, dev 100): every puzzle is 32 states, bucket 64, DFA.
