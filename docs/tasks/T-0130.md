# T-0130 — `astra down` cannot stop the STT container

**Status:** superseded by T-0158 (2026-10-26) · **Blast radius:** medium (supervisor; every desk session ends with `astra down`) · **Origin:** reproduced 2026-10-22.

## Problem

The human ran the shutdown at the end of the 2026-10-20 desk session. The vLLM and TTS services stopped, but the STT container `astra-stt` (image `astra-moshi:0.6.4`, `--gpus all`, port 8080) was still up 38 hours later. Its launcher pid file stayed under `<git-common-dir>/local_astra/run/stt.pid`.

Re-running `uv run astra down` on 2026-10-22 printed:

    astra down: stt: signalled pid 1580782; still running after 12 s — not removed (the argv changed: it was started as …/services/stt.sh and exec'd into docker run --rm --name astra-stt … worker --config /config/stt-1b-en_fr.toml --addr 127.0.0.1 --port 8080; the start time says it is the same process)

It exited with code 1, and the container stayed up.

`supervisor.stop` sends SIGTERM to the `docker run` front end and, by ruling A16, never sends SIGKILL, so that the container is not orphaned. The front end forwards the signal, but the moshi worker inside the container does not exit on SIGTERM within `STOP_WAIT_S`.

Consequences:
- The GPU stays occupied after a shutdown the human believes worked.
- Port 8080 stays bound, so locked GPU scripts refuse to start. The T-0111g C-G1 smoke was blocked this way.
- STT is pinned to `--gpus all`, so the container holds VRAM.

## Direction (for the planner)

Stop the container by its name rather than by signalling the front end. The service's own handle already names the container. Run `docker stop --time <n> astra-stt`, which sends SIGTERM and then SIGKILL inside the container after the grace period, and wait for the front end to exit.

Keep the A11/A16 safety: never kill a process whose start time does not match, and never orphan a container. After stopping, verify that the container is gone and the port is free, and report each with a PASS or FAIL line.

Also check why moshi ignores SIGTERM. It may be running as PID 1 with no handler; if so, consider `--init` in `services/stt.sh`. That is a services change, so it gets its own run.

Rows:
- A fake `docker` on PATH records `stop astra-stt` and simulates a front end that ignores SIGTERM. `down` then stops the container and exits 0.
- A container that is already gone is reported, not an error.
- The start-time mismatch still kills nothing.
