## Goal

`local_astra/search/ddgs_backend.py` provides `DdgsSearch`, a `SearchBackend`:
- `async search(query) -> SearchResults` gets at most 5 bounded text results from DuckDuckGo through the keyless `ddgs` package.
- The blocking call runs on a daemon thread and never blocks the event loop.
- Failures surface as `TimeoutError` or `SearchFailed(kind)`. `SearchFailed` is now in `contracts/protocols.py`, so the session can read the kind without importing the backend.
- `aclose()` returns at once. A search thread still running never holds up interpreter exit.

Egress is scoped exactly:
- This is the only file in `local_astra/` that imports a web-search client.
- It contains no URL literal.
- The engine is pinned to `duckduckgo`, and the hosts it may reach are a module-level allowlist.
- It refuses to run behind a proxy taken from the environment.

CI never touches the network: unit tests inject a fake client, and the live row is opt-in.

1. **The protocol (T-0113 criterion 15, real side).**

2. **Mapping and bounds.**
   - The client is constructed with:
     - `timeout=CLIENT_TIMEOUT_S` (5);
     - `proxy=None`.
   - `text()` is called with:
     - `backend=ENGINE` (`"duckduckgo"`);
     - `max_results=MAX_RESULTS` (5, equal to `toolcall.loop.MAX_RESULTS`);
     - `region="wt-wt"`;
     - `safesearch="moderate"`.
     - If the pinned ddgs does not accept one of these values, the implementer records the pinned equivalent under *Rulings*, and the test-author reads it from there.
   - Each returned row with `title`, `href` and `body` becomes `SearchResult(title, url=href, snippet=body)`, in rank order. `SearchResults.query` is the query as asked.
   - Rows are dropped if they:
     - are not a mapping;
     - lack `title` or `href`;
     - have an `href` whose scheme is not `http` or `https` (so `javascript:` and `data:` go).
   - Runs of whitespace collapse.
   - Fields are cut to `MAX_TITLE` 200, `MAX_URL` 500 and `MAX_SNIPPET_RAW` 600 chars. These cuts bound memory and the log; the 300-char snippet cut stays the renderer's.
   - At most `MAX_RESULTS` results are kept, whatever the client returns.
   - An empty or whitespace-only query returns `SearchResults(query, ())` without calling the client.
   - A query longer than `MAX_QUERY` (500, equal to the session's `MAX_ARG_TEXT`) is cut before it is sent.

## Implementation notes

- **Threading.**
  - One daemon thread per search, never joined.
  - No `asyncio.to_thread`, no `loop.run_in_executor(None, …)` and no `ThreadPoolExecutor`. On 3.11, `asyncio.run` waits on the default executor at shutdown with no bound, and `concurrent.futures` joins its workers at exit.
  - Hand the result back with `loop.call_soon_threadsafe` into an `asyncio.Future`, and ignore a result for a future already cancelled or done.
  - Use a new client per call; the thread-safety of a shared client is unverified.
- **Landmine (unverified):** ddgs 9.x's `DDGS.text` may itself run engines on an internal `ThreadPoolExecutor`, which is joined at interpreter exit. The fake cannot see this; criterion 9's fourth phase can. If it bites, exit is bounded by the client timeout (5 s), which is acceptable. Record what you find.
- **No timer of your own.**
  - The client `timeout` is the wall bound.
  - The session's `TOOL_EXEC_TIMEOUT_MS` (10 s, session clock) is the outer bound.
  - No `asyncio.wait_for`.
- **Error table.** Check the class names against the pinned source and record them under *Rulings*.

  | Raised by the client | Surfaces as |
  |---|---|
  | ddgs `TimeoutException`, builtin `TimeoutError` | `TimeoutError` |
  | ddgs `RatelimitException` | `SearchFailed("rate_limited")` |
  | `OSError`, and connection errors from the HTTP layer as they surface | `SearchFailed("network")` |
  | ddgs `DDGSException`, including its "no results" form, and anything else | `SearchFailed("error")` |
  | `CancelledError` | propagates |

  - Do not string-match exception messages: that is a blacklist that fails open.
  - A DuckDuckGo captcha or anomaly page probably surfaces as a rate limit or as "no results" (unverified). Both reach the model as a failure, never as invented results.
- **Imports.** Import `ddgs` lazily, inside the default `client_factory`. Importing the module, or constructing it with a fake, never imports `ddgs`.
- **Hosts.**
  - `ALLOWED_HOSTS` defaults to `{"html.duckduckgo.com", "duckduckgo.com", "lite.duckduckgo.com"}`.
  - Read the pinned duckduckgo engine to see which hosts it contacts, and whether an explicit `backend` disables fallback to other engines.
  - Record the result under *Rulings*. The live row is the check.
- **No logging in the backend.** The session logs (T-0125).
- **Socket audit.** ddgs 9.x does its HTTP through `primp` (Rust), so Python-level socket patches see nothing. That is why the audit uses `strace` (docs/03 §Privacy).
- **Mypy strict.** Imports are limited to the stdlib, `local_astra.contracts` and the lazy `ddgs`.

    - **The live row.** `make search-live` passes if each query gets ≥ 1 result from **any** engine in `ENGINES`, and every connect is allowlisted. If all engines refuse, the row fails and names each engine's refusal.
