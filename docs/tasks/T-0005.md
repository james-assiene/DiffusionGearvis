# T-0005 — LLM client, prompt builder, anticipatory prefill

**Status:** merged 2026-09-13 (e5b94de; revised per review; B13 gap tests 17329e7) · **Blast radius:** high · **Depends on:** T-0002, X3 (container sanity)

## Goal
`VllmClient` streams commits with thought/answer/ui separation and abort; `PromptBuilder`
implements the D9 layout with the token budget; `prefill()` warms the prefix that the final
request re-uses (docs/01 D9/D11, docs/02 §2.4, docs/10 §9).

## Acceptance criteria
1. `request_body()` is pure and contains only whitelisted sampling fields, `vllm_xargs` (with `astra_request_id`), `chat_template_kwargs`, `stream: true`; never `response_format`, `temperature`, `seed`, `logit_bias`. The HTTP transport is injected (`httpx.MockTransport` in tests).
2. `split_segments`: reasoning deltas → `thought`; content deltas → `answer`; an `<a2ui>…</a2ui>` fence inside content → `ui`, state carried across deltas; a canvas ending inside reasoning sets `thought_open=True` on its commit.
3. `abort()` closes the SSE stream and is idempotent; contract test checks `/metrics num_requests_running` drops within 200 ms on the real service (`gpu`).
4. `prefix.shares_prefix_with(full)` holds: `full()` extends the *last user message* of the prefix (the D9 boundary is inside the user turn; no consecutive user messages), and the prefix tokenises identically after templating (contract test on the real tokenizer, `gpu`; the last partial block may miss).
5. Layout order: `[system][history][user: frame]` ‖ `[TutorState][memory hits][frame_text assists (only flags on in `Prompt.assists`)][transcript]`; thinking goes through `chat_template_kwargs={THINKING_TEMPLATE_KWARG: bool}` (kwarg name verified in X3), never as a literal token; history frames (`HistoryTurn.frame_phash`) older than `image_age_turns` become caption lines; ≤ `max_images` with the current frame always kept; history capped at `max_history_turns`; system prompt contains `CLOSE_THE_THOUGHT` and `SPOKEN_STYLE`.
6. A frame whose phash equals the newest history frame still in image form is not attached a second time (the cached image carries the pixels); a changed frame is.

## Amendments (2026-09-13, orchestrator rulings after the test-author flagged eight gaps)
Where these conflict with the criteria above, these win. Made as decisions rather than left for
the implementer to guess; the reviewer should challenge any of them on the merits.

**B1 — the reasoning delta key is UNMEASURED; accept both spellings.** An old test feeds
`delta.reasoning`; our live probe reads `reasoning_content` and got `''` with thinking off, which
proves nothing. Nobody has captured a real `--reasoning-parser gemma4` streaming delta. The client
MUST treat either key as the thought segment. Do not pick one. When a real SSE chunk is captured,
record the key in `.claude/rules/gpu-services.md` and narrow
`test_reasoning_delta_is_recognised_under_both_vllm_spellings` in the same change.

**B2 — token-budget overflow order.** When the assembled prompt exceeds `Budget.max_prompt_tokens`,
drop in this order, stopping as soon as it fits: (1) oldest history turns, oldest first; (2) images
older than `image_age_turns`, oldest first, each falling back to its caption line; (3) memory hits,
lowest-ranked first. **Never** drop the system message, the current user turn, or the current
frame. Rationale: the assistant should forget the distant past before it forgets what it is
looking at right now — the failure this ordering avoids is going blind mid-turn to save tokens.

**B3 — `max_images` cap.** A frame dropped to satisfy the cap **falls back to its caption line**,
exactly as an aged-out frame does. A frame never silently vanishes: it degrades from pixels to
text. This resolves the case the original test left deliberately silent.

**B4 — memory thumbnails are DEFERRED to T-0009.** `Episode` carries `thumbnail_path`, and
attaching bytes needs file I/O that `tests/unit` forbids. In T-0005 the prompt builder consumes
caption lines only, and criterion 5 governs ordering alone. T-0009 owns the store and will supply
loaded thumbnails through an injected loader; that injection point is T-0009's to design.

**B5 — `PrefillHandle.prefix_tokens`** comes from `usage.prompt_tokens` on the prefill response when
present, and is `None` otherwise. It is never computed with a local tokenizer in this task: a second
tokenizer is a second source of truth and would drift from the engine's count silently.

**B6 — `vllm_xargs` gets a parameter now.** `request_body` and `generate` take
`xargs: Mapping[str, str] | None = None`, merged into the `vllm_xargs` object alongside
`astra_request_id`. T-0011 (tap) and the constrained-decoding work both need it, and retrofitting a
parameter through a signature two tasks already depend on is worse than adding it unused today.

**B7 — a UI fence split across deltas is out of scope.** On the diffusion path a chunk is a whole
committed canvas (docs/02 §2.4), so a fence cannot straddle deltas in practice. The implementer must
still never leak a partial fence marker into `answer` — when in doubt the tail stays in the current
segment. If Phase 0 traffic ever shows a straddling fence, that is a new task with a recorded
counterexample, not a silent widening of `split_segments`' signature.

**B8 — "canvas" means one SSE chunk**, per docs/02 §2.4 "output arrives per committed canvas". This
is the only mapping derivable from the documented wire and is what `canvas_idx` / `thought_open` are
tested against. If the engine ever emits several chunks per canvas, this assumption breaks loudly in
the commit-index test rather than silently.

## Amendments, round 2 (2026-09-13, rulings on the reviewer's REVISE verdict)

**B9 — H1, the modules do not compose. Add the injection point now; keep the image path.**
`prompt_builder` emits `ImagePart(url="astra-frame:<phash>")` for a history frame and
`llm_client._part_body` raises on any non-`data:` URL, so an ordinary second turn raises. Raising
is the right instinct — a silent unresolved reference would make the model go blind — but a
producer and a rejecter in the same task with nothing in between is not a seam.

Ruling: `prefix()` takes `resolve: Callable[[str], bytes | None] | None = None`. With no resolver
(the T-0005 default) a history frame **degrades to its caption line**, exactly as an aged-out frame
does under B3, so the two modules compose and a two-turn prompt is sendable today. T-0007/T-0009
pass a real resolver and the pixels come back. A bare URL scheme no task owns is not an injection
point; a parameter is.

If criterion 5's existing test demands an `ImagePart` without a resolver, that test needs the
resolver passed — a test change, recorded here, for the test-author rather than worked around.
**A composition test is owed**: builder output fed to the client, which no test does today, which
is why this reached review.

**B10 — H3, delete the token-budget estimator.** `estimate_tokens()` guesses 4 chars/token and
1120 tokens/image, and nothing tests it — three mutations (loops disabled, chars-per-token=1,
image tokens=0) all leave the suite green. Worse, it is **unreachable**: `max_prompt_tokens` is
24 000 while `--max-model-len` is now 16 384, so the engine rejects any prompt the loop would trim.
The mechanism provides no enforcement while looking like it does, and B5 forbids a local tokenizer
as "a second source of truth" while this is a cruder third one.

Delete `estimate_tokens` and both `while` loops. Keep the structural caps (`max_history_turns`,
`max_images`, `image_age_turns`) — those are correct, mutation-covered, and are the real control.
Re-scope budget enforcement as its own task using the engine's own count, and give that task the
over-long-prompt recovery path too: nothing in `conductor/` handles a 400 today, so "loud"
currently means the turn dies. **Also fix the stale test assertion** `max_prompt_tokens < 32768`,
which cites a `--max-model-len` T-0014 superseded.

**B11 — H4 escalation: the `vllm_xargs` signature needs files T-0005 does not own.**
`request_body`/`generate` take `xargs`, but `contracts/protocols.py` and `tests/fakes/llm.py` still
declare the old signature, so T-0011 and the constrained-decoding work will fail mypy against the
protocol and `TypeError` against the fake — the exact retrofit B6 existed to avoid.

Ruling: **its own task (T-0017)**, not an ownership extension. CLAUDE.md requires a contract change
and its fake in the same PR, and `tests/fakes/` is the test-author's. Scope: add `xargs` to the
`LlmBackend` protocol and `FakeLlm`, and add the missing
`isinstance(VllmClient(), LlmBackend)` conformance assertion — nothing asserts the real client
conforms today.

**B12 — M8 escalation: `prefix_tokens` stays `0`, and the blocker is the test, not the contract.**
B5 says `None` when usage is unreported; `contracts/llm.py` declares `prefix_tokens: int`
non-optional. The implementer used `0`, which is the only implementable value and therefore right.
But vLLM only emits `usage` when `stream_options` is set, and the closed-key-set test forbids it —
the test-author generalised evidence about *sampling params* into a constraint over the whole body,
and `stream_options` is an OpenAI protocol field, not a `SamplingParams` one.

Ruling: leave `0` and **document that `0` means "not reported"**, since nothing consumes
`prefix_tokens` yet (grep confirms no reader in `conductor/`). Resolving it properly needs a GPU
check — does the diffusion path accept `stream_options`? — which cannot run unattended. Queued for
the next GPU session; do not reword B5 to say "0", which would turn a `ge=0` count into an
unfalsifiable sentinel.

**B13 — the remaining review findings**, all implementation-level and in scope: H2 (aborting a
prefill raises into the caller; `generate` handles the same case cleanly), M5 (an `abort()` before
the generator is first pumped is silently dropped — the barge-in race), M7 (an unclosed `<a2ui>`
fence permanently diverts every later canvas away from TTS; decide and test whether `in_ui` resets
per canvas), M9 (a cheap guard for a think token arriving in the content channel), L10 (partial
fence markers leaking into `answer` contra B7).
