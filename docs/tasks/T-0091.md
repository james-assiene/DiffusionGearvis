# T-0091 — Precompiled native T4 payloads, a pure repair builder, and the dry-run tool executor

**Status:** done 2026-10-12 (verified at d55cfce; rulings F1–F10) · **Blast radius:** medium (one reviewer) · **Branch:** `T-0091-repair-executor` from `main` after
T-0088 merges · **Depends on:** T-0088 (`toolcall/special_tokens.py`, `contracts/protocols.py`), T-0087's reading (the stop id and
`/tokenize`). Umbrella `T-0080d.md`.

## Goal
Everything the session needs to judge a draft, build the H-T84-2 repair, and dry-run a call, as pure, fast-suite-importable code:
- the classifier;
- the seeded T4 repair `CdRequest`, byte-identical to what the eval sent for `native/T4/named/perstep_mar+seed`;
- the continuation prompt and its guard;
- the executor protocol and the dry-run executor.

## Acceptance criteria
1. **Payloads.**
   - **Build script.** `scripts/build_toolcall_payloads.py` (cd group) writes `local_astra/toolcall/payloads/native_T4.json`, holding:
     - the manifest: tools_v1 sha, tokenizer sha, model revision, compiler version, CL;
     - per v1 tool: `automaton`, `automaton_sha256`, `n_states`, `bucket`.
   - **Payload identity (cd group).** Each payload equals, byte for byte, the payload `twopass` sends for scope = tool, thought `T4`,
     `call_format="native"` (`compile_toolcall` → `encode_automaton`).
   - **Load check (fast suite).** `live.load_payloads()` checks the file's shas against `tools.load().version` and each `automaton_sha256`.
     It raises `PayloadStale` on any mismatch. Every bucket is ≤ 128 (live gate; T-0084a measured 29–80 states for T4).
2. **`classify(tool_text) -> Verdict`**, with `status ∈ {valid, repairable, refused}`, `name`, `arguments`, `reason` and
   `query_problem`.
   - **Inputs.** `tool_text` is the concatenated `tool` segment. A leading `<|tool_call>` is removed. A trailing stop text, if any, is
     removed as in `twopass.call_text_of`.
   - **valid** iff `native.parse_call` succeeds and `score.schema_valid` holds.
   - **repairable** iff not valid and `native.draft_name(text)` is a v1 name.
   - **refused** otherwise, with the parse reason or `"no tool name"`.
   - **Delta (T-0100, H-T99d, H-T99e, 2026-10-15).** `repairable` is narrowed: a not-valid `press_key` draft whose combo does not map into
     the list (`"combo not in enum"`) or cannot be read (`"no combo"`), and a not-valid `click_at`/`type_at` draft with a read-back
     coordinate outside 0–999 (`"coordinate out of range"`), are `refused`. Definitions in `docs/tasks/T-0100.md`.
   - **Delta (T-0102, H-T101c, 2026-10-15).** `repairable` is narrowed again: a not-valid draft with more model text after its call is
     `refused` (`"model text after call"`), after the T-0100 rules. Definitions in `docs/tasks/T-0102.md`.
   - **Parity (cd group).** On every native pass-1 row of the stored T-0084e/T-0084f artifacts (read-only, shas checked), `classify`
     agrees with the row's `draft_parse` and `draft_schema_valid`.
3. **`query_problem`.** It is computed for `google_search` only and never changes `status` (log-only; H7).
4. **`repair_prompt(pass1: Prompt, spoken_prefix: str) -> Prompt | Refusal`.**
   - **Prompt.** pass 1's messages plus `assistant(spoken_prefix + "<|tool_call>")`, with `continue_final_message=True` and the same tools
     and thinking.
   - **Refusal.** `continuation_guard: template|marker` when `router.template_content(c) != c.strip()`, or when the spoken part holds any
     `SPECIAL_TOKENS` literal. `template` wins when both hold.
   - **Parity (cd group).** The verdict equals `twopass.continuation_guard` on T-0085's rows (click-01, the K3 splice, `<|image|>`).
5. **`repair_request(name, draft_ids, stop_id, record_tag, payloads, calibration) -> CdRequest`.**
   - **Fields.** mode `perstep_mar`, self-conditioning `model`, the tool's payload and sha, `entropy_bound` 1.0 and
     `confidence_threshold` 0.005 from `docs/cd/calibration-bfcl.json` (sha `4084026c…` checked), `draft_noise` 0.0,
     `draft_start_step` 24.
   - **Seed.** `seed = (draft_ids + ([stop_id] if stop_id is not None else []))[:256]`.
   - **Parity (cd group).** For every stored native pass-1 row with a v1 draft name, `repair_request(...).to_xargs()` equals
     `twopass.seeded_xargs(arms.cd_xargs("perstep_mar", payload, tag, knobs), twopass.seed_ids("T4", ids, draft, fmt="native"))` key for
     key, except `record_tag`. Here `draft_ids = vocab.encode(draft.rstrip())` and `stop_id` is the first stop in the row's ids.
   - **Purity.** `draft_ids` are passed in; the session obtains them through `LlmBackend.tokenize`. `live.py` never tokenizes.
   - **Options.** The repair options are `LlmOptions(max_tokens=256)` (`PASS2_MAX_TOKENS["T4"]`).
6. **`repair_verdict(text) -> Verdict`.** It classifies the repair output (answer text, closed thoughts removed). A `repairable` result
   becomes `refused` (never a second repair).
7. **Executor.**
   - **Contracts.** `contracts/toolcall.py`:
     - `FrameGeometry(phash, source, width, height)`;
     - `ToolInvocation(call_id, turn_id, name, arguments, source, frame: FrameGeometry | None)`;
     - `ToolOutcome(call_id, status: dry_run | executed | refused | failed, action: str, reason: str | None, resolved: dict)`.
   - **Protocol.** `contracts/protocols.py::ToolExecutor` (`runtime_checkable`): `mode`, then `async execute(inv) -> ToolOutcome`.
   - **`DryRunToolExecutor`** (`conductor/tool_executor.py`):
     - `x_px = round(x * (width - 1) / 999)`, and the same for `y`, against `inv.frame`;
     - `click_at`/`type_at` without a frame give `refused("no frame")`;
     - `google_search` gives `action "would search for: <query>"` with no URL;
     - `scroll` and `press_key` are described;
     - status is always `dry_run` or `refused`.
8. *Negative.*
   - `live.py`, `tool_executor.py` and `contracts/toolcall.py` import nothing from `decoding`, torch, numpy, outlines or tokenizers (AST
     fence).
   - The dry-run executor opens no socket, spawns no process and writes no file.
   - Unchanged: router, native, score, tools, twopass, decoding, plugin.

## Rulings (orchestrator, 2026-10-12, on the test-author's questions)
- **F1. The rstrip belongs to T-0092.** T-0092 calls `tokenize(draft.rstrip())`. `repair_request` uses `draft_ids` verbatim.
- **F2. API names.** The names the test-author assumed are accepted as the surface, as listed in `_toolcall_live_support.py`'s docstring:
  - `load_payloads(path=None)` and `load_calibration(path=None)`;
  - `Refusal.reason` in `{template, marker}`;
  - `REPAIR_OPTIONS`;
  - `DryRunToolExecutor()`, with `mode == "dry_run"`;
  - `ToolOutcome.resolved` with `x_px`/`y_px`;
  - the build script's `--out PATH`.
- **F3. `PayloadStale` covers more.** A missing v1 tool and a bucket above 128 both raise `PayloadStale`, and only that type. T-0092 turns
  repair off on exactly that exception.
- **F4. Refused reasons.** A failed parse gives the parse reason. `"no tool name"` is used only when the call parses but names no v1 tool.
- **F5.** The test-author's unpinned items stay free, as listed in their report.
- **F6. Leading tag.** Criterion 6 accepts the tagged form, which is the T-0088 E4 shape, and the untagged form.
- **F7. Import fence.** The fence includes `local_astra.eval`, per the implementation note.
- **F8.** The perturbed-draft parity row is accepted as the strengthening of criterion 2.
- **F9. No bool or float stop ids.** `Commit.stop_id` is strict (T-0088 E14), so they cannot arrive.
- **Note for T-0094.** The fork-point guard in `test_toolcall_imports.py` compares against `merge-base HEAD main`, which is a moving ref.

## Amendment (planner, 2026-10-12, after T-0087 reading B and the T-0088 replan)
- **Depends on** T-0088a (`toolcall/special_tokens.py`: `SPECIAL_TOKENS`, `STOP_IDS`) and T-0088 (`contracts/protocols.py`,
  `Commit.stop_id`, the single `tool` commit). The branch is cut after both have merged.
- **The stop id.** This replaces "the stop id per T-0087's rule". T-0087's reading was "replan T-0091" only procedurally, because
  reading B chose no arm. The evidence settles it: the first stop id in the streamed ids equalled `stop_reason` on 24/24 recorded streams
  (50 on all 20 tool streams, 106 on the 4 chat streams).
  - **Source.** The stop id is the first id of pass 1's streamed `token_ids` that is in `STOP_IDS = {1, 106, 50}`. The client delivers
    it as `Commit.stop_id` on the request's `tool` commit. This is the eval's `_until_stop` rule, the same one criterion 5's parity row
    already uses. `stop_reason` is never read.
  - **Accepted values.** `repair_request` accepts a `stop_id` in {1, 106, 50}, or None for a length cut, in which case the seed has no
    stop. It raises `ValueError` for anything else.
  - **Rows.** Criterion 5's parity rows gain one with `stop_id=None` and one with 106.
- **Criterion 2, inputs.** `tool_text` is the text of the request's single `tool` commit.
  - It never holds stop text, because the client stops decoding at the first stop id. The trailing-stop removal stays, as a no-op.
  - It may start with `<cc>` or `<genui>` instead of `<|tool_call>`. Such a call is `refused` with the parse reason (H6), and a row pins
    this.
- **Criterion 4, `spoken_prefix`.** The session passes the concatenated pass-1 `answer` commits.
  - Every `SPECIAL_TOKENS` literal has already been stripped from those (T-0088 criterion 6, human Q2). So the spoken part of the
    continuation is exactly what was spoken and stored (H8).
  - The guard is unchanged and still runs.
- **Criterion 6, `repair_verdict(text)`.** `text` is the repair request's `tool` text.
  - Per T-0088 criterion 7, a continuation ending in `<|tool_call>` is split in the tool state, so the repair's output arrives as one `tool`
    commit, never as `answer`.
  - Closed thoughts are removed as before. Removing the leading tag is a no-op.
- **Criterion 8, negative.** Add `toolcall/detok.py` and `toolcall/special_tokens.py` to the list of unchanged files.
- **F10 (at 52d6b54). A bad calibration file is `PayloadStale` too.** `load_calibration` raises `PayloadStale`, not a plain `ValueError`,
  when the file is missing or unreadable, or its sha is not the pinned one. T-0092 then turns repair off and publishes that it did, rather
  than crashing the session. Add rows for a missing file and an edited copy.
