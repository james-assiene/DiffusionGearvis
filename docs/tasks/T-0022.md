# T-0022 — An unclosed code fence is summarised, not spelled out

**Status:** merged 2026-09-13 (review MERGE) · **Blast radius:** medium (spoken channel: what reaches Pocket TTS) · **Depends on:** T-0004 (must be **merged to main** first — it owns `local_astra/conductor/speech_gate.py` and `tests/unit/test_speech_gate.py`; if T-0004 is still open when this task is picked up, stop and wait)

## Goal
When a canvas ends inside an open code fence — `llm.done` arrives mid-fence, or `max_tokens`
truncates the answer — the speech gate flushes the held clause verbatim and Pocket TTS reads the
backticks and the code aloud. The reviewer's probe on the T-0004 branch:
`feed("Here it is: ```python\nfor x in y:\n    print(x)"); close()` yields
`text='Here it is: ```python for x in y: print(x)'`. `_FENCE_RE` only matches a *closed* fence
(```` ```.*?``` ````), and the `final` branch of `close()` appends the remainder with no fence
check, so the "do not speak code blocks; summarise them" rule of docs/02 §5.2 holds for closed
fences and silently fails for unclosed ones. T-0004 amendment A4 scoped this out and its rulings
section names it as a follow-up; this is that follow-up. After this task an unterminated fence is
spoken exactly like a terminated one — "a code block" — with `source` still byte-exact.

## Rulings (decided at plan time; the implementer does not re-open them)

**R1 — an unterminated fence extends to the end of the input and gets the same marker.**
`normalise_for_tts` treats ```` ``` ```` with no closing ```` ``` ```` as a fence running to end of
string, replaced by the same `"a code block."` marker as a closed fence. Not a different wording
("an unfinished code block"), not silent deletion: the user hears the same thing whether the model
finished the block or was cut off, the shown channel carries the actual code, and one marker keeps
the fixture table one table. The fix belongs in the pure function, not in a `close()` special case —
`normalise_for_tts` is public and documented as "fenced code → a code block"; a `close()`-only patch
would leave the function wrong for every other caller.

**R2 — `source` is conserved, unchanged.** The backticks and the code still travel inside
`Sentence.source` byte for byte (T-0004 criterion 5 / A1, T-0003 criterion 10's `ValueError`).
Only `text` changes.

**R3 — `close()` is the only place the unclosed case can arise, and A7 stays as it is.** A7's
balance rule (`_is_balanced`, fences hold) means a terminator inside an open fence is never a
sentence end, and a mid-turn emitted `source` therefore always has an even fence count. At
`final=True` the same balance check keeps terminators inside the open fence from splitting, so the
whole fence tail leaves as **one** sentence. Nothing about the hold rule changes: a fence still
open mid-turn still holds until the next commit closes it or `close()` arrives. R1 is the flush
path only, by construction, not by a new branch.

**R4 — the `ui` segment case is "nothing to do", and that is a test.** `ui` and `thought`
segments are rejected by `feed` (T-0004 criterion 1) and never reach the normaliser, so an
unclosed fence inside an A2UI payload is the `ui_gate`'s business (T-0010), not the speech gate's.
The one thing that must be pinned is that the fix was *not* implemented by loosening that guard.

## Acceptance criteria

1. `normalise_for_tts("Here it is: ```python\nfor x in y:\n    print(x)")` ==
   `"Here it is: a code block."` — no backtick, no code token, in the returned string. (R1,
   docs/02 §5.2, docs/03 §3 "replaces fenced code blocks with a spoken summary marker".)
2. The gate end-to-end: `g.feed(commit(<that text>))` emits nothing, and `g.close()` emits exactly
   one `Sentence` with `text == "Here it is: a code block."` and `source == <that text>` byte for
   byte, and `g.pending == ""` afterwards (R2, R3; T-0004 criteria 3 and 5, A3 "nothing is held
   forever"). This is the reviewer's probe, turned into a test.
3. A bare opening fence with nothing after it (`"See below: ```"`) yields
   `"See below: a code block."` — the degenerate case is handled by the same rule, not
   special-cased away. (R1.)
4. **Negative — closed fences are untouched.** The existing fixture row
   `("```python\nprint(1)\n```\nThat prints one.", "a code block. That prints one.")` still passes
   *exactly*, and two closed fences separated by prose
   (`"```py\nx = 1\n```\nThen ```sh\nls\n``` ends it."` → `"a code block. Then a code block. ends
   it."`) prove the new match is not greedy: prose between and after fences must survive. (T-0004
   criterion 4.)
5. **Negative — A7's hold rule is unchanged.** `feed("Here. ```py\nx = 1. y = 2")` emits exactly
   one sentence (`text == "Here."`), holds the rest, and nothing emitted before `close()` contains
   a backtick or any code byte. A terminator inside an open fence is still not a sentence end
   (T-0004 A7).
6. **Negative — conservation and the turn-machine contract are unchanged.** For every input of
   criteria 1–5, `"".join(s.source for s in emitted) + gate.pending == fed_text` at every step and
   `== fed_text` after `close()`; the existing segmenter-contract test through the real
   `TurnMachine` still passes (T-0003 criterion 10, T-0004 criterion 5 / A1).
7. **Negative — the segment guard is not the fix.** `feed(commit("```py\nx", segment="ui"))` and
   `segment="thought"` still raise `GateInputError`, and a commit with `thought_open=True`
   containing an unclosed fence still raises. (R4, T-0004 criterion 1.)
8. **Negative — the EOS/`<|think|>` latch still wins.** `"Ready.<|think|> ```py\nsecret"` produces
   no `text` containing `"secret"`, `"<|"` or a backtick; trimming happens before the fence rule,
   and every later sentence in the turn still has `text == ""` (T-0004 A6).
9. Property: over an alphabet that includes the backtick, no emitted `Sentence.text` from any
   `feed`/`close` sequence ever contains three consecutive backticks. (Catch-all for R1; if the
   test-author finds a counterexample this is a spec question for the reviewer, not a reason to
   weaken the assertion.)

## Implementation notes
- Landmines from `.claude/rules/conductor.md`: `TtsSpeak.source` is the committed substring the
  docs/02 §4 invariant checks — do not strip, collapse or "tidy" `source`; only `text` is
  normalised. The turn machine raises `ValueError` when
  `"".join(sources) + remainder != text` after *every* call.
- Order inside `normalise_for_tts` matters and is already right: trim (EOS / `<|think|>`) first,
  then fences, then special tokens, then paths, then identifiers, then whitespace collapse.
  Keeping the fence rule where it is means truncated post-EOS code cannot reappear via the marker.
- `_is_balanced` (A7) is not in scope. Do not relax the `chunk.count("```") % 2` clause to "fix"
  this — that would voice code sentence by sentence mid-turn, which is the opposite of the goal.
- `_split(..., final=True)` needs no change: the balance check already keeps terminators inside an
  open fence from splitting, so the fence tail arrives as one source. If the implementer finds it
  does not, that is a finding for the reviewer before any edit, not a second branch.
- Expect a diff of roughly one regex plus its comment and a docstring line. The protocol is **not**
  skipped even so: this changes what is spoken aloud, which is behavioural (CLAUDE.md allows
  skipping only for typos, comments, renames and mechanical refactors). It is sized as one pass:
  one test-author edit, one implementer edit, one review with the mutation above.
- `mypy --strict` on `local_astra/`; no new imports, no new module-level state.
