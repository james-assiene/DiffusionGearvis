## Goal

Today a broken turn-machine invariant runs into the Stop hook's `timeout 110`, and the report names no failing property.

Under mutant M4 (drop `or ev.thought_open` at `local_astra/conductor/turn_machine.py:654`, so an answer canvas inside an open thought is voiced), the run goes like this:
- The deterministic row `TestTable::test_thought_commit_and_unclosed_thought_never_speak` fails in 0.3 s.
- The stateful properties also fail, and Hypothesis then shrinks each counterexample for 26–47 s. The module takes 170 s serially.
- The hook kills pytest before xdist prints its `-rfE` summary. The turn is blocked by the "no FAILED line" tail branch, and the report names no failing test.

After this task:
- Inside an xdist worker (the hook and `make fast-parallel`), Hypothesis runs every phase except `shrink` and `explain`. A failing property is reported at once with its unshrunk counterexample: M4's module takes about 6 s, and the gate's normal summary names every failing row.
- The serial canonical run (`make fast`), which the verifier quotes, keeps Hypothesis's full default phases and still shrinks.
- No example count, step count, deadline, seed policy, database, test or hook changes.

**Why this is not a weakening** (architecture §4: the invariants are Hypothesis properties and are never weakened):
- For a given seed, the generate phase draws the same examples with or without shrink. Shrinking starts only after an example has already failed.
- So which seeds go red, and how many examples run on a green run, are unchanged. Only the size of the counterexample printed by the gate changes.
- Criteria 3 and 9 pin both claims.

## Implementation notes

- **Where the profile goes.** In `tests/conftest.py`: register a named profile, and load it only when the process is an xdist worker, before any test module is imported. In practice that is `pytest_configure`, checking that the config carries `workerinput`, or the `PYTEST_XDIST_WORKER` variable. The controller process runs no tests. Do not key on `-n`, on `numprocesses` or on whether xdist is installed (P3, P4).
- **Phases.** Exactly `explicit, reuse, generate, target`. `explain` needs `shrink`, so leave it out too. Set nothing else in the profile: `database` stays the default. The gate then saves its unshrunk failure, and the next serial run replays it and shrinks it. `database=None` belongs to the mutation-measurement discipline only (tests.md, T-0112), never to the gate.
- **Import timing is the landmine.** A Hypothesis `settings` object inherits from the profile active when it is built. Planner check on 6.168.0: one built before `load_profile` kept `(…, shrink, explain)`, and one built after did not. The stateful classes' settings are built at import.
- **`--hypothesis-profile` must still win** (criterion 4). The hypothesis pytest plugin loads it in its own `pytest_configure`. Get the order right, or skip the gate profile when the option is set.
- **Do not touch the hook's argv.** T-0143's rows pin it token for token against BASE, so an env var or a `--hypothesis-profile` flag in the hook line would turn them red. That is why the trigger is "running in a worker". The cost: `pytest -n N` run by hand also reports counterexamples unshrunk, and `--hypothesis-profile=default` restores shrinking.
- **`.claude/rules/tests.md`:** one line under the Hypothesis bullet. It says: in xdist workers (the gate) properties do not shrink and report raw counterexamples; the serial `make fast` run shrinks; never add a `phases=` or a smaller `max_examples` to a test to make the gate fast.
- **Option (d), deferred, with its hazard recorded for whoever picks it up.** Planner probe: `timeout -s INT` on `pytest -n 2` under M4 does print `FAILED` lines.
  - It also reports the property that was interrupted mid-shrink as FAILED, with a KeyboardInterrupt rather than its invariant.
  - The `!!! KeyboardInterrupt !!!` banner does not match `classify_failures.py`'s `_INTERRUPTED` pattern.
  - A partial run whose FAILED lines all fall in an in-progress task's module would take the tolerated branch and let the turn finish on an unfinished suite.
  - Any future (d) must block on exit code 124 unconditionally. Whether `uv run` forwards SIGINT to pytest was not verified.
- **Open questions (defaults in bold):**
  - **H-T146-1 (human): trigger by xdist worker or by an explicit env var in the hook?** **Worker.** It needs no hook change and no edits to T-0143's pins. The env-var alternative is more explicit, but it is a hook task (main session) that also rewrites `test_suite_budget.py`'s BASE literals.
  - **H-T146-2 (human): derandomize the gate?** **No.** It fixes the failure set but freezes exploration across the gate's many runs a day, and it buys no speed.
  - **H-T146-3 (human): also make the hook name failures on timeout (option d)?** **No, not now.** Revisit only if a timeout recurs on a run with no shrinking.
