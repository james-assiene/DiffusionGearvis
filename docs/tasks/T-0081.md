**Status:** done (2026-10-09; verified at e421892, tier 2 at dad1382) · **Blast radius:** high (decode loop and wire contract; two reviewers; engine `/launch` reviewed) ·
**Branch:** `T-0081-cd-seed` from `T-0062-perstep-cd` · **Depends on:** T-0079 (tier 2 knobs only); may run in parallel with T-0080a/b
(disjoint files).

## Goal
A constrained request may carry a draft: token ids from the same model's unconstrained pass. The plugin then starts the request's
**first** canvas from that draft, partially re-noised, instead of from uniform noise, optionally at a later denoise step (lower temperature,
shorter remaining cap). The aim is that the constrained pass converges in fewer steps while every CD guarantee holds:
- the committed output is in the language;
- the budget is respected;
- failures are loud;
- unconstrained requests are bit-identical to stock.

stability_threshold is 1 in the model's config, so a confident seeded canvas can converge after one denoise step. That is the lever this task measures.

## Where the hook is (read in the vendored v0.29.0 sampler and the plugin)
- Stock initialises a canvas in two places: `DiffusionSampler._finish_prefills`, at prefill completion, via `states.init_canvas`
  (`torch.randint` on the global RNG), then `draft_tokens[slot,:CL] = canvas[slot]`; and `_compiled_sample_step` at every commit
  (`canvas ← random_tokens`).
- Both run inside the inner sampler call that `ConstrainedDiffusionSampler.__call__` already wraps. That includes the prefill-only path
  (`num_draft_tokens == 0` → `_handle_prefill`) and mixed batches (`_finish_prefills` called from a decode call).
- So a request-level seed needs **no vLLM change**. After the inner call returns, for each seeded slot whose prefill completed in this call, the wrapper overwrites:
  - `states.canvas[slot]`;
  - `draft_tokens[slot, :CL]`;
  - optionally `states.step[slot]`.
  It recognises such slots with the same host-numpy expression stock uses: `num_computed_prefill_tokens_np + num_scheduled_tokens ≥ prefill_len_np` over the prefill
  indices. Stock's `init_canvas` still runs first, so global-RNG consumption is unchanged.
- Later canvases are re-initialised by stock at commit and are not seeded (prototype scope).

## Acceptance criteria
**Tier 1 — CPU (`make cd-test`, fast suite where applicable)**
1. **Wire.** `CdRequest` gains optional `draft`, `draft_noise` and `draft_start_step`:
   - `draft`: standard base64 of little-endian int32 ids, 1..CL ids;
   - `draft_noise`: float in [0, 1), default 0.0;
   - `draft_start_step`: int ≥ 0, default 0.

   `draft_noise`/`draft_start_step` without `draft` is a validation error. `to_xargs()` emits `astra_cd_draft*` keys only when set.
   `plugin/.../cd/xargs.py` parses them in the W1 check order. These are refused with stable reasons: ids ≥ vocab, length 0 or > CL, a non-base64
   payload, `draft_start_step ≥ max_denoising_steps`, noise outside [0, 1). A refusal ends the request loudly with an EOS canvas and is
   never served unseeded or unconstrained. Every pre-existing wire case decodes to the same `CdSpec`. The fake server records the new keys
   (test-author, same PR).
2. **Seed semantics.** On the prefill-completion call of a seeded request, the first canvas is set as follows:
   - for i < len(draft), `canvas[i] = draft[i]` unless position i is in the noised set, where it gets a uniform id;
   - for i ≥ len(draft), `canvas[i]` is uniform;
   - `draft_tokens[slot, :CL] == canvas[slot]`;
   - `step[slot] = draft_start_step`.

   The noised set is exactly round(noise · len(draft)) positions, drawn without replacement from the **CD-owned generator**. The uniform ids also
   come from that generator. Hand-built expectations at noise 0, 0.5 and (0.999 → all but zero positions…) with a fixed generator state.
3. **Guarantee holds (adversarial).**
   - **Out-of-language draft:** a draft that violates the grammar (e.g. out-of-enum value, stop id inside a string) with noise 0 commits a canvas the host replay accepts (CS = 1), never the draft.
   - **In-language draft:** with confident logits, a draft in the language commits in ≤ 2 denoise steps and equals the draft (`end_projection`, `perstep_mar` and
   `perstep_mar_qargmax`).
   - **Matrix:** T-0068 c3's multi-canvas guarantee matrix runs with seeded requests at noise ∈ {0, 0.5} and start step ∈ {0, mid}: viable prefix after every commit, CS = 1, zero loud errors on feasible instances,
   termination by `max_tokens`.
4. **First canvas only.** The second canvas of a seeded request starts from stock's uniform re-init: canvas, step 0, history length 0.
5. **Step accounting.** With `draft_start_step = k0`, the record's `steps` equals k0 + executed denoise steps; the temperature on entry
   is stock's schedule at k0; the step cap is reached at `max_denoising_steps`, so at most max − k0 denoise steps run. Tap frames keep the R10/R14
   shape: the commit step is in 1..max_steps.
6. *Negative (bit-identity).*
   - Requests without `astra_cd_draft` (constrained or not) are bit-identical to the golden traces (`perstep_golden_8416e39`, T-0076 c9) and to stock.
   - The fast path issues no torch op when no seeded slot is completing prefill (T-0067 c3/c4; op-count rows).
   - Global-RNG state after a mixed batch with a seeded slot equals stock's.
   - Unconstrained slots in that batch are bit-identical.
   - The `ASTRA_CD` record schema (`record_schema.py`, `CdCanvasRecord`) is unchanged; the harness knows the seed from its own request (W5 pattern).
   - No host sync is added (sync-debug rows).
7. **Preemption.** A seeded request resumed after preemption ends loudly (`preempted`, S10) and is never re-seeded from a partial state.

**Tier 2 — engine (`/launch`, one boot)**
8. **BFCL dev seeded repair**, n = 100, thinking off, `max_tokens` 256, concurrency 1.
   - **Draft:** each record's unconstrained output from this launch (sent once, first).
   - **Grammar:** `channel_header=False, fence=True`, JSON whitespace. This is the drafts' own format; see notes.
   - **From scratch vs seeded:** `perstep_mar` at T-0079's knobs (eb 1.0 / ct 0.005) from scratch vs seeded at (noise, start step) ∈ {0, 0.25, 0.5} × {0, 24}.
   - **end_projection:** from scratch vs seeded at (0.25, 0).
   - All arms are paired by record, with the order rotated per record.
   - **Report:** exact_call, schema_valid, CS (host replay), executed steps per canvas (mean/p90), wall p50/p90, split by whether the draft was schema-valid;
   copy rate (committed == draft); repair rate on invalid drafts.
   - Zero loud errors and CS = 1.000 on every row, or the run stops.
9. **Pre-registered reading** (reported, not gated). Seeding is "worth wiring into T-0080c" iff a seeded cell has exact ≥ from-scratch − 0.05 (exact
   Fraction arithmetic) and mean executed steps ≤ 0.6 × from-scratch and p50 wall ≤ 0.8 × from-scratch. The chosen cell is the H2-style
   rule (that tolerance, then fewest steps, then lower noise, then lower start step). Separately, the report states whether exact on
   **invalid** drafts is lower seeded than from scratch (anchoring), with McNemar.

## Implementation notes
- **Alignment landmine (measured at 067ee04, BFCL dev, thinking off).**
  - 87/100 unconstrained outputs open with "```json\n" (ids 2717 3723 107 …) and none open with `<|channel>`.
  - Under the calibration grammar (`channel_header=True`), 85/100 `perstep_mar` outputs open with `<|channel>json\n<channel|>`.
  - A raw draft seeded into a header grammar is therefore misaligned by the header.
  - Tier 2 uses `channel_header=False, fence=True` so the draft and the grammar share positions, and re-measures from scratch under that same grammar, so the comparison stays internal.
  - Do not "fix" the draft by splicing a header in.
  - In T-0080 (thinking on), T2's draft must be prefixed with `100 45518 107 101`; T4's starts at the call.
- **Generator use.** Noise positions and ids come from the CD generator (`ConstrainedDiffusionSampler._generator`). This consumes
  variates that later per-step draws in the same process would otherwise have used. That is acceptable only for runs with seeded
  requests; criterion 6 pins that runs without seeds are unchanged.
- **Self-conditioning embeddings** stay zero on the seeded canvas (stock `add_request`). Seeding SC from the draft's one-hot embeddings is a
  possible follow-up, not this task.
- **Writes are device-side, `non_blocking`.** The draft is decoded on the host at `add_request` and moved to the device then, like the automaton
  tables. Writing a Python scalar into a CUDA row is a sync (T-0073 D6): use device tensors for `step`.
- **The tap.** The tap (Tap∘CD) publishes the seeded canvas as a real per-step canvas. That is truthful, because the denoising view shows real
  canvases, and nothing is presented as committed before convergence. Nothing from a seeded canvas reaches the output except through the
  normal commit, so "never voice uncommitted text" holds by construction.
- **Check (unverified).** Confirm that `vllm_xargs` string values of about 1.4 KB (256 int32 ids in base64) pass the v0.29.0 API server. T-0064 proved a 1 MiB automaton string passes, so this is expected; assert it in tier 2's first request.
- **Out of scope:**
  - seeding later canvases (needs an alignment rule across canvases);
  - seeding unconstrained requests (the `astra_cd_` prefix requires a mode);
  - learned noise schedules.

## Implementation log
- **2026-10-08, implementer (branch `T-0081-impl` from 8770d2a).**
  - **Wire.** `contracts/cd.py`: `draft: str | None` (strict, canonical standard base64; non-empty; a multiple of 4
    bytes; every little-endian int32 id in [0, 262 144)), `draft_noise: float | None` (`ge 0, lt 1`, finite),
    `draft_start_step: StrictInt | None` (`ge 0`). A model validator refuses noise/start without a draft. Unset
    fields are `None`, so `to_xargs()` omits them; an explicit `0.0` / `0` is emitted. `cd/automaton.py`: the five
    SD3 reason constants, added to `REASONS`. `cd/xargs.py`: the three keys are optional fields. Noise/start
    without a draft → `missing_key`, right after the required-key check. `_draft()` runs in the bad-values stage
    after `max_bucket`, so before the payload cap, the sha and the decode. It refuses, in order: a non-str draft or
    non-canonical/strict base64 or ragged bytes → `draft_bad_encoding`; 0 bytes → `draft_bad_length`; an id < 0 or
    ≥ V → `draft_id_out_of_vocab`; noise not an int/float, non-finite or outside [0, 1) → `draft_noise_out_of_range`;
    start not an int (bool excluded) or < 0 → `draft_start_step_out_of_range`. `CdSpec` gains `draft` (read-only
    int64 array or `None`), `draft_noise`, `draft_start_step` with defaults, so every pre-existing spec is unchanged.
  - **Admission** (`cd/requests.py`, `cd/seed.refusal`): `new_request` takes `max_steps` (the sampler passes
    `diffusion_states.max_denoising_steps`). More than CL ids → `draft_bad_length`; a start step ≥ `max_steps` →
    `draft_start_step_out_of_range`. Both set `host_error` (the usual loud EOS path). A live seeded request gets
    `CdRequest.seed` (`cd/seed.build`), built on the host at `add_request` and copied to the device then:
    - the draft zero-padded to CL (int64);
    - the keep mask `i < n`;
    - a 0-d int64 start step;
    - host `n` and `k = round(noise · n)` (Python round; no .5 cases in the rows).
  - **How the hook detects prefill completion.** `ConstrainedDiffusionSampler` keeps a host bool array
    `_seed_flag[slot]` and a count `_n_seed`.
    - The flag is set at `add_request` only for a live request with a seed. It is cleared on `_drop` (slot reuse,
      release, stale occupant) and when the seed is consumed.
    - `__call__` first does a host-numpy check, `_seed_flag[idx_mapping_np[:n]].any()`, only when `_n_seed > 0`.
      If that hits, it calls `seed.completing_prefill_slots(input_batch)`. That function is stock's own
      `_finish_prefills` expression (`num_computed_prefill_tokens_np + num_scheduled_tokens ≥ prefill_len_np`). It
      applies the expression to all rows on the prefill-only path (`num_draft_tokens == 0`, as `_handle_prefill`
      does) and to the `nlog == 0` rows on a decode call. It returns slots in batch order.
    - Then the old body (now `_dispatch`, unchanged) runs the inner call, so stock's `init_canvas` and the flip to
      the denoise phase happen exactly as before on the global RNG.
    - Then `_seed(slots)` runs. For each completing flagged slot it unflags the slot and takes the seed off the
      request (`req.seed = None`: at most once). It skips the slot if the request is no longer live, which covers
      preemption detected by `_bind` after `add_request` (S10). Otherwise it calls `seed.apply`.
    - A preempted resume never carries a flag, because `add_request` sets `host_error = preempted` before the flag
      check. A request that fails in `apply` ends as `internal` (S9 pattern).
    - Calls with no flagged slot, or with a flagged slot only mid-chunk, issue no torch op outside the inner call
      and return the inner object (SD6).
  - **Generator draw order** (CD-owned generator `_generator(seed.ids.device)`; global RNG never touched).
    - Within one call, the per-step arms' draws for decode slots happen in `pre`, before the inner call. The seed
      draws happen after the inner call, slot by slot in batch order.
    - Each seeded slot draws `randint(0, V, (CL,))` (the uniform ids, used for the noised positions and the tail).
    - Then, only if `k > 0`, it draws `rand(n)`. The noised set is the k positions of smallest key (`argsort` twice
      gives the rank; `rank < k`), so the set has exactly k positions, drawn without replacement.
    - The row is `where(keep, draft, uniform)`, written to `canvas[slot]` and `draft_tokens[slot, :CL]`. Then
      `step[slot] = seed.step` (a device tensor, so no host scalar write).
    - History length, SC embeddings and the phase are stock's (`add_request` and `_finish_prefills`).
    - `cd/steps.py` was not changed. It already reads `st.step`, so the temperature on entry and the cap follow k0.
