## Goal
`tests/unit/test_guards_use_fixed_refs.py` catches the moving-ref forms T-0094's review listed, where a simple AST or regex addition
suffices. It also gains a second fast-suite check: a scope comparison of a **literal commit that is an ancestor of a fixed "closed-as-of"
commit** with the working tree fails. That blocks the latent-guard shape (T-0094b) from returning, without flagging open-branch guards: an
open branch's base postdates the closed-as-of commit.

## Holes to close (simple additions)
1. **Empty-end ranges and revision suffixes:** `"<sha>.."`, `"..<sha>"`, `"<sha>..."` (an empty end means HEAD); `^{commit}` / `^{tree}`,
   `@{u}`, `@{upstream}`, `@{-1}`, `HEAD@{1}`, bare `@`; `FETCH_HEAD`, `ORIG_HEAD`, `MERGE_HEAD`; `refs/heads/*`, `refs/remotes/*`, `origin/`
   with an empty remainder. All regex. **f-strings are rendered whole** with an opaque placeholder per `{}` (or the bound literal when the
   name resolves), so `f"{BASE}..{TIP}"` and `f"806da12..{ev.sha}"` are *not* empty-end ranges while `f"{x}.."` is.
2. **Task-branch names:** strings matching `^T-\d{4}[a-z]?-[\w.-]+$` passed to git (how G1 hid: `T-0062-perstep-cd`). Must not flag
   `T-0092b` alone or paths.
3. **`parametrize`-supplied refs:** bind a parameter name to the literal strings of a `pytest.mark.parametrize` decorator that names it.
4. **Module-attribute and return-value refs, one level:** `alias.NAME` where alias is an imported `tests` module resolves to that module's
   literal bindings; `f()` where `f` is a module-level function in the same module contributes the literals of its `return` expressions.
5. **Shell strings:** `subprocess.run("git …", shell=True)`, `subprocess.getoutput` / `getstatusoutput`, `os.system`, `os.popen`, and
   `"git …".split()` — `shlex.split` the string when it starts with `git ` and scan its tokens.
6. **Helper recognition:** an argv built as `["git"] + x`, `[*GIT, …]` with `GIT` bound to a literal list starting `"git"`, or a name bound
   to such a list; `self.<helper>(…)` / `cls.<helper>(…)` when `<helper>` is a git-running method of a class in the module.
7. **Scratch exemption by position only:** a call is a scratch-repo call only when the tmp-derived name sits in the repo-selecting position
   (the value after `-C`; `cwd=`/`repo=`; a helper's first positional parameter when the helper passes it to `-C`/`cwd`; `git init <x>`). A
   real-repo call that merely mentions a tmp-derived name elsewhere (e.g. `stdout=` to a tmp file) is scanned.
8. **Provenance taint:** a name assigned from a `rev-parse HEAD` call that then appears in another git call's arguments in the same function
   is flagged; `rev-parse HEAD` used only for records stays exempt.

## Not worth closing (stated in the module docstring)
Split literals (`"ma" + "in"`, `"".join(...)`); refs read at run time (env vars, config files, `git config`, CLI output other than
`rev-parse HEAD`); `getattr(subprocess, "run")`, `importlib` and other dynamic dispatch; multi-level data flow. The closed-range helper plus
review cover them.

## Moving-tip half
Flag real-repo git calls (after hole 7's scratch rule) whose revision resolves to a literal commit that is an ancestor of
`CLOSED_AS_OF = "ce34516"` (the T-0094b merge; every task up to it is done), of these forms: (a) `diff` with exactly one revision before
`--`; (b) `show <rev>:<path>` whose result is compared, in the same function, with `read_bytes()`/`read_text()` of the same path (ruling
Q-c2); (c) `status --porcelain -- <pathspec>` or `ls-files --others -- <pathspec>` in the same function as (a). Not flagged: frozen-copy
and oracle `show` rows (a fixed blob vs a fixed copy). Accepted limits: unresolvable revisions are not flagged; later latent guards are
caught only when `CLOSED_AS_OF` is bumped (ruling Q-c1).
