## Goal

In the T-0125 search GPU smoke (`logs/t0125-search-smoke-b372eda/phase1/sessions/20261027-112444-1064873.jsonl`, seq 92), a tool-continuation canvas (`continue_final_message: true`, request `t1-gen-s2`) was committed as one `answer` with `thought_open: false`:

> "The user wants to know the height of the Eiffel Tower in one sentence.\nThe search results show it is 330 meters … I will provide this information in one sentence.The Eiffel Tower is three hundred …"

All of it was voiced at `llm.done` (seq 95, `t1-u1..u3`) and stored as the spoken answer. The probable cause: the model skipped `<|channel>thought\n` but still wrote the closing `<channel|>`. `_ThoughtSplit.feed` (`local_astra/conductor/llm_client.py:889-931`) only treats text after a `<|channel>` as thought, so the orphan close stayed in the answer channel and was deleted by `drop_special_literals` (E8), leaving "sentence.The". It cannot be proven from the log (special literals are deleted from `llm.commit` text; the canvas `wire.out` rows carry no text); criterion 1 makes future cases provable, and H-T170-1 re-sends the request on the GPU. A scan of `logs/` at b372edaa finds 202 request attempts that start with answer text. The planner counted one `[.!?][A-Z]` splice; reviewer B's run of the new scanner over all of `logs/` (2,542 files, 7,125 attempts) found **seven**, each the same bug (reasoning followed by the answer with no space; two begin "The user wants to…"): t0125 seq 92 (this one), t0135-thought-call-ab-e1ae76e seq 163, t0136-outcome-ab-97c444a seq 311, t0137-repeat-guard-ab-38423a5 seqs 218 and 269, t0140-overview-ab-8697960 seqs 81 and 27 (seq 27 a step-1 `t1-gen` followed by a tool commit). So the model does this repeatedly; criterion 6 stays scoped to the incident file.

After this task, in id mode (tools on), a `<channel|>` that is the first channel marker of a response ends an implicit thought that began at the start of the response. Everything before it is `thought`: never voiced, never stored in history, logged as a thought commit and marked. Everything after it is split as today. Until the client knows which case it is in, text at the start of a response that has not opened a thought is held back and never released as answer.

## Acceptance criteria

1. **Provable from now on.**
   - `Commit` (`local_astra/contracts/llm.py`) gains `implicit_thought: bool = False`, allowed `True` only on a `thought` commit (a validator refuses it elsewhere, following the `stop_id` precedent).
   - The client sets it on every thought commit whose text came from an implicit thought.
   - The session's `llm.commit` log sites (`session.py` ~3966, ~4737, ~5320) add `"implicit_thought": true` to such records only; every other record keeps exactly its current keys.
2. **The rule (id mode).** Let D be the response decode up to the first stop id (the text `_ThoughtSplit` reads). Implicit mode applies only when the reader does not start in the tool state (no `tool_prefix`). Then:
   - if the first of {`<|channel>`, `<channel|>`, any `router.TAGS` literal} in D is `<channel|>` at index j, D[:j] is thought (a leading `thought\n` header is removed as for an explicit thought) and the marker is consumed;
   - D[j+len(`<channel|>`):] is read exactly as today with no thought open, so later stray closes keep today's behaviour;
   - otherwise (an open, a tag or nothing comes first) the output equals today's;
   - a marker spelled in plain pieces counts as the marker, as today (E7/E11 holding applies to `<channel|>` prefixes in this window too).
3. **No early release (streaming).**
   - While D has no channel marker and no call tag yet, no `answer` or `ui` piece is yielded, for any chunk partition.
   - The held text is released, unchanged and as today's split would produce it, at the first `<|channel>` or call tag, or at the end of the response (stop id or `finish_reason`).
   - At an orphan close it becomes thought pieces with `implicit_thought` set.
   - On abort it is never released.
4. **Hypothesis property.** For any D drawn from prose, fragments, specials (excluding stops), with or without an orphan close, an explicit block, a call tag or a UI fence, and any partition into chunks (including one id per chunk): (a) the concatenated `thought` texts and the concatenated `answer`/`ui`/`tool` outputs equal a reference function written in the test from criterion 2; (b) no `answer` commit is yielded before the first channel marker or tag of D has been fed. The existing router-parity properties stay green unedited.
5. **The real record (eval case).** The fixture holds the logged canvas text of seq 92 with `<channel|>` re-inserted at the splice ("…in one sentence.<channel|>The Eiffel Tower…") plus provenance (log path, seq, request id `t1-gen-s2`, SHA b372edaa). Fed as a step-2 continuation, the client yields thought commits whose concatenation is the three reasoning sentences, all `implicit_thought: true`, and answer text exactly "The Eiffel Tower is three hundred and thirty meters tall, or one thousand and eighty-three feet, including its antenna." Fed through the session (tools on, loop on, step 2), no `TtsSpeak.source`, `astra.spoken` text, history entry or `turns.jsonl` field contains "user wants", "search results show" or "I will provide".
6. **Log scan (CPU replay).** `scripts/replay_implicit_thought.py <session.jsonl|dir>... [--json]` (read-only) lists (a) every `llm.commit` with `implicit_thought: true`; (b) for pre-fix logs, every request attempt whose first non-tool commit is `answer` and whose answer text contains `[.!?][A-Z]`, with path, seq, request id and attempt id. Exit 0 on success, 2 on usage or unreadable input (named). Over the b372edaa log above it reports exactly the seq-92 record under (b).
7. **Tools-off path unchanged.** `split_canvas` and the text path (`reader is None`) are byte-identical to b372edaa (vLLM's `gemma4` reasoning parser's handling of an orphan close is unknown; H-T170-1(b)).
8. **Negative: the normal case is byte-for-byte unchanged.** For every D whose first channel marker is `<|channel>` with no text before it, the yielded `Commit`s (segment, text, `thought_open`, `canvas_idx`, `fence_close`, `fence_continued`, `stop_id`; `implicit_thought` false) are identical to b372edaa for any chunk partition, checked against a frozen copy of the b372edaa `_ThoughtSplit` kept in the test as the oracle.
9. **Negative: other suites green unedited.** `test_llm_id_mode.py`, `test_llm_client_segments.py`, `test_session_thought_in_answer.py`, `test_session_thought_tools_off.py`, `test_answer_cleaner_thoughts.py`, `test_t0135_thought_call.py`, `test_turn_invariants.py`. `turn_machine.py`, `speech_gate.py`, `router.py`, `canvas_relay.py` and `hud_server.py` unchanged.
10. **Negative: continued call.** A reader started in the tool state (`continues_call`) never enters implicit mode; a `<channel|>` inside a continued call's arguments leaves the `tool` commit's text equal to b372edaa's.
11. **Literal in user or tool content.** A `<channel|>` literal in the prompt (user text, or an untrusted search snippet in a tool response) has no effect on the split.
12. **Documented trade-off.** A response whose D starts with answer text and whose first channel marker is a `<channel|>` the model meant literally has all text before it treated as thought (lost, not voiced). One row pins this. Deliberate: losing a sentence beats speaking a thought.

## Implementation notes

- **The hold lives in `_ThoughtSplit`**, before `_AnswerSplit`, so fence, tag and E11 logic stay untouched; per response (a local of the `generate` frame, T-0052 D1). Keep E11's linear-time property (do not rescan the whole held text per chunk).
- **The window ends at the first `<|channel>`, `<channel|>` or call-tag literal, or at final.** A tag inside a UI fence before any channel marker also ends it; state that in the docstring.
- **No canvases are emitted during the hold** (`canvas_idx` does not advance on a chunk with no pieces, today's rule). `thought_open` is unaffected.
- **`router.py` is not changed** (the parity property's domain always starts with the header). Changing the router would also change T-0117's cleaner, T-0135's `live.classify`, `eval/cd/twopass.py` and the GPU harness scorers; leave that to a ruling.
- **Turn machine, speech gate and the T-0117/T-0121 cleaners unchanged.** Downstream readers of thought commits (T-0142 degeneracy guard, T-0135 recovery) get more input; an implicit thought is closed, so T-0135 does not fire on it.
- **Tools-off is out of scope** (criterion 7).
- **Denoising view:** no change; the relay already shows the raw committed pieces, orphan `<channel|>` included.
- **Measured cost of the hold** (logs on this box at b372edaa): step-1 responses starting with answer text 7 of 2,705 (these lose first-canvas speech and are voiced at `llm.done`); continuations 195 of 4,435, already voiced only at `llm.done` (T-0112 R14).
