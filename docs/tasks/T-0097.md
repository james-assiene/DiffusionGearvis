## Goal
The T-0093 report counts a positive Q12 case as surfaced when `extras.ui_valid is True`. The session computes that flag as an AND,
over every gated `ui` commit of the turn, of "the gate emitted a surface" (`session.py:2761-2765`). One later canvas that fails the
gate flips it, although the surface already reached the panel: the session publishes on success and never retracts
(`session.py:2782-2784`).

That is stricter than the definition the Q12 cases came with:
- docs/03 Q12 counts "runs whose `ui` segment the gate turns into a surface";
- T-0055's eval counts `surface_accepted`, set by any gate call that returned a surface and never cleared
  (`tests/eval/test_surface_placement_live.py:316-335`). Its own `ui_valid` is last-write-wins `report.ok` and is not used for uptake.

At 4b0bd92 the difference is the whole headline: `ui_valid` gives on 2/4 vs off 3/4; "a surface was shown" gives on 4/4 vs off 3/4.

After this task the report gives, per arm: **surface shown** (primary, comparable with Q12/T-0055 `surface_accepted`); **every ui
commit valid** (secondary, today's number); the `ui.gate` counts behind both; and the negative control under both definitions. It
says plainly what is still not comparable: the record carries no component count and no `root`. Nothing is gated, and no verdict
moves.

## Acceptance criteria
All rows read `build_report(run_dir)` on hand-built run directories. J1's case set and denominators are unchanged.

1. **Primary: `report["q12_shown"]`**, `{"on": rate, "off": rate}` over the positive Q12 cases (J1; `expect_surface` read as today).
   A case counts when its own turn's session-log records include at least one `ui.gate` record with `data.gated is True` and
   `data.surface_emitted is True`. Rates use the existing `_rate` shape `{k, n}`. The case is matched to its turn by the existing
   (log, turn_id) join; nothing is read from another turn.
2. **Secondary: `report["q12_all_ui_valid"]`**, same shape, counting `extras.ui_valid is True` — exactly today's computation, renamed.
3. **Negative control under both definitions:** `report["q12_negative_shown"]` and `report["q12_negative_all_ui_valid"]`, `{on, off}`
   over the negative cases. A negative case never enters a positive rate, and the reverse.
4. **Gate counts: `report["q12_gates"]`** = `{"positive": {"on": C, "off": C}, "negative": {"on": C, "off": C}}`, with
   `C = {"gated", "emitted", "failed", "not_gated"}` summed over the group's turns: `gated` = records with `gated is True`; `emitted`
   = `gated is True and surface_emitted is True`; `failed` = `gated is True and surface_emitted is not True`; `not_gated` = `gated is
   False`. Tests check the counts against hand-counted fixtures, not `gated == emitted + failed` as an identity.
5. **Per-case rows: `report["q12_cases"]`**, one per Q12 (case, arm): `case_id`, `arm`, `expect_surface`, `shown`, `all_ui_valid`
   (raw `extras.ui_valid`, may be `None`), `gated`, `emitted`, `failed`, `not_gated`, `first_emit_canvas` (`canvas_idx` of the first
   emitting record in `seq` order, else `None`), `speech_refused` (`extras.speech_refused` if present, else the count of the turn's
   `speech.refused` records).
6. **Consistency is reported, never voided: `report["q12_inconsistent"]`** lists (case, arm) pairs where log and flag disagree:
   `ui_valid is True` with no emitting record; `ui_valid is False` with no failed record; `ui_valid is None` with any gated record. A
   non-empty list adds nothing to `report["void"]` and does not change `gates(report)` (H-T93).
7. **The old keys are gone.** No `q12_surface` and no `q12_negative` key: a redefined key would mix definitions across runs silently,
   a missing one fails loudly. Amends T-0093 J0's surface additions (ruling K2).
8. **`render_markdown`** renders a Q12 section, each row labelled with its definition: "surface shown (primary; Q12 / T-0055
   `surface_accepted`; component count not recorded)"; "every ui commit valid (secondary; `extras.ui_valid`)"; "ui.gate on positive
   cases: gated / emitted / failed / not gated"; "negative control, surface shown"; "negative control, every ui commit valid"; and one
   line listing `q12_inconsistent` when non-empty. Today's mislabelled row ("negative control, surface shown" over `ui_valid`) is gone.
9. ***Negative: no gate or void moves.*** For every input `gates(report)` returns the same 8 keys (J0) with the same values as at
   `6a8600b`; `report["void"]` is unchanged; every non-Q12 report key has the same value as before; no file under `local_astra/`
   changes; `tests/eval/test_toolcall_live.py` is unchanged; the 4b0bd92 run directory is not rewritten (T-0093 criterion 5).
10. **The write-up** (`docs/cd/toolcall-live.md`), per human ruling **H-T97** (2026-10-14: "Add recount beside original"):
    - the Q12 row of *Reported against the eval* keeps its original text verbatim ("`ui_valid`: on 2/4, off 3/4; negative control 0/3

      surface shown on 4/4, off 3/4; every ui commit valid on 2/4, off 3/4; positive-case gates on 20 gated / 6 emitted / 14 failed /
      0 not gated, off 6 / 6 / 0 / 0; negative control 0/3 and 0/3 under both definitions, 0 gates in either arm;
    - finding 6 states both definitions and which matches Q12/T-0055; corrects the per-case gate counts (`flight_booking` on: a
