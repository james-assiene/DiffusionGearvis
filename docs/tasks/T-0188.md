## Goal

At seq 14219 the HUD Restart ran `reset_page` (`executor.py` 555-563: `ensure()`, then `driver.goto(start)`). It failed: the `error` record at 14222 keeps only the type name, `"Error"` (`session.py` 6804-6813). The browser stayed on photopea.com, so t15 and t16 started inside an app with no address field.

**Root cause (confirmed):**
- Photopea registers a `beforeunload` handler once a document is open. t15 s1 (seq 14654) and t16 s2 (seq 15335) both report `dismissed: [{"dialog": "beforeunload"}]`.
- The driver dismisses every dialog (`runtime.py` 694-698). Dismissing a beforeunload cancels the navigation.
- A probe with Playwright 1.64.0 and headless Chromium on loopback reproduced it: a page with a beforeunload handler and a user gesture; `page.goto` saw `dialog beforeunload` and raised `Error: Page.goto: net::ERR_ABORTED` (class `Error`, matching the log); the page stayed on the old URL.
- Recovery works: a new page in the same context opened the start URL, and `page.close(run_before_unload=False)` closed the old one.
- t15's `Ctrl+T` (seq 14717, `failed press_key: Error during press_key`) is the same `goto` (`executor.py` 840-842, 1087-1088) failing the same way.

After this task, a Restart always lands on the start page, and the log says why the first navigation failed without any message text.

## Acceptance criteria

### Group A

1. **Fallback.** When `reset_page`'s navigation to the start page raises, the executor opens a new page in the same context, navigates it to the start page, makes it the active page (`page_serial` moves), and closes the previous page or pages without running beforeunload (`run_before_unload=False`). After a Restart, exactly one page is open (H-T188-3) and it shows the start page.
2. **The reason class** is one of `beforeunload` (a beforeunload dialog event was recorded during the attempt), `timeout` (Playwright `TimeoutError` or `asyncio.TimeoutError`), `target_closed` (`TargetClosedError`) or `other`. It is decided from event kinds and exception types only. No exception message is read into the class, logged or returned.
3. **Outcome.** `reset_page` returns or exposes `{replaced: bool, reason: <class> | None}`. When the fallback also fails, it raises an exception that carries the class, never the message.
4. **Ctrl+T / Ctrl+L in web mode** (H-T188-2, recommended yes): the same fallback applies. A beforeunload-blocked start-page navigation ends `executed` with `opened the start page` on a fresh page; the previous page is closed without beforeunload.
5. **Negative.** Unchanged: a successful `goto` leaves today's page, serial and calls byte-identical on the fake driver; `reset_page` stays a no-op with no browser, an ended browser, or nothing opened (T-0162); closing the old page never ends the browser, because the new page opens first; dialogs are still dismissed everywhere else; the egress fence is untouched.

### Group B

6. **The log.** `_wipe_memory` logs, on a recovered reset, `note {"what": "live_browser.reset_page", "replaced": true, "reason": <class>}`; on an unrecovered reset, `error {"what": "live_browser.reset_page", "error": <type name>, "reason": <class>}`. A row asserts no exception message, URL or host appears in the log file. The reset still completes and `session.reset` is still logged exactly once.

## Group A review rulings (2026-10-28, orchestrator)

- **A-R1. Permissions stay denied after a replacement, persistent context too.** `replace_page` closes the other pages first and then denies permissions on the new page (closing the old page detaches the CDP session holding the overrides). A browser row on a persistent context (`user_data_dir=tmp`) asserts geolocation, notifications, camera and microphone are `denied` after the replacement and after a further navigation.
- **A-R2. The raised `ResetPageError` reaches no driver exception at all:** `__cause__` and `__context__` are both `None` (classify inside the `except`, raise after it). Rows assert `exc.__context__ is None` wherever the message check runs.
- **A-R3. A failed replacement leaves everything as it was:** with a URL the fence refuses, `replace_page` raises, the same page stays active, `page_serial` and `page_count` are unchanged, no page is tracked as new, and a later `ensure`/`settle` does not switch pages. A browser row pins it.
- **A-R4. `ResetPageError.reason` is the first navigation's class**; `fallback_reason` is the replacement's. A unit row pins it. Accepted without rows: drained Restart events are discarded; an undrained earlier beforeunload may label a later timeout `beforeunload`; a driver without `replace_page` re-raises unchanged.
