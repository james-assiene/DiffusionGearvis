# T-0084d — Format comparison: the pre-registered rule, the report, the CLI and the locked script

**Status:** done (2026-10-10; verified at 6e8df4b); planned 2026-10-09 · **Blast radius:** medium (one reviewer) · **Branch:** `T-0084d-native-select` from `main` after T-0084c
merges · **Depends on:** T-0084c. **Ends at H-T84-0:** the human approves the native system prompt, the rule below and the launch plan before
any GPU request.

## Goal
Decide whether native beats `<cc>` with the T-0080c rule, written down before any request (QN2). Make the comparison runnable once per SHA
through a locked script.

## Acceptance criteria
1. **`select_format(rows, stage) -> FormatChoice(native_thought, choice, winner, tables)`.** It is pure, and every comparison uses
   `Fraction`.
   - **Step 1 (dev only; T-0080c criterion 1, unchanged).** Over `native/<T1|T2|T4>/named/perstep_mar` (cd_always):
     - eligible: schema_valid 1.000;
     - keep exact ≥ best − 1/10;
     - choose the lowest median pass-2 wall; within 5 %, fewer mean steps; then T4, T2, T1.
     
     The result is θ_n.
   - **Step 2 (T-0080c criterion 3, with the stage's tolerance).**
     - Family: `draft_only`, `draft_only:native`, and `cd_always:`/`cd_on_invalid:` over cc `T1/named/{end_projection, perstep_mar,
       perstep_mar_qargmax, perstep_mar+seed}` and native `native/θ_n/named/{the same four}`.
     - Eligible: schema 1.000, and CS 1.000 on every constrained row.
     - Keep exact ≥ best eligible − tol, with tol = 1/10 on dev and 1/20 on test.
     - Choose the lowest e2e p50 over tool cases; within 5 %, the lower p90; then fewer mean steps; then kind order; then arm order (seed
       arm last); then **format cc before native**.
   - `winner` is the chosen policy's format. The test stage takes θ_n from a dev selection file and runs step 2 only.
2. *Negative.* `select(rows, "stage1"/"stage2")`, its tolerances, orders and `_STAGE1` are unchanged. On the T-0080c artifacts it returns the
   recorded choices.
3. **Report** (from artifacts only). Additions per format:
   - route recall (by the format's own tag), false tags on no-tool cases, the `wrong_tag` count, the `open_thought_call` count;
   - the draft parse-failure reason histogram;
   - the spoken-prefix share (non-empty after strip) and median chars; the `text_after_close` count;
   - pass-1 prompt tokens, prefix-hit fraction, and per seed cell the coverage, copy rate and trim.
   
   Also:
   - the step-1 and step-2 tables;
   - a line `format winner: <cc|native> (policy …)`;
   - an exact McNemar of `exact` between each format's best policy, paired by case and reported only, with Bonferroni over the family.
   
   A dev artifact is marked "dev pilot; not a held-out result".
3a. **Every existing report section splits by format (amendment, 2026-10-10, from the T-0084c review).** On a mixed artifact, today's
   `report()` pools both formats. This criterion requires each of the following to be computed per format:
   - `p1_by_case` (last-write-wins today), so `draft_agreement` pairs each cell with its own format's draft;
   - the seed report, so a native seed cell does not count cc cases as `missing`;
   - `n_cases`;
   - route recall, the false-tag rate, `pass1_wall_ms`, `stripped_close`;
   - McNemar against that format's `draft_only` (`draft_only:native` for native cells);
   - the dev stage-1 line.
   
   A row per section on a hand-built mixed artifact pins it, and cc-only artifacts give byte-identical reports.
4. **CLI** `scripts/gpu/cd_toolcall.py --compare-native --stage dev|test [--selection PATH]`.
   - Dev default cells: cc `T1/named/{4 arms}` plus native `{T1,T2,T4}/named/{4 arms}` (16 cells).
   - Test: cc `T1/named/{4}` plus native `θ_n/named/{4}` (8 cells).
   - Writes `selection-native-<stage>.json`: stage, rule, native_thought, choice, winner, commit, artifact sha256 and cells.
   - Existing invocations are unchanged.
5. **Locked script** `scripts/locked/t0084_native.sh --stage dev|test [--selection PATH]` (t0080 pattern).
   - It refuses:
     - no stage, or an unknown one;
     - a dirty tree;
     - bound ports or running containers;
     - `services/vllm.sh` drift since 806da12;
     - an existing out-dir `logs/t0084-native-<stage>-<SHA>`.
   - `--stage test` is refused unless the selection has `stage == dev`, `commit == HEAD` and `winner == native`.
   - It then runs `make plugin-wheel`, starts the engine-only `services/vllm.sh`, waits for `/health`, and runs the driver in an `||` list so
     the real exit code is kept.
   - Every `nvidia-smi … || true`.
6. *Negative.* `t0080_toolcall.sh` and `t0082_replay.sh` are byte-identical, and `thresholds.py` is unchanged.

## H-T84-0 (human, 2026-10-10)
- **Native system prompt:** `NATIVE_SYSTEM_PROMPT` approved as written (T-0084c).
- **Rule:** criterion 1 approved as written. It is fixed from here on.
- **D5 resolved: a `wrong_tag` gets a constrained retry. This amends QN7 and T-0084c C8.** A native-format pass 1 routed with a non-native
  toolcall tag (e.g. `<cc>`) is treated like an invalid draft. It still records `draft_parse: "wrong_tag"` and is counted in the report, but:
  - the native name picker runs, since no native draft name exists;
  - then one constrained native pass 2 for the picked tool, exactly as a native-tag case without a draft name.
  
  This matches the cc arm, where a native-tag answer goes to the cc picker. Under every native policy, the row's outcome is then the pass-2
  outcome (`cd_on_invalid` sends it because the draft is invalid); `draft_only:native` keeps it called, invalid and not exact.

## Implementation log (implementer, 2026-10-10, branch `T-0084d-impl` from df03421)
- **Files:** `local_astra/eval/cd/twopass.py`, `scripts/gpu/cd_toolcall.py`, `scripts/locked/t0084_native.sh` (new, mode 644 like
  its siblings) and this file. No test touched.
- **Criterion 7.** `sends_pass2` is now "routed `toolcall`, any tag" in both formats. In `_Run.pass2`, a native row with
  `draft_parse == "wrong_tag"` forces `named = None`, so the native picker runs even if the `<cc>` text happened to start with
  `call:NAME{`. The seed arm then records `seed_reason: "picker"`. `derive` dropped the C8 override, so a `wrong_tag` draft is an
  invalid draft: `cd_*` take its pass-2 row, or `missing` without one (D8), and `draft_only:native` keeps the draft.
- **`select_format(rows, stage, native_thought=None) -> FormatChoice`.**
  - Step 1 renames the three `cd_always:native/<T>/named/perstep_mar` rows to bare cells and calls the unchanged `select(...,
    "stage1")`, so it is T-0080c criterion 1 by construction.
  - Step 2 (`_format_step2`) reuses `_schema_rate_one`, `_accuracy_filter`, `_median`, `_p90` and `_mean_steps`, with tolerances
    `FORMAT_TOLERANCE = {dev: 1/10, test: 1/20}`. The sort key is (p90, mean steps, kind, arm with the seed arm last, format cc
    before native, name).
  - `select`, its constants and `_STAGE1` are untouched.
- **Report.** On a cc-only artifact the output is `main`'s (`_format_sections("cc", own_tag=False)`, assembled in `main`'s key order).
  The markdown helpers are `main`'s code split into functions. The byte-identity rows pass on all four stored artifacts and on the
  synthetic ones.
  - When a native cell or row is present, `by_format[fmt]` holds every format-dependent section plus the criterion-3 additions.
    `draft_only:native` joins `policies`, and `format_selection` and `format_mcnemar` are added. The top level keeps only artifacts,
    regime, stopped, cells, formats and the per-policy table.
  - The markdown adds the pilot marker (dev), the `format winner:` line, per-format sections, the step-1/2 tables and the
    cross-format McNemar.
- **CLI.** `--compare-native`:
  - dev runs `COMPARE_NATIVE_DEV_CELLS` (16 cells) unless `--cell` is given;
  - test runs cc T1 ×4 + native θ_n ×4, with θ_n from the selection's `native_thought`;
  - a replay or a dev `--selection` is refused (exit 2);
  - writes `selection-native-<stage>.json` with stage, rule `T-0084d`, native_thought, choice, winner, commit (=
    `--expected-commit`), head, artifact, artifact_sha256, cells and tables.
  
  It exits 1 and writes nothing if the rule chose nothing, or (test) if the report's θ_n differs from the selection's. Per D6 it
  does not check the selection's commit or winner. Invocations without `--compare-native` are unchanged.
- **Locked script.** A copy of the t0080 pattern. On test, the selection is read with `python3` (tab-separated stage, commit, winner;
  unreadable or non-object JSON gives empty fields). It is refused unless stage `dev`, commit equal to the full HEAD and winner
  `native`. The driver line is `--compare-native --stage <stage> [--selection …]`.
- **Choices the tests do not pin (for the reviewer):**
  - `select_format` requires **every** member of step 2's family to have rows, not only θ_n's seed cell. An incomplete family raises
    and names the missing policies. Without this, a run missing the cc cells would let native "win" uncontested.
  - Mixed-report definitions:
    - `route_recall` is by the format's own tag in both formats (`route_recall_any_tag` beside it);
    - `wrong_tag` counts routes with a tag other than the format's own, for cc too;
    - `spoken_prefix_share` counts tool cases routed by the own tag;
    - `spoken_prefix_median_chars` uses unstripped lengths of the non-blank prefixes (as `spoken_prefix_chars` records them);
    - `text_after_close` counts non-blank text after the close, over rows that have a close;
    - `open_thought_call` is a rate over the rows carrying the field (n 0 for cc).
  - The cross-format McNemar is oriented b = cc exact / native not, c = the reverse. Its Bonferroni family is every McNemar
    comparison in the report (both formats' families + 1).
  - On a mixed report whose family is incomplete (e.g. the 3a fixture), `format_selection` carries `choice: None` and a reason, and
    the step tables are omitted.
