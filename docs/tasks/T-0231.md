# T-0231 — The repeat guard never counts the start page; an empty step after a browser action is re-asked once

**Status:** merged 2026-11-02 (tip 4ff32389); a desk session in `--tools live` with the screen reminder on is owed (real-engine empty-step rate). Was in progress (tests a002c63e on `T-0231`). Planned 2026-11-02 (James, 2026-11-02 desk sessions: "these were awful"; "Fix whatever you can fix quickly"). Merge subject `Merge T-0231:`.

## Evidence

- **A (repeat guard).** Session 2026-11-02 12:43, turn t6. The model pressed Ctrl+L (to the start page) twice. The T-0137 recurrence rule then refused 8 actions in a row on the start page ("this screen has come back for the third time in this request; the action was not done"), and the model gave up. Going back to the start page is the guidance's own way to leave a site (live guidance v3: "press Ctrl+L, which opens the start page"), so counting its visits blocks the prescribed recovery.
- **B (empty step).** Session 2026-11-02 12:12. 10 of 48 `tool_step` requests came back with zero commits (`llm.done commits 0`, no engine error, not the T-0171 retryable kind) right after an executed browser action. Each time the turn ended after one spoken "I will click …", with no answer, no completion check and no clip. The empty steps sat in requests ending with the T-0201 screen reminder. With `--screen-reminder off` there were 0 of 64, but the model then repeatedly thought it could not see the screen. Desk sessions on 2026-10-29: 1 of 225. GPU runs: 1–2 %.

**Rulings (orchestrator, 2026-11-02, from the test-author's report):**
- **R-A1, start-page identity.** The executor reports no URL. A step is on the start page when the latest executed action that navigated was the start-page action (Ctrl+L: "opened the start page"). Any later executed action that navigated (`navigated: True`) leaves it. Whether the turn's onset page is the start page is not pinned. `computer/executor.py` stays unowned and unchanged.
- **R-A3, replaces A1's "screen=None".** `progress.judge` (or `Step`) gains an optional argument or field, defaulting to today's behaviour so no existing call or fixture changes, that marks start-page steps. Start-page steps add no visit and are never stopped as "recurring". The no-change repeat rule still applies to them. A site page's visits are still counted across start-page detours (A, start, A, start, A is three visits of A). Pinned by the test-author's rows.
- **R-B1.** The outcome note's `what` is "empty step re-ask outcome".
- **R-B2.** The re-ask's `llm.request` phase is `"empty_reask"`.
- **R-B3.** "Browser action" means click_at, type_at, press_key or scroll with status executed. `wait` is not one.
- **R-B4.** A T-0171 retry that itself comes back empty counts as that step's re-ask; there is no second re-ask.
- **R-B6.** Once the cap of 2 re-asks is reached, a later empty step ends the turn as in B3.
- **R-B7, B3 against T-0179 B-7.** `lost_thread` also plays on an empty-step end. This amends T-0179 B-7, and the docs/02 delta records it. The session plays it through the existing honest-ending clip path. The HUD and the turn line must not call it "degenerate"; the turn line carries `empty_step: true`. If this cannot be done with `turn_machine.py` untouched, the implementer stops and reports.
- **Conditional re-pins.** `tests/unit/test_t0207_session_check.py::test_not_when[recovered_thought_call]` and `tests/unit/test_t0142_session.py::test_next_turn_runs_after_trip` join the owned files if they go red.

## Acceptance criteria

**A. The start page is not a recurring screen.**
- A1. A step whose browser page is the session's own start page (the T-0160 web start page or the loopback start page, identified by the URL or origin the executor reports, never by pixels) is recorded for the guard with `screen=None`.
  - It therefore never adds a visit, and a proposed action on the start page is never stopped as "recurring".
  - The no-change repeat rule (A-4, `MAX_NO_CHANGE_REPEATS`) still applies on the start page, so typing the same address three times with no change is still stopped.
- A2. `progress.py` stays pure. If the rule needs the start-page notion there, it takes it as an argument.
- A3. Negative: on every other page, the guard's verdicts are byte-identical to main's over the existing T-0137 tables and a replay of the 2026-11-02 12:43 t6 step sequence (hand-copied into the test as literals). The replay ends with no "recurring" refusal on the start page.

**B. An empty step after a browser action is re-asked once.**
- B1. Re-ask once: a `tool_step` request that ends with zero commits (no thought, no answer, no call), with no engine error, and whose previous step executed a browser action. It is resent once as a new attempt, with the same prompt bytes and a fresh attempt id, under a note `{"what": "empty step re-asked", "request_id", "step"}`. A second note records the outcome (`call` / `answer` / `empty`).
- B2. Recovered: if the re-ask yields a call or an answer, the loop continues exactly as for a normal step. A no-call answer goes through the T-0207 completion check as usual.
- B3. Still empty: the turn ends with the existing honest-ending system clip `lost_thread` (T-0178/T-0182: system audio, never in history), and the turn line records `empty_step: true`. Nothing is invented as speech.
- B4. Scope:
  - at most one re-ask per step and at most 2 per turn;
  - a step after a non-browser call (search, wait) is unaffected;
  - the T-0171 retryable-empty path is unchanged and does not double count;
  - `generate` (step 1) is unchanged.
- B5. Negative: a turn with no empty step is byte-identical to main in every request body and record. The turn machine is untouched. Thinking is never toggled.
