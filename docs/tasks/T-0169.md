# T-0169 — a live web session starts on /web.html

**Status:** done 2026-10-27 (reviewer approved, verified PASS at 02d75096; impl 4c6bcb29, tests 6f82e700 + activation a0e3e91d + rig fix 02d75096); was in progress (planned 2026-10-27). Follow-up: no row opens a loopback first page other than `/` with a start origin set (reviewer mutant M7, equivalent in the cli path) · **Branch:** `T-0169-web-start-page` from b372edaa · **Blast radius:** medium (see below) · one reviewer.

Origin: the T-0160 web GPU smoke at b372edaa (`logs/t0160-web-smoke-b372eda/`: W1 1/5, W2 0/5, `hosts` [] in all 10 trials). Verified cause: in web mode `cli._open_start_page` opens `pages.origin + "/"` (the loopback catalogue), not `/web.html`. The model typed URLs into the catalogue's search box for up to 9 steps; nothing navigated, so the proxy saw no CONNECT. `/web.html` was reachable only through Ctrl+T/Ctrl+L (`executor.START_PAGE_COMBOS`/`START_PAGE_PATH`) or `reset_page()`, which already uses `/web.html` in web mode, so in web mode Restart and session start disagreed. T-0160's plan (lines 31 and 369: "the model learns about the web from `/web.html`'s pixels") assumed the session starts there, and no test covered the first page a live session opens (B-7 and C-5 open `/web.html` directly).

## Goal

A `--tools live` session in web mode (the default; neither `--no-web` nor `browser_web = false`) opens the agent browser on `<start origin>/web.html`, the page with the web-address field and the Go button. Every path that opens "the start page" uses that URL — session start, Restart (`reset_page`) and Ctrl+T/Ctrl+L — and all get it from one place in the executor, so they cannot drift apart. In loopback mode (`--no-web`, `browser_web = false`) nothing changes: the session opens the catalogue `<start origin>/`, and Restart returns to it. The prompt, the tools file and `web.html` stay unchanged.

## Acceptance criteria

1. **Web mode, session start.** With web mode on, `cli._open_start_page(graph)` makes the executor's first navigation `<pages.origin>/web.html`, exactly once, with no navigation to `<pages.origin>/` before it.
2. **One source for the start URL.** In both modes the URL session start opens equals the URL `reset_page()` navigates to. Both come from one executor-side definition, which is also the Ctrl+T/Ctrl+L target in web mode. A test pins the equality in both modes; no test greps the implementation.
3. **Negative: loopback mode unchanged byte for byte.** With `--no-web`, `browser_web = false`, or a mode other than live, the first navigation is exactly `<pages.origin>/` as at b372edaa; `reset_page()` still returns to the first page `open()` was given; the `--dry-run` lines, startup stdout/stderr lines and the T-0111g start-failure message are identical to b372edaa's.
4. **Negative: what the model is told does not change.** `LIVE_TOOL_GUIDANCE` (768a973b), the tools file (`tools_v1` bbfc53cc), `pages/static/web.html` and the session's prompt bytes are unchanged; existing pins stay green unedited. No new stdout/stderr line, session-log kind or turn-line key.
5. **Start failures keep their messages.** A web-mode open of `/web.html` failing with Chromium's sandbox error still raises `LiveStartFailed` with `WEB_SANDBOX_HINT`, and the browser is closed. Other failures keep T-0111g's message.
6. **End to end, web mode (browser).** A session built by `cli` (`--tools live --browser headless`, web on by default, fake LLM and services, real `StartPageServer`, real web-mode executor with sandbox and egress proxy):
   - after start, the agent page's URL is `<origin>/web.html` and `window.__state.page == "web"`;
   - turn 1's image is that page's own frame;
   - after a Restart (session reset), the page is still `<origin>/web.html`;
   - the page fits on one 1280x800 screen, so with the T-0152 default the step-1 overview-frame outcome is `fits`;
   - no connection leaves loopback.
7. **End to end, loopback mode (browser, negative).** The same rig with `--no-web` starts on `<origin>/` (the catalogue), and Restart returns there.
8. **Existing suites green, unedited:** `make fast-parallel`, `make browser-live`, `make browser-web`, `make browser-suite`.

## Implementation notes

- **Single source.** Put the start-URL definition in the executor next to `START_PAGE_PATH`, used by `reset_page`, the Ctrl+T/Ctrl+L plan and `cli._open_start_page`. The executor's `web` flag is the authority, not `graph.web`. Do not touch `session.py` or its `LiveBrowser` protocol.
- `open()` is unchanged; it already accepts the start origin in web mode.
- **Do not change** `web.html`, `LIVE_TOOL_GUIDANCE`, `tools_v1.json` or the system prompt (prefix cache; T-0160 ruling).
- Overview frame: web.html fits on one screen, so step 1 keeps the normal frame; criterion 6 pins it.
- **Questions for James (out of scope):** in web mode the loopback demo pages can no longer be reached from the agent browser (`/web.html` accepts https only) — is `--no-web` the documented way to run those demos? A browser relaunched by `driver.ensure()` after a crash comes back on a blank page in both modes (predates T-0169).
