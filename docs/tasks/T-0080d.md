## Goal
In a live turn with tools on, the conductor does the following.
- **Pass 1.** It sends the native pass 1 as one request: the `tools` field, `tool_choice: "none"`, thinking on as always.
- **Speech.** It speaks only the committed spoken prefix (T-0085's `router.route(...).spoken_prefix`). It never speaks a thought, a call, a
  special token or any pass-2 output.
- **Detection.** It detects the native call, parses it with `native.parse_call` and validates it with `score.schema_valid` against tools_v1.
- **Repair.** An invalid draft that names a v1 tool gets exactly one seeded constrained native T4 pass 2 through the plugin.
- **Execution.** The resulting call goes to a `ToolExecutor`. In v1 that executor is **dry-run only**: it logs the call, resolves
  coordinates to frame pixels, and the HUD shows the intended action. Nothing touches the desktop or the network.

## Findings that shape the plan
1. **The live stream cannot see the call today.** vLLM serves `content` with the special pieces dropped (`skip_special_tokens`; see
   `tests/cd/fakes/vllm_server.py::split_served`). The eval scored host-decoded ids; the live client reads `content`. So today a native
   call would reach the speech gate as `call:click_at{...}`, and the `<|"|>` string delimiters would vanish.
2. **The speech gate misses Gemma 4's asymmetric special tokens.** Its `<\|[^|>]*\|>` rule misses `<|tool_call>`, `<tool_call|>`,
   `<|channel>`, `<channel|>`, `<|turn>`, `<turn|>` and `<|tool_response>`. `_TRIM_TOKENS` names `<end_of_turn>`, not `<turn|>`.
3. **The protocol cannot carry constrained-decoding keys.** `LlmBackend.generate(xargs=Mapping[str, str])` (T-0017 A2) cannot carry the
   numeric `astra_cd_*` values that `parse_cd_xargs` requires.
4. **The conductor cannot import `local_astra.decoding`.** Hence precompiled payloads, and seed tokenisation through the engine's
   `/tokenize` on loopback.
5. **The declarations are part of the cached prefix.** They render in the system turn, so the prefill and the generate request carry
   identical `tools`. Tools are a session setting.
6. **Computer use is a v1 non-goal** (docs/01 §3).
7. **The live prompt is not the eval prompt.** Native accuracy is unmeasured under it (T-0093).
8. **The eval's nameless-draft path is unseeded.** It runs the name picker and then an unseeded T4 pass 2, the arm that wrote garbage
   queries (T-0084f finding 1).
9. **The fallback is unmeasured on real invalid drafts.** H-T84-2's caveat: 0 of 120 native drafts were invalid.

## Settled defaults
1. **Executor boundary.**
   - **Interface.** `ToolExecutor` is a `runtime_checkable` protocol: `mode`, then `async execute(ToolInvocation) -> ToolOutcome`.
   - **v1 executors.** `DryRunToolExecutor` maps 0–999 coordinates to the pixels of the newest image attached to the turn and describes
     the action. It opens no socket, spawns no process and touches no input device. `tests/fakes` holds a recording fake.
   - **The switch.** It is `tools: off | dry_run`, default `off` (H3). A `live` value is reserved and refused at startup, citing
     docs/01 §3.
   - **Later tasks.** Real screen control (portal RemoteDesktop or uinput) and real search are separate tasks after a design-doc change.
   - **google_search.** It is never executed in v1, because it needs the network and that breaks G5/S8/E8 and the loopback rule. The
     human decides (H2).
2. **Turn machine.** The machine stays pure.
   - **Events.** `LlmDone` gains `tool: ToolDraft | None`.
   - **Commands.** `ToolRepairStart`, `ToolExecute` and `ToolCancel`, plus the timer `tool_repair`.
   - **Rows.** Repair only after pass 1 is done, so there is still one active generate. Execute only when the turn completes
     uninterrupted, after the spoken prefix has drained. Cancel on every interruption, error and disconnect row. At most one repair per
     turn. Repair commits are never voiced.
   - **Invariants.** All of the above become Hypothesis properties in `test_turn_invariants.py`, plus a differential "no tool ⇒
     identical to main" property (T-0089).
3. **Speech.**
   - **What is voiced.** Only answer-segment text before the first `<|tool_call>`, which equals the router's `spoken_prefix` (channel
     markers removed).
   - **Defence in depth.** The speech gate trims or drops every special token of the pinned tokenizer.
   - **No spoken sentence.** When native skips the sentence (13/40 dev, 26/80 test, every google_search on dev), nothing extra is voiced.
     The acknowledgement clip has already played, because thinking is always on. The HUD card shows the action (H4).
   - **History.** History holds only what was played (H8).
4. **`query_problem`.** Log-only. It is computed for every google_search call, recorded, and shown as a HUD warning. It never blocks and
   never triggers a repair (F4 false rejections; H7).
5. **Latency.**
   - **Pass 1.** The declarations join the cached prefix; the native eval prompt had 1071 median prompt tokens against 1538 for cc. A call
     adds about 20–40 tokens to the answer canvas.
   - **Valid draft.** No extra request: `draft_only:native` e2e p50/p90 was 227/352 ms on test, under the eval prompt.
   - **Fallback.** One seeded T4 request. On valid drafts it measured p50/p90 208/220 ms (dev, n = 40, 2.0 steps, prefix-hit median
     0.977). It runs while the spoken prefix plays (T-0080 Q6), so it delays the action, not first audio. It has never been measured on a
     real invalid draft.
   - **Repair timeout.** 3000 ms.
   - **Budgets.** B3 and B11 must not regress more than 10 % with tools on (T-0093). No new threshold goes into `thresholds.py`; action
     latency is reported, not gated.
6. **Multi-step tool loop.** The loop with `<|tool_response>` (id 50 stays a stop) is out of scope: a dry run has no result to return.
7. **Test layers.**
   - Unit and contract tests over fakes in every sub-task.
   - `gpu` contract rows in T-0088 (tools body, `cd` keyword, `/tokenize`).
   - The probe (T-0087) and the live eval (T-0093) go through `/launch`.
8. **Split.** Seven sub-tasks; order below.

## Human decisions (2026-10-11): all defaults H1–H12
The human accepted every default below. H-T93 (the live-eval gates) and the H11 prompt wording are still approved separately, before the
GPU runs.

- **H1. Executor in v1.** **Dry-run only.** Real screen control and real search become separate tasks after a docs/01 §3 change.
- **H2. google_search and the loopback rule.** **Never executed in v1; the HUD shows the query as text with no link.** The alternatives are:
  - (a) a click-through link the human opens in their own browser;
  - (b) a separate search process with its own network allowance and audit (it changes G5, E8 and the systemd policy).
- **H3. Tools default.** **`off` until T-0093 passes.** After that, the human decides whether `lean` defaults to `dry_run`.
- **H4. No spoken sentence.** **Voice nothing extra; the ack clip and the HUD card cover it.** The alternative is a pre-rendered fixed clip,
  never text built from the call.
- **H5. When to execute.** **After the spoken prefix has fully played, and only if the turn was not interrupted.** The alternative is to
  execute concurrently with speech: lower latency, but "no, wait" could not cancel it.
- **H6. Nameless or `<cc>` invalid drafts.** **Refuse; no name picker and no unseeded pass 2.** This deviates from the eval cell's picker
  path, because of T-0084f finding 1.
- **H7. `query_problem` live.** **Log-only, shown as a HUD warning; never blocks.** Revisit before search executes for real (T-0086 F4).
- **H8. History.** **Only what was spoken.** A "[proposed action …; not executed]" marker would need a CLAUDE.md rule change.
- **H9. Seed tokenisation.** **The engine's `/tokenize` on loopback.** The alternative is to add `tokenizers` to the core deps and read the
  pinned `tokenizer.json` from the local HF cache.
- **H10. Reading B fallback.** **If T-0087 shows the content channel cannot carry special tokens, replan T-0088 on streamed token ids with
  host detokenisation** (this needs H9's alternative).
- **H11. Prompt wording.** **Append the H-T84-0-approved paragraphs 2 and 3 of `NATIVE_SYSTEM_PROMPT` verbatim; the persona sentence is
  omitted.** Coordinates resolve against the newest image of the turn; click and type are refused with no image. The human approves the
  wording, as at H-T84-0.
- **H12. Repair timeout.** **3000 ms.**
- **H-T93.** Approve T-0093's hard gates and its report-only quality lines before the run.
