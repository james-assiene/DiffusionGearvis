## Goal
Dang & Ermon published their reference implementation, Mosaic (MIT), at
`MhDang/mosaic@36945e4b3c64913e23962e0924a8b40a84c58807` (2026-10-02). Check our independent port in
`plugin/astra_vllm_plugin/astra_vllm_plugin/cd/` against it offline, on CPU, with the same automata and logits: per-position
constrained marginals q, H(q), the joint draw, and our MAP. A disagreement becomes a red test plus a triage verdict (ours /
theirs / convention / harness), never a looser tolerance. Known convention differences are stated and checked by tests that
assert the divergence. No runtime code changes; the output is evidence and possibly follow-up fix tasks.

**Mapping (Mosaic → ours).** q, log Z: `ParallelSampler._compute_marginal_log` (segment tree), `SequentialSampler`
(forward-backward) → `marginals.constrained_marginals` (two-pass, Doob-gauged): deterministic, tolerance per dtype. H(q):
not in Mosaic's sampler (its vLLM integration computes −Σp log p) → ours; harness computes H from Mosaic's q in fp64. Joint
draw: `ParallelSampler.sample(T=1)` / sequential ancestral → `draw.joint_draw`: in distribution only. MAP: none in Mosaic
(T=0 is the argmax token on a sampled path) → `mapdecode.constrained_map`: membership and dominance only. Ends: `start_nodes`
(one node), `end_log`, `finish_within_log(R)` → `a_start` set, `terminal_factor(R_after)`, `l_eff`: equal after a super-start
node. State threading: `advance` (DFA) → `budget.delta_star` (sets): DFAs only. Precision: Mosaic fp64 matmuls by default
in its vLLM integration → ours fp32 log space, compensated (T-0062 decisions 10/13), also accepts fp64.

## Acceptance criteria
1. **Vendored and auditable.** `tests/fixtures/mosaic_36945e4b3c64/` holds byte-identical `LICENSE`, `mosaic/__init__.py`,
   `mosaic/sampling/{__init__,automaton,layers,parallel,sequential}.py`, and a `MANIFEST.md` (repo, full sha, MIT notice,
   sha256 per file, the einops pin). A test recomputes the hashes against constants in the test (planner's fetch: automaton
   `27439f67…94e8a`, layers `bc805f37…94db`, parallel `4793b6ea…f344f`, sequential `fc0940b8…2633`, sampling/`__init__`
   `6dcc9b73…c304`, LICENSE `4e995225…9db`).
2. **The reference is sound before it judges.** On tiny instances (V ≤ 6, L ≤ 8, |S| ≤ 5; DFAs, NFAs with overlapping parallel
   labels, non-singleton start sets, binding end weights), Mosaic fp64 marginals (both samplers, after conversion) match
   `tests/cd/oracle/enumerate.py` within |Δq| ≤ 1e-10.
3. **Marginals, fp64 vs fp64.** Ours fp64 vs Mosaic parallel fp64: max |Δq| ≤ 1e-10 tiny, ≤ 1e-9 at production shape (L 256,
   V 262 144 via the quotient vocabulary, buckets ≤ 128).
4. **Marginals and H, fp32 vs fp64.** Ours fp32 vs Mosaic fp64 on T-0065 criterion 2's regimes (softcapped logits at T ∈
   {0.8, 0.4}, spans up to 250 nats, narrow negated classes, the unscored tail, `L_eff < L`): ≤ 10× stock H(p)'s fp32 error
   on the same logits + 1e-6, for q and H(q).
5. **Joint draw, enumerable cases.** Ours, n = 20 000 per instance, χ² against Mosaic's exact posterior built by the chain
   rule from Mosaic marginals; cells pooled to expected ≥ 5; Bonferroni at family α = 1e-3. Mosaic's own draws through the
   same test are the control and must pass.
6. **Joint draw, large cases (Sudoku, BFCL).** (a) Per position, χ² of our tokens against Mosaic's q (q ≥ 0.01 own cells,
   rest pooled), n = 4 000, Holm over positions at α = 1e-3. (b) For the 8 highest-H(q) positions (chosen before any draw),
   χ² of our (x_i, x_{i+1}) table against Mosaic's exact `q_i(a)·q_{i+1}(b | x_i = a)` (top tokens to 0.99 mass, ≤ 8).
7. **Power, adversarial — green before ours runs.** Mutants must be rejected at the stated n and seeds: M1 ∃-form draw
   ignoring multiplicity (by 5 on the multiplicity NFA); M2 mean-field draw (by 5 on literal/NFA and by 6(b) on Sudoku,
   while passing 6(a)); M3 converter dropping multiplicity (2 or 3 red). If a mutant survives, n is raised and frozen before
   ours runs; never lowered after.
8. **MAP.** (a) Mosaic `accepts` our x̂ over `[0, L_eff)`; (b) `CdMap.score` = Σ log_softmax(logits)[x̂] in fp64 within 1e-4
   (fp32) / 1e-10 (fp64); (c) no Mosaic draw scores above x̂; (d) on enumerable cases, x̂ is the argmax over all accepted
   strings.
9. **Ends and state threading.** For R ∈ {0, 1, 2, d_max, d_max + 3}, Mosaic `steps_to_accept`/`finish_within_log(R)`
   gives the same live set as our `terminal_factor`; on DFAs, `delta_star` over committed ids up to the first stop id equals
   Mosaic `advance`.
10. **Pre-registered disagreement handling.** Every red row of 3–9 gets a ledger row in `tests/cd/mosaic/DIVERGENCES.md`
    (case, quantity, magnitude, the independent arbiter's verdict — `enumerate.py` tiny, `dense64.py`/`viterbi64.py` at shape —
    and attribution). **ours:** the test stays red and a fix task is opened against `cd/`; T-0075 does not merge before it.
    **theirs:** that case compares ours vs the arbiter, plus a test asserting Mosaic's divergence. **convention:** listed
    with a probe test. **harness:** fixed by the test-author. No tolerance, n or α change after the first run against ours;
    no `pending`/`xfail` to green a red row.
11. *Negative, isolation.* Only owned files change (nothing under `plugin/`, `local_astra/`, `services/`, `scripts/`). After
    the Mosaic import, `torch.get_float32_matmul_precision()` and the global RNG state are restored; a tiny case through our
    core before and after the import is bit-identical.
12. *Negative, suites.* The fast suite and `make fast-parallel` unchanged (`tests/cd` needs `ASTRA_CD_TESTS=1`);
    `uv sync --all-extras` installs neither torch nor einops; the new module adds ≤ 15 min serial to `make cd-test`.

## Implementation notes
- **Order:** test-author vendors, writes the harness, gets 1, 2 and 7 green (recorded with commit sha) before ours runs,
  then 3–6 and 8–11 (modules `pending(task="T-0075")` until `/implement`); implementer adds the two `pyproject.toml` lines,
  runs `make cd-test`, triages every red into `DIVERGENCES.md`, opens fix tasks; edits neither tests nor `cd/`.
- **Converter (ours → Mosaic):** fill `ParallelSampler`/`SequentialSampler` buffers directly (`from_graph` asserts unique
  pairs and out-edges, which our dead/padding states violate); merge parallel edges into one edge whose emission counts
  member edges per token (keeps NFA multiplicity exact); fold a start set into a super-start node; `accept_node` =
  `b_final`; Mosaic gets `logits[:L_eff]`; `.double()` and `matmul_dtype = torch.float64` for the reference (Mosaic fp32
  reported only). It reads only the host-side compiled automaton and class tables, never `cd.emission.build_tables` /
  `CdTables`; our side runs from the wire payload (`decode_payload` → `build_tables`) as in production.
- **Quotient vocabulary for V = 262 144:** group tokens by class-membership signature; Mosaic gets per-group logsumexp
  logits; compare q per group; H via the group decomposition in fp64; one test checks our within-group ratio.
- **Conventions (each a probe, never compared as equal):** Mosaic temperature ≠ 1 semantics (parallel tempers only the
  edge token; sequential the whole conditional) — only T = 1 on pre-scaled logits is compared, as our `steps.py` does;
  Mosaic T = 0 is not MAP (agreement rate reported only); empty support → Mosaic uniform fallback vs our loud
  `z0`/`empty` (decision 12); EOS/padding conventions (out of scope: both sides run our automaton); `advance` assumes a
  DFA; L = 0 unsupported; the import-time `torch.set_float32_matmul_precision("high")` side effect.
- **RNG:** ours `torch.Generator(seed)`; Mosaic global RNG under a fixture that saves/restores state; seeds
  `20261003 + case_index`. No network in tests; fixtures committed. Mosaic's −inf mapped to our −1e30 sentinel before
  comparison.
- **Out of scope:** the compiler side by side (Mosaic `grammar/json_schema.py` vs T-0063; it needs `automata-lib`), engine
  runs, real logit dumps (none exist yet).
