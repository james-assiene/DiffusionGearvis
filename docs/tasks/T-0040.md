# T-0040 — Ctrl-C-safe session shutdown with `--serve-hud`

**Status:** done 2026-09-15 (merged; reviewer APPROVE on the design, A5/A6 fixes pinned by tests) · **Blast radius:** low (one reviewer; `cli.py` shutdown path and `hud_static.py` only) ·
**Depends on:** T-0033 (merged), T-0039 (merged) · **Origin:** the first live text-mode run (PROGRESS Runs 2026-09-15,
`logs/t0039-live-82d8462/run.log`).

## Goal

`uv run astra session --silent --serve-hud` is now the first thing the human runs. Ctrl-C in a terminal delivers SIGINT to the
foreground process group, i.e. to `uv` **and** to the Python child; `uv` forwards its copy, so the session sees two SIGINTs. The first
is handled (T-0028 criterion 16: the session closes, the endpoint stops, no `turns.jsonl` line); the second lands while
`session_cmd` is inside `static.close()` → `http.server.HTTPServer.shutdown()` → `threading.Event.wait()`, and escapes as a
`KeyboardInterrupt` traceback with exit 130. Ports were released, nothing was corrupted, but "the demo prints a traceback when you
stop it" is the first impression the human gets. After this task a second (or third) SIGINT during shutdown is absorbed: the
process still exits 0, prints one line, and leaves no listener.

## Acceptance criteria

1. **A second SIGINT during shutdown is absorbed.** With the session serving (`--serve-hud`), two SIGINTs delivered back to back
   (the second while the first's shutdown is in progress) leave exit code 0, no traceback on stderr, and 8000/1420 unbound. Mechanism
   is the implementer's (e.g. `signal.signal(SIGINT, SIG_IGN)` for the duration of the shutdown sequence once the first is seen, or a
   shutdown that never blocks on an interruptible wait); the turn-machine, session and hud_server internals are not touched.
2. **`HudStaticServer.close()` is interrupt-safe and idempotent.** A `KeyboardInterrupt` raised inside it does not leave the
   `serve_forever` thread running or the socket bound; calling it twice is a no-op.
3. **Criterion 16 of T-0028 still holds for a single SIGINT** (exit 0, no `turns.jsonl` line, ports released) — the existing row
   `tests/unit/test_cli_session.py::test_sigint_closes_the_session_and_writes_no_extra_line` passes unmodified, and (ruling T-0039 A16)
   the row moves off the fixed port 8000 so concurrent runs never collide.
4. **Negative.** No change under `local_astra/conductor/`, `hud/`, or `tests/` except the rows below; a SIGTERM is handled the same way
   as SIGINT (one line, exit 0).

## Rulings

- **A1 (mechanism).** Criterion 1 as written: the second SIGINT is delivered deterministically inside the shutdown window, so the fix
  must absorb it (ignore SIGINT for the duration of the shutdown sequence), not merely avoid blocking.
- **A2 (SIGTERM).** No row; criterion 4's SIGTERM clause is implemented (same handler) but pinned only by reading — reviewer checks it.
- **A3 (restore).** The SIGINT disposition is restored after `session_cmd` returns (in-process callers stay interruptible); the
  reviewer checks it with a probe.
- **A4 (activation).** Markers removed by the orchestrator after 2b25fb9.
- **A5 (review, REVISE narrow).** Behaviour correct under every signal storm probed (81 live runs). F1 (implementer): a first stop signal
  after the loop has closed (e.g. the busy-port `OSError` exit) reaches `cancel_the_serve_loop` on a closed loop → `RuntimeError` —
  clear `_on_first` in `_serve`'s `finally` (or suppress `RuntimeError`). F2 (test-author): the `atexit` hook is pinned by no
  deterministic row — the integration row sends its duplicate 50 ms after the first signal and misses the 240–440 ms window; send
  the duplicate after reading the "session closed" stdout line, plus a second one ≈ 250 ms later. Note in the task: that row runs only
  when the module is named (tests/integration is `/launch`-only by README; this row spends no GPU and may be run directly). Style:
  the `add_signal_handler` mention in test_cli_session.py:288 is stale.
- **A6 (residual found by the deterministic row).** CPython runs `threading._shutdown` (joining non-daemon threads) *before* the
  `atexit` callbacks, so after A3's restore a late duplicate signal prints `Exception ignored in threading._shutdown: KeyboardInterrupt`
  (exit still 0; ≈ 40 % of runs at b3fae52). Ruling: after a stop signal was serviced, the CLI keeps `SIG_IGN` installed through
  interpreter exit and restores the previous disposition only when the caller had installed a non-default handler (A3 for in-process
  callers with their own handler; a process whose previous handler was the default is exiting anyway). The `atexit` hook stays as
  belt-and-braces. Test rows: the two-point row and the held-down-Ctrl-C row in tests/integration/test_session_ctrl_c.py (a7d9cb9).
- **A7 (merged).** F1 (closed-loop cancel) and A6 (keep SIG_IGN through exit unless the caller had its own handler) landed at 73463a3;
  the deterministic integration rows pass 10/10 and go red under the A6 mutation. Merged without a further review round (low blast
  radius; both fixes test-pinned). Note: an in-process caller that installed a handler for only one of the two signals keeps that one
  and the other stays SIG_IGN for the life of the process after a serviced stop.
- **A8 (regression found by the Stop hook, 2026-09-15).** A6's "keep SIG_IGN unless the caller had a handler" leaks into an in-process
  caller: after an interrupted `cli.main([... session ...])` the pytest worker keeps SIGTERM/SIGINT ignored, every child it spawns
  afterwards inherits SIG_IGN (ignored dispositions survive fork+exec), and `tests/unit/test_cli_down_status.py`'s `sleep 30` victims
  become unkillable — 3 rows red whenever `test_cli_session.py` runs first in the same worker (reproduced: session-then-down 3 failed,
  down-then-session 27 passed). Ruling: the "keep ignored through exit" behaviour applies only when the CLI owns the process — `main()`
  called with `argv=None` (the console entry point) — and in-process callers (tests, embedders) always get A3's full restore of both
  dispositions. The atexit hook is registered only in the process-owning mode. Test rows: after an interrupted in-process session, both
  dispositions equal their pre-call values and a spawned `sleep` child dies on SIGTERM; the subprocess rows keep proving the CLI mode.
- **A9 (merged).** A8 landed at beadca3: `StopSignals(own_process=argv is None)`; in-process callers restore both dispositions and register no atexit hook; the CLI keeps the A6 behaviour (integration rows 10/10). The Stop-hook `down` failures are gone (session-then-down 30 passed). Merged without a further review: three rows pin both modes and the mutation reverts the six failures.
