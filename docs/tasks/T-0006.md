# T-0006 — Playback path, the played clock, and the audio rig (PipeWire)

**Status:** merged 2026-09-14 (implementation a794005 + 05b2bd8 + 7e3a74e + d3bce41; five reviews, E APPROVE; 71 tests; rig assertions unmeasured until P1)· **Blast radius:** high (audio path — two reviewers per CLAUDE.md) ·
**Depends on:** T-0003 (merged; consumes what this task produces) · **Blocks:** T-0006b, T-0007

## Goal
`local_astra/conductor/audio_io.py::PipeWireAudioIO` becomes a real playback engine on the
Conductor-owned device (docs/01 D7, docs/02 §2.1/§2.7, ADR-013): 48 kHz mono, 10 ms blocks, TTS
audio resampled 24 kHz → 48 kHz, with `pause()` / `resume()` / `flush()` that act on the device
within tens of milliseconds and a **`played_ms` read from the device's own rendered-frame
position, never from bytes handed to the buffer**. That number is not a statistic: the merged turn
machine puts `PlaybackStopped.played_ms` / `played_text` straight into history, and §4's invariant
"the history never contains assistant text that was not played" is true only if the number is
honest (docs/03 I3). This task also builds the rig that makes the audio path testable with nobody
in the room: a PipeWire null sink whose monitor is the oracle for what was actually rendered, and
an acoustic loopback (real sink → speaker → mic) that measures the echo path delay the capture
gate will need. Capture is **not** implemented here.

**Split and ordering (this task is the first of two).** T-0006 = playback, the played clock, the
rig. **T-0006b** (to be planned, starts after T-0006 merges) = `capture()` at 10 ms/48 kHz f32,
48 kHz → 24 kHz for STT, the capture gate during playback driven by the reference ring this task
exposes, xrun accounting, and the `audio.capture` span. **T-0007** (Unmute fork / `session.py`)
starts after T-0006b: it owns the seam described under "Seam to `session.py`" below and must not be
started against a half-built audio module.

## Acceptance criteria

Each is checkable by a test or a rig measurement without an implementation existing. "The monitor"
means the PipeWire null-sink monitor recording made by the rig (criterion 11); it is an independent
oracle, not a re-implementation of the module.

1. **Device seam and block cadence.** A new `local_astra/conductor/audio_device.py` defines a
   `runtime_checkable` `AudioDevice` protocol with at least `start()`, `stop()`,
   `write(block: numpy f32 mono) -> None`, `rendered_ms() -> float` (frames the device reports as
   *rendered*, monotonic, non-decreasing), `latency_ms: float`, `block_ms: int`, `quantum_ms:
   float` (the quantum actually negotiated, not the requested one). `PipeWireAudioIO` takes an
   `AudioDevice` by injection (default: the real backend) and never imports a device library
   itself. Defaults: 48 kHz, mono source, `block_ms == CAPTURE_BLOCK_MS == 10`
   (`contracts/speech.py`), configured output latency ≤ 30 ms. On the rig the module **reports**
   the negotiated quantum and the tests assert on the reported value, never on the requested one
   (docs/01 D7 "48 kHz, 10 ms blocks"; docs/02 §2.7).
2. **`played_ms` is device-side and one-sided conservative.** Definition to implement:
   `played_ms = clamp(device.rendered_ms() - rendered_ms_at_run_start - paused_ms, 0,
   enqueued_ms)`, where the run starts when the queue goes non-empty from idle. Bounds, both
   tested: it **never over-reports by more than 20 ms** relative to the monitor oracle, and
   under-reports by at most `latency_ms + block_ms` (≤ 40 ms at the criterion-1 defaults).
   Over-reporting is the failure that silently corrupts history; under-reporting only loses a word
   (docs/02 §4 invariant; docs/03 I3). *Adversarial (the headline test):* with a device double
   whose `rendered_ms()` lags writes by 200 ms, enqueue 1000 ms and query at run time 300 ms —
   `played_ms` must be ≈ 300, and an implementation returning enqueued/written bytes (≈ 1000) must
   fail this test loudly.
3. **Pause acts on the device, not on the producer.** `pause()` silences the output within
   **50 ms p95 / 30 ms p50** measured from the call to the last non-zero sample on the monitor
   (criterion 9's regime), applies a fade of 2–10 ms so no consecutive-sample step on the monitor
   exceeds 0.1 full-scale (no click), and stops `played_ms` advancing. An implementation that only
   stops feeding the device and lets ≥ 100 ms of queued audio play out fails. *(docs/02 §4 row
   `SPEAKING | user_speech_onset | PAUSED | playback.pause (≤ 150 ms)`; B4.)*
4. **Resume is sample-exact.** `resume()` emits the first non-zero sample within 50 ms p95 and
   continues from exactly the sample where pause landed: concatenating the non-silent regions of
   the monitor recording reproduces the source waveform with no sample dropped and none repeated
   (cross-correlation peak at lag 0, residual ≤ −40 dB). `pause()` while paused and `resume()`
   while playing are no-ops.
5. **Flush is idempotent and reports the run.** `flush()` stops output on the same path as
   criterion 3, drops everything queued, returns the run-total `played_ms` (int, ms), and emits
   exactly one `PlaybackStopped`. A second `flush()` before the next `play()` returns the same
   number and emits no second event (`IDEMPOTENT_COMMANDS` in `contracts/commands.py:223`;
   T-0003 criterion 21).
6. **`played_text` is the committed source, cut conservatively.** `play(utterance, *, source: str
   | None = None)` records, per utterance, the source string the turn machine put in
   `TtsSpeak.source`. A word counts as played iff `utterance_offset_ms + word.start_ms + 100 <=
   played_ms` (docs/02 §4: "a word counts as played if it started ≥ 100 ms before the cut").
   `played_text` is the in-order concatenation, **with no separator inserted**, of the source
   strings of fully played utterances plus the word-boundary prefix of the partially played one —
   no separator because T-0003 criterion 10's conservation law makes the sources exact substrings
   of `committed_answer`. **Ruling on normalisation mismatch:** if `len(source.split()) !=
   len(utterance.words())` the partially played utterance contributes **no text at all** (it still
   contributes to `played_ms`). Under-reporting is allowed by the invariant; over-reporting is not.
   When `source` is None the TTS text is used and the span records
   `played_text_source="tts_text"`. *Adversarial:* a source of 2 words against a TTS rendering of
   4 ("3.5 apples" → "three point five apples"), cut after 2 TTS words, must yield `""` for that
   utterance and never "3.5 apples".
7. **`PlaybackDrained` needs an explicit end-of-stream — a queue that empties is not a drain.**
   `mark_drain()` declares that no further audio is coming for this run; `PlaybackDrained` is
   emitted only when `mark_drain()` has been called **and** the last sample has been rendered
   (same device clock as criterion 2), carrying the same run total and `played_text` rule.
   *Adversarial:* a 400 ms TTS underrun mid-utterance with no `mark_drain()` emits **no**
   `PlaybackDrained` and increments an `underruns` counter instead. This closes a real hole: T-0003
   row `SPEAKING + playback.drained ∧ llm.done → IDLE` would end the turn mid-sentence.
8. **Events, no new contract types.** `playback_events()` is an async iterator yielding the
   existing `contracts.events.PlaybackStopped` / `PlaybackDrained` instances with `t_ms` on the
   session audio clock, at most one terminal event per run, in emission order, and it never drops
   an event if the consumer is slow (bounded queue, ≥ 8 slots, with the drop counted and the
   *newest* kept never the oldest). *Negative:* `git diff main -- local_astra/contracts/` is empty.
9. **Module slice of B4, with its regime.** On the null-sink rig (§Regime), over n = 30 flush/pause
   points drawn with `seed=0`: `pause()` → silence p95 ≤ **50 ms**, `resume()` → first sample p95
   ≤ 50 ms, `flush()` return p95 ≤ 50 ms. This is the module's share of the 150 ms docs/02 §4
   allots to `playback.pause`, itself inside B4's 300 ms onset→paused (docs/03 §7 B4,
   `bench/thresholds.py`). The report quotes p50 and p95 with the whole regime line; a later
   regression > 10 % fails (CLAUDE.md). *Negative:* `bench/thresholds.py` is **not** edited — B4
   stays at 300 ms and remains T-0007's end-to-end number.
10. **Echo: the reference, the measurement, and what is deferred.** v1 ships **no AEC**
    (`Profile.aec == "none"`, docs/01 R4 headset-first, docs/06 R3). This task ships the two things
    the gate and any future AEC3 need and cannot get later for free: `playback_reference(window_ms)
    -> (samples f32 48 kHz, first_sample_device_ms)` returning the exact mixed output actually sent
    to the device from a ring of **≤ 2 s** whose memory does not grow over a 10-minute run, and
    `is_rendering(t_ms) -> bool`. The acoustic run reports the **speaker→mic echo path delay**
    (p50/p95, n ≥ 10) and the hangover T-0006b's gate will need (= p95 + one block). *Out of scope,
    named:* the capture gate itself, `livekit-rtc` APM, `module-echo-cancel`, ERLE and double-talk
    numbers (docs/03 B15).
11. **The rig cannot pass silently.** `scripts/audio_rig.sh` creates/destroys a null sink named
    `astra-test-sink` **without `pactl`** (absent on the box — use `pw-cli create-node` /
    `pw-loopback`, verify with `pw-dump`), and `scripts/audio_loopback.py` plays a lead-in
    calibration chirp and **exits non-zero with a named reason** if the recording does not contain
    it above an energy floor. Rig-dependent tests `pytest.fail`/error in that case — they never
    skip and never pass. *Why this is a criterion:* at planning time `wpctl status` showed the
    default sink is **"Dummy Output"**; without this check an echo test would "find no echo"
    through a dead speaker and report success.
12. **Negative — the module is the sole audio owner and nothing else moves.** (a) `capture()` still
    raises `NotImplementedError("T-0006b")` and no test asserts capture behaviour. (b) No file under
    `hud/` is created or modified (docs/02 ADR-013; T-0008 criterion 13 keeps testing the HUD side).
    (c) A repo scan asserts that within `local_astra/`, only `conductor/audio_device.py` imports
    `sounddevice`/`_sounddevice`/`ctypes`-loaded audio libraries or spawns `aplay`/`arecord`/`pw-*`.
    (d) The module imports no networking module and opens no socket (docs/02 §9 loopback-only).
    (e) `local_astra/contracts/**`, `local_astra/bench/thresholds.py`, `local_astra/telemetry/**`
    and `tests/` are untouched by the implementer; the fast suite is unchanged except for the new
    unit modules.
13. **The event loop is not the audio thread.** The device callback/writer runs off the asyncio
    loop and hands off through a lock-free/bounded queue; over a 10 s playback the measured
    event-loop lag stays ≤ 20 ms p99 (`.claude/rules/conductor.md`: "never block the event loop for
    more than 20 ms (there is a test)"), and no `asyncio` primitive is called from the device
    callback (source-scan test).

## Implementation notes
- **The one thing that matters:** `played_ms` comes from the device's rendered position
  (`sounddevice`'s callback `time_info.outputBufferDacTime` + `Stream.latency`, or libpipewire's
  `pw_stream_get_time_n()` — `queued`/`delay`), never from a count of what was written. Everything
  else in this task is plumbing around that one number.
- **Prerequisite P1 (sysadmin, not the implementer's):** `sounddevice` 0.5.6 is already in
  `uv.lock`, but the Linux wheel bundles no PortAudio and the box currently fails with
  `OSError: PortAudio library not found` — `sudo apt-get install -y libportaudio2` (or the
  implementer picks the libpipewire route and P1 is void). Unit tests must pass with **neither**
  installed; only the `audio`-marked tests may need it.
- **`pactl` is not on this box** (`pw-cli`, `pw-cat`, `pw-play`, `pw-record`, `pw-loopback`,
  `pw-link`, `wpctl`, `aplay`, `arecord`, `ffmpeg` are). The rig must not call `pactl`, and
  `scripts/bootstrap.sh`'s "no pactl" warning is not a blocker.
- **The default sink is "Dummy Output"** and the only capture source is the Logitech C925e webcam
  mic (`wpctl status`, planning time). The acoustic run must select a real sink explicitly and the
  rig must prove it is audible (criterion 11) before any echo number is believed.
- **PipeWire quantum:** the graph default is 1024/48000 ≈ 21 ms, not 10 ms. Request
  `PIPEWIRE_LATENCY=480/48000` (or the node property) *and report what you actually got* — another
  client can force the graph quantum, and a module that assumes 10 ms while the graph runs at 21 ms
  will mis-time every pause.
- **Pause must act on already-queued audio**, so keep the device queue shallow (2–3 blocks) and
  fade rather than hard-zero; a hard cut is an audible pop and a click is a real defect even though
  no one is in the room to hear it (criterion 3 makes it measurable on the monitor).
- `.claude/rules/conductor.md` is binding: audio I/O sits on a dedicated thread with a lock-free
  ring so event-loop pauses never drop frames; nothing in `conductor/` may block the loop > 20 ms.
- Landmine from the T-0003 history: a defect that all 73 tests passed was found only by mutation.
  Expect the reviewer to mutate `rendered_ms()` → write cursor and `mark_drain()` → "queue empty";
  if the suite stays green, the tests are wrong, not the mutation.
- `numpy` is a core dependency — the resampler needs no new package. 24 → 48 kHz is exactly 2×
  (zero-stuff + windowed-sinc FIR, or polyphase); carry the filter state across chunks.
- TTS output is 24 kHz mono **s16le** (`TTS_OUTPUT_FORMAT`); the device wants f32 at 48 kHz.
  Convert once, and duplicate mono to the device's channel count without touching the clock.
- Do not weaken a test to make a threshold fit. If the 50 ms slice in criterion 9 proves impossible
  on this hardware, that is a **spec change** (the §4 `playback.pause ≤ 150 ms` allocation), raised
  with the measurement and its regime — not an edited assertion.
