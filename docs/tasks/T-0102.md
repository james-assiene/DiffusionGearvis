# T-0102 — Refuse instead of repair: a native draft followed by more model text after its call (H-T101c)

## Goal

Today `live.classify` marks a draft "repairable" whenever its parse fails and it names a v1 tool. That includes a draft where the model closed the call's argument object and then kept writing prose, which usually means it took the call back. In the T-0101 run at df379e4 (kout-03, rep 2), pass 1 voiced "I will press Ctrl Shift T…" and wrote `call:press_key{combo:<|"|>Ctrl+T<|"|>} Wait, the tool press_key only takes … I cannot perform Ctrl+Shift+T … <channel|>I cannot perform that specific shortcut directly.` It ended with stop id 1. The draft was classed repairable ("no close"), the repair closed it as Ctrl+T, and Ctrl+T ran as a dry run.

After this task, a draft that is not valid and has more model text after its call is refused at detection. The session shows a refused card, sends no repair, executes nothing and voices nothing new. Unchanged:

- Clean cuts (the draft ends mid-call with nothing after it) stay repairable.
- Remainders that are only whitespace, newlines, channel markers or punctuation stay repairable.
- A second call after the first keeps today's verdict.
- Valid drafts, T-0100's refusals and their reasons, the eval, the turn machine, contracts, wire and HUD.

## Definitions (normative)

- **Where.** Only `live._judge(body)`, which `classify` and `repair_verdict` share, on the text after `<|tool_call>` with any trailing stop text dropped (as today). The rule applies only to a draft whose verdict would otherwise be repairable: not valid, names a v1 tool, and not refused by H-T99d/H-T99e. T-0100's rules take precedence and keep their reasons.
- **The call's end E.** Start just after `call:NAME{`, using the same head pattern as `native.draft_name`, at depth 1, and walk the body:
  - A closed `<|"|>…<|"|>` span is skipped as one value.
  - An unterminated `<|"|>` ends the walk with no E: a cut inside a string is clean.
  - `{` or `[` adds one to the depth; `}` or `]` subtracts one.
  - When depth reaches 0 at index k, set E = k+1. If the body continues (after optional whitespace) with `<tool_call|>`, E moves past that tag.
  - A `<tool_call|>` outside a string at depth ≥ 1 sets E just after the tag.
  - A `<|tool_call>` outside a string sets E at its own index.
  - Reaching the end of the body gives no E (a clean cut: "cut off mid-call, nothing after").
- **Remainder R = body[E:].** It is a **second call** if `R.lstrip()` starts with `<|tool_call>`; then the rule does not apply and today's verdict stands (Q2).
- **More model text.** R holds more model text iff, after every literal in `special_tokens.SPECIAL_TOKENS` is replaced by a space, at least one character has `str.isalnum()` true.
  - Whitespace, newlines, `<channel|>`/`<|channel>`, `<turn|>`, stray `}`, `]` or `.` are benign.
  - Prose always has letters.
- **Stop id is not used.** Commit.stop_id (T-0088) is not an input; `classify(tool_text)` keeps its one-argument signature (Q3). Evidence: the retraction had stop id 1, and clean closed calls also end on stop id 1 (21 of them).
- **Verdict.**
  - Shape: `Verdict("refused", name, arguments_or_None, REASON, query_problem)`.
  - Name kept. Arguments are `None` when the draft does not parse; a draft whose call closed but fails only on text after it carries `arguments=None` too (parse failed).
  - REASON is one new exported module constant with the pinned value **`"model text after call"`**. The name is the implementer's choice; it goes in `live.__all__`.
- **Reasons, mapped to positions.** Whether a draft is refused depends on its positions, not on the parser's reason string:
  - "no close" with a closed object followed by prose → refused (the df379e4 shape).
  - "no close" where the brace never closes (`{x:488,y:5`) → stays repairable.
  - "text after call" with prose → refused. With only markers or punctuation → stays repairable.
  - "unterminated string" is refused when the object closed before the stray delimiter (`} Wait "<|"|>…`); a cut inside a string stays repairable.
  - "malformed arguments" is refused when the object closed and prose follows before a later `<tool_call|>`; stays repairable for typos (`}}<tool_call|>`, `{x:1,,y:2}`).
  - "multiple calls" stays repairable (Q2).
