## Goal
On this stack (vLLM + NVFP4), measure what per-step Mar costs (a), which Mar values the dev cuts choose (b), and whether
per-step Mar changes accuracy against the end-projection control and the unconstrained model — and why Sudoku collapsed
in the JAX port (c). Every baseline is re-measured; the JAX numbers appear only as a labelled reference. Each sub-task
pre-registers its thresholds and coded stops; the test cuts are touched exactly once, by c.

## Acceptance criteria
**T-0071a — cost (tier-2 `/launch` a1, engine `/launch` a2)**
1. **Sync rows (a1, before B13).** Over the image's compiled sampler, after ≥ 12 warm-up calls, ≥ 50 calls under
   `set_sync_debug_mode("error")` with one constrained slot, once per arm (`perstep_mf`, `perstep_mar`, `perstep_mar` +
   SC), commits and a release included, at buckets 64 and 128. Pass = 0 raises. A raise is a defect in `cd/**`: its fix
   is its own task and a2 does not run until it lands (T-0069 O5 pattern).
2. **Microbench (a1, container, no engine; `scripts/gpu/cd_microbench.py`).** Per-step cost split into emission, both
   marginal passes (decision 10), draw, H(q), MAP and the SC matmul; CL 256, V 262 144, fp32, buckets 64/128/256/512, real
   T-0063 automata, reusing T-0072's probe for `class_max`/MAP/δ\*. Median and p95 over 200 steps after 20 warm-up (CUDA
   events), plus peak added memory per arm (SC at 512). Reported, not gated.
3. **B13 (a2, the gate; T-0062 decision 8).** `perstep_mar` per-step overhead against unconstrained ≤ 10 % at bucket 64 (a
   Sudoku dev prompt) and ≤ 15 % at bucket ≤ 128 (a BFCL dev prompt of bucket 128).
   - 30 rounds per stratum, paired by round index, arm order rotated per round over A, B, A′ (T-0011 R17). A and A′ send
     `vllm_xargs={"astra_tap": true}`; B sends the same plus the `astra_cd_*` keys. A fourth arm D (no xargs) is reported,
     not gated. The verdict comes from `b13_cd.evaluate` (E10).
   - **Step time** = (wall − F̂)/Σsteps. Σsteps from the request's tap commit frames (cross-checked against the CD records
     for B); F̂ = the fixed per-request cost, least-squares fit of wall on steps over every A and A′ request of the run.
     The verdict is computed at F̂ and at F̂ = 0; if they disagree, the result is `not_resolvable`.
   - Before the gate is read, the report states the metric's exposure to xargs with evidence (D vs A per-step, against
     the control).
4. **Report-only strata (a2):** per-step `perstep_mar` and `end_projection` at buckets 256 and 512, n = 5 rounds each.
5. **Runner on the engine (a2, dev only).** T-0070's `runner.run --limit 10` on every arm and both tasks (Mar with stock
   knobs through `mar_knobs`, labelled). Exit 0, zero `join_error`, records joined by `record_tag`. A stop is triaged
   before b.
6. **Thresholds.** `local_astra/bench/thresholds.py` gains `Threshold("B13", "cd_step_overhead_pct_b64", 10.0, "%")` and
   `Threshold("B13", "cd_step_overhead_pct_b128", 15.0, "%")`, whatever the verdict; the verdict is recorded beside them
   here. *Negative:* no pre-existing row changes. On FAIL the limit is never raised (D-H1).

## Implementation notes
- **Tap slow joiner (T-0069 O7):** any driver that reads tap frames sends one unconstrained warm-up request and waits,
  bounded, for its frames before any measured request; none → refuse with exit 2; the warm-up is excluded from every row.
- **Locked-script pattern** (`t0011_tier3.sh`, `t0069_cd_smoke.sh`): refusals (dirty tree, bound 8001/8002/8080/8081,
  running containers, `services/vllm.sh` diff from 806da12); `make plugin-wheel`; engine-only `services/vllm.sh`; wait for
  `/health`; `last_boot` slicing; report before the exit code; the `/launch` command echoes the exit code; engine stopped on
  exit; node ids instead of `--deselect` (refused by `guard_bash`).
- **Memory.** perstep_mar+SC added 1.57 GiB at bucket 256 (CD tier 2); T-0069 had 4.7 GiB free after boot and 3.7 GiB at
  the end. All runs serial (concurrency 1). If a1's SC peak at 512 exceeds free-after-boot − 1 GiB, flag it at H1.
- **Bucket histogram first:** b and c print each cut's bucket histogram on the CPU before the first request; the launch
  reviewer re-derives the budget from it.
- **Pre-registered interpretation** (not acceptance): "per-step Mar is worth pursuing" if BFCL exact call ≥ unconstrained
  − 0.02 and Sudoku solved is not significantly below `end_projection`; "SC helps" only if Mar+SC vs Mar is significant
  after Bonferroni; otherwise report parity or a loss plainly.
- **Hard stops.** H1 (after a): the human reads B13 (D-H1 already chooses "continue"). H2 (after b): the human approves
  both frozen files before c. H3 (after c): the human reviews §9 before any merge; any test-cut re-run is the human's call.
- **Open risks for §9:** MAP-vs-draw cost; SC off-distribution; NVFP4 vs bf16; thinking-off header vs the thinking-on
  product; early stopping vs JAX's 48 fixed steps; the unseeded sampler (A/A′ is the only noise floor); 130 of 258
  live_simple records are a prefix, not a random sample; the stop id is included in constrained `token_ids` (T-0069 c9).
- **Carried from earlier reviews:** T-0068 launch counts (`perstep_mar` ≈ 5 650 per slot per call vs stock 166); T-0070's
  AR(1) warning (addressed by rotation and A/A′); decision 10 (both passes on); decision 11 (JSON whitespace; pretty only
  on the parity arm). From T-0011 R17: `vllm_xargs` alone costs ≈ 4 % end to end, so B13's gated arms send identical xargs.
- **Evidence behind the B13 expectation** (n = 1, not measurements; T-0069 788e1df and the f5381ac probe): stock ≈ 18.5 ms
  per step + ≈ 47 ms fixed per request; Sudoku `perstep_mar` at bucket 64 ≈ 72 ms per step; `constrained_map` alone 7.15 ms
