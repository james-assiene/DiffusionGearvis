## Goal

Today the three verbs that stand between a clean checkout and a live turn are all lying. `astra up`
cannot start anything — `cli.run_service` is a blocking `subprocess.run` and every `services/*.sh`
ends in `exec` on a foreground server (`vllm.sh:76` is `docker run --rm` with no `-d`, `stt.sh:52`,
`tts.sh:5`), so `up()` blocks on the first script forever and Ctrl-C kills the engine it just
started; the fast suite never saw this because the injected `Runner` in `tests/unit/test_cli_up.py`
returns instantly. The health probes are bare TCP connects, which answer "healthy" all through
vLLM's 68 s init and, worse, after a model failure. Nothing serves the HUD page: `hud/README.md`
tells the human to run a second `python3 -m http.server`, `config.Services.hud_port = 1420` exists
and is read by nobody, and `astra session` prints "open the HUD page" without saying how.
`scripts/bootstrap.sh` reports "ready" on a box where `astra session` exits 1, because it checks for
`pactl` (absent here) and never tries `import sounddevice`. After this task there is one read-only
command, `astra doctor`, that prints PASS/WARN/FAIL per line with the fix and exits non-zero if
anything is FAIL; `astra up` starts each service detached with a log and a pid file and then proves
it with the service's real health endpoint; `astra down`/`astra status` are real; and one command
gives the human a page URL. The point is that the first live run is a run, not a back-and-forth.

### Group A — `astra doctor`

1. **The verdicts are a pure function of a box description.** `preflight.evaluate(facts) ->
   tuple[Check, ...]` where `Check` carries `name`, `status ∈ {PASS, WARN, FAIL}`, `detail` (the
   fact that decided it) and `fix` (the command or edit that would make it PASS). No I/O, no
   clock, no subprocess in that function; collectors are injected and each returns a field of
   `facts`. A test builds a `Facts` describing this box on 2026-09-14 and asserts the exact
   multiset of statuses. *Negative:* `evaluate` called twice on the same `facts` returns the same
   tuple in the same order; it never shells out (asserted by monkeypatching `subprocess.run` and
   `socket.socket` to raise).
2. **Audio is checked the way `astra session` fails.** Three lines: `import sounddevice` succeeds
   and `query_devices()` returns (FAIL with `apt install libportaudio2` as the fix otherwise —
   this is P0-3, the exact gap between "bootstrap says ready" and `astra session` exiting 1); the
   default sink is not a dummy (`Dummy Output` → FAIL, naming it); at least one capture source
   exists (none → FAIL). *Negative:* the check **opens no stream** and plays and records nothing —
   a test asserts `sounddevice.InputStream`/`OutputStream` are never constructed.
3. **Health is the service's own endpoint, not a TCP connect.** vLLM: `GET {services.vllm}/health`
   → 200. Pocket TTS: `GET {services.tts}/health` → a body containing `healthy`. moshi has no
   health route, so: `GET` the http form of `services.stt` with `auth_id=public_token` → **4xx
   proves the route is mounted** (a 404 means a live process with no ASR route — the silent
   failure this check exists for — and is FAIL). *Adversarial, and the reason for the criterion
   (P1-6):* against a stub that accepts the connection and answers 503 on `/health`, and a second
   stub that answers 200 on `/` and 404 on the STT path, today's `probe_endpoint` returns healthy
   and the new probe must return FAIL naming the status. *Negative:* every probed URL passes
   `config.LOOPBACK_PREFIXES`; no probe carries a request body and none touches
   `/v1/chat/completions`, `/v1/completions`, `/v1/embeddings` or `/v1/responses` (a static test
   over the module's source), so `astra doctor` spends no GPU time and needs no `/launch` token
   (`.claude/rules/gpu-services.md`: status polls are free). Written as a contract test
   parametrised `backend=["fake", "real"]` per `.claude/rules/tests.md`; `real` is marked `gpu`.
4. **The served model is the pinned model.** `GET {services.vllm}/models` → the served id is
   compared to `services/versions.lock`'s `model`; the HF cache snapshot ref for that repo is
   compared to `model_revision`. A mismatch is FAIL naming both sides. A lock value of `"TBD"`
   (today: `pocket_tts`, `chat_template_revision`) is **WARN** naming the line and the command
   that produces the value — not FAIL: an unpinned line does not stop a run, it stops a *number*
   from being comparable.
5. **Container argv is read, never assumed.** From `docker inspect` of the running containers:
   whether the STT server was started with `--cpu`, and the vLLM argv compared to the flags in
   `services/vllm.sh`. An STT device that disagrees with the profile's `stt_backend`
   (`kyutai-gpu` vs a `--cpu` container — the live P0-2 state) is **WARN** whose detail carries
   the measured cost (step time 100–108 ms per 80 ms of audio, RTF ≈ 1.3) and points at the human
   queue entry; a missing `--revision` on the vLLM argv is WARN with the carve-out named.
   *Negative:* the environment variable `ASTRA_STT_CPU` is **not** consulted anywhere in
   `local_astra/` (criterion 20 pins this statically) — the container's argv is the fact, the env
   var is what somebody meant to type.
6. **VRAM against the floor.** Free VRAM from `nvidia-smi` vs the ≥ 3 GiB sampler-transient floor
   (docs/02 §7, `.claude/rules/gpu-services.md`). Below the floor is FAIL; the detail states
   used/total. On a box with no `nvidia-smi` the line is WARN ("laptop"), never a crash.
7. **Loopback only.** Every listening socket belonging to the astra services is on `127.0.0.1`;
   a listener on `0.0.0.0` or `[::]` is FAIL (docs/02 §9, docs/03 E8, CLAUDE.md). *Negative
   criterion:* `astra doctor` itself opens no listening socket and makes no connection to anything
   that is not loopback.
8. **Toolchain and tree.** `uv`, `git`, `node`, a chromium/chrome binary present (missing chrome is
   FAIL — there is no live run without a page); a dirty git tree is WARN naming the paths (a
   service started against a tree an agent is editing makes every later number unattributable —
   the same reason `guard_bash.sh` refuses).
9. **The exit code means something, and there is a machine-readable form.** One line per check,
   `PASS`/`WARN`/`FAIL`, the detail, and the fix. Exit **non-zero iff at least one FAIL**; WARNs
   keep exit 0 and are still printed. `astra doctor --json` prints one JSON object per check
   (stable keys) and nothing else on stdout. *Negative:* `astra doctor` starts no service, writes
   nothing anywhere on disk (a test runs it with `tmp_path` as cwd and asserts the tree is
   unchanged), and never mutates `versions.lock` or any `services/*.sh`.

### Group B — `astra up`, `astra down`, `astra status`

10. **`up` does not block on a foreground server.** Each entry of `start_plan` is spawned
    **detached** and `up` proceeds to the next without waiting for it to exit. *Adversarial, and
    the single most likely regression (this is P0-1):* the injected runner spawns a real 30 s
    sleeper; `up`, with a probe that reports healthy, returns within 1 s (regime below). The
    current implementation fails this in ~30 s; assert the *wall time*, not just the return.
    *Negative:* the spawned children are not in the CLI's process group in a way that makes
    Ctrl-C on `astra up` kill the engine — a test asserts `start_new_session`/`setsid` semantics
    on the handle, and that `up` returning does not terminate the child.
11. **Every start leaves evidence.** Per service: stdout+stderr to `logs/<service>.log` (already
    gitignored) and a pid file under the **git common dir** (`git rev-parse --git-common-dir` →
    `<common-dir>/local_astra/run/<service>.pid`, so worktrees share one state directory), written
    only after the spawn succeeds and containing the pid plus the argv that produced it.
    *Negative:* nothing is written under `artifacts/`.
12. **The probe loop uses criterion 3's endpoints with per-service timeouts.** vLLM gets a long
    budget (its init is ~68 s), the speech services a short one; the per-service budget is
    printed, and a timeout says which service, which endpoint, how long it waited and what the
    last response was. Exit non-zero if any service is unhealthy at the deadline.
13. **`down` stops exactly what `up` started, and nothing else.** For each pid file: terminate the
    recorded process (which stops the container it fronts), then remove the file; containers
    started by name are stopped by name. `down` twice in a row is a no-op that exits 0.
    *Adversarial, the nastiest failure mode:* a **stale** pid file whose pid no longer exists, and
    one whose pid has been **reused by an unrelated process** (the recorded argv does not match
    `/proc/<pid>/cmdline`) — in both cases `down` kills nothing, says so, and removes the file.
    A test that asserted only "the file is gone" would pass a `down` that killed the wrong
    process; assert the victim process is still alive.
14. **`status` prints the same probe table and starts nothing.** Same rows and same wording as
    `up`'s final report (shared code path, pinned by a test comparing the two outputs), plus each
    pid file's liveness. Exit non-zero if any service of the profile is not healthy.
15. **Regression fence.** `--dry-run` still prints the exact ordered plan and runs nothing; `up`
    never downloads a model (`fetch-models` is the only network egress, docs/02 §9); no probe
    targets a non-loopback URL; `astra config` and `astra session` behave exactly as they do today
    (T-0028 criteria 15, 16, 18 re-asserted). *Spec change, recorded here rather than worked
    around:* T-0028 criterion 17's seam `Runner = Callable[[Sequence[str]], int]` cannot express
    "started and still running" and is **superseded** by criterion 10's handle-returning seam.
    `tests/unit/test_cli_up.py` is therefore rewritten by the **test-author** under this task,
    preserving its order, `--dry-run`, loopback and no-download assertions verbatim. The
    implementer does not touch `tests/`.

### Group C — serving the page

16. **`astra hud` serves `hud/` on loopback and prints the exact URL.** Binds
    `127.0.0.1:{services.hud_port}` (1420 — the field that exists and is read by nobody today)
    with a stdlib static server, and prints the URL **including the query string** the page needs:
    `http://127.0.0.1:1420/?ws=ws://127.0.0.1:{services.conductor_port}/v1/realtime`, plus the
    `?source=canvas` variant for headless runs.
17. **`astra session --serve-hud` is the one command.** The same static server runs on a thread
    beside the session; the printed line is the same URL; Ctrl-C stops both and still satisfies
    T-0028 criterion 16 (no `turns.jsonl` line at shutdown).
18. **The static server is not a hole.** *Negative and adversarial:* `GET /../../local_astra/config.py`
    and a percent-encoded equivalent return 404 and read nothing outside `hud/`; a request from a
    non-loopback peer is impossible by binding, and `getsockname()` is `127.0.0.1`, never
    `0.0.0.0`; `POST`/`PUT` are refused; if the port is taken the command exits non-zero naming
    the port and **never falls back to another one** (a page on a port nobody chose is a page
    talking to nothing — T-0028 criterion 19's rule, applied to the second listener).

## Implementation notes

- The doctor's shape is *collect → describe → evaluate → render*. Everything interesting lives in
  `evaluate`, which must never touch the box; the collectors are thin and each is allowed to fail
  into a "not gathered" field (criterion 1's adversarial test is aimed exactly there).
- Severity discipline: **FAIL = the first live run cannot succeed. WARN = a fact that should be
  pinned but does not block.** The pocket-tts/chat-template TBDs and the CPU-STT mismatch are
  WARNs on purpose — they are the human's open decisions, not the doctor's.
- The guard (`.claude/hooks/guard_bash.sh:314`) treats `astra up` as a *routine service start*:
  clean tree, no token, no Runs entry (T-0016 I12 / the human's D2). Nothing in this task may make
  `astra up` match the *engine start* or *measurement* patterns, and nothing may make
  `astra doctor` match any of them. Do not touch the hook; if a new allowance seems necessary,
  that is a separate high-blast-radius task.
- `docker run` in the foreground proxies signals to the container (`--sig-proxy` defaults on), so
  terminating the child that `up` spawned stops vLLM even without `--name`. Do not add a
  `docker kill` by image name — that would stop containers this CLI did not start.
- The pid-file directory comes from `git rev-parse --git-common-dir` so `.claude/worktrees/` share
  one state dir; create it lazily and never inside `artifacts/`.
- `config.Services.stt` is a `ws://…/api/asr-streaming` URL. Deriving the http form for the probe
  must keep the loopback validation — build the probe URL from the parsed `Services` value, never
  from a string typed in the module.
- mypy `--strict` on `local_astra/`, Pydantic v2 only for wire contracts: `Facts`/`Check` are
  frozen dataclasses, not `contracts/` models. No new dependency — `http.server`, `urllib`,
  `subprocess`, `socket` and the already-present `sounddevice` are enough.
- CLAUDE.md's "never quote a number without its regime" applies to the doctor's own output: the
  STT RTF line must carry its regime text, not just "1.3".
- Landmines from `.claude/rules/`: no `pip install` outside `uv`, no system CUDA changes, never
  `sudo` (the doctor prints `apt install libportaudio2` as a *fix line for the human*, it never
  runs it); `scripts/gpu/` is the GPU-spending directory and nothing here belongs in it.

## Regime

Only two criteria are measured; neither is a latency number and neither is comparable across
boxes — state that in any report.

- **Criterion 10 (liveness bound).** Fast suite, no GPU, no network. Sleeper: `sleep 30` spawned by
  the injected runner. Threshold: `up` returns in **< 1.0 s** wall (`time.monotonic`), n = 5
  repeats in one test, no seed (no randomness). Profile `lean`, `astra.toml` defaults, probe
  stubbed healthy. Rationale: the failure it excludes takes 30 s, so the bound is three orders of
  magnitude away from the boundary and is not a performance claim.
- **Criterion 9 (doctor wall time).** With all collectors stubbed, `astra doctor` completes in
  < 5 s, n = 3, no seed. Against a real box the figure is not asserted anywhere.
- Versions for any box run: `services/versions.lock` as committed at the run's SHA; the Runs entry
  states profile, STT device from the container argv, served model id, VRAM used/total, n and
  `seed=null` (seed is a hard 400 on the diffusion path).

## Rulings

- **A1 (criterion 10, test shape).** With an injected runner the liveness row XPASSed (the blocking lives in the default `run_service`), so
  the test runs the real verb with the default runner in a child process (start plan patched to three `exec sleep 30` scripts, run/log dirs
  redirected) under a 5 s timeout, asserting child-measured wall < 1.0 s, n = 5, all children alive and reaped. Accepted: the test targets the
