## Goal

In the T-0125 search GPU smoke (phase 2, live headless, `--no-web`, search on), the first image-bearing generate of the session (`logs/t0125-search-smoke-b372eda/phase2/sessions/20261027-112530-1065632.jsonl` seq 14, attempt `7c4a47eefb16-t1-gen-2`) ended at seq 545 with `LlmWireError('… the stream ended without a finish_reason')`: zero commits, zero canvases, and the user got nothing. At the same second vLLM logged its only "Multi-modal cache miss … P0/P1 cache drift; returning a retryable response" (`logs/vllm.log:59326`). Probable trigger: the anticipatory prefill (seq 9), aborted at seq 11, about 100 ms before the generate with the same image hash.

In vLLM v0.29.0 (checked in the pinned image) the engine answers a drift miss with `finish_reason=ERROR` and no tokens (`v1/engine/core.py:1767-1771`, `_handle_mm_cache_miss` 1866-1898). The frontend removes the hash from its own cache (`async_llm.py:786-794`), so the next identical request carries the image data again. But the chat streaming server skips zero-token outputs before its error check (`entrypoints/openai/chat_completion/serving.py:644-650`, before line 752). On the wire this is HTTP 200, a role chunk, then `data: [DONE]`, with no `finish_reason` and no error event.

After this task:
- `VllmClient` recognises exactly that signature in id mode and raises a distinct subclass of `LlmWireError`;
- the session I/O layer resends the same request once, under a fresh attempt id, and logs the retry (step-1 generate and tool-loop steps);
- any other truncated stream stays the error it is today (review B: the same wire comes from any zero-token engine finish in v0.29.0 — the drift-miss ERROR, a preprocessing ERROR, an engine-side ABORT — and the client cannot tell them apart, so each gets the one resend; the drift miss is why the retry exists);
- the turn machine is unchanged.

## Acceptance criteria

1. **Signature recognised (client, tools on).** For a tools-on prompt (id mode), a 200 stream that is the role chunk then `data: [DONE]`, not aborted, makes `generate` raise `LlmEngineEmpty`, a new public subclass of `LlmWireError` in `llm_client.py`, with zero commits. The message contains the attempt id and the word `retryable`. A stream that is only `data: [DONE]` (no role chunk) raises the same.
2. **Negative: a truncation after ids is not this.** A stream with at least one chunk carrying `token_ids`, then `[DONE]`, no `finish_reason`, raises plain `LlmWireError` (`type(exc) is LlmWireError`) with today's message. So does a stream whose connection ends with no `[DONE]`, including one with zero chunks.
3. **Negative: an in-stream error event is not this.** A stream carrying a `{"error": {...}}` payload before `[DONE]` does not raise `LlmEngineEmpty`.
4. **Negative: normal streams unchanged.** Every existing id-mode and tools-off client test passes unedited (`test_llm_id_mode.py`, `test_llm_client_segments.py`, `test_llm_fence_carry.py`, `test_session_tool_wire.py`, `test_vllm_sse_live_shape.py`, `test_llm_client_visual_tokens.py`). A tools-off stream never raises `LlmEngineEmpty`.
5. **Step-1 retry (session).** When the turn's step-1 generate raises `LlmEngineEmpty` with no commit delivered, the session:
   - releases the failed attempt id and issues a fresh one (as the T-0020 over-long retry does);
   - logs a `note` with `what: "the engine returned an empty retryable response; retrying once"`, `request_id`, `failed_attempt_id`, `attempt_id`, `phase: "generate"`;
   - logs a new `llm.request` record before the resend;
   - resends the same `Prompt` (same messages, same `ImagePart` data and phash, same options; the body equals the first except for the attempt id).

   The turn completes from the retry's commits; no `error` record and no `LlmError` come from the first attempt; the turn line's extras carry `llm_empty_retries: 1` (absent when there is no retry).
6. **Tool-loop step retry.** Criterion 5 holds for `_run_step` (`phase: "tool_step"`, `step` in the note).
7. **Exactly once.** If the retry also raises `LlmEngineEmpty`, the turn ends through today's path (an `error` record, then `LlmError` to the machine). Exactly 2 requests are sent.
8. **Never after voiced or committed text (negative).** If any commit of the attempt was delivered before `LlmEngineEmpty` (adversarial fake), there is no retry and the error path runs. A plain `LlmWireError` after commits is never retried.
9. **Abort wins.** An abort or barge-in between the failure and the resend means no resend; an abort during the retry closes it, and no third request follows.
10. **One live generate at a time (docs/02 §4).** The retry is sent only after the failed attempt is released, never concurrently.
11. **Denoising view stays real.** The failed attempt produces no `astra.canvas.step`, `astra.canvas.commit` or `astra.canvas.synthetic`; the retry introduces no `astra.canvas.synthetic`; every canvas message of the turn carries the retry's attempt id.
12. **Turn machine pure and untouched.** `turn_machine.py` and `local_astra/contracts/**` unchanged across the branch; no new event type.
13. **Out of scope stays as-is (negative).** The `tool_repair` path, ReGround pass 2, prefill, captioner and warm-up treat `LlmEngineEmpty` exactly as `LlmWireError` today. The over-long (413/400) retry and the degeneracy guard behave as before; the two retries are independent (at most one of each per request).
14. `uv run ruff check . && uv run ruff format --check . && uv run mypy local_astra` clean; fast suite green.

## Implementation notes

- **Recognition rule (id mode only):** at the end of `generate`, not aborted, `[DONE]` seen, `reader.finished` false, and no chunk carried a `token_ids` key → `LlmEngineEmpty`; otherwise as today. Track whether `[DONE]` was seen. Do not loosen T-0088 criterion 5 for any other case.
- **Retry placement:** next to the T-0020 over-long retry (`_run_generate`), with its `_ids.release` then `_ids.issue` pattern; `_run_step` likewise. Keep the guard on `count.delivered == 0`.
- **The resend:** the identical `Prompt` (the client always sends full image bytes; vLLM already dropped the drifted hash). Do not rebuild the prompt with a new frame. No delays or backoff.
- **Pure turn machine:** no Tick-driven retry, no new event.
- **Denoising view:** do not synthesise or replay canvases for the failed attempt.
- **Logging:** ids and phase only in the note, no prompt text.
- `.claude/rules/tests.md`: avoid "3/4"-style text in `session.py` docstrings (`test_prompt_budget.py`). Fakes change in the same PR as the client behaviour they model.
- **Follow-ups (not in scope):** tools-off recognition; the unexplained 13.5 s between the generate and the miss; not aborting an image-bearing prefill (a turn-machine change, only if drift is frequent); GPU repro H-T171-1 (abort an image prefill ~100 ms before a same-image generate, n=20, count drift warnings and retries).
