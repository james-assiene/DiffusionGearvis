## Goal

Four rows guard the same property: linear work with no quadratic blow-up, and for bracket repair no recursion. They are the bracket-repair row `test_linear_time_and_no_recursion[*]` (T-0108 criterion 5) and three id-mode rows in `test_llm_id_mode.py` (T-0088 criterion 9, rulings E11 and E15):
- `test_host_work_in_id_mode_is_linear_4096_one_id_chunks_under_50_ms`
- `..._alternating_lt_and_pad_4096_one_id_chunks_e11`
- `..._marker_prefix_is_followed_by_a_long_run_of_pads_e15`

Today all four measure `perf_counter` wall time (median of 5), either as an absolute bound or as a ratio. After this task each row measures two things:
- **(W) work, deterministically:** the number of traced Python line events in the code under test, compared at two sizes.
- **(C) CPU time:** `time.thread_time`, gc disabled, sizes interleaved, minimum of k runs. This catches C-level blow-ups that W cannot see. Ratios are taken against sizes of the same run or against a raw-reader baseline from the same run.

Under synthetic load at 30–55, the rows stay green. They still go red on every mutant the current rows catch, and on two recursion mutants the current row misses. The spec text of T-0108 criterion 5 and T-0088 criterion 9 / E11 / E15 is amended to say what is now measured. No bar is loosened in a way that lets a previously caught mutant through.

## Implementation notes

- **Rules this must respect** (`.claude/rules/tests.md`):
  - No re-implementing the function under test.
  - No discovering private names: the tracer is name-agnostic and counts by file path.
  - No bars taken from current output. Ratio bars come from the linear/quadratic prediction; the one absolute bar is T-0108's 10 ms; the raw-reader multiple translates T-0088's 50 ms.
  - Mutation copies must be shown to be imported.
- **Sizes and bars per measure:**
  - W is exact, so its bar can be tight. 2.25 still admits n log n (about 2.17 at 4096).
  - C bars sit at the geometric middle of linear and quadratic for a 4× step.
- **C measurement recipe:**
  - `gc.collect(); gc.disable()` in `try/finally`.
  - `time.thread_time` (per-thread CPU), not `process_time`: asyncio and httpx run in this thread, and other threads must not count.
  - Interleave sizes, or raw and client, within each repetition, and take minima.
  - A first id-mode campaign with gc on and min-of-5 showed a host/raw outlier of 5.53 under load. That is why gc is off and k = 7 for id mode.
- **The tracer:**
  - Python 3.11 is pinned, so there is no `sys.monitoring`; `settrace` costs about 0.1 s for 0.5 M events.
  - The root comes from `module.__file__` at runtime, never a literal path, so a mutation copy counts its own files.
  - It must not run inside Hypothesis-decorated tests.
- **Keep the order:** the expected-answer premise of each id-mode row runs before any measurement, so a fast but wrong client cannot pass.
- **Spec amendments** (orchestrator):
  - T-0108 c5 bullet 2 becomes: "work: traced line events L(2n)/L(n) ≤ 2.25 for n ∈ {1024, 2048}; CPU (thread_time, gc off, min of 5, interleaved): ≤ 10 ms at 8192, and t(16384)/t(4096) ≤ 8". Add the two new families to bullet 1.
  - T-0088 c9 gated row, E11 and E15: "under 50 ms (median of 5)" becomes criteria 4 and 5 above, with this task id as the reason.
- **Instruction counting is unavailable:** `perf_event_paranoid` is 4 on this box, and changing it is a system setting.
