## Goal

`astra session --tools live`, or `tools = "live"` in the profile, runs the T-0111c `BrowserToolExecutor` inside the session.

What the session does in `live`:
- **The browser.** It starts before the first turn, headed at the desk (H-T111c-1), on a small loopback start page served by Astra (H-T111c-4).
- **Frames.** Each turn's image is the agent browser's own viewport frame. HUD frames are received but never attached (H-T111c-5).
- **After every step,** the next loop request shows the screen as it is now. The newest image of the step-1 prompt is swapped for the post-action frame, and every call is resolved against the frame the model was actually shown.
- **Failures** settle as `failed`, not `refused`. After a `failed` or `timeout` step, the screen is re-captured.
- **Closing the window** ends computer use for the rest of the session, and the session says so.
- **Egress** is limited to the start-page server's own loopback origin (H-T111c-E). Real websites are the next task.

The task also ships:
- three demo pages the human can try at the desk;
- a CPU end-to-end row: the fake LLM drives the real headless browser through 2–3 steps;
- a locked GPU smoke script with report-only metrics, run by the orchestrator via `/launch` before the human's desk session ("test before the desk").

`off` and `dry_run` stay byte-identical to BASE.

**Why the image is swapped, not appended.** T-0115a Q5 sent an image part after text in a continued assistant message, and 3/3 were rejected with HTTP 500 (`docs/cd/toolcall-loop-probe.md:615`). Replacing the newest image of the user turn in place keeps the ordinary user-turn shape, and it follows the "last snapshot wins" rule (`session.py:2025-2049`, docstring at 2040). The cost is a prefix-cache miss from that image onward, which the smoke measures, report-only.

## Acceptance criteria

**Definitions.**
- **Own frame:** a `Frame` returned by the executor, either from `frame()` or as the post-action capture exposed as `latest_frame`.
- **Capture identity:** the session's key for one captured frame. Two frames with identical JPEG bytes share one identity. Two frames with different bytes always have different identities, whatever their phash (T-0111c note (a)).
- **Live browser seam:** the object the kit carries in `live`. It has the executor's public surface (`frame()`, `latest_frame`, `open(url)`, `egress_log`, `close()`, `execute(inv)`), plus the `closed` state of A2.
- **Start pages:** the files served by `local_astra/pages/`:
  - `/`, the start page;
  - `/search.html`, results over a fixed local catalogue;
  - `/demo/shop.html`, `/demo/contact.html` and `/demo/deals.html`.

### Group A — executor options and the start pages (`local_astra/computer/**`, `local_astra/pages/**`)

**A1. Headed or headless.** `BrowserToolExecutor(..., headless: bool = True)` passes `headless` to `PlaywrightDriver`.
- The default stays headless, so every T-0111c row and `make browser` stay green unchanged.
- Unit row (fake seam): the driver is constructed with the given value.

**A2. Closing ends it.** With `end_when_closed=True` (the default is `False`), the browser ends for good when either of these happens:
- the last page is closed by anything other than the executor itself;
- the browser disconnects.

After it ends:
- `closed` is `True`;
- `ensure()` neither relaunches nor opens a page, so no new Chromium process exists (the pid set is unchanged);
- every non-search `execute` is `refused` with `the browser window was closed`, and nothing is dispatched;
- `frame()` raises a named exception;
- `google_search` still answers as the dry run.

With the default `False`, T-0111c's relaunch-once behaviour (criterion 10) is unchanged. A popup closing itself while other pages remain is not an end, so the T-0111c S9 row stays green.

e2e: tested headless, once by closing every page through the Playwright API and once by killing the browser.

**A3. Origin allow-list.** `BrowserToolExecutor(..., allowed_origins: frozenset[str] | None = None)`.
- `None` keeps T-0111c's rule: any `fence.is_loopback_url`.
- A set limits navigations, sub-resources, fetch, WebSocket and redirects to exactly those `scheme://host:port` origins. Everything else is blocked and logged as `{host, scheme}` only.
- e2e, with the allow-list set to the start-page server's origin:
  - a page's `img`, `fetch`, `sendBeacon`, `iframe`, `WebSocket` and top-level navigation to `127.0.0.1` on ports 8000, 8001, 8080, 8081, 1420 and one free port all fail, and each is logged;
  - a canary listener on a free loopback port receives zero connections;
  - the start-page origin loads.

**A4. Start-page server.** `local_astra/pages/` serves its `static/` tree with the stdlib (`ThreadingHTTPServer`).
- It binds `127.0.0.1` only, on an ephemeral port, and exposes its origin.
- It serves GET and HEAD of files under `static/` only:
  - a path traversal (`/../`, `%2e%2e`, an absolute path, a symlink out) gives 404;
  - there is no directory listing;
  - any other method gives 405.
- It writes no file and logs no query string.
- It stops cleanly and leaves nothing bound.

**A5. Start and demo pages** (H-T111c-4). The pages are self-contained HTML, CSS and JS:
- no external URL, protocol-relative URL, web font or remote image. A static scan checks that every `src`/`href`/`url(`/`fetch(` target is relative or same-origin;
- deterministic at 1280×800;
- each page exposes `window.__state` for tests and the smoke.

The pages:
- `/`: a blank page with one centred search box. Submitting it opens `/search.html?q=…`, which lists matching catalogue entries, each linking to a demo page.
- `/demo/shop.html`: three mugs (red, blue, green), each with "Add to cart", and a visible cart count. `__state.cart` is the list of item names.
- `/demo/contact.html`: name, email and message fields, and Send. Sending shows "Thanks, <name>" with no network, and `__state.sent` holds the submitted values.
- `/demo/deals.html`: eight priced items over two viewports, the cheapest below the fold, each with "Add to cart" and the same `__state.cart` as the shop.

**A6. Import hygiene holds.**
- `local_astra/computer/**` still imports no socket client; `test_computer_imports.py` is unchanged and green.
- Only `runtime.py` imports `playwright`.
- `local_astra/pages/` imports nothing from `computer/` or `conductor/`.

### Group B — the wiring (config, cli, preflight, session, loop, docs)

**B1. Config.**
- `ToolsMode = Literal["off", "dry_run", "live"]`, and `TOOLS_MODES` gains `live`.
- `tools_refusal` names the three modes and still names `docs/01 §3` and `T-0080d`, so the junk-value rows stay green.
- `Profile` gains `browser: Literal["headed", "headless"] = "headed"` (H-T111c-1) and `browser_viewport: tuple[int, int] = (1280, 800)` (H-T111c-3).
- A profile with `tools = "live"` and `tool_loop = false` is refused at load, and the refusal names the loop. The post-action frame only exists in the loop.

**B2. CLI argv and startup refusals.** `--tools live` is accepted, and `--browser headed|headless` overrides the profile. `live` is refused with exit 2, before anything is constructed, when:
- the loop is off by explicit choice: `--no-tool-loop` or `tool_loop = false`;
- `playwright` is not importable, or the pinned Chromium executable is absent. The message names P1 and `uv sync --extra browser && uv run playwright install chromium`;
- `headed` is asked for and neither `DISPLAY` nor `WAYLAND_DISPLAY` is set. The message suggests `--browser headless`.

The availability check never launches a process: a launch bomb on `PlaywrightDriver` stays untouched.

**B3. The `--dry-run` line** reads `tools=live native:<sha12> repair=<on|off(...)> loop=on(<N>) browser=<headed|headless> egress=loopback viewport=<W>x<H>`.
- `--dry-run` launches no browser and binds no start-page server; both are bombed.
- The `off` and `dry_run` lines are byte-identical to BASE.

**B4. Doctor.** `preflight.evaluate` gains three rows. All are read-only and WARN at worst, since tools are off by default:
- `browser.playwright`: the installed version against `services/versions.lock [browser]`;
- `browser.chromium`: the executable is present (the path is read; Chromium never runs);
- `browser.display`: whether a headed browser can open.

Unit rows over `Facts`:
- missing gives WARN with the fix;
- a version mismatch gives WARN;
- present gives PASS.

No collector starts a process; collectors only read the filesystem and the environment.

**B5. Kit and lifecycle.**
- **Kit.** `ToolKit.mode` is `Literal["dry_run", "live"]`. In `live` the kit carries the live browser seam, and `kit.executor` is that same object. The guard is `None` (H-T107; T-0111c criterion 12).
- **Regime label.** `_tools_regime()` reads `native:<sha12>:live[:repair_off]:loop<N>`.
- **Executor arguments:**
  - the session clock as `now_ms`;
  - `headless` from B2;
  - `end_when_closed = (browser == "headed")`;
  - `allowed_origins = {start-page origin}`.
- **Startup.** Before the first turn can open, the start-page server is bound and the start page is open in the browser. A failure here exits `astra session` with code 1 and one stderr line naming the exception type, before the HUD endpoint binds.
- **Shutdown.** Executions are cancelled first, as today (`session.py:1147`). Then the browser is closed, then the start-page server is stopped. A close failure is one `error` record in the session log, and `aclose` still completes; no exception escapes.

**B6. The turn's frame** (H-T111c-5). In `live`, `snapshot_frame` takes its frame from the live browser's `frame()`, never from `perception.get_frame`.
- The call is bounded by `LIVE_FRAME_TIMEOUT_MS` on the session clock.
- The frame is registered under its capture identity, with its `FrameGeometry(source=WINDOW)`.
- HUD frames still arrive at `BrowserFrameSource`. They are never attached, never registered, and never become a call's geometry.
- Adversarial row: the fake perception returns a distinctive HUD frame, and its bytes appear in no request body.
- When `frame()` fails, times out, or the browser is `closed`, the turn carries no image (the existing no-image wording applies), and nothing falls back to the HUD frame.
- In `live` only, the turn line gains `frame_source` (`"window"` | `"none"`) and `browser` (`"open"` | `"closed"`).

**B7. Capture identity** (T-0111c note (a)). In `live`, `_frame_bytes`, `_frame_geometry`, the `_append_frame` dedupe and history resolution are keyed by capture identity.
- Adversarial row: the fake browser yields two frames with an equal phash and different JPEG bytes. Both are held, either as two images on the turn or with the newer replacing the last slot by the cap rule, but never dropped as "seen". Each resolves to its own bytes in history.
- Two captures with identical bytes are one capture, so the prompt-builder rule "a frame equal to the newest history frame is not re-attached" still holds.
- The invocation's `FrameGeometry.phash` is the executor's phash; otherwise the executor would refuse it as `frame not from this browser`.

**B8. The post-action frame and the image swap.**

For a step k that settles `executed`:
- **Request.** Step k+1's request is `loop.step_prompt(swap(loop_base, F_k), steps)`. `swap` is a pure function in `toolcall/loop.py` that replaces only the newest `ImagePart` of the prompt. History images and every other byte stay unchanged.
- **The frame.** F_k is the live browser's `latest_frame`, and its phash equals `resolved["frame_after"]`. If it does not, the session takes a fresh frame and logs a note; it never attaches a mismatching frame.
- **Geometry.** Step k+1's `inv.frame.phash == resolved["frame_after"]`.
- **Encoding.** The swapped part's data URL is byte-identical to what `prompt_builder` produces for the same frame. Oracle: build a prompt with that frame through the builder.

For a step k that is not executed:
- **`refused`:** the image and the geometry are unchanged.
- **`failed` or `timeout`:** step k+1's image is a fresh own frame taken when step k+1's request is built, bounded by `LIVE_FRAME_TIMEOUT_MS`. If none can be taken, the previous image stays, a note is logged, and coordinate calls against it are refused by B9.

Adversarial row: after `failed: browser restarted`, step k+1's click is executed against a new-generation frame. Without the fresh frame, every later click would be refused for good.

The response payload of every live step carries `screenshot`: `"updated"` when the image was replaced for the next step, otherwise `"unchanged"`. It is built by a pure builder in `loop.py`. Dry-run payloads are unchanged.

**B9. Freshness** (T-0111c note (b)). In `live`, a `click_at`/`type_at` whose frame's capture identity is not that of the live browser's newest own frame is refused before `execute`:
- the result is `refused`, with `the screen changed since this frame; take a new frame`;
- nothing is dispatched, and the executor's call count is unchanged.

Rows in both directions (`.claude/rules/tests.md`):
- **Absent:** an older own frame of the same page, with valid geometry, is refused.
- **Too wide:** the newest frame is accepted even when it shares a phash with an older one.

**B10. Results** (T-0111c note (c)).
- An executor `failed` outcome settles the loop result as `failed`, with `loop.status_payload("failed", reason)`. Today it settles as `refused` (`session.py:2963-2992`). The card stays `refused` with the executor's reason: the card's status set is unchanged and contracts are untouched.
- These reasons reach the model and the card verbatim:
  - the `ensure()` adoption refusal (`the active page changed; take a new frame`);
  - the executor's own timeout (`failed`, `TimeoutError during …`);
  - `browser restarted`;
  - `the browser window was closed`.
- The session's own 10 s deadline still yields `timeout` (`TOOL_EXEC_TIMEOUT_MS`). An executor that raises still gives `executor error`, as BASE does.

**B11. Window closed.** When the live browser becomes `closed` (A2):
- the session publishes it once, as an existing HUD error message saying computer use is off for this session (`.claude/rules/conductor.md`: "a subsystem that silently disables itself must publish");
- it writes one session-log note;
- later turns carry no image (`frame_source: "none"`, `browser: "closed"`);
- the request's `tools` field is unchanged, so the prefix is unchanged;
- every live call is refused with A2's reason;
- the voice session keeps running.

**B12. Ask-first and honour-no.** T-0107a's `asked the user first` and T-0107e's `the user said no` apply unchanged in `live`. The executor is never called for such a call: the fake's count is 0. No confirmation guard is wired.

**B13. Barge-in.**

- The turn reaches IDLE, and the next turn's onset frame is a fresh own frame.

**B14. Assists.** In `live`, assist texts (DOM, PDF, cells) describe the HUD's capture, not the agent browser, so they are not attached.
