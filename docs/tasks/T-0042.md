# T-0042 — the audio smoke script never finishes: its drain wait writes silence forever

**Status:** done 2026-09-16 (merged; reviewer APPROVE) · **Blast radius:** low (one reviewer; `scripts/demo/audio_smoke.py` only) · **Origin:** the first
run of the smoke on real PortAudio, 2026-09-15 (human at the desk), `logs/audio_smoke_probe.log`.

## Goal

`uv run python scripts/demo/audio_smoke.py --sink astra-test-sink --source astra-test-sink.monitor` hung on this box after the
`libportaudio2` install. `faulthandler` shows the main thread inside `PortAudioDevice.write()` called from `play_and_capture`, and
a bare PortAudio probe on the same null sink fires 200 callbacks in 2 s with the stream linked to `astra-test-sink` — so the stack is
fine and the script is wrong: after the 2 s chirp it "waits for the device to drain" with
`while device.queued_ms() > 0.0: device.write(np.zeros(block))`, and every write refills the queue it is waiting on. Real-time
playback makes each write block for one block's worth of time, so the loop runs for ever and the T-0035 group-A rows never saw it
(every row patches the device). After this task the smoke terminates on a real device, reports honestly, and a unit row drives the
script over the sounddevice stub with a callback that actually consumes.

## Acceptance criteria

1. **The drain wait waits.** After the last chirp block, `play_and_capture` polls `queued_ms()` with a sleep (not a write) until it
   reaches 0 or a ceiling of chirp length + 2 s elapses; on the ceiling it reports "queue did not drain (N ms left)" and exits
   non-zero (exit 1, the device-raised class). No block is written after the chirp.
2. **Terminates on a consuming device.** Over `tests/fakes/sounddevice_stub.py` with a driver thread consuming 480 frames every
   10 ms (real-time pace), the script's `play_and_capture(seconds=0.5)` returns within 3 s and reports `written == rendered` within one
   block; a driver that never consumes yields exit 1 with the drain message and still prints the report (no traceback).
3. **`write()`'s own 2 s timeout is honoured, not hidden.** A device whose callback stops mid-chirp makes `write()` raise
   `TimeoutError`; the script reports it as a device failure (exit 1) with the message, not a hang.
4. **Negative.** `audio_device.py` and everything under `local_astra/` are byte-identical; the report block and the discriminator are
   unchanged; `--dry-run` behaviour unchanged.

## Rulings

- **A1.** Criterion 3 already holds (`main()` catches `TimeoutError`, exit 1, no hang); its row is a green regression guard, not pending.
- **A2.** The drain ceiling may raise `AudioDeviceError` or `TimeoutError`; the row pins exit 1, the phrase `queue did not drain` and the
  leftover-ms number (hand-computed band), not the class.
- **A3.** "written == rendered within one block" is read as every written frame taken by the callback (`written − queued ≈ written`);
  `rendered_ms()` subtracts the negotiated latency by design and cannot be the oracle.
- **A4 (activation).** Markers removed by the orchestrator after fede5ec. Routed to T-0035: the rig row's 120 s subprocess timeout is a
  slow way to detect a hang — tighten to ≈ 30 s in a follow-up.
- **A5 (review, APPROVE, merged).** All mutations red; live on the rig 11/11 exit 0. Owed one-liners (a later mechanical pass on the owned file): (1) `underflow_frames` is snapshotted the instant the queue empties, so the reported 0 vs 480 is scheduling noise — report the value read at the last poll where the queue was non-empty (T-0035 B11 depends on it); (2) on a failed non-dry run the report says `not measured (dry run)` — say `(the run failed)`.
