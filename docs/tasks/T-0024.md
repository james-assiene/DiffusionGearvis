## Goal

The *shown* channel stops being a placeholder. `hud/src/ui/**` mounts through T-0008's panel seam,
takes the `astra.ui.surface` messages the merged `UiGate` produces, hands them to `@a2ui/lit` +
`@a2ui/web_core` v0_9 (vendored as one prebuilt ESM bundle so the page stays buildless and works
with no network route), renders the surface into `#shown-channel`, morphs it as later canvases
arrive, and sends the user's clicks back as `astra.ui.action` over the same socket — closing
T-0010's criterion 5 ("a quiz answer round-trips into the Conductor as `UiAction`", docs/12 §1.1,
docs/03 §Q11 "renderer round-trip"). The first thing this task produces is something a human can
look at: `scripts/demo/hud_ui_demo.py` runs the real gate over
`tests/fixtures/a2ui/quiz_example.jsonl`, pushes the validated surface to the page from a loopback
stub, and leaves a PNG of the rendered quiz in `logs/hud/`. Nothing here changes the Conductor: the
action is *sent*; turning it into a user turn stays T-0007's.

**The renderer, vendored**

1. **One vendored bundle with provenance.** `hud/vendor/` contains exactly one runtime artefact —
   an ESM bundle of `@a2ui/lit@0.11.0`'s `./v0_9` entry (which pulls `@a2ui/web_core@0.11.x`, `lit`,
   `@lit-labs/signals`, `@lit/context`, `signal-utils`, `zod`) — plus `hud/vendor/MANIFEST.md`
   naming, for every bundled package: name, exact version, licence, and the SHA-256 of the produced
   file, the esbuild version and the exact command that produced it. `scripts/hud_vendor.sh`
   reproduces it from `hud/package-lock.json`. A test asserts the committed bundle's SHA-256 equals
   the manifest's and that every bundled package is listed with a licence (fixture-provenance rule,
   `.claude/rules/tests.md`). *Negative:* no sourcemap and no `.map` file is committed; no
   `node_modules/` is committed (`.gitignore` already covers `hud/node_modules/`); the page still
   loads with the network route down, i.e. **no** CDN import, no import map pointing off-box, no
   fetch of a catalog by its `catalogId` URL. Cites T-0008 criterion 12.
   *Decision recorded here, with the reason:* vendor a prebuilt bundle rather than a build step,
   because node 18.19.1 cannot even *import* `@a2ui/lit` (`Unexpected token 'with'` — import
   attributes; T-0010 toolchain note), because the page is buildless by T-0008's out-of-scope
   ruling, and because a committed artefact is what makes "works with no network" checkable. npm is
   a one-time developer action behind `scripts/hud_vendor.sh`, not a runtime dependency.
2. **The panel mounts through the existing seam.** `hud/src/ui/index.js` exports
   `mount(host)` (the contract `hud/src/panels.js` already calls). With it present,
   `mountPanels()` reports it in `mounted`, and `./denoise/index.js` stays in `missing` with one log
   line — T-0008 criterion 10 keeps holding. *Negative:* `mount` never throws out of
   `mountPanels`; a bundle that fails to load leaves the socket, the capture pipeline and the other
   panes working, and puts one line in the error strip.
3. **The message seam is T-0025's; this task only consumes it.** `host = { shown, document,
   subscribe(handler) -> unsubscribe, send(message) -> Promise, log }` as delivered by T-0025
   (criterion 13 there): `subscribe` is called with every message T-0008's `decode` classified as
   `kind === "astra"`, in arrival order; a handler that throws is caught and counted. **This task
   does not edit `hud/src/main.js`.** *Negative:* the shell itself still emits only `astra.hello`
   and `astra.frame` (`hud/src/protocol.js` `CLIENT_TYPES` is unchanged); `state.js`'s reducer is
   unchanged and still ignores `astra.ui.surface`; T-0008's headless and node tests stay green.
4. **A surface renders only because the gate validated it.** The only input the panel accepts is a
   decoded `astra.ui.surface` (`contracts/protocol.AstraUiSurface`), whose `messages` it passes to
   the A2UI `MessageProcessor` unmodified except for the `catalogId` aliasing of criterion 5.
   *Negative (the honesty rule):* there is no code path that renders A2UI from anywhere else — not
   from `astra.spoken` text, not from `astra.canvas.commit`, not from an `<a2ui>` sentinel the page
   parses itself, not from a URL parameter, not from a file the page fetches. Proved by an
   adversarial test that sends a full, well-formed A2UI message body inside an `astra.spoken.text`
   and inside an unknown `astra.zzz`: the shown pane still reads `no surface yet (T-0010)`.
5. **The quiz fixture renders.** With the three messages of `tests/fixtures/a2ui/quiz_example.jsonl`
   taken through the real `UiGate.gate(..., turn_id="t1")`, the page shows: both tab titles (`Quiz`,
   `Flashcards`), all five question prompts, and four choices for question 1. The DOM assertion
   pierces shadow roots. Two landmines this criterion exists to catch, both measured from the
   package source on 2026-09-13: the renderer's `basicCatalog.id` is
   `…/specification/**v0_9**/catalogs/basic/catalog.json` while our fixture and vendored schemas say
   `**v0_9_1**`, and `MessageProcessor.processCreateSurfaceMessage` *throws* `A2uiStateError:
   Catalog not found` on a mismatch; the fix is a local alias (register the basic components under
   the id our gate emits), never a silent rewrite of the model's message and never a fetch of that
   URL. *Negative:* an unknown `catalogId` produces a visible error strip line, not a blank pane and
   not an invented surface.
6. **The demo path — the first deliverable.** `scripts/demo/hud_ui_demo.py` serves `hud/` on
   loopback, runs the fixture through the real `UiGate` canvas by canvas, pushes each resulting
   `AstraUiSurface` over a loopback WebSocket stub, and writes a PNG of the rendered quiz to
   `logs/hud/ui-quiz.png` (`logs/` is gitignored and is not `artifacts/`, so no launch token).
   The reviewer reads that PNG. *Negative:* if `gate()` returns no surface the script prints the
   `SurfaceReport` and exits non-zero — it never falls back to pushing the raw fixture, because a
   demo that renders unvalidated JSON is exactly the lie criterion 4 forbids (same rule as
   `astra.canvas.synthetic`, docs/12 §2).

**Progressive render, actions, fences**

7. **Progressive morph, including the idempotent `createSurface`.** Canvases *k = 0…n* of one turn
   arrive as separate `astra.ui.surface` messages with the same `surface_id` and increasing
   `canvas_idx`; the pane morphs in place (one surface element, not n). The gate re-sends
   `createSurface` within a turn by design (T-0010 A4) and
   `MessageProcessor.processCreateSurfaceMessage` throws `Surface … already exists` on the second
   one — the bridge must make that a no-op. A later `surface_id` (`turn-t2`) *replaces* the surface;
   it does not morph turn 1's. *Negative:* an out-of-order or duplicate `canvas_idx` never removes
   components already shown, and `final=false` does not clear the pane.
8. **A missing child is a placeholder, never invented content.** A surface whose parent references a
   child id that never arrives (hand-built, bypassing the gate's pruning — this is X11's open
   question, docs/12 §1.1) renders the rest of the tree, shows the renderer's placeholder (or our
   own visibly-empty slot) where the child would be, and logs one line. *Negative:* no text, label
   or default value is synthesised for the absent component, and the surrounding components are not
   dropped.
9. **`astra.ui.action` goes back, and it decodes.** Clicking the quiz's `check_btn` sends exactly
   one client→server message that `local_astra.contracts.codec.decode` turns into an `AstraUiAction`
   with `surface_id == "turn-t1"` (the gate's rewritten id, T-0010 A7 — *not* the model's
   `lesson_1`), `name == "check_quiz"`, the model's own `context` keys (`quizId`, and `answers`
   resolved by the binder to the chosen values), and `data_model` populated because the fixture's
   `createSurface` sets `sendDataModel: true`. The A2UI action's `sourceComponentId` and `timestamp`
   are carried under a single reserved `context["a2ui"]` object; if the model's own context already
   holds an `a2ui` key, the model's value wins and the page writes an error-strip line rather than
   overwriting it silently. **Named spec gap, not fixed here:** `AstraUiAction` has no
   `source_component_id` field and `Contract` is `extra="forbid"`, so the component id has nowhere
   else to go; adding the field is a `contracts/protocol.py` change with its fake update in the same
   PR and belongs to T-0007's session pass. Do not add it in this task and do not smuggle it as a
   top-level key. *Negative:* no action is sent for a click the renderer did not raise an action for
   (scroll, tab switch, typing into a `TextField`), and exactly one message per click — a
   double-send is the failure mode to test.
10. **Loopback only, and no audio, re-proved behaviourally.** During a full render-and-click run,
    headless Chrome records **zero** network requests to a non-loopback host (CDP
    `Network.requestWillBeSent` over the whole session), and the rendered DOM (shadow roots included)
    contains no `<audio>` element, constructs no `AudioContext` and requests no audio track.
    **Spec change this criterion authorises, and nothing more:** `tests/unit/test_hud_no_audio_no_egress.py`
    greps every `.js`/`.json` under `hud/` for non-loopback URL literals and for audio patterns; a
    vendored A2UI bundle contains catalog/schema `$id` strings such as
    `https://a2ui.org/specification/v0_9/…`, which are *identifiers the renderer compares as
    strings*, never fetched. The test-author therefore scopes the textual URL scan to `hud/src/**`
    and the page shell (unchanged fence for the code we write) and replaces it, for `hud/vendor/**`,
    with (a) a scan for network *verbs* (`fetch(`, `XMLHttpRequest`, `new WebSocket(`,
    `importScripts`, `navigator.sendBeacon`, dynamic `import(` of an absolute URL) and (b) the
    behavioural CDP assertion above, which is strictly stronger than the grep it replaces. The audio
    patterns stay in force over the whole tree; the implementer reports the per-pattern match count
    measured on the built bundle **before** any test is amended, and if the bundle does contain an
    audio-capable component the answer is to exclude it from the bundle or from the registered
    catalog, not to loosen the pattern. *An amendment that deletes a check rather than replacing it
    with a stronger one is an automatic REVISE.*
11. **The shown-channel placeholder survives the panel's arrival.** With the panel installed but no
    `astra.ui.surface` received, `#shown-channel` still reads `no surface yet (T-0010)` — which is
    what keeps T-0008's `test_the_shown_channel_is_a_labelled_placeholder…` green. **T-0008 test
    updates this task forces, the test-author's, named here so nobody "fixes" them in the
    implementer's tree:** `tests/hud/panels.test.mjs` ("no importer injected" case) counts missing
    panels — after T-0025 the truth is "assists mounted, ui and denoise missing"; after this task
    "denoise missing" only (`ui` mounted, or `failed` for want of a DOM under `node --test`). And
    `tests/integration/test_hud_headless.py`'s panel-log assertion counts missing panels. Both are
    *behaviour moving as planned*, not tests to be worked around.

## Implementation notes

- **Read first:** `docs/12` §1.1, `docs/02` §2.1 and §5, `docs/tasks/T-0008.md` (criteria 10, 12, 13
  and rulings R1–R14), `docs/tasks/T-0010.md` (A3/A4/A7/A8/A10 — they describe exactly what the
  renderer will receive), `docs/tasks/T-0025.md` (the seam you consume), `.claude/rules/tests.md`.
- **API facts measured from the packages on 2026-09-13** (so nobody guesses):
  `@a2ui/lit@0.11.0` exports `A2uiSurface, A2uiLitElement, A2uiController, Context, basicCatalog`
  from its `./v0_9` entry; the actual engine is `@a2ui/web_core@0.11.x`'s
  `new MessageProcessor(catalogs, actionHandler?, {version: 'v0.9' | 'v0.9.1'})` with
  `processMessages(msgs)`, `onSurfaceCreated(s => …)`, `getClientDataModel()`, and
  `ActionListener = (action: {name, surfaceId, sourceComponentId, timestamp, context}) => void`.
  The surface renders as `<a2ui-surface .surface=${surfaceModel}>`. The server→client zod schema
  accepts `version` ∈ `{'v0.9', 'v0.9.1'}`, so our `A2UI_SPEC_VERSION` messages pass — construct the
  processor with `{version: 'v0.9.1'}` so the client data model reports the same version.
- **The two throw sites are the whole design risk**: `Catalog not found: <id>` (criterion 5) and
  `Surface … already exists` (criterion 7). Decide where they are handled *before* writing the
  panel; catching them at `processMessages` granularity loses the rest of the canvas.
- **Keep the DOM out of `bridge.js` and `action.js`** so `node --test` can import them, exactly as
  T-0008 does for `state.js`/`protocol.js`. `index.js` must `await import()` the vendor bundle
  *inside* `mount()`, never at module top level — a static import drags `lit` into node and every
  node test that touches the panel dies at collection.
- **`_grounded`, pruning and resamples are the gate's job, already merged.** The page renders what it
  is given; it does not re-validate A2UI, does not repair JSON, and does not decide what to drop.
  If a surface looks wrong on screen, the bug is in `ui_gate.py` (T-0010's file) — report it, do not
  compensate in the page.
- **The gate exposes no `resample` list on the wire** (`AstraUiSurface` carries `surface_id`,
  `canvas_idx`, `final`, `messages`, `repaired`). So criterion 8's placeholder is about *dangling
  references*, not about re-requests; do not invent a "waiting for q3_c" chip from data the page
  does not have. `repaired > 0` may drive a small badge (the field's docstring says so) — if you add
  it, it shows the number, not an opinion.
- **esbuild**: pin it as a devDependency in `hud/package.json` and record the version in the manifest;
  build with `--format=esm --bundle --target=chrome120 --sourcemap=false`. Report both the raw and,
  if you also try `--minify`, the minified size; prefer the readable one unless the reviewer asks —
  a 756 KB auditable file beats a 300 KB one nobody can read, and this file is served from loopback
  to one browser.
- **Do not touch `hud/src/protocol.js`.** Its `CLIENT_TYPES` is pinned by
  `tests/unit/test_hud_constants_parity.py` as the *shell's* whitelist; the panel's outbound type is
  pinned by its own node test, by T-0025's per-owner scan (`hud/src/ui/**` ⊆ `{astra.ui.action}`),
  and by the codec round-trip.
- **`npm install` reaches the network once** (verified: `npm view @a2ui/lit version` → 0.11.0 from
  this box). That is a developer action gated by `scripts/hud_vendor.sh`, not a runtime dependency;
  the committed bundle is what makes criterion 1's "works with no network route" true.
- Nothing in this task spends GPU time or writes `artifacts/`, so no launch token is needed;
  `logs/` is gitignored.
