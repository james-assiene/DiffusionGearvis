# T-0045 — `astra session` never opens a microphone: the CLI has no capture source

**Status:** done (merged at bb1470e; status corrected 2026-10-23 from 'in progress', T-0147 audit: no implementation in flight) · earlier: in progress 2026-09-16 (tests activated 210118a; **T-0043 group A has merged, so `cli.py` is free and the implementer can run now**) · **Blast radius:** low–medium (one reviewer; `cli.py` and the doctor's regime/source rows) ·
**Origin:** the human's first spoken attempt, 2026-09-15 late evening: nothing appeared; the turn record says `stt_frames_fed: 0`.

## Goal

`cli.open_audio` calls `open_device(sink=args.sink)` and never passes a `source`; `PortAudioDevice` opens a duplex stream only when
`source` or `input_device` is set (`duplex = self.source is not None or self.input_device is not None`). So every `astra session` is
output-only: `stt_blocks()` never yields, the capture pump feeds nothing (`stt_frames_fed: 0` on every live turn), and the session is
deaf on hardware although T-0032's group A proved the pump over fakes. The `--source` flag the rung already has (`session_rung.py
--audio-path`, `--sink`) has no CLI twin, and the only route today is the `ASTRA_AUDIO_SOURCE` environment variable (T-0035 criterion 7).
After this task `astra session` opens the microphone by default when one exists, says which, and refuses loudly when it cannot.

## Acceptance criteria

1. `astra session --mic <PipeWire node name>` passes it (`--source` already means the perception source — screen/camera — so the microphone flag is `--mic`) to `open_device(sink=…, source=…)`; without the flag the source defaults to
   the PipeWire **default source** (read from `wpctl status`/`pw-dump` via the doctor's collector, never guessed) unless `--no-mic` is
   given; `--silent` still opens no device at all. `--mic none` ≡ `--no-mic`.
2. The startup line and `describe_graph` print `mic=<node name|none>` beside `sink=`; the regime line and `Regime` carry the source
   node name (a turn must say which microphone heard it — CLAUDE.md regime rule); `turns.jsonl` lines carry it.
3. A session started with a source has `stt_frames_fed > 0` after two seconds of running (the integration row over the null-sink rig:
   `--mic astra-test-sink.monitor --sink astra-test-sink`), and `astra session --dry-run` prints the resolved source.
4. When the requested or default source does not exist, `open_device` refuses before the stream opens (T-0035 criterion 4) and the CLI
   exits 1 naming the node and the ones that exist; it never silently runs output-only.
5. `astra doctor`'s `audio.source` row names the default source and says whether it is the webcam mic (the only mic on this box); the
   arrival checklist's audio command becomes `uv run astra session --serve-hud` (mic on by default, HDMI playback) or with
   `--sink astra-test-sink` for silence.
6. **Negative.** `audio_device.py`, `audio_io.py`, `session.py` unchanged; `--silent` behaviour unchanged (no device, no mic).

- **A14 (F1, the remaining lie — ruled; this is a spec gap, not just a bug).** `audio_device.open_device` falls back to
  `ASTRA_AUDIO_SOURCE` when `source is None`, and `resolve_mic` never consults it, so "no capture source" and "consult the environment"
  are the same value at that seam. Demonstrated: `astra session --no-mic` with the variable set prints `mic=none` on the resolved-graph
  line, the regime line and (once ruling A1 lands) the turn record, while a duplex stream is open on the named node. **This is not
  hypothetical — the variable is the workaround the human was told to export on 2026-09-15**, so it is plausibly still in their shell.
  **Ruled precedence, highest first:** `--mic <node>`, then `--no-mic`, then `ASTRA_AUDIO_SOURCE`, then the graph's default source. The
  environment variable becomes an explicit, *printed* step in `resolve_mic` rather than an invisible fallback two layers down, and the
  off path must **defeat** the fallback (clear the variable around the call; `audio_device.py` stays byte-identical per criterion 6).
  Two further symptoms the same fix closes: with an unreadable graph *and* the variable set, the session now exits 1, a regression on the
  route this task's own Goal calls "the only route today"; and with a readable graph the default silently outranks the variable, so
  someone who exported the rig monitor gets the webcam instead.
