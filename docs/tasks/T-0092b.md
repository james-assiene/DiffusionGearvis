## Goal
`tools` is a session setting, `off` by default (H3).

**With `dry_run`:**
- the composition root loads and checks what a tool turn needs, before the event loop runs;
- every prefill and generate carries the native `tools` field and the H11 instructions;
- the client reads the stream in id mode;
- the request's `tool` commit is logged and kept for T-0092c, but not yet judged. `LlmDone` carries no tool in this task.

**With `off`:** nothing changes.

## Acceptance criteria
1. **The switch.**
   - `Profile.tools: Literal["off", "dry_run"] = "off"` in `config.py`, settable in `astra.toml`.
   - `astra session --tools {off,dry-run}`. The flag overrides the profile.
   - `live`, or any other value, is refused both at config load and at argv, with a message that names docs/01 §3 and T-0080d. The
     session never starts.
   - It is a session setting: no request and no turn changes it.
   - `astra up` gets no flag, because it starts no conductor. This corrects the 2026-10-11 wording "`astra up|session`".
   - `astra session --dry-run` prints `tools=off`, or `tools=dry_run native:<tools sha12> repair=on|off(<reason>)`.
2. **Startup with `dry_run`.** All of this runs in `cli.build_session`, before `asyncio.run`, so never on the event loop.
   - **(a) Detokeniser.** `HostDetokenizer.load()` runs (about 320 ms, T-0088a). Any exception refuses `dry_run`: `astra session`
     exits 1, the message names the file and the reason, and no session starts.
   - **(b) Payloads.** `live.load_payloads()`, then these manifest checks:
     - `model_revision` equals `[gpu].model_revision` in `services/versions.lock`;
     - `tokenizer_sha256` equals the detokeniser's pinned sha;
     - `canvas_length` equals `profile.diffusion.canvas_length`.
   - **(c) Calibration.** `live.load_calibration()`.
   - **Staleness.** Any `PayloadStale` from (b) or (c), or any manifest mismatch, turns **repair off** with that reason. It does not
     refuse the session. Repair off is announced:
     - in one stderr line at start;
     - in a session-log `note {what: "tool repair off", reason}`, the first record after `log.started`;
     - in `Regime.tools` (criterion 5).
     Repair stays off for the life of the session.
   - **Wiring.** `VllmClient(..., detokenizer=…)`. The session receives the loaded kit by injection: the mode, the tools field, either
     the payloads and calibration or the repair-off reason, and a `DryRunToolExecutor`. The session reads none of these files itself.
   - **With `off`.** None of (a)–(c) runs, and no executor is constructed.
3. **The prompt** (H11).
   - With `dry_run`, the system message is today's text followed by `NATIVE_TOOL_INSTRUCTIONS`.
   - `NATIVE_TOOL_INSTRUCTIONS` is a literal in `prompt_builder.py`, equal to paragraphs 2 and 3 of `twopass.NATIVE_SYSTEM_PROMPT`; the
     persona sentence is omitted. It is a literal because the conductor may not import `eval`.
   - Every `Prompt` the builder returns (`prefix`, `full`, `fit` and the over-long retry) carries the same `tools =
     tuple(native.tools_field(tools.load()))`.
   - A turn's prefill and generate carry identical tool fields (T-0088 criterion 2; q8). The existing prefix-parity rows hold with
     tools on.
4. **The request path.** With `dry_run`, `_run_generate`'s request is tools-on.
   - **The `tool` commit.** There is at most one per request. It is logged and kept for the turn, with its `Commit.stop_id`. It is not
     submitted as `LlmCommit`, so it never reaches the machine, the speech gate or `canvases`.
   - **The `llm.commit` record** gains `stop_id`, on `tool` commits only. Records of every other segment stay byte-identical to today.
   - **`LlmDone`** carries no tool in this task.
   - **Hashing.** A `Prompt` with `tools` is never hashed, and never used as a set member or dict key (T-0088 note). Prompts are
     compared by equality only.
5. **Telemetry fields** (`telemetry/turns_log.py`).
   - **`Regime.tools: str = "off"`.** When tools are on it is `"native:<tools sha12>:dry_run"`, with `":repair_off"` appended when
     repair is off.
   - **`TurnRecord.tool: dict[str, Any] | None = None`.** This task adds the schema only; T-0092c writes it.
   - `outcome` keeps its pattern.
   - Every `turns.jsonl` line written before this task still parses with `from_line`.
6. *Negative: the tools-off golden.*
   - **The script.** With `tools = off`, run a multi-turn session over the fakes: a spoken turn, a typed turn, a UI action, an A2UI
     surface, a barge-in, a TTS error and an over-long retry.
   - **The base.** The base SHA is T-0092a's merge commit, `a502871`.
   - **Identical to the base:**
     - request bodies and prompts;
     - machine events, commands and states;
     - HUD messages;
     - the `kind`/`data` of the `llm.*`, `machine.step` and `tts.*` session-log records.
   - **Turn records** are identical apart from exactly two added keys: `regime.tools == "off"` and `tool == null`.
7. *Negative.*
   - With `tools = off`, a spy row confirms that `HostDetokenizer`, `load_payloads`, `load_calibration` and the executor are never
     called or constructed.
   - Unchanged: `contracts/**`, `llm_client.py`, `turn_machine.py`, `toolcall/**` and `tool_executor.py`.
   - With `dry_run`, no non-loopback socket is opened (the egress row extended).
   - `executor.py`'s tool-command handlers are untouched and stay inert:
     `test_session_loop.py::test_t0089_tool_commands_have_named_inert_handlers` stays green, unedited.

## Rulings (orchestrator, 2026-10-12)
- **H-A1. The kit.** `session.ToolKit(mode, tools, executor, payloads, calibration, repair_off)`, injected as `Session(..., tool_kit=)`.
- **H-A2. The builder.** `PromptBuilder(..., *, tools=None)`.
- **H-A3. The lock file.** The CLI reads `cli.SERVICES_DIR / "versions.lock"` at call time.
- **H-A4. The flag default.** `--tools` defaults to `None`, which means the profile decides.
- **H-A5. The pinned sha.** It is `detok.TOKENIZER_SHA256`. The implementer must not name it inside session.py or prompt_builder.py,
  because of the landmine.
- **Free, as the test-author lists:**
  - `--dry-run` may or may not load the detokeniser;
  - the wording of the stderr line;
  - whether a refused toml value raises or exits.

## Implementation notes
- **Landmine: banned substrings.** `test_prompt_budget.py::test_the_count_comes_from_the_engine_and_nothing_else` bans these in
  `session.py` and `prompt_builder.py`: `tokenizer` (case-sensitive; docstrings count, and only `#` lines are stripped), `tiktoken`,
  `sentencepiece`, `AutoTokenizer`, `chars_per_token`, and any `/ 4` shape.
  - `HostDetokenizer` and the manifest key `tokenizer_sha256` both contain `tokenizer`.
  - So the detokeniser and manifest checks live in `cli.py`, and the injected kit's names avoid the substring.
- **No new conductor file.** Among the T-0092 files, the T-0080a fork-point guard (`test_toolcall_imports.py`) excuses only
  `session.py`, `prompt_builder.py` and `executor.py`. A new file under `local_astra/conductor/` would trip it. `cli.py`, `config.py`
  and `telemetry/` are outside its guarded set.
- **The conductor may not import `local_astra.eval` or `decoding`.** That is why the instructions are a literal, pinned against twopass
  by a test.
- **Both thinking and tools are session settings.** Thinking keeps `chat_template_kwargs` untouched. Tools must not be toggled per
  request either, because that misses the cache (q8: 0.71 without).
- **The captioner's requests stay toolless.** They are a different prompt and do not share the prefix.
