# T-0066 — Torch inference core II: the constrained joint draw and the constrained MAP

**Status:** done (merged at 695e3e8; status corrected 2026-10-23 from 'in progress', T-0147 audit: no implementation in flight) · earlier: in progress · **Blast radius:** medium · **Branch:** `T-0066-cd-core-draw-map` · **Depends on:** T-0065

## Goal
From T-0065's retained tree, this task draws a whole canvas **jointly** from the constrained posterior (Algorithm 1:
boundary pair, then midpoint recursion, then an edge-multiplicity-weighted token draw) and computes the **constrained
MAP** exactly (max-plus, with token recovery). Randomness comes only from a caller-supplied `torch.Generator`. The MAP
must reduce to the per-position argmax whenever that argmax is already in the language. That property is what makes
the Sudoku end-projection control decisive.

## Acceptance criteria
1. **Draw exactness.**
   - Instances: tiny DFAs and NFAs with parallel overlapping labels, non-singleton start sets and budget terminals.
   - Test: n = 20 000 draws per instance, χ² goodness of fit against the enumerated posterior (cells pooled to
     expected ≥ 5), Bonferroni over all instances and cells at family α = 1e-3.
   - Control: the ∃-form (unweighted) token draw is a named control that must fail on the NFA instance (SPEC §2.6
     eq. 8).
2. **Support.** 10⁴ draws at L = 256 on T-0063's real automata with random softcapped logits are all accepted by host
   replay on positions < L_eff. Positions ≥ L_eff are drawn from p unconstrained; they are never committed.
3. **Generator discipline.** The draw consumes only the passed generator. `torch.get_rng_state()` (and the CUDA RNG
   state in tier 2) is unchanged across the call. The same generator state gives an identical draw.
4. **MAP exactness.** On tie-free random instances (DFA and NFA) the MAP sequence equals the brute-force argmax over C,
   and its score equals the brute-force maximum within 1e-5 relative (fp32) or 1e-12 (fp64). The MAP is always in C.
   It is identical at T = 0.8 and T = 0.4 on the same logits (SPEC §2.7, temperature invariance).
5. **Projection identity (the Sudoku control's property; adversarial).** If the per-position argmax x\* satisfies
   `x* ∈ C` under the budget, then MAP = x\* exactly. If x\* ∉ C, then MAP ≠ x\* and MAP ∈ C. Tested on hand-built
   cases, on random instances, and on real Sudoku automata with logits whose argmax is a valid grid, and one whose
   argmax overwrites a given.
6. **Regimes of T-0065 criterion 2** (L = 256, buckets 64/128, 250-nat spans, narrow negated classes, the two-band
   case): draw support holds and the MAP score matches the oracle.
7. *Negative:* the MAP uses no randomness. Neither function uses the global RNG, makes a host sync on the per-step path
   (spy), or imports vLLM.

## Implementation notes
- **From the T-0065 review:** the `LogTree` the caller holds is the ungauged pass-1 tree (T-0062 decision 10);
  the joint draw and MAP must either use it (and meet criteria at fp32 without the gauge) or rebuild the gauged tree.
- Whether the MAP shares work with the sum sweep or needs its own max-plus sweep is the implementer's decision; the
  report states which. The MAP needs `(s, s') → class` recovery (SPEC §2.7). Do not store an O(L·S²) backtrace.
- Any deterministic tie-break is acceptable. The criteria use tie-free instances so as not to overspecify it.
- Cost matters: the draw and the MAP both run every step in the per-step arms. T-0071 measures them.

## Implementation (implementer, 2026-09-29)
- **Draw on the ungauged pass-1 tree.** Every conditional (boundary pair, midpoint, eq. 8 edge) is a ratio
  inside one node or a sibling pair, so the per-node log scales cancel and only normalised entries are read,
  as logs (Gumbel-max); fp32 storage error (~ulp of the entry, 6e-5 at 850 nats) is far below what 20 000
  draws resolve, and the zero pattern is exact (finite sentinel). No gauged rebuild.
- **Token draw** is eq. 8 in two stages (edge ∝ W_i(class) among the edges s_i → s_{i+1}, parallel edges each
  counted; then token ∝ p_i·1[v ∈ label]), by a two-level inverse CDF over V with `searchsorted(right=True)`,
  which can only land on a strictly positive weight. Every random op is `torch.rand(..., generator=g)`.
- **The MAP has its own max-plus sweep** (no work shared with the sum tree): leaves in regret form
  `max_{v∈c} (ℓ_i(v) − max_v ℓ_i(v))`, so a valid per-position argmax has path value exactly 0 and the
  projection identity holds without a margin. Descent by argmax over the retained max-plus nodes; the
  `(s, s') → class` step is re-derived per position (argmax over the edges of the chosen pair, O(L·E)), no
  backtrace table. Ties: lowest token id inside a class, `torch.argmax`'s first index elsewhere.
