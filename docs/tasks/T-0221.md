# T-0221 — Every option explained once: the settings catalog's notes brought up to date, and a README table generated from it

**Status:** merged 2026-11-01 at 24abb267 (tip 645d9114; R-1 the README section check is structural); was in progress (impl dd34a8a9 + tests 19b4e3ed combined) (James, 2026-11-01: "Does the documentation / README explain succinctly the different options, when they are useful and when they are not?"). Text only; no behaviour changes.

## Goal

The settings catalog (`local_astra/settings_catalog.py`, 29 entries) is the one place that explains each option (what, useful when, not useful when, evidence, cost); the HUD Settings panel shows it. It has drifted:
- `reground.useful_when` is a copy of the crop row's text and never states the measured small-target result (T-0212: click misses 35/96 → 10/74 on the three.js editor; T-0214 both arm 10/64);
- `action_outcome` still says "T-0212 measures it" (T-0212: no sign; T-0214 with ReGround: no sign beyond ReGround alone);
- `search` does not say that, since T-0215, search off withdraws the tool (T-0220: shared handoff used its browser 9/9);
- about ten rows have "—" or a placeholder where a one-line note is easy.

The README explains how to run and the panel's mechanics but has no per-option "when useful / when not". After this task the catalog is accurate, and the README carries a short options table generated from the catalog, kept in sync by a test.

## Acceptance criteria

1. **Catalog audit.** For every one of the 29 entries, `what`, `useful_when`, `not_useful_when`, `evidence` and `cost` are accurate against the runs recorded in PROGRESS *Runs* and the task files, each one short (one sentence or a fragment). Specifically:
   - `reground`: useful on small or dense UI targets (quote T-0212 misses 35/96 → 10/74, n = 15 per arm, three.js); not useful on ordinary pages (T-0132 C 65 vs 64/100), adds a request per click; refused with the overview frame.
   - `reground_visual_tokens`: keeps its crop-budget text (T-0132 C crop 280 64/100 vs 1120 66/100).
   - `action_outcome`: no measured gain (T-0212 outcome 0/15, misses 23/69 vs base 35/96; T-0214 with ReGround no sign beyond ReGround alone); for experiments.
   - `search`: off withdraws the `google_search` tool (T-0215); useful for questions that need the web; off for private or offline work.
   - No `useful_when` or `not_useful_when` is "—", empty or a placeholder; when there is genuinely nothing to say for a fixed or engine row, a short plain statement ("always on: switching it per request would make every reply slow") replaces it.
   - Every number quoted carries its run id; no number appears that is not in PROGRESS or a task file.
2. **README table.** `README.md` gains, under "Settings", a section "Options at a glance": one row per catalog entry in catalog order and groups, columns *Setting* (label), *Default*, *Useful when*, *Not useful when*, *Changes* (live from the panel / needs a restart, with the flag). It is generated by `scripts/gen_readme_options.py` from `CATALOG` between two marker comments (`<!-- options:begin -->` / `<!-- options:end -->`); nothing else in the README changes except the "Needs a restart" bullet if it is now redundant.
3. **No drift.** A unit test regenerates the table from `CATALOG` and asserts the README block is byte-identical; it fails with the command to run.
4. **Negative.** No change to any catalog field other than the five text fields above; `key`, `label`, `kind`, `default`, `flag`, `relaunch`, groups and order unchanged; the panel's wire message changes only in those texts; no product behaviour changes.
