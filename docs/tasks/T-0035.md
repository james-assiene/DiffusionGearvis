Group B was blocked on prerequisite P1, which the human satisfied on 2026-09-15 by installing `libportaudio2`, so it is now startable. · **Blast radius:** medium (one reviewer — see §Blast radius for why this is not the audio path's usual "high") ·
**Depends on:** T-0006 (merged 52e6657) and T-0021 (merged 30147da) — `audio_device.py` is free · group B additionally on **P1 (`sudo apt-get install -y libportaudio2` → `libportaudio2`)** ·

## Goal

`local_astra/conductor/audio_device.py` has never met PortAudio: it was written, reviewed and
merged against fakes, and the 2026-09-14 first-contact audit — run through the same
alsa-lib → PipeWire plugin path PortAudio will take — found that three of the things it reports
are not measurements. `underflow_frames` counts only *our* empty ring and never reads
`status.output_underflow`, so a real device xrun is invisible in the one counter T-0006 ruling A22
put on the protocol precisely because it is "the backend's own xrun counter". `quantum_ms` is
`1000 · frames / rate` with a fixed `blocksize`, so it returns 10.0 whatever the graph negotiated —
contradicting its own docstring and `_PipewireEnv`'s promise to "report what came back". And
nothing checks that the stream landed on the node we asked for: a `PIPEWIRE_NODE` naming an absent
node links to `auto_null` silently, and a monitor capture of an absent node yields seconds of
exactly 0.0 with no error — which is indistinguishable from a working rig in the dark, and is the
single most expensive failure mode for every hardware run T-0023 and T-0032 are queued to do.
Beneath that sits a design gap: for `sink ≠ source` both halves of the duplex stream are pointed at
the *source's* node, so the acoustic regime T-0023 needs (real sink → speaker → mic) has no working
device path at all. This task makes the device's self-reports honest, gives the sink≠source case a
mechanism that either works or says so, and ships `scripts/demo/audio_smoke.py` — the two-minute
"is the audio path real" check that prints the discriminator the audit had to work out by hand.
Everything in group A is testable today with `sounddevice` stubbed and `pw-dump` output recorded;
group B waits on P1.

## Acceptance criteria

Group A (1–10) is checkable in the fast suite with no PortAudio and no hardware. Group B (11–14)
needs P1 and the null-sink rig; it is ungated per the existing ruling for the null-sink rig
(`scripts/demo` is D5-ungated), and anything acoustic stays `/launch` and stays T-0023's.

Each criterion names the audit finding (F2–F7) or the prior ruling it satisfies.

### Group A — the device tells the truth about itself

1. **A device xrun is counted (F2, closes T-0006 ruling A22 properly).** In the output callback,
   `underflow_frames` increases when the backend reports `status.output_underflow`, **including the
   case where our ring was full and `taken == frames`**. The per-callback increment is
   `max(frames - taken, frames if output_underflow else 0)` — a callback the device flagged is
   suspect in whole, and the two causes are never silently added together. A second, non-protocol
   attribute `device_xruns: int` counts *callbacks* carrying the flag, so "our ring starved" and
   "the graph starved" stay distinguishable in every report. The docstrings at `audio_device.py:84`
   (protocol member) and `:167` (the instance attribute) are rewritten to describe what is actually
   counted. *(T-0006 criterion 7's xrun evidence; ruling A22.)*
2. **`underflow_frames` stays monotone and still feeds `audio_io.underruns` unchanged.**
   `PipeWireAudioIO` reads this counter as a delta (`audio_io.py:569-570`); the counter never
   decreases and never resets while the stream is open, so no delta is negative. `audio_io.py` is
   **not edited** (it is T-0023's file, narrow mandate).
3. **`quantum_ms` is the negotiated graph quantum or it is declared unknown (F3).** The reported
   value is **not** derivable from the requested `blocksize`: it comes from the graph — the
   negotiated `node.latency` quantum of this process's `Stream/*` node in `pw-dump` (or an
   equivalent source the implementer justifies, e.g. opening with `blocksize=0` and re-blocking).
   When no negotiated value can be read, `quantum_ms` is `0.0` meaning *unknown* — never the
   request — and a new non-protocol attribute `quantum_source: str` carries `"pw-dump"` /
   `"callback"` / `"unknown"`. *(T-0006 criterion 1: "the module reports the negotiated quantum and
   the tests assert on the reported value, never on the requested one".)*
   **Cross-task consequence, stated:** `scripts/locked/audio_acoustic.py` (T-0023) puts
   `negotiated_quantum_ms` in its regime block; a `0.0` there now means "the graph would not say",
   which is honest and non-empty. T-0023 is told, not edited.
4. **An unknown node name is refused before the stream opens (F4, cheap half).** When `sink=` or
   `source=` names a PipeWire node that does not appear in `pw-dump`, `open_device()` raises a named
   error quoting the name asked for and the sink/source names that *do* exist. It never falls back
   to the default device. When no node name is requested at all (the plain-default case), no
   `pw-dump` call is made and behaviour is unchanged.
5. **The stream is proven to have landed on the requested node (F4, the half that matters).** After
   `start()`, when a node name was requested, the device finds this process's `Stream/Output/Audio`
   and/or `Stream/Input/Audio` node in `pw-dump` and checks its link peer against what was asked
   for, retrying for a bounded settle window (≤ 500 ms) because links are made asynchronously. A
   peer that is not the requested node — `auto_null` being the case the audit actually reproduced —
   raises a named error that prints *requested* and *actual*. If `pw-dump` is unavailable or fails
   while a node name was explicitly requested, that is also an error: an explicit request that
   cannot be verified is not honoured blindly.
6. **`sink ≠ source` has a mechanism, and it is a seam (F5).** `_pipewire_target` stops being the
   whole story. Ruling, so the implementer does not have to re-derive it: `PIPEWIRE_NODE` is
   per-process and a duplex stream has two halves, so it is reserved for the **input** half; the
   **output** half is placed after `start()` by linking this process's `Stream/Output/Audio` ports
   to the requested sink through the PipeWire graph (`pw-link`, present on this box; `pw-cli
   create-link` is an acceptable equivalent), and the placement is then verified by criterion 5's
   check. The single-target path stays **byte-for-byte unchanged** for the two cases that are
   measured and working: `source is None`, and `source` equal to the sink or to the sink's own
   `.monitor` (the null-sink rig, T-0021 criterion 9's bit-exact echo path). Placement is a named,
   injectable seam (e.g. `_place_output`) with the subprocess call behind it, so group B can replace
   the mechanism without touching a caller and so group A can test the policy without a graph. If
   placement cannot be performed or verified, `start()` raises — it never leaves the output half on
   the default sink.
7. **`ASTRA_AUDIO_SOURCE` means what every caller thinks it means (audit fact).** Today it is passed
   to `input_device`, i.e. a *PortAudio device name*, so the documented
   `ASTRA_AUDIO_SOURCE=astra-test-sink.monitor` cannot work — PortAudio's device list has no such
   entry. `ASTRA_AUDIO_SOURCE` becomes the **PipeWire node name** (→ `source`), and the PortAudio
   escape hatch moves to `ASTRA_AUDIO_INPUT_DEVICE` (→ `input_device`). `audio_device.py` is the only
   reader of either name in the tree (verified by grep at planning time); both are documented in the
   module docstring and printed by the smoke script.
8. **`scripts/demo/audio_smoke.py` — first contact in one command.** A new ungated demo script
   (`scripts/demo/` is D5-ungated: it produces no number anyone will quote). It opens the device
   through `audio_device.open_device()` — never through `sounddevice` directly — plays a 2 s chirp,
   and prints, in one block: the requested vs negotiated output/input latency, `quantum_ms` with its
   `quantum_source`, `underflow_frames` and `device_xruns`, the captured peak, the verified link
   peers of both halves, and the `pw-dump` sink/source node list. It prints the audit's
   discriminator verbatim next to the peak: **`peak == 0` ⇒ the target is absent (you are recording
   nothing); `peak ≈ 0.11–0.16` on a silent rig ⇒ you captured the webcam mic, not the monitor.**
   With `--dry-run` it performs no device I/O, so criterion 9 can exercise its report on a box with
   no PortAudio. Exit code is non-zero when the device raises or when the discriminator fires.
9. **The script is code, not a snippet.** `scripts/demo/audio_smoke.py` imports cleanly with no
   PortAudio installed (nothing device-touching at import time), passes `ruff` and — being under
   `scripts/` — is at minimum import-tested and `--dry-run`-tested by the fast suite. It opens no
   socket (the loopback-egress scan covers it).
10. **Negative criteria — what must not change.**
    a. The played clock is untouched: `rendered_ms()`, `queued_ms()`, `written_ms`, the DAC-lag
       estimate and the `_adc_base`/`captured_ms()` rule (T-0021 rulings A9/A19/A20) keep their
       current behaviour and their current tests pass **unedited**.
    b. `local_astra/conductor/audio_io.py` and `local_astra/conductor/audio_capture.py` are not
       edited (T-0023 holds them). If a fix here appears to need one of them, stop and say so.
    c. The `AudioDevice` protocol's **member set is unchanged**: `device_xruns` and `quantum_source`
       live on `PortAudioDevice` only, exactly as T-0006 did for `played_ms()`
       (`tests/unit/test_audio_capture_ownership.py` pins the protocol members and must pass
       unedited). `contracts/protocols.py` is not touched.
    d. `audio_device.py` remains the only module in `local_astra/` naming a sound library
       (`tests/unit/test_audio_ownership.py`), imports nothing device-side at module import, opens
       no socket, and the callback still allocates nothing and does no I/O — in particular **no
       `pw-dump` subprocess is ever launched from the device callback** (criterion 13,
       `.claude/rules/conductor.md`).
    e. The fast suite stays under its 120 s ceiling; the Stop hook's parallel run stays under 60 s.
       No test is deselected, skipped or marked `pending` to get there.

## Implementation notes

- **Landmines from `.claude/rules/conductor.md`:** the device callback runs off the event loop and
  must stay allocation-free and I/O-free. Every `pw-dump` call belongs to `open_device()` /
  `start()` / `stop()`, on the calling thread, never in `_stream_callback` or `_duplex_callback`.
  No asyncio in this module at all.
- `audio_device.py` is the only module in `local_astra/` allowed to name a sound library
  (`tests/unit/test_audio_ownership.py`). Importing `sounddevice` stays inside `start()`/
  `open_device()`; the new code adds `subprocess` + `json`, which is not a sound library but *is* an
  external process — keep it behind one small function so the tests can inject a recorded dump
  instead of shelling out, and so the pure parsers are testable without a graph.
- Keep the parsers pure: `parse_nodes(dump) -> …`, `parse_link_peers(dump, pid) -> …`,
  `parse_quantum(dump, pid) -> float | None`. Every criterion in group A that matters is then a
  table-driven test over recorded JSON, which is the only way this is testable before P1.
- The settle window (criterion 5) is a poll, not a sleep-and-hope: PipeWire links asynchronously,
  and a fixed `sleep(0.2)` will be flaky on a loaded box exactly when someone is debugging.
- Do **not** add an opt-out env var for the placement check. An escape hatch here is the failure
  mode: the whole point is that `auto_null` stops being silent.
- `underflow_frames`' meaning is a protocol contract read by `audio_io.underruns` as a delta
  (`audio_io.py:564-570`), and `audio_io.py` is **not yours** — if the counter's semantics change in
  a way that file would have to know about, that is a spec change: stop and raise it, do not edit
  `audio_io.py`.
- T-0021 rulings A9/A19/A20 (one ADC base, set on the stream's first callback even at 0.0; the span
  start is `captured_ms() + (written − rendered)`) are load-bearing and measured. Nothing here goes
  near them. `snd_pcm_link` returns `ENOSYS` on this box, so the duplex halves are unsynced but share
  the capture tstamp clock — that is the existing design, not a defect to fix here.
- `mypy --strict` covers this module. `subprocess.run(..., text=True)` output is `str`;
  `json.loads` gives `Any` — narrow it at the boundary rather than spreading `Any`.
- Audit facts that are **not** defects and must not be "fixed": JACK/ALSA stderr spew at
  `Pa_Initialize` (no jackd; `JACK_NO_START_SERVER=1` quiets it); `snd_pcm_status` delay is real
  (30–34 ms at a 30 ms request), so the DAC-lag maths holds; 48 kHz mono `FLOAT_LE` opens on
  `default` and fails on `hw:CARD=C925e` (16/24/32 kHz stereo only) — the smoke script should say so
  rather than the device working around it.
