## Goal

A live session without a search backend still declares `google_search` today: `--search off`, the profile's `search = "off"`, and the default-on search that falls back to off when it cannot start (`search_off` in `cli.build_session`). Every call gets "search is not connected in this session" (`toolcall/loop.py` `SEARCH_NOT_CONNECTED`); the T-0208 C shared arm went 0/9 that way (T-0211 Q3; docs/02 T-0211 B delta "Search off (finding)").

After this task such a session declares the live tool set without `google_search`, and its guidance carries no sentence that names searching. Today that is only `S_SOURCE_GUIDANCE` inside v4, including v4 chosen mid-session from the Settings panel through `guidance_table_of`. Live with search on, dry-run and tools off do not change by a byte.

## Acceptance criteria

1. In live with no search backend (the `--search off` flag, a profile `search = "off"`, or the degrade path), `kit.tools` names exactly the live set the session would otherwise have, minus `google_search`, for all four combinations of `page_overview` × `wait_tool`. The remaining declarations keep v1's order and are byte-identical to it (T-0211 Q3 option (a); the T-0140 R-p pattern).
2. In that session `kit.tools_version` is the sha256 of the bytes the declared set was built from, and `kit.tool_set` is that set, so the judge (`live.classify(..., tool_set=kit.tool_set)`) never returns `valid` for a `google_search` call (I13 in `test_tool_kit_version.py`: one `ToolSet` builds both tools and version).
3. Adversarial: in that session a model commit `call:google_search{query:…}` is never executed: no search backend is called, no `SEARCH_NOT_CONNECTED` payload reaches a continuation, and the call ends refused like any call outside the declared set.
4. The `--dry-run` tools line of a live session with search off shows the sha12 of the no-search set, and the real start's regime line shows the same sha.
5. With guidance v4 and search off, the session's tool guidance is v3 + " " + `S_SHARED_GUIDANCE` (plus the wait sentence when the wait tool is on). No guidance text contains `google_search` or "search" in the sense of web search; v3's "the current site's search box" stays. The same holds for every value `guidance_table_of` returns when search is off, so a Settings-panel switch to v4 cannot bring the sentence back.
6. Negative: live with search on is byte-identical to main at every combination of flags: the `load_tool_kit` call, `kit.tools`, `tools_version`, the guidance text and `guidance_table_of`. `load_tool_kit` receives exactly today's kwargs in that case ("the keyword only when on"), so every harness that calls it directly is unchanged.
7. Negative: dry-run (with or without `--search ddgs`) and tools off are unchanged. `load_payloads`, `load_calibration` and `warmup.CANONICAL_DRAFTS` / `warm_repair` are unchanged: payloads stay keyed to v1's sha, and warm-up still warms per payload automaton.
8. Negative: the `search` row in `settings_catalog.py` is not edited and stays truthful; its item still reports value `"off"` with its source.
9. docs/02 (orchestrator): the T-0125 delta's "Default and switch" sentence states the live exception, and the T-0211 B delta's "Search off (finding)" line is replaced by a short T-0215 delta.
