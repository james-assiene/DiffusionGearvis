# T-0113 (was T-0111a2) — Tool-result rendering for the loop: a pure renderer, a sanitiser, `step_prompt`, and the search backend contract

## Goal

Build the pure parts of the tool-result loop. Session wiring is T-0111a3, and the machine is T-0111a1. The parts:

- `render_call(name, arguments)` and `render_response(name, payload)`, byte-identical to the pinned Gemma 4 template (`36e3a42e…`, lines 118–173) as the oracle `tests/cd/oracle/gemma4_template.py` renders them;
- the sanitiser, which repeats `drop_special_literals` over every string until nothing changes;
- the response builders for each v1 tool and each status. These are the T-0111a §4 payloads: search with or without a backend, dry-run actions, refused, failed and timeout;
- the bounds: ≤ 5 results, snippets ≤ 300 chars, each response ≤ 1500 chars;
- `step_prompt(step1_prompt, steps)`, which returns the continued-assistant-message prompt (form G, H-T111a-10);
- the `SearchBackend` protocol and the `SearchResult` / `SearchResults` contracts. The fake backend is `tests/fakes/search.py`.

## Acceptance criteria

T-0111a criteria 10, 11, 12 and 13, verbatim:
- template parity;
- special-literal injection, including spliced literals, with `router.template_content(text) == text`;
- the bounds, and zero diff in `router.py`, `native.py`, `score.py`, `tools.py`, `tools_v1.json`, `live.py` and `tool_executor.py`;
- import hygiene.

In addition:
- **(14)** `step_prompt` keeps the step-1 messages, `tools`, `thinking` and `assists` unchanged, and sets `continue_final_message=True`. Its final assistant text ends with `<tool_response|>` after each executed step.
- **(15)** The new contracts follow the house contract rules (Pydantic v2, `contracts/`), and `tests/fakes/search.py` satisfies `SearchBackend` (`runtime_checkable`).
