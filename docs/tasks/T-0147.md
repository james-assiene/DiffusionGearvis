## Goal

Today, while a task is `in progress`, `scripts/check_pending.py::strong_claims` takes every `tests/**.py` path anywhere under its `## Owned files` heading as a structured claim. That includes paths in a "does not own" list. Through `module_owner`, such a claim outranks the done task that owns the module, so the Stop hook reports that module's failures as `expected: T-NNNN` instead of `regression:`.

The replay shows it. With `docs/tasks/` from `41093ec^` (T-0146 in progress, its not-owned list still inside `## Owned files`), the current scripts print `expected: T-0146 (1 failing in tests/unit/test_turn_invariants.py, implementer pending)` for a failing turn-machine invariant and exit 0.

After this task, the claims parser reads `## Owned files` with the rule that `bash .claude/hooks/_lib.sh owned-globs` uses for grants:
- only the first token of a bullet counts, with backticks stripped;
- the section ends at any heading or at a not-owned marker line;
- fenced blocks are skipped.

So the claims parser and the grants parser agree on what a task owns, and a parity test pins that agreement. `## Tests to write` keeps its whole-section scan (ruling A10) but stops at the same marker. The task changes no hook, no ownership precedence and no whole-file mention scan (ruling A1).

## Acceptance criteria

1. **The adversarial row: the T-0146 shape stays a regression** (docs/09 §2 "the prescribed red window"; T-0019 rulings A7/A10).

2. **Parity with the grants parser** (T-0029 "one parser"; this task's goal).
   - The rule: for every task file, the Owned-files part of `strong_claims(text)` equals the set of lines printed by `bash .claude/hooks/_lib.sh owned-globs <file>` that fully match a concrete `tests/…/*.py` path.

3. **The marker ends the Owned-files claims.** A path after a line containing any of `does not own`, `deliberately does not touch`, `ownership conflicts`, `claims no ` (any case) is not claimed. A path before that line is claimed. The same holds after a heading of any level (`### Not owned`, `## Not owned`).
4. **Only the first token of a bullet is a claim.** These are not claims:

   - a test path in a non-bullet paragraph under `## Owned files` (the T-0060 shape);
   - a test path inside a fenced block.
   A marker inside a fenced block does not end the section.
5. **The too-wide row: a module listed as owned and also in the not-owned prose is still claimed.** Setup: a module is an Owned-files bullet before the marker, appears again after the marker, and is also named in the Goal. 6. **Globs claim no module.** `- \`tests/**\`` and `- \`tests/unit/test_x_*.py\`` under `## Owned files` give no structured claim on `tests/unit/test_x_a.py`. The grant stays as it is; the claim only covers concrete paths.
7. **`## Tests to write` keeps its prose claims up to a marker** (A10, too-narrow guard). All of these stay claimed:

   - a path inside a bold heading line (the T-0108 shape);
   - `path::test_name`.
   A path after a non-fenced marker line in that section is not claimed.
8. **Negative: nothing else moves.**
   - (a) `claimed_modules` (the whole-file mention scan, A1) still returns every `tests/**.py` path in the file, including those in a not-owned list.

## Implementation notes

**Ruling (a): port the grants rule to Python; do not call `_lib.sh` or move it.**
- `owned_paths(task_text)` reproduces the heredoc parser in `owned_globs()` of `.claude/hooks/_lib.sh`:
  - the first `^\s{0,3}##+\s*Owned files\s*$` heading outside a fence (case-insensitive);
  - fenced lines are skipped, including any marker on them;
  - the section ends at `^\s{0,3}#{1,6}\s` or at a non-fenced line that matches the four-phrase MARKER (case-insensitive);
  - bullets are `-*+`; the first token has backticks stripped, then `,;:` stripped from the right, then a leading `./` removed;
  - the token must match the same SHAPE regex, have no `..` segment, and pass the "has `/` or `.` unless it is the bullet's only token" rule.
- Copy the regexes, do not reinterpret them. The parity test is the only thing that keeps the two copies together.
- Strong claims from Owned files are `{p for p in owned_paths(text) if _TEST_MODULE.fullmatch(p)}`. Globs never become claims (criterion 6), and nothing uses `fnmatch`.
- Why not call `bash _lib.sh owned-globs` at runtime:
  - `classify_failures.py` runs on every red Stop and would start one process per task file;
  - the sandboxes in T-0019's two modules copy only `check_pending.py` and would break;
  - `task_claims` takes text, not a path.
- Why not move the parser into `scripts/` and have `_lib.sh` call it: the grants parser would then sit in a file an implementer can own, so an implementer could widen their own grants. Grants stay in `.claude/hooks/`.
- The direction is fail-closed. Apart from the heading shapes the old `_SECTION` split missed (criterion 2, last corpus rows), the change only removes structured claims.

**Ruling (b): `## Tests to write` keeps the whole-section scan, cut at the marker.** Audit at 0bc60ff (18 in-progress and 18 planned task files):
- **Prose there is mostly real claims.** Examples: the paragraph-opening modules of T-0023 (`tests/integration/test_audio_acoustic_gate.py`, `tests/integration/test_audio_soak.py`), T-0043's multi-path bullets (`test_hud_hello_replay_wire.py` after `test_hud_hello_replay.py`), T-0047's second path (`test_assist_protocol.py`), and T-0108/T-0108b's bold headings. A first-token rule would drop these and block prescribed windows (the reason for A10).
