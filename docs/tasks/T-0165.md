## Goal

Today the HUD page calls `mountPanels(...)` and `socket.open()` in the same tick (`hud/src/main.js` 331–354). `panels.js` then imports and mounts the seven panels one after another (`for … await importer(spec); await module.mount(host)`). Any panel that mounts after the first `astra.hello` reply arrives misses that reply, including its T-0037/T-0090 journal replay:
- The Tools pane is empty after a reload during an open turn (the T-0162 C reviewer saw this 4/4 times).
- The ask box stays disabled for about 0.4 s after "connected".
- Two rows in `tests/integration/test_hud_text_mode.py` have been red on main since 6ecd2af9.

After this task the page opens its socket only once every installed panel has mounted, and it marks that moment on `<html>`. The page must also load fast enough that a reload still reconnects inside the server's `RECONNECT_GRACE_MS = 1000`. Two changes serve that: panel imports run in parallel (mounts stay in `PANEL_SPECS` order), and `HudStaticServer` loses its roughly 40 ms per-request keep-alive stall.

Nothing changes on the wire, in the server's journal semantics, or in the T-0162 reset order.

C4. **The reset replay order is kept** (T-0162 A-5, D-2).
- Setup: Restart, then a new open turn with one tool call, then a reload.
- The page applies the replayed `astra.session.cleared` first. The thread, cards and Tools pane are empty of pre-reset content, and the post-reset call is listed.

C5. **The socket opens even if mounting stalls** (T-0008 criterion 10: "a loader that throws leaves every other panel and the socket working", extended to a loader that never settles).
- A DOM-free helper in `hud/src/panels.js` decides when to call `open`. Proposed contract: `openAfterMount(mounting: Promise, open: () => void, { ceilingMs, setTimeout, clearTimeout, log })`.
- It calls `open` **exactly once**:
  - when `mounting` settles (fulfilled or rejected), or
  - when `ceilingMs` elapses, whichever comes first.
- On the ceiling path it logs one line. It never calls `open` before either event.
- `main.js` routes its single `socket.open()` (when `wsUrl` is set) through this helper.
- The ceiling value is open question Q1.
- Checked by node rows with injected timers.

C6. **Panel imports run in parallel; mounts stay in order** (T-0008 criterion 10; T-0162 B-1 "panes self-append in mount order").
- `mountPanels` starts every `PANEL_SPECS` import before awaiting any of them.
- It calls `mount(host)` in `PANEL_SPECS` order, each after the previous mount settled, even when imports resolve in reverse order.
- `{mounted, missing, failed}` keep their meaning and their `PANEL_SPECS` order.
- It never rejects.
- Every existing row in `tests/hud/panels.test.mjs` stays green, unedited.

C7. **Load work, counted** (the load-time measure; work, not wall time). Over one load of the page from `HudStaticServer`, from Chrome's CDP `Network` events:
- (a) Every URL under `hud/` is requested exactly once: no duplicate fetch, for example from modulepreload plus `import()`.
- (b) The seven panel entry modules are requested in one wave: each `requestWillBeSent` comes before the `loadingFinished` of all seven.
- (c) The serial depth of module requests is at most K. The depth is the longest chain in which each request starts after its predecessor's `loadingFinished`. K = depth of `main.js`'s static import graph + 1 (`panels.js`) + max depth of any panel's own static import graph + 1 (`index.html`). The test computes K by scanning the `import … from` statements under `hud/src/`, so it moves with the code.

  Today the depth is about the sum over the seven panels; with C6 it is about the max.
- These are ordering and count assertions. They must hold at any load average.

C8. **The keep-alive stall is gone** (T-0033 criterion 16).
- Setup: one HTTP/1.1 keep-alive connection to `HudStaticServer`, 30 sequential `GET /src/panels.js` requests. Each response is read fully by its `Content-Length`.
- At most 2 of the 30 take ≥ 35 ms (the Linux delayed-ACK floor is 40 ms; today about all 30 do).
- The record (assertion message) includes `os.getloadavg()` and the per-request times.
- Responses are byte-identical to the file. Status, `Content-Type` and `Content-Length` are unchanged.

- (c) `HudStaticServer` still:

  - returns 404 on traversal and 405 on write methods;

  Every existing row in `tests/unit/test_hud_static.py` stays green, unedited.
- (d) No new non-loopback socket and no fetch off loopback (the B8 / no-egress rows).
- (e) The server's journal semantics are unchanged: a closed turn's tool calls are still not replayed (T-0037 "never … a previous turn"), and `RECONNECT_GRACE_MS` stays 1000.

## Implementation notes

- **The reconnect-grace landmine.** `HudServer` reports the last page gone, and **clears the journal**, `RECONNECT_GRACE_MS = 1000` after the last socket closes (`hud_server.py` 723–746). Deferring `socket.open()` until after the mount lengthens the reload gap. With today's sequential imports over `HudStaticServer`'s ~40 ms per fetch, a reload can exceed the grace and replay nothing, the very bug C3 tests. So C6 and C8 are required for C3 to hold, not polish. Land all three together.
- **Reset tracking.** One reset tracker (`clears` in `main.js`) stays the page's source of truth. Panels keep seeding from `host.lastResets()`: after this task it is normally `null` at mount, but the C5 ceiling path can still mount a panel late, and the seam exists for that.
- **Hello.** `hello()` stays in `onOpen` (one per socket, reconnects included). Do not send it from the mount callback.
- **Ask box.** `ask/index.js` enables the box at mount from turn state alone (`form.enabled()` ignores the socket). C2 relies on that and on C1. Do not edit the ask panel.
- **`<html data-panels>`.** It is a test seam, not styling. Set it once, when mounting settles. On the ceiling path set it to something other than `"mounted"` (for example `"timeout"`) so C1 cannot pass vacuously.
- **Keep-alive stall.** The likely cause is two small writes per response, headers flushed at `end_headers()` and then the body, with Nagle holding the second until the client's delayed ACK. The stdlib offers `StreamRequestHandler.disable_nagle_algorithm`, or one combined write. Either fits mypy strict. Keep `protocol_version = "HTTP/1.1"`: keep-alive is what makes parallel module fetches cheap. Do not change binding, path resolution or refusals (`.claude/rules/` loopback rule; CLAUDE.md "all services bind to loopback").
- **No build, no fetch.** No bundler and no npm (T-0008 criterion 12). Parallelism comes from `import()` in `panels.js` (or modulepreload, see Owned files).
- **Tests stay as written.** Do not edit `test_hud_text_mode.py` or `open_page`. If C2's rows stay red after C1, that is a finding about C1 or C2, not a reason to add a wait (CLAUDE.md: change the behaviour or the spec, not the test).
- **Known limit, not fixed here.** A reload after the turn closed shows an empty Tools pane by design (the journal holds only the open turn). If James expects the pane to survive reloads across turns, that is a server/spec change (Q2).

**Open questions**
- Q1 (orchestrator/James): the C5 ceiling. Recommended: 3000 ms. That is above a cold load under load and well under a human's patience, but it exceeds `RECONNECT_GRACE_MS`, so a ceiling-path reload loses the journal. The alternatives are a ceiling below 1000 ms, which risks opening before slow panels on a loaded box, or no ceiling, which leaves the page dead if an import hangs.
- Q2 (James): should the Tools pane, and the thread, survive a reload after the turn closed? That needs the journal to keep the last closed turn, a docs/02 §5 T-0037 change in `hud_server.py`. Out of scope here; separate task if yes.
- Q3 (reviewer): should C8 also pin the mechanism structurally (`TCP_NODELAY` set on the accepted socket, read through a test-only seam)? The count row is behavioural and load-tolerant, but it is a timing row.
- Q4: the T-0159 follow-up "false `denoise_no_tap` if a whole turn fits inside the ~0.4 s load" is server-side and not addressed here. It may become rarer, not impossible.
