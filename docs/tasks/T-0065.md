## Goal
This task builds a device-agnostic PyTorch implementation, fp32 on the live path and fp64-capable for tests, of the
sum-product half of the method. It runs in log space end to end and has no vLLM import. It takes the step's logits
`[L, V]` at the schedule temperature (softcapped, as the sampler sees them) and produces:
- the per-position log transfer matrices `log M_i` (complement classes formed without subtraction)
- one log-semiring up-sweep that retains the aligned dyadic nodes (SPEC §2.6)
- log Z for a start **set** `A_k` and a budget terminal factor `b = 1[d(s) ≤ R]`
- the constrained marginals q and the per-position constrained entropy H(q_i)
- δ*(A, committed ids), which advances the state set across canvases

This is the exact numerical ground that the draw, the MAP (T-0066) and the Mar signal (T-0068) stand on.

## Acceptance criteria
1. **Exactness on tiny instances** against brute-force enumeration: V ≤ 6, L ≤ 8, |S| ≤ 5; DFAs, and NFAs with parallel
   overlapping labels; start sets that are not singletons; budget terminal factors. Tolerances:
   - fp64: |Δ log Z| ≤ 1e-10, max |Δq| ≤ 1e-12
   - fp32: |Δ log Z| ≤ 1e-4·max(1, |log Z|), max |Δq| ≤ 1e-6, |ΔH(q_i)| ≤ 1e-5 nats

   (SPEC §6.1)
2. **Differential against the float64 reference and `Fraction` oracles at production shape** on CPU. Shape: L = 256,
   V = 262 144, buckets 64 and 128, automata from T-0063 plus synthetic ones. Regimes:
   - temperatures 0.8 and 0.4 applied to softcapped logits `30·tanh(x/30)` (up to about 150 nats per position)
   - synthetic spans up to 250 nats
   - narrow negated classes with the model's mass inside `N_c`
   - the unscored tail
   - `L_eff < L`

   The fp32 per-position H(q) error must be no worse than 10× the fp32 error of the **stock** H(p) on the same logits,
   plus 1e-6. That makes the bar relative to what vLLM already tolerates. The q error has the same form.
3. **Non-subtractive complement (adversarial).** For a negated class whose complement set holds ≥ 1 − 1e-7 of the
   position's mass, the class log-weight matches the `Fraction` oracle within 1e-4 relative. The test includes the
   subtractive form `log(1 − Σ_{N_c} p)` as a control that is demonstrably red.
4. **No spurious Z = 0.** No instance with oracle Z > 0 returns `log Z = −inf`. This includes the two-band case, where
   the unscored tail sits at 0 and genuine paths sit about 850 nats below (the `live_simple_106-63-0` regime).
   `log(a_i·b_i)` is i-invariant within tolerance at every i (SPEC §2.4).
5. **No NaN/Inf** for inputs containing `−inf` (top-k-filtered) logits or finite sentinels. Forbidden tokens have q
   exactly 0 and contribute exactly 0 to H. H(q_i) ≥ 0.
6. **Budget.**
   - `b(s) = 1[d(s) ≤ R_after]` with `R_after = min(max_tokens − emitted, headroom) − L_eff`, and `L_eff = min(CL,
     valid_canvas_len, max_tokens − emitted)`.
   - Positions ≥ L_eff are identity (unscored) transitions.
   - Cases the tests hold: `max_tokens = 300` means the second canvas has `L_eff = 44` and must end in F; a large R
     means b is every live state; R = 0 means b = F.
   - `min_{s∈A} d(s) > max_tokens − emitted` is reported as a typed infeasible signal, either by a host check at
     `add_request` (A_0 is known on the host) or as a device flag read one sampler call later; never by a host sync
     on the per-step path (criterion 8).

   (SPEC §3.1b and §3.5 trap 1, including the off-by-one-canvas correction)
7. **δ\*.** It consumes the committed ids up to and including the first stop id; the tail after it is absorbed by the
   unscored tail. It returns a bool state vector. An empty result is reported and **never substituted** by the
   previous set (SPEC §3.1b, the closure-2 fix).
8. *Negative, hygiene:*
   - no `vllm` import
   - no use of the global RNG (this half is deterministic)
   - no synchronizing call (`.item`, `.cpu`, `.tolist`, `bool(t)`, `.nonzero`, `torch.cuda.synchronize`) inside
     functions on the per-step path, checked by spy tensors
   - at L = 256 and bucket 512, no single allocation exceeds 256 MiB (tracked with a `TorchDispatchMode`), so
     `[L/2, S, S, S]` is chunked, and retained tree levels total ≤ (2L−1)·S²·4 B

## Implementation notes
- SPEC's lessons are rules here:
  - log space throughout
  - normalise every tree node
  - edge-multiplicity weighting on NFAs, with an `is_dfa` fast path
  - `log(max(q, 1e-30))`
  - never build a class mass by subtracting two large sums; one non-subtractive route is a token → atom partition
    refining all class boundaries, with class mass as a logsumexp over atoms (the JAX kernel's
    `outside + sel @ gathered` is the same idea)
- **Landmine: TF32.** If a log-matmul is implemented as exp-shift-matmul, it must be exact fp32 whatever
  `torch.set_float32_matmul_precision` is globally, because vLLM may set "high". Tested on CUDA in T-0067 tier 2.
- fp64 is not an option on sm_120 (1/64 rate). fp64 exists here for tests only.
- Keep the API small and batched over constrained slots. The test-author fixes names at the first test pass, recorded
  as a ruling in this file (as T-0011 R1 did).

## Implementation notes (implementer, 2026-09-29; for the reviewer)
- **Criterion 2 needs a second, gauged pass in `constrained_marginals`.** A single fp32 log-space pass (log M → tree
  → down-sweep → q) missed the 10×-stock bar by 10–60× at bucket 128 (T 0.8/0.4, span250, narrow_neg, L_eff), because
  fp32 stores a log value to `ulp(|y|)` and posterior-relevant tree/vector entries sit tens to thousands of nats from any
  scalar anchor. Pass 2 rebuilds the leaves as `log M_i + β_{i+1}(s') − β_i(s)` with the integer gauge
  `β = round(log b)` from pass 1 (a Doob transform: rows near-stochastic, relevant entries within a few nats of 0),
  directly from split class masses (anchor differences and integer parts first, the near-0 fractional log-ratio last),
  and forms q in linear space. Cost: a second up-sweep and down-sweep, i.e. 2× the `S³` work of pass 1; `log_z`,
  `log_a`, `log_b` come from pass 1. T-0066/T-0068 consumers of the retained tree should know the tree the caller
  passes in is the ungauged pass-1 tree.
- Revision after review finding 1 (0.89 was seed luck; narrow_neg failed on 4/5 extra seeds): pass 2 is now
  compensated end to end on the fp32 path. `log_matmul(..., compensated=True)` (used only by pass 2's tree and
  down-sweep) carries the TwoSum error of every `A+B` into the exponent and corrects `log s` by its residual, and
  H(q) is `log S − Σ q̃·log q̃_c / S` on the unnormalised q̃ with pairwise TwoSum reductions over V
  (`log q̃_c = max(log q̃, log S + log 1e-30)`, i.e. the `log(max(q, 1e-30))` rule on the normalised q). Pass 2's
  elementwise work is ~2× pass 1's. Worst position / bar over 15 instances per (regime, bucket) — seeds 0–7 of
  the test's `-seed{k}` scheme plus 1–7 of a second salt scheme — on CPU, torch 2.13.0+cpu, L=256, V=262144:
  narrow_neg b64 0.68, b128 0.76; T0.4 b64 0.74, b128 0.80 (q ≤ 0.34 everywhere).
