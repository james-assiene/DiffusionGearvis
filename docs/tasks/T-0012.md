# T-0012 — Pixel-first assists: the assist state, the ingress filter, and the per-turn regime

**Status:** merged 2026-09-13 (7d5eb15; re-review MERGE, all mutations red) · **Blast radius:** medium · **Depends on:** T-0002 (merged), T-0005 (must be
merged before the integration test is activated) · **Blocks:** T-0012b (HUD assist panel), Q9

## Goal
Today "pixel-first" is a sentence in CLAUDE.md and a set of default-`False` booleans that nothing
owns, nothing enforces and nothing records. After this task the Conductor has one authority for
non-pixel assists: an `AssistState` that starts all-off, applies `astra.assist.toggle`, echoes
`astra.assist.state`, buffers assist text *only* for kinds whose flag is on, drops the rest at
ingress, and hands each turn a frozen `AssistFlags` snapshot; and `turns.jsonl` carries that exact
snapshot, so a latency or rubric number measured with DOM text on can never be compared to one
measured pixel-only by accident (docs/01 D12a, docs/12 §3, CLAUDE.md "every turn logs which were
on"). It also adds the pure focus-crop policy — the pixel-only mitigation for dense documents
(docs/12 §3) — as geometry and a magnification rule, so the crop decision is a tested function
before any capture path exists. The HUD checkboxes and badge are *not* in this task; see
"Out of scope".

## Acceptance criteria

Positive:

1. **All off unless ticked.** A freshly constructed `AssistState` has `flags == AssistFlags()`,
   `flags.badge() == "pixels"`, and `state_message()` is an `AstraAssistState` whose `badge` equals
   `flags.badge()`. No constructor argument, config key or environment variable can be the *only*
   reason an assist is on: the sole transition to on is an `astra.assist.toggle` message.
   (docs/01 D12a; docs/12 §3.)
2. **Toggle handling.** `toggle(AstraAssistToggle)` replaces the flag set wholesale with the
   message's `flags` and returns an `AstraAssistState` echo with `flags` and a `badge` equal to
   `flags.badge()`. Round-trips through `AstraMessageAdapter` unchanged (docs/02 §5).
3. **Ingress filter.** `accept_frame_text(AstraFrameText)` returns a `FrameText` when that kind's
   flag is on and `None` otherwise; a dropped message is counted per kind in a readable counter and
   is never buffered. This is defence in depth behind the prompt-side filter already pinned by
   `tests/unit/test_prompt_builder.py::test_only_the_assist_kinds_whose_flag_is_on_reach_the_prompt`
   (T-0005): an eager or buggy HUD must not be able to put text in front of the model.
4. **Turning an assist off purges what it captured.** After a toggle that clears `page_text`,
   `texts_for(at_ms)` returns nothing of kind `page_text`, including text buffered while it was on.
5. **Per-turn snapshot.** `freeze()` returns the `AssistFlags` used for a whole turn; a toggle that
   arrives after `freeze()` changes neither the returned snapshot nor `texts_for` results derived
   from it for that turn, and takes effect from the next `freeze()`.
6. **`texts_for(at_ms)` is the turn's assist payload**: at most one `FrameText` per kind, the newest
   at or before `at_ms`, only for kinds on in the snapshot, in a deterministic kind order; the
   buffer is bounded (same 60 s horizon as the frame ring, `.claude/rules/perception-memory.md`).
7. **Telemetry contract (the field).** `local_astra/telemetry/turns_log.py` gains
   `Regime.assist_flags: AssistFlags = AssistFlags()`, and `Regime` gains a validator requiring
   `assists == assist_flags.badge()`; a `Regime` constructed with `assists="pixels"` and
   `assist_flags=AssistFlags(page_text=True)` is a `ValidationError`. `Regime.with_assists(flags)`
   returns a copy with both fields set consistently and is the only sanctioned way to set them.
   (CLAUDE.md "state the whole regime"; docs/03 §7; Q9 docs/03 line 116.)
8. **One derivation, not two.** For a turn, `TurnRecord.regime.assist_flags == prompt.assists` and
   `TurnRecord.regime.assists == prompt.assists.badge()`, where `prompt` is the `Prompt` the request
   was built from — the badge is derived from the object that built the prompt, never from a second
   copy of the state that could have moved on.
9. **Focus-crop policy (pure).** `local_astra/perception/policy.py` gains
   `focus_crop_rect(frame_w, frame_h, *, window=None, pointer=None)` returning an
   `(x, y, w, h)` rect inside the frame, preferring the window rect over the pointer, preserving
   `CROP_BUCKET`'s aspect ratio, clamped to the frame; and `images_for_turn(full, crop)` returning
   `(full,)` or `(full, crop)` — never the crop alone — and rejecting a crop whose `crop_of` is not
   the full frame's `phash`. (docs/12 §3 "whole screen plus a high-resolution crop … as two
   images".)
10. **A crop that does not magnify is not sent.** `focus_crop_rect` returns `None` when the region
    would reach less than `MIN_CROP_MAGNIFICATION` (= 1.5, a policy constant, not a measurement)
    times the pixel density the full frame already gets after `target_size(...,
    SCREEN_BUCKETS[0])`, and when neither `window` nor `pointer` is given. A duplicate of the whole
    screen at 560 visual tokens is a pure cost.

Negative (what must *not* change):

11. **Pixel-only means zero assist content.** With no toggle ever received, a turn built from a
    frame plus `astra.frame.text` messages of all four kinds contains none of those payloads
    anywhere in the prompt, `prompt.assists == AssistFlags()`, and the record logs
    `assists == "pixels"` / `assist_flags == AssistFlags()`. This is the criterion that exists
    because "off by default" is the kind of default that silently flips.
12. **The wire is unchanged.** `ASTRA_MESSAGE_TYPES`, `CLIENT_TO_SERVER`, `SERVER_TO_CLIENT`,
    `AssistFlags`' field names/defaults and its badge strings are untouched;
    `tests/unit/test_contracts_roundtrip.py` and `tests/contract/test_protocol_codec.py` pass with
    no edit, and no fake in `tests/fakes/` changes (CLAUDE.md: a wire change would require both).
13. **The required-regime set is unchanged.** `test_telemetry.py::
    test_regime_requires_every_field_that_makes_a_number_comparable` passes unmodified — the new
    field is defaulted, not required. (If a future task wants `assists` required, that is a spec
    change to `docs/03` §7 and its own task, not an edit here.)
14. **Existing perception policy is unchanged.** `bucket_for` / `target_size` / `scene_changed`
    return exactly what `tests/unit/test_perception_policy.py` already asserts; screen frames still
    default to `SCREEN_BUCKETS[0]` at 1120 visual tokens.
15. **No new spans, no new sockets, no new writes.** `telemetry/spans.py` is not touched (this task
    adds no stage); nothing under `perception/` opens a socket or writes outside
    `~/.local/share/local_astra/` (`.claude/rules/perception-memory.md`, loopback test).

## Implementation notes
- Every contract is frozen (`ConfigDict(frozen=True, extra="forbid")`, `contracts/base.py`), so a
  snapshot is a reference, not a copy — but never rebind a field of a shared object and assume the
  snapshot moved; `freeze()` must return a value that later toggles cannot reach.
- The toggle message carries the **whole** flag set (`AstraAssistToggle.flags: AssistFlags`), so
  `toggle()` is a replace, not a per-kind merge. Do not invent a per-kind message.
- The landmine in the telemetry field is that `Regime.assists` already has a *plausible* default
  (`"pixels"`), so a forgotten assignment logs a false regime rather than failing. The validator
  plus `with_assists` exists to make forgetting impossible; single derivation from `Prompt.assists`
  (criterion 8) is what keeps the log and the prompt from drifting apart.
- `.claude/rules/perception-memory.md`: nothing under `perception/` opens a non-loopback socket or
  writes outside `~/.local/share/local_astra/`; the 60 s ring horizon is the shared constant.
- `.claude/rules/conductor.md`: a new stage would need a span name and a bench-reader change — this
  task deliberately adds neither (criterion 15).
- `mypy --strict` on `local_astra/`, ruff format; Pydantic v2 idioms (`model_validator(mode="after")`
  as used in `contracts/protocol.py`).
- Do not weaken or edit any existing test to fit the implementation. If the `Regime` validator makes
  an existing construction impossible, that is a finding for the reviewer, not a test edit.
- Keep `AssistState` free of asyncio and of `time`: timestamps arrive as arguments (`at_ms`), the
  same discipline the turn machine follows.

## Regime
No measured number is produced by this task, and none may be quoted from it. The regime it *fixes*
is the one every future number inherits: `turns.jsonl` now carries `regime.assists` (badge string)
and `regime.assist_flags` (structured), alongside the existing profile, canvas length, denoising
steps, thinking, vLLM/model/STT/TTS versions, audio path and seed. Q9 (docs/03 line 116, the
assists-on/off delta) and every B-series latency number are only comparable across runs once these
two fields are populated from the prompt; a run whose lines carry the defaulted `"pixels"` without
having gone through `with_assists` is not evidence of pixel-only operation.

Test regime for this task: fast suite only, any machine, no GPU, no `/launch`, deterministic
(no clock, no network, Hypothesis with its default profile and a fixed seed for the crop property).

## Amendments (2026-09-13, rulings on the test-author's eight ambiguities)

**A1 — the drop counter is `AssistState.dropped: Mapping[str, int]`**, keyed by assist kind,
zero for kinds never dropped. (Criterion 3 named no name.)
**A2 — `texts_for()` before any `freeze()` returns an empty tuple.** No snapshot means nothing is
admitted; a caller that forgot to freeze gets pixel-only, which is the safe default.
**A3 — the deterministic kind order is `AssistFlags` field declaration order.**
**A4 — clamping shifts inward first, and shrinks (keeping aspect) only if the region is larger
than the frame.**
**A5 — the pointer region is `CROP_BUCKET` at native size, centred on the pointer, then clamped
per A4.** On a 4K frame that magnifies well above 1.5x; on a small frame criterion 10 correctly
returns `None`.
**A6 — a foreign crop (`crop_of != full.phash`) raises `ValueError`.** Dropping it silently would
hide a wiring bug in whichever task sends it.
**A7/A8 — conventions, not properties**: "`with_assists` is the only sanctioned way" and "one
derivation" are enforced by the validator (a disagreeing pair is rejected) and by review of the
call site in T-0007/T-0011, not by a test. Stated so nobody writes a vacuous test for them.

## Rulings after review (2026-09-13, verdict REVISE → test-author, plus two implementer lines)

**A9 — the assist horizon is a window on the turn's time, not on the last ingest.** `texts_for(at_ms)`
returns only texts with `ts_ms >= at_ms - ASSIST_HORIZON_MS` (and `<= at_ms`). Today a 10-minute-old
DOM dump is returned as current context after the HUD goes quiet; criterion 6's "same 60 s horizon as
the frame ring" means the ring's semantics (a window on *now*). Implementer: one line in the read
loop. Test-author: a stale-after-silence case.
**A10 — the ingress filter fails closed.** `_is_on(flags, kind)` admits only `kind in ASSIST_KINDS
and getattr(flags, kind)`; a kind naming a method (`badge`, `any_on`) or an unknown name is
dropped and counted, never admitted. Implementer: the guard; test-author: the two probes.
**A11 — criterion 4 wins over criterion 5 on a mid-turn untick.** Unticking purges immediately,
including from the in-flight turn's payload; the frozen snapshot stays immutable (so the turn record
still says what was on at freeze). Pinned by a test; criterion 5 text amended: "the snapshot is
immutable; the payload is not".
**A12 — `tests/integration/test_pixel_only_default.py` moves to `tests/unit/`** (rename only; it
needs no service, 0.02 s). Criterion 11's headline test must run in the fast suite and the Stop
hook; the "Tests to write" entry naming `tests/integration` was wrong.

`dropped` has a zero entry for every kind (not `.get(k, 0)`); T5 A6 — foreign crop *raises*
