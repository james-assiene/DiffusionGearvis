## Goal

Today nothing between the model and the browser knows that a page is a checkout; the only stops are T-0160's password and card guards and the site's own sign-in wall. After this task, in web mode, the executor reads the agent browser's main-frame URLs itself (never sending them to the model or the logs). Once the browser has reached a checkout page, every further page action is refused, and the turn ends at once with a fixed system clip handing the purchase back to the user, who can finish it in the headed browser window. Searching, browsing, adding to cart and attempting CAPTCHAs work as before.

Confirmed in source (planner): the egress proxy sees only `CONNECT host:443`, and `resolved.hosts` for the demo's cart/checkout clicks read `www.google.com`, `images-na.ssl-images-amazon.com` or nothing, so hosts cannot detect checkout; `PlaywrightDriver` already records main-frame navigation requests/commits per page (`_on_nav_request` / `_on_frame_navigated`, runtime.py 636-689); Amazon's "Proceed to checkout" goes to `/checkout/...` then redirects to `/ap/signin`, so every main-frame request during the action counts, redirect hops included; an executor refusal does not end the turn today (`_run_execute` 6217-6223, `turn_machine._on_tool_result` R12); the loopback suite's S13 starts on `/checkout.html`, so the guard is web mode only; URLs in logs are host-only already (T-0162 C-1).

## Acceptance criteria

### Group A — detection and refusal (`fence.py`, `runtime.py`, `executor.py`)

A1. **The predicate.** `fence.checkout_url(url: str) -> bool` is pure and stdlib-only. It is `True` exactly when, for an `http(s)` URL: (a) a path segment matches `checkout`, `checkouts`, `checkoutnow`, `payment`, `payments`, `pay` (case-insensitive, after one percent-decode, after removing at most one trailing `.html`/`.htm`/`.php`/`.aspx`/`.jsp`); or (b) a segment `buy` comes right after a segment `gp`; or (c) the host's leftmost DNS label is `checkout`, `pay` or `payments`. Query and fragment are never read. An unparseable URL is `False` (the current URL is always present, A2).

A2. **The seam.** `PlaywrightDriver` gains a synchronous `main_frame_urls() -> tuple[str, ...]`, looked up on the driver's class like `focused_field` and `navigation_mark`, returning every main-frame navigation request URL since the previous call (redirect hops included, covering any page that became active in between), with the active page's current main-frame URL (`page.url`) last. Reading drains the store. It runs nothing in the page, reads no DOM or text, uses no CDP. Only the executor calls it, and the executor passes only booleans onward.

A3. **Refusal on a checkout page.** In web mode, with a driver class that has `main_frame_urls`, every `execute()` reads it after `ensure()` and its restart/page-serial checks, before any dispatch. If any returned URL is a checkout, these are `refused` with `CHECKOUT_REASON = "this is a checkout page; the user finishes the purchase themselves"` and nothing is dispatched or captured: `click_at`, `type_at`, `scroll`; `press_key` except the start-page combos `Ctrl+T`/`Ctrl+L`; `page_overview`; the T-0151 overview-frame path. If the read raises, the call is refused the same way (fail closed).

A4. **Arrival.** For an executed action in web mode, the executor reads `main_frame_urls` again after the action's last settle and before the post-action capture (where T-0174's `navigated` is read). If any URL is a checkout, `resolved["checkout"] = True`; absent otherwise; never a URL, path or host. Includes a checkout passed only as a redirect hop, a checkout popup the settle adopted, and a same-document `pushState` to `/checkout`.

A5. **The add-to-cart path stays open (negative).** No refusal and no `checkout` on `/cart`, `/gp/cart/view.html`, `/cart/smart-wagon`, `/gp/aws/cart/add.html`, `/gp/buyagain`, `/checkout-faq`, `/payment-methods`, `/s?k=checkout`, `/ap/signin?openid.return_to=…%2Fcheckout…`, `#checkout`, `checkout-help.example`, `shop.checkout.example`. Action strings, model-facing tool responses, `tools_v1.json` and `tools_v1_overview.json` are byte-identical to a9a11add.

A6. **CAPTCHAs are neither blocked nor helped (negative).** No code path names or detects a CAPTCHA; only main-frame URLs are read (a reCAPTCHA iframe is ignored); Google `/sorry/index`, Amazon `/errors/validateCaptcha` and `/ap/cvf/…` are not checkouts; T-0160's guards are unchanged.

A7. **Unchanged outside web mode (negative).** With `web=False`, `main_frame_urls` is never called and dispatch sequences equal a9a11add's (incl. the T-0138 suite's S13 on `/checkout.html` and every BASE fake driver). A web-mode fake driver without the method runs BASE's path; one row pins that the real driver has it.

A8. **No URL leaves the executor (privacy).** A unique token in a checkout fixture path appears in no `ToolOutcome` (`action`, `reason`, `resolved`), no `take_events()` entry, no `egress_log` entry, no exception message. `reset_page()` from a checkout page still reaches `/web.html`; a checkout page does not refuse Restart.

### Group B — the hand-back ends the turn (`events.py`, `commands.py`, `turn_machine.py`, `session.py`, `clips.py`)

B1. **Contract.** `events.ToolResult` gains `hand_back: Literal["checkout"] | None = None` (still no text). `commands.ClipKind` gains `"at_checkout"`. `session.CLIP_TEXT["at_checkout"] = "I've reached the checkout, so I'll stop here. Over to you to finish the purchase."` `clips.ENDING_KINDS` includes it (played by default; doctor reports it).

B2. **Machine row (docs/02 §4 spec delta).** `tool.result(call_id = awaiting_result, hand_back = "checkout")` in THINKING while a result is awaited with the loop on → IDLE with: cancel `tool_result`; no `llm.continue`; `play_clip(at_checkout)` (T-0178 B2's ending tuple for any `still_working` clip playing); `commit_history(user_only = false)` over the joined played text; `schedule_summary`. Same at any step, including after the last allowed execute (no `out_of_steps` instead). Any other `tool.result` with `hand_back` is inert (R13).

B3. **Invariants (never weakened).** L7 (reaches IDLE); L10 extended (at most one ending clip per turn); L1/L3 (no `llm.continue` after a hand-back); H8/L6 (the clip never enters history); L8 (loop off equals the frozen post-T-0191 machine); new differential: with no `hand_back`, the machine equals the frozen a9a11add machine.

B4. **Session.** With the live browser, `_run_execute` submits `hand_back = "checkout"` for an `executed` outcome with `resolved.get("checkout") is True` (exact `True`), or a `refused` outcome whose reason is `CHECKOUT_REASON`. The HUD card is the usual one; the `tool.result` log row gains `"hand_back": "checkout"`; the turn line's `tool_loop_end` is `"handed_back"`. No URL, path or page text is logged. No browser / dry-run: nothing changes.

B5. **The next turn.** An action asked for while still at checkout is refused (A3) and hands back again (B4). The user navigates in the browser themselves, asks for the start page (Ctrl+L/Ctrl+T), or presses Restart.

B6. **Desk check (report-only, James, via `/launch`).** A live headed session with web on: "Buy <item> on Amazon" ends with the `at_checkout` clip at "Proceed to checkout"/"Buy Now", and the HUD shows no further action. Never on an account with a saved card.

## Implementation notes

- Pixel-first: no URL, path, title or DOM reaches a prompt; reading `page.url` and navigation request URLs is browser state used as a safety input to the executor only (A8).
- Add URL recording to `_on_nav_request` / `_on_frame_navigated` (already main-frame filtered). Redirect hops: Playwright emits a `request` per hop (`redirected_from`); in web mode public URLs go through `route.continue_()`; row (b) proves it — probe first if it fails.
- Pre-dispatch read where `PAGE_CHANGED_REASON` is checked (executor.py ~680-684); post read beside `_navigated(mark)` (~696); `_execute_overview` / `_act_on_overview` need the pre-dispatch check too. `main_frame_urls` has its own drain; URLs never go into `_report(events)`.
- The machine stays pure; B2 mirrors T-0178 B2's ending tuple; reuse `_commit_played` / `_end_turn`.
- Clips are system audio, never history. Until `diffusion_gearvis render-clips --kinds at_checkout` (CPU, data dir) runs, the clip plays as zero-length audio and doctor WARNs: rendering is a release step.
- No prompt change.
- Known over-wide case (H-T192-3, accepted): a user who passes through checkout by hand between turns and returns to the cart gets the next action refused once (the drained URLs include the checkout). Not covered: checkout shapes A1 doesn't match (`/order/place`, an SPA with an unrecognised path); T-0160's card/password guards still stand behind it.
