# T-0087 — What the live stream carries for a native tool call (GPU probe)

**Status:** done (ran at 724c0c4; reading B) 2026-10-12; in progress 2026-10-11 (tests at 8983e2b); planned 2026-10-11 · **Blast radius:** high (GPU; `/launch`; two reviewers) · **Branch:** `T-0087-native-stream-probe` from
`main` · **Depends on:** nothing · **Blocks:** T-0088 (its design rides on the reading). Umbrella `T-0080d.md`.

## Goal
Measure, on the pinned engine, what a streaming native pass 1 delivers to a client that reads `content`/`reasoning` (as `llm_client` does),
not host-decoded ids. Measure the other facts the live path needs:
- whether the prefix cache covers the `tools` field;
- whether a T4 continuation is accepted with string and with list content;
- what the final chunk says about the stop;
- whether `/tokenize` agrees with the pinned tokenizer.

The output is a pre-registered reading (A or B) that T-0088 is built on.

## Acceptance criteria
1. **The harness.** `scripts/gpu/t0080d_native_stream_probe.py` sends to the loopback engine only, with `main(argv) -> int`.
   - **Cases.** 12 fixed case ids from the dev split of `tests/eval/toolcall/cases.jsonl` (sha `460cd1c3…`, checked): 2 per tool and
     2 no-tool. The ids are listed in the script.
   - **Pass-1 body.** Built with `twopass.native_pass1_body` plus `stream: true`.
   - **Arms.** For each case:
     - (a) default;
     - (b) `skip_special_tokens: false`;
     - (c) (b) plus `spaces_between_special_tokens: false`;
     - (d) (b) with `stream: false` and `return_token_ids: true`;
     - (e) (b) with `stream: true` and `return_token_ids: true`.
   - **Output.** Everything goes to `logs/t0087-probe-<sha>/`: raw SSE lines, with request image data URLs replaced by `{bytes, sha256}`,
     plus `report.json` and `report.md`. The tree must be clean.
2. **Recorded per arm and case:**
   - **q1:** HTTP status.
   - **q2:** whether the stream completes.
   - **q3:** whether `reasoning` is separated. In (d), `reasoning` equals the thought region of the host decode of the same response's
     ids (`replay.detokenize`), and no thought text appears in `content`.
   - **q4:** whether `content` is byte-identical to the answer region of that host decode (d), or of the per-chunk ids (e). This covers
     `<|tool_call>`, `<tool_call|>`, `<|"|>` and any stray `<channel|>`.
   - **q5:** `finish_reason` and `stop_reason` on the final chunk, and whether id 50 is in the ids or its text is in `content`.
   - **q6:** SSE chunks per canvas, and whether any special piece's text is split across two chunks.
   - **q7:** whether (e) carries per-chunk `token_ids`.
3. **Prefix cache (q8).** On 3 tool cases, measured as the `/metrics` delta:
   - a prefill with `tools` (`max_tokens` 1) followed by the generate request with identical `tools` hits at least 0.9 of the prefix
     (B11 rule);
   - the control, a prefill **without** `tools`, then the same generate request, is reported (an expected miss).
4. **T4 continuation (q9).** On 3 tool cases, a non-stream continuation with the assistant content `spoken_prefix + "<|tool_call>"` sent
   as a plain string, and the same content as a single `[{"type":"text",...}]` part. For each: the status, and whether the served prompt
   ids end in 48.
5. **`/tokenize` parity (q10).** For the 10 tool cases' draft call texts from arm (d) (`router.route` on the host decode), the engine's
   `/tokenize` (`add_special_tokens: false`) ids equal `vocab.encode(draft.rstrip())`. The exact path (`/tokenize` or `/v1/tokenize`) and
   its body are recorded.
6. **Pre-registered reading, written before the run.**
   - **Reading A** holds iff all of these hold:
     - (b) or (c) is 200 on all 12 cases;
     - q3 holds on all;
     - q4 is byte-identical on all 10 tool cases for that arm;
     - q6 shows no split special piece.
     T-0088 then sends that arm's fields; it prefers (b) when both qualify.
   - **Reading B** applies otherwise: T-0088 is replanned on streamed token ids (q7) with host detokenisation (H10), before its
     test-author starts.
   - **Stop id.** It is `stop_reason` if q5 gives an int in {1, 106, 50} on every tool case. Otherwise T-0091 is replanned.
   - **Tools in the prefill.** Required iff q8 shows at least 0.9 with them.
   - **Continuation content.** T-0091 uses string content if q9 accepts it with the prompt ending in 48.
   - **Seed tokenizer.** It is `/tokenize` iff q10 is equal on 10/10; otherwise H9's alternative.
7. **Write-up.** `docs/cd/toolcall-live-probe.md` contains, from the report only:
   - the regime;
   - the table q1–q10;
   - the reading;
   - two anonymised SSE excerpts (one tool case, one no-tool case).
8. *Negative.* No change under `local_astra/**`, `plugin/**` or `services/**`. Stored artifacts are unchanged. Only loopback is used.
