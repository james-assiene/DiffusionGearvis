## Goal

1. **Close a safety gap (A).** James's ruling: "typing into a focused plain div/canvas: no". In web mode a focused `<canvas>`/`<div>` reads `unreadable` and is refused. But a click on a canvas that cannot take focus (the three.js viewport, most WebGL apps, games) leaves the focus on `body`, which is in `_TYPABLE_TAGS`, so `type_at` sends every character to the page's document `keydown` handlers. In the three.js editor, typing "Crate" over the viewport fires single-letter shortcuts instead of naming anything (unverified at the pin: `r` = scale, `e` = rotate), and the model is told it "typed 5 characters". After A that `type_at` is refused with the unreadable-focus reason and nothing is typed.
2. **A Blender-like web app Gearvis operates (B, C, E).** B: a pinned loopback copy of the three.js editor (MIT) with a state shim and a pure judge; five spoken modelling tasks through the real web executor with a fake LLM. C: the real model on them on the GPU. E: on Monday Gearvis edits a 3D scene in the real threejs.org editor at the desk.
3. **Optional colour (D).** `<input type="color">` opens a native picker that screenshots never show; with D, `type_at` of `#rrggbb` into a colour input sets the value.

**What does not change:** one image source per step; no downloads or uploads, no sign-in, no card or password typed; checkout stop, submit stop and the T-0206 Enter withhold; `press_key` (H-T210-2); outside web mode a `body` focus is typed into as at BASE; prompt, live guidance, labels, turn machine, contracts, session, cli, config; `pages/server.py`, `pages/static/**`, `pages/scenarios/**`, `pages/suite/**`, `pages/handoff/**`, `pages/rtx*`; no new network path in code.
