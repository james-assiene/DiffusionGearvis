# T-0068 — Per-step arms: Mf, Mar (the paper), Mar with constrained self-conditioning; the multi-canvas guarantee

**Status:** merged into the integration branch (tier 1); tier 2 pending · **Blast radius:** high (two reviewers) · **Branch:** `T-0068-cd-perstep` · **Depends on:** T-0067 and T-0072 merged (`cd/sampler.py` and the core modules are handed over from T-0072; the per-step path uses T-0072's pass-through keywords); criterion 8 (tier 2) also depends on T-0073 — H(q) on CUDA is not evidence before it merges

## Goal
Constrained slots can run the paper's loop at every denoising step:
- the **joint draw** x̂ ~ p(x | C) is fed back where accepted, with uniform renoise elsewhere (R0)
- acceptance and the mean-entropy convergence signal use **H(q)** (Mar) or stock H(p) (Mf)
- history, stability and commit use the **constrained MAP**
- optionally, the self-conditioning embedding is `q @ E` instead of `p @ E`

Across canvases the guarantee holds: every commit leaves a viable prefix within budget, and every terminated output is
accepted.

## Acceptance criteria
1. **Arm semantics.** Per constrained denoise step, with positions ≥ L_eff treated as stock (they are never committed):

   | | `perstep_mf` | `perstep_mar` | `perstep_mar` + `self_conditioning=constrained` |
   |---|---|---|---|
   | fed-back canvas | `where(accept, x̂, uniform ids)` | same | same |
   | accept rule (stock EntropyBound: Σ sorted − cummax ≤ bound) on | H(p) | H(q) | H(q) |
   | `confident` = mean over CL of | H(p) < threshold | H(q) < threshold | H(q) < threshold |
   | history / `argmax_canvas` / commit | constrained MAP | constrained MAP | constrained MAP |
   | `sc_embeds` | stock p·E | stock p·E | q·E (stock normalizer, `sc_keep` from CD's own convergence) |

   Further requirements:
   - `bound` and `threshold` come from the request, else stock (0.1 and 0.005 from `generation_config.json`).
   - Convergence = stable MAP history over ST, and `confident`, or the step cap.
   - At convergence, `canvas ← MAP`.
   - Uniform ids come from CD's generator, never the global RNG.

   Tests use hand-built expectations with H(q) from the fp64 oracle.
2. **Mar is not Mf (both directions, tests.md guard rule).** At a position where the grammar forces the token (high
   H(p), zero H(q)), Mar accepts and Mf does not. On an instance where every per-position support is the full
   vocabulary, the two accept masks are identical.
3. **Multi-canvas guarantee (CPU simulation).** The vendored stock step, the CD sampler and a fake scheduler trim at the
   first stop id, at `max_tokens` and at `valid_canvas_len`. Runs: 2000, over T-0063's BFCL and Sudoku automata and
   synthetic NFAs, with random and adversarial logits, `max_tokens ∈ {256, 300, 512, 768}`, all three per-step arms and
   `end_projection`. Required:
   - after every commit, `δ*(A_k, committed) ≠ ∅` and `min d ≤` remaining budget (viable prefix)
   - every terminated output's full id sequence is accepted by host replay
   - zero loud errors on feasible instances
   - termination by `max_tokens` at the latest

   (SPEC §3.1b proposition)
4. **Adversarial logits.** A model that prefers EOS at position 0, `<turn|>` inside strings, and PAD everywhere after a
   stop still produces output in C. With the unscored tail, the MAP's stop position follows the model and does not
   cluster at CL − 1: the recorded `stop_pos` distribution on a fixture where the model ends at position ≤ 40 has a
   median ≤ 40.
5. **Convergence sanity.** On a literal-only automaton (a single string), `perstep_mar` converges within ST + 1 steps
   and commits the literal. `perstep_mf` on a grammar that admits the stock argmax converges in the same number of
   steps as stock on a deterministic fixture.
6. *Negative:* T-0067 criteria 3, 4 and 9 are re-run with the per-step arms active in the constrained slot, and stay
   green. Criterion 4's bit-identity is compared only over the sampler calls in which both runs schedule the same set of requests (the stock `_compiled_sample_step` draws `torch.rand_like` over the whole `[num_decode, CL, V]` batch, so any change in the scheduled set shifts every slot's noise); per-step arms end at different calls than
   stock, so the window closes at the first call where the scheduled sets differ.
7. **Records** fill T-0064's `CdCanvasRecord` fields for the per-canvas mean accepted count per step and the step
   count, which calibration (T-0071) needs. The schema is not changed here.
8. **Tier 2** (container, `-m gpu`, `/launch`, no engine): the peak added device memory of a `perstep_mar` +
   constrained-SC step at CL 256 is ≤ 1.5 GiB at bucket ≤ 256; criterion 1 repeated on CUDA.

## Implementation notes (implementer, 2026-09-30)
- **Shape.** Same as T-0067's wrapper: stock runs on the whole batch, so the unconstrained slots and the global RNG
  stay stock's. For a per-step slot, `steps.prepare` runs before the inner call on the pristine logits. It takes
  them at stock's temperature for the entry step (P3) and computes H(p), the class masses / class max once (T-0072
  pass-through), and per `L_eff` candidate: tree, joint draw, MAP, and (Mar only) the marginals. It also builds the
  accept mask, `confident`, the fed-back canvas and the SC embedding. `steps.write`/`steps.finish` run after the
  inner call. They overwrite the slot's history row (MAP), phase, `argmax_canvas`, `canvas`, `confident` and
  `sc_embeds` with `torch.where` on the entry phase. There are no host syncs. Mf skips the marginals, since it
  never reads q.
- **Commit calls pay too.** The host cannot know a slot's phase, so the per-step work also runs on commit calls,
  where it is discarded. That costs about one extra per-step computation per canvas.
- **P1 / P13 in `requests.py`.** `SERVED_MODES` now includes `perstep_mf` and `perstep_mar`. The
  `entropy_bound`/`confidence_threshold` refusal applies to `end_projection` only. logprobs/top_k/top_p stay refused
  for every constrained arm. The earlier `steps.admit` workaround is deleted.
- **Budget spent ⇒ no z0.** After `emitted ≥ max_tokens`, `L_eff = 0` and `R_after < 0` make Z = 0 by construction.
  The engine commits nothing more at that point. The every-step z0 check (P10) is therefore gated on
  `emitted < max_tokens`. Without the gate, a request the scheduler keeps after its last canvas (as
  `test_tightest_feasible_budget_does_not_trip_for_perstep` does) ends loudly. end_projection is unchanged.
  **Latent end_projection case (not changed here):** end_projection checks z0 only at a converging step, without
  the budget gate. If the scheduler kept a request whose budget is spent and it converged again, that step would
  report `z0` (L_eff = 0, R_after < 0 ⇒ Z = 0). A real engine ends the request at `max_tokens` first, so this has
  not been observed. The fix, if wanted, is the same `emitted < max_tokens` gate; that is its own change.
- **Report header** grows by one int64: the canvas's accepted-count sum, which is 0 for end_projection.
  `mean_accepted_per_step = sum / steps` is computed on the host at read time.
- **Generator.** There is one `torch.Generator` per device per sampler, seeded with a fixed constant
  (`steps.GENERATOR_SEED`).
