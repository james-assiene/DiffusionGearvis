# T-0003 — Turn machine + §4 invariants

**Status:** merged 2026-09-13 (3a553ea; 83 tests, mutation-verified at merge) · **Blast radius:** high · **Depends on:** T-0002 (seeded; the Realtime-model
remainder is not needed here)

## Goal
`local_astra/conductor/turn_machine.py::TurnMachine.step` becomes the real implementation of the
docs/02 §4 transition table: a pure `step(state, event) -> (state, commands)` with time arriving
as `Tick`, no I/O, no clocks, no asyncio, and the §4 properties holding as Hypothesis stateful
invariants. `local_astra/contracts/turn.py::MachineState` grows the fields that make those
transitions expressible (pause onset, endpoint-flush marker, unspoken committed tail, the buffer
for words whose audio time falls after the endpoint). After this task the Conductor has a
testable turn policy that `session.py` (T-0007) only has to execute: nothing in the machine
speaks, aborts, sleeps or logs — it returns data. This is the first task of the implementation
loop (docs/09 §9.2) and its pending tests are its spec.

Two deliberate spec deltas relative to docs/02 §4 are implemented here and must be carried back
into docs/02 by the orchestrator via `/spec` (not by the implementer): the `any | tts.error` row
is narrowed to the speaking states (criterion 20) and an `stt.error` row is added (criterion 20).
The `concatenate_transcript` command named in the §4 table is *not* added — it is internal state
(criterion 15).

## Acceptance criteria

Numbering is stable; tests cite it. "In order" means the relative order of the named commands
inside the returned sequence; implementations may interleave `hud.state` and timer commands.

1. **IDLE + `UserSpeechOnset` → LISTENING** (§4 row 1) emitting, in order, `CaptionerAbort`,
   `SnapshotFrame(at_ms=ev.onset_ms)` (the onset frame, not the latest), `PrefillOpen(request_id)`.
   Afterwards `active_prefill == request_id`, `active_generate is None`, `turn_seq` incremented
   and `turn_id` derived from it deterministically. `CaptionerAbort` implements
   `.claude/rules/conductor.md` ("the captioner is aborted on speech onset", test-plan I8).
2. **LISTENING + `SceneChanged` → LISTENING** (§4 row 2) emitting `SnapshotFrame(at_ms=ev.t_ms)`
   then `PrefillReissue(request_id=active_prefill)`; `active_prefill` is unchanged (rate limiting
   is the executor's job). *Negative:* `SceneChanged` in any other state returns the state
   unchanged and an empty command sequence.
3. **LISTENING + `SttEndOfTurn` → ENDPOINTING** iff `ev.p_end >= policy.eot_p_threshold`
   (new `TurnPolicy.eot_p_threshold = 0.6`, docs/01 §8 "EMA of pause probability > 0.6"),
   emitting `FreezeAfter(ev.t_eot_ms)` and setting `state.t_eot_ms`; below the threshold the
   state and commands are unchanged. No `LlmStart` is emitted on this row.
4. **Word attribution is by audio time, never by state-entry time** (§4 prose; docs/03 §3
   "a word that arrives 0.5 s late is attributed to the turn whose onset window contains its
   audio timestamp"). While LISTENING every `SttWord` is appended to `state.words`. Once frozen
   (`state.t_eot_ms is not None`), a word with `start_ms <= t_eot_ms` is appended to
   `state.words`; a word with `start_ms > t_eot_ms` is appended to a new
   `MachineState.next_words` buffer **in any state**, and the buffer seeds `state.words` of the
   next turn opened by criteria 1/15/19, then empties. Both sequences are capped at
   `policy.max_buffered_words` (new, default 256), dropping oldest first.
5. **ENDPOINTING + `UserSpeechOnset` → LISTENING** (§4 row 5) emitting `Unfreeze`; `t_eot_ms` and
   the flush marker are cleared, `state.words` is preserved.
6. **ENDPOINTING → THINKING requires both signals** (§4 row 6): an `SttFlushed` whose
   `t_eot_ms == state.t_eot_ms` (the moshi `Marker`, i.e. "all words ≤ t_eot delivered") **and** a
   later `Tick` with `t_ms >= flush_t_ms + policy.eot_settle_ms` with no `UserSpeechOnset` in
   between. A `Tick` before either signal changes nothing. On the transition the commands are, in
   order: `CheckOwner(from_ms=state.onset_ms, to_ms=state.t_eot_ms)` — emitted **iff**
   `t_eot_ms - onset_ms >= policy.owner_check_min_speech_ms` (new, default 1500; docs/01 D7:
   speaker embeddings need ≥ 1.5 s) — then `PrefillAbort(active_prefill)`, then
   `LlmStart(request_id, transcript)` where `transcript == " ".join(w.text for w in words)` in
   `start_ms` order. Afterwards `active_generate` is that request id, `active_prefill is None`,
   and the `llm_timeout` timer is armed at `ev.t_ms + policy.llm_timeout_ms`.
7. **Acknowledgement clip** (§4 row 6 `decide_ack`, docs/01 S6/D11): `PlayClip(kind="ack")` is
   emitted immediately after `LlmStart` iff `policy.thinking` **or** `state.first_canvas_ms is
   None` **or** `state.first_canvas_ms > policy.ack_first_canvas_ema_ms`; `fillers_this_turn` is
   incremented. At most one `PlayClip` per turn is emitted by this machine, never after a canvas
   has committed in that turn. *Negative:* no `PlayClip(kind="hmm")`, no
   `PlayClip(kind="still_working")`, and `ArmTimer(name="interim_update")` is never emitted —
   those belong to T-0013.
8. **First-canvas EMA** (docs/01 §8 "an acknowledgement clip keyed to an EMA of first-canvas
   latency"): on the **first** `LlmCommit` of a turn whose `request_id == active_generate`,
   `state.first_canvas_ms` becomes `round(a * measured + (1 - a) * prev)` with
   `measured = ev.t_ms - <t_ms of the LlmStart of this turn>`, `a = policy.first_canvas_ema_alpha`
   (new, default 0.3) and `prev = measured` when it was `None`. Later commits of the same turn do
   not update it. The field keeps its name; its docstring in `contracts/turn.py` states that it is
   the cross-turn EMA.
9. **THINKING + `LlmCommit(segment="answer", thought_open=False, request_id == active_generate)`
   → SPEAKING** (§4 row 9). `state.committed_answer` is the exact concatenation of such commit
   texts (no whitespace normalisation, no reordering). The machine emits one `TtsSpeak` per
   sentence returned by the segmenter (criterion 10), in order, with `source` an exact substring of
   `state.committed_answer`, `text` the segmenter's rendering, `utterance_id` deterministic
   (derived from `turn_id` and a per-turn counter) and appended to `state.utterances`;
   `state.spoken_text` grows by exactly the emitted `source`s. `StopClip` is emitted before the
   first `TtsSpeak` of a turn iff a clip was played in that turn.
10. **Segmenter is injected and policed.** `TurnMachine.__init__` gains a keyword-only
    `segment` parameter with signature
    `segment(text: str, *, final: bool) -> tuple[Sequence[tuple[str, str]], str]`
    returning `(sentences as (source, text) pairs, remainder)`. The default implementation returns
    `([(text, text)], "")` for non-empty text and `([], "")` for empty text — no sentence splitting
    (T-0004 supplies the real gate later; the machine must not import `speech_gate`). The machine
    raises `ValueError` — no logging, no I/O — when
    `"".join(source for source, _ in sentences) + remainder != text`. *Adversarial:* a segmenter
    that invents, drops or reorders text must never cause a `TtsSpeak` whose `source` is not in
    `committed_answer` (§4 invariant "never `tts.speak` with text the LLM has not committed";
    CLAUDE.md "never voice text the LLM has not committed").
11. **Never voiced** (§4 invariant; `.claude/rules/conductor.md`): a commit with
    `segment="thought"`, `segment="ui"`, `thought_open=True`, or `request_id != active_generate`
    (stale request) produces no `TtsSpeak`, leaves `committed_answer` and `spoken_text` unchanged,
    and does not move the state out of THINKING.
12. **`LlmDone`** for the active request sets `state.llm_done`, cancels the `llm_timeout` timer,
    and flushes the segmenter with `final=True`, emitting any remaining sentences as `TtsSpeak`
    before anything else in that step. In THINKING with `committed_answer == ""` it goes to IDLE
    with `CommitHistory(user_only=True)` and no `HudError`.
13. **Completion → IDLE** (§4 row 16): whichever of `LlmDone` / `PlaybackDrained` arrives last,
    the other already seen, moves SPEAKING → IDLE emitting `CommitHistory(user_only=False)` then
    `ScheduleSummary`. A `HistoryTurn(user_text=<this turn's transcript>,
    assistant_spoken=<`played_text` of the drained event>, interrupted=False, frame_phash=None)`
    is appended and `state.history` is truncated to the last `policy.max_history_turns` entries.
    `TtsDone` only sets `state.tts_done` and is not required for the transition. In IDLE
    `active_generate` and `active_prefill` are `None`. Both arrival orders are tested.
14. **THINKING + `LlmError` (with `request_id` `None` or equal to `active_generate`) or a `Tick`
    at/after the `llm_timeout` deadline → IDLE** (§4 row 10) emitting `HudError` and
    `CommitHistory(user_only=True)`; timers are cleared and no `TtsSpeak` follows.
15. **THINKING barge-in** (§4 rows 7–8): `UserSpeechOnset` keeps the state THINKING and emits
    `StopClip` and `ArmTimer("takeover", ev.t_ms + policy.takeover_ms)`. `UserTakeover` moves to
    LISTENING emitting `LlmAbort(active_generate)` first, then `SnapshotFrame(at_ms=ev.onset_ms)`
    and `PrefillOpen`; no `CommitHistory` is emitted, `active_generate` becomes `None`, and the
    aborted turn's `words` are retained so the next `LlmStart.transcript` starts with them — this
    is the §4 `concatenate_transcript` cell, expressed as state. *Negative:* no command named
    `concatenate_transcript` is added to `contracts/commands.py`.
16. **SPEAKING + `UserSpeechOnset` → PAUSED** (§4 row 11): `PlaybackPause` is the **first**
    element of the returned sequence (the executor's B4 budget, ≤ 300 ms p95, depends on it being
    issued before anything else), followed by `ArmTimer("takeover", ev.onset_ms +
    policy.takeover_ms)`; `pause_onset_ms` is recorded. While PAUSED, answer commits still extend
    `committed_answer` but **no** `TtsSpeak` is emitted (synthesis is not spent on speech that a
    takeover would cancel).
17. **PAUSED → SPEAKING** (§4 row 12, "speech < 600 ms ∧ (backchannel ∨ no words)") happens on
    the earlier of: (a) `UserBackchannel`; (b) a `Tick` at/after `offset.t_ms +
    policy.resume_max_ms` following a `UserSpeechOffset` with `speech_ms < policy.resume_max_ms`,
    provided no `SttWord` with `start_ms >= pause_onset_ms` and no takeover arrived in between.
    Commands, in order: `CancelTimer("takeover")`, `PlaybackResume`, then the `TtsSpeak` commands
    for text committed while paused, in commit order.
18. **PAUSED → INTERRUPTED** (§4 row 13) on any of: `UserTakeover`; `UserSpeechOffset` with
    `speech_ms >= policy.resume_max_ms`; a `Tick` at/after `pause_onset_ms + policy.takeover_ms`
    with no qualifying offset seen; an `SttWord` with `start_ms >= pause_onset_ms` when no
    `UserBackchannel` has been classified for this pause. Commands, in order and **once per
    interruption**: `LlmAbort(active_generate)`, `TtsCancel`, `PlaybackFlush`,
    `ArmTimer("interrupt_timeout", ev.t_ms + policy.interrupt_timeout_ms)`. SPEAKING +
    `UserTakeover` (no preceding onset) takes the same edge with the same commands.
19. **INTERRUPTED → LISTENING** (§4 rows 14–15): on `PlaybackStopped` emitting
    `TruncateHistoryToPlayed(played_ms=ev.played_ms, played_text=ev.played_text)`,
    `SnapshotFrame(at_ms=ev.t_ms)`, `PrefillOpen`; the appended history turn has
    `interrupted=True` and `assistant_spoken` equal to `ev.played_text` plus the ` [interrupted]`
    marker, and contains **no** character beyond `ev.played_text` (§4: "the history never contains
    assistant text that was not played"; test-plan I3). On a `Tick` at/after the
    `interrupt_timeout` deadline: the same commands with `played_ms=None, played_text=""` and
    `assistant_spoken == "[interrupted]"` (the executor estimates; the machine must not invent a
    number).
20. **Error and disconnect rows** (§4 row 17, refined — see Goal):
    (a) `ClientDisconnected` from **any** state → IDLE with `Degrade(mode="text_only")`,
    `LlmAbort`/`PrefillAbort` for whatever was live (each at most once), `degraded=True`, and
    `CommitHistory` only when the turn has user text or played text.
    (b) `TtsError` always emits `Degrade(mode="text_only")` and sets `degraded=True`; it ends the
    turn to IDLE (committing the played prefix) **only** from SPEAKING/PAUSED/INTERRUPTED and
    leaves IDLE/LISTENING/ENDPOINTING/THINKING unchanged otherwise.
    (c) `SttError` emits `HudError`; from LISTENING/ENDPOINTING it goes to IDLE with
    `CommitHistory(user_only=True)` when the transcript is non-empty and with no history entry
    otherwise; from other states it only emits `HudError`.
21. **Command discipline (property, all states).** For every `(state, event)`: a step that changes
    `state.state` returns exactly one `HudState(state=<new state name>, turn_id=state.turn_id)`,
    and a step that does not change it returns none; `state.timers` never holds two entries with
    the same name, every `ArmTimer` is reflected in `state.timers` and every `CancelTimer` removes
    it; `LlmAbort`, `TtsCancel` and `PlaybackFlush` are never emitted twice for the same cause
    (same `request_id` / same interruption) even if the triggering event repeats
    (§4 invariant "idempotent"; `IDEMPOTENT_COMMANDS` in `commands.py:223`).
22. **Purity (property).** `turn_machine.py` imports none of `asyncio`, `time`, `random`, `uuid`,
    `logging`, `os`, `pathlib`, `httpx`; `step(s, e)` returns equal results when called twice on
    the same inputs; `step` does not mutate its argument (the input `MachineState` compares equal
    to a copy taken before the call); every generated id is derived from `turn_id` / counters.
23. **Bounded state (property).** Over a 2000-step Hypothesis run, `len(state.history) <=
    policy.max_history_turns`, `len(state.words) <= policy.max_buffered_words`,
    `len(state.next_words) <= policy.max_buffered_words`, `len(state.timers) <= 6` and
    `len(state.utterances)` resets to 0 at the start of each turn.
24. **Negative — what must not change.** `local_astra/contracts/events.py` and
    `local_astra/contracts/commands.py` are byte-identical to `main` after this task (no new,
    renamed or removed event/command types). `TurnState`, `Word`, `HistoryTurn` and `TutorState`
    keep their current field names, types and defaults (`tests/unit/test_prompt_builder.py` and
    `tests/unit/test_contracts_roundtrip.py` depend on them). `TurnMachine.__init__` keeps
    `policy` as its first positional parameter so `conductor/session.py` still constructs it
    unchanged. The machine imports neither `local_astra.conductor.speech_gate` nor
    `local_astra.reflex.filler_policy`. Every test outside
    `tests/unit/test_turn_invariants.py` and `tests/unit/test_turn_edges.py` passes exactly as on
    `main` (277 passed / 8 skipped, minus the 19 T-0003 pending xfails that become passes).

## Amendments (2026-09-13, after the test-author found seven ambiguities)
These resolve contradictions in the criteria above. Where they conflict with the original wording,
**these win**. Each was a defect in the task file, not in the tests.

**A1 — which field names are contract.** The Implementation notes say "names are yours"; criteria 4
and 16 name `next_words` and `pause_onset_ms`. Resolution: **`MachineState.next_words` is contract**
(criterion 4 states it as one and the tests assert it). Every other new field name is the
implementer's choice, `pause_onset_ms` included. The notes' "names are yours" applies to the rest.

**A2 — `HudState.turn_id` on a step that opens a turn.** It is the **post-step** `turn_id`, i.e. the
turn being entered. The HUD tracks what is now current, not what was left.

**A3 — criterion 12 "before anything else in that step"** conflicts with the criteria preamble
allowing `hud.state` and timer commands to interleave. The preamble wins: `arm_timer`,
`cancel_timer` and `hud.state` may precede the flushed `tts.speak`s; every *other* command must
follow them.

**A4 — an answer commit whose segmenter returns no complete sentence** still moves THINKING →
SPEAKING, emitting zero `TtsSpeak`. §4's row is keyed on the commit, not on speech being produced;
the held text is spoken on a later commit or on the `LlmDone` flush (criterion 12).

**A5 — `llm.error` scope (the real spec decision, not just wording).** Criterion 14 specifies only
the THINKING row, but the frozen stateful postcondition requires `LlmError → IDLE` from **any**
state, and the test-author rightly refused to weaken it. Resolution: **`LlmError` for the active
request ends the turn to IDLE from every state in which a generate is live — THINKING, SPEAKING,
PAUSED and INTERRUPTED.** In SPEAKING/PAUSED/INTERRUPTED it commits the *played* prefix (as
criterion 19 does) rather than `user_only=True`; in THINKING it commits `user_only=True` as
criterion 14 says. The invariant stands as written; criterion 14 was too narrow. This widens
docs/02 §4's error row and must go back via `/spec` with criterion 20's two deltas.

**A6 — the `[interrupted]` separator.** One rule, both paths: `assistant_spoken` is
`played_text + " [interrupted]"` when `played_text` is non-empty, and exactly `"[interrupted]"`
when it is empty (the timeout path, where `played_ms is None`). No double space, no trailing space.

**A7 — criterion 7's "never after a canvas has committed in that turn" is unreachable** as
specified, because the clip is emitted in the same step as `LlmStart`, before any commit can have
arrived. Drop that clause. The testable content is "at most one `PlayClip` per turn from this
machine" plus the negative list (no `hmm`, no `still_working`, no `interim_update` timer).

## Implementation notes
- `MachineState` is `frozen=True, extra="forbid"` (`contracts/base.py`): build new states with
  `model_copy(update=…)`, keep every collection a `tuple`, and remember that `model_copy` skips
  validation — construct explicitly where a field is derived.
- New `MachineState` fields you will need (names are yours, the criteria are not):
  the `t_ms` of the current `LlmStart`, the `t_eot_ms` a `SttFlushed` confirmed, `pause_onset_ms`,
  a per-pause "backchannel classified" flag, the unspoken committed tail handed back by the
  segmenter, `next_words`, a per-turn utterance counter. Do not remove or rename existing fields
  (criterion 24).
- `.claude/rules/conductor.md` is binding: commands are data, the machine never calls a client;
  transcript words are attributed by audio timestamp; barge-in truncates history to what was
  *played*; history stores `(user_text, assistant_spoken)` and never thinking.
- The `pending` machinery only tolerates `NotImplementedError` and `AssertionError`
  (`tests/conftest.py:56-63`) — during development a `TypeError` from a wrong signature surfaces as
  a hard failure, which is intended.
- Hypothesis shrinks badly on deep dispatch chains; keep `step` a flat dispatch on
  `(state.state, type(event))` with small per-row helpers so a counterexample is readable.
- `TurnPolicy.pause_latency_budget_ms` stays unused by the machine: it is the executor's B4 budget.
  Do not smuggle it into a `Tick` comparison.
- Landmine from CLAUDE.md: never weaken an invariant in `tests/unit/test_turn_invariants.py` to get
  green. If a §4 property genuinely cannot hold, stop and escalate to the reviewer with the
  counterexample — the spec changes, not the assertion.
- Sequencing note for later tasks (do not act on it here): when T-0004's gate is wired in, the
  stateful postcondition at `tests/unit/test_turn_invariants.py` ("a complete committed sentence
  must be spoken") needs an "or held by the gate" clause, and T-0013 will replace criterion 7's
  inline ack rule — both are test/spec changes owned by those tasks.

## Regime
Pure CPU, no GPU, no services, no artifacts. `profile=n/a canvas=n/a steps=n/a`; versions:
python 3.11 (`.python-version`), pydantic v2, hypothesis as pinned in `uv.lock`; `n` = Hypothesis
`max_examples=200`, `stateful_step_count=40` for the standard stateful run and one

## Amendments, round 2 (2026-09-13, after the edge-test author found seven more)

**A8 — word identity for de-duplication.** A word is the same word iff `(text, start_ms, end_ms)`
match. Criterion 4's "every `SttWord` is appended" means every *distinct* word; a re-delivery of an
identical triple is ignored in both `words` and `next_words`. STT re-delivers on correction, so
this is a real wire condition, not a theoretical one.

**A9 — supersedes A5's "where a generate is live".** `LlmError` ends the turn to IDLE from **any**
state, matching the frozen stateful postcondition, which is not to be weakened. In THINKING it
commits `user_only=True`; in SPEAKING/PAUSED/INTERRUPTED it commits the played prefix
(`user_only=False`); in IDLE/LISTENING/ENDPOINTING — where no generate is live and an `llm.error` is
anomalous — it emits `HudError` and idles, committing `user_only=True` only if the transcript is
non-empty. A5 was too narrow; the invariant wins.

**A10 — `TtsError` from SPEAKING with nothing reported played.** No playback event has reported
`played_text` yet, so there is nothing to commit: emit `CommitHistory(user_only=True)` and append no
assistant text. Never synthesise `"[interrupted]"` here — that marker means "the user cut us off",
and inventing it for a TTS failure would put a false claim about the conversation into history.

**A11 — criterion 20(c) with an empty transcript** means no `CommitHistory` command at all and no
growth of `state.history`. Not "commit an empty turn".

**A12 — the criterion 17(b) / 18(c) race.** A qualifying short offset (`speech_ms <
resume_max_ms`) **cancels the takeover deadline** and arms the resume tick. Without this, the
default policy (`takeover_ms == resume_max_ms == 600`) makes the two deadlines fire on the same
tick and the outcome depends on evaluation order — which is exactly the kind of coin-flip a pure
machine must not contain.

**A13 — `pause_onset_ms` is `ev.onset_ms`** (the audio onset), not `ev.t_ms`. This makes
criterion 16's timer arming (`ev.onset_ms + takeover_ms`) and criterion 18(c)'s deadline
(`pause_onset_ms + takeover_ms`) the same instant, as the criteria plainly intend. It also keeps
criterion 18's word rule (`start_ms >= pause_onset_ms`) in the audio clock, consistent with
criterion 4's "attribution by audio timestamp, never by state-entry time".

**A14 — criterion 17(a) is literal, and the "backchannel flag" in the Implementation notes is
withdrawn.** `UserBackchannel` while PAUSED resumes immediately. Criterion 18's clause "when no
`UserBackchannel` has been classified for this pause" therefore only governs the word rule *before*
any backchannel arrives; after a resume the machine is no longer PAUSED and the question does not
arise. Do not add a per-pause flag with no observable effect.

## Amendment A15 (2026-09-13, ruling on the implementer's escalation)

**The `tts.error` conflict is a test-side defect, not an implementation choice.** Two assertions in
`tests/unit/test_turn_invariants.py` contradict each other:
- line ~641 clears `live_generates`/`live_prefills` on `TtsError` alongside `LlmError` and
  `ClientDisconnected`, which forces `tts.error` to be terminal in every state;
- line ~702 `_postconditions` asserts `-> IDLE` for `LlmError | ClientDisconnected` only, and
  deliberately omits `TtsError`.

Criterion 20(b) and A10 agree with line 702, and `tests/unit/test_turn_edges.py` tests that
behaviour in three states. **Line 641 is the one that is wrong** — bookkeeping over-reach that
presumes the wider §4 row this task deliberately narrowed.

Ruling: keep the shipped behaviour; fix line 641 to clear the live sets for
`LlmError | ClientDisconnected` always, and for `TtsError` only when the step actually idled.

Why this direction and not the other: a synthesis failure must not destroy a turn the user is
halfway through speaking. `tts.error` means "we cannot voice this", not "the conversation is
over" — the right response is to degrade to text and keep listening, which is what
`Degrade(mode="text_only")` exists for. Making it terminal everywhere would turn a recoverable
output fault into a dropped turn, and the user would experience a lost sentence rather than a
silent one.

**Also test-side: `TestTurnMachineBoundedState` cannot pass for any implementation.** It dies on
Hypothesis's `filter_too_much` health check before any assertion runs, because five rules use
`assume()` and `stateful_step_count=200` draws each ~11 times. Fix with `@precondition` instead of
`assume`, or `suppress_health_check=[HealthCheck.filter_too_much]`. With the check suppressed the
implementer measured it clean three runs running (20 examples x 200 steps, every invariant held),
so criterion 23, purity, non-mutation and command discipline do hold on long traces.

## Amendment A16 (2026-09-13, reviewer escalation — SPEC DEFECT, not an implementation one)

**The turn-ending error rows must abort the live generate.** Criterion 14 and `docs/02` §4 row
`THINKING | llm.error ∨ Tick(timeout) | IDLE | hud.error, commit_history(user only)` both omit
`llm.abort`. The implementation followed them faithfully, so on a 20 s LLM timeout the machine
idles, clears `active_generate`, and leaves vLLM still denoising a request nothing will ever
cancel.

§4's "at most one active generate" property does not catch this — an orphan is not a second
active generate — and neither does the stateful model (see A17). It is budget-relevant rather
than cosmetic: `.claude/rules/conductor.md` caps the session at one generate + one prefill +
captioner against `--max-num-seqs 3`, with ~2.5 GiB of unprofiled sampler transient per
concurrently denoising request. The next turn's `llm.start` would run beside the ghost.

Ruling: **every row that ends a turn while a generate is live emits `LlmAbort(active_generate)`**,
and likewise `PrefillAbort` for a live prefill. That covers criterion 14 (`llm.error`, the
`llm_timeout` tick), A9's widened `llm.error` rows, and the `tts.error` / `client.disconnected`
rows. The abort is moot only when the error already carries the matching `request_id` — emit it
anyway, since `IDEMPOTENT_COMMANDS` makes a redundant abort harmless and a missing one costs VRAM.

Carry back to `docs/02` §4 via `/spec`, together with the two deltas in this task's Goal and A9's
widening. That is four spec changes this task now owes.

## Amendment A17 (2026-09-13 — the test gap that hid A16)

`tests/unit/test_turn_invariants.py` clears `live_generates` / `live_prefills` **by event type**,
so `at_most_one_generate_and_one_prefill` can only fail if the machine *starts* two requests,
never if it forgets to abort one. The reviewer confirmed by mutation: deleting `llm.abort` from
the `tts.error` and `client.disconnected` rows leaves all 73 tests passing.

Fix: clear the live sets only on an observed `LlmAbort` / `PrefillAbort` command or an `LlmDone`,
and have `idle_means_no_live_requests` also require both sets to be empty. Then the invariant
catches a forgotten abort on every row at once, instead of the interrupt rows being pinned by
hand-written command assertions while every other row goes unchecked.

## A16 correction and A18 (2026-09-13, after the test-author pushed back)

**A16 corrected — "abort what is still LIVE", not "emit it anyway".** A16 said to emit the abort
even when the error carries a matching `request_id`, on the grounds that a redundant abort is
harmless. That wording collides with criterion 21, which forbids two `LlmAbort`s for one request
id, and would lead an implementer to emit `LlmAbort(<remembered id>)` unconditionally and break
the INTERRUPTED path. The correct rule: **emit `LlmAbort(active_generate)` iff a generate is still
live at that moment**, same for `PrefillAbort`. On a row that has already aborted, nothing is live
and nothing is emitted. The test-author pinned this reading with
`test_llm_error_after_an_interruption_does_not_abort_a_second_time`.

**A18 — A17 was necessary but not sufficient, and the reason generalises.** Clearing the live sets
only on an observed abort command cannot catch a forgotten abort on a row that **no Hypothesis rule
ever reaches**. Two such rows existed: `client.disconnected` had no rule at all, and no trace ever
rested in THINKING, so the `llm_timeout` row was unreachable however the ticks fell. Both are fixed,
but the lesson is structural: *the invariant's reach is bounded by the rule set*, so a row added to
§4 later without a rule is silently unchecked again.

Recommended guard, not yet implemented: a test asserting every member of `EVENT_TYPES` is emitted
by at least one stateful rule. It converts "we forgot to exercise this row" from an invisible gap
into a failing test. Worth doing when T-0003 closes.

## A19 — A18 guard and the A5 postcondition landed (2026-09-13, after T-0004 merged)
The stateful model now instruments every event type a rule *delivers* to `step` ("emitted" means
delivered, not constructed — a rule whose precondition never fires counts for nothing) and asserts
the set equals `EVENT_TYPES`. It found three rowless types with no rule (`user.pause`, `stt.step`,
`ui.action` — now a `telemetry` rule) and that `tts.done` was delivered once per 200 examples (its
precondition re-keyed to the last utterance id). The model drives the real `SpeechGate`, one per
turn, never calling `close()` (T-0004 A9); after every step `"".join(TtsSpeak.source)` is a prefix
of the turn's committed answer, equal to it on `llm.done` **from THINKING/SPEAKING** (PAUSED defers
to the resume, criteria 16–17 — A5's unqualified "equals it on `llm.done`" is corrected to that),
and while THINKING/SPEAKING `spoken + gate.pending == committed` (so "speak nothing until
`llm.done`" cannot pass). Any `TtsSpeak` for a barged turn fails. Three deterministic edge tests
carry the minimal counterexamples the 40-step run misses at seed 0.
**Open, not invented:** the machine checks conservation at the seam but not exhaustion —
`final=True` returning a non-empty remainder is caught only by the model-level postcondition.
Adding "`final=True` must return an empty remainder" to criterion 10 is a spec change for T-0007's
wiring task.
