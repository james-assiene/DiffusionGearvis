## Goal

Removing any single deny rule from `protect_paths.sh` or `guard_bash.sh` must turn at least one row red, and that row must be one that only the removed rule can decide. Today, five implementer rows in `test_protect_paths_hook.py::test_role_rules_are_unchanged` are denied because the sandbox's owned section, `- **/*`, parses as empty ("lists no path"); the role rule plays no part. Two more implementer rows (the version locks and another role's memory) have the same problem. Separately, three `guard_bash.sh` rules are untested or only partly tested: the tests-overwrite deny, the implementer push/PR deny, and four of the six destructive-git forms. After this task:
- the implementer sandbox owns every path the role rules protect, so the ownership check would allow them and only the role rule can deny;
- a positive control proves that owned list parses;
- each deny row asserts its reason text, and asserts that the ownership reasons are absent.

Nothing changes for the agents: the hooks behave exactly as before.

## Implementation notes

- **Audit background.** T-0143 reviewer B ran the M1 mutant: `tests/unit/test_x.py rc 2 stderr BLOCKED (implementer): the '## Owned files' section of docs/tasks/T-0099.md lists no path`. The planner audited the other hook tests:
  - `test_protect_paths_hook.py`: the version-lock rows and another role's memory row are denied for the wrong reason, the same way as M1.
  - `test_guard_bash_hook.py`: the tests-overwrite rule and the implementer push/PR rule have no row at all, and four destructive-git forms are unpinned. For an implementer, the tests-overwrite rule overlaps the ownership rule, so a naive row would repeat M1.
  - `test_stop_hook.py`: no instance. The `uv` shim answers mypy with 0, and every blocking row asserts an attributed regression line or a specific message.
  - `require_evidence.sh`: no test module (proposed follow-up T-0145b, not in this task).
  - `format_and_typecheck.sh`: untested, but its exit 2 is advisory.
- **What to assert on.** Use a short, stable substring of each `deny` message and keep it in one constant per rule, so a wording change in a hook is a one-line test edit. Pin the reason, not the whole sentence.
- **Asserting the ownership messages are absent** is what makes an implementer deny row discriminating. Use all three: "Owned files", "not in the owned files", "no task branch".
- **The owned list must not use leading-`*` globs.** The parser rejects them by design (ruling A9's token shape), so that rejection is not a hook bug. Use explicit paths, one bare backticked path per bullet. Leave out annotations, so the premise does not depend on the annotation parser that other groups already pin.
- **The live guard blocks literal strings.** It runs on your own Bash commands, so a probe whose command line contains the destructive-git literals is blocked (seen while planning). Put such strings in a file, write probes in the scratchpad, and never use heredocs into the repo.
- **Mutation harness hygiene** (`.claude/rules/tests.md`):
  - name the copy uniquely;
  - purge `tests/**/__pycache__` between arms;
  - prefer mutations that change the file's length;
  - a mutant caught only by a row naming another reason is not a kill (the "coarse mutation" rule).
- **Keep the existing ids.** If a row needs a different premise, extend it rather than renaming it, so criterion 9(b) can be checked with `pytest --collect-only -q` diffed against main.
- **Leave other modules alone.** If a new row exposes a hook defect, mark nothing pending or xfail. Stop and report it to the orchestrator; the hook fix is a main-session task and gets its own task id.
- **Systemic follow-up (not in this task).** A line in `.claude/rules/tests.md` ("assert a deny's reason when another rule could also deny") after T-0143 merges, since T-0143 owns that file until then.
