## Goal

A newcomer on a clean Linux box can follow the README from clone to a running session, and when something fails, the README tells them what the message means and what to do. Several setup statements are wrong or missing today (no `playwright install chromium` step for `--tools live`; `libportaudio2` not listed; Node.js listed as required; "only part that needs the network" and "at runtime nothing talks to the network" are false since search and web mode; only the LLM revision is pinned, not STT; the first `up` will likely show `tts FAILED` while Pocket TTS downloads). The code also prints stale setup advice (`astra fetch-models`, which is not implemented; bootstrap's "~20 GB" vLLM image, "moshi-server not installed yet (cargo install…)", "open Claude Code here … /plan T-0003").

## Acceptance criteria

**A (code texts, implementer).** No behaviour change; only user-facing text:
1. `local_astra/preflight.py` (and any other user-facing message) no longer tells users to run `astra fetch-models`; it points at the README's `hf download` commands.
2. `scripts/bootstrap.sh`: the vLLM image size reads about 31 GB; the moshi-server cargo warning is gone (STT is a container); the closing line points at the README's next step (`up --profile lean`), not at Claude Code; "git hooks" wording, if printed, is accurate (they are Claude Code agent hooks). It still never uses the GPU.
3. `services/README.md` no longer says models come from `astra fetch-models`. `services/vllm.sh` is NOT edited: the locked GPU wrappers refuse when it changed since 806da12 (its stale header comment stays until a post-release task).
4. `fetch-models`'s CLI help no longer says "(the only network egress)".
5. Every existing test passes unchanged, or a test that pins a changed text is named and re-pinned (test-author).

**B (README, orchestrator; reviewed line by line).**
1. Requirements: Chrome/Chromium is for the HUD page; Node.js only for the HUD's own tests; `libportaudio2` (PortAudio) needed; at least 4 CPU cores (Pocket TTS is pinned to cores 2–3); a desktop session (DISPLAY/WAYLAND_DISPLAY) for the headed agent browser, or `--browser headless`.
2. One-time setup: what `bootstrap.sh` really does (and that its `make check` takes several minutes); `uv run playwright install chromium` for `--tools live`; the STT model is downloaded at its current revision (only the language model is pinned); first `up` may report `tts FAILED` while Pocket TTS downloads — run `up` again.

4. "When something is wrong" becomes a troubleshooting table: symptom (the message the user sees), likely cause, what to do — the audit's rows, each checked against its source.
5. A note that console messages say `astra …` (the program's old name, kept as an alias).
