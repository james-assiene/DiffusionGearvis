## Goal
After the two trees, every `perstep_mar*` call (`perstep_mar`, `perstep_mar_sc`, `perstep_mar_qargmax`) still pays ≈ 8.7 ms at every bucket for the
vocabulary-bound tail of `constrained_marginals` (`logs/t0071a-microbench-9a386ee`, row `hq`; CL 256, V 262 144). The tail is:
- `total` = the compensated row sum of `q_raw`, clamped to fp32 tiny;
- `log_total`;
- the term `q̃·max(log max(q̃, 1e-38), log_total + log 1e-30)`;
- a second compensated row sum and `entropy = log_total − Σterm/total`;
- the in-place normalisation `q = q_raw / total`.

`compensated_sum` runs as a log2(V) = 18-level torch tree of 6–8 launches per level, issued twice. The whole tail is about 300 launches and holds
1 GiB of [L, V] temporaries (peak added 1024 MiB in that row). This task replaces it with a few Triton launches that are **bit-identical** to the
torch path on CUDA. Every rounding is done in the same order with the same elementwise functions, so `q` and `H(q)` do not change by a single bit.
It also lands the shared kernel infrastructure:
- `triton==3.7.1` in the host `cd` group, so kernels run under `TRITON_INTERPRET=1` on CPU;
- a lazily imported `cd/kernels/` package and a dispatch that is logged once per process;
- the tier-2 shape that T-0077c/d reuse.

The CPU path, which is the reference and what `make cd-test` exercises, is not changed by a byte. Out of scope (umbrella "Deferred"): fusing
`class_max`, `class_mass`, the draw, or `_token_marginals`. Also out of scope: `semiring.compensated_sum` itself, because `semiring.py` belongs
to T-0077c and the torch function stays as the CPU path and the reference.

## Implementation notes
- **The torch tail is the spec** (`marginals.py` at the base, lines after `q_raw = _token_marginals(...)`). Op by op, in fp32:
  1. `total = clamp_min(compensated_sum(q_raw), finfo.tiny)`
  2. `log_total = log(total)`
  3. `c = clamp_min(q_raw, 1e-38)` — the fp32 rounding of 1e-38 is **subnormal**
  4. `c = log(c)`
  5. `c = maximum(c, log_total + fp32(log 1e-30))` — torch rounds the Python scalar to fp32 opmath
  6. `term = c * q_raw` — rounded on its own
  7. `entropy = log_total − div(compensated_sum(term), total)`
  8. `q = div(q_raw, total)`, written in place into `q_raw`

  `torch.clamp_min` and `torch.maximum` propagate NaN. Torch on CUDA is not FTZ, does not contract across kernels, and its `div` is IEEE (rn).
- **Triton landmines** (checked in triton 3.8.0's source on the host; re-check in 3.7.1 inside the image and report any difference):
  - `/` lowers to the approximate `fdiv`: use `tl.math.div_rn`.
  - `tl.log` is approximate on NVIDIA: use libdevice `log` (`__nv_logf`).
  - Libdevice is FTZ by default (`enable_reflect_ftz=True`): pass `enable_reflect_ftz=False`.
  - FMA fusion is on by default (`enable_fp_fusion=True`): pass `enable_fp_fusion=False`, or round the multiply explicitly. Libdevice `mul_rn`
    cannot run under the interpreter.
  - Options go per launch only. Setting knobs or env vars is forbidden by N6.
  - `tl.maximum` needs `propagate_nan=tl.PropagateNan.ALL`.
  - `tl.sum`, `tl.reduce` and `tl.associative_scan` do not promise the adjacent-pair order. Build the tree explicitly: reshape `[n/2, 2]`, split,
    repeated with `tl.static_range` over log2(BLOCK) levels.
  - Aligned power-of-two blocks compose bit-exactly: stage 1 gives per-block `(s, err)`, stage 2 gives the row combine with the same formulas.
    About 4 launches in all.
- **Interpreter:** in 3.8.0, `create_extern_elementwise` and `create_inline_asm` raise `NotImplementedError` under `TRITON_INTERPRET=1`. So the
  log implementation is chosen by a `constexpr` set from whether the interpreter is active (read, never set). The interpreter also asserts that
  `triton.language` is in the jitted function's module globals.
- **Memory:** no [L, V] temporary. Partials are `[L, p/BLOCK]` (`s`, `err`) per stage. `q` is written into `q_raw`'s storage (the read happens
  before the write in the same program).
- **No host sync:** `total` and `log_total` stay on the device. Grids come from `q_raw.shape`. Make L a runtime argument, so different L values
  do not trigger recompiles, and make BLOCK a `constexpr` that depends only on V.
- **The kernel needs a contiguous fp32 [L, V] tensor.** Anything else goes to the torch path, and the reason is logged. This is a layout guard,
  not a numerics fallback.
- **Dispatch:**
  - Check the device first, so CPU never imports triton. Check that triton can be imported once per process.
  - On the golden traces, a tensor-attribute check (`is_cuda`, `device`) is visible to `TorchFunctionMode` and will add names to the op digest.
    Report exactly which names were added (ruling M3).
  - The log must not use the `ASTRA_CD ` prefix: the golden and record capture reads those lines.
- **JIT compile** happens on the first use of each specialisation. The A/B warm-ups absorb it; the engine's first constrained request pays it
  (reported, criterion 9).
- **Ordering (ruling M5):**
  1. The implementer's first commit is the one-line `pyproject.toml` change.
  2. The human runs `uv lock` and commits `uv.lock` on the branch.
  3. Then the test-author starts. Before step 2 nobody runs `make cd-test` or `uv run --group cd`: `uv run` re-locks a changed `pyproject.toml`
     on its own.
- **Tier 2 (`t0077b_tier2.sh`, the same refusals as `t0077a_tier2.sh`):**

  2. Only if its sync rows held: the T-0073 numerics wrapper (host summary exactly "1 passed", 51 inner).
