**The protocol is not skippable.** The diff is not one sentence: it changes what every multimodal request contains by default, it changes a pure machine's per-turn state, and the failure it can produce — a prompt the engine refuses with a 400 (`--limit-mm-per-prompt {"image": 4}`), or a prefix that stops caching — is invisible from the code and only visible in latency and in the engine's log.

## Goal

Today a turn shows the model exactly one screen. `snapshot_frame` overwrites `Session._frame`, so when the scene changes while the user is still speaking the new frame **replaces** the old one and the prompt carries a single `ImagePart` (docs/01 D9, *"the last snapshot wins"*). A question that spans two screens — *"which of these two pages has the later date?"*, *"I just switched tabs, compare them"* — cannot be answered, and nothing anywhere says a screen was dropped. After this task a turn **accumulates** the frames it saw: the current user message becomes `[label₁][img₁][label₂][img₂]…[transcript]`, every image before the text so the D9 prefix discipline still holds by *appending*, ordered oldest first, de-duplicated by perceptual hash, capped at three per turn (with the whole-prompt cap of four images unchanged and current frames winning over history), each image carrying a short position label so the model can be asked about "the first screen". This is the **default mode**, not a flag: one scene change during an utterance gives two frames. `max_frames_per_turn = 1` is the rollback lever and restores today's behaviour exactly, including "the last snapshot wins". Interleaving the transcript between the frames is **not** in this task — it is T-0060, optional, and it starts from this.

### Design rulings (these are what the implementer works to; the tests pin them, this prose does not)

**D1 — append-only while under the cap; the last slot is the live one.** A frame that has been sent in a prefill is never removed or reordered for the rest of the turn. That is the whole reason the images go before the transcript: each new frame *extends* the message the previous prefill already warmed, so **every prefill sent during the turn is a byte-prefix of the final request** — strictly better than today, where a replaced frame invalidates every cached block from the image onwards. Once the turn holds `max_frames_per_turn` frames, a further distinct frame **replaces the last one**: at cap 1 that is today's rule unchanged (the rollback lever is then exact), and at cap 3 it keeps the newest screen live at the cost of one image's worth of cache, which is exactly the cost today pays on every scene change. Frames are never dropped from the middle.

**D2 — the cap is 3, and the arithmetic is the engine's, not a taste.** `services/vllm.sh` passes `--limit-mm-per-prompt '{"image": 4, "video": 1}'`: a fifth image is an HTTP 400, not a degradation, so **4 is a hard ceiling on the whole prompt** and `Budget.max_images = 4` already encodes it. A screen frame costs ≈ 1 120 visual tokens (`perception/policy.py::MAX_SCREEN_VISUAL_TOKENS`, an *estimate* — `ResolutionBucket.measured` is False everywhere; criterion 24 measures it for the first time). Three current frames plus one history image is 4 × 1 120 ≈ 4 480 tokens of the 14 336 budget (31 %), which `fit()` never has to trim in practice. Three is also what the wire can produce: the reissue rate limit is `PrefillPolicy.reissue_min_interval_ms = 1 000` and an utterance is 2–5 s, so one to four scene changes are reachable and three of them are the most a turn can show without evicting history entirely. The pinned chat template accepts any number: its content-part loop emits one `<|image|>` per image part with no per-message cap (`chat_template.jinja`, sha256 `36e3a42e…`, lines 320–345), so the template is not the binding constraint and **the launcher is**. **Finding, not an edit:** nothing in this task changes `services/vllm.sh`; if a future cap above 3 is wanted, `--limit-mm-per-prompt` must rise first and that file is T-0058's and the human's. Criterion 11 asserts our cap against the launcher's number so the two cannot drift silently.

**D3 — de-duplication happens in three places and the prompt builder is the authority.** The machine dedups on `SceneChanged.phash` so a change back to a screen already seen costs **no snapshot and no prefill re-issue** (the cost criterion). The session dedups on the *fetched* `Frame.phash`, because `get_frame(at_ms)` can return a frame whose hash differs from the announced one, or the same frame twice. The builder dedups on the phashes actually assembled, which is the only place that also sees the history images (today's `frame.phash != newest_attached` rule, generalised). The machine cannot dedup against the **onset** frame — `SnapshotFrame(at_ms=onset)` carries no hash and no event ever tells the machine what was captured — so a scene change back to the onset screen costs one wasted re-issue per turn. Recorded, accepted, not worked around.

**D4 — a label may never mention the total.** `[screen 1 of 3]` is fatal: when the third frame arrives the first label changes and the whole prefix, including the cached image blocks before it, changes with it — a silent total cache miss and a violation of D9. Labels are a pure function of the frame's **index only** (`frame_label(i)`), and they are emitted **iff `budget.max_frames_per_turn > 1`**, which is what makes the rollback lever byte-exact rather than approximately exact.

**D5 — history ages a multi-frame turn as one unit: one image, one caption, the newest frame.** `HistoryTurn` carries one `frame_phash` and one `frame_caption` (today the window title), `_caption_part`'s `[screen: {caption}]` rendering is frozen by T-0053 criterion 10 and pinned by `tests/unit/test_session_over_long_prompt.py`'s `CAPTION` canary, and there is no image budget for more: three current frames already leave one slot of four. So a turn that showed three screens contributes its **last** frame to history exactly as today, `fit()`'s ladder is unchanged, and no contract moves. The follow-up — history turns carrying a frame *list* — is named in *Ambiguities* and is not done here.

**D6 — `fit()` never spends a current-turn frame.** The floor grows from one image to at most three, which is safe only because D2 bounds it; criterion 12 pins both halves. A history image that shares a phash with a current frame stays spendable only while another copy of those pixels survives (today's `_oldest_history_image` rule, generalised from one current hash to a set).

**D7 — no change to the system prompt.** The block in `ui_instructions.py` is the prefix-cached region and **T-0055 still owes its token count under `/launch`** (its criterion 12); T-0053 criterion 10 pins `system_message()` byte-identical. Adding "you may be shown several screens" there would invalidate a measurement that has not been taken yet. The per-frame labels sit in the *turn's own* user message, which is where the model is looking when it reads the images, and they carry the instruction implicitly ("the screen the user was looking at when they started speaking" / "the screen they switched to while still speaking"). If the eval in criterion 24 shows the model conflating the screens, the sentence belongs in the block and that is a T-0055 follow-up with a re-count, not a silent edit here.

### Group A — the machine accumulates, in order, once each, bounded

1. **A scene change appends.** LISTENING with an active prefill and a `SceneChanged` whose `phash` is not already recorded this turn: the returned state's new field **`MachineState.turn_phashes`** (the name is contract) gains `ev.phash` **at the end**, and the commands are `SnapshotFrame(at_ms=ev.t_ms)` then `PrefillReissue(request_id=active_prefill)` — unchanged from today, in that order. Three distinct changes give `turn_phashes == (a, b, c)` in arrival order. *(docs/02 §4 row 2; docs/01 D9 as amended by this task.)*
2. **The same screen twice costs nothing.** A `SceneChanged` whose `phash` is already in `turn_phashes` returns a state equal to its input and an **empty** command list — no `SnapshotFrame`, no `PrefillReissue`. Adversarial row: `A, B, A` yields two snapshots and `turn_phashes == (A, B)`; `A, A, A` yields one. *(The cost criterion: no extra engine request when nothing changed.)*
3. **The cap holds and the last slot stays live.** With `len(turn_phashes) == policy.max_frames_per_turn - 1` (the onset frame is the turn's first frame and the machine never sees its hash — D3), a further distinct phash **replaces the last entry**, still emitting `SnapshotFrame` + `PrefillReissue`; entries before the last never change once written, the tuple never exceeds `max_frames_per_turn - 1`, and nothing is ever removed from the middle or reordered. *(D1.)*
4. **A turn boundary clears it; continuing a turn does not.** Every row that opens a turn (T-0003 criteria 1, 15, 19: onset from IDLE, `UserTakeover` from THINKING, `PlaybackStopped`/timeout from INTERRUPTED) resets `turn_phashes` to `()`; ENDPOINTING → LISTENING on a new onset (T-0003 criterion 5, `Unfreeze`) **keeps** it, because that is the same turn still being spoken. Hypothesis invariant: in IDLE, `turn_phashes == ()`.
5. **The rollback lever, machine half.** With `TurnPolicy(max_frames_per_turn=1)` every distinct scene change still emits `SnapshotFrame` + `PrefillReissue` and `turn_phashes` holds **exactly the newest** phash — docs/01 D9's "the last snapshot wins", unchanged. *(This criterion is what makes the lever a rollback rather than a third behaviour; a naive "append, ignore beyond the cap" would freeze the onset frame at cap 1 and lose the screen the user is pointing at.)*
6. **The §4 properties still hold, with the new field inside them.** The stateful model in `tests/unit/test_turn_invariants.py` draws phashes from a small strategy (not one constant, as today) and asserts, in addition to T-0003 criteria 21–23: `turn_phashes` is ordered by arrival, holds no duplicate, never exceeds the cap, and loses no entry except at a turn boundary; `step` still does not mutate its argument; `turn_machine.py` still imports none of `asyncio, time, random, uuid, logging, os, pathlib, httpx`. *(architecture §4 invariants; `.claude/rules/conductor.md` "turn_machine.py is pure".)*

### Group B — the prompt carries them, in order, strictly before the transcript

8. **N frames, oldest first, all before the text.** `PromptBuilder.prefix(history, frames=(f1, f2, f3), assists, resolve)` returns a last user message whose content is, in order, `label₁, img₁, label₂, img₂, label₃, img₃` (labels per criterion 14), with `[p.phash for p in images] == [f1.phash, f2.phash, f3.phash]`. After `full(...)`, **every `ImagePart` in the prompt precedes every text part `full()` added**, and the transcript is the last part of the last message. *(`.claude/rules/conductor.md` prompt layout; docs/02 §5; docs/01 D9.)*
9. **The prefix grows by appending — byte-exactly.** For every `k < len(frames)`: `prefix(frames=frames[:k]).shares_prefix_with(prefix(frames=frames[:k+1]))` is True **and** the k-frame prompt's part sequence is a strict prefix of the (k+1)-frame one, compared on the serialised parts, not on lengths. `prefix(frames=all).shares_prefix_with(full(prefix, transcript, …))` still holds. **Adversarial row (the headline one):** a label spelling the total (`[screen 1 of 3]`) must redden this — the row is written so that this mutation, and only a real append violation, fails it. *(docs/01 D9; docs/03 §2 "the prefix used for anticipatory prefill tokenises identically"; B11 ≥ 0.9 prefix-cache hits.)*
10. **One image per distinct phash.** A `frames` sequence with a repeat, or containing a frame whose phash equals the newest history frame still attached as pixels, yields one `ImagePart` per distinct phash in first-occurrence order. Today's `test_unchanged_frame_is_not_attached_twice` generalises and stays green. *(T-0005 B9; `.claude/rules/conductor.md` "a frame whose perceptual hash equals the newest history frame still held as an image is not attached a second time".)*
11. **Two caps, both enforced, and ours is consistent with the engine's.** At most `budget.max_frames_per_turn` current images, at most `budget.max_images` (4) images in the whole prompt, and the current frames win: `_image_turns`' slot arithmetic subtracts the number of current images, not one. Adversarial: ten frames in → ≤ 3 current images, ≤ 4 total. Plus a parity row reading `services/vllm.sh`: `Budget.max_images <= ` the `image` value in `--limit-mm-per-prompt`. *(docs/03 §2 "≤ 4 images per prompt with oldest history image dropped first"; the launcher's flag is the reason, quoted in the test's docstring.)*
12. **`fit()` spends history, never the turn.** No ladder rung removes a current-turn image (rung 1 spends history pixels oldest-first as today; `trimmed["images"]` counts history images only); a history image sharing a phash with **any** current frame is spendable only while another copy of those pixels survives; with three current frames and a history over budget the result still carries three current images, or `fits=False`. *(T-0020 ruling A1; D6.)*
13. **The no-image statement is still exactly right.** T-0053 criterion 2's four rows re-run with the new signature: current frames present (one or three) → `NO_IMAGE_STATEMENT` **absent**; `frames=()` with a resolved history image → absent; `frames=()` with captions only → present; `frames=()` with no history → present. *(T-0053 criterion 2 — the over-wide direction tells a human who is sharing their screen that nothing is visible, which is worse than the bug this task fixes.)*
14. **Labels are positional, bounded and conditional.** A module-level pure `frame_label(index: int) -> str` (name is contract) that is a function of the index alone: no total, no count, no duration, no clock — and a module-level constant the tests read for its wording family. Each label ≤ 64 code points. Labels are emitted **iff `budget.max_frames_per_turn > 1`**. *(D4; T-0053 criterion 11 — `prompt_builder.py` imports no clock, still asserted by the AST scan.)*
15. **The rollback lever, prompt half (negative).** With `Budget(max_frames_per_turn=1)`, `prefix(frames=(f,))` and `prefix(frame=f)` both return a prompt **byte-identical** to today's `prefix(frame=f)` for the same inputs — no label, no new part, same order — and `tests/unit/test_prompt_builder.py`, `tests/unit/test_prompt_budget.py` and `tests/unit/test_prompt_recollection.py` pass with the **assertion diff empty** (`git diff main...HEAD -- tests/ | grep -E "^-[^-]" | grep assert`) and no fall in per-module assertion count. *(`.claude/rules/tests.md`, "to check whether a premise rewrite killed an assertion, diff the assertions".)*
16. **Nothing in the cached region moves (negative).** `system_message()` is byte-identical (compared by hash, derived from `system_prompt` + the constants, **never** from a copied literal of the block — T-0053 ruling A3, T-0055's owed token count); `_caption_part`, `MEMORY_HEADER`, `RECOLLECTION_MARKER`, `NO_IMAGE_STATEMENT`, `relative_age`, `ANSWER_HEADROOM_TOKENS`, `Budget.max_images/image_age_turns/max_history_turns/max_prompt_tokens` unchanged; `HistoryTurn` and every other contract unchanged; the existing `frame: Frame | None` parameter still accepted and still meaning one frame; `mypy --strict` clean.

### Group C — the session keeps them, and the record says so (BLOCKED on the `session.py` grant)

18. **The session accumulates per turn.** A `_frames` list keyed on the current `turn_id`, appended by `snapshot_frame` under the same rules the machine applies (dedup on the fetched `Frame.phash`, cap with the live-slot replacement of D1), reset when the turn id changes, and passed to `prefix()`/`fit()` as `frames=`. `self._frame` stays the newest frame, so `commit_history`, `Episode`, `_write_thumbnail`, `_sync_history_frames` and `_resolve_frame` are untouched (D5). Every frame's bytes enter `_frame_bytes` as today.
19. **Two scene changes in one utterance reach the model, over the fakes.** A session driven over `FakePerception`/`FakeLlm`: onset, `scene.changed` A, `scene.changed` B, end of turn → the fake LLM's final request carries **three** `ImagePart`s in capture order, the transcript is the last text part, the prefill actually sent last is a byte-prefix of that request, and the turn record's `extras["frames"]` is the list of the three phashes in the same order. *(docs/03 I2; this is the criterion the human asked for by name.)*
20. **The turn line and the session log carry all of them.** `TurnRecord.extras` gains `frames` (ordered phash list), `frames_kept` and `scene_changes_seen` (so a dropped screen is diagnosable: seen > kept means the cap or the dedup bit); the `llm.request` record already dumps the prompt with image parts redacted to hash and size (T-0043), so the phashes appear there without a new tap. **No new session-log kind** — `KINDS` is a closed vocabulary owned by T-0043 and nothing here needs to open it. *(`.claude/rules/perception-memory.md`: "the badge state is logged with every turn" — which frames the model saw is the same class of fact.)*
21. **A suppressed re-issue never loses a frame.** With `PrefillPolicy.reissue_min_interval_ms` **unchanged**, two scene changes 200 ms apart produce two snapshots and one prefill on the wire, and the final request still carries **both** frames. *(Today the rate limit is 1 000 ms while docs/01 D9 says "~700 ms" — **a documented discrepancy, recorded here as a finding and deliberately not changed**: it is a tuning decision with a latency consequence and belongs in its own task.)*
22. **The cost of the feature is bounded and observable.** Over one turn: prefill re-issues sent ≤ frames appended, and **zero** extra requests when the scene does not change or returns to a screen already seen. Asserted by counting calls on the fake LLM, not by timing.

## Implementation notes

- **`turn_machine.py` is pure** (`.claude/rules/conductor.md`): no clock, no I/O; `MachineState` is `frozen=True, extra="forbid"`, so build with `model_copy(update=…)` and keep the new field a `tuple`. The bounded-state property (T-0003 criterion 23) is why the machine records **hashes, not counters**: an integer counting dropped scene changes grows without bound over a long LISTENING and would need an arbitrary clamp. Whoever wants "how many were dropped" gets it in group C, where the session sees every event it submitted.
- **Two caps, on purpose.** `TurnPolicy.max_frames_per_turn` (machine) and `Budget.max_frames_per_turn` (builder) are separate constants in modules that must not import each other; a row asserts their defaults are equal, and the **builder's is authoritative** — an adversarial row sets the machine's to 10 and asserts the prompt still carries ≤ 3 current images and ≤ 4 in total, because the thing that must never be exceeded is the engine's `--limit-mm-per-prompt`, and only the builder sees the whole prompt.
- **The prefill must stay byte-identical where D9 promises it.** Everything this task adds lives *inside* the current user message and *after* the frames already sent, so each prefill remains a prefix of the next and of the final request. The label constant is the trap (D4). Second trap: `_extend` appends the suffix parts to the last message — the labels are **not** suffix parts; they belong to the prefix, next to their image, or the first re-issue after a `full()` would not share a prefix.
- **`prefix()`/`fit()` signature.** Keep `frame: Frame | None` accepted and add keyword-only `frames: Sequence[Frame] = ()`; exactly one of the two may be non-empty, and `frame=f` is exactly `frames=(f,)` — one internal normaliser, no second code path. This is what keeps every existing caller and every existing row unchanged (criteria 15/16) while giving group C a clean call. `mypy --strict` must be clean without an overload zoo; if the honest signature needs one, that is the implementer's call to make and the reviewer's to check.
- **`_oldest_history_image` generalises from one hash to a set.** Today it protects "the last copy of the current frame's phash"; with N current frames it must protect the last copy of **each** current phash, and `_image_turns`' `slots = max_images - (1 if frame else 0)` becomes `max_images - len(current images)` — note *images*, not *frames*: a current frame deduped against a history image consumes no slot.
- **The onset frame is still the onset frame.** `get_frame(at=speech_onset)` is the default for the first frame (`.claude/rules/perception-memory.md`); later frames are captured at the scene-change time, as today. Do not "improve" this into `latest`.
- **Do not add a session-log kind.** `KINDS` in `telemetry/session_log.py` is a closed vocabulary (T-0043) and the prompt dump already carries the redacted images.
- **Frames from two sources.** `Frame.ts_ms` for a screen frame and for a camera frame are not necessarily on one clock; the labels are therefore positional and carry **no elapsed time at all** (`.claude/rules/conductor.md`: "a duration is never computed from two clocks"). If a future label wants "+1.4 s", it must first establish that both frames came from the same source and the same clock.
- **Focus crops (`Frame.crop_of`) are out of scope.** A crop is already "a second image" by design (`.claude/rules/perception-memory.md`); how a crop interacts with an accumulated frame list is a follow-up, and nothing here may make it harder.
- After two failed corrections in a session, stop and rewrite the task rather than stacking fixes (CLAUDE.md).

## Ambiguities for the human to decide

1. **The cap.** 3 is argued from the engine's 4-image ceiling and the ≈1 120-token cost per screen (D2). 2 would leave two history images and halve the added prompt cost; 4 would evict history pixels entirely and leave no slot for the recollection thumbnails D8 still owes. Say a number if 3 is wrong.
2. **What happens at the cap.** D1 keeps the first frames and replaces the **last** slot, so the newest screen is always present and the middle of a long utterance is what gets lost. The alternative — ignore everything past the cap — keeps the whole prefix append-only (no cache churn at all) but freezes the model's view at the third screen. The trade is one image's worth of prefix cache against freshness.
3. **The rate limit.** The code re-issues at most every **1 000 ms**; docs/01 D9 says **~700 ms**. Nothing in this task changes either, and the discrepancy predates it. With accumulation the limit now also bounds how many frames a turn can gather — at 1 000 ms a 3 s utterance can show at most three screens, which is exactly the cap, and that coincidence is not a design.
4. **The HUD.** "What the model sees" is the page's *own* capture preview, not the frames the prompt carried; today a human cannot see which screens were sent. Showing N server-side thumbnails is a new `astra.*` message, a panel change and a `contracts/protocol.py` edit — a small task of its own, worth doing if you intend to demo this.
5. **History.** A multi-frame turn ages to one image and one caption (D5). If a two-screen comparison should still be visible one turn later, `HistoryTurn` needs a frame **list** and the image budget needs to grow — which the engine's 4-image ceiling forbids without a launcher change.
6. **Per-frame episodes.** `commit_history` still writes **one** `Episode` per turn (the newest frame), so the memory store never learns about the screens in between. Writing one per frame multiplies thumbnails and captioner work; it is the right thing if "what was that other tab I had open?" is a query you want answered.
7. **T-0060 (interleaving).** Ordering is the question: interleaving the transcript between frames breaks the "all images before the text" shape this task relies on for D9, so it will need its own prefix argument — probably "the prefix ends at the last image and the interleaved text lives in the suffix", which only works if the frames still precede the *first* transcript fragment. Worth deciding before T-0060 is planned, because it may constrain this task's layout retroactively.
