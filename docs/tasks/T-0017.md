# T-0017 — `LlmBackend.generate` takes `xargs`; the fake and the real client both conform

**Status:** merged 2026-09-13 (review MERGE, 9/9 mutations red) · **Blast radius:** medium (a service protocol) · **Depends on:** T-0005 (its revision must land first)

## Goal
`local_astra/contracts/protocols.py::LlmBackend.generate` gains the `xargs` keyword that
T-0005's `VllmClient.generate` already accepts (amendment B6), `tests/fakes/llm.py::FakeLlm`
follows, and — new — a contract test asserts the **real** client is an `LlmBackend`. After this
task, T-0011 (the per-step tap) and the constrained-decoding work can pass `vllm_xargs` through
the protocol type without a mypy error against the protocol or a `TypeError` against the fake.

## Why this is its own task
Spun out of T-0005's review (finding H4, ruling B11). B6 added `xargs` to the concrete client so
two later tasks would not have to retrofit a signature. But the protocol and the fake are not in
T-0005's owned files, and CLAUDE.md is explicit: a contract change and its fake land in the same
PR, and `tests/fakes/` is the test-author's. Widening one task's ownership to reach both would
break the rule that keeps two agents off one file. Twenty lines, its own PR.

## Acceptance criteria
1. `LlmBackend.generate(self, prompt, request_id, options=None, *, xargs=None)` — `xargs` is
   `Mapping[str, str] | None`, keyword-only, defaulting to `None`. Positional callers are
   unaffected: every existing call site compiles unchanged.
2. `FakeLlm.generate` accepts `xargs` with the same signature and **records** it on the fake
   (`self.last_xargs` or equivalent), so a test can assert what a caller passed through.
3. `isinstance(FakeLlm(), LlmBackend)` still holds (already asserted in
   `tests/contract/test_fakes_conform.py`), **and** `isinstance(VllmClient(...), LlmBackend)` is
   now asserted too. Today nothing checks the real client conforms; a drift between the two would
   surface only at runtime in T-0007.
4. `mypy --strict` passes with a caller typed as `LlmBackend` passing `xargs={"astra_tap": "1"}`.
5. `xargs` keys and values are strings only, matching `vllm_xargs`' JSON-scalar rule in
   `contracts/llm.py::LlmOptions.extra_body`; a non-string value is rejected at the boundary, not
   forwarded to the engine to 400 later.

## Rulings after test activation (2026-09-13)

**A1 — criterion 3, corrected wording.** `isinstance(VllmClient(...), LlmBackend)` is a name-only
check under `runtime_checkable` and cannot fail today; it stays as a rename guard, but the
criterion's content is *signature* conformance of both sides, carried by
`test_both_implementations_accept_the_protocols_xargs` (red until the protocol changes).
**A2 — criterion 5 is static, not a new runtime rule.** "Strings only" is enforced by the type
checker (`Mapping[str, str]`; a non-string value is a mypy `arg-type`/`dict-item` error, never
`call-arg`). At runtime the boundary is `LlmOptions.extra_body`'s existing JSON-scalar rule
(`contracts/llm.py`, merged T-0005 tests pass `True` deliberately) — T-0017 does not own that file
and does not tighten it. The exception type there stays `TypeError`.
**A3 — the fake mirrors the real client's `request_body` composition** (`dict(xargs)` +
`astra_request_id`, then `extra_body`), so a caller's spoofed `astra_request_id` is overwritten on
both backends and `abort()` stays targetable.
