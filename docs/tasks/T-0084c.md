# T-0084c — The two-pass driver runs the native format (pass 1 with `tools=`, native pass-2 shapes, seeds, guards)

**Status:** done (2026-10-10; verified at 0467fb6); planned 2026-10-09 · **Blast radius:** medium (one reviewer) · **Branch:** `T-0084c-twopass-native` from `main` after T-0082b,

## Goal
`twopass.run` can send a native-format pass 1 and native pass-2 cells next to the existing `<cc>` cells, in the same run and paired by
case. Every row records its format, and `derive` is format-aware. A cc-only run is unchanged.

## Acceptance criteria
1. **Cells.**
   - `native/<T1|T2|T4>/<named|union>/<arm>` is accepted, with the same arms as cc. The seed arm is allowed only with `named`.
   - cc cell names are unchanged.
   - A run sends a native pass 1 iff it has a native cell, and a cc pass 1 iff it has a cc cell.
   - An unknown format raises `ValueError` before any socket.
2. **Native pass-1 body.**
   - `system` = `NATIVE_SYSTEM_PROMPT` (wording below; sha recorded in the regime).
   - The same user content as cc.
   - `tools` = `native.tools_field(tools)` and `tool_choice` = `"none"` (QN3).
   - Thinking on, `max_tokens` 1024, `return_token_ids`.
   - The cc pass-1 body is byte-identical to `main`.
3. **Native pass-2 bodies.**
   - T1/T2: a deep copy of the native pass-1 body, plus `vllm_xargs` and `max_tokens` (1024 for T1, 256 for T2). `tools` is kept.
   - T4: the same, plus the assistant message `{"content": spoken_prefix + "<|tool_call>"}`, `continue_final_message: true`,
     `add_generation_prompt: false`, and `max_tokens` 256.
   - Grammar: `compile_toolcall(..., call_format="native")`.
   - `named` scope = `native.draft_name(draft_call_text)`. When that is None, the native picker runs, and the picked name comes from
     `native.draft_name` on the picker's call text.
4. **Scoring.**
   - Native drafts and outputs are parsed by `native.parse_call` and scored by the unchanged `score.schema_valid`/`score.exact`.
   - The pass-2 call text is the answer channel with closed thoughts removed and a leading `<|tool_call>` dropped.
   - A native-format pass 1 routed with a tag other than `native` scores as `wrong_tag` (QN7): it counts as called, with `draft_parse:
     "wrong_tag"`, schema_valid False and exact False, and no pass 2 is sent.
   - In cc rows, native-tag routes keep today's handling bit for bit.
5. **Seeds (QN6).**
   - `seed = (H(thought) + encode(T + draft_call_text.rstrip()) + S)[:CL]`, where T = `<|tool_call>` for T1/T2 and `""` for T4, and H and S
     are as in T-0081b.
   - **Alignment proof:** for each tool and thought, a template-rendered draft ending in 49 and stop 50 gives a seed that `replay.accepts`
     under the native grammar.
   - Controls, which must be rejected: a seed keeping the spoken prefix; a seed with `<cc>` in place of 48.
   - cc seeds are byte-identical to `main`.
6. **Served-prompt guards** (native requests only). Each failure is a stop: exit 1, `stopped` set, report written.
   - No `prompt_token_ids` → `prompt_guard: missing`.
   - Native pass 1 where the count of id 46 or of id 47 ≠ the number of tools → `prompt_guard: declarations`.
   - T1/T2 whose prompt ids ≠ the case's native pass-1 prompt ids → `prompt_guard: prefix`.
   - T4 whose prompt does not end in 48 → `prompt_guard: continuation`.
7. **Rows.**
   - Every row gains `format`; rows of older artifacts without it read as cc.
   - Native pass-1 rows also record `prompt_len`, `text_after_close`, `spoken_prefix_chars`, `open_thought_call` and `draft_close: ""`.
   - Native seeded rows record the T-0081b seed fields.
8. **`derive` is format-aware.**
   - `draft_only` uses cc pass-1 rows; `draft_only:native` uses native rows.
   - `cd_*:<cell>` pairs a cell with its own format's pass-1 row.
   - On T-0080c's stored artifacts, `derive` and `select` reproduce the recorded tables and choices.
9. **Order.**
   - Pass-1 format order alternates per case: cc first on even case indexes, native first on odd ones.
   - Pass-2 order follows the R-W Williams row over the full cell list, indexed by the count of cases routed in at least one format. Cells
     whose format did not route are skipped.
10. **Replay.** T-0082b's `pass1_from` refuses an artifact containing a native row (`ValueError`, before any socket).
11. *Negative.*
    - A cc-only run of the scripted scenario is identical to `main`: bodies, request count and rows, apart from the added `format: "cc"`.
    - `SYSTEM_PROMPT` sha `fa5dace3…` is unchanged.
    - Unchanged: `router.py`, `score.py`, `native.py`, `decoding/**`, `plugin/**`, `conductor/**`, `contracts/**`,
      `eval/cd/{runner,arms,calibration,cuts,hardstop,replay,records}.py`, `thresholds.py` and the locked scripts.
    - Loopback only; `google_search` is never executed.

## Implementation notes
- **`NATIVE_SYSTEM_PROMPT`**, proposed wording (the human approves it at H-T84-0). The template appends the declarations.
  > You are Astra, a voice assistant that can see the user's screen and act on it.
  >
  > Answer the user briefly. When an action is needed, first say in one short sentence what you will do, then call exactly one of the
  > declared tools. Use at most one call per answer. When no action is needed, answer normally and call no tool.
  >
  > Screen coordinates x and y are integers from 0 to 999, normalised to the attached screenshot: (0, 0) is its top-left corner and
  > (999, 999) its bottom-right corner.
  
  Record the sha256 of this text and of the canonical JSON of the `tools` field in the regime.
- Score from host-decoded `return_token_ids`, never from the served `content` or `tool_calls`. `replay.detokenize` keeps special pieces.
- vLLM v0.29.0 returns `prompt_token_ids` at the top level when `return_token_ids` is set. With `tool_choice: "none"`, the server skips its tool
  parser but still renders the tools, unless `--exclude-tools-when-tool-choice-none` is set. `services/vllm.sh` does not set it, and guard 6
  catches the case if it ever does.
- One place decides a row's format. `executed_steps` stays the one place for k0.

## Implementation log (implementer, 2026-10-10, branch `T-0084c-impl` from db496bf)
- **One file:** `local_astra/eval/cd/twopass.py`. Nothing else under `local_astra/` changed; no test touched.
- **Format, one place each.** A cell's format is `cell_format(name)` (`native/` prefix), stored on `Cell.fmt` by `parse_cell`
  (`native/<T>/<scope>/<arm>`; any other 4-part name, `xml/...` or `json/...` included, is a `ValueError` before any socket). A row's
  format is read only through `row_format(row)` (`format`, absent → cc). Rows get `format` from `Cell.fmt` (pass 2) or the pass-1 call's
  `fmt`.
- **Pass 1.** `native_pass1_body` = `pass1_body(model, NATIVE_SYSTEM_PROMPT, …)` + `tools` (`native.tools_field`) + `tool_choice: "none"`.
  The routed and scored fields of a pass-1 row come from one function, `pass1_fields(text, fmt, tools, gt)`, which both `_Run.pass1` and
  `rescore` call. cc is the old code path. Under native, a `native` route is parsed by `native.parse_call`, and any other `toolcall` tag is
  `wrong_tag` (called, invalid, not exact). The function also records `text_after_close`, `spoken_prefix_chars` and `open_thought_call`
  (C6). `prompt_len` is recorded in `_Run.pass1`.
- **Pass 2.** `pass2_body(..., fmt)`: T4 continues `spoken + "<|tool_call>"`, and `tools` is kept (it is a deep copy of the native
  pass-1 body). `automaton(scope, thought, fmt)` passes `call_format="native"` only for native, so cc calls are unchanged. The named scope
  is `native.draft_name(draft_call_text)`; the native picker reads `native.draft_name(call_text_of(text, "native"))`. `call_text_of` and
  `score_call` take `fmt`.
- **Seeds.** `seed_ids(..., *, fmt="cc")`; T = `<|tool_call>` for native T1/T2. `seed_source` is unchanged, and the `executed_steps`/k0
  path is untouched.
- **Guards.** `_Run.prompt_guard` checks native requests only. It runs on the response before the records are awaited, so no flush and
  no later request follows a failure. The stops are `prompt_guard: <reason> (the served prompt; …)`. The T1/T2 prefix is compared against
  the case's served native pass-1 prompt ids, which are kept in memory and not in the rows.
- **Order.** `_loop` sends one pass 1 per format in use, in cc→native order on even indexes and the reverse on odd ones. The Williams row
  covers all cells, indexed by cases where `sends_pass2` holds for some format. Cells of a format that does not route are skipped.
- **derive.** `_policy_format` assigns `draft_only` to cc, `draft_only:native` to native, and a cell to its own format. `p1` is filtered
  by format. A native `wrong_tag` row keeps the draft's outcome under every policy (C8).
- **Regime.** Only when a native cell is present, a `native` block records the prompt, its sha, the canonical tools-field sha, the
  tool_choice and the pass-1 order. A cc-only regime is unchanged.
- **Replay.** `_replay_source` refuses any pass-1/2 row with `row_format == "native"` (the message names "native"). Replayed rows are
  written with `format: "cc"`.
- **Choices the tests do not pin (for the reviewer):**
  - `run` also refuses a replay whose cells include a native cell (`ValueError`, before any socket). A replay would otherwise mix a live
    native pass 1 with a replayed cc pass 1.
  - A `wrong_tag` row keeps the router's `draft_close`, so a native pass 1 ending in `<cc>{…}</cc>` records `"</cc>"`. Native-tag rows
    always record `""`.
  - `text_after_close` is `None` when there is no `<tool_call|>` (or the route is not native). It is cut at the first `<tool_call|>` in the
    draft, not by a string-aware scan.
  - `bucket_histogram` keys native thoughts as `native/<T>`.
  - `report()` is not yet format-aware beyond `derive`: `n_cases`, route recall and the agreement and seed sections pool both formats'
    pass-1 rows. That is T-0084d's report.
