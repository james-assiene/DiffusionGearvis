## Goal

**Bug 1.** The model claims it has no current screenshot while the request carries one: `logs/sessions/20261029-173950-15317.jsonl` seq 16202 (weebcentral step 7, continuation 1501 chars: "I don't have the latest screenshot because the turn ended" → spoke "I cannot see the screen right now"); `logs/sessions/20261029-181336-282350.jsonl` seq 3957 (gov.uk ILR step 15, continuation 6168 chars: "I don't have the current screenshot" → "I cannot see the current search results"). Not only late: across the 10-27..10-29 live logs (`20261027-230926-966483`, `20261028-145330-1824860`, `20261029-173950-15317`, `20261029-181336-282350`) ~15 labelled `tool_step` requests with an image were followed by such a thought, some at step 2–3 (seq 8945, 9083, 5225).

Confirmed in source at efae3ad6: a step request is `loop.step_prompt(base, steps)` — the step-1 prompt plus one final assistant message `text_1 + call_1 + response_1 + …` sent with `continue_final_message` (`toolcall/loop.py` `step_prompt`, `_continuation`). The current frame is the newest `ImagePart` of the step-1 final user message (`show_current_image`), with the T-0134 label after it (`Session._run_step` → `_live_label`, `session.py` ~4479). So the last thing the model reads is the last tool response, not the image or its label. The only text that can follow the continuation without closing the model turn is inside that final assistant message; precedent: `loop.with_report_fact` (T-0178 B1) appends `REPORT_SEPARATOR + REPORT_FACT` after the last tool response, and `_run_step` reserves room for it (B1a). Rejected: a key in the newest tool response (responses persist in `loop_steps`; it would break T-0120b's same-bytes extension, move response pins, `MAX_RESPONSE`, compaction stubs and T-0137's `repeat_of_step` copies).

**Bug 2 (HUD).** "What I see" goes blind during a T-0172 re-ask: `20261029-181336-282350.jsonl` seq 1329 and 2962 show `astra.vision.frame {blind: true, images: []}` beside `phase announce_reask` with 1 image. Confirmed: `reask_prompt` (`toolcall/announced_call.py` 186) ends with a user message holding only `REASK_NUDGE`; `_publish_vision` (`session.py` 3972) reads only the final user message's images; its history fallback accepts only `_turn_frames()` phashes, and the live frame swapped in by `show_current_image` is not one of them.

## Acceptance criteria

### Group A — the re-ask's vision frame
- **A1.** A T-0172 re-ask's publish key `(source, identities, blind)` equals the key of the step request it re-asks (T-0177 B7); with that already published, the re-ask publishes nothing new. At step 1 and step ≥ 2, live browser source.
- **A2.** Same with an older turn's history image present: images are the current frame, never the history image; `history_images` equals the step's.
- **A3.** If a reset or new turn cleared the key before the re-ask's publish, the re-ask publishes the re-asked request's images (not blind) with the step's `source`, `step`, `images`, `history_images`.
- **A4 (negative).** A re-ask of a request with no image anywhere still publishes `blind: true` with the turn's `vision_source`.
- **A5 (negative).** Prefill, generate, step, T-0171 resend and T-0179 degenerate-retry publishes byte-identical to BASE; captioner and ReGround pass 2 never publish; every row of `tests/unit/test_t0177_vision_frame_publish.py` and `tests/unit/test_t0172_session_reask.py` passes unchanged.

### Group B — the screen reminder (off by default)
- **B1.** `Session(screen_reminder: bool = False)`; with `False` every request body, `llm.request` record and wire message is byte-identical to BASE on every existing session test.
- **B2.** With `True`, a `tool_step` request on which `_live_label` placed a label gets `SCREEN_REMINDER_SEPARATOR + <reminder>` (`"\n\n"`) appended to its continued final assistant message, after the last tool response, outside any payload, via a pure append-only helper in `toolcall/loop.py`; every other byte, message, part and `Prompt` field unchanged; the wire body differs from BASE only in the suffix of `messages[-1]["content"]`.
- **B3.** One of five fixed constants by the label placed: `LABEL_NOW` → `now`; `LABEL_UPDATED` (with or without outcome/extent clause) → `updated`; `LABEL_UNCHANGED` → `unchanged`; `SHARED_LABEL_SCREEN` → `shared_screen`; `SHARED_LABEL_CAMERA` → `shared_camera`; T-0177 B2's `label_now_next` → `now`. - **B6.** The T-0171 resend, T-0179 retry and T-0135 recovery resend the prompt as sent (reminder included); a T-0172 re-ask is `reask_prompt(<that prompt>, said)`.
