## Goal

`make fast-parallel`, which is what the Stop hook runs on every agent finish, measures 52–61 s against its 60 s budget (last run 60.65 s), and grows by about 1–3 s per task. The cause is not one slow module. The suite now holds about 470 s of test time (8 772 rows, 294 modules), which is about 59 s per worker at 8 workers, on a box with 32 threads. The planner's measurement (below) groups that time by cause:
- **Real-time audio and STT waits, 23 %.** They are wait-bound, so they overlap well across workers.
- **Hook-script subprocesses, 12 %.**
- **Report and refusal tables, 9 %.**
- **BASE-commit `git archive` + subprocess comparisons ("differentials"), 7 %.**
- **CPU "dress runs" of the A/B harnesses' `main`, 6 %.**
- **The Hypothesis invariant properties, 4 %.**
- **Everything else, 30 %, spread over 228 modules.**

Nothing in that list can be removed without weakening a check, and no single cheap change in it is worth more than about 2 s of gate time.

The cheapest change that keeps every check's power is more workers. T-0031 chose 8 as "a fixed modest `-n`" and pinned the range 4 ≤ N ≤ 12. Measured on main at 0248cfd on a busy box:
- `-n 12 --dist loadfile` ran in 38.8 s and 46.6 s;
- `-n 8` ran in 54.9–68.2 s;
- the selection and the results were identical.

After this task:
- the hook and `make fast-parallel` run `-n 12 --dist loadfile`;
- the five places that state the worker count agree, and a test makes them agree;
- each later task costs the gate about two-thirds of what it costs today.

The 60 s budget, the 120 s serial ceiling, the hook timeout and every test stay as they are.

## Implementation notes

- **Why 12 and not more.** 12 is the top of T-0031's measured range, and `test_stop_hook.py` already allows it. Going higher needs H-T143-1. At 12 the run is still CPU-bound (470 s of test time ÷ 12 ≈ 39 s), so the longest single file is not yet the bottleneck:
  - `test_protect_paths_hook` 27 s under load;
  - `test_turn_invariants` 20 s;
  - `test_audio_clock` 20 s;
  - `test_stop_hook` 19 s.
- **Keep `--dist loadfile`.** worksteal measured 39.7 s against loadfile's 38.6–38.8 s at 12 workers: no gain. It would also:
  - split module-scoped fixtures across workers, so each BASE `git archive` + subprocess (one per module today, 14 distinct SHAs) would run once per worker that touches the module;
  - drop T-0031's guarantee that a module's rows never interleave, which the audio modules rely on.

  `loadgroup` without `xdist_group` marks behaves the same as `loadfile`, and adding the marks would edit dozens of test modules.
- **No ordering plugin.** Longest-file-first ordering was measured and was inconclusive: at `-n 8`, 57.3 s against 54.9–68.2 s without it; at `-n 12`, 39.5/38.7 s against 38.8/46.6 s. It is a candidate only if the worker count goes past 12, where the longest files start to set the wall time.
- **Load sensitivity is the risk** (T-0031 A2/A3). Each extra worker adds contention for the timing-sensitive rows; T-0129's linear-time row has already failed at load 2.8–5.4 with 8 workers, and once more during this planning. The criterion 4 accounting is the mitigation. Never loosen an assertion to get green, and never use `-n auto`.
- **CPU-resident services.** STT runs on CPU (desk sessions). A hook run during a live desk session now takes 12 of 32 threads instead of 8. See H-T143-4.
- **Hook rules.** `stop_fast_suite.sh` matches `FAILED`/`ERROR` only at the start of a line, and xdist keeps the `-rfE` summary lines unprefixed. The mypy step stays byte-identical. `guard_bash.sh` blocks test-silencing flags; `-n` is a worker count, but re-check its flag tables.
- **Mutation copies** follow `.claude/rules/tests.md`: a unique name, origin proof, a `__pycache__` purge, and Hypothesis `database=None`. Never export `GIT_DIR`/`GIT_WORK_TREE`. No heredocs around a blocked Write.
