## Goal

The page the human sits in front of is a 2018 developer console: one 14 px monospace family for everything including prose, all-caps 11 px letterspaced headings, a fixed four-column grid that leaves two ragged holes and ~300 px of dead black below the fold once the assist and session-log panels mount themselves, empty panes that are simply blank boxes, no focus ring on the ask box that is the whole typed path, and an empty-transcript line rendered in `var(--edge)` at a measured **1.34:1** contrast — legible only if you know it is there. This task restyles it: a real type scale with a sans face for prose and the mono face kept for numbers, a 4 px spacing rhythm, a named colour-token layer with a light theme that follows the system, one elevation level, a grid that lays out *n* panes rather than exactly four, a visible state for every `data-turn-state`, an honest empty state per pane, and reduced-motion and contrast floors that hold at a desk while the human is talking.

**The single most likely way this work goes wrong is the network.** Everything binds to loopback and a test asserts zero non-loopback sockets and zero absolute non-loopback URLs in `hud/**` (`docs/02` §9, `docs/03` §9, `tests/unit/test_hud_no_audio_no_egress.py`). A page that wants to look current reflexively reaches for a font from a font CDN, an icon set, or a framework stylesheet; every one of those breaks that rule, fails that test, and — worse — makes the page depend on a route this box is not supposed to have. **Nothing is fetched.** Fonts are system stacks; if a face is ever vendored it arrives as a file under `hud/` with a provenance row in a manifest, and that is its own task, not this one. No npm entry, no `@import`, no `url()` that resolves outside `hud/`.

The second thing to get right is *which* ugly the human means. Two surfaces are involved and they are not the same problem. The **page chrome** is ours: plain HTML and CSS, group A. The **shown channel** is an interface the model generates, rendered by the pinned vendored `@a2ui/lit` bundle in `hud/vendor/` against a catalog — we do not restyle its markup, we bind the `--a2ui-*` custom properties it already reads (the bundle exposes ~60, measured), which is group B. The log says the human has seen that pane render either the `no surface yet (T-0010)` placeholder or, once, a **two-component** surface (T-0052 ruling A6; the reassembled version renders seven). So the shown channel has arguably never rendered well enough to be judged, and group B's result cannot be evaluated until T-0052 has merged. Group A is what they were looking at.

Non-goals: no behaviour, no wire field, no new message, no panel logic, no copy change that any test or any JS file matches on, no new dependency, no build step. The page stays buildless ES modules served over loopback.

## Implementation notes

Constraints, contracts and landmines. The implementer designs the sheet; these are the fences.

- **The four project rules this restyle can break without looking like it.** (1) Loopback only — no fetched asset of any kind. (2) The shown surface is the vendored renderer's, themed through `--a2ui-*` and never by restyling its markup or touching `hud/vendor/**`. (3) `hud/**` is contested with T-0047 — stay inside *Owned files*, and if a change seems to need `panels.js`, `main.js` or `state.js`, it is out of scope by definition. (4) The data path is not presentation — nothing in this task may make the page derive, buffer or optimistically render anything. In particular: **do not add `aria-live` to the spoken pane** in this task. It is one attribute in a stylesheet-shaped diff and it makes a screen reader speak text on a schedule the Conductor did not authorise, which is the wrong side of "never voice text the LLM has not committed". If it is wanted, it is a task with a criterion about what may be announced and when.
- **Known landmines, each already paid for once:**
  - `hud/src/ui/index.js` strips the placeholder by `querySelectorAll(".placeholder")` **and** a text match on `no surface yet (T-0010)`. Class or copy change ⇒ a dead placeholder under every surface, and `test_hud_rehearsal.py`'s "the placeholder is still up" row goes red.
  - `tests/hud/state.test.mjs` allows **exactly one** rule in `hud/styles.css` to contain `line-through`, with selector exactly `[data-unplayed]` (T-0030 criteria 19–22). A second decorative strike-through anywhere under `hud/` fails it. The correct response is to not add one.
  - `panels/thinking.js` writes `--fill` as an inline custom property and positions `.tick` with an inline `left`. Any bar implementation must consume both.
  - `assists/index.js` and `log/index.js` inject `<style>` into `document.head` **after** `styles.css` loads, so their declarations win ties. Specificity matters: do not rely on a `.pane p { … }` rule beating `#log-panel .log-counters { … }`.
  - `color-scheme` is what keeps native checkboxes and the ask input dark. Changing it to `light dark` (criterion 13) changes native control rendering in both schemes — check the assist checkboxes in a screenshot, they are the page's only native controls.
- **The token layer is the whole design.** Define `:root` once: the nine existing names (kept, values may change), plus `--bg --surface --surface-2 --edge-strong --faint --sans --mono --text-xs/-sm/-base/-lg --space-1..-6 --radius-sm/-md/-pill --ring`. Every rule below consumes tokens; no colour literal outside `:root`. That is what makes criterion 13 a fifteen-line block and what lets group B map the surface with no second palette.
- **Concrete defaults to execute (the human vetoes from the screenshots, they do not have to invent):**
  - *Type.* Two stacks, zero bytes fetched. `--sans: system-ui, -apple-system, "Segoe UI", Roboto, "Noto Sans", "DejaVu Sans", sans-serif` for prose, labels, buttons, the transcript and the spoken pane; `--mono: ui-monospace, "DejaVu Sans Mono", monospace` kept for counters, ids, the log path, `thinking_ms`, capture size — numbers stay tabular (`font-variant-numeric: tabular-nums`, which stops the counters twitching at 4 Hz). Scale 12/13/15/18 px; body line-height 1.5, spoken 1.55. Headings drop from 11 px all-caps 0.16em to 12 px semibold 0.04em, sentence case, `--dim`.
  - *Spacing.* 4 px base. Pane padding 16, grid gap 16, bar padding 10/16, control height 32 minimum.
  - *Grid.* `repeat(auto-fit, minmax(320px, 1fr))` with `grid-auto-rows: minmax(220px, auto)` and `main { min-height: calc(100dvh - <bar>) }`; spoken and shown may span two tracks where tracks allow. Panes stretch rather than leaving a black shelf.
  - *Elevation.* One level. On dark, no drop shadow — a 1 px hairline plus `box-shadow: inset 0 1px 0 rgb(255 255 255 / 0.04)`. Radius 10 px panes, 6 px controls, pill chip.
  - *The two output channels are never confusable.* The spoken pane is prose: sans face, an accent-coloured left rail per turn (the existing `.turn` border), heading in `--accent`. The shown pane is a rendered artefact: neutral `--edge-strong` frame, heading in `--dim`, no accent rail, and a visible frame edge so the model's interface is plainly inside a container rather than part of the page. ## Blast radius

**Medium — one reviewer**, with named escalation. It is not high: no turn machine, no audio path, no GPU service, no hook, no wire format, and nothing under `local_astra/`. It is not low either, for three reasons the reviewer should hold in mind: `.pane` and `<main>` are a cross-file contract that three JS files this task may not edit depend on; a token rename silently degrades four panels to hard-coded fallbacks while every test stays green; and a colour binding in group B can remove something the model chose to show without removing it from the DOM.

**Escalate to two reviewers if** any of these becomes true: the diff touches a file outside *Owned files*; a test module outside *Tests to write* is edited; a font file, npm entry or `hud/vendor/**` byte changes; `aria-live`, `role` or any other attribute that alters the accessibility tree is added; or the implementer changes a string that any JS file or test matches on.

## Ambiguities — for the human, not for the implementer to decide

1. **Light theme now or later?** My default is to ship it (criterion 13) as a declarations-only block, because "follows the system" is the modern default and the cost is one block plus a second pass of the contrast rows. Cheaper alternative: dark-only now, tokens structured so light is a later fifteen-line change. Dark is what the desk looks like; light is what a screenshot in a doc looks like.
2. **How technical should the top bar read?** `frames 0 dropped 0 capture — ignored 0u/0m/0r` is operator telemetry sitting where a product would put status. Options: (a) leave it, it is a developer HUD; (b) keep every counter but demote it to `--faint` mono at 12 px with the words shortened; (c) collapse it behind a disclosure and show only connection + capture state. My default is (b) — it is presentation-only, and (c) hides numbers the human has used to diagnose four separate bugs this week.
3. **Density: four columns of information, or two columns and a reading pane?** Default: the auto-fit grid of criterion 6, which at 1280 gives three tracks and at 1920 gives five, with spoken and shown spanning two. The alternative the human may prefer for a talking session is a fixed two-column reading layout with everything else in a right rail. This is the one decision a screenshot answers better than a paragraph — the implementer's before/after PNGs are the place to settle it.
4. **`no surface yet (T-0010)`.** The copy is developer-facing and appears in the pane the human looks at most. Changing it means editing `PLACEHOLDER` in `hud/src/ui/index.js` and two integration tests, which is a behaviour-adjacent change and deliberately **out of this task** (criterion 3). If the human wants it, it becomes a two-line follow-up task that changes the constant and the tests together — not a string edit smuggled into a restyle.
5. **Icons.** A 2026 page usually has some. No icon font and no icon package may be added (criterion 2). That leaves inline SVG written by hand in `index.html`. Default: **none this task** — the page reads fine with text labels, and hand-rolled SVG in a stylesheet task is scope creep. Say if you want a small set and it becomes its own task with a provenance line.
6. **Motion budget.** Default: one ≤ 1 Hz opacity pulse on the THINKING chip and nothing else; no transitions on pane content, because it repaints at up to 10 Hz and animated repaints at that rate read as jitter, not polish.
