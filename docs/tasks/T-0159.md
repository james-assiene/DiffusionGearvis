## Findings (planner, 2026-10-26)

1. `AstraCanvasStep.text_preview` is filled by no one. The plugin never detokenises (T-0011), and `test_plugin_tap.py:170` asserts `None`. It is one whole-canvas string and cannot be tinted per position. It stays as it is.
2. `local_astra/toolcall/detok.py` `HostDetokenizer` is the stdlib, offline, sha-checked reader of the pinned `tokenizer.json`. Its `decode` is proven equal to `tokenizers` by `tests/cd/unit/test_host_detok_parity.py`. Today the session loads it only when tools are `dry_run`/`live`. HF `tokenizers` is only in the `cd` group and is not importable in `session`.
3. Measured (CPU, 594cfd7, load 0.18, Python 3.11, pinned tokenizer cc8d3a0c, fixture `trajectory_806da12`, CL 256):
   - `HostDetokenizer.load()` takes 355 ms, adds 71 MB that stays and peaks at 312 MB.
   - One 256-id row to pieces: 12.2 µs median, 25.8 µs max (n = 920).
   - Validate + `model_dump_json` of one frame: 11 µs median, 105 µs max (n = 460).
4. Fixture rows: the argmax rows have 0 byte-fallback pieces and the canvas rows have 7; no id is unknown. JSON size of a piece row: ≤ 2.3 KB (argmax). The worst case is 256 × 65 B ≈ 16.6 KB per row, against the codec's 8 MiB. The HUD Outbox is capped by message count (8), not bytes.
5. The `wire.out` session-log row (`hud_server._canvas_row`) is built from a fixed key list, so the pieces are never logged with no change to `hud_server.py`.

## Goal

Every `astra.canvas.step` the relay publishes carries the text piece of every position: the argmax of a denoise frame and the committed ids of a commit frame. The pieces are decoded in the conductor from the real ids by the pinned stdlib detokeniser. The page shows the token at each position as it denoises, thought included, tinted by its existing state colour, and never decodes ids itself.
- **Group A:** the contract, the piece rule, the relay, and the HUD decoder mirror. The page looks the same after A alone.
- **Group B:** the page renders a grid of token cells per canvas.

## Acceptance criteria

### Group A — conductor and wire

A1. **Contract** (docs/02 §5, D15). `AstraCanvasStep` gains two optional fields, each `tuple[str, ...] | None = None`: `argmax_pieces` and `committed_pieces`. `_lengths_agree` adds these rules:
   - A denoise frame may carry `argmax_pieces`, of length `canvas_length`. It never carries `committed_pieces`.
   - A commit frame may carry `committed_pieces`, of length `len(committed_tokens)`. It never carries `argmax_pieces`.
   - A frame without pieces validates exactly as at BASE: every existing corpus case and contract row keeps its verdict.
   - `text_preview` is unchanged.

A2. **The piece rule** (`HostDetokenizer.pieces(ids) -> tuple[str, ...]`, one string per id):
   - An ordinary vocab piece is returned with every `▁` replaced by a space.
   - An added token, the 24 specials included, is returned verbatim (`<|channel>`, `<channel|>`, `<eos>`, …).
   - A byte-fallback piece is returned as its own literal, as written in `tokenizer.json` (`<0xE2>`). It is never merged with its neighbours: one position is one token.
   - An id outside the vocabulary raises `UnknownTokenId`.
   - Property: for every id list containing no byte-fallback id, `"".join(pieces(ids)) == decode(ids)`.
   - `decode`, `stream` and `load` behave exactly as at BASE (every T-0088a row stays green unmodified).

A3. **The relay fills the pieces.**
   - When the detokeniser is loaded, every `astra.canvas.step` the relay publishes carries `argmax_pieces` (denoise, when the frame has `argmax`) or `committed_pieces` (commit).
   - Every other field equals the received, validated frame. This amends T-0128c A2 from "unchanged" to "unchanged except the T-0159 fields, which the relay adds".
   - Pieces are computed only for frames that are published. A frame dropped by latest-wins coalescing is never decoded.
   - A frame whose ids do not decode is published without pieces (never dropped) and counted `undecoded`. This counter is added to `counts` and to the per-turn `denoise` note, which amends the T-0128c A7 note shape.
   - The T-0128c A3/A4 rate, order and admission rows still hold.

A4. **Never blocks the loop** (conductor.md, 20 ms).
   - The detokeniser is loaded off the event loop (`asyncio.to_thread` in `CanvasRelay.start()`), or is injected through the constructor. `cli.py` is unchanged.
   - Frames that arrive before the load finishes are published without pieces, and do not count as `undecoded`.
   - A loop-lag probe shows a maximum lag < 20 ms in two cases: while `start()` loads the real pinned detokeniser, and while the recorded trajectory is replayed through the relay at 40 ms per frame.

A5. **Says when it cannot decode** (conductor.md: a subsystem that turns itself off publishes that it did). If the detokeniser cannot load:
   - the relay still runs and publishes frames without pieces;
   - it prints one stderr line `astra session: denoising text off: <reason>`;
   - it records one session-log `note` `{denoise_relay: {pieces_off: <reason>}}`;
   - it publishes one `astra.error(code="denoise_no_pieces", message=…)` per session, at the first frame it publishes without pieces after the failure.
   - The session never fails to start because of this, whatever the tools mode.

A6. **The HUD decoder mirrors the contract.**
   - `hud/src/protocol.js` accepts the two fields with the same presence, phase and length rules, and refuses non-string items.
   - `tests/fixtures/hud/decode_corpus.jsonl` gains these cases, each with the same verdict in Python and JS: valid denoise with pieces; valid commit with pieces; argmax pieces whose length disagrees; `committed_pieces` on a denoise frame; `argmax_pieces` on a commit frame; a non-string item; pieces containing `<|channel>`, a newline and `</script><b>`.
   - docs/02 §5 and the "Canvas relay (T-0128c)" paragraph state the fields and the piece rule.

A7. **Size.** A synthetic denoise frame whose argmax row is 256 × the longest piece of the pinned vocab encodes under `codec.MAX_MESSAGE_BYTES` and passes `Outbox.offer` as a droppable canvas message. The Outbox cap stays 8 messages.

### Group B — the page (from James's reference image)

B-1. **Reads, never decodes.** The page reads `argmax_pieces` / `committed_pieces` from the decoded frame. No tokenizer and no id→text table exist in `hud/`.

B-2. **Never a fake trajectory.** A cell shows text only from the frame it draws. No pieces means no text (the cell is drawn as today, empty of text). No frame means no draw (T-0128c B5). There is still no `Math.random` in `hud/` except `ws.js`.

B-3. **Text is text.** Pieces are inserted with `textContent` (or canvas `fillText`), never as HTML. A piece `</script><b>x` shows literally.

B-4. **Thought text stays in the denoising view.** Model text from a canvas frame appears only inside `[data-denoise-root]`; no other pane's DOM gains it.

B-5. **States unchanged.** The T-0128c B2 cell states (stable, kept, noise, revised, committed, empty) and their current colours still come from the ids and masks only; the pieces never change a state. `data-denoise-digest` is computed exactly as at BASE.

B-6. **One cell per position, showing its token.**
   - Each canvas is a grid of fixed-width cells in position order, one per canvas position. Each cell is filled with its state's existing colour and shows the piece at that position:
     - denoise frame: `argmax_pieces[i]`;
     - commit frame: `committed_pieces[i]` for `i < len(committed_tokens)`; the remaining cells are `empty` and show no text.
   - The text updates at every drawn frame: a cell whose argmax changed shows the new piece.
   - Noise cells show their current guess dimmed, as in the reference image. Text colour is a token per state that reads on that state's fill in both themes.
   - Cells keep a fixed width. A piece longer than the cell is cut with "…". The full piece is in the cell's `title`, with whitespace made visible.
   - **Display form of a piece:**
     - leading and trailing spaces are trimmed;
     - a piece that is only spaces shows `␣`;
     - a newline shows `↵`;
     - a tab shows `⇥`;
     - an added or special token (`<…>` form, `<0x..>` bytes included) shows in the monospace utility face at a smaller size.
   - The grid has as many columns as fit the pane at a minimum cell width (8 in the 340 px rail). The canvas grid scrolls inside the pane (a bounded height). The page body never scrolls sideways.

B-7. **Several canvases.** The view keeps one section per `canvas_idx` of the shown request (B6 of T-0128c: only the newest request is shown).
   - Each section is a native `<details>` disclosure. Its `<summary>` states the section's label in the B4 form (`canvas k · step s/N` or `canvas k · committed at step s/N`).
   - When a frame of a new canvas arrives, that canvas's section is appended and open, and the previous newest section closes. Older sections keep whatever open state the viewer left them in.
   - A closed section can be opened to see that canvas's last drawn tokens.
   - A new request starts with an empty view: the previous request's sections go.
   - The pane label `[data-denoise-label]` still shows the newest drawn frame's label.

B-8. **Rate and motion.** At most one draw per animation frame, and only changed cells are updated. Under `prefers-reduced-motion: reduce`, at most 2 draws per second (the T-0128c rule). Text changes in place without transitions.

B-9. **Pixel and DOM rows replace T-0128c B10.** The Chrome rows prove four things:
   - each state's fill is the current state colour in both themes;
   - each cell's text contrasts with its fill (≥ 4.5:1 for settled/committed text, and ≥ 3:1 for noise, which is deliberately dim);
   - the rail at 1280/1440/1920 px has no horizontal overflow;
   - the disclosure opens and closes from the keyboard.

B-10. **`denoise_no_pieces`** is stated in the pane, in the same way as `denoise_no_tap`.

B2-1. **An end-of-sequence section.** A section is *end of sequence* when its newest drawn frame is a denoise frame with `argmax_pieces` present and every piece equal to `<eos>`. A frame without pieces is never end of sequence.

## Rulings

- **O-A1 (orchestrator, 2026-10-26 ~15:00, on the A test-author's measurement):** `HostDetokenizer.load` in `asyncio.to_thread` still lags the loop by up to 238 ms, because `json.loads` of the 30 MB file holds the GIL (CPU, load 0.42, sha cc8d3a0c, n=1). A4 is amended:
  - `CanvasRelay.start()` awaits the load (thread or not) **before** it begins reading the tap. That happens at session start, before the first turn, so the startup lag is accepted.
  - The < 20 ms bound applies to frame handling after `start()` returns: decoding and publishing frames during a replay.
  - The "frames before the load completes go out without pieces" row therefore no longer applies to the default path. It still applies to an injected `piece_loader` that has not finished, if the implementation keeps that path; otherwise drop the row.
  - The seam is `CanvasRelay(..., piece_source=None, piece_loader=None)`, as frozen in `tests/fakes/canvas_tap.py` (c192170).
  - Any test that starts a real relay without a stub either passes `piece_source`, or accepts the real load (355 ms) or the A5 path. `tests/unit/test_cli_session.py` and `tests/fixtures/hud/MANIFEST.md` join the A test-author's files for that, with minimal changes.

- **O-A2 (orchestrator, 2026-10-26 ~16:30, on group A reviewer 2, CHANGES REQUESTED at 9fe8a58a; supersedes O-A1's "start() awaits the load"):** awaiting the load inside `start()` opened a cancel window in `cli.run_session`. `_start_relay` runs after `server.start()` and before the `try/finally` that closes everything, so a Ctrl-C or SIGTERM during the ~0.4 s load skipped `server.aclose()` and `session.aclose()`. Reproduced at hold 0 and 0.1 s; BASE closes both. `cli.py` is not ours (A8, T-0156), so:
  1. `start()` opens and connects the SUB, starts the reader task, and returns at once, never awaiting the load.
  2. The reader awaits the load (in a thread) before its first `recv`, so no frame is read before the piece source is ready or has failed. Frames queue in the socket meanwhile, up to RCVHWM; latest-wins applies as usual.
  3. `aclose()` cancels a pending load and closes the socket and context. A `CancelledError` is never swallowed by the load wrapper; only `Exception` takes the A5 path.
  4. The < 20 ms bound applies to frame handling. The one-off load stall happens in the background after `start()` returns, at session start, before the URL lines are printed and in practice before the first turn; it is accepted.
  5. **Readings:**
     - frames published without pieces after a **failed load** are **not** counted `undecoded`, because no decode was attempted;
     - a decode failure without a load failure raises no `denoise_no_pieces`;
     - `_with_pieces` counts only `UnknownTokenId` and the frame's own `ValidationError` as `undecoded`, and anything else also goes through the rate-limited `_fault`.

## Implementation notes

- **Decoding in the relay:**
  - Decode at publish (`_emit`), not in `receive`.
  - Build the published frame so that it validates as `AstraCanvasStep`. `model_copy(update=…)` skips validators; if you use it, prove validity another way.
  - No cache: the table lookup is O(1).
- **`pieces()`** is a pure per-id lookup that shares no state with `stream()`. The change is additive, because `llm_client` imports `detok.py` on the speech path.
- **Loading the detokeniser:**
  - The relay constructor gets an optional injected piece source (tests), and otherwise loads `HostDetokenizer.load()` in `start()` through `asyncio.to_thread`.
  - A load exception is caught, reported through A5, and never re-raised into `_start_relay`.
  - With tools on this makes a second copy, about 71 MB; sharing it is a follow-up once T-0156 releases `cli.py`.
- **Thought and answer:** `segment` is `None` on every plugin frame (v0.29.0), so the relay cannot tell thought from answer. It decodes everything (ruling 1).
- **Page rendering:** a DOM grid of cells, updating `textContent` and a state class only where they changed, is the expected shape for B. The 2D canvas bitmap can go. Keep `data-denoise-frames/-draws/-digest` and the label exactly as their T-0128c meaning.
- **Oracles:** do not re-implement the function under test as the oracle (`.claude/rules/tests.md`).

## Risks

- **Field names change after B starts.** They are frozen here in A1.
- **Thought text reaches a pane other than the denoising view.** Guarded by B-4 and A8.
- **Two detokeniser copies with tools on.** Accepted for v0.1.

- **Rollback.** The fields are optional, so reverting A or B leaves a working view.
