## Goal
Choose `perstep_mar`'s two knobs (entropy bound, confidence threshold) per task on the dev cuts only, with every hard
stop armed, and freeze them in committed files before any test-cut request. Two engine launches: b1 Sudoku, b2 BFCL.

## Acceptance criteria
Criteria 7–9 of `docs/tasks/T-0071.md`:
1. **Stack check first, same boot** (umbrella 7): `unconstrained` on the dev cut (n = 100) with hard stops (d) and (f)
   armed; (d) firing ends the launch, (f) is reported.
2. **Grid** (umbrella 8, T-0070 criterion 10 amended by D-H3): all 18 `perstep_mar` cells on the dev cut per task, every
   hard stop armed, one boot per launch. An (e)-stopped cell (step cap on > 50 % of canvases) is **ineligible**, its partial
   score kept, and the grid continues; (a), (b), `internal`, (c) or (g) abort the launch. BFCL launch budget 6 h.
3. **Freeze** (umbrella 9): write and commit `docs/cd/calibration-{sudoku,bfcl}.json` with their sha256 and the chosen
   values as a ruling in this file **before** any test-cut request; `perstep_mar_sc` reuses Mar's values. Also recorded:
   accepted count per step and steps per canvas for the chosen values against stock knobs.
4. *Negative:* the driver refuses `--cut test`; no test-cut request is sent; no threshold or calibration code in
   `local_astra/eval/cd/**` changes (read-only; a defect there gets its own task).

    (e.g. log the decision on `vllm.astra_vllm_plugin.cd.kernels`), which is outside this task's owned files and a plugin
    rebuild; re-scope needed.
