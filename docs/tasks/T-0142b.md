## Goal

**Evidence (planner, read-only, re-derived by the test-author's eval row).** Answer commits come from the session logs of `logs/t0132-crop-budget-ab-2ccff41/`, `logs/t0134-feedback-ab-e59aa69/` and `logs/t0135-thought-call-ab-e1ae76e/`. They are accumulated per `attempt_id` and judged with T-0142's detector at `T-0142-impl` 712fea3, using T-0142's tokens (`re.findall(r"\w+|[^\w\s]+", text.casefold())`).
- **1,666 requests carried answer commits** (t0132: 713, t0134: 584, t0135: 369). **Exactly 1 collapsed:**
  - Which: T-0135 arm B S2#5, session `20261023-135637-1135093.jsonl`, attempt `5008519a4296-t1-gen-s2-4`. It had 3 answer commits.
  - Answer commit 0 (canvas 1) is `"Wait, let me check the cart. the. the. the. the. the. the."`, with 6 back-to-back repeats of `. the`. Commits 1–2 add 640 and 405 characters of `" the."`, 215 repeats in all.
  - At BASE every commit was submitted. The speech gate split it into about 217 `tts.utterance` records, which played until the 60 s turn timeout. `llm.done` had arrived at 6.9 s.
  - The cart was already right. The trial wrote no turn line.
- **Clean answers (1,665):** the longest back-to-back repeat of any unit of 1–3 tokens is **1**, and the longest single-character run is **2**. The median answer is 11 tokens and the longest is 58.
  - So any threshold `K` from 3 to 8 gives 0 false positives on these logs. The logs do not choose `K`.
  - What chooses it is the voiced cost. At `K = 8`, the thought threshold, the guard trips at answer commit 1: commit 0 ("Wait, let me check the cart." plus 6 × "the.") is already voiced. At `K ≤ 6` it trips at commit 0, and none of the collapse is voiced.
  - This task proposes `MIN_REPEATS_ANSWER = 6`, the largest value that stops the only observed collapse before any of it is spoken (H-T142b-2).
- **Thought, for completeness (not in T-0142's evidence):** the t0135 directory holds 6 more thought collapses in 562 requests with thought commits. They are arm A S2#1 and S1#11, and arm B S5#19, S2#17, S2#12 and S2#16. All 6 trip T-0142's guard as accepted. S2#5's thought is clean.
- **Gap:** all three directories are computer-use answers. No conversational-mode (`--tools off`) answer corpus was in the planner's read scope. False positives on chat prose are covered by a hand table only (H-T142b-3).

**What changes:** with `degeneracy_guard` on (T-0142 turns it on in every cli mode), the session also judges each request's committed **answer** text, accumulated per attempt. When the text trips, the session does the following:
- it judges each answer commit **before** submitting it to the machine, so the tripping commit never reaches the speech gate;
- it aborts the engine request;
- it drops everything that attempt commits afterwards;
- it logs a `note`;
- it ends the turn through T-0142's `LlmError` path, with its own message, `DEGENERATE_ANSWER_MESSAGE`. That message becomes the turn's `hud.error`, so the HUD says what happened.

Nothing new is spoken. Audio queued from earlier commits stops through the turn machine's existing error path. History keeps only what was played.

**A3. Session wiring.** With `degeneracy_guard=True`, every answer commit that `_stream_commits` would submit is judged; that covers the generate and every tool-loop step, in every mode, tools off included. The judgment is:
- on the attempt's whole committed answer text so far, the raw `Commit.text` concatenated across canvases with no separator;
- with `min_repeats=MIN_REPEATS_ANSWER`;
- after the commit's `llm.commit` record is logged, and **before** anything is submitted to the machine.

Thought and answer are accumulated separately, and never concatenated with each other. On a trip, in this order:
1. One `note`: `{"what": "degenerate answer: request aborted", "request_id", "attempt_id", "canvas_idx", "unit", "repeats", "kind"}`. These are T-0142's fields with a different `what`.
2. The engine request is aborted through the existing `llm.abort` path. The abort record precedes the error.
3. The tripping commit is not submitted. Every later commit and `llm.done` of that attempt is dropped, exactly as after a T-0142 thought trip.
4. When a loop is on, `turn.tool_loop_end = "degenerate"` (T-0142's value, reused). Then `E.LlmError(request_id=machine_id, message=DEGENERATE_ANSWER_MESSAGE)` is submitted. `DEGENERATE_ANSWER_MESSAGE = "degenerate answer: request aborted"` is a module constant.

These are **out of scope** because they are not voiced, and nothing changes for them:
- ReGround pass 2's answer text;
- `tool_repair` requests;
- prefill;
- the captioner's answer.

## Implementation notes

- **Where.** T-0142 already judges thought commits inside `_stream_commits`, after the `llm.commit` log and before submission, and returns `True` so the caller runs `_end_degenerate`. The answer check belongs at the same place, on the answer branch, before the commit is cleaned and submitted.
  - Reuse `_degenerate_trip` and `_end_degenerate`, parameterised by segment and message. Do not duplicate them.
- **Raw text.** Judge the raw `Commit.text`. The cleaners (the T-0124 literal cleaner, `_AnswerCleaner`) shape what is voiced and must not change what is judged; the evidence was measured on raw logged text.
- **Per attempt.** A T-0135 recovery, a repair or the next loop step is a different request with fresh accumulators.
- **No retry and no text edit** (H-T142-1 carries over). The guard only stops.
- **The turn machine's `LlmError` path is the stop.** `_fail_turn` emits `HudError`, aborts the live output and commits what was played. If a test shows queued audio is *not* cut there, stop and report: that is a `turn_machine.py` change and a different task.
- The implementer never edits `tests/`. No heredocs. Never export `GIT_DIR`/`GIT_WORK_TREE`.

## Open questions

- **H-T142b-1 (human):** should a trip say anything aloud? CLAUDE.md forbids voicing text the LLM has not committed. So this task shows only `DEGENERATE_ANSWER_MESSAGE` on the HUD.
