## Goal
Add `call_format="native"` to `compile_toolcall`, producing per-step CD automata for the model's own call syntax:
- the language is exactly the pinned template's renderings of schema-valid v1 calls, with the structural markers as single ids;
- every JSON-format payload stays byte-identical.

This builds docs/07 §5.1's planned `gemma4_tool_call(tools)`.

## Acceptance criteria
1. **API.**
   - The signature is `compile_toolcall(tools, *, scope, thought, whitespace="json", call_format="json")`.
   - `call_format` must be `"json"` or `"native"`; anything else raises `ValueError`.
   - The cache key includes `call_format`.
   - `report_sizes()` prints and returns rows for both formats, with `call_format` in each row.
2. **CALL_native(tool)** = `call:` NAME `{` ARGS `}` · 49.
   - ARGS lists every declared property in the template's key order (jinja `dictsort`, case-insensitive; asserted for v1), as `key:VALUE`
     joined by `,`, with no whitespace.
   - VALUE depends on the schema:
     - integer with bounds [0, 10^k − 1] → `0|[1-9][0-9]{0,k-1}`;
     - integer without bounds → `-?(0|[1-9][0-9]*)`;
     - boolean → `true|false`;
     - string enum → 52 · literal · 52;
     - string → 52 · BODY · 52, where BODY is any UTF-8 text with no `<|` and no `|>` substring, and is non-empty when `minLength ≥ 1`.
   - A tool with an optional property, or with a number, array, object or null property, raises `ValueError` under native. v1 has none.
3. **Single ids.** `<|tool_call>` is admitted only as id 48, `<tool_call|>` only as id 49, `<|"|>` only as id 52. Their multi-token spellings
   are rejected. Plain text is admitted in every tokenisation the lift allows.
4. **Variants.**
   - T4 = CALL_native; the pass-2 prompt ends with 48.
   - T2 = the empty-thought header · 48 · CALL_native.
   - T1 = `prepend_thought_header` · 48 · CALL_native, with the free region = the JSON T1 free set minus {48, 49} (QN5).
   - Nothing (no whitespace, no text) is admitted between 101 and 48.
   - `scope="name"` = [header] [48, except for T4] `call:` (one v1 name) `{` + STOP. It is a literal, token-for-token prefix of every per-tool
     native language.
   - `union` stays eval-only.
5. **Sizes.** Every live native automaton (5 tools × T1/T2/T4, plus `name`) is at most `LIVE_MAX_STATES` (128) states and `is_dfa`, asserted
   by a test.
   - The union is reported.
   - The measured table is recorded in this file.
   - Planner scratch table (CPU): max live 100 (press_key T1/T2), click_at T4 31, union 213–227.
6. **The language equals the template renderings (oracle).** Every schema-valid v1 call (Hypothesis, edges included) is rendered by the
   pinned template's `tool_calls` path and encoded with `vocab.encode`. Then:
   - T4 accepts the call text after 48, plus the stop 50;
   - T2 accepts the empty header + 48 + the call + 50;
   - T1 accepts the template's full `<|channel>thought\n…\n<channel|><|tool_call>…<tool_call|>` + 50, with a real multi-line thought.
7. **Rejected** (per thought, where applicable):
   - whitespace inside the call; keys out of order; a missing or extra key;
   - `x:1000`, `x:-1`, `x:007`, a quoted integer, `True`, an out-of-list enum value, an empty string where `minLength` is 1;
   - a body containing `<|` or `|>`; a stop id inside a body;
   - a missing 49; text between 49 and the stop;
   - the delimiter spelled as byte tokens; a spelled-out `<|tool_call>`;
   - variant-specific: a leading 48 in T4; thought text in T2; a 48 inside the thought in T1; spoken text or whitespace before 48 in T1/T2.
8. *Negative.*
   - For every (scope, thought) with `call_format="json"`, the sha256 of `artifact.encode_automaton(...)` equals the value pinned from `main`
     before this task.
   - `vocab.build_vocabulary()` with default arguments is unchanged.
   - The `compile_bfcl`/`compile_sudoku` parity rows stay green unedited.
   - Unchanged: `local_astra/toolcall/**`, `eval/**`, `plugin/**`, `conductor/**`, `contracts/**`.

## Implementation notes
- The vendored lift is byte-level over `build_vocabulary()`, where 48, 49 and 52 appear as their literal bytes. Lifting `<\|"\|>` as text
  would also admit the multi-token spellings. Choose one of these and record which:
  - a native-only vocabulary mapping 48/49/52 to private-use placeholder bytes (the planner's measurement used this);
  - DFA surgery.
  
  Never change `build_vocabulary()`'s default.
- BODY "no `<|`, no `|>`" is a 3-state byte DFA. Property-test it against `"<|" not in s and "|>" not in s` on random strings.
- T1's free set is a native-only argument to `prepend_thought_header`. Its signature and the JSON T1 payload do not change.
- Live-path automata stay at most 128 states. Stop ids are out of band (`FA·STOP·Σ*`); never put 1, 106 or 50 inside the grammar.

## Implementation log (implementer, 2026-10-09, branch `T-0084a-impl` from db18874)
- **Route: DFA surgery (segment concatenation), not placeholders.** The native call is a list of text segments and marker ids
  (`native_call_parts`), e.g. `type_at` = `call:type_at{press_enter:(true|false),text:` · 52 · BODY⁺ · 52 · `,x:INT,y:INT}` · 49. Each text
  segment is lifted on its own over the unchanged `build_vocabulary()` with `drop_labels = RESERVED_TOKENS ∪ {48, 49, 52}`, and the segments
  are chained by single-id edges `final --m--> next start` (`_chain`), then minimized. A token never spans a marker (each marker is its own
  id), so the chain's token language is exactly the segments' token languages joined by the single ids, every tokenisation of the plain
  text included; the marker ids are disjoint from every segment's labels, so the chain is a DFA. No placeholder bytes exist, so the
  byte-fallback leak in the warning above cannot occur. `build_vocabulary()` is not touched.
- **BODY** = `(?:[^<|]|\|*<+[^<|]|\|+[^<|>])*\|*<*` (`BODY_REGEX`); the non-empty form `BODY_NONEMPTY_REGEX` is what is lifted. Checked
  against `"<|" not in s and "|>" not in s` with Python `re` on every string over `<|>a\n` up to length 7 (0 mismatches), besides the rows.
- **Empty segments.** outlines-core 0.2.14 refuses to index any regex that matches the empty string under the `\z` anchor ("anchored
  universal start state doesn't exist"), so a string without `minLength` (and an enum with an `""` member) is a `MaybeEmpty` part: the
  non-empty regex is lifted and ε is added on the automaton (`_or_empty`: a fresh accepting start with copies of the start's edges).
  v1 has no such property; the `probe_strings` rows exercise it.
- **Variants.** T4 = the call; T2 = `prepend_channel_header` (unchanged arguments) of `48 · call`; T1 = `prepend_thought_header` of
  `48 · call` with `reserved` = the JSON T1 reserved set ∪ {48, 49} (QN5; the function's signature is unchanged, and this also keeps 48/49
  out of the header's name alphabet). `name` = the lifted `call:(names)\{` (checked to be a literal prefix of every tool's first native
  segment), with the same headers. `union` (eval-only) = the subset construction over the five per-tool call DFAs, minimized.
- **API/cache.** `compile_toolcall(..., call_format="json")`; anything but `"json"`/`"native"` (including non-strings) raises `ValueError`.
  The cache key is `(tools.version, scope, thought, whitespace, call_format)`. The JSON path is the old code path with the same `source`,
  options and automaton name, so its `schema_hash` and payload are unchanged; the native `schema_hash` covers
  `{"kind", "call_format": "native", "tools_version", "scope", "parts"}` plus the thought, the header bound and the BODY rule, and the native
  automaton is named `toolcall:native:<scope>:<thought>`. `whitespace` is validated but does not apply to native. `report_sizes()` iterates
  both formats and puts `call_format` in every row and line.
- **Unsupported shapes (criterion 2).** Optional properties, any type but integer/boolean/string, integer bounds other than [0, 10^k − 1],
  `minLength` > 1, non-string enum members and any other keyword except `description` raise `ValueError` under native only.
