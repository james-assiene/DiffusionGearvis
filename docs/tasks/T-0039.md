# T-0039 — Text mode: type a question in the HUD, read the answer, keep the speakers silent

**Status:** done 2026-09-14 (groups A, B, C merged; reviews APPROVE) · three groups, ordered · blast radius **medium** (one reviewer; see §7 for the escalation trigger)

## 1. Goal

Today the only way into a turn is a microphone (or a synthetic rung script), and on this box `astra session` cannot even start: `build_session` opens the PortAudio device before the endpoint binds, and `libportaudio2` is not installed (P1). The user's stated need on 2026-09-14 was "a text interface so I can communicate and see the answer via text — useful if I don't want to disturb my neighbours." This task gives the HUD page a text box that submits a typed question over the existing loopback WebSocket as a new client→server wire type `astra.text`; the session turns it into an ordinary user turn — the same machine rows the `[ui]` click path uses, the same history, the same transcript/spoken panes, one `turns.jsonl` line whose regime says the input was typed — and adds a per-session `--silent` flag that installs a null playback device, so TTS still runs, the spoken pane still fills, nothing is audible, no microphone is opened and **no audio device is required at all**. After this task the human can run `uv run astra session --silent --serve-hud`, open the page, type, and read the answer, before PortAudio is installed and before a real sink exists.

Non-goals: the turn machine is not changed; barge-in, the endpointer and the capture pump are not changed; there is no keyboard path to the microphone, no per-turn mute, no A2UI change, no audio over the WebSocket.

## 2. Acceptance criteria

**Group A — wire and session**

1. `contracts/protocol.py` gains `AstraText` (`type: "astra.text"`, `text: str`), it is in `AstraMessage`, in `ASTRA_MESSAGE_TYPES` and in `CLIENT_TO_SERVER` only. The parametrised round-trip in `tests/contract/test_protocol_codec.py` and the direction/partition assertions (`CLIENT_TO_SERVER | SERVER_TO_CLIENT` covers every model, the two sets are disjoint) pass unchanged in shape. Satisfies docs/03 "Protocol codecs"; supersedes docs/02 §5's T-0028 delta (c).
2. `text` is validated on the model, not in the transport: stripped of surrounding whitespace, non-empty after stripping, at most **2000 code points**. A violation is therefore a `codec.decode` → `Malformed` and the page is answered `astra.error(code="malformed")` on the existing path — never a truncation, never a silent drop, never a new error code. (docs/02 §5; T-0027 owns the byte limit and is untouched.)
3. `HudServer.route` accepts `astra.text` only after the hello fence and only from the client direction (an `astra.text` arriving in the server→client set is impossible by construction; an `astra.text` before `astra.hello` yields `astra.error(code="no_hello")` and `counts["no_hello"] += 1`, exactly like every other client message). A routed `astra.text` increments `counts["routed"]` and submits one `events.UserText` on the session's pump — the transport makes no turn decision of its own (T-0028 design: "it validates nothing of its own").
4. `contracts/events.py` gains `UserText(type="user.text", t_ms, text)` in `Event`/`EVENT_TYPES`. `turn_machine.step` is **not** modified: `user.text` falls through the existing no-row branch to `(state, [])`, proven by a test that steps every state with a `UserText` and asserts the state is identical and no command is emitted.
5. A typed question submitted while the machine is `IDLE` opens exactly one turn and drives it to `THINKING` through the ordinary rows: one `user.speech_onset` stamped at the message's own time, then the turn's word buffer seeded with the typed text and the state set to `ENDPOINTING` with `t_eot_ms`/`flush_t_ms`, so the existing `ENDPOINTING → THINKING` tick row runs untouched (the mechanism `Session._on_ui_action`/`_open_ui_transcript` already uses; the implementer factors it, does not copy it). The turn's transcript is the typed text **verbatim**, with no `[ui]` prefix and no synthesised `stt.*` event.
6. ## 5. Implementation notes

- **Contracts to respect.** `docs/02-architecture.md` §4 invariants (nothing is voiced that the LLM has not committed; history never contains unplayed assistant text; abort/cancel/flush idempotent) and the §4 spec deltas from T-0006 (drain), T-0028 (a)(b), T-0030 and T-0037 (`replay`). The T-0028 delta (c) — "v1 has no wire type for typed text input from the page" — is the sentence this task retires: add a **new** spec delta paragraph to §5 naming `astra.text`, its validation, its refusal codes and the `TurnRecord.input` field, and say explicitly that it supersedes T-0028 (c). Do not rewrite the historical delta.
- **The wire and its fake move together** (CLAUDE.md): `tests/fakes/hud_server.py` decodes with the production codec, so it needs no change — confirm that in the report rather than assuming it.
- **Reuse, do not copy, the `[ui]` turn-opening mechanism.** `Session._on_ui_action` / `_resolve_pending_ui` / `_open_ui_transcript` already encode the hard part (ruling A14's identity-not-shape onset match and the `turn_seq` advance check). A copy will drift and the copy is where criterion 6 will break. Factor the shared part; `_PendingUi` becomes a pending *turn* carrying its transcript and its origin (`"ui"` or `"text"`), and the origin is what criterion 9's `input` field reads.
- **Never synthesise `stt.*` events for typed text.** The endpointing rows belong to a microphone; the session hands the machine the end-of-turn state directly, as `_open_ui_transcript` already does. T-0032's endpointer must not observe a flush that no STT produced.
- **The transport stays dumb.** `hud_server.route` builds one `events.UserText` and hands it to `session.submit`; it does not strip, cap, refuse-as-busy or inspect state. Every refusal is the session's, because the session is the only thing that knows what state it is in.
- **`--silent` is a device swap, not a policy branch.** TTS still runs and `astra.spoken` is still published, because that is what keeps the turn machine byte-identical and the spoken pane honest; the CPU cost of Pocket TTS in silent mode is accepted and named in the startup line. Do not add a "skip TTS" path: without playback the `SPEAKING → IDLE` row never fires and the machine would need a change.
- **The null device models time; it does not abolish it.** Real-time pacing is the decision: a silent turn takes as long as the speech would have, so `played_ms`, `played_text`, the unplayed strike and the drain rule all keep their meaning and a barge-in (when T-0034 lands) still means what it means. The clock is injected so unit tests run on a fake one and the fast suite is not paced by wall time.
- **Known landmines** (`.claude/rules/conductor.md`, `.claude/rules/tests.md`, `.claude/rules/perception.md`): nothing may block the pump for more than ~20 ms; outboxes stay bounded and only `astra.turn.state` is droppable; no clock, logger or uuid enters `turn_machine.py`; a test that asserts a tautology (e.g. "the message we constructed has the text we put in it") is a mutation-test target for the reviewer — assert about what the *session* did, not about the model.
- **Adding to `EVENT_TYPES` breaks a pinned list on purpose.** `tests/unit/test_turn_invariants.py` pins the sorted event tags; the test-author adds `"user.text"` there. If an implementer is tempted to avoid the event by calling a session method directly from the transport: don't — ordering with frames, ticks and onsets on the one pump is the reason `ui.action` is an event, and losing it is exactly how criterion 6 fails.
- **Toggling thinking is not part of this.** Text mode does not change the thinking setting (CLAUDE.md: the whole prefix cache misses).
- **Open ambiguities, listed so the implementer does not silently resolve one.**
  1. **2000 code points** is a chosen bound, not a measured one. If a real question is refused, that is a spec change here, not a test edit.
  2. **`input` on `TurnRecord` vs `Regime`.** Placed on the record because a session mixes voice, text and click turns; if the bench reader would rather filter on the regime, that is a follow-up task, not a quiet second copy of the field.
  3. **Real-time pacing vs instant rendering** in the null device: decided real-time (above). An instant-render mode would make text mode snappier and every playback number meaningless; if the human wants it, it is a separate flag with its own regime word, not a change to `silent`.
  4. **Does `--silent` imply the mic is off?** Decided yes (criterion 19), because the device is the same object. A user who wants "speak to it, read the answer" needs a separate half-duplex flag; that is not this task, and the task must not pretend to offer it.
  5. **Where the box lives on the page** (above the transcript vs beside the spoken pane) is the implementer's, constrained only by criteria 10–14.
  6. The stale `ui.action` comment in `turn_machine.py` (see §3) is owed to a later mechanical commit.
