## Goal

The session runs the loop that the T-0112 machine already describes.
- **Execute in a task.** On `tool.execute` with the loop on, the session runs the call in a task, behind a session-clock timeout. It builds the result payload with `toolcall/loop.py`, logs it, and always submits a text-free `ToolResult(call_id, status)`.
- **Continue.** On `llm.continue`, the session builds the next request with `loop.step_prompt` (form G). The base is the step-1 prompt as sent. The steps are each step's thought-stripped, special-literal-free answer text, its validated call and its rendered response. The request is sent with `continue_final_message`.
- **Judge each step.** The session reads the step's stream through the same commit path as step 1, judges it under `{turn}-call-s{k}`, and refuses a repairable draft at step ≥ 2 with `"repair: step 1 only"`.
- **Speech and drain.** The speech gate and the drain mark become per (turn, step). A playback terminal that belongs to no run of the current step never reaches the machine while the machine is awaiting a result or generating a step.
- **Configuration.** The profile gains `tool_loop` (default `false`) and `max_tool_steps` (default 8, validated `>= 1`). The CLI gains `--tool-loop` and `--max-tool-steps`.
- **Telemetry.** The turn line gains `tool_steps`, `tool_steps_executed` and `tool_loop_end`, on loop-on sessions only.
- **Docs.** docs/02 §4/§5, docs/01 §3/D16 and T-0080d record the change.

With `tool_loop` off, every request body, prompt, session-log record, HUD message and turn line is byte-identical to `main`.

## Implementation notes

- **Step-1 prompt.** Take it from the step-1 `_ToolCall.pass1_prompt`, which is the prompt as sent, after any over-long retry. Never rebuild it, and never change `tools`, `thinking` or assists per step (CLAUDE.md, prefix cache).
- **Step text.** It is the step's `_AnswerCleaner.spoken_prefix`, with closed and unclosed thought blocks removed before embedding (`router` already has the stripping; reuse it, do not edit `router.py`). Step 1's text is the spoken prefix.
- **Execute task.** With the loop on, `execute_tool` must not block the pump. Run it in a task registered so that turn close and `tool.cancel` cancel it. Use a deadline set with `clock.call_at`, and keep durations on the session clock only (`.claude/rules/conductor.md`). With the loop off, keep today's inline await, byte for byte.
- **Card status with a backend.** It stays the executor's `dry_run` card in this task. T-0111b must change the card wording before any real backend is wired (H-T114-3).
- **The terminal guard (criterion 7)** is session bookkeeping on the run ids of T-0092a, like its G-rulings. Scope it to "the machine is awaiting a result or generating step ≥ 2, and the terminal is attributed to no run started in this step". Do not drop terminals in any other state.
- **Interim filler.** It is unchanged. Note that a filler clip opens a run in THINKING; the guard must not drop the step-k run that clip joins (unverified whether any rig produces this; test-author to check).
- **Memory and history** are written only by the machine's `commit_history`; nothing new is ingested.
- **Constants.** `TOOL_EXEC_TIMEOUT_MS`, `MAX_STEP_TEXT`, `MAX_ARG_TEXT` and `MAX_CONTINUATION` are module constants in `session.py`, with the H-T114-4 defaults.
