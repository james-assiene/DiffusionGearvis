## Goal

docs/14 lists two problems with the live loop:
- **The model repeats clicks.** cua measured 32.6 % of actions as repeats. Here, the T-0151 logs hold 6 repeated clicks in arm B, and over-clicks went 1 → 4/60.
- **Self-reports are uninformative.** The model's own "it seems the cart didn't update" preceded an over-click. The cart had updated.

The harness can state two facts the model lacks:
- **The repeat fact:** this call repeats step *j*, and here is what step *j* did.
- **The no-progress stop:** the same action has already done nothing twice, or the agent has come back to the same screen a third time. Doing it again is refused.

This task adds `Session(repeat_guard=True)`, opted into with `astra session --repeat-guard` or the profile key `repeat_guard`. It is live only and off by default. When on:
- **A repeat that executes:** its result gains `repeat_of_step: {step, action, <step j's outcome keys>}`.
- **The stop:** after 2 no-change repeats of the same action on the same screen, or when a browser action is read off a screen on its third separate visit in the turn, the call is refused before `execute` with a fixed reason, as a tool result.
- **Speech:** nothing new. The loop continues as it does after any refusal (R12). If the model's next step answers instead of calling, that committed answer is voiced through the existing path (R15/H-T111a-3). That is D16 moment 3 ("stuck") becoming possible. It is never synthesised.
- **No other model-facing change:** no new instruction sentence, no tool change, no `LIVE_TOOL_GUIDANCE` change and no turn-machine change.

A locked A/B (arm A HEAD's live default, arm B plus `--repeat-guard`) then decides adoption.

## Acceptance criteria

### Group A — the rule, `local_astra/conductor/progress.py` (pure, CPU)

**A-1. Module and imports.** The module imports the stdlib only. It does no I/O, reads no clock and keeps no global mutable state, so it is deterministic: the same input always gives the same output (the T-0142 `degeneracy.py` pattern). Its constants:
- `REPEAT_TOLERANCE = 10`: model units (0–999), per axis (Chebyshev).
- `MAX_NO_CHANGE_REPEATS = 2`.
- `MAX_SCREEN_VISITS = 3`.
- `ACTIONS = frozenset({"click_at", "type_at", "scroll", "press_key"})`.
- `NO_PROGRESS_REPEAT_REASON = "the same action did not change this screen the last two times; it was not done again"`.
- `NO_PROGRESS_RECURRING_REASON = "this screen has come back for the third time in this request; the action was not done"`.

**A-2. Types.** Frozen dataclasses. The implementer may add fields but not rename these.
- `Step`, one per settled step of the turn:
  - `step: int`: the 1-based loop step;
  - `name: str`;
  - `arguments: Mapping[str, Any]`: as the model wrote them;
  - `screen: str | None`: an opaque screen key; `None` means unknown or blind;
  - `status: str`: `executed`/`refused`/`failed`/`timeout`/`dry_run`;
  - `overview: bool`: the call was read off a T-0151 overview frame;
  - `no_change: bool | None`: `True` no visible change, `False` changed, `None` unknown;
  - `outcome: Mapping[str, str]`: the step's outcome keys, copied verbatim;
  - `action: str | None`: the executor's action string.
- `Verdict`:
  - `repeat_of: int | None`;
  - `stop: Literal["repeat", "recurring"] | None`;
  - `no_change_repeats: int`;
  - `screen_visits: int`.

`judge(history: Sequence[Step], name: str, arguments: Mapping[str, Any], screen: str | None, *, overview: bool) -> Verdict`.

**A-3. Same action (`same_action`).** Two calls are the same action only if all of these hold:
- the names are equal and in `ACTIONS`;
- both screens are non-`None` and equal;
- neither call is `overview`;
- `click_at`: `|Δx| ≤ 10` and `|Δy| ≤ 10`;
- `type_at`: the same, plus exactly equal `text` and equal `press_enter`, where a missing value equals `False`;
- `scroll`: equal `direction`;
- `press_key`: exactly equal `combo`;
- `google_search` and `page_overview` are never the same action.

**A-4. Repeat.** The *instances* are the history steps with `status == "executed"` that are the same action as the proposed call. Refused, failed, timed-out and dry-run steps are never instances.
- `repeat_of` is the step number of the latest instance, else `None`.
- `no_change_repeats` counts the instances after the earliest one (the original is not a repeat) whose `no_change is True`.

**A-5. Recurrence.** Take the sequence of `screen` values of every history step in order, then the proposed call's, and drop the `None`s. Collapse consecutive equal values into runs. `screen_visits` is the number of runs of the proposed screen, the current run included. Three consecutive steps on one screen are one visit, so filling a form on one screen never recurs.

**A-6. Stop.** For a proposed call whose name is in `ACTIONS`:
- `stop = "repeat"` when `repeat_of is not None` and `no_change_repeats ≥ MAX_NO_CHANGE_REPEATS`. Example: an action done on an unchanged screen with no effect three times; the fourth is refused.
- Else `stop = "recurring"` when `screen is not None` and `screen_visits ≥ MAX_SCREEN_VISITS`.
- `repeat` takes precedence.
- A proposed `google_search`/`page_overview`, or any call with `screen is None`, always gives `stop None`.

**A-7. Negative.**
- `judge` never mutates `history`.
- No file other than `progress.py` changes in group A.
- Byte-identical over BASE_A..TIP_A: `local_astra/**` except the new file, and `tests/fakes/**`.

### Group B — session, cli, config, docs (CPU)

**B-1. `Session(repeat_guard: bool = False)`.** It raises `ValueError` unless the kit's mode is `live`. It may be combined with ReGround, the auto overview, the page overview and the overview frame: none is refused.

**B-2. Screen key.** The `Step.screen` of a step, and the `screen` of a proposed call, is the **executor phash** of the browser's live frame that the step's request showed: the `FrameGeometry.phash` registered for that frame's capture identity, salted per browser generation.
- For a T-0151 overview step 1, it is the live frame the overview replaced (`loop_base`'s), and `overview` is `True` for that call.
- On a blind turn it is `None`.
- It is never the capture identity (sha256 of the bytes): the caret, hover and JPEG noise change the bytes of a screen that has not changed (H-T137-2).

**B-3. Outcome (`no_change`, `outcome`).** These are recorded when B8 settles the step, in `_live_step_screen`, onto the session's own per-turn record. They are never read back later from `turn.loop_steps` responses, because compaction (`loop.compact`) elides them.
- **S-OUT-1:** when T-0136's outcome label is on and was computed for the step:
  - `no_change` is `True` exactly for T-0136's no-change literal (`no visible change`, as merged), and `False` for its other labels;

- **S-OUT-2, otherwise:**
  - `no_change` is `screenshot == "unchanged"`, B8's value, which is what the T-0134c label told the model;
  - `outcome` is `{"screenshot": <value>}`.
- A blind step's outcome is unknown (`None`).
- **Consistency rule:** the guard never counts a step as no-change when the model was told the screen changed.

**B-4. Where the guard runs.** In `_run_execute`, after the B9 check, and before the page-overview refusal, ReGround and `execute`. It runs for loop steps ≥ 2 whose name is in `ACTIONS`, through `progress.judge` over the turn's settled steps.
- **B9 first:** a stale-frame call is refused with `FRESHNESS_REASON` and never reaches the guard.
- **ReGround:** matching uses `call.arguments`, the model's own arguments as the continuation shows them, not pass 2's.

**B-5. Refusal.** On `stop`:
- The call is refused before `execute`, so nothing is dispatched or captured.
- **Card:** `refused` with the reason.
- **Loop result:** `{**loop.status_payload("refused", REASON), "repeat_of_step": {...}}`. The `repeat_of_step` key is there only for `stop == "repeat"`. B8 then adds `screenshot: "unchanged"`, as for any refusal.
- **Budget:** the refused step counts against `max_tool_steps`, as a B9 refusal does (`tool_steps_executed` increments at execute; no turn-machine change).
- **`tool.call` record:** gains `no_progress: "repeat" | "recurring"` on that call's records only.

**B-6. The repeat fact.** An *executed* call with `repeat_of = j` (it was not stopped) settles with BASE's payload plus `repeat_of_step: {"step": j, "action": <step j's action string>, **<step j's outcome>}`. Rendered example, fallback, echo `model`:

`repeat_of_step:{action:<|"|>clicked at (423, 631)<|"|>,screenshot:<|"|>updated<|"|>,step:1}`

- A failed, timed-out or refused (non-guard) repeat gets no fact.
- The call's `tool.call` records gain `repeat_of_step: j`.

**B-7. Speech: committed text only.**
- No `TtsSpeak` is created, and no text is added, by the guard. The reasons, the `repeat_of_step` mapping and the action strings reach no `TtsSpeak.source`, history, `Episode` or `machine.events()` text.
- After a stop, a step with no call has its committed answer voiced through R15 exactly as at BASE. A step that calls again is judged again. A step that ends without answer text voices nothing.

**B-8. Logging.**

## Implementation notes

- **Facts, not instructions** (docs/14 rule). The only new model-facing text is the two reason constants and the `repeat_of_step` mapping. Each states what happened or what the harness did. `LIVE_TOOL_GUIDANCE`, the tools and every label are frozen. If the A/B says `no change`, that is the finding.
- **The rule is pure; the session only feeds it.** Keep a per-turn list of `progress.Step` on `_TurnLog`.
  - Append at `_settle_result`, from the call, its status and its screen key.
  - Fill `no_change`/`outcome` in `_live_step_screen`, where B8 decides `updated` and where T-0136's label is computed.
  - Never derive these from `turn.loop_steps`: compaction rewrites old responses.
- **Screen key.** It is `self._frame_geometry[identity].phash` of the live frame the request showed. That is the executor's salted perceptual hash, not the sha256 capture identity the prompt and B9 use. B9 already guarantees a coordinate call's frame is the newest own frame, so the call's frame and the shown frame agree for `click_at`/`type_at`. `scroll`/`press_key` have no coordinates; use the shown frame for them as well.
- **The T-0136 dependency.** Read T-0136's outcome through whatever it merges (its key on the settled payload, or its `_TurnLog` field). Do not re-compute a pixel diff. If T-0136 merges without a per-step machine-readable outcome, stop and report.
- **No speech path.** Do not touch the speech gate, `_TOOL_REFUSALS` or the machine. A refused tool result already continues the loop (R12). An answer-only step already voices its committed text (R15). That is all "stuck speech becomes eligible" means here.
- **No latch** (H-T137-5). Each proposed call is judged afresh. The conditions stay true, so the same repeat, or any action on a screen on its third visit, is refused again. A different action on a new screen is allowed: VLAA's "recover".
- **The overview frame is on by default after T-0152.** Its step-1 coordinates are in overview units, so a numerically equal step-2 call is a different action (A-3 `overview`).
