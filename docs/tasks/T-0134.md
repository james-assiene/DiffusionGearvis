## Goal

Live computer use now fails mainly on two things that are not grounding. T-0132 at 2ccff41 measured, per arm (n = 100, 1120 visual tokens; regime below):
- **S4 ("find the cheapest item") is 0/20 in every arm, with 0 scrolls.**
- **False claims run at 23–25 per 100 turns.**

### Diagnosis (from `logs/t0132-crop-budget-ab-2ccff41/`, read-only, re-derived by the planner)

**D-1. S4 answers from the first screen.**
- All 60 S4 trials end after one step, `tool_loop_end = final`, with no tool call.
- Every thought lists exactly the six deals visible at 1280×800 (Ceramic teapot $32.00 … Enamel mug $11.50) and concludes "The cheapest item is the Enamel mug at $11.50" (e.g. `sessions/20261022-203129-1975518.jsonl`, `…-203216-…`, `…-203403-…`).
- The answers: "The cheapest item is the enamel mug at eleven dollars and fifty cents."
- The cheapest deal is the Cotton tea towel at $4.75. It sits in the fourth row of `deals.html`'s 2-column grid of 230 px rows, below the fold: its button box is at y ≈ 1117 px in an 800 px viewport (`steps.jsonl`, S5 repeat 19, off arm).
- The visible lede "Eight offers, while stocks last" is ignored. A visible cue is not enough.
- **Why S5 scrolls and S4 does not.** S5 scrolls only to reach the Enamel mug's button, which sits at the fold ("I will scroll down to find the add to cart button for the enamel mug", e.g. S5 repeat 19). After the scroll it sees the tea towel and switches. Scrolling in S5 is incidental to a click, not a search of the page.
- **D-1b. The S4 scorer cannot register a correct spoken answer.** T-0111g's `score("S4", …)` requires the price as the digits `4.75`. The speaking prompt makes the model spell prices out: all 60 S4 answers do. A correct "four dollars and seventy-five cents" scores 0. This is the same artefact as T-0115a ("accepted-answer lists for a voice assistant must include spelled-out number forms").

**D-2. False claims are mostly S4, and the rest had a fresh screenshot.**
- By T-0131's `false_claim` proxy: off 25, on/1120 23, on/280 23. S4 is 20 of each (60 of 71).
- The other 11 are S1 (4), S2 (4), S3 (1) and S5 (2).
- In all 11, the last executed action's response says `screenshot: "updated"`. The step prompt carries exactly one image: the post-action screen, swapped in by B8 (checked per session log, e.g. `…-203657-…`, `…-205029-…`, `…-210437-…`).
- What the claims say: "I have added the blue mug to your cart." Eight of the 11 come from turns whose final cart holds the item more than once (S2 repeat 8, off arm: 7 blue mugs; S1 repeat 0, off: 4).

**D-3. The model does not believe the image is current.**
- In 136 of 300 turns (S2 52/60, S1 42/60, S5 34/60, S3 8/60), a thought matches "(don't|do not|cannot|can't) see the (updated|new) screenshot".
- Example: S2 repeat 7, on/1120, `…-203342-…`: "I don't see the new screenshot yet, but the tool says "status: executed" … Actually, I don't have the new screenshot yet."
- The image sits in the user message, before the continuation that holds the call. Nothing says it was replaced.

**D-4. The echo is in a different frame of reference from the call.**
- `click_at` takes 0–999 coordinates (`tools_v1.json`: "0 is the left/top edge, 999 the right/bottom edge"). The executor answers `clicked at (540, 505)`: pixels from `to_pixels`.
- 13 turns' thoughts read the mismatch as a miss (S2 9, S5 3, S1 1). Example, S2 repeat 8, `…-203657-…`: "The coordinates I sent were (422, 631) … (540, 505) is inside the blue mug image, not the button … I should try again." The cart ended with 7 items.
- Across the run, 9 turns ended with a duplicated cart (S2 5, S1 3, S5 1).

**D-5 (out of scope, a follow-up).** In 15 of 300 turns (S3 11, S1 4) the next tool call was written inside an unclosed thought (`llm.commit` segment `thought`, `thought_open: true`). The step ended with no call and no answer, and the turn went silent. That is 11 of S3's 20 failures. Proposed as T-0135. This task does not change it, and the A/B reports it.

### What this task does

- **(A) Three harness features, behind keywords that default to off:**
  - **(A-echo)** The executor reports `click_at`/`type_at` in the call's own 0–999 units.
  - **(A-label)** A fixed text label right after the current frame says it is the browser screen now, and whether the last action changed it.
  - **(A-extent)** The label adds how much page lies above and below the screen, in screens. The numbers are read from the browser's layout metrics, never from page text.
- **(B) A locked 3-arm GPU A/B**, n = 100 per arm:
  - **A:** the baseline, 1120 with ReGround off, no feature;
  - **B:** echo plus label;
  - **C:** echo, label and extent.

  It adds an S4 scorer that accepts spelled-out prices, plus S4, false-claim, over-click and mechanism metrics with intervals. The decision rule awaits H-T134-1.

**Considered and deferred** (planner; see Implementation notes):

- A `done`/`verify` tool.
- An automatic below-the-fold preview frame.
- Showing scrollbars.

## Acceptance criteria

### Group A — the features (CPU)

**A1. Keywords, off by default.**
- `Session(..., live_feedback: LiveFeedback | None = None)`.
  - `LiveFeedback` is a frozen dataclass defined in `session.py` (not in `contracts/`), with `screen_label: bool` and `page_extent: bool`.
  - `page_extent=True` with `screen_label=False` raises `ValueError`: the extent is a clause of the label.
  - Given with a tool kit whose mode is not `live`, it raises `ValueError`, naming `live`. A silent no-op is not allowed (`.claude/rules/conductor.md`).
- `BrowserToolExecutor(..., echo: Literal["pixels", "model"] = "pixels")`. Any other value raises `ValueError`.
- With the defaults, everything matches BASE (A8).

**A2. The echo (A-echo).**
- With `echo="model"`, an executed `click_at` action reads `clicked at (X, Y)`, and a `type_at` action reads `clicked at (X, Y) and typed N characters[ and pressed Enter]`.
- `X`, `Y` are the 0–999 values of the invocation the executor executed: the arguments it received, which are ReGround's when ReGround rewrote them.
- `resolved` keeps `x_px`/`y_px` unchanged, and the session log keeps pixels. No pixel number appears in the action string.
- Scroll and key actions are unchanged.

**A3. The label (A-label).** With `screen_label=True`, every live request whose final user message carries the current frame has one `TextPart` immediately after that frame's `ImagePart`. Its text is exactly one of:
- step 1: `[This screenshot is the browser screen now.{P}]`
- step k ≥ 2, after a step whose payload says `screenshot: "updated"`: `[This screenshot is the browser screen now, after your last action.{P}]`
- step k ≥ 2, after `"unchanged"`: `[This screenshot is the browser screen now; your last action did not change it.{P}]`

Placement rules:
- `{P}` is empty unless A4 applies.
- The label follows the frame wherever `show_current_image` places it: swapped in place, or placed first.
- There is exactly one label per request, never on a history image.
- A blind turn (no image) gets no label; its prompt already says so in words.
- Captioner, prefill and ReGround pass-2 bodies get no label.
- The step payload's `screenshot` key is unchanged (T-0111g B8).

**A4. The page extent (A-extent).** With `page_extent=True`, `{P}` is ` Page beyond this screen: {below} below, {above} above.`
- Each value is `nothing` when it is under 0.05 screens. Otherwise it is `about {v:.1f} screens`, with `v = px / viewport_height`.
- Viewport height and scroll offsets are measured in CSS px.
- The values describe the frame shown in that request, keyed by its capture identity. They are read at capture time from the browser's own layout metrics; Chromium's `Page.getLayoutMetrics` over CDP is one such source.
- The values cannot be changed by page script (A4a).
- If the metrics read before and after the screenshot differ, or the read fails or times out, `{P}` is empty and a `note` record says so.
- The extent carries numbers only: no page text, title, URL or DOM content.
- **A4a (adversarial).** A start-page fixture whose script redefines `window.scrollY`, `innerHeight` and `document.scrollingElement` must still produce the true extent.

**A5. Logging.**
- In live, when `live_feedback` is given, every turn line gains `live_feedback: {"screen_label", "page_extent", "echo"}`.
  - `echo` is read from the live browser by duck typing (`getattr(browser, "echo", None)`).
  - With `live_feedback=None`, no key is added (the T-0132 A4c pattern).
- Every request that carries a label logs a `note`, or a key on its `llm.request` record (the implementer chooses and says which), with the label text and the extent numbers used (`above_px`, `below_px`, `viewport_px`, or `null`).
- No new span and no new log kind.

**A6. Never spoken, never stored.**
- Label text never reaches a `TtsSpeak`, history, the HUD, an `Episode` or `machine.events()`.
- History stores only what was spoken (CLAUDE.md).
- The speaking policy for computer use is unchanged: no per-step narration is added.

**A7. Cache.**
- The anticipatory prefill body is byte-identical with and without the label, for the same frame. The label lives in the query-dependent suffix, after the frame.
- If the implementer finds the prefill already covers text after the frame, stop and report; do not move the label before the frame.

**A8. Negative.**
- With `live_feedback=None` and `echo="pixels"`, these are byte-identical to BASE c29a8d9 in every mode, `live` included:
  - request bodies;
  - turn lines;
  - session-log records;
  - executor action strings.
- `LIVE_TOOL_GUIDANCE` is unchanged (sha256 `768a973b…`).
- `toolcall/tools_v1.json` is unchanged (`bbfc53cc…`).
- These are byte-identical over the task's closed range:
  - `local_astra/contracts/**`, `tests/fakes/**`;
  - `conductor/turn_machine.py`, `speech_gate.py`, `tool_executor.py`, `conductor/prompt_builder.py`;
  - `toolcall/reground.py`, `perception/policy.py`;
  - `local_astra/pages/**`, `hud/**`, `services/**`;
  - `local_astra/cli.py`, `local_astra/config.py`.

**A9. Docs.** One `docs/02-architecture.md` §5 paragraph, "Spec delta (T-0134)", covering:
- A1–A7;

- **The rest:** steps per turn, statuses, step latency, turn wall p50/p95, prefix-cache hit and query tokens, minimum free VRAM, acceptance, and all T-0131/T-0132 safety counts (each expected 0).
- **Difference intervals** (Newcombe 95 %) on success for B−A, C−B and C−A; on S4 for C−B; on non-S4 false claims for B−A.

**B5. Configuration voids the run.** Any of these findings gives `void` with the reason `configuration: <finding>`:
- a non-1120 body, or any reground line;
- `guidance_sent` false;
- an arm-A body carrying any label string;
- an arm-B or arm-C live step body lacking exactly one A3 label right after the current frame;
- an arm-B body with a `Page beyond this screen` clause;
- an arm-C body without that clause where the logged extent was known;
- an executed click or type response whose coordinates are not the call's own (arms B and C) or not `to_pixels` of them (arm A). A point where both readings agree is not judged.

**B6. Decision rule (proposed numbers; H-T134-1).**
- **Order:** P1 failed → `inconclusive`; P2, P3, P5 or configuration → `void`; stopped early → `incomplete`; any arm ineligible → `inconclusive`, naming the arm, the clause (`acceptance`, `safety` or `engine`) and the first failing trial (as T-0132 C6b). Then (y), then (x).
- **(y) Feedback (B vs A)** is adopted only if all of these hold:
  - success(B) ≥ success(A) − 3 (of 100);
  - non-S4 false claims(B) ≤ non-S4 false claims(A);
  - over-clicks(B) ≤ over-clicks(A).
- **(x) Extent (C vs B)** is adopted only if both hold:
  - S4(C) − S4(B) ≥ 5 (of 20);
  - success(C) ≥ success(B) − 3 (of 100).
- **Labels:**
  - (y) and (x) → `feedback + extent`;
  - (y) only → `feedback only`;
  - not (y), but success(C) − success(A) ≥ 5 and total false claims(C) ≤ total false claims(A) → `feedback + extent`, with the reason "via C vs A";
  - otherwise `no change`.
- Boundaries compare with a 1e-9 tolerance, so an exact margin passes.
- **Power, stated in the report:**
  - At n = 100 and p ≈ 0.65, one arm's success has a standard error of about 4.8 pp.
  - (y) is a non-inferiority rule for two mechanism-backed bug fixes; it cannot detect a small gain.
  - For (x), 5/20 against 0/20 has Fisher p ≈ 0.047, and Wilson 95 % intervals of [0.11, 0.47] against [0, 0.16].
  - The non-S4 false claims (3–5 of 80 at baseline) are too rare to show a reduction. Hence "≤" rather than a margin.
- Adopting a default is T-0134c.

## Implementation notes

**Why these fixes and not others.**
- **Prompt-only instructions already failed.** T-0107 failed on GPU, and T-0131's `LIVE_TOOL_GUIDANCE` already says "scroll to see the rest of the page" and "check that the new screenshot shows its effect". S4 stayed at 0/60 and the claims stayed.
- **The three features here are facts the harness owes the model:**
  - which image is current (D-3);
  - the echo in the units the model used (D-4);
  - that the page continues (D-1).

  They are not instructions. Do not touch `LIVE_TOOL_GUIDANCE`. The A/B must differ only by the features.

**Deferred options:**
- **A forced verify step** (a fresh screenshot plus a check before the final answer):
  - Every non-S4 false claim already had a fresh post-action screenshot in its last request (D-2). A second look at the same pixels is unlikely to help while the model doubts the image is current, and A-label tests that cheaply.
  - It also needs the final answer held back from TTS until the check passes: a speech-gate or turn-machine change, the highest blast radius in the repo.
  - If arm B leaves non-S4 false claims at or above A's, plan it as T-0134d.
- **A `done`/`verify` tool:** it changes `tools_v1.json`, whose sha is pinned by every harness. It belongs to T-0111h (tools_v2).
- **A below-the-fold preview frame:** about 1094 tokens per image at 1120, and it complicates B9's frame identity for clicks.
- **Visible scrollbars:** headless shell hides them, the desk browser is headed, and the model ignored a stronger visible cue ("Eight offers").

**Pixel-first (H-T134-2).**
- The extent is viewport geometry, the textual form of a scrollbar position. It is derived from layout metrics, never from page text.
- The planner rules it is not a content assist, so it can default on in live after T-0134c, and is logged per turn (A5).
- If the human rules it an assist instead, it becomes an off-by-default HUD checkbox in T-0134c (`hud/**` then owned there), and arm C stays as designed.

**Other notes.**
- **Reading the metrics.** Prefer a source page script cannot change, such as CDP `Page.getLayoutMetrics` on the page's CDP session (`runtime.py` already opens one). A `page.evaluate` of `window.scrollY` can be spoofed by any page, which matters when real websites arrive.
  - Read the metrics before and after the screenshot. If they disagree, there is no clause.
  - Inner scroll containers (a scrolling `div`) are not covered. Say so in the docs/02 delta.
- **Keep the defaults out of `Session`'s behaviour** (T-0132 R-f). Group A changes nothing for callers that do not pass the keywords. `cli` is T-0133's and later T-0134c's.
- **The echo with ReGround.** The executor receives 0–999 arguments in every path (`test_session_reground.py` already writes the executed `x`/`y` in model units). Echo exactly what was executed; do not convert pixels back.
- **No characters-per-token arithmetic** anywhere (B10).
- **Tool use.** The implementer never edits `tests/`. No heredocs around a blocked Write. Never export `GIT_DIR`.
