## Goal

James can mute the microphone from the HUD, with a button or with `m`.

While it is muted:
- Gearvis hears nothing: no transcript, no onset, no end-of-turn and no barge-in.
- Its own speech keeps playing, and typed questions still work.
- Unmuting resumes at the live edge, with no burst of buffered audio.

How it works:
- Mute is a gate on the audio path inside the session; the turn machine never sees it.
- The session owns the state, and the page shows the server's echo (T-0043).
- The state is replayed on hello and survives Restart.

On screen:
- A muted session is unmistakable.
- A session with no microphone shows the control disabled, with the reason.
- The capture button is renamed "Stop sharing".

## Acceptance criteria

### Group A: the wire, the gate, the state

**A1. Wire contract** (docs/02 §5 spec delta T-0181; the fake changes in the same PR).
- Two strict models go in `contracts/protocol.py`, in `AstraMessage`, `ASTRA_MESSAGE_TYPES` and exactly one direction set each. They are mirrored in `hud/src/protocol.js`, which decodes them strictly.
  - `astra.mic.mute` (client→server): `muted: bool`.
  - `astra.mic.state` (server→client): `muted: bool`, `available: bool`, `reason: str | None`.
- `astra.mic.state` is malformed in each of these cases:
  - `available` is false and `muted` is true;
  - `available` is false and `reason` is null;
  - `available` is true and `reason` is non-null.
- The codec round trip passes.

**A2. The session owns the switch.**
- `hud_server.route` hands `astra.mic.mute` to `session.apply_mic_mute(message)`, behind the hello fence.
- With a mic available, every routed mute publishes one `astra.mic.state` to every connection, redundant ones included.
- A change writes one `mic.mute {from, to}` record; a redundant toggle writes none.
- With no mic, the toggle changes nothing. It publishes `astra.error(code="mic_unavailable")` to the sender only.

**A3. Availability is decided once, at construction.**
- `Session` takes one keyword: available, or not available with a reason.
- The default is inferred: available if and only if `audio` is a `CaptureSource`. Otherwise the reason is `"this audio path has no capture seam"`.
- `cli.py` passes the resolved `Microphone` (T-0045). The reasons are exact:
  - `--no-mic`: `"this session has no microphone (--no-mic)"`;
  - `--mic none`: `"this session has no microphone (--mic none)"`;
  - `--silent`: `"this session is silent: no audio device is open (--silent)"`.
- A resolved node is available.
- Every printed line is byte-identical to BASE.

**A4. Hello.**
- Every hello reply carries `astra.mic.state` as its fourth message, right after `astra.log.state`, in no-mic sessions too.
- The T-0162 replayed reset still comes first, and T-0177's vision messages still come last.
- No other message changes.

**A5. The gate.** While muted, `_pump_capture` feeds `stt.feed` an all-zero frame in place of each captured frame.
- Each zero frame has the same length, `t_ms` and order, with one feed per captured frame. Nothing is dropped, held, paused or duplicated.
- The capture module, the self-speech gate and the raw stream are untouched.
- Mute takes effect, and lifts, at the first frame the pump handles after `apply_mic_mute` returns. The decision is made per frame, at handling time.
- On unmute, the next frame is bit-identical to the captured frame.
- Adversarial rows:
  - a "drop frames while muted" implementation hangs a mid-utterance mute in ENDPOINTING;
  - a "pause the pump" implementation fails the one-feed-per-frame count.

**A6. No word from a muted span reaches the machine.**
- The session records each muted span as the `t_ms` of its first and last zeroed frame, on the STT-tap audio clock. Word `start_ms` is on the same clock.
- An `SttWordEvent` whose `start_ms` lies inside a span is dropped before `Endpointer.observe`. It produces no onset, no `stt.word`, no transcript and no `stt.decision`.
- Words that started before the span are kept.
- Rows in both directions:
  - **too wide:** a word starting 1 ms before the span is kept, and so is a word after unmute;
  - **absent:** a content-blind fake word inside the span opens no turn.
- The dropped count goes in the unmute's `mic.gate` record. No dropped word's text is ever logged or published.

**A7-M. Muting mid-question drops the question** (H-T181-2, ruled by James 2026-10-28: "just drop it"). This supersedes H-T181-1 and A7's LISTENING/ENDPOINTING rows, and it adds a turn-machine change: group A0 below.

**A0. Machine (group A0, before group A; two reviewers; the turn machine and `contracts/events.py`).**
- New event `MicMuted(t_ms)` in `contracts/events.py`. The fake changes in the same PR.
- The session emits it once, at the moment `apply_mic_mute` turns mute on, and never on unmute. Time arrives in the event.
- **In LISTENING or ENDPOINTING with a voice turn open:**
  - the machine abandons the turn: no LLM request, no `CommitHistory`, no `ScheduleSummary`;
  - it emits `TurnAbandoned` (or the existing equivalent, if one exists) and reaches IDLE;

- **In IDLE, THINKING, SPEAKING and PAUSED:** no change. In THINKING the question was complete, so it is still answered. Muting during SPEAKING lets the answer finish.

**A7. Behaviour per state when mute engages** (as amended by A7-M: LISTENING and ENDPOINTING now abandon).

| State | Behaviour |
|---|---|
| IDLE | Nothing opens. |
| LISTENING mid-utterance | The zeros end the run, and the turn reaches THINKING with the pre-mute words and is answered (H-T181-2). |

**A8. Output and typed input are unaffected.**

**A10. Logging.**

## Implementation notes

- **Where the gate goes.** It sits in `session._pump_capture`, between `stt_blocks()` and `stt.feed`, never in `audio_capture.py`. Keep the pump's "never stops" property: zeros, not omission.
- **Clocks.**
  - A span boundary is the `t_ms` of the first frame the pump handles after the toggle, on the STT-tap audio clock. Compare it only with `SttWordEvent.start_ms`, which is on the same clock.
  - Never compare a session time with an audio time.
  - Audio up to the capture backlog before the click (≤ `QUEUE_BLOCKS` = 640 ms) can still reach STT. State this in the docstring.
- **Where to drop words.** Before `self._endpointer.observe(event)`.
- **Span ledger.** Bounded: discard spans older than `STT_OPEN_WORD_HOLD_MS` plus a margin.
- **Silent self-disable rule.** The published state must be the gate's truth. If mute cannot take effect, publish `available: false`, never a muted-looking state.
- **Logging.** Dropped words are counted, never logged.
- **Turn-line key.** `mic_muted` goes where T-0177 A10 adds `vision_source`. If the turn line is a strict contract outside `session.py`, stop and re-plan.
- **HUD.**
  - `mic.js` is DOM-free, and `main.js` only wires.
  - The `#mute-button` id stays: it is the hook for about 8 test modules and for `styles.css`.
  - The settings popover already stops key propagation.
- **Proactive speech.** When it lands, it must decide whether a muted mic suppresses proactive turns. That is a note for that task.
- **Rebasing.** A rebases over T-0176, T-0177 A/B, T-0178 and T-0179. B rebases over T-0177 C.
