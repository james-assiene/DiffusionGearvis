# T-0041 — `astra up` after a reboot: TTS is not on PATH, the engine's budget is too short

**Status:** done 2026-09-15 (merged; reviewer APPROVE after the test-side fixture) · **Blast radius:** low (one reviewer; `services/tts.sh`, `local_astra/supervisor.py` budget table) ·
**Origin:** the first real `astra up` on this box, 2026-09-15 23:00 after a reboot (the human present).

## Goal

The first real `astra up --profile lean` started all three services but reported two FAILED rows. (1) `services/tts.sh` execs
`taskset -c 2,3 pocket-tts serve …` and `pocket-tts` is not on PATH — Pocket TTS had only ever been started by hand with
`uvx pocket-tts …` (PROGRESS Runs, 2026-09-14), so the script has never worked from `astra up`; the `tts.pid` it left was stale.
(2) vLLM came up healthy at ≈ 130 s (engine init 69 s incl. 33 s compilation, plus container start and a cold page cache after the
reboot), but `probe_budget_s("vllm")` is 120 s, so `up` printed FAILED and exited 1 while the engine was seconds from ready. After
this task `astra up` succeeds on a rebooted box with nothing started by hand, and the Pocket TTS version it runs is the pinned one.

## Acceptance criteria

1. `services/tts.sh` starts Pocket TTS through `uvx` at the version pinned in `services/versions.lock` (`pocket_tts = "3.1.0"` — the
   version measured on this box on 2026-09-15 via `importlib.metadata`), on the pinned cores, loopback only; it does not require
   `pocket-tts` on PATH. A `bash -n` and a static row check the invocation; `astra status` after `up` shows the tts pid running.
2. The engine's probe budget covers a cold start: `probe_budget_s("vllm")` ≥ 240 s, printed as the budget used (T-0033 A14). The
   speech services keep their 20 s.
3. `astra up` on a box where `tts.sh` fails to exec reports the failure with the log's last line, not just "connection refused"
   (the supervisor reads `logs/<service>.log` tail into the FAILED row).
4. `versions.lock` gains `pocket_tts = "3.1.0"` — **human edit** (the lock is hook-denied to agents); the task records the value.
