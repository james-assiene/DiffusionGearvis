## Goal
After T-0077a the three log-semiring trees run on the live `[·, S, S]` block. They are still bandwidth-bound: `semiring.log_matmul`
materialises `[g, r, m, c]` chunks of up to 16 MiB and makes about 8–15 passes over them per product. Measured (`logs/t0077a-ab-ffa46f4`,
live path, CL 256, V 262 144, n 4×50, b64/b128/b256/b512 with |S| 32/91/205/400):
- `pass1_tree`: 0.90 / 3.46 / 43.2 / 226.6 ms;
- `pass2`: 4.10 / 9.00 / 83.3 / 452.0 ms;
- `perstep_mar` whole call: 30.1 / 39.9 / 158.4 / 763.8 ms.

This task replaces every CUDA `log_matmul` call with one Triton kernel family (plain and compensated) that computes, in registers, the
per-entry max over m, the shifted exp-sum (with the TwoSum error of every `A_ij + B_jk` in the compensated variant) and `_finish`, and
writes only the `[nb, n, k]` output. Per-term arithmetic is unchanged, so the kernel becomes ALU-bound: 255·S³ terms per tree at L 256
(2.2 G at b256, 16.3 G at b512).

Scope boundaries:
- The max-plus product (`mapdecode.max_matmul`, the MAP tree) is **out of scope** (T-0077d); its contract is N3, not N4.
- The per-product normalisation (`tree.py`) and the down-sweep bookkeeping (`marginals.py`) are out of scope: not owned.
- The CPU path (the reference; what `make cd-test` runs) does not change by a byte or by a traced op.

**What precision-neutral means here.** Trees, a/b, log Z, q and H(q) are sum-product parts and may move at the N4 level on CUDA (umbrella:
"not bit-identity to the old path unless a sub-task says so"). This task does not claim bit-identity to torch's CUDA reduction, whose
order over m is internal to ATen. It fixes its own order (the **spec order**, below); the kernel is pinned to it bit for bit on CUDA
(against a torch emulation) and on CPU under the interpreter, and N4's fp64 bars apply on top. Every N3 part (`class_max`, the max-plus
tree, MAP, δ\*, `terminal_factor`, generator consumption) is untouched by construction: none calls `log_matmul`.

## Implementation notes
- **Spec order** (the contract; the implementer designs the tiling). IEEE fp32 round-to-nearest, no contraction (`backend.launch_options()`).
  For each output `(g, i, k)`:
  1. Max pass, any order (max is exact): `mx = max_j t_j`, `t_j = fl(a[g,i,j] + b[g,j,k])`, NaN-propagating (`tl.maximum(...,
     propagate_nan=tl.PropagateNan.ALL)` inline; 3.7.1 rejects it bound to a variable).
  2. `live = mx > DEAD`, `safe = live ? mx : 0`; `DEAD`/`SENTINEL` as fp32 bit patterns.
  3. Sum pass, **strictly j = 0, 1, …, m−1 ascending**, from `s = +0.0`, `c = +0.0`: compensated `x_j = exp(fl(fl(t_j − safe) + err_j))`
     with `bb = fl(t_j − a)`, `err_j = fl(fl(a − fl(t_j − bb)) + fl(b − bb))` (exactly `semiring.log_matmul`'s formulas); plain `x_j =
     exp(fl(t_j − safe))`; then TwoSum: `s' = fl(s + x_j)`, `z = fl(s' − s)`, `e = fl(fl(s − fl(s' − z)) + fl(x_j − z))`, `c = fl(c + e)`,
     `s = s'`.
  4. `S_tot = fl(s + c)`.
  5. `out = _finish(mx, S_tot, compensated)` op for op as `semiring._finish`: `ls = log(S_tot)`; compensated: TwoSum`(safe, ls)` → `hi + (lo
     + (fl(S_tot·exp(−ls)) − 1))`; then `where(live, ·, SENTINEL)`.

  Masked lanes beyond m are not iterated (or contribute exactly nothing). exp/log are libdevice `__nv_expf`/`__nv_logf` on CUDA; fp64 rounded
  once under the interpreter (constexpr from reading interpreter mode, never setting it).
- **Why this order (planner's CPU measurement**, torch 2.13.0+cpu, numpy 2.4.6, fp32, outer 64, 30 % sentinels, seeds 0/1, fp64+fsum
  oracle on fp32-rounded inputs; scratch `orders.py`, not CUDA). Gauged mean/max ulp(1.0) (bar 0.75/2.5) at inner 32/91/205/400/512; wide
  max ulp / % > 0.51 (bar 1.0/5 %):
  - torch CPU sum (today's reference): 0.67/2.77 (**fails max**), 0.49/2.33, 0.50/2.32, 0.43/2.05, 0.44/2.03; wide ≤ 0.62 / ≤ 2.8 %;
  - plain sequential: 0.73/3.04, 0.76/4.30, 1.07/5.42, 1.45/6.77, 1.56/7.70; wide up to 0.93 / 9.3 % (fails 5 % from inner 205);
  - **spec order:** 0.64/2.16, 0.39/2.10, 0.34/1.44, 0.30/1.19, 0.31/1.16; wide ≤ 0.58 / ≤ 2.0 %;
  - adjacent-pair tree: 0.67/2.79, 0.46/2.30, —, —, 0.35/1.60.

  Plain spec vs torch CPU plain: max and mean ≤ on every row; share > 0.51 ulp within 0.1 pp. The spec order is tiling-independent (N2 and 3b
  automatic), costing ~6 extra fp32 ops per term on top of ~20. An outer-product kernel looping j over a `[BLOCK_N, BLOCK_K]` tile twice
  implements it natively.
- **Dispatch placement (zero traced ops on CPU preferred).** `log_matmul` already reads `a.device` once for `torch.empty(...,
  device=a.device)`; read it once there (`dev = a.device`), decide on `dev.type`, then launch on `a3`/`b3`/`out`, so the CPU op sequence is
  unchanged and the golden stays green unedited. Otherwise list the added names; O4 applies.
- **Triton landmines (T-0077b, all present in 3.7.1):** `tl.exp`/`tl.log` approximate (use libdevice); libdevice FTZ by default (pass
  `enable_reflect_ftz=False`); FMA contraction on by default (pass `enable_fp_fusion=False`; the spec forbids contraction in `_finish` so 3a
  is bit-checkable); options per launch only, never knobs/env (N6); a Python float < 2^−126 becomes fp64 — pass fp32 constants as bit
  patterns; `tl.maximum` needs inline `propagate_nan`; `tl.sum`/`tl.reduce` promise no order; M1/K3 builder form (global `triton`, `tl`,
  `libdevice` and every jit helper); strides as runtime args (live views have row stride B ≠ S); n, m, k, nb runtime ints; tiles `constexpr`
  from shapes; int32 offsets suffice (≤ 256·512·512 < 2^31; assert on host); `torch.compile`: compiled == eager required, a per-function
  `torch._dynamo.disable` on the host entry is allowed (not global config).
- **NaN/±inf** follow the torch path (same ops): NaN anchor → `live` False → sentinel; −inf operands in the compensated variant → NaN via
  TwoSum, as today. 3a/3c compare positions.
- **Memory.** The kernel allocates only `out` (as the torch path does); up to ~3–4 × 16 MiB chunk temporaries per product disappear. The
  whole-call peak sits at the draw/H-tail `[L, V]` step; allocator block reuse changes, so L9's item-2 slack (< 1 MiB per resident block)
  can move either way, with no margin left (A already contains the L9 draw fix). If the peak gate fails, argue the bytes from the code (L9);
  see H1.
- **No host sync:** grid from shapes; no `.item()`; dispatch reads only `.device`, `.dtype`, `.shape`, `.dim()`. L5 unchanged (no static
  buffers, no CUDA graphs).
- **Expected effect** (estimates): `pass1_tree`/`emission` 0.9→≈0.5, 3.5→≈1, 43→≈4–8, 227→≈25–50 ms; `pass2` 4.1→≈2, 9→≈4–5, 83→≈8–15,

  `map_sweep` and `end_projection` unchanged.
