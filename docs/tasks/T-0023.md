## Goal
T-0006 and T-0021 built the audio path and proved it on fakes and on a bit-exact null-sink monitor.
Neither has ever met a loudspeaker. This task is measurement, not construction: it runs the real
acoustic path — speakers → room → Logitech C925e mic → this module's capture tap → `astra-stt` on
127.0.0.1:8080 — and produces the four numbers the design has been quoting as hypotheses. (1) The
**echo-path delay** (DAC → air → ADC), which is precisely the residual T-0021 ruling A20 left
unmodelled when it made the rendering span `captured_ms() + (written − rendered)`: the span knows
when we handed audio to the DAC, not when the microphone hears it. (2) **Zero self-transcription**
with the gate on, against a **positive control with the gate off** that must self-transcribe — without
the control, "the STT produced nothing" is indistinguishable from a dead mic, a dead STT, or a gate
stuck shut. (3) `DEFAULT_HANGOVER_MS`, today the placeholder **60.0**, re-derived from that
measurement with its regime recorded in the module docstring. (4) A **10-minute duplex run** with zero
xruns, capture→STT handoff p95, event-loop lag p99 and RSS growth — docs/03 §7 B15's one line that is
measurable without AEC. On the way it takes the first real readings of T-0021's rig criteria 9 and 11
(seven rig tests that have never executed) and re-runs T-0006's criterion 9 pause→silence with its
bias stated (ruling A13). The only behavioural change to `local_astra/` this task is allowed to make
is one constant and, if the leading-edge measurement demands it, the span start in `audio_io.py`.

## Acceptance criteria

Each is checkable by a test, a script threshold, or a report field. Criteria 1 and 8 are checkable in
the fast suite with no hardware; 2–7 need the box, the room and a `/launch`. "The control" always means
the gate-off run in the same session, with the same tail policy, on the same hardware.

1. **A report without its regime is not a report (fast suite, group A).** Both scripts emit one JSON
   document whose first object is a `regime` block with every field of §Regime present and non-empty:
   `box`, `pipewire_version`, `sink`, `sink_volume`, `source`, `transducer` (`speakers` | `headset`),
   `distance_cm`, `noise_floor_peak`, `stt` (server version, model revision, CPU/GPU, batch_size),
   `co_resident` (what else was running), `profile`, `gate` (`on`/`off`), `hangover_ms`, `n`, `seed`,
   `git_sha`, `duration_s`, `negotiated_quantum_ms`, `measured_dac_lag_ms`. A missing or empty field
   makes the script **exit non-zero with that field named and print no measurement at all**. The
   headset row is either a measurement or the literal `"NOT MEASURED"` plus a reason; a speakers
   number may never appear under the headset label. *(CLAUDE.md "state the whole regime beside every
   number"; docs/03 §7.)*
2. **Echo-path delay, measured and stable.** On the acoustic path, the lag that maximises the
   cross-correlation between the chirp as written to the device and the chirp as recorded by the mic,
   **n = 10, seed = 0**, reported as p50 / p95 / spread / pstdev, for **speakers** and — if P4 is met —
   **headset**, each with its own regime line. Physicality is asserted (0 < delay ≤ 1000 ms) and
   `pstdev ≤ 50 ms`, because a hangover derived from a delay that wanders by more than that is
   meaningless. The calibration guard (T-0006 criterion 11) runs **first** and **fails, never skips**,
   when a sink is named but silent. *(Closes T-0006 criterion 10, owed since ruling A10.)*
3. **Zero self-transcription with the gate on, and a control that self-transcribes.** Play the
   `pocket_tts_sentence.wav` fixture through the speakers while feeding `stt_blocks()` straight into
   `MoshiSttClient.feed()` (no resampling, reframing or retiming — T-0021 criterion 7), followed by
   ≥ 3 s of real captured tail before the transcript is read (the delayed-stream model advances its
   clock only on audio; a stream that stops dead transcribes nothing, and a starved STT is a false
   pass). **n = 10 utterances per condition.**
   - Gate **on**: content-word overlap with the spoken sentence is **exactly 0** after casefolding,
     punctuation stripping and stop-word removal. Spurious words attributable to room noise are
     reported as a separate count, not folded into the headline.
   - Gate **off (the positive control, mandatory)**: overlap ≥ **50 %** of the spoken content words.
     If the control transcribes nothing the whole measurement **errors** — "silence proves silence"
     is the failure this criterion exists to prevent.
   *(docs/03 §7 B15's self-echo line minus AEC; docs/02 §4.)*
4. **Negative — the gate is not stuck shut.** With playback idle (no rendering span open), the same
   fixture played through the speakers **is** transcribed (overlap ≥ 50 %) with the gate on, in the
   same session as criterion 3. An implementation that gates every block passes criterion 3 perfectly
   and destroys the product; this test must exist and must fail that implementation.
5. **The hangover is chosen from the measurement, bounded, and documented.**
   `audio_capture.DEFAULT_HANGOVER_MS` is set to `ceil(p95 echo delay + CAPTURE_BLOCK_MS)` from the
   **speakers** run (the worse path), or explicitly re-affirmed at 60.0 when the measurement agrees,
   and the module docstring carries that number **with its regime line and the date**. Bound: the
   chosen value is **≤ 200 ms**; a larger measured value is a **spec change** (docs/01 §8's capture
   line and docs/02 §4) raised with the measurement, not a silently large constant — because every ms
   of hangover is a ms of the user's reply that reaches the STT as substituted silence. The
   leading-edge residual is reported separately and is **not** covered by the hangover: the hangover is
   a trailing-edge device (T-0021 criterion 8). *(T-0021 ruling A22 re-measurement.)*
6. **Leading-edge residual, measured and bounded.** Per utterance, the duration of echo-carrying
   capture that reached the STT tap **ungated** at the start of playback, n = 30 across the criterion-3
   runs, p50 / p95 reported. Bound: p95 ≤ `CAPTURE_BLOCK_MS + p95 echo delay` (the span start knows
   the DAC hand-off, not the air path — T-0021 ruling A20). If it exceeds that, the correction is the
   span start in `audio_io.py` (owned here, narrowly) and the report says which term was wrong; it is
   never absorbed by raising the hangover.
7. **The 10-minute duplex run (B15's measurable line).** 600 s of continuous capture with playback at a
   stated duty cycle (4 s speech / 6 s silence, seed 0), gate on, on the null-sink rig: **`xruns == 0`,
   `dropped_blocks == 0`, `substituted_ms == 0`, `underruns == 0`**; capture→STT handoff **p95 ≤ 20 ms**
   (docs/01 §8 "Mic capture + AEC + resample — 20 ms"), with p50 reported and the structural +80 ms of
   filling a 1920-sample frame stated and excluded, never hidden inside the number; event-loop lag
   **p99 ≤ 20 ms** (`.claude/rules/conductor.md`); RSS growth **< 1 MB/min** by a least-squares fit over
   samples taken every 10 s (n ≥ 60), never `last − first`. A run shorter than the declared 600 s is
   refused, not reported. *(docs/03 §7 B15 "audio xruns/dropouts = 0 over 10 min".)*
8. **The owed rig numbers are taken, and a miss is diagnosed, not re-baselined.** All seven tests of
   `tests/integration/test_audio_capture_null_sink.py` (T-0021 criteria 2, 3, 9, 11, 12f — never
   executed) and all six of `tests/integration/test_audio_null_sink.py` run, plus
   `scripts/audio_loopback.py --measure pause --n 30 --seed 0` for T-0006 criterion 9, whose p95 is
   quoted **as a lower bound understated by up to `latency_ms + block_ms`** in the same sentence as the
   number (T-0006 ruling A13), alongside the negotiated quantum and the measured DAC lag. Every failure
   is classified in the report as *fixture bug* or *spec bug* with evidence (T-0021 ruling A8 predicts
   fixture bugs on the first run). **No threshold is edited to make a run pass.**
9. **Negative — nothing but one constant moves.** (a) `git diff --stat main -- local_astra/` shows only
   `conductor/audio_capture.py` (the constant and its docstring) and, at most, the span-start lines of
   `conductor/audio_io.py` under criterion 6. (b) `local_astra/contracts/**`, `local_astra/telemetry/**`,
   `local_astra/bench/thresholds.py`, `local_astra/reflex/**`, `conductor/session.py`, `hud/**` and
   `services/versions.lock` are untouched; B3/B4/B15 stay where they are. (c) **No AEC:** no import of
   `livekit`, `webrtc`, `speexdsp`, no `module-echo-cancel` wiring, `Profile.aec` stays `"none"`
   (docs/01 R4, docs/06 R3). (d) Every unit and contract test of T-0006 and T-0021 passes unmodified
   with the new constant in place — if the re-measured hangover breaks a unit test, the test is telling
   you the constant leaked into a behaviour the spec fixed, and that is a finding, not an edit. (e) The
   scripts open no non-loopback socket (`127.0.0.1:8080` only) and write only to `$TMPDIR` unless
   `--out` names a path under `artifacts/`, which runs through `/launch`.

## Implementation notes
- **The one thing that matters:** the number this task exists for is the DAC→ADC delay, and it is the
  exact term T-0021 ruling A20 left out of the rendering span. Measure it before touching the hangover;
  the hangover is a consequence, not an input.
- **The hangover does not protect the leading edge.** It anchors on the *end* of the last rendering
  block (T-0021 ruling A16c). Echo that arrives before the span opens is a span-start problem
  (criterion 6), and an implementer who fixes a leading-edge miss by enlarging the hangover has moved
  the defect, not removed it.
- **Do not port `scripts/demo/ask.py`'s acoustic loopback.** It was a hand-verified rung: no gate, no
  capture clock, level-based endpointing. What carries over is the hardware lesson — the delayed-stream
  STT advances only on audio, so every transcript read needs a real captured tail (`_listen.py` used
  `TAIL_SILENCE_S = 3.0`), and the control run uses the same tail policy as the gated run or the
  comparison is invalid.
- **Feed the STT tap, not the raw stream.** `stt_blocks()` → `MoshiSttClient.feed(pcm, t_ms)` with no
  resampling, reframing or retiming (T-0021 criterion 7). Feeding 48 kHz audio to a 24 kHz endpoint
  produces a plausible-looking transcript of nonsense and would quietly invalidate criterion 3.
- **The room is not a null sink.** The mic's ambient peak measured ≈ 0.116 in this room; a −60 dBFS
  energy assertion that works on the monitor is meaningless through the air. Gated blocks are digital
  silence by construction, so measure *which blocks were gated*, not how quiet the room was.
- **P1 gates everything.** `libportaudio2` absent → `open_device()` raises; the rig tests must **error
  naming P1**, never skip (T-0006 ruling A10).
- **Contention moves these numbers.** Record whether vLLM and `astra-stt` were co-resident; the STT is
  on CPU and the soak's handoff p95 is a CPU number. Run on a clean tree (`git status --porcelain`
  empty) — measuring while another agent edits `local_astra/` is the first line of CLAUDE.md's observed
  mistakes.
- **numpy only**; `scipy` is not a dependency and must not become one.
- **Known landmines the reviewer will mutate for:** (1) force `should_gate` to return `True` always →
  `test_the_gate_does_not_silence_audio_that_is_not_ours` must go red (criterion 3 alone will not
  catch it); (2) return an empty control transcript → `test_an_empty_control_transcript_errors...` must
  go red; (3) compute RSS growth as `last − first` → the GC-dip test must go red; (4) drop a regime
  field → criterion 1's parametrised test must go red. If the suite stays green on any of these, the
  tests are wrong, not the mutation.
- **Do not weaken a test to fit a threshold.** If handoff p95 > 20 ms or the measured hangover > 200 ms
  on this hardware, that is a spec change to docs/01 §8's capture line (or docs/02 §4), raised with the
  measurement and its regime — never an edited assertion, never a `pending` marker on a red test.
