## Goal
File ownership stops depending on how a planner happened to format a bullet. Today
`.claude/hooks/protect_paths.sh` reads `## Owned files` line by line, strips a leading `-` and
*outer* backticks, and uses whatever is left as a bash `case` glob: an annotated bullet
(`` - `local_astra/conductor/audio_io.py` *(from T-0006: …)* ``) becomes a glob that matches
nothing, so **every** Edit/Write on a file the task legitimately owns is denied, while a not-owned
path written as a plain bullet under "Files this task needs and does not own" is **granted**,
because the section regex swallows that list and the prose around it. Both were measured on a
throwaway repo against the live hook (evidence below). Meanwhile `guard_bash.sh` has no ownership
rule at all, so an implementer that reaches for `cat > x.py <<'PY'`, `tee`, `sed -i` or `cp` writes
any file in the repo with no ownership check whatsoever — also measured. After this task there is
**one** owned-files parser, in `_lib.sh`, used by both hooks; ownership is enforced on the common
Bash write shapes as well as on Edit/Write; and the formatting workaround forced on T-0021 ("Exact
bare paths — the hook reads one path per bullet") is no longer needed, because annotated and
wrapped bullets parse correctly.

## Why (measured 2026-09-14 on `main` @ 7989c81, throwaway repo, hooks invoked as `bash <hook>` with the real hook JSON on stdin)

Task file under test (`docs/tasks/T-0099.md`), branch `T-0099-probe`, `agent_type=implementer`:

```markdown
## Owned files
- `local_astra/x.py` *(new — the module)*

**Files this task needs and does not own:**
- local_astra/other.py
```

```
BLOCKED (implementer): local_astra/x.py is not in the owned files of task T-0099.   <- owned
ALLOWED                local_astra/other.py                                         <- not owned
```

The verdict is exactly inverted. Parsing T-0021's pre-HEAD `## Owned files` block through the
hook's embedded python prints, among other things:

```
'local_astra/conductor/audio_io.py` *(from T-0006: `capture()` delegates here; playback untouched)*'
'local_astra/contracts/protocols.py` — **T-0017** (open). `AudioIO` is not widened: `capture()'
'T-0006 owns four of these today. **This task may not start until T-0006 is merged**; ownership then'
```

— one unusable glob per owned file, one *not-owned* file's path leaking into the same list, and
prose lines becoming patterns. `\n##` also matches `\n###`, which is the only reason the not-own
list stops where it does in that file; a task whose not-own list sits before no `###` heading leaks
everything after it.

And the Bash side, same sandbox, same implementer role, owned file = `local_astra/only_this.py`:

```
ALLOWED: cat > local_astra/x.py <<'PY' … PY
ALLOWED: sed -i s/a/b/ local_astra/x.py
ALLOWED: printf hi | tee local_astra/x.py
ALLOWED: cp /tmp/a local_astra/x.py
```

Only `tests/*.py` writes are shape-blocked today (the "do not delete, move or overwrite tests"
rule), and that rule is about tests, not about ownership.

## Acceptance criteria
"Denied" means the hook exits non-zero; "allowed" means exit 0. Every criterion is checkable by a
unit test in the two modules below, except 12 (a measurement).

1. **One parser, in `_lib.sh`, used by both hooks.** `_lib.sh` exposes a function (name the
   implementer's, e.g. `owned_globs <task-file>`) printing one glob per line; `protect_paths.sh`
   calls it instead of its embedded python, and stage 2's Bash rule calls the same function. The
   parser must not run at *source* time: sourcing `_lib.sh` for a call that never needs ownership
   costs nothing (criterion 12). Proved by a test that feeds one pathological task file to **both**
   hooks and asserts they agree on the same path (docs/09 §"All hooks source `_lib.sh`").
2. **An annotated or wrapped bullet yields the path.** For each bullet form the parser yields
   exactly the path and nothing else: bare (`- local_astra/x.py`); backticked
   (``- `local_astra/x.py` ``); backticked with a trailing annotation
   (``- `local_astra/x.py` *(new — the module)* ``); the same with the annotation **wrapped onto a
   continuation line** (the T-0021 shape, which is the defect this task exists for); a `*` or `+`
   bullet marker; an indented sub-bullet; a glob (`local_astra/conductor/**`, `scripts/gpu/**`); a
   path with a hyphen or a dot in it. The verbatim pre-HEAD T-0021 `## Owned files` block is a
   fixture in the test module and all five of its paths are allowed (T-0021 ruling A15).
3. **The section ends where it should.** The parser stops at the first heading of any level
   (`^#{1,6}\s`) **and** at a "not own" marker line — the bold form
   `**Files this task needs and does not own:**`, `**Files this task deliberately does not
   touch…**`, and any line whose text matches the marker rule the implementer states in a comment
   (it must cover those two live spellings plus "does not own" / "deliberately does not touch"
   case-insensitively). Paths listed after the marker are **never** owned, whether backticked or
   bare. This is the second half of A15.
4. **Prose never becomes a pattern.** A non-bullet line inside the section yields nothing; a bullet
   whose first token is not path-shaped yields nothing. Path-shaped is defined by the implementer
   and stated in a comment; it must at minimum reject tokens containing whitespace, `—`, `*` used
   as bold markup (`**T-0017**`), a leading `/`, or `..`, while accepting `**` as a trailing glob.
   *Corpus criterion:* for **every** `docs/tasks/T-*.md` in the repo, the parsed list contains only
   tokens that look like repo-relative paths, and contains no pattern matching
   `local_astra/conductor/turn_machine.py` unless that file is genuinely one of the bullets.
5. **Negative — no over-grant, ever.** No parse of any task file may yield a pattern that matches a
   path the file does not list: in particular a bare `*`, an empty string, or a pattern derived from
   a prose line. A test drives the corpus of `docs/tasks/*.md` plus a hostile synthetic file (a
   section containing ``- **everything under `local_astra/**`**``, a lone `*`, a table row, a fenced
   code block containing `- /etc/passwd`) and asserts an unrelated path stays denied.
6. **Fail closed, with a name.** If the task file is missing, has no `## Owned files` section, or
   the section parses to zero globs, the implementer's edit is **denied** with a message naming the
   task file and the section (today an empty parse silently allows everything — an open hole). If
   the parser itself errors, the hook denies rather than allows, and the message says the parser
   failed and names `_lib.sh`; no bare traceback reaches the model.
7. **Negative — every other `protect_paths.sh` rule is unchanged.** Regression pins, all passing
   today: `services/versions.lock` and `uv.lock` always denied; every role may write
   `.claude/agent-memory/<role>/**`; implementer denied on `tests/**`, `.claude/**`, `CLAUDE.md`,
   `docs/03-test-plan.md` *before* the owned-files check; implementer with no task branch denied
   with the "run 'git switch -c T-NNNN-<slug>'" message; test-author confined to `tests/**`; planner
   to `docs/tasks/**`; reviewer/verifier/launch-reviewer/explorer read-only; `notebook_path`
   honoured when `file_path` is absent; a path outside `$TOP` is not silently turned into a relative
   match (docs/09 §hooks paragraph).
8. **Negative — the bare-path workaround keeps working.** T-0021's current, already-rewritten
   bare-path block parses to the same five globs as its annotated predecessor. Nobody has to re-edit
   a task file for this fix, and no task file is edited by this task.
9. **`guard_bash.sh` enforces ownership for `ROLE=implementer` on the common write shapes.** With a
   task branch whose task owns `local_astra/only_this.py`, each of these is denied because its write
   target is not owned: `cat > local_astra/x.py <<'PY' … PY`; `cat >> local_astra/x.py`;
   `printf … | tee local_astra/x.py`; `tee -a`; `sed -i s/a/b/ local_astra/x.py`;
   `cp /tmp/a local_astra/x.py`; `mv /tmp/a local_astra/x.py`; `rm local_astra/x.py`;
   `cd local_astra && cat > x.py <<'PY'` (the `cd` is resolved, T-0016 I1); and the quoted spellings
   `cat > "local_astra/x.py"` / `'local_astra/x.py'` / `"$TOP/local_astra/x.py"` (T-0016 I10: a
   quoted path is still a path — the ownership scan reads the quote-preserving view and strips
   quotes per token, never the blanked `scan` view). The refusal names the path and the task, like
   `protect_paths.sh`'s.
10. **Negative — the Bash ownership rule does not become a nuisance.** All allowed: a write to an
    **owned** path in every shape above; a write outside the repo (`/tmp/...`, the scratchpad); any
    write when `ROLE != implementer` (the main session is `none` and does this task's own work);
    reads of any path (`cat`, `grep -n '>' local_astra/x.py`, `ruff check`, `git add`); a `>` or a
    path mentioned **inside a heredoc body fed to a non-interpreter** or inside a commit message
    (`git commit -m 'wrote > local_astra/x.py'`) — the over-block twin, and the same distinction
    group 4/9 of the guard suite already pins; `mkdir -p`, `cd`, and pipelines with no file target.
    An implementer on **no** task branch that writes a repo path is denied with the same message
    `protect_paths.sh` gives (consistency, criterion 7).
11. **Negative — the GPU path is untouched.** All 113 existing rows of
    `tests/unit/test_guard_bash_hook.py` stay green; the destructive-git, test-silencing,
    implementer-push, launch-token, dirty-tree and service-start behaviour is byte-for-byte the same
    decision for the same input; `bash scripts/bootstrap.sh` still prints
    `hooks run and block an unapproved GPU command` (T-0016 criterion 4). The ownership rule is
    additive and runs after them.
12. **Per-call cost.** No new `python3` process on any **untriggered** path: `guard_bash.sh` still
    starts exactly one normaliser (candidate write targets are a third line of its existing output,
    or an equivalent no-new-process design), and `_lib.sh`'s parser runs only when a triggered path
    needs it (`ROLE=implementer` **and** at least one in-repo write target, or an implementer
    Edit/Write). Median wall time over n=25 is within **1 ms** of the `main` baseline for each of
    the three commands in §Regime (T-0026 criterion 10's bar; report the structural half — the
    process count from the diff — too).

- The parser is a *format* reader, not a markdown parser. Keep it in python3 (both hooks already
  shell out to `python3`; `_lib.sh`'s `jf` is the precedent) and keep it total: any input yields a
  clean list or a named failure, never a traceback on the model's screen.
- Contracts to respect in `guard_bash.sh`: the two-line `gated\nscan` protocol between the python
  normaliser and bash becomes three lines at most and the fallback stays the same shape (on a python
  failure: not gated, raw command, **no** write targets — and the ownership rule then does not fire,
  which is fail-*open* for ownership and fail-closed for GPU; state the choice in a comment and tell
  the reviewer, since it is the one place the two gates disagree about which way is safe). `scan`
  blanks quoted spans; the ownership scan must use the quote-preserving view (`kept`) with per-token
  quote stripping, or it re-opens I10 for writes. Heredoc **bodies** are not scanned for write
  targets (that is what makes the over-block rows pass).
- Do not try to make the Bash rule complete. It covers the shapes an agent reaches for, not every
  way a byte can land in a file; the guard is a speed bump, not a sandbox. The residuals go in the
  hook's comment header.
- Do not change what any role may do. This task changes *how the owned list is read* and *where it
  is enforced*, never who owns what.
- Known landmines the reviewer will mutate for: (1) drop the section-end/marker rule → the
  not-owned test must go red; (2) accept the whole remainder of a bullet instead of its first token
  → the annotated-bullet rows go red; (3) return "allow everything" when the parse is empty →
  criterion 6's rows go red; (4) match the raw command for `>` in the Bash rule → the commit-message
  row goes red; (5) use the blanked `scan` view for write targets → the quoted-target rows go red. A
  mutation that leaves the suite green means the pinning row does not exist — report it, do not
  adjust the test.
