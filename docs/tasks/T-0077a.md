**Status:** done (2026-10-04; verified at 9c5217f) · **Blast radius:** high (two reviewers; the launch reviewed) · **Branch:**

## Goal
The three log-semiring trees (pass 1, the compensated pass 2, the max-plus MAP tree), both down-sweeps and the draw's descent
run on `[·, B, B]` with B the padded bucket, paying (B/|S|)³ = 8×, 2.8×, 1.95×, 2.1× too much work at buckets 64/128/256/512
(`logs/t0071a-microbench-9a386ee`). Run them on `[·, S, S]` with S = `n_states` and pad back to bucket shapes at the outputs,
with no change to any numerical contract beyond N4.

## Acceptance criteria
1. Umbrella criteria 1–3 (N1–N6; negatives: `unconstrained` bit-identical to stock, the not-owned files byte-identical, public
   signatures and output shapes unchanged, peak memory ≤ 9a386ee per arm and bucket; `t0071a_a1.sh` runs unedited — sync rows 0
   raises, microbench per component vs 9a386ee, the same-process A/B shows no component > 10 % slower at any bucket).
2. **Live states (umbrella criterion 4).** Pass-1/pass-2 trees, both down-sweeps, the draw's descent and the MAP sweep run on
   `[·, S, S]`; outputs are padded back to bucket shapes. The draw still draws its uniforms at the padded shapes and slices them,
   so CD-generator consumption is unchanged (N3). Optional: dyadic nodes entirely at positions ≥ `l_eff` are not multiplied
   (bit-identical to the product they replace).
3. **Exact parts (N3)** bit-identical to the frozen pre-change copy on CPU: `class_max`, the max-plus tree, the MAP's tokens,
   score and `empty`, δ\*, `terminal_factor`, generator state after `joint_draw`, the draw's tokens.
4. **Sum-product parts (N4)** within T-0065 c1's fp32 tolerances (dq ≤ 1e-6, dH ≤ 1e-5) of the frozen path on the core instances,
   and T-0073 D0-(c)'s ulp bar for every compensated product against fp64 on fp32-rounded inputs.
5. **Records (N5)** on the CPU stock world: `unconstrained` and `end_projection` bit-identical; per-step records equal to the
   frozen path's for every per-step arm (incl. `perstep_mar_qargmax` and its SC twin); a difference fails the row and is
   adjudicated by the orchestrator (value, |Δ| within N4), never edited.
6. **Reported (umbrella criterion 5):** the tree, pass-2 and MAP components at buckets 256/512 against (|S|/B)³; and the T-0076
   golden module (`test_cd_perstep_golden.py`) — say whether it stays bit-identical (it pins op sequences and sum orders: a
   legitimate N4 change will redden it; if so the orchestrator rules whether the golden traces are re-recorded under this task).

Where the bytes came from (the A/B's "peak added" is `max_memory_allocated()` after a reset minus `memory_allocated()`
before one call: the sum of *allocated block sizes*, 512-B rounded, at the call's peak). perstep_mf's peak is the draw's
token step (`[L, V]` fp32 tensors), with the pass-1 tree and `scaled` resident.
1. **Real bytes, +0.831 / +0.232 / +0.033 MiB at b512 / b256 / b128: three `[S, S]` fp32 tensors alive through the
   draw's peak.** The live `joint_draw` built the boundary pair's Gumbel noise inline, so `pair`, `u` (the `[B²]`
   uniforms sliced and copied to `[S²]`) and `g` stayed `joint_draw` locals until it returned; the frozen path keeps
   only `pair` (`[B²]`; its `u`/`g` die inside `gumbel_argmax`). Live 3·S²·4 vs frozen B²·4: b512 3 × 640 000 −
   1 048 576 = +871 424 B (0.831 MiB); b256 3 × 168 448 − 262 144 = +243 200 B (0.232 MiB); b128 3 × 33 280 − 65 536
   = +34 304 B (0.033 MiB, the "sub-0.1"). These are the A/B's `draw` component deltas (b512 1091.1 → 1091.9, b256
   1089.1 → 1089.3, b128 equal at 0.1 MiB) and all of b256's and b128's whole-call deltas.
2. **Allocator slack, ≈ +0.88 MiB at b512 only: not a tensor.** 1.7 − 0.83 ≈ 0.88 MiB of b512's whole-call delta is
   no live tensor (CPU allocation trace below: at the peak the live/frozen tensor sets differ only by item 1). The
   CUDA caching allocator does not split a large-pool block when the remainder is ≤ 1 MiB, and counts the whole block
   as allocated. Live `up_sweep` frees its odd-sized `[h, S, S]` products just before allocating the next
   bucket-shaped level; at b512 the `[4, B, B]` level (4 194 304 B) fits the freed `[8, S, S]` product (5 120 000 B):
   remainder 925 696 B (0.883 MiB) ≤ 1 MiB, not split, and that level is resident through the draw's peak.
   0.831 + 0.883 = 1.714 MiB, the measured 1.7. The frozen path's products and levels are equal power-of-two sizes,
   so it fits exactly. Removing the slack itself means changing the order of the sweep's allocations, which moves
   the golden op digest (`perstep_golden_9c9c508.pt` pins the op sequence; L9 says it must stay bit-identical), and
   allocating the levels first raises the sweep's own transient (≈ +60 MiB at b512). So it is not removed. It is
   covered by item 3 instead. Each resident block's slack is < 1 MiB.

Change (`cd/draw.py`; same ops in the same order, so values and op digests are unchanged; no host sync):
- `_gumbel_argmax_pair_live(pair, S, B, generator)`: the live boundary-pair Gumbel-max moved, op for op, into its own
  function, so `u` and `g` die on return (removes item 1's `[S²]` pair; what stays is `pair`, S²·4 < the frozen B²·4).
- Token step: `e = torch.exp(x - m); del x; w = torch.where(allowed, e, torch.zeros_like(e)); del e`. Before, it was
  one expression with `x` alive through `zeros_like` and `where`. `x` is dead once `exp(x − m)` exists, so one `[L, V]`
  fp32 tensor (256 MiB) fewer is alive at the draw's peak. `zeros_like(e)` = `zeros_like(x)` (same shape, dtype,
  device, contiguous). That makes live ≤ frozen with a margin of ≈ 256 MiB, which no allocator slack (< 1 MiB per
