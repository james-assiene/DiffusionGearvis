## Goal
Measure what per-step constrained decoding costs on the engine, gate it with B13 (T-0062 decision 8) under a metric that
can be observed, prove the per-step arms make no host sync on CUDA, and run T-0070's runner against the real engine for
the first time (dev cuts only). Per D-H1 a B13 FAIL is recorded, not hidden, and does not stop T-0071b.

## Acceptance criteria
Criteria 1–6 of `docs/tasks/T-0071.md`, verbatim in meaning:
1. Sync rows (a1): ≥ 12 warm-up then ≥ 50 calls under sync-debug "error" per per-step arm (`perstep_mf`, `perstep_mar`,
   `perstep_mar` + SC) at buckets 64 and 128, commits and a release included; 0 raises. A raise blocks a2 and becomes its
   own `cd/**` fix task.
2. Microbench (a1): per-component per-step cost and peak added memory, buckets 64/128/256/512; reported, not gated.
3. B13 (a2): ≤ 10 % at bucket 64 and ≤ 15 % at bucket ≤ 128; 30 rotated rounds A/B/A′ (+ D reported); identical
   `astra_tap: true` xargs on A, A′ and B; step time = (wall − F̂)/Σsteps, verdict at F̂ and at F̂ = 0, disagreement →
   `not_resolvable`; xargs exposure stated with evidence before the gate is read.
4. Report-only strata at buckets 256 and 512 (n = 5 rounds).
5. `runner.run --limit 10` on every arm and both tasks, dev cuts, exit 0, zero `join_error`.
6. The two B13 rows in `local_astra/bench/thresholds.py`; no other row changes; the verdict recorded beside them in this file.

## Rulings (orchestrator, 2026-10-03, from the test-author's report at f01488c)
- **T1 — the xargs adversarial, restated.** F̂ is fitted on A and A′ only, so a per-request cost carried by B alone is not
  subtracted; it is spread over B's Σsteps. The row pins the one consistent form: a fixed cost of 4 % of an A request's
  wall on B only reads as ≈ +0.6 % per step (not +4 %). The xargs exposure itself is measured by the D arm (criterion 3).
- **T2 — D's place.** D's position in a round rotates through all four slots (round r puts D at slot r mod 4 of the
  rotated A/B/A′ order); D is informational, the gated A/B/A′ rotation is the one pinned by the tests.
- **T3 — Σsteps vs records.** Whether a commit frame's `step` equals the CD record's `steps` exactly is established by the
  implementer from the code (T-0069 O6: a commit frame's step is the pre-reset step) and stated in the implementation log;
  a mismatch is a finding, not a tolerance.
- **T4 — the sync rows' knobs.** CL 256 and the always-confident test configuration (bound 1.0) so commits happen within
  50 calls; the rows test syncs, not calibration.
- **T5 — formatter strictness** (40-hex commit, `[repo@]sha256:<64 hex>` digest, `ValueError`) is accepted as the ruling.

## Implementation log (implementer, 2026-10-03, branch `T-0071a-cd-cost-impl`)
- **API (tests at f01488c, recorded here as the docstrings ask).** `local_astra/bench/b13_steps.py`: `sum_steps`,
  `fit_fixed_cost`, `rotation`, `pair_by_round`, `RequestTiming`, `evaluate_steps(rows, *, threshold_pct, fixed=None)`
  → `B13Steps(verdict, fixed, at_fit, at_zero)`, plus `per_step_times`. The one addition beyond the tests is the
  keyword `fixed`: criterion 3 fits F̂ "over every A and A′ request of the run", and the driver evaluates each gated
  stratum separately, so it fits once over both gated strata and hands F̂ in. Without `fixed` the fit is on the rows
  given (what the tests pin). `scripts/gpu/cd_microbench.py::format_report(rows, *, container_digest, commit, regime)`
  per ruling T5 (also refuses a multi-line regime).
- **Ruling T3, from the code: exact equality is expected.** The tap's commit frame carries `pre_step`, a clone of
  `states.step` taken in the tap's plan before the call (`tap.py`, `_Plan.pre_step`); CD's record carries
  `steps=step0`, a clone of `st.step[s]` taken in `_Job.pre` before the stock call (`cd/sampler.py`, header slot 1,
  read back in `_read`). The tap wraps CD, nothing writes `step` between the two clones, and stock resets it only
  inside the stock call, so both are the slot's step at entry of the commit call. `make_record` clamps with
  `max(0, steps)`, a no-op on that value. The one record with no commit frame is `_maybe_final_error`'s (a request
  removed before its EOS commit, `steps=0`); the driver counts a request with an error record as a problem anyway. The
  a2 driver compares frame `step` with record `steps` per `canvas_idx` for every B and E request; a mismatch is listed
  under PROBLEMS and makes the run exit 1.
- **a1 (container, no engine).** Two parts, one `/launch`: criterion 1 is the test-author's wrapper
  (`tests/contract/test_vllm_cd_perstep_sync_gpu.py`, 7 passes pinned); criterion 2 is `scripts/gpu/cd_microbench.py`,
  whose host side runs one `docker run --rm --gpus all --network none` the way T-0072's probe was launched (repo `:ro`
  at `/repo`, `PYTHONPATH=/repo:/repo/plugin/astra_vllm_plugin`, digest and commit passed in) with the payloads of four
  real dev-cut automata mounted at `/cdpayloads`: b64 Sudoku `dev:sudoku4_0` (|S| 32), b128 BFCL `live_simple_133-86-0`
  (91), b256 `live_simple_130-84-0` (205), b512 `live_simple_165-98-0` (400) — the first dev record of each bucket
  (CPU check from the compile cache: Sudoku dev 100/100 at 64; BFCL dev 35/32/32/1 at 64/128/256/512). The container
  side reuses the T-0072 probe's `_timed` (and its `measure`, reported as arm `t0072_probe`). Rows: `whole_call` per
  arm (end_projection = class_max + MAP + δ*; per-step arms = `steps.prepare` + δ*) with peak added memory; components
  class_mass, class_max, emission (log_transfer + up_sweep), draw, map, delta_star, marginals_full, marginals_pass1
  (`_down_sweep`), hq (the H(q) ops replayed on q), sc_matmul (`steps._soft`), and marginals_pass2_derived = full −
  pass 1 − H(q) (derived, not timed: pass 2 is not separable without copying `constrained_marginals`). n 200 after 20
  unless a row would exceed 60 s, then n shrinks (≥ 20) and the row says so. SC's peak at 512 is flagged against
  4.7 − 1 GiB. Evidence `logs/t0071a-microbench-<sha>/`.
- **a2 (engine).** `scripts/locked/t0071a_b13.sh` (t0069 pattern) → `scripts/gpu/cd_b13.py`. Warm-up per O7, then
  b64 (Sudoku dev 0) and b128 (BFCL `live_simple_133-86-0`): 2 warm-up rounds + 30 rounds, `rotation` with D at slot
  `r % 4` (T2); then b256/b512: 1 + 5 rounds of A, perstep_mar, A′ and end_projection (E) at slot `r % 4`. Stock knobs
  0.1/0.005 sent explicitly on B. Σsteps from commit frames, commit count = ceil(completion_tokens/256), release line
  with `commit_overrun == 0`, B/E records joined by tag and cross-checked (ids and T3). F̂ fitted once over every A and
  A′ of the gated strata; each stratum's own F̂ is printed as a sensitivity line, never the verdict. A round with a
  problem in A, B or A′ is dropped and named (n then < 30; E10 needs ≥ 20 to pass). The xargs exposure (D vs A per step
  at F̂ and at 0, with the A/A′ control) is printed before the gate. The report is written before criterion 5, then

## Rulings after review round 1 (orchestrator, 2026-10-03; reviewers A and B at 680ad8e)
Both reviewers: the expected ≈ +290 % fails under any of the variants below; these rulings only make a PASS harder to
reach and never move a limit (decision 8 stands).
- **R1 — F̂ uncertainty (B's H-1).** Each gated stratum's verdict is computed at F̂, at F̂ = 0 and at F̂⁺ = F̂ + 2·SE(F̂)
  (OLS standard error of the intercept). **PASS** only if all three pass; **FAIL** if F̂ and F̂ = 0 both fail; otherwise
  `not_resolvable`. (Simulation by B: a point F̂ passed a true +10 % in 13–19 % of runs; requiring F̂⁺ brings it ≤ 0.2 %.)
- **R2 — per-stratum F̂ (B's H-2, A's H-a).** F̂ and SE(F̂) are fitted per gated stratum on that stratum's A and A′ only.
  If the stratum's A/A′ step counts are too uniform to identify F̂, SE(F̂) is large and R1 yields `not_resolvable` —
  that is the honest result, never a pooled substitute. The pooled fit (all gated A/A′) is reported as a sensitivity line
  and in `verdict.json`, not used for the verdict.
- **R3 — pure driver logic (A's I3).** `schedule`, `check_rows`, `evaluate_b13` (and R1/R2) move out of the gated script
  into `local_astra/bench/b13_run.py` (pure, mypy strict, tested); the driver only calls it. Owned files amended.
- **R4 — robustness (A's I1, I2, I4, I5, I6).** The microbench probes `docker info` alone, runs the job once with a named
  container, kills it on timeout, records exit 1, never retries. A crash after the gated strata still evaluates and records
  the strata that completed (the crash is named). A report-only stratum that fails to build is a run problem. Criterion 5's
  `runner.run` calls pass explicit `budget_s` / `request_timeout_s` (≈ 1800 s / 600 s). `verdict.json` carries the
  pooled-F̂ sensitivity verdict.
- **R5 — reporting (A's H-c, microbench labels; B's binds note).** Report the automaton payload size per stratum (B carries
  it, A/A′ do not); flag a negative `marginals_pass2_derived`; label `whole_call` as `steps.prepare` + δ* only. The CUDA
  sync module's wording says binds cover `ms.add_request` only — CD's admission (`sampler.add_request`, one host sync by
  design) runs relaxed — and H1 states that this admission sync lands in B's per-request cost.
- **R6 — a1 as one launch.** `scripts/locked/t0071a_a1.sh`: refuse a dirty tree; run the sync-row contract module, tee, take
  its exit code; run `cd_microbench.py` only if it is 0; echo both codes. Log paths use the literal short sha.
- **R7 — test-author's open choices, confirmed (a71bac8).** `check_rows` takes the engine log as text; `RowCheck.steps` is
  returned, not written into rows; a dropped round is **not** a run problem by itself (it is named, n falls, and E10's
  n ≥ 20 makes the gate `not_resolvable` if too few remain) — but the defect that caused the drop (a missing release
  line, a T3 mismatch, a short commit count) **is** a run problem and makes the exit 1, as `test_b13_run.py` pins; report-only strata are not gated; `run_container` returns
  rc 1 on timeout and the host maps a non-zero rc to exit 1.
