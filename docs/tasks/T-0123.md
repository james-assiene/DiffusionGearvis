## Goal

H-T111a-1 kept the loop off until the T-0115 probe was read. The probe read `ready` on every pre-registered bar, and the human has turned the loop on. After this task, whenever a session's resolved tools setting is `dry_run`, the tool-result loop runs by default with `max_tool_steps` 8. `--no-tool-loop` or a profile's `tool_loop = false` opts out. With tools off (the default) the loop setting is inert and startup is byte-identical to `68d5566`, except for the one refusal text in criterion 4(d). An *explicit* request for the loop with tools off (`--tool-loop`, or `tool_loop = true` in the profile) is still refused (H-T114-2). Only `config.py`, `cli.py`, docs and tests change.

2. **The resolution rule (one function, the single source for `build_session`, the startup refusal and the `--dry-run` line).** Let `tools` be the resolved tools mode (`--tools` over `Profile.tools`, H-A4); `req` be `--tool-loop`/`--no-tool-loop` when given, else `Profile.tool_loop`; `steps` be `--max-tool-steps` when given, else `Profile.max_tool_steps`. Then: tools `dry_run` → loop = `req` if not `None`, else **True**; tools `off` → loop = **False**, and if `req is True` startup is **refused** (criterion 4); `max_tool_steps` = `steps`; `build_session` passes `TurnPolicy(thinking=…, tool_loop=loop, max_tool_steps=steps)`.
