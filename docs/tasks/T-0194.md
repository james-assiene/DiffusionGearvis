## Goal

A `type_at` into Amazon's search box in web mode was refused with `FOCUS_UNKNOWN_REASON` ("could not check the field before typing; nothing was typed") while the page was still loading. The same call worked yesterday in 515 ms.

Confirmed in source at 611068bb:
- `_dispatch_guarded` (executor.py ~1131) clicks, then `_focused_secret` (~1105) makes one `driver.focused_field()` read under `asyncio.timeout(FOCUS_TIMEOUT_S)`, `FOCUS_TIMEOUT_S = 0.5` (executor.py 227).
- `PlaywrightDriver.focused_field` (runtime.py 544) is a chain of `frame.evaluate(_FOCUSED_JS)`, deliberately unbounded; on a page whose main thread is busy loading it waits behind that work.
- Six cases make the read "unknown": no `focused_field` method, timeout, exception, `None`, non-mapping, unreadable element (`_focus_readable` false). Web mode fails closed on all six; `resolved` does not say which.
- The 682 ms proposal→refusal fits a timeout.
- **Found while planning:** outside web mode an unknown read types at the caret, so on a slow loopback page a 0.5 s timeout lets text land in a password field (criterion 9 reproduces it).

After this task: the read gets 2 s; a timeout or exception is retried once; every other case fails closed as today; a web-mode `FOCUS_UNKNOWN` refusal records which case in the non-model-facing `resolved`. What the model sees does not change; the secret-field refusal is not weakened.

## Acceptance criteria

1. **Budget.** `executor.FOCUS_TIMEOUT_S == 2.0` and `2 * FOCUS_TIMEOUT_S <= ACTION_TIMEOUT_S / 2` (4.0 ≤ 4.0 at `ACTION_TIMEOUT_S = 8.0`). Spec change to T-0160 B-3 (b) (pinned 0.5 s); the `test_computer_web_executor.py:194` pin moves with it.
2. **Retry once on a timeout or a raise.** When the first `focused_field()` read times out or raises an `Exception`, the executor reads once more with the same bound, with no other driver call in between (no second click, key or `settle`). The second answer is judged exactly as a first answer is today. On a driver whose first read hangs/raises and whose second returns `{"tag": "input", "type": "text"}`, a web-mode `type_at` is `executed`: click, `focused_field` ×2, T-0189 select-all (`COMBOS["Ctrl+A"]`), text, Enter; `resolved["replaced"] is True`.
3. **The secret-field refusal is never weakened (negative).** First read hangs/raises, second answers a password field or a card field (`autocomplete: cc-number`) → `failed` with `SECRET_FIELD_REASON`, `resolved["secret_field"]` `"password"`/`"card"`, `typed == 0`, no `type_text`/`key_down`/`key_up` after the click. Same on the overview-frame path (T-0151, T-0160 B-3 (f)).
4. **Still fails closed (negative).** In web mode, timeout/timeout, raise/raise, timeout/raise and raise/timeout → `failed` with `FOCUS_UNKNOWN_REASON`, nothing typed, frame re-captured as `assert_guard_failed` checks today; the call ends within `2 * FOCUS_TIMEOUT_S + 1.5 s` (constant monkeypatched small). `None`, non-mapping, unreadable element and a driver without `focused_field` are **not** retried (one read, or none for the missing method), outcome as at BASE.
5. **One read on the success path (negative).** When the first read answers, exactly one `focused_field` call per `type_at`; dispatch sequence, `action` and `resolved` byte-identical to BASE (`test_t0189_type_replaces.py::test_one_focus_read_and_replace_again` and the `set(out.resolved)` pins in `test_t0174_navigated_executor.py` stay green unchanged).
6. **The failure kind is logged, not shown to the model.** A web-mode `FOCUS_UNKNOWN` outcome's `resolved` gains exactly one key `focus_check`, one literal of `{"missing", "timeout", "error", "none", "not_mapping", "unreadable"}`, describing the **last** read. Never the exception message, page text, a URL or an attribute value. No other outcome gains it. `out.action` and `out.reason` byte-identical to BASE.
7. **Outside web mode a failed read still types as BASE (negative).** `web=False`, `focused_field` hangs/raises on both tries → types at the caret as BASE (`executed`, BASE's action, no `Control`, `replaced`, `typed`, `secret_field`). The retry applies: read count 2.
8. **Cancellation is not retried (negative).** A `CancelledError` during either read propagates; no second read, nothing typed.
9. **Real browser reproduction.** Headless Chromium, loopback fixture: a password field whose `mouseup` schedules a ~1.0 s main-thread busy-wait. A default (non-web) `BrowserToolExecutor` `type_at` into it is `failed` with `SECRET_FIELD_REASON` and the field keeps its old value (at BASE the text lands in it). A partner row on a plain text input with the same handler is `executed` with the text replaced.
10. **Docs.** `docs/02-architecture.md` gains a "Spec delta (T-0194)" paragraph after the T-0160 delta: the 2 s bound, the single retry on timeout/exception, `resolved["focus_check"]`, no retry on definite answers, and the residual risk below.

## Implementation notes

- Change only `_focused_secret` and the `FOCUS_UNKNOWN` branch of `_dispatch_guarded`; not `runtime.focused_field` or `_FOCUSED_JS`.
- Read `FOCUS_TIMEOUT_S` at call time.
- `_focused_secret` must tell `_dispatch_guarded` which case happened without changing the `None`/`"password"`/`"card"` contract or T-0189's `attrs` return.
- `except Exception` excludes `CancelledError`; keep it. No `BaseException`, no `asyncio.shield`.
- `focus_check` is a fixed literal; `resolved` is logged and sent to the HUD (T-0160 B-6). `session._card_arguments` matches on `reason` and must keep masking text.
- **Residual risk (state in docs/02):** on the success path a slow page can spend up to 4 s in the read; settle and capture follow inside the same 8 s `ACTION_TIMEOUT_S`. A call hitting the action timeout after its keys were sent reports `failed` although it typed — a shape that already exists at BASE. Do not raise `ACTION_TIMEOUT_S` here.
- Nothing under `tests/fakes/` changes; nothing in `session.py`, the machine, `protocol.py` or the HUD.
