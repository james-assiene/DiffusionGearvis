## Goal
Today J2 gates each tools-on case at hit / query of pass 1's `/metrics` delta over the whole final request, suffix included (the
`[screen]` note, recollections, the question). A memory-hit turn fails by design: `flight_booking_with_memory` hit 1408 of 1599 = 0.881
although its prefix was hit in full. B11 (`docs/03-test-plan.md:99`) divides by the final request's **prefix tokens** — those the turn's
own anticipatory prefill covered ("only the last partial block may miss").

After this task the harness records per case the prefill's own query and hit tokens (a `/metrics` delta around the prefill) and the
engine's token ids for the prefill prompt and pass 1's prompt (`/tokenize`, chat form). `build_report` derives the shared prefix S
(longest common prefix of the two id lists) and the hit inside it, Hs = min(H, S). The gate becomes B11 per case: Hs ≥ ⌊S/32⌋·32 and
Hs/S ≥ 0.9. The whole-request J2 number stays in the report, not gated. Hits beyond S come from other requests' blocks (finding 2): the
cap excludes them and the report shows them separately. Nothing under `local_astra/` changes. The 4b0bd92 run is not re-scored.

## Acceptance criteria
All rows run `build_report(run_dir)` / `gates(report)` on hand-built run directories, or `main` against the mock engine. Notation for one
(case, arm): P = the prefill's `/metrics` query delta, Hp = its hit delta; Q, H = pass 1's query and hit deltas (today's J2 numbers);
S = LCP(prefill ids, generate ids); Hs = min(H, S); A = 32.

1. **What the harness records.** For every (case, arm), `scripts/gpu/t0093_toolcall_live.py`:
   - (a) writes P and Hp to the manifest case as `prefill_query_tokens` / `prefill_hit_tokens`; the delta runs from the last reading of
     the pre-case idle check (m0) to pass 1's existing post-wait reading (m1), so the timed path gets no extra `/metrics` read;
   - (b) records `prefills_before_pass1` (prefills started before pass 1's generate);
   - (c) after `session.aclose()` and outside every timed span, POSTs `/tokenize` at the server root in chat form, once for the last
     prefill's prompt and once for pass 1's prompt. The body comes from `VllmClient.request_body(prompt, …)` and keeps exactly `model`,
     `messages`, `tools` (when present), `chat_template_kwargs`, `add_generation_prompt` / `continue_final_message` as that body has
     them, and `add_special_tokens: false`;
   - (d) appends one line per (case, arm) to a new sidecar `prefix_ids.jsonl`: `case_id`, `arm`, `session_id`, `prefill_request_id`,
     `generate_request_id`, `prefill_ids`, `generate_ids`;
   - (e) writes `regime.prefix_rule = "H-T96"`, `regime.prefix_block_tokens = 32` and `regime.cache_config_block_size` (the `block_size`
     label of `vllm:cache_config_info`, reported only) to the manifest regime.
   Loopback only, through the existing `_NoRedirect` opener. (B11; J0 amended, ruling M1)
2. **S is derived by `build_report`, not trusted from the harness**: the longest common prefix of the sidecar's two id lists.
3. **The gate** (`gates()["prefix_hit_on"]`, key unchanged, J0) holds iff there is at least one tools-on case and every tools-on case:
   has a verified measurement (criterion 5); S > 0; Hs ≥ ⌊S/A⌋·A; `Fraction(Hs, S) ≥ 9/10`. With A = 32, "only the last partial block may
   miss" means the miss S − Hs is at most S mod 32; on a block-aligned S nothing may miss. (B11; H-T96)
4. **Cross-case reuse is capped, not reset.** Hs = min(H, S). H − Hs is reported per case as `hit_beyond_prefix`, and Hp/P as
   `prefill_prewarmed`. Neither enters the gate. No cache reset, no baseline subtraction. (H-T96; ruling M3)
5. **Verification voids** (`integrity:`, either arm; the run cannot pass on unverified data, as J14/J19). Each adds one void reason naming
   the case, arm and both numbers, and the case's B11 row reads "unread":
   - (a) `len(prefill_ids) != P`; (b) `len(generate_ids) != Q`; (c) `prefills_before_pass1 != 1`;
   - (d) the image digest list in the prefill's `llm.request` record differs from the generate's for the shared messages;
   - (e) a nonzero H or Hp anywhere in the run that is not a multiple of 32 ("cache granularity is not the registered 32");
   - (f) a missing or unparsable sidecar line for a case.
6. **Fail fast.** If case 0 (order 0) fails 5(a), 5(b) or 5(f), `main` stops after that case with exit 1 and writes a void report.
7. **Whole-request number kept, not gated.** `report["prefix_hit"]` (pooled ΣH/ΣQ) and `report["prefix_hit_cases"]` keep today's keys,
   values and definition; render_markdown labels them "whole request (J2), reported, not gated since H-T96".
8. **New report keys:** `report["prefix_rule"]` (`"H-T96"` from the manifest, else `None`); `report["prefix_block_tokens"]`;
   `report["prefix_b11_cases"]` = `{on: [...], off: [...]}`, one row per case with `case_id, S, P, Hp, H, Q, hit_on_prefix,
   allowed_miss (S mod 32), missed, ratio, holds, hit_beyond_prefix, prefill_prewarmed, prefill_tail (P − S)`; `report["prefix_b11"]` =
   pooled ΣHs/ΣS per arm, reported (tools-off measured the same way, not gated).
9. **render_markdown.** The `prefix_hit_on` gate row reads "B11-prefix (H-T96): n tools-on case(s) failing or unread", with case_id, S,
   Hs and allowed miss for each. The latency/prefix section gets rows: B11-prefix pooled on/off; whole request (J2) pooled on/off; hit
   beyond the prefix, on/off totals; prefill pre-warmed share p50 on/off; prefill tail (P − S) min/max.
10. **Adversarial rows** (tools-on unless stated):
    - (a) memory-hit, prefix fully hit, passes: S 1360, P 1365, H 1344, Q 1599 → holds; whole-request 1344/1599 = 0.840 still reported;
    - (b) prefill missed half its prefix, fails: S 1360, H 672;
    - (c) partial last block allowed: S 1370 (= 42·32 + 26), H 1344 → holds;
    - (d) two blocks not allowed: S 1370, H 1312 → ratio 0.958 ≥ 0.9, yet fails;
    - (e) aligned prefix: S 1344 with H 1312 fails; with H 1344 holds;

## Implementation notes
- **Why this measurement (ruling M2).** (a) `usage.prompt_tokens` / `cached_tokens`: rejected — needs `stream_options` (a client change)
  and `--enable-prompt-tokens-details` (an engine flag, a regime change), and gives P, not S. (b) A `/metrics` delta around the prefill:
  gives P and Hp exactly at no cost, but P ≠ S — the prefill's last user message is empty, so its template tail is not in the generate's
  prompt. (c) `/tokenize`, chat form: renders through the same `preprocess_chat` as chat completions in vLLM 0.29
  (`entrypoints/serve/tokenize/serving.py:70-92`), so S is exact. Choice: (c) for S, checked by (b) (length equality with the engine's
  own query counts). Q is prompt length, not prompt + canvas (text-only Q 1423–1433 while H is 1408). The client's `tokenize(text)`
  (T-0088) is text-only; do not extend it (no `local_astra/` change).
- **Hits are contiguous from token 0**, so Hs = min(H, S) is exact. Anything above S came from earlier requests' blocks.
- **No reset (H-T96; ruling M3).** `/reset_prefix_cache` needs `VLLM_SERVER_DEV_MODE=1` at boot (a `scripts/locked/` and engine change
  that exposes dev routes), and would make every case cold, moving absolute latency further from production and from 4b0bd92. Inside S, a
  block warm before this case's prefill was still covered by that prefill (J12 `prefill_done`, P ≥ S); `prefill_prewarmed` reports it.
- **m0 (ruling M4)** is the last reading of `_wait_idle` that showed the engine idle; between m0 and m1 only the prefill may reach the
  engine (session start and the detokeniser load send nothing; the captioner never sends). Criteria 5(a) and 5(c) enforce this.
- **The own prefill** is the last prefill started before pass 1. At 4b0bd92 all 120 cases had exactly one, with equal image digests
  (planner check). A later prefill (after pass 1) is outside both deltas and ignored.
- **A = 32 (ruling M5)** is pre-registered from 4b0bd92: every hit was a multiple of 32 (gcd 32). vLLM aligns hybrid-group hits to the LCM
  of group block sizes, which the `block_size` label does not show; the label is reported, never used. If the true alignment is finer,
  5(e) voids the run. Do not derive A from the run.
- **The `/tokenize` calls** happen after close: no span or latency changes. Strip `stream`, `max_tokens`, `vllm_xargs`, `tool_choice`,
  `skip_special_tokens`, `return_token_ids`. `--exclude-tools-when-tool-choice-none` is off at boot, so tools render in both. Image data
  URLs go as built (CPU work in the API server, not an inference request; `.claude/rules/gpu-services.md`). Ids go only in the sidecar.
- `prompt_tokens: 0` in session logs stays (the client's documented "not reported").
- **The guard hook** blocks bash commands naming `scripts/gpu`: edit with the Edit tool, commit with `git commit -a`. Never run the
  harness through indirection; the smoke row calls `main` in-process.
- **No GPU run in this task.** The first run under H-T96 is its own `/launch` entry.
- **Risk.** If `/tokenize`'s chat rendering does not match a request's query count (e.g. image expansion differs), the run voids at case 0
  within about a minute of a GPU window; the plan is re-opened and no number is read.
