# T-0067 — `ConstrainedDiffusionSampler`: stock delegation, bit-identical unconstrained slots, request registry, end-projection arm, loud non-fatal failures, records

**Status:** done (merged at 66bfa72; status corrected 2026-10-23 from 'in progress', T-0147 audit: no implementation in flight) · earlier: in progress · **Blast radius:** high (decode loop; two reviewers) · **Branch:** `T-0067-cd-sampler` ·
**Depends on:** T-0064, T-0065, T-0066

## Goal
The plugin gains a wrapper around vLLM v0.29.0's `DiffusionSampler` and a model-state factory that composes with
T-0011's.
- A batch with no constrained decode slot is delegated untouched: zero torch ops and the inner result object returned.
- In a mixed batch, the unconstrained slots are bit-identical to a stock run.
- Constrained slots get per-slot state: the automaton on device, the state set A_k, the emitted count, max_tokens and
  knobs.
- The first arm is `end_projection` (the J0 analogue and the Sudoku control): stock trajectory and convergence, with
  the constrained MAP of the converging step committed in place of the argmax.
- Every failure is loud and non-fatal: the request ends early with an error record, the engine keeps serving, and the
  request never continues unconstrained.

## Acceptance criteria
Tier 1 is CPU, using the vendored v0.29.0 stock step. Tier 2 is the container (`-m gpu`, `/launch`, no engine boot).

**Tier 1**
1. **Composition.** `make_cd_model_state_cls(base).custom_sampler(s)` calls `super()`. It returns
   `(ConstrainedDiffusionSampler(inner), second)`, where `inner` and `second` are exactly the objects super returned
   (identity). If super returns `None`, it returns `None`; if super raises, the exception propagates unchanged. The CD
   code never constructs `DiffusionSampler`. This mirrors T-0011 criterion 1, so T-0011's
   `make_model_state_cls(make_cd_model_state_cls(DiffusionGemmaModelState), tap=…)` is valid.
2. **Transparency.** Attribute parity with the inner sampler (T-0011 criterion 2's probe list). No public attribute the
   inner lacks, in particular no `remove_request`.
3. **Unconstrained fast path (negative, "no overhead").** When no decode slot in the batch is constrained, `__call__`
   returns the inner `SamplerOutput` object itself, having issued **zero** torch operations outside the delegated
   inner call (counted by
   `TorchFunctionMode`/`TorchDispatchMode`) and zero host syncs. The decision uses host numpy only. A CPU microbench of
   the decision on a realistic batch stand-in shows p99 ≤ 20 µs.
4. **Mixed-batch bit-identity (negative).** Under a fixed global torch seed, a batch of {constrained, unconstrained,
   unconstrained} slots through the wrapper leaves every unconstrained slot's state rows and output rows bit-identical
   to the stock sampler run on the same batch with the constrained request's `astra_cd_*` keys removed, compared
   over the sampler calls in which both runs schedule the same set of requests (the stock `_compiled_sample_step` draws `torch.rand_like` over the whole `[num_decode, CL, V]` batch, so any change in the scheduled set shifts every slot's noise):
   - state rows: `canvas`, `argmax_canvas`, `step`, `is_encoder_phase`, `confident`, `self_conditioning_embeds`,
     `accepted_canvas_history`, `accepted_canvas_history_len`, `draft_tokens`
   - output rows: `sampled`, `num_sampled`, `num_rejected`

   The global RNG state after the call also equals the stock run's. The row holds for denoise, converging and commit
   steps, and for top-k/top-p set on an unconstrained slot.
5. **Registry and slot hygiene (adversarial).**
   - Options are parsed with T-0064's parser in `add_request`.
   - Both `add_request` orderings are tolerated (model state vs sampler; T-0011 criterion 9).
   - State is reset in the model state's `remove_request`.
   - Freed slots are reused last-in first-out. A slot freed and re-taken by an unconstrained request is unconstrained;
     re-taken by another constrained request, it never sees the previous occupant's automaton, A_k or emitted count.
6. **`end_projection` semantics.** For a constrained slot, the trajectory, history, acceptance and convergence are the
   stock ones. On the step where stock convergence fires (including the 48-step cap), `argmax_canvas[slot]` **and**
   `canvas[slot]` are replaced with the constrained MAP of that step's logits, so the commit pass writes the MAP into
   the KV. `draft_tokens[slot, :CL]` is re-synced. The committed canvas equals the MAP. At commit, A_{k+1} = δ*(A_k,
   committed) and emitted += valid length.
7. **Loud, non-fatal failures.** Classes:
   - T-0064 `CdRequestError`
   - unsupported combinations (logprobs requested; top_k/top_p set on a constrained request)
   - infeasible budget (T-0065 criterion 6)
   - log Z = −inf at a step
   - empty δ\*

   For each class:
   - no exception escapes `add_request` or `__call__`
   - the request ends within ≤ 2 sampler calls by committing a canvas whose first committed id is EOS (1)
   - one `ASTRA_CD` record with `error=<code>` is logged, and a per-process counter increments
   - the other slots' rows are bit-identical to the same batch with the failing request's `astra_cd_*` keys removed,
     over the calls in which both runs schedule the same set of requests (the stock `_compiled_sample_step` draws `torch.rand_like` over the whole `[num_decode, CL, V]` batch, so any change in the scheduled set shifts every slot's noise); the failing request's early end is the
     first call where the scheduled sets differ
   - the request never continues unconstrained

   **Adversarial:** log Z = −inf injected at step 7 in a mixed batch.
8. **Records.** One `ASTRA_CD <json>` line per committed canvas per constrained request, validated by T-0064's
   `CdCanvasRecord` (`contracts/cd.py`, schema fixed there; this task only emits it). Fields filled here:
   - `record_tag` (echoed from the request), `arm`, `canvas_idx`, `committed_ids` (valid length), `state_set_after`, `in_final`, `steps`,
     `bucket`, `stop_pos`, `error`
   - for `end_projection` also `shadow_argmax_ids` (what stock would have committed), `argmax_in_language` and
     `map_equals_argmax`

   A record may lag its commit by ≤ 2 sampler calls.
9. **Host-sync budget.** On a batch containing constrained slots, the sampler thread makes **no** synchronizing call
   (spy tensors, 200 steps, including commit steps). Device values reach the records through pre-allocated pinned
   buffers and events read at least one call later.
10. **Imports and packaging.** The CD modules import stdlib, numpy and torch; `vllm` only lazily or under
    `TYPE_CHECKING`; never `local_astra` (AST). `make plugin-wheel` includes every `cd/` module (the T-0011 criterion
    10 mechanism).

**Tier 2 (container, `-m gpu`, `/launch`, no engine)**

11. **Coupling pinned to v0.29.0.** A probe reports, and the host asserts:
    - `_compiled_sample_step`'s parameter names, and the sha256 of its source, equal the vendored fixture's
    - every `DiffusionSampler`/`DiffusionGemmaRequestStates`/`SamplerOutput` attribute CD reads exists
    - `custom_sampler` returns a 2-tuple

    A version bump reads as "the CD coupling drifted from vLLM X".
12. **CUDA repeats.**
    - Criterion 4 with the real compiled step on the card.

      `torch.set_float32_matmul_precision("high")` set globally** (the TF32 landmine).
    - The peak added device memory of an `end_projection` convergence step at CL 256, bucket ≤ 256 is ≤ 1.5 GiB.

## Implementation notes
- **From the T-0065 review:** per-step cost includes T-0065's second (gauged) pass (T-0062 decision 10); the
  memory and latency figures here are measured with it on.
- **From the T-0066 review:** each `joint_draw` allocates [L, V] temporaries of ~64 MB (bool) + 2×256 MB (fp32) on
  top of the logits, and `constrained_map` a similar set: ~0.6–0.8 GB transient per call per constrained slot at
  L = 256, inside `gpu_memory_utilization` 0.86. `joint_draw` recomputes `class_log_weights(logits)`, which T-0065's
  leaf build already computed; pass it through when wiring the per-step path. ~0.7 s per production draw on CPU.
- **From the T-0065 re-review:** after the compensated-arithmetic fix, `constrained_marginals` takes ~2.05 s on CPU
  (bucket 128, L=256, V=262144, T0.4, 16 threads, torch 2.13.0+cpu, n=1 warm), about 3× pass-1 `up_sweep`.
  The TwoSum/compensated paths are silently removed by any reassociating backend (`torch.compile`/Inductor with
  fast-math or `unsafe_math`); tier 2 runs T-0065's direct compensated-arithmetic rows on whatever path is served
  (eager or compiled, CUDA). FMA contraction is harmless.
- Stock `__call__` does a lot on the host before the compiled step: prefill finishing, top-k/p, canvas padding for
  `valid_canvas_len`, tiling by free memory, logprob stashing. One design that satisfies criterion 4: run the inner
  sampler on the **whole** batch unchanged, then recompute the constrained slots from a snapshot of their pre-call rows
  using a dedicated generator. Rewrite every field stock wrote for them, including `sc_embeds`, whose `sc_keep`
  depends on convergence, and `draft_tokens`. The implementer may do better if 3, 4 and 9 still hold.
- On commit steps stock already emits `argmax_canvas`, which CD set at convergence. `num_sampled`/`num_rejected` depend
  only on the entry phase and so match stock.
- The commit pass writes the committed canvas to the KV because stock sets `canvas ← argmax_canvas` for newly
  converged slots. CD must preserve that coupling, or the KV holds tokens nobody emitted (CLAUDE.md: never voice
  uncommitted text).
- Logprobs on a constrained request are refused in v1: stock would report logprobs of the unconstrained argmax.
- **Landmine:** an exception inside the engine loop kills EngineCore (see T-0015's history). Loud means a record plus
  an early EOS commit, never a raise.
- The emitted count and R are kept on device to respect criterion 9. `max_tokens` arrives in `add_request`.

- S9. (review A+B, 2026-09-30; resolves S8's open question) **Catch-all, yes** (decision 7). Wrap each constrained

  `pre()` marks that request `internal` and takes the non-live forced-EOS branch for that job only (nothing written

## Implementation notes (implementer, 2026-09-30)
- **Shape.** The inner stock sampler runs on the whole, unchanged batch. For each constrained decode slot the
  wrapper snapshots `is_encoder_phase`, `step` and `argmax_canvas` before the inner call. It then computes the
  constrained MAP of the call's own logits (pristine, before stock's in-place top-k/p) and δ*(A_k, MAP).
  After the inner call it selects on the device with `converged = is_encoder_phase & ~entry`. The host never
  knows when a slot converges, so the MAP and δ* run on **every** denoise call of a constrained slot. That is
  the end_projection per-step cost; T-0071 measures it. Skipping the MAP when the lagged reports prove that a
  call cannot converge is a possible later optimisation, not done here.
- **δ\* at convergence, applied at commit.** δ* is computed on the MAP canvas on the converging call. If it is
  empty, the canvas about to be committed is already EOS (the S4 trigger is the commit call, and the row expects
  the EOS canvas on that call). At the commit, A_{k+1} and `emitted += valid` are applied on the device.
- **L_eff is a host int (T-0066 API); emitted lives on the device.** The host holds the emitted count from the
  reports it has read. For unread calls it enumerates the possible counts, computes one MAP per distinct L_eff
  and selects on the device. `R_after` always comes from the device count. On CPU the reports of call t−1 are
  read at call t, so exactly one MAP is computed. `headroom = valid` when the canvas is truncated (`valid < CL`,
  near `max_model_len`), else unbounded.
- **Loud failures.** Codes: T-0064 reasons, `unsupported_option` (logprobs, top_k/top_p, a per-step mode, or
  `entropy_bound`/`confidence_threshold` overrides, which would change the stock end_projection trajectory),
  `infeasible`, `z0` and `empty_delta`. A failing slot is forced after every call to `argmax_canvas = canvas =
  EOS` with `is_encoder_phase = True`. One error record is emitted: on the EOS commit, or at removal if the
  request never committed. A logprobs request's params reach the inner sampler with `logprobs=None`, so stock
  stashes nothing for it.
- **Records.** Each call packs an int64 report per constrained slot, copies it `non_blocking` into a pooled host
  buffer (pinned on CUDA, plus a `cuda.Event`) and reads it in order at a later call. The logger is
  `vllm.astra_cd`, so inside the engine it inherits vLLM's handler. `argmax_in_language` is derived through
  T-0066's projection identity (MAP[:L_eff] == stock argmax[:L_eff] and the MAP is non-empty), not through a
  second δ* replay.
- **Catch-all (S9, after review).** Each job's `pre()` and `post()` are wrapped separately; the inner stock
  call is not. A raise in `pre()` makes that job take the forced-EOS branch. A raise in `post()` reruns that
  branch, which rewrites `argmax_canvas`, `canvas`, `is_encoder_phase` and `draft_tokens`. `new_request`'s
  device build (`_tables_for`, `initial_infeasibility`, allocations) is guarded too. The code is `internal`,
  the traceback is logged once per request, and the error record bumps the counter.
- **Preemption (S10).** The sampler keeps a bounded set of CD request ids it has served (65 536). A re-added id,
  or a prefill longer than the prompt (`prefill_token_ids`, if the runner provides it), ends as `preempted`.
- **Flush on release (S11).** `_release` flushes the records whose events are complete. Non-record log lines
  use the prefix `astra_cd ` (S12).
- **Flush path (S14).** `_flush` pops each item's pending entry first, then reads it inside a per-item try; a
  raise calls `log_internal` (latches `internal`) and the guarded final-error path, and the loop continues.
  `event.query()` itself is unguarded (it only raises with a dead CUDA context).
