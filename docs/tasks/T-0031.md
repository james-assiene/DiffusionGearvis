# T-0031 — the fast suite runs in parallel: Stop-hook feedback under 60 s with no test moved out of it

**Status:** merged 2026-09-14 (implemented by the main session 514c883; review APPROVE — 22–26 s parallel vs 147 s serial on a box carrying 21 concurrent pytest processes, failure sets identical, eight mutations red)· **Blast radius:** medium (the Stop hook every agent turn pays, and
the dependency set; no product code, no test semantics) · **Depends on:** T-0019 (merged; the
classifier), T-0029 (merged; the guard's flag tables) · **Prerequisite P-T0031:** `uv.lock` is
edit-protected, so the orchestrator (main session) adds `pytest-xdist` to the `dev` extra and commits
`pyproject.toml` + `uv.lock` on the task branch before anything else runs.

## Goal

The fast suite (`tests/unit tests/contract -m "not gpu"`) has grown from ~6 s at the scaffold to
**134.9 s** measured today, over CLAUDE.md's two-minute rule, and the Stop hook
(`.claude/hooks/stop_fast_suite.sh`, timeout 280 s) runs it on **every** agent finish — so every agent
turn now pays more than two minutes of dead time and the 280 s timeout is one merge away from firing.
Measurement shows the cost is not algorithmic: the heaviest modules are *waiting*, not computing
(`test_audio_clock`: 18.44 s wall, 5.41 s CPU; `test_stt_client`: 9.41 s wall, 2.21 s CPU), and the
hook-sandbox modules are process-bound; the box has 32 cores and the serial run uses about one and a
half of them. This task makes the Stop-hook run parallel (`pytest-xdist`, fixed worker count,
file-level distribution), lowers the hook timeout to match the new scale, and writes the new budget
into the three places that state it (`CLAUDE.md` Commands block, `.claude/rules/tests.md`, `docs/09`).
**No test changes tier, no test is deselected, no threshold is raised**: every test that runs today
under the Stop hook still runs under the Stop hook, only ~4.5× faster. A prototype with 8 crude
file-level shards already produced 28.7 s wall with an identical failure set.

## Acceptance criteria

1. **The Stop hook's run is under 60 s.** `.claude/hooks/stop_fast_suite.sh` invokes the fast suite
   with a worker count and file-level distribution (`-n <N> --dist loadfile`, `4 ≤ N ≤ 12`, a fixed
   integer, not `auto`), and the measured wall of the hook's own pytest invocation on a clean tree is
   **≤ 60 s for each of 5 consecutive runs** and ≤ 45 s at the median. Baseline and regime in
   §Regime.
2. **Selection is unchanged.** The set of node ids the hook's command collects is **exactly equal**
   to the set the current command (`tests/unit tests/contract -q -m "not gpu"`) collects, compared
   as sets of ids from `--collect-only -q` on the same commit. No new marker, no `-m` change, no
   `--ignore`, no `deselect`.
3. **The result is unchanged.** Over 3 consecutive parallel runs and 1 serial run on the same
   commit, the sets of passed / failed / xfailed / skipped node ids are identical.
4. **The classifier still attributes failures.** `classify_failures.py` receives xdist-shaped output
   (`FAILED …` lines emitted in worker completion order, `[gw3]` markers present in the body) and
   produces the same `expected:` / `regression:` verdicts as on the serial fixture; a regression
   still exits 2, an in-progress-only failure set still exits 0 with the `expected:` block on stdout.
5. **A worker crash blocks, never passes.** If pytest exits non-zero with no parseable
   `FAILED`/`ERROR` line — an xdist worker crash (`node down`, `worker gw2 crashed`), a collection
   abort, or the `timeout` firing — the hook prints the tail and exits 2 (T-0019 ruling A14).
6. **The hook timeout matches the new scale.** `timeout` in `stop_fast_suite.sh` is **≤ 120 s**.
7. **The project default stays single-process.** `[tool.pytest.ini_options].addopts` in
   `pyproject.toml` contains **no** `-n`, `--dist` or xdist plugin activation; parallelism is only in
   the hook's and `make fast-parallel`'s explicit command lines. Reason: `scripts/check_pending.py`
   runs `pytest --collect-only` in a subprocess and each process writes `$ASTRA_PENDING_REPORT`
   from `pytest_collection_modifyitems`; under xdist every worker would overwrite it and the pending
   backlog would silently truncate. A test asserts the pending report is complete against an
   independent oracle.
8. **`pytest-xdist` is a declared dev dependency** with a lower bound in `pyproject.toml`'s `dev`
   extra, and `uv sync --all-extras` installs it.
9. **The three statements of the budget agree.** `CLAUDE.md`'s Commands block,
   `.claude/rules/tests.md` line 8 and `docs/09-agent-workflow.md` §3 quote the same commands and
   the same two numbers (the Stop-hook budget and the serial ceiling), and `.claude/rules/tests.md`
   no longer claims the fast suite is run with `-m "not slow"` when it is not. A docs-parity test
   enforces it.
10. **The verifier still runs the suite serially before merge.** `.claude/agents/verifier.md` names
    the serial command explicitly (`make fast`, no `-n`) as the pre-merge run and `docs/09` §2 says
    which run is canonical.
11. **Negative — no test file's behaviour, markers or assertions change.** The diff touches no test
    module except `tests/unit/test_stop_hook.py` (new assertions about the hook's command line), the
    new `tests/unit/test_suite_budget.py`, and `tests/conftest.py` (terminal-summary line only). No
    `@pytest.mark.slow`, `skip`, `xfail` or `max_examples` value anywhere in the repo is added,
    removed or lowered by this task.
12. **Negative — the mypy gate is untouched.** `stop_fast_suite.sh` still runs mypy after the suite,
    still blocks on its failure, and its invocation is byte-identical.
13. **Negative — no new network or GPU dependency.** The parallel run makes no socket that the serial
    run does not, and no test acquires the GPU.

## Implementation notes

**Why parallelism and not the alternatives.** Measured on this commit:

| option | effect | verdict |
|---|---|---|
| (c) `pytest-xdist`, file-level | 134.9 s → 28.7 s measured with an 8-shard hand prototype, identical failure set | **taken** — every test keeps running on every Stop-hook run |
| (a) a `slow` tier excluded from the hook | removes ~76 s of audio/STT tests from the per-turn gate — the timing-sensitive modules most likely to regress — and collides with T-0030/T-0023's owned files | rejected; if ever needed, the rule must be mechanical (> 2 s wall) and `docs/09` + the verifier must name the command that runs the tier |
| (b) a Hypothesis `fast` profile via env | does not work as stated: every heavy property carries an explicit `@settings(max_examples=…)` that overrides a profile; the modules are sleep-bound, not example-bound | rejected; documented as the fallback if xdist proves flaky (a test-author change) |
| (d) raise the two-minute rule | the rule is not the problem: 134 s of wall on 1.5 cores of a 32-core box is | rejected |

**Regression risk, stated plainly.** Nothing leaves the selection (criteria 2 + 11). The risk is
**order- and load-sensitivity**: tests that pass alone on a quiet machine may fail or flake when eight
workers contend, and the audio modules assert against elapsed time. Mitigations: `--dist loadfile`
so a module's tests never interleave; a fixed modest `-n` (8 measured; the box hosts vLLM) rather
than `-n auto`; the 5-consecutive-runs evidence — if any run differs from serial, the worker count
comes down or the module is reported, **never** the assertion loosened. A flake found later goes
through `/triage`.

**Landmines.**

- `.claude/rules/tests.md` says the fast suite excludes `slow`; no invocation does. Fix the rule to
  describe reality — do not add `-m "not slow"` to the command.
- `stop_fast_suite.sh` parses `FAILED`/`ERROR` at line start only (T-0019). xdist keeps the `-rfE`
  summary lines unprefixed; confirm on real output.
- Hypothesis's example database under `.hypothesis/` is written by all workers; a cross-worker
  interaction is a plausible once-in-twenty flake — the 5-run evidence is where it shows. Do not set
  `derandomize` globally to hide it.
- `scripts/check_pending.py` and `scripts/bootstrap.sh` shell out to pytest; neither may gain `-n`.
  `make check` stays serial so the canonical number is the serial one.
- `guard_bash.sh` blocks test-silencing flags; `-n` is a worker count, but check the flag tables.
- The main session implements (as T-0016/T-0026/T-0029); reviewer and verifier stages unchanged.
