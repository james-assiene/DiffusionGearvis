## Goal
The served `AstraDiffusionGemma` builds its sampler as Tap(CD(stock)). With no `astra_cd_*` key nothing changes: the
tap still publishes and the engine takes the stock path. With CD keys, every arm runs end to end on the real engine
and spans canvases. A malformed or oversized request fails loudly and the engine keeps serving. The run also settles
the transport (decision 4: is the payload intact at the cap?) and whether v0.29.0 returns token ids (T-0070 E5).
**It makes no latency or accuracy claim.** It is a smoke test. Wall times are logged and labelled as not a
measurement.

**Tier 3 (booted engine, `/launch` 2; one boot, standard `services/vllm.sh`)**
4. **Arms end to end.** One Sudoku-dev and one BFCL-dev request run per arm: `end_projection`, `perstep_mf`,
   `perstep_mar`, `perstep_mar` + `self_conditioning=constrained`. Each one:
   - (a) has records that echo its `record_tag` and name its arm (proving xargs reach `extra_args`);
   - (b) has contiguous `canvas_idx` and a final record with `stop_pos` or `error`;
   - (c) is accepted by host replay (T-0070 `replay`, JSON whitespace), and replay agrees with `in_final`;
   - (d) has a tap release line with `commit_overrun == 0`;
   - (e) has commit frames equal in number to its records, each with `committed_tokens` = `committed_ids`.

   Every tap frame of the run validates (R10, R14/R15 step ranges; `accepted`/`entropy` None). `error` is null on all
   eight. The number of `preempted` records is reported (T-0067 S10).
5. **Loud, non-fatal (adversarial).** Request G (constrained, valid) starts first. When G's first tap `denoise` frame
   arrives, request X is sent: its payload is altered and its sha recomputed.
   - X returns empty content.
   - X has one record with `canvas_idx` 0, `committed_ids[0] == 1`, and `error` equal to the code that the host
     `parse_cd_xargs` predicts for the same xargs (`bad_encoding` or `structure`).
   - G completes, is replay-accepted, and has no error.
   - A next unconstrained request succeeds and `/health` is 200.
6. **Multi-canvas.** The grammar is a synthetic literal of 260–290 tokens; its minimum accepted length is > 256, so it
   is bucket 512 by construction. It runs with `max_tokens` 300 under `perstep_mar` and under `end_projection`. Each
   request closes exactly two canvases (records `canvas_idx` 0 and 1), is replay-accepted, and has `emitted ≤ 300`.
   A CUDA OOM or any `internal` code fails this criterion loudly; it is never retried silently.
7. **Transport at the cap (decision 4).** Size check before sha, sha before decode (`cd/xargs.py`).
   - **Near cap:** `astra_cd_automaton` is `cap − 512` ASCII chars with the correct sha, not a valid archive. Its record
     carries `error == "bad_encoding"`. That code is reachable only after the sha matched, so the string arrived
     intact.
   - **Over cap:** the same with `cap + 1` chars gives `payload_too_large`.
   - Host `parse_cd_xargs` gives the same codes for both. Both requests are built by hand (W4 exception, this row only).
   - An HTTP 4xx/413 on either is a **fail** and goes to the human (ruling O3).
8. *Negative, on the engine (T-0062 c4):*
   - `boot_config_lines(last_boot(log))` equals `logs/t0011-tier3-806da12/boot-reference.txt`, minus its `#` lines.
   - The harness refuses if `git diff 806da12..HEAD -- services/vllm.sh` is non-empty.
   - At concurrency 1, an unconstrained request writes no `ASTRA_CD ` and no `astra_cd ` line in its log window
     (closed by a flush request).
   - Its tap frames validate and its commit frames match `ceil(completion_tokens/256)`.
9. **Token ids and header rate (T-0070 E5, 8(f)).**
   - Both `backend=real` rows of `tests/cd/contract/test_eval_fake_server_contract.py` pass on this boot, pinning
     `choices[0].token_ids` under `return_token_ids`.
   - 20 unconstrained dev records (10 Sudoku, 10 BFCL; test cuts untouched): the first 8 ids are recorded,
     `ids[0] == 100` is checked, and the header-prefix rate is reported. Reported, not a gate.
   - For constrained requests, `token_ids` equals the concatenated `committed_ids` up to the first stop id; the run
     reports whether the stop id is included.

## Implementation notes
- **No fallback.** If the `cd` import fails in `get_model_state_cls`, the boot must fail. A Tap∘stock fallback would
  ignore `astra_cd_*` keys and serve those requests unconstrained, silently.
- Under composition the tap reads what CD wrote: the per-step canvas, the MAP in `argmax_canvas`, and the MAP history.
  That is the honest CD trajectory. Do not add H(q) to frames.
- **Join keys.** A tap `request_id` is the response `id` plus `-<8 hex>` (seen in 806da12's `requests.json`). CD records
  join on `record_tag`. At concurrency 2 (criterion 5), join by that prefix, never by time window.
- **Reuse, read-only:** `last_boot`, `boot_config_lines`, `parse_tap_release_lines` (T-0011 R12/R16); T-0070 `prompts`,
  `arms`, `records`, `replay`; `CdRequest.to_xargs()` everywhere except criterion 7.
- **Locked script** (pattern of `scripts/locked/t0011_tier3.sh`): refuses a dirty tree, bound ports
  8001/8002/8080/8081 and running containers; runs `make plugin-wheel`; boots `services/vllm.sh` directly (engine only;
  STT/TTS/conductor down, so toggling thinking costs no live prefix cache); waits for `/health`; runs the driver with
  `uv run --group cd`; stops the engine on exit and leaves no container. The `/launch` command echoes the exit code.
- **Tier-2 conventions (T-0011/T-0067):** `--network none`, repo `:ro`, image-only packages,
  `--noconftest -o addopts= -p no:cacheprovider`, `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`, fail-not-skip, `require_exact`
  pinned counts, a regime line per row, warm-up before sync-debug "error", the sync spy counting value reads on device
  tensors only, and harness snapshots outside strict contexts.
- **Memory.** CD transients (≈0.6–1.5 GiB per constrained slot) are outside vLLM's profile. Criterion 5 runs two
  constrained slots and criterion 6 uses bucket 512, not yet measured on the engine. Log free device memory after boot
  and at the end of the run. An S9-caught OOM shows up as `internal`, which is a fail (ruling O2).
- **For T-0071, not here (T-0011 R17):** `vllm_xargs` alone costs ~4 % end to end. Any CD-versus-unconstrained timing
  must send xargs on both arms and rotate the arm order.
