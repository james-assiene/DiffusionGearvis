## Goal

James's flow: the user shares a screen showing a picture of an item (a broken steam wand, a stove box, a chat message asking for something) and says what they want ("this broke, put the replacement in my cart"). Gearvis reads the item off the shared image, works in its own browser, and stops at checkout.

Already built (T-0177): a user-initiated Share selects "shared" (H-T177-1); step 1 carries the shared frame with `SHARED_LABEL_SCREEN`; after the first executed browser action the browser frame replaces it (H-T177-3); a click read off the shared image is refused with `SHARED_FRAME_REASON`.

Gaps this task closes or measures:
1. The chain from Share to the session's step-1 body is untested end to end (T-0177's status: "no test drives the HUD page against a real Session"). A1 adds that test.
2. The completion check never runs on a shared-start turn: T-0207 A2.1 requires `vision_source == "browser"` for the whole turn (H-T207-9). A2 arms it on the step's own current image instead; the model still never sees a shared and a browser image in one request.
3. No handoff scenario exists. B adds three loopback scenarios (H1–H3), each with an original shared image, a judge and lookalike traps, run through the real web-mode executor with a fake LLM.
4. Nobody has measured whether the model carries the item across the switch (after the swap the identity survives only in what it said or typed; thoughts are never carried). C measures success, the first action, shared-image refusals and identity carry on the GPU, with a typed control arm.

What does not change: one source per step; no typing into div/canvas; the checkout stop, submit stop and no-card/no-password rules; the turn machine and §4 invariants; the system prompt, live guidance and shared label text; `pages/scenarios/**` and `scenario_tasks.py`; no new network path.

## Implementation notes

- **One source, always.** Never keep the shared image beside a browser image, and never add a browser image to a request whose current image is shared. The check's fresh frame is a browser frame, so arming must read the step's own current image (T-0177's note: decide "browser frame" in one place).
- **A2 reads the identity before the stream.** `_check_armed` runs before the step's stream; confirm it can read the sent prompt's current-image identity there. If not, move only the shared clause to the fire point (Q-1).
- **The identity problem is measured, not fixed.** No text carry-over, captions or guidance sentence here; each is a model-facing change needing its own task and A/B (H-T208-4, H-T208-5).
- **The ingress path.** `BrowserFrameSource` may re-encode or keep the posted bytes. Assert equality against what the session stored for that frame, not the file on disk, and say which (Q-2).
- **Images are oracle-free.** The judge never reads the image; the identity text is drawn into the pixels only (pixel-first).
- **Brand text** appears only as drawn plain text, no logo (H-T205-4).
- **Hook rules.** The implementer never edits `tests/`; no heredocs into the repo; never export `GIT_DIR`/`GIT_WORK_TREE`.
