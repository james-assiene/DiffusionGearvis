## Goal
Mosaic (Dang & Ermon, https://github.com/MhDang/mosaic) turns on two changes by default for every request, saying they
bring vLLM's DiffusionGemma in line with the HF release: encode a committed canvas without the self-conditioning block
(`MOSAIC_COMMIT_RAW`) and anchor a denoising canvas's sliding window at the canvas start (`MOSAIC_ANCHOR_WINDOW`). We must
know whether our pinned stack (v0.29.0, NVFP4 rev 2ea8372, TRITON_ATTN, CL 256) diverges, which requests that touches, and
whether it changes outputs. The answer decides whether the HF behaviour should ever become our default. That would break
the plugin invariant that requests without `astra_cd_*` keys are bit-identical to stock (T-0067/T-0069), so it is a human
decision. Nothing here changes default serving behaviour.

**Planner's read-only pre-reads (to be reproduced by a, not results):** v0.29.0 runs the self-conditioning block on every
request with logits, including commit steps (`diffusion_gemma.py` L907–928, called L952–967; the sampler zeroes the signal
on commits L630–634, so only `post_norm` acts); HF's encoder path takes the raw scaled embeddings (`modeling_diffusion_gemma.py`
L901–945; the block is decoder-only, L1253–1264). vLLM centres the sliding window on each query
(`triton_attention_helpers.py` L204–226), unchanged at 1b3b88ec and on main 4ac0d0eac2 (2026-10-03); no upstream issue or PR.
W vs W − 1 is unsettled (JAX docstring `[context_end − W, context_end)` vs Mosaic's account of HF). Under T-0071's regime
(one canvas, thinking off, short prompts) exposure may be small; the product regime (thinking on, long context, multi-canvas)
is exposed to both.

## Acceptance criteria
**T-0074a — static diff (CPU only, no container start)**
1. Per behaviour, `docs/cd/hf-parity.md` gives a verdict (diverges / same / not applicable) with exact lines in (i) the
   v0.29.0 image (`@sha256:c2914767…`), (ii) HF transformers @ `0a896aa41bba`, (iii) google-deepmind/gemma @ `c490becf42d1`
   (the reference diffgemma-fa imports), (iv) vLLM @ `1b3b88ec2` and the main sha of the day; whether the divergence was
   introduced, kept or fixed upstream. Every cited segment is vendored in `tests/fixtures/hf_parity/` with path, line range
   and sha256 in its own `manifest.json`.
2. Commit behaviour: which forwards pass through the self-conditioning block in v0.29.0 (prompt prefill final chunk,
   commit steps, or both), and the scale change as an RMS ratio over the vocabulary of the scaled embedding vs `post_norm`
   of it, computed on the CPU from the pinned checkpoint's embedding tensor, with its regime.
3. Window: the exact visible context range per canvas position on each side, including W vs W − 1.
4. A pure exposure calculator (`hf_exposure.py`) reports per record whether either behaviour can affect it (canvases,
   positions), run on the dev and test cuts with histograms in the report.
5. Confirms or refutes, with lines, that Mosaic has no other "as HF does" adjustment applying to every request
   (`_SameFreeMemory` is TP-only; we run TP 1). Also confirms v0.29.0 runs the same code path as Mosaic's
   `VLLM_USE_V2_MODEL_RUNNER=1` on 0.29.1rc1.
6. *Negative:* `tests/fixtures/vllm_v0_29_0/` byte-identical; no `plugin/`, `services/` or `local_astra/bench/` change; no
   GPU time.

**T-0074b — opt-in parity hooks (only after G1)**
7. A request carrying `astra_hf_parity` ∈ {`off`, `raw`, `window`, `both`} gets exactly that behaviour; requests in the same
   batch keep their own, under CUDA graphs (the switch is a device buffer the kernel reads, not a Python branch in a captured
   region). If the window switch cannot be per-request, stop and return to the planner; no two-boot substitute.
8. Hooks installed only when a committed plugin switch is on; with the merged default (off), `register()` leaves
   `triton_attn.unified_attention` and the self-conditioning path untouched.
9. With the switch on, requests with no key or `off` are **bit-identical** to stock in mixed batches (T-0067 pattern).
10. *Negative:* tap and CD paths and their tier-1/2 suites unchanged and green; `services/vllm.sh` unchanged since 806da12.

**T-0074c — does it change outputs (one `/launch`, engine only)**
11. One boot from a commit with the switch on; five arms, all sending the key (identical xargs, T-0011 R17): A=`off`,
    R=`raw`, W=`window`, RW=`both`, A′=`off`; arm order rotated per round (Latin square).
12. Sets: (i) dev cuts (Sudoku n=100, BFCL 130–229 n=100), split by exposure (criterion 4), unexposed records as the
    negative control; (ii) a long-context multi-canvas set built by the test-author: n=40, context 1.5k–8k tokens, thinking
    on, answers > 1 canvas, exact-match scorable (e.g. key-value retrieval with the key 770–1023 tokens before the canvas).
13. Per arm with Wilson CIs: Sudoku solved; BFCL exact call / arg acc; long-set exact match; steps per canvas;
    committed-canvas agreement within vs across arms; McNemar paired by record, Bonferroni over 3; A vs A′ spread as the
    noise floor. No effect claim beyond what n supports.
14. *Negative:* no threshold or calibration file changes, no default flipped, no T-0071 artifact reused.

## Implementation notes
- Read `.claude/rules/` for GPU services and tests. If b text-edits vLLM's kernel source like Mosaic does, it refuses
  loudly when an edit site's count ≠ 1 (pinned against the vendored segments).
- Config channel: `services/vllm.sh` passes only fixed `-e` vars and the locked scripts refuse any diff since 806da12, so
  the switch is a committed value in the plugin; c's commit sets it on, the merged default is off.
- Unseeded sampler: no paired bitwise comparison across arms; A/A′ is the only noise floor.
- Locked-script pattern as in `t0069_cd_smoke.sh` (refusals, `make plugin-wheel`, engine only, `/health`, `last_boot`,
  tap warm-up per T-0069 O7, engine stopped on exit).
- A true HF-vs-vLLM numerical parity check needs the bf16 checkpoint, which doesn't fit the 5090; out of scope.
