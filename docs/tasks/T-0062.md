## Goal
DiffusionGemma served by our vLLM plugin gains an opt-in, per-request constrained decoding mode that implements
Dang & Ermon (arXiv 2607.07026)'s per-step loop, which the JAX port never actually ran. At each denoising step a
constrained slot receives, as in the paper: a **joint draw** from the automaton-constrained posterior, fed back as the
trajectory, and the **constrained per-position entropy H(q_i)** as the acceptance and convergence signal ("Mar").
The **constrained MAP** as the committed canvas is this port's choice, not the paper's (its method section has no
MAP; diffgemma-fa SPEC §2.7): it is the constrained counterpart of DiffusionGemma's argmax commit. The automaton state set is threaded across canvases, with a budget-aware
terminal factor. An end-projection control arm (the J0 analogue), a per-step Mf arm (J2 analogue) and a
constrained-self-conditioning arm make the BFCL-Live simple and Sudoku 4×4 results attributable. Unconstrained
requests are bit-identical to today and pay no device work. This file is the charter: it defines the branch, the
order, the ownership handovers and the gate that must pass before the human is asked to merge.

## Human decisions (2026-09-29)

superseded where they conflict.
1. **Torch on the host:** CPU torch in the non-default `cd` uv dependency group (pytorch-cpu index). Core tests run

2. **Container torch version:** the orchestrator reads it from `vllm/vllm-openai:v0.29.0` and pins it in the `cd`
   group (T-0063). Not a human action. **Read 2026-09-29:** `torch-2.13.0+cu130` (dist-info in the image,
   python 3.12; image not started). The `cd` group pins `torch==2.13.0` from the pytorch-cpu index; a
   `2.13.0+cpu` cp311 manylinux_2_28 x86_64 wheel exists there.
3. **BFCL data (pinned 2026-09-29 at gorilla `6ea57973c7a6`, `tests/fixtures/cd/bfcl/`):** the orchestrator fetches `BFCL_v4_live_simple.json` and `possible_answer/BFCL_v4_live_simple.json`
   from ShishirPatil/gorilla; the human approves the pinned commit before it is written to the MANIFEST.
4. **Automaton transport:** inline base64 in `vllm_xargs`, capped at 1 MiB, **provisional**. T-0064 and T-0069 must
   prove that `vllm_xargs` reaches `DiffusionSampler.add_request` extra_args and that a payload at the cap survives
   the API server, before anything depends on it. Until committed token ids are known to be returned, the harness
   reads the ASTRA_CD engine-log records.
5. **|S| buckets:** the plugin supports buckets up to 512; 128 stays the live-path compile policy; B13 applies at ≤128.
6. **Thinking:** evals run with `enable_thinking=false` for comparability with the JAX numbers. The always-on-thinking
   conductor path stays deferred (see above).
7. **Loud failure is non-fatal:** a CD failure ends the request with an EOS-first committed canvas plus an error
   record; never raise inside the engine.
8. **B13 thresholds:** Mar per-step overhead ≤15 % at bucket ≤128 and ≤10 % at ≤64 (CL 256, one constrained slot);
   unconstrained fast path does zero torch ops, host decision p99 ≤20 µs. Accepted as initial values, revisited
   after the T-0071 microbench via a `docs/tasks/` entry, never silently.
9. **diffgemma-fa SPEC §3.1:** the human agrees the table is wrong (J0's trajectory is an unconstrained categorical,
   `model/sampler.py:586-592`); corrected in that repo, outside this tree.

10. **T-0065 two-pass marginals (orchestrator ruling, 2026-09-29, from the T-0065 review).** `constrained_marginals`
   runs a second, Doob-gauged sweep for fp32 accuracy, roughly doubling the S³ work per step, and `class_mass` over
   [L, V] may run twice. The B13 overhead budget (≤15 % at bucket ≤128) is measured with both passes on (T-0067,
   T-0071); a miss is reported, not hidden by dropping pass 2. The retained `LogTree` a caller holds is the
   **ungauged** pass-1 tree; the gauged tree is internal. T-0066 either rebuilds what it needs or extends
   `CdMarginals` to expose it (its choice, recorded in T-0066).

11. **Evaluation whitespace (human, 2026-09-29; amends decision 5's premise).** The T-0063 review showed that
   diffgemma-fa's pretty whitespace (`PRETTY_WS = ( |\n {0,6})?`) roughly doubles |S|: on the BFCL test cut the
   baseline options give median |S| 161 and **14/130 above 512**, against median 62 and 2/130 for the stock
   report's settings (the often-quoted 97 is over 4 549 schemas from four splits, not this cut). The human chose
   **standard JSON whitespace** (upstream's `--whitespace=json`, RFC 8259, which accepts all five renderings) as the
   grammar for every constrained arm in T-0070/T-0071. All five arms share it, so the arm comparison is unaffected;
   the JAX side-by-side becomes reference-only. A **pretty-whitespace parity check** is also run on the records with
   |S| ≤ 512 under pretty whitespace, to link to the JAX numbers. T-0063 keeps `BFCL_BASELINE_OPTIONS` (pretty) as
   the parity baseline; the eval options are that dict with `whitespace` overridden. Records still above 512 under
   JSON whitespace are counted as failures and reported (no denominator shrinks).

12. **Loud CD error codes (orchestrator, 2026-09-30, from T-0070 ruling E6).** T-0067 emits `error` codes `z0`
    (log Z = −inf), `empty_delta` (δ* empty) and `infeasible` (budget) for the failure classes T-0070's hard stop (b)
    watches; T-0064 refusals keep their own codes (W1). Both tasks follow this list.
    Added 2026-09-30 (T-0067 S9/S10): `internal` (unexpected exception in the CD path, caught) and `preempted` (a
    resumed request, ended loudly). Both count as failures in T-0070; `internal` is a hard stop like (b), `preempted`
    is not a stop but is reported per arm.
