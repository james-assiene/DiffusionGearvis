# T-0080a — Tool schemas v1, pure router and call scorer, and tool-call grammars with thought variants

**Status:** done (2026-10-08; verified at 7e394a3 + scope-guard fix 26e32e1) · **Blast radius:** medium · **Branch:** `T-0080a-toolcall-grammars` from `T-0062-perstep-cd` ·
**Depends on:** human approval of the v1 tool list (question Q1) before the test-author starts. Umbrella `T-0080.md`.

## Goal
Define the product's tool-call surface once, in code both the eval and (later) the conductor can import without torch:
- the v1 tool schemas;
- a pure router that finds the tag in a committed answer;
- a scorer that parses and validates a call and compares it with ground truth;
- in the `cd` group, grammar builders for the three thought variants (T1, T2, T4) and the two scopes (union of all tools, or one named tool), with a size report.

## Acceptance criteria
1. **Schemas.** `local_astra/toolcall/tools_v1.json` has JSON-Schema function declarations, exactly the set approved in Q1. The proposal:
   - `google_search(query: str)`;
   - `click_at(x: int 0–999, y: int 0–999)` (normalised to the attached frame);
   - `type_at(x, y, text: str, press_enter: bool)`;
   - `scroll(direction: enum up|down|left|right)`;
   - `press_key(keys: array of enum, 1–3)`.

   `tools.load()` validates the file (unique names, `required` ⊆ properties, no `$ref`) and exposes the sha256 of its bytes as the
   schema version.
2. **Router (pure, total).** `router.route(answer_text) -> Route` with the fields:
   - `kind ∈ {"none", "toolcall", "genui"}`;
   - `tag`;
   - `spoken_prefix` — the text before the first tag;
   - `draft_call_text` — the text after the tag;
   - `draft_name` — the tool named by the draft, if it parses enough to name one; else None.

   Only the **answer** channel is scanned. Text containing `<|channel>` without a later `<channel|>` (an unclosed thought) routes `none`,
   and a tag inside a thought never routes. The first tag wins. `<genui>` routes `genui` with no draft parsing. A native `<|tool_call>`
   marker is recognised as `toolcall` and logged as `tag="native"` (the router accepts it; Q3 decides whether prompts use it). Never raises.
3. **Scorer.** `score.parse_call(text)` returns `{name, arguments}` or a reason. `score.schema_valid(call, tools)` uses `jsonschema`
   against the declaration. `score.exact(call, gt)` scores per tool:
   - `google_search`: name equal and every required keyword of the case present in the query (case-insensitive, NFC);
   - `click_at`: point inside the case's target bbox (normalised 0–999);
   - `type_at`: bbox as above, `text` equal after strip, `press_enter` equal;
   - `scroll`: direction equal;
   - `press_key`: the key set equal.
   The scorer is the same code the eval uses (b) and the conductor will use (d).
4. **Grammars (`cd` group).** `decoding/toolcall.py::compile_toolcall(tools, *, scope, thought, whitespace="json")` returns a
   `CompiledAutomaton`. `scope` is `"union"` or a tool name. `thought` is:
   - `"T1"`: header with a FREE* thought body closed by 101, then an optional `<cc>`;
   - `"T2"`: the existing `prepend_channel_header`, then an optional `<cc>`;
   - `"T4"`: no header, call only.
   CALL is `{"name": <const>, "arguments": <the tool's parameters schema>}` in JSON whitespace. `report_sizes()` prints |S| and the bucket for every
   (scope, thought). Every automaton encodes through `artifact.encode_automaton` under the 1 MiB cap. A size over bucket 512 is reported,
   never silently dropped.
5. **Grammar language (host replay).** For each variant, a hand-written accepted set and rejected set of token sequences are checked with
   the host replay (`eval/cd/replay.py`), using real tokenizer ids.
   - **T1 accepts:** a real thought with newlines followed by a valid call. **T1 rejects:** a second `<|channel>` and a 101 inside the call.
   - **T2 rejects:** any thought text.
   - **T4 accepts** the call at position 0; **T4 rejects** a leading header.
   - **Every variant rejects:** a call to a tool outside its scope, a missing required argument, an out-of-range `click_at.x`, and a stop id inside a string.
6. *Negative:*
   - `local_astra/toolcall/**` imports neither `local_astra.decoding`, torch, numpy nor outlines (AST check), and imports under the fast-suite environment;
   - `local_astra/conductor/**`, `contracts/llm.py` and `plugin/**` are unchanged;
   - `compile_bfcl`/`compile_sudoku` give byte-identical payloads before and after (the existing grammar parity rows stay green unedited).

## Implementation notes
- Build T1's FREE region in the vendored automaton layer the way `prepend_channel_header` is built: single-id markers 100/101, so the
  "no occurrence of w" construction is two states (SPEC §3.6). Exclude `{PAD} ∪ end_tokens ∪ {100, 101, 105}` (SPEC note at the
  `RESERVED_TOKENS` section).
- The optional `<cc>` is a byte-level literal lifted to tokens like the rest of the regex, so every tokenisation is admitted. Check it
  with the real tokenizer ids in the tests.
- Check (unverified): T-0077 measured |S| for "assumed" schemas: click_at/scroll 62 → b64, google_search 71, type_at 80, press_key 99 →
  b128, union 255 → b256. Re-measure with the v1 file. If the union lands above 256, report it and keep going; c decides whether union is
  usable.
- The router scans text, not ids. The conductor's `llm_client` already separates `reasoning` from `content` per commit. The router gets
  the concatenated answer channel and an explicit flag `thought_open` (`llm_client`'s own field), and routes `none` when it is set.
- No network: `google_search` is never executed by anything in this task or in b/c.

## Implementation log (implementer, 2026-10-08, branch `T-0080a-impl` from 2dcf223)
- **API as the rows pin it (K1–K13).** `toolcall/tools.py`: `load(path=None) -> ToolSet` (`declarations`, `version` = sha256 of
  the bytes, `path`, `names`, `get`, `parameters`); `ValueError` on duplicate names, `required` ⊄ properties, `$ref`, a non-object
  `parameters` or an invalid JSON Schema. `router.py`: `route(answer_text, *, thought_open=False) -> Route`; closed thought blocks
  are cut out before the scan, an unclosed one (or the flag) gives `none` with `spoken_prefix=""`; `TAGS`/`KIND_OF_TAG` are the
  closed tables; `draft_name` only for `cc`, only a v1 name (full JSON parse, else the `{"name": "..."` prefix). `score.py`:
  `parse_call` → `{"name", "arguments"}` or `ParseFailure(reason)` (seven distinct reasons), `schema_valid(call, tools)`,
  `exact(call, gt)` (keywords: NFC + casefold + whitespace runs collapsed, substring).
- **tools_v1.json (Q1, K8, K9).** Top-level list of five declarations, every `parameters` with `additionalProperties: false`;
  `query`/`text` carry `minLength: 1` (non-empty, enforced by outlines); `type_at.press_enter` required; `press_key.keys` is an
  array (1–3) over 54 keys: 18 named (Enter, Tab, Escape, Backspace, Delete, Space, four arrows, Home, End, PageUp, PageDown,
  Control, Shift, Alt, Meta) plus `a`–`z` and `0`–`9`. No `uniqueItems` (outlines drops it; the pre-pass would refuse it).
- **0–999 in the grammar.** `decoding/toolcall.py::call_regex` replaces every `{"type": "integer", "minimum": 0, "maximum":
  10**k-1}` node by a unique string `const` sentinel before the schema reaches outlines, then substitutes the sentinel's single
  rendering `"<sentinel>"` in the regex by `(0|[1-9][0-9]{0,k-1})` (asserted to occur exactly once). Any other numeric bound
  raises; `minimum`/`maximum` are never put on the `allow` list. Rows: 0, 9, 10, 99, 100, 500, 998, 999 accepted; 1000, 1500,
  9999, −1 rejected in every variant.
- **Variants.** Regex = `[(<cc>)?] WS (CALL_1|…|CALL_n)` (no tag for T4; WS = the chosen JSON whitespace, so T4 also admits leading
  whitespace), lifted once per regex (cached). T2 = vendored `prepend_channel_header`; T1 = `prepend_thought_header`, the same
  name chain with the post-newline state looping on FREE = V − (`RESERVED_TOKENS` ∪ stop ids) and leaving on 101 (still a DFA).
  `compile_toolcall` caches per `(tools.version, scope, thought, whitespace)`; the cache key is stamped like `grammars._stamp`.
  `compile_bfcl`/`compile_sudoku` are untouched (parity rows green).
- **Sizes (CPU; tools_v1.json sha256 13cc6a5b746c…; tokenizer cc8d3a0c…; model rev 2ea8372; outlines-core 0.2.14; JSON
  whitespace).** |S| / bucket, T1 · T2 · T4: union 438/512 · 438/512 · 423/512; google_search 76/128 · 76/128 · 61/64; click_at
  66/128 · 66/128 · 51/64; type_at 107/128 · 107/128 · 92/128; scroll 74/128 · 74/128 · 59/64; press_key 231/256 · 231/256 ·
  216/256. All `is_dfa`, all payloads ≤ 61k chars (cap 1 MiB). The union is above the 256 the notes hoped for, and press_key
  is above 128; dropping `a`–`z`/`0`–`9` from the enum changes neither (press_key T4 216, union T4 423, measured), so the
  cost sits in the 18 named keys under the 1–3 repetition (not decomposed further). For c to decide (live-path build gate is
  ≤ 128 states per `.claude/rules/gpu-services.md`).

## Human decisions after the size report (2026-10-08)
Sizes at 5bb12d0 (`report_sizes()`, CPU, tools_v1 sha 13cc6a5b…): single tools under T4 — click_at 51, scroll 59, google_search 61 (bucket
64), type_at 92 (128); press_key 216 (256); union 423 (512). Project build gate: automata on the live path ≤ 128 states.
- **D1 — press_key = one combo from a fixed list.** `press_key(combo)`, `combo` a string enum of ~20 common keys and shortcuts (e.g. Enter,
  Escape, Tab, Backspace, Delete, Space, the four arrows, Home, End, PageUp, PageDown, Ctrl+A, Ctrl+C, Ctrl+V, Ctrl+X, Ctrl+Z, Ctrl+L, Ctrl+T,
  Ctrl+W, Alt+Tab, Ctrl+Enter). Target ≤ 128 states under T1/T2/T4; the scorer compares the combo string. New combos are a list edit.
- **D2 — scope = the named tool; two-step when the draft names none.** The constrained pass uses the grammar of the single tool the draft
  names (`draft_name`). When `draft_name` is None, pass 2 first runs a tiny **name-only** grammar (`scope="name"`: `{"name": <one of the v1
  names>` …, or just the name enum) to pick the tool, then the per-tool grammar for the arguments. The union grammar is not used on the live
  path (it stays available for reporting/eval only).
- Every live-path automaton (each tool under T1/T2/T4, and the name-only grammar) must be ≤ 128 states, asserted by a test.

## Implementation log, D1/D2 (implementer, 2026-10-08, branch `T-0080a-impl-2` from 31b68ce)
- **D1.** `press_key(combo)`: `combo` a string enum of 24 entries (the D1 list: Enter, Escape, Tab, Backspace, Delete, Space, four
  arrows, Home, End, PageUp, PageDown, Ctrl+A/C/V/X/Z/L/T/W, Alt+Tab, Ctrl+Enter); `required: ["combo"]`,
  `additionalProperties: false`. `score.exact` compares `arguments.combo` with `gt["combo"]` (string equality).
- **D2.** `compile_toolcall(..., scope="name")` is the name picker: `[header] ["<cc>"] WS {"name": "<one v1 name>"` + STOP, for
  T1/T2/T4 (T2/T4 are the sensible live variants; T1 re-denoises the thought in both steps). Chosen over a bare name because the
  `{"name": "` prefix is how the model writes a call, and because the picked canvas is then token for token a prefix of the
  per-tool grammar's language (`name_regex` asserts the prefix is literal in every tool's CALL regex), so step 2 —
  `compile_toolcall(scope=<picked>, thought=<same>)`, an ordinary pass-2 request — can be seeded with it (T-0081) or simply
  re-derive the const name. `"name"`/`"union"` are refused as tool names. `report_sizes()` lists `name`, each tool, then
  `union` marked `path=eval-only`; live rows over 128 states are flagged `OVER-LIVE-GATE-128`.
