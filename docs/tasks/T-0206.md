## Goal

**Today:** a live agent can fill in a quote, contact or booking form and press its send button, or press Enter in it, with nothing between the model and an irreversible request. T-0192 stops only at checkout URLs.

**After this task, in web mode:**
- The executor reads, on the driver side, what a click would actually press and which form it belongs to.
- It refuses the click when that is the send control of a form holding filled personal data (name, email, phone, address, free-text message).
- It withholds Enter, and Space on a focused send button, in such a form.
- Group B ends the turn with a fixed system clip handing the send back to the user. The user can check the form and press the button in the headed window.

**What stays open:** search, filters, store locators, flight searches, add-to-cart, sign-in and CTA links ("Get a free quote") behave exactly as before. A send button only counts when personal data is filled, and search-like forms and labels are exempt.

**Model-facing text:**
- In the hand-back turn the model is told nothing new: the turn ends, as T-0192 B does.
- Between A's merge and B's, the model sees the refusal reason, as T-0192 A's model did. The T-0205 C run observes that state if it runs then.
- No prompt or tool change, so no GPU A/B. A behaviour smoke is T-0205 C's D7 (report-only).

**Threat model:**
- **What it protects against:** model mistakes, and on-screen injection ("click Submit").
- **What it does not protect against:**
- a page that disguises a send: a `div` with a script that posts the form, a control labelled outside the lexicon, or an auto-submitting radio. The page owner wants submissions anyway; this is stated, not solved.
- a page that breaks the read, which fails open (H-T206-5).
- The card, password and checkout guards still stand behind it.
- **Privacy:** field values never leave the page, only `filled` booleans. Labels are compared inside the executor and never reach an outcome, an event or a log (T-0192 A8 pattern).

## Acceptance criteria

### Group A — detection and refusal

**A1. The predicate, `fence.irreversible_submit(facts: Mapping[str, object]) -> bool`.** Pure, stdlib-only, total; it never raises for any JSON-like value; linear time.
- **`facts` keys:**
- `control`: `{tag, type, role, label, href_nav, structural}`;
- `scope`: `form` or `document`;
- `search_scope` (bool);
- `fields`: a list of at most `MAX_FIELDS = 64` items `{tag, type, autocomplete, name, id, placeholder, label, filled, visible}`.
- **`True` exactly when all four hold:**
- (a) the control is not a navigating link (`href_nav` false: an `a[href]` whose href is not empty, `#…` or `javascript:`);
- (b) the scope is not search-like:
  - neither `search_scope` (a `role=search` ancestor or `<search>` element);
  - nor a filled field of `type=search`;
  - nor a field whose `name`/`id` is in `SEARCH_NAMES` = {q, query, search, s, k, keyword, keywords, field-keywords, term, search_query};
- (c) at least one *personal* field is `filled` and `visible`. A personal field is one of:
  - a textarea;
  - `type` in {email, tel};
  - an `autocomplete` token in `PERSONAL_AUTOCOMPLETE` (name, given-name, family-name, email, tel, tel-national, street-address, address-line1, address-line2, postal-code, address-level1, address-level2, organization);
  - a normalised `name`/`id`/`label`/`placeholder` that matches whole-word `name|email|e-mail|phone|tel|mobile|address|street|zip|postcode|postal|message|comments?`;
  - but never a search-like field;
- (d) the control's normalised label (casefold, whitespace collapsed, punctuation and trailing arrows stripped, at most 6 words) begins on a word boundary with an entry of `SEND_LABELS` (H-T206-1), **or** the control is `structural` (a `button` whose type is submit or missing, or an `input` of type submit or image, with a form owner) and its label is empty.
- **`SEND_LABELS`:**
- submit, send, send message, send request, send enquiry, send inquiry;
- request quote, request a quote, request a free quote, request estimate, request an estimate;
- get quote, get a quote, get my quote, get a free quote, get free quote, get estimate;
- place order, place my order, complete order, complete purchase, confirm order, confirm booking, confirm reservation;
- book now, reserve now, pay, pay now, buy now;
- sign up, register, create account, subscribe, apply now, donate.
- **`SEARCH_LABELS` win over `SEND_LABELS`:** search, find, go, look up, find stores, search flights, show results.

**A2. Driver read** (`runtime.py`). `PlaywrightDriver.submit_facts(x, y)` and `submit_facts_focused()`, each async and looked up on the driver's class like `focused_field`, each returning A1's `facts` or `None`.
- **What they read:** the hit-tested element at the CSS point, or the deepest focused element. Each descends through open shadow roots and into same- and cross-origin frames, translating the point, as `focused_field` does. Each resolves to the nearest `button`, `input`, `a` or `[role=button]`.
- **Scope:** the form owner, else the document.
- **Never returned:** a field value, only `filled`.
- **What they do not do:** change no page state, and use no init script. The isolated world vs the main world is the implementer's choice; state it, and see the Implementation notes.

**A3. Refusal of a click** (`executor.py`).
- **When it applies:** in web mode, when the driver class has `submit_facts`, before dispatching the click of `click_at`, of `type_at` (its focus click) and of the overview-frame click.
- **Order of checks:** the page-serial check, then the checkout check (T-0192 A3), then T-0204's moved guard, then this read, bounded by `SUBMIT_TIMEOUT_S = 0.3`.
- **On `True`:** `refused` with `SUBMIT_REASON = "this button sends the form; the user presses it themselves"`. Nothing is dispatched or captured.
- **On a read that is `None`, raises or times out:** the click proceeds as at BASE (fail open, H-T206-5), and `on_note({"what": "live click: submit check", "result": "unknown"})` is called, with no URL or label.

**A4. Withheld Enter and Space.**
- **`press_key`:** a chord holding Enter, NumpadEnter or Space, in web mode, reads `submit_facts_focused()` first.
- Enter and NumpadEnter apply A1 to the focused element's form, with the control replaced by the form's default button (or a structural empty-label control when there is none).
- Space applies when the focused element is itself the control.
- On `True` it is refused with `SUBMIT_REASON`, and nothing is sent.
- **`type_at` with `press_enter=True`:**
- The facts are read after the focus read (T-0160 B-3) and before any key. The target field counts as `filled` when the text is non-empty.
- On `True`: the text is typed (T-0189 replace applies), Enter is not pressed, and the outcome is `executed`.
- Its `action` string is exactly BASE's for the same call with `press_enter=False`.
- `resolved["submit_withheld"] = True`; the key is absent otherwise.
- A textarea target never withholds, because Enter there is a newline.

**A5. False positives stay open (negative).** None of these is refused or withheld:
- a Google-shaped form (`q`, "Google Search"); an Amazon-shaped form (`field-keywords`, input submit "Go"); Wikipedia's ("Search");
- T-0205's D4 model search, D6 "Find stores" with a filled street address, D9's "Search" with origin and destination filled;
- a sign-in form ("Sign in", email filled);
- an "Add to cart" form with quantity;
- an `<a href="/trees/quote.html">Get a free quote</a>` with nothing filled, and the same link with a newsletter email filled on the page (rule (a));
- a filter checkbox; a cookie banner's "Accept all".
- `tools_v1.json`, `tools_v1_overview.json` and every existing action string are byte-identical to BASE.

**A6. True positives.** These are refused or withheld:
- T-0205 D7's "Request quote" after Name is typed;
- the same button with only the Description filled (a textarea);
- an empty-label structural submit in a contact form with email filled;
- a formless SPA `div[role=button]` "Send message" with a filled textarea on the page;
- Enter in D7's Phone field;
- Space on a focused "Submit";
- a cross-origin iframe contact form's "Send".

**A7. Unchanged outside web mode (negative).**
- With `web=False`, neither read is ever called, and dispatch sequences equal BASE's.
- T-0138 S11 ("send the booking", non-web) still succeeds through the real executor, and its early-Enter trap still submits.
- A web-mode fake driver without the methods runs BASE's path.
- One row pins that the real driver has both methods.

**A8. Privacy.** A unique token placed in a field value and in a button label appears in no `ToolOutcome`, no `take_events()` entry, no note, no `egress_log` entry and no exception message.

**A9. Cost** (report plus a bar from measurement, the T-0204 B-R3 precedent).

## Implementation notes

- **Where it sits:** the read goes at the dispatch point, after T-0204's moved guard, so what is read is what is pressed. `_act_on_overview` needs the same check.
- **Main world vs isolated world:** `focused_field` precedent reads in the main world (`frame.evaluate`), where page script can shadow `document.elementFromPoint`. Prefer an isolated world (`Page.createIsolatedWorld` / CDP `DOM.getNodeForLocation`) if it is cheap. Either way, a forged answer can only make the read fail open, which is the stated residual.
- **Overlays:** hit-testing returns the topmost element. A transparent overlay that forwards clicks hides the button. Pin it as a known gap (`False`) in the browser row. Do not chase it with elementsFromPoint scanning in this task.
- **Enter in a form without a submit button:** HTML implicit submission still fires when the form has one text field and no submit button. A1(d)'s structural empty-label clause covers that case.
- **Withheld Enter:** typing then withholding is chosen over refusing the whole `type_at`, so that B's hand-back leaves a filled form for the user (H-T206-2).
- **No prompt change:** the reason strings mirror `CHECKOUT_REASON`'s shape.
- **The machine stays pure.** B reuses T-0192's ending path; no new row shape.
- **Hook rules** as in T-0205.
