## Goal

On 2026-10-28 (`logs/sessions/20261028-145330-1824860.jsonl`, build c0cb001e) the headed agent browser was on top when computer use started; on 2026-10-29 (`logs/sessions/20261029-121653-2974784.jsonl`, build 611068bb) it stayed behind. Nothing in `local_astra/` ever raises the browser window (no `bring_to_front`, `Target.activateTarget` or `Browser.setWindowBounds`).

Confirmed in source: in both builds the headed browser launches at session start (`cli.run_session` → `_open_start_page` → `BrowserToolExecutor.open` → `_ensure` → `PlaywrightDriver._launch`, `cli.py` 2506-2546; T-0111g B5). Nothing in `c0cb001e..611068bb` changes that. The difference is the HUD: yesterday `astra.hello` at 3.7 s and the first tool step at ~15.9 s with no HUD input between, so the browser was the newest window; today `astra.hello` at 87 s, mute at 126 s, unmute at 383 s, `astra.text` at 412.8 s, first tool step ~430 s with the HUD focused.

The box reports `XDG_CURRENT_DESKTOP=ubuntu:GNOME`, `XDG_SESSION_TYPE=x11` (not KDE; docs/02 §2.1's KWin rule does not apply). Mutter may block a raise it treats as focus stealing (H-T198-1).

After this task, in a headed live session the executor brings the agent browser's active page to the front once per turn just before the first browser action it actually dispatches, and again whenever the active page changes (popup, late popup, T-0188 replacement during an action). Never in headless mode, in a turn whose vision is the user's shared screen, for a refused call, a search, a page overview or a frame capture, or for a conversational turn.

## Acceptance criteria

Definitions: **the executor** is `BrowserToolExecutor`; **fronting** is one call to the driver's optional `bring_to_front()`, looked up on the driver's class like `replace_page` and `focused_field`; **a page key** is `(inv.turn_id, driver.generation, driver.page_serial)`.

1. **Once per turn.** With `headless=False`, `raise_window` `True` and a driver class with `bring_to_front`, the first `execute()` of a turn that passes every refusal check calls `bring_to_front` exactly once, before its first input or navigation call (`mouse_move`, `mouse_down`, `key_down`, `type_text`, `scroll_by`, `goto`, `replace_page`). Later actions in that turn on the same generation and `page_serial` call it zero times; the first such action of the next `turn_id` calls it once more.
2. **On a page change** (a popup adopted by the action's `settle()`; a late popup adopted by the next action's `ensure()` (T-0187); a T-0188 `replace_page` during `Ctrl+T`/`Ctrl+L`): exactly one fronting for the new page key — inside the action: after settle, before the after-frame capture; found by `ensure()`: before the next dispatch. No page key is fronted twice, including after a failed try (criterion 6).
3. **Headless never fronts.** `headless=True` (default, every GPU harness): zero `bring_to_front` calls over any sequence, even when the driver has it.
4. **A shared-screen turn never fronts.** Where a live turn's vision choice is fixed (`snapshot_frame`, `_turn_vision`, `session.py` 3429-3432) the session sets the browser's `raise_window` to `self._turn_vision == "browser"`, checking the attribute with `inspect.getattr_static` (as `cli._open_start_page` does for `start_page_url`); a `LiveBrowser` without it is untouched. With `raise_window` `False` no fronting in that turn; a later browser-vision turn fronts again.
5. **Never fronts:** a refused or failed-before-dispatch call (the plan's refusals, the guard's verdict, `CLOSED_REASON`, `browser restarted`, `PAGE_CHANGED_REASON`, `CHECKOUT_REASON`); session-side refusals that never reach `execute()` (B9 freshness, T-0177 B2, T-0137 guard, T-0140 A8); `google_search`; `page_overview`; `frame()`, `open()`, `reset_page()`; **a conversational turn** (each live turn's first snapshot calls `browser.frame()`, which must never front).
6. **Best effort, bounded.** A `bring_to_front` that raises any `Exception` or runs past `FRONT_TIMEOUT_S` (1.0 s) leaves the `ToolOutcome` (status, action, reason, resolved) identical to a driver without the feature. `CancelledError` propagates. A page key whose fronting failed is not retried. The wait counts inside `ACTION_TIMEOUT_S`.
7. **Nothing else changes (negative).** For a scripted sequence (turns, popups, refusals) every `ToolOutcome` and every non-front driver call, in order, is identical between `headless=True` and `False`. No `resolved` key, no change to the `LiveBrowser`/`Driver` protocols, `ToolInvocation` or `contracts/`. No new log kind, turn-line key, HUD message, stderr line, process, thread, socket or request. `runtime.py` stays the only `playwright` importer. `off`, `dry_run` and live `--browser headless` behave as before.
8. **The real driver.** `PlaywrightDriver.bring_to_front()` awaits `self.page.bring_to_front()` on the active page and nothing else; with no page it raises the existing `RuntimeError` (swallowed under 6). Browser row: on real Chromium the policy calls `Page.bring_to_front` once per page key on the then-active page (the popup after `window.open`), and the next action and capture still succeed.
9. **Wiring.** `make browser` runs the new browser module; `MAKE_BROWSER` re-pinned (after T-0194's re-pin).
10. **Spec.** docs/03 gains a T-0198 spec delta: criteria 1-7, H-T198-3's keyboard-focus risk, and that a raise the window manager blocks, or a keep-above HUD, can still leave the browser hidden.

## Implementation notes

- The policy lives in the executor (`turn_id` is on every `ToolInvocation`); the session only sets `raise_window`. Do not add `bring_to_front` to the `Driver`/`LiveBrowser` protocols; look it up on the class.
- Front only after `_ensure_ended()` and every generation/page-serial/checkout refusal, before the first dispatch (`_dispatch`, `_dispatch_guarded`, `_act_on_overview`). After `settle()`, compare the page key before `_capture()`. `frame()` never fronts.
- Store the executor's `headless` keyword and apply the policy to injected drivers too.
- `Page.bringToFront` should not move `framenavigated`/`domcontentloaded` bookkeeping (T-0174 B1-1b, T-0192 A2); the browser row asserts it.
- Possible T-0198b fallback (unverified): CDP `Browser.getWindowForTarget` + `Browser.setWindowBounds` minimize→normal via a browser-level CDP session (not available on a persistent context). Not `window.focus()`.
- Landmines: `test_hud_server_no_egress.py` scans `session.py`; `test_computer_imports.py` pins `playwright` importers and `MAKE_BROWSER`; everything stays inside `asyncio.timeout(ACTION_TIMEOUT_S)`; a fronting error never becomes `_failed(inv, exc)`.
- Out of scope: window geometry, the HUD's keep-above rule, logging fronting.
