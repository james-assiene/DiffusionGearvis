## Evidence this plan rests on
Source: T-0087 at 724c0c4, `logs/t0087-probe-724c0c4/`, raw.jsonl sha `f871d037…`.
- **Reading B: the call never reaches `content`.** The engine runs with `--reasoning-parser gemma4 --tool-call-parser gemma4` and the
  request sends `tool_choice: "none"`. Served `content` never carries the call, in any arm. It is the answer cut at its first special
  piece, and the call is in no `tool_calls` key.
- **Chunk shape.** With `stream: true, skip_special_tokens: false, return_token_ids: true` (arm (b)), every non-role chunk carries
  `choices[0].token_ids` (q7 12/12).
  - The role chunk has `delta: {role, content: ""}`, `prompt_token_ids` and `prompt_text`, and **no** `token_ids` key.
  - The final chunk carries `finish_reason` and `stop_reason`.
  - Every recorded response fits one canvas, so each has one content chunk. The multi-canvas shape has not been recorded; gpu row 2
    below records it.
- **The host decode matches the served fields.** Decoding the ids up to the first stop id on the host gives:
  - a thought region equal to `reasoning` (24/24);
  - a router draft that `native.parse_call` accepts on 20/20 tool streams;
  - a first stop id equal to `stop_reason`: 50 on tool streams, 106 on chat.
  - In e/key-02, a stray `<tool_call|>` sits between the spoken sentence and `<|tool_call>`.
- **Engine facts.**
  - Tools must be in the prefill (q8: 0.976–0.987 with tools, 0.71 without).
  - String continuation content is accepted, and the prompt ends in id 48 (q9).
  - `/tokenize` at the server root equals the pinned encode 10/10 (q10).

## Goal
With tools on (`Prompt.tools` set), the client:
- sends T-0087's measured arm (b), with the native `tools` field and `tool_choice: "none"`;
- decodes each chunk's `token_ids` on the host (T-0088a). It reads `content` and `reasoning` only for a presence check;
- splits the decoded text into `thought`, `answer` and `ui` commits, as today;
- emits everything from the first call tag to the stop as **one `tool` commit** at the end of the response. That commit carries the stop
  id, and nothing in it can reach speech.

The backend also accepts a typed `CdRequest` and a continuation prompt, and exposes `tokenize`.

With tools off, every request body and every commit is byte-identical to `main`.

   - **`Commit.stop_id`:** `int | None = None`. It may be non-None only on a `tool` commit, and then only with a value in
     `special_tokens.STOP_IDS`; otherwise construction raises.
   - Every existing constructor, fake and fixture stays valid.
2. **Request body** (`VllmClient.request_body`).
   - **With tools:** the body adds `tools` (in `native.tools_field` order), `tool_choice: "none"`, `skip_special_tokens: false` and
     `return_token_ids: true` to today's fields. This is exactly arm (b); nothing else is added.
   - **With `continue_final_message`:** the body adds `continue_final_message: true` and `add_generation_prompt: false`, and the final
     assistant content is a **plain string** (q9).
   - **Prefill:** the prefill body for a prefix is `request_body(prefix, …, max_tokens=1)`, so it carries the same tool fields as the
     generate request for the same prompt (q8; B11).
   - Neither `skip_special_tokens` nor `return_token_ids` enters `LlmOptions`; both follow from `Prompt.tools`.
   - *Negative.* For a prompt without tools, the body is byte-identical to `main` (golden-captured at the base SHA).
3. **Typed CD.** `LlmBackend.generate(..., *, xargs=None, cd: CdRequest | None = None)`, on the protocol, on `VllmClient` and on the fake.
   - `cd.to_xargs()` is merged under `vllm_xargs`, with JSON types preserved (float, int, str).
   - `astra_request_id` still wins.
   - A key present in both `xargs` and `cd` raises `ValueError` before any socket opens.
   - T-0017 criterion 5 (`xargs` values are strings) is unchanged.
4. **`tokenize`.** `LlmBackend.tokenize(text) -> list[int]`.
   - `VllmClient` POSTs `{model, prompt: text, add_special_tokens: false}` to `/tokenize` at the server root (the base URL without
     `/v1`; q10) and returns `tokens`.
   - It raises on a non-200 status, or on a body whose `tokens` is not a list of ints.
   - It never tokenizes locally.
5. **Id mode, reading the wire.** A `generate` whose prompt has `tools` runs in id mode.
   - **The detokeniser.** `VllmClient(..., detokenizer: HostDetokenizer | None = None)`.
     - In id mode with no detokeniser, `generate` raises `ValueError` before any socket opens.
     - The client never loads the tokenizer file itself, so no file is read inside a turn.
   - **Chunks must carry ids.** Every chunk with non-empty `content` or reasoning text, or with a non-null `finish_reason`, must carry
     `choices[0].token_ids` as a list of ints. Otherwise `generate` raises `LlmWireError` (new, in `llm_client.py`) and nothing from that
     chunk is yielded.
     - A role chunk with empty text and no ids is accepted.
   - **`content` and `reasoning`.** In id mode they are never segmented, voiced or published.
   - **Where decoding stops.** Ids are decoded up to, and excluding, the first id in `STOP_IDS`; any ids after it are ignored.
     - That stop id is the request's stop id.
     - `stop_reason` is not read.
   - **Errors.** An unknown id raises `LlmWireError`, and so does a stream that ends (without being aborted) with no non-null
     `finish_reason`. Neither case emits a `tool` commit.
   - **Abort.** An abort behaves as today and yields no `tool` commit.
6. **Id mode, the split.** The split is pure and belongs to `split_canvas`'s family. Let D be the host decode up to the stop.
   - **Thought.**
     - Text from `<|channel>` to the next `<channel|>` is `thought`, with the markers and any leading `thought\n` header removed.
     - For the first thought this is exactly T-0087's `regions()` definition.
     - A canvas that ends inside a thought sets `thought_open` on all its commits, as today.
   - **Answer.**
     - Text outside thoughts and before the first call tag is `answer`. A call tag is any of `router.TAGS`, found the way `route` finds
       it.
     - Answer text goes through the existing UI-fence logic: one implementation, not a copy.
     - **Answer pieces have every `SPECIAL_TOKENS` literal removed by `drop_special_literals`** (human Q2). The removal happens **after**
       the tag search, so a removal can never create a tag.
   - **Tag placement.**
     - A tag inside an open UI fence is UI text.
     - A tag inside a thought is thought.
     - M9 holds: `THOUGHT_MARKERS` in answer text ⇒ thought.
   - **Held fragments.** A trailing proper prefix of a recognised marker is held for the next canvas. Recognised markers are the tags, the
     channel markers, the UI markers, and any special literal spelled out in plain text. If the response ends while a fragment is held, it
     is dropped (L10).
   - **Router parity** (the eval's definition; T-0085). Take any D = `<|channel>thought\n` + t + `<channel|>` + s, where t holds no
     channel marker and s holds no `<|channel>` and no `<a2ui>`. For any partition of D's ids into chunks:
     - the concatenated `answer` texts equal `drop_special_literals(route(D).spoken_prefix)`;
     - there is a `tool` commit iff `route(D).tag` is not None, and its text equals
       `TAGS[tag] + route(D).draft_call_text + route(D).draft_close`.
   - **Unclosed thought.** When D holds a `<|channel>` that is never closed, no text after it is `answer`.
7. **The `tool` commit.**
   - **At most one per request.** It is yielded after the final chunk is processed and before the generator ends.
   - **Its text** runs from the tag to the stop, with closed thought blocks removed, and is cut at an unclosed `<|channel>`. For every D
     in criterion 6's parity set, this is exactly the router's text.
   - **Its fields.**
     - `stop_id` is the request's stop id, or None for a length cut.
     - `thought_open` is False.
     - `canvas_idx` is the final canvas's index, and `canvas_idx` never decreases across a request's commits.
   - **The continuation case** (the T4 repair; T-0091/T-0092). When `prompt.continue_final_message` is set and the final assistant text
     ends with `<|tool_call>`:
     - the split starts in the tool state;
     - the whole output, with thoughts removed as above, is the single `tool` commit;
     - no `answer` commit is yielded.
   - **Never voiced.** A `tool` commit is refused by the speech gate (T-0088a criterion 3) and is never voiced (T-0089 P6).

## Implementation notes
- **Two read paths, one split.**
  - With tools off, today's `content`/`reasoning` path stays byte for byte.
  - Id mode decodes the ids, then feeds one pure split that reuses `split_canvas`'s UI-fence and M9 logic (one implementation).
  - T-0052 D1 holds: all carry state is a local of the `generate` frame, never stored on the client.
- **The tool text comes from the router.** Compute it with `router.route` semantics, importing it rather than re-implementing it, so eval
  parity holds by construction. The incremental split decides only where speech must stop.
- **Specials are atomic in id mode.** Every special piece is one id, so a chunk boundary cannot split one. Plain-text spellings still can
  be split, hence the held fragments.
- **`content` is never a fallback.** A chunk without ids is a wire error: fail loudly, never degrade to reading `content`. The session
  turns the exception into `LlmError` (the existing `_run_generate` path), and T-0089 R8 cancels any pending call.
- **The stop id comes from the ids.** This is the eval's `_until_stop` rule, and what T-0091's seed parity uses. `stop_reason` agreed on
  24/24 recorded streams; that agreement is a replay row, not a runtime dependency.
- **`content` and `reasoning` in id mode** are used for exactly one thing: the presence check in criterion 5. `REASONING_DELTA_KEYS` is not
  narrowed here, since the probe saw `reasoning`. Narrowing it is a follow-up that also edits `.claude/rules/gpu-services.md`.
- **The tool status is not computed here.** Per T-0089, "the machine trusts `ToolDraft.status`, which the session computes": T-0091
  classifies the `tool` text and T-0092 builds `LlmDone(tool=…)`. The client delivers only the text and `stop_id`.
- **Rules to respect:**
  - `.claude/rules/gpu-services.md`: only whitelisted sampling fields. `skip_special_tokens` and `return_token_ids` are output-format
    fields, sent only in id mode, per T-0087's evidence.
  - `.claude/rules/conductor.md`: only `answer` commits feed the gate, and a canvas that ends inside an unclosed thought is never voiced.
  - CLAUDE.md: thinking stays a session setting (`chat_template_kwargs` unchanged).
