## Goal
The first real-GPU run of T-0067 tier 2 (`logs/t0067-tier2-295c13b.log`, PROGRESS Runs 2026-09-30) showed that T-0065's
fp32 core, green on CPU, is wrong on CUDA in three rows of `tests/cd/cuda/test_cd_cuda_repeats.py`:
- (a) `c2_differential…[0.4]`: worst H(q) error / bar = 2.62 (CPU ≤ 0.80 over 60 seeds).
- (b) `c5_no_nan…`: H(q) = −87.3365 at all 6 positions. That is **ln(FLT_MIN) = ln 2⁻¹²⁶**, not ln 1e-38 (−87.498) nor
  ln 1e-30 (−69.08). So `total` hit its `finfo.tiny` clamp: q̃ summed to 0, i.e. **q ≡ 0 on CUDA**. The row's q checks
  passed vacuously.
- (c) compensated `log_matmul`: 1.13 ulp / 9.5 % > 0.51 (eager), 1.06 / 9.3 % (compiled) — near CPU's *uncompensated*
  control (≥ 1.17 / ~16 %, `test_core_compensated.py` header), so the TwoSum/residual terms look lost, not degraded.

Per-step Mar (T-0068), the engine runs (T-0069) and the campaign (T-0071) all read H(q) on CUDA, so none of them are
evidence until this task lands. Every GPU iteration costs the human a `/launch`, so the task is **diagnostics first**:
1. One self-contained probe discriminates the candidate causes for all three failures.
2. The orchestrator records a diagnosis ruling (D1).
3. The fix follows, accepted by the existing rows at their existing bars.

Candidate causes: FTZ/DAZ at the clamps; CUDA `expf`/`logf` ulp breaking the error model of the TwoSum/residual
corrections; FMA contraction or reduction order; TF32; compiled reassociation; something else the stage dump shows.

## Rulings (orchestrator, 2026-09-30, after the probe author's CPU reproduction at 70fc1a2)
- D0. Two of the three tier-2 failures are **test defects**, reproduced identically on host CPU (torch 2.13.0+cpu) with
  the rows' own seeds; no plugin change is warranted for them and no bar changes:
  - (b) `c5_no_nan…`: the fixture's language is **empty** under its −inf mask (0 of 729 finite strings accepted). T-0065
    R6 already leaves H(q) unspecified when Z = 0 (callers never read it; the sampler reports `z0` loudly, T-0067). The
    row's emptiness gate was defeated by its oracle clamping logits to −1e300 (log Z = −1e300 counts as finite). Fix:
    the fixture must have a non-empty language (asserted by an independent enumeration), and the gate must use the
    exact oracle; a separate row pins that an empty language is detected (log Z at the sentinel), not that H has a value.
  - (c) `compensated_log_matmul_on_the_served_path`: the oracle is built from the **unrounded** fp64 inputs while the
    core receives fp32-rounded ones. Against the rounded inputs the core gives 0.587 ulp / 1.56 % (bar: ≤ 1 ulp,
    ≤ 5 % > 0.51) on CPU; seeds 1–4 give 0.57–0.58. Fix: the oracle uses the fp32-rounded inputs (as
    `test_core_compensated.py` already does); the bar and the uncompensated control are unchanged.
  - (a) `c2_differential…[0.4]` stays a **real** finding: on host CPU the row's exact instance gives worst err/bar

## Implementation notes (orchestrator summary of the implementer's report, 2026-09-30)
- **Order-fixed reductions (D4).** `semiring.SegmentLayout` / `SegmentLevel`: a fixed summation plan — inputs sorted
  stably by segment and packed into padded blocks of ≤ 64 slots, upper levels grouping blocks the same way until one
  block per segment; reductions are gathers + `where` on padding + `sum(-1)`/`amax(-1)`, chunked by whole blocks under
  `CHUNK_ELEMS`. Built on the host (vectorised numpy) once per request in `emission.build_tables` as new `CdTables`
  fields (`memb_layout`, `upos_layout` + `upos_class`, `edge_class_layout`, `edge_pair_layout`; ~0.01 s for BFCL).
  Replaced: `class_mass`, the parallel-edge `segment_logsumexp` in `log_transfer` and `_gauged_leaves`, the joint's
  per-class sums in `constrained_marginals`, and the `index_add_` in `_token_marginals`. The segment max is gathered, so
  no scatter atomics remain on the per-step path. `segment_sumexp_split` / `segment_logsumexp` keep their signatures
  (off the per-step path; bit-identical to the layout path). Compensation and the two-pass structure untouched; `tree.py`
  not edited. Same code on every device.
- **Cost:** end_projection op counts unchanged vs T-0072 (BFCL 483/741, Sudoku 449/518 at CL 64/256); the marginals
  chain +0.8 % ops at L 256 (BFCL 11 064 → 11 149), CPU median unchanged within noise. Very skewed class sizes cost up to
  n_segments × 63 padding slots per level.
