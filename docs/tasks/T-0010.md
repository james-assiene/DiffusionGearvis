# T-0010 — Generative UI: ui_gate + edu catalog + HUD renderer

**Status:** Python half merged 2026-09-13; criteria 4–6 open (A6) · **Blast radius:** medium · **Depends on:** T-0002, T-0008

## Goal
`ui` segments become validated A2UI v0.9.1 surfaces rendered by `@a2ui/lit` with the `edu`
catalog (docs/12 §1). Pipeline: json_repair → schema → topology → per-component resample →
progressive render.

## Acceptance criteria
1. `UiGate.repair` tries the strict parser first (`repaired == 0` for valid input) and only then `json_repair` (pinned) with `stream_stable=True`, `logging=True` (`repaired` = log length); schema-guided salvage is applied to the *components array* with a derived schema (no `unevaluatedProperties`, local `$ref`s only) and any `ValueError` from the fixer falls back to unguided repair — behaviours pinned in `tests/unit/test_json_repair_contract.py`.
2. `UiGate.gate` returns a surface only when `A2UIValidator` reports ok after pruning; `resample` lists invalid component ids (≤ `max_resamples`), and pruned parents drop the dangling references.
3. Progressive: canvas *k* is validated with `final=False` and `prior=` the components already accepted on the surface (forward references are warnings), renders the reachable subset with `final=False`; the final canvas is validated with `final=True`; `repaired` counts fixer edits.
4. `edu` catalog (`local_astra/ui/schemas/edu/catalog.json`): Math, Markdown, Table, Chart, Timer/Progress, Flashcard, AnnotatedImage, Steps — validated with the custom-catalog hook (`test_a2ui_schema.py::test_custom_catalog_extends_any_component_and_topology` is the pattern).
5. HUD renders surfaces and returns `astra.ui.action`; a quiz answer round-trips into the Conductor as `UiAction`.
6. Q11 metrics (validity rate, repairs per surface, resamples per surface) are logged per turn.

## Amendments (2026-09-13, rulings on the test-author's six ambiguities, plus toolchain facts)

**A1 — "held, not rendered" does not apply to the UI channel; C3 stands.** A truncated canvas
renders its reachable, validated prefix with `final=False`. The UI-channel guarantee is narrower
than the speech one: nothing that fails validation is emitted, and incomplete components are
excluded — but a partial *surface* is shown and morphed, because progressive render is the point.
A `final` canvas that arrives truncated is pruned-and-rendered the same way, not withheld.

**A2 — a cycle yields no surface.** Per C2's literal text, pruning is defined over schema-invalid
components, and a cycle of valid components is a topology failure, so the gate returns no surface
and the report names the cycle. Do not break cycles heuristically.

**A3 — `surface_id` is `f"{surface_id_prefix}-{turn_id}"`**, and the gate rewrites the model's
`surfaceId` inside the messages to match, so the renderer keys on one stable id per turn.

**A4 — a re-sent `createSurface` for a surface this turn already created is not an error**; treat
it as idempotent when threading `prior=`. The reference implementation the test-author built
tripped on exactly this.

**A5 — "valid" in C1 means parseable.** Strict parse first; the fixer runs only when it fails, so
`repaired == 0` for well-formed JSON that is merely schema-invalid.

**A6 — criteria 4, 5, 6 are not covered by `test_ui_gate.py` and are split out:** the `edu`
catalog (criterion 4) gets `tests/unit/test_edu_catalog.py`; the renderer round-trip (criterion 5)
waits on the HUD transport from T-0008; criterion 6 (Q11 metrics) is untestable as written until a
named `TurnRecord.extras` key exists — name them here before any test: `ui_repairs`,
`ui_resamples`, `ui_valid` (bool per canvas).

**Toolchain (measured 2026-09-13):** node 18.19 / npm 9.2. `@a2ui/lit@0.11.0` installs, but does
**not** import under node 18 (`Unexpected token 'with'` — import attributes). That is node's parser
only: **esbuild bundles it cleanly** (756 KB ESM, `engines: node>=18`), and Chrome 147 runs the
result. So the renderer is built with esbuild, no node upgrade, no Vite. `scripts/hud_shot.sh`
takes headless screenshots for visual verification without a display.

**Ownership: this task and T-0011 both claim `hud/**` verbatim**, and T-0008 is being planned
against the same tree. Until the orchestrator narrows all three to specific paths, the implementer
for this task works on `local_astra/conductor/ui_gate.py` and `local_astra/ui/**` **only** — the
renderer half waits.

## Rulings after review (2026-09-13, verdict REVISE — both sides)

**A7 — A3's rewrite half stands, scoped to the one surface the gate emits.** The renderer keys on the
`surfaceId` *inside* the messages, so an un-rewritten `lesson_1` re-mounts and morphs turn 9's surface
in turn 10 — the exact failure A3 exists to prevent. The gate rewrites `surfaceId` in every emitted
message to `surface_id` (`f"{prefix}-{turn_id}"`). A canvas that creates more than one surface keeps
the first `createSurface`'s surface and drops the others' messages, naming them in `problems`
(v1 is single-surface; a second surface is a spec question, not a merge). `test_ui_gate.py:30`
becomes equality modulo `surfaceId`; `test_surface_id_differs_between_turns` must inspect the ids
*inside* the messages, not the envelope.
**A8 — an id-less invalid component is dropped by index, never the whole surface.** Today it
survives pruning, fails `validate_messages`, and takes 38 components down with `resample=()`. Ruling:
`prune_invalid` drops it, it appears in `problems` (not `resample` — nothing to re-request), the
surface is still emitted.
**A9 — single-child containers are restored like list-children ones.** A `Card`/`Button`/`Modal`
dropped on canvas *k* for a missing child is re-emitted when the child arrives on canvas *k+1*
(delta discipline), matching the `children: [...]` path. Track dropped-for-missing-child components
so `_restore_references` can re-check them.
**A10 — C3's wording is corrected to the implementation:** the gate emits every validated component,
not only the root-reachable subset (unreachable ones are inert in the renderer). Docstring and C3
agree on that; no behaviour change.
**Test gaps to close (test-author; each reviewer mutation currently survives):**
T1 grounding — use the `"id":"root"` cut (ungrounded fixer invents `Divider`/`axis`; grounded strips
to `{"id": "root"}` → pruned → `resample == ("root",)`); mutation `grounded = list(messages)` must go
red. T2 fixer fallback — feed *malformed* JSON whose repaired array violates the derived schema at the
top level so the `ValueError` path is actually reached; mutation "delete the salvage step" and
"narrow the except" must go red. T3 one end-to-end salvage test on `fixer_schema` (a bad enum value
is stripped, log non-empty). T4 A2 pinned — a cycle yields **no** surface and names the cycle; a
heuristic cycle-breaker must fail. T5 progressive morph — a two-canvas delta sequence where the
parent is re-sent with the completed `children` list, plus the A9 case; deleting
`_restore_references` must go red. T6 A7/A8 as above. Follow-up (not this task): `check_topology`
recursion at ~1500 chained components — pre-existing in `a2ui_schema.py`.

**A11 (after the T1–T6 test pass) — salvage never rewrites a component that already validated,
and grounding covers every leaf type.** Schema-guided salvage of one invalid component today also
rewrites its *valid* neighbours with defaults (`ChoicePicker.value: {"path": "/answers/q1"}` →
`[]`, plus `filterable`/`displayStyle` the model never wrote), and `_grounded` strips only string
leaves, so a destroyed data binding reaches the renderer. Ruling: (a) a component that validates
against the catalog before salvage is passed through byte-identical; salvage runs only over the
components that failed; (b) `_grounded` applies to all leaf types — a non-string leaf must equal
the parsed original at that path or the key is dropped. C1's wording "any `ValueError` from the
fixer falls back to unguided repair" is corrected: with an array top level the reachable fixer
failures are `Unresolvable` and `KeyError`; the `ValueError` branch is documented as unreachable-
by-construction, not deleted (the docstring says so). A8 clarification: `ok` may be `True` with a
non-empty `problems` (the same shape as the idempotent-`createSurface` forgiveness); `problems`
names the index in any of the `a2ui_schema.py` conventions.
