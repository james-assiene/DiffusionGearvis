- **Header:** brand, the turn-state pill, Share, Mute and a Settings control.
- **Left column:** the existing spoken, you-said and shown panes.

The theme is resolved in this order: a valid stored setting, otherwise the system scheme, followed live. The A2UI surface is re-themed only through the `--a2ui-*` properties the vendored bundle already reads.

Nothing about what the page receives, sends, validates or voices changes. No wire format, protocol message, reducer, panel JavaScript or vendored file changes. The only new JavaScript is the theme module.

The denoising area shows real per-step canvases or an empty state, never a placeholder animation. The conductor does not relay the plugin tap to the page today: no `astra.canvas.*` message appears among the 465 `wire.out` records of the 2026-10-20 session. So the empty state is what ships here; see H-T128-4.

6. **Theme resolution order.** The preference is one of `system | light | dark`, stored under the key `astra.hud.theme`. The page always ends with `<html data-theme>` set to `light` or `dark`, and with `color-scheme` set to match. Resolution rules:
   - **(a)** a valid stored `light` or `dark` wins over the system scheme;
   - **(b)** a missing value, `system`, or any other value resolves from `matchMedia("(prefers-color-scheme: light)")`;
   - **(c)** while the preference is `system`, a change of the system scheme re-themes the page within one frame, with no reload. While it is `light` or `dark`, a system change does nothing;
   - **(d)** choosing `system` in the control removes the override, and the page re-resolves at once.

   (Human choice 3.)
