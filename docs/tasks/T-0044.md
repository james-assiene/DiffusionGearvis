## Goal

The Conductor has a whole shown channel — `<a2ui>…</a2ui>` fences in `llm_client.split_segments`, a validate-and-repair `ui_gate`, a vendored `@a2ui/lit` renderer, an `astra.ui.surface` wire message, `ui_valid` in the turn record — and the model has never been told it exists. The only instruction in the system prefix is `SPOKEN_STYLE`'s "If you also show something, put it in the ui channel, never in speech": no fence, no JSON shape, no component names, no rule about when to use it, no size limit. So the model narrates that it is showing something and emits prose; no `ui` segment is ever produced, the gate is never called, and `ui_valid` stays `null` — the log line that made this diagnosable. After this task the cached system prefix carries a compact, budgeted A2UI instruction block: the exact fence, one minimal example that is *validated by the same validator the gate uses* (so prompt and gate cannot drift), the component names the active catalog and the HUD bundle actually support, and the rules (show only when showing helps, never mention the fence in speech, JSON only inside the fence, one surface per turn, finish the fence inside one canvas). The block's presence, its shape and its cost are asserted, and a live eval over the engine says how often three "show me …" requests really produce an accepted surface — and that a plain question still produces none.

## Acceptance criteria

1. **The block is in the cached system prefix, exactly once, and nowhere else.** `PromptBuilder.system_message()` contains the A2UI block; no other message of `prefix()` or `full()` contains any part of it, and neither does the query-dependent suffix (docs/02 §2.2 prompt layout; `.claude/rules/conductor.md`: everything up to the frame is the cached prefix, memory/state/transcript come after). Checkable: substring search over every message of a built prompt, count == 1, and the message index is 0.
2. **Prompt and gate cannot drift: the example validates through the gate's own validator.** The literal example payload inside the block is accepted by `local_astra.ui.a2ui_schema.A2UIValidator` (`validate_text(...)` reports `ok`, topology clean) *and* by the real `UiGate` when it arrives as a `ui` segment — i.e. an example that the gate would reject cannot ship (docs/12 §1.1; T-0010 criteria 1–3). No second copy of the schema, no hand-written "example JSON" that is only checked by eye.
3. **Only components that exist are advertised.** Every component name the block names is in `A2UIValidator().component_kinds` (today: the A2UI v0.9.1 **basic** catalog, 18 kinds) **minus** the ones the HUD cannot render or must not fetch: `AudioPlayer` (excluded from the vendored bundle, `hud/vendor/MANIFEST.md`) and the URL-fetching media components (`Image`, `Video`) — the HUD asserts zero non-loopback requests (CLAUDE.md loopback rule, T-0024). A test compares the advertised set against the validator's set so that when the `edu` catalog (T-0010 C4: `Math`, `Markdown`, `Table`, `Chart`, `Timer`, `Flashcard`, `AnnotatedImage`, `Steps`) lands, this test goes red and the block is updated in that task. **Negative:** `Table`, `Flashcard`, `Math`, `Chart` are *not* advertised today — advertising a component the catalog does not define makes every surface that uses it get pruned, which is the same `ui_valid`-shaped failure with a different cause.
4. **The fence and the one-canvas rule are stated verbatim.** The block contains the fence markers taken from `llm_client.UI_OPEN` / `UI_CLOSE` (a test asserts identity with those constants, not a retyped `<a2ui>`), states JSON only inside the fence, one surface per turn (the gate rewrites `surfaceId` and drops second surfaces — T-0010 A3/A7), never naming the fence in speech, and that the fence must be **opened and closed inside one canvas**: `split_segments` is called with `in_ui=False` per SSE chunk and one chunk is one committed canvas (llm_client amendments B7/M7), so a surface that straddles a canvas boundary has its tail classified `answer`. This is the most likely live failure mode and the block's "keep it small" rule is what prevents it.
5. **The block's size is bounded, and the token number is the engine's.** (a) Fast suite: the block is ≤ 2 000 code points, asserted with the number and its provenance in the test — a structural change-detector, explicitly **not** a token claim (T-0005 B10 deleted character-based token estimation; nothing in `local_astra/` counts tokens). (b) GPU (`/launch`): the engine's own count of the block is ≤ **600** tokens, measured as the difference in `usage.prompt_tokens` (or vLLM's `/tokenize`) between the system message with and without the block, reported with the full regime; a measurement over 600 shrinks the block or gets its own `docs/tasks/` entry with the reason (CLAUDE.md: no threshold moves without one). `Budget.max_prompt_tokens` (14 336) and `ANSWER_HEADROOM_TOKENS` (2 048) are **unchanged**: the block is spent out of the prompt budget, not out of the answer's headroom (T-0020 criterion 1, ruling A5).
6. **`fit()` is unchanged and never trims the block.** The ladder (T-0020 ruling A1: history pixels → memory hits → whole turns) is untouched; with the block present a representative full prompt (3 history turns, 4 images, 3 memory hits, transcript) still returns `fits=True` under a `measure` that reports the budget, and at a budget of 1 token the result is `fits=False` with the system message — block included — still present and the user's turn intact. The system message is the floor; it is not a rung.
7. **The prefix stays byte-identical between turns and between sessions.** Two `PromptBuilder`s built from the same config, and two consecutive turns of one builder, produce the *same* system message bytes (the prefix cache is the reason `<|think|>` is a session setting and thinking is never toggled — CLAUDE.md "Observed mistakes"). Consequence to be named in the implementation's report and in the PROGRESS Runs line: the first turn after this merges misses the prefix cache once, for every session, by construction.
8. **A fenced canvas still becomes a surface end to end.** The existing fake-LLM session row `tests/unit/test_session_record.py::test_q11_fields_are_present_for_a_turn_that_produced_a_surface` (canvas with `<a2ui>` → `astra.ui.surface`, `ui_valid is True`, `ui_repairs == 0`) stays green **unedited** — this task changes the prompt, not the plumbing. Referenced here as the regression pin, not rewritten.
9. **Live eval (gpu, via `/launch`).** `tests/eval/test_a2ui_prompt_live.py` runs four cases against the live engine through the real `PromptBuilder` + real `VllmClient` + real `UiGate`: three positives — "show me a table of the first five prime numbers and their squares", "make a flashcard for the word *ephemeral*", "illustrate the fractions one half and three quarters" — and one negative, "what is the capital of France". Per positive case, at n = 3: at least 2 of 3 runs produce a `ui` segment that the gate turns into a surface with ≥ 1 accepted component; a case with 0 of 3 fails the row. Per run the harness records `ui` segment count, canvases spanned by the fence, `ui_repairs`, `ui_resamples`, tokens in the surface (the X11 tokens-per-surface measurement) and the whole regime. **Negative case:** 3 of 3 runs produce no `ui` segment and no `<a2ui>` anywhere in the answer text — a surface on "what is the capital of France" fails the row, and the fix is the block's wording (the spec), never the assertion.
10. **Docs.** `docs/02-architecture.md` §2.2's `prompt_builder.py` bullet names the A2UI instruction block as part of the cached system prefix (with its size bound); `docs/03-test-plan.md` §8 gains one eval row (**Q12 *A2UI channel uptake***: surface rate on show-me requests, no-surface rate on plain questions, canvases per surface, tokens per surface — the row X11 reads) beside Q11. A line in the task/PR notes that the per-turn session log (T-0043) is the diagnostic for a future miss: `ui_valid: null` means no `ui` segment reached the gate; `ui_valid: false` means it did and failed.
11. **Negative, whole-system.** `SPOKEN_STYLE` and `CLOSE_THE_THOUGHT` keep their current wording and are still present in the system message (`.claude/rules/conductor.md`: the prompt always instructs closing the thought; `tests/unit/test_prompt_budget.py:212` pins it); `local_astra/conductor/session.py`, `ui_gate.py`, `llm_client.py`, `a2ui_schema.py` and `hud/` are byte-identical; no new runtime dependency (no tokenizer, no `transformers`); `DEFAULT_SYSTEM_PROMPT` in `session.py` is not edited; the fast suite gains no new I/O at import time on the turn path.

## Implementation notes

- **Where the block lives.** A new `local_astra/conductor/ui_instructions.py` holding the block as a module-level **literal** string (plus the example payload as a literal), joined into `PromptBuilder.system_message()` after `SPOKEN_STYLE`. Do **not** generate the block from `A2UIValidator` at import time: `prompt_builder.py` is documented as pure and deterministic, the validator reads vendored schema files through `importlib.resources`, and — worse — a generated block would silently change the cached system prefix whenever a vendored schema changes. A literal plus an equality test (criterion 3) gives the same no-drift guarantee and makes the change visible in a diff.
- **The catalog is the basic one today.** `A2UIValidator().component_kinds` = `Button, Card, CheckBox, ChoicePicker, Column, DateTimeInput, Divider, Icon, Image, List, Modal, Row, Slider, Tabs, Text, TextField, Video, AudioPlayer`. There is no `edu` catalog in the code (T-0010 C4 is open), so `Table`/`Flashcard`/`Math`/`Chart` are *not* available; `Text` carries simple Markdown and `Column`/`Row`/`List`/`Card`/`Tabs`/`ChoicePicker` cover a table-ish layout, a flashcard-ish card and a quiz. The requests in the eval ("a table of…", "a flashcard…") must therefore be satisfiable with basic components; if the model insists on `Table`, that is data for T-0010 C4, not a reason to advertise it.
- **Child references.** `child_list_props = {Row: children, Column: children, List: children}`, `single_child_props = {Card: child, Button: child, Modal: (trigger, content)}`; the gate defers a container whose required single child is missing (T-0010 A9) and prunes references to components that have not arrived. The example must have `root` present and every reference resolvable in the same payload — a forward reference in the *example* would teach the model exactly the shape that costs a resample.
- **One canvas.** Lean profile canvas is 256 tokens and `split_segments` is called with `in_ui=False` per chunk (llm_client B7/M7), so the whole fence must fit one committed canvas. Keep the example to a handful of components and say so in the rules; docs/12 §1.1's "progressive render across canvases" is the *gate's* capability, not something the client's fence tracking currently supports. Name this contradiction in the report rather than papering over it.
- **Budget consequences to state in the report.** The block costs the same tokens on every turn, is inside the cached prefix (so it is prefill-cheap after the first turn of a session and never re-paid per canvas), and shrinks the usable history budget by its size out of 14 336. First turn after merge = one cache miss per session, by construction.
- **Loopback.** Nothing in the block may invite a remote URL (no `Image`/`Video`/`AudioPlayer`, no example URL): the HUD page renders whatever the surface says and the suite asserts zero non-loopback requests.
- **Rules that bite here:** `.claude/rules/conductor.md` (prompt layout, prefix must tokenise identically between prefill and final request, thinking is a session setting, the thought-closing instruction is always present); `.claude/rules/tests.md` (no tautologies — "the block contains the string the implementation put in it" is vacuous; expected values are hand-written or come from the validator as an independent oracle); CLAUDE.md (never voice uncommitted text; the shown channel is validated before rendering).
- `mypy --strict` on `local_astra/`, `ruff` line length 100. The block is text; keep it readable in the source (the reviewer reads it as English, and the model reads it as instructions).

## Ambiguities (decide before `/implement`; each one names who decides)

1. **Which catalog the prompt teaches.** The request named the `edu` catalog (Math, Markdown, Table, Chart, Timer, Flashcard, AnnotatedImage, Steps); the code has only the basic catalog — `edu` is T-0010 C4 and unimplemented. This task teaches the **basic** catalog (criterion 3) because teaching components the gate prunes reproduces the bug with a different cause. *Decider: the planner has ruled this way; a reviewer who wants `edu` first must reorder T-0010 C4 before this task.*
2. **A surface that needs more than one canvas.** `llm_client` deliberately does not carry the fence state across chunks (B7/M7), while docs/12 §1.1 describes progressive rendering across canvases, and docs/12 §1.3 estimates 300–500 tokens for a small surface — i.e. two canvases at 256. The prompt's "finish the fence in one canvas" is a workaround for a real spec gap. *Decider: reviewer/human. If the eval (criterion 9's adversarial row) shows the model routinely needs two canvases, the next task changes `llm_client`'s fence rule (the behaviour), not the eval.*
3. **The 600-token ceiling.** Chosen, not measured — roughly 4 % of the 14 336-token prompt budget. If the engine says the block is over, shrink it (drop the example to the bare minimum) rather than raise the ceiling silently. *Decider: the measurement, then a `docs/tasks/` note.*
4. **Character↔token relation.** There is no local tokenizer (and adding `transformers`/`tokenizers` just for a test would be its own decision), so the fast suite bounds characters and the GPU row bounds tokens. *Decider: reviewer — if a local tokenizer is wanted, it is a dependency task, not this one.*
5. **Where the block sits in the system message.** Appended after `SPOKEN_STYLE` (last instruction, minimal diff). If someone wants it before `CLOSE_THE_THOUGHT`, that is a wording experiment (X-series), not a criterion.
6. **Whether to say anything about `astra.ui.action` round-trips** (the model gets `[ui] <event> <context>` user turns back, docs/02 §2.2 / T-0028 A19). Left **out** of the block for budget reasons; the model usually copes because the transcript is self-describing. *Decider: the eval's follow-up — if clicked surfaces confuse the model, a second sentence is cheap.*
7. **Eval harness shape.** Specified as `PromptBuilder` + `VllmClient` + `UiGate` directly (fewest moving parts, isolates the prompt). A full-`Session` live run is the human's demo and is recorded in PROGRESS *Runs*, not asserted here. *Decider: test-author may argue for the session path if the direct path cannot reproduce the defect.*
