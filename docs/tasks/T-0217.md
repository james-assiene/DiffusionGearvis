# T-0217 — the settings panel's relaunch hint does not suggest a flag already in force

**Status:** merged 2026-10-31 at 5843fe09 (tip a2726997); was in progress (impl f1e29889 + tests 3880d790 combined; rulings R-28: criterion 4 excludes the parametric, engine and viewport rows; R-29: the inverse rule is live only) (2026-10-31, pre-release reliability pass; T-0213 known limit after R-10..R-12, R-10a).

## Goal

A one-way catalog command is sent as the relaunch text even when its effect is already the value in force: `--search off` when search is off, `--browser headless` in a headless session, `--wait-tool off` when the wait tool is off, `--page-overview` when it is on, `--action-echo pixels` when the echo is already pixels, `--no-web` when web is off, `--filler-clips` when filler clips are on, `--tools live` in live. Copying such a hint changes nothing.

After this task the server (`Session` settings state, the R-12 relaunch block) sends the flag that sets the other value when one CLI flag does that, and sends no relaunch text when none does. The panel already renders `relaunch: null` without a box (`hud/src/settings/model.js` `relaunchText`) and needs no change.

## Acceptance criteria

1. In live, for each one-way row whose value in force equals its command's effect, `item.relaunch` is the inverse flag text. Proposed table (the implementer confirms each flag exists in `cli`'s argparse; a flag that does not exist means that row falls under criterion 2 instead):
   - search `"off"` → `--search ddgs`
   - browser `"headless"` → `--browser headed`
   - wait_tool `False` → `--wait-tool on`
   - page_overview `True` → `--no-page-overview`
   - action_echo `"pixels"` → `--action-echo model`
   - filler_clips `True` → `--no-filler-clips`
2. **R-27 (amends R-10):** with no single flag that sets the other value (browser_web `False`; tools `"live"` in live), `item.relaunch` is `None`. The kind stays `relaunch`.
3. When the value in force differs from the command's effect, `item.relaunch` is exactly today's R-12 text.
4. Every relaunch text the server can send parses with `cli`'s argument parser together with `session --tools live` (no argparse error), and parsing it gives the other value.
5. Negative: parametric rows (`max_tool_steps`, `max_tool_steps_web`), `engine` (`--profile <profile>`) and `browser_viewport` (config text) are unchanged. Outside live, R-10a's `not_here` and `tools` → `--tools live` are unchanged. No change to the wire model, `kind`, `changeable`, `pending`, the catalog entries as the panel receives them, or the HUD.
