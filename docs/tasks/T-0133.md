## Goal

The T-0132 locked A/B at 2ccff41 measured these arms:

| Arm | Success | Hit rate | Pass-2 done p50 / p95 |
|---|---|---|---|
| 1120/off | 65/100 | 0.977 | – |
| 1120/on, 1120 crop | 66/100 | 0.994 | 724 / 2099 ms |
| 1120/on, 280 crop | 64/100 | 0.994 | 352 / 1531 ms |

Regime: lean, CL 256, 48 steps, thinking on, NVFP4 rev 2ea8372, vLLM 0.29.0, `vllm.sh` 806da12, 5 tasks × 20 per arm, order seed 0, concurrency 1, engine unseeded, STT down, headless Chromium 156 at 1280×800.

Its pre-registered rule gave the label **"reground off"**: (b) chose the 280 crop, then (a)'s success gain over off was under 5/100.

The human ruled on 2026-10-22 (James): live mode defaults to **1120 visual tokens with ReGround off**. ReGround stays available through `--reground` and the profile key `reground = true`.

This task does two things:
- **The flip.** An unset ReGround in live resolves off, from source `default`. Everything said about it on screen follows: the `grounding` line, the tools-line suffix and the turn-line dict.
- **The crop default (H-T133-1, proposed).** When a user turns ReGround on at a 1120 main budget and sets no pass-2 budget, the crop budget defaults to 280. The A/B found the 280 crop matched the 1120 crop on success (64 vs 66/100) and hit rate (0.994 for both), at half the pass-2 latency.

## Implementation notes

- **Keep the default in `cli`** (T-0132 R-f). `Session`, the rigs and the GPU harnesses take explicit values, and none of them changes.
- **Key the crop default on resolved values only:** the mode, the ReGround bool and the main budget int. Never key it on `profile.tools` or on a `*_from` source. `reground_visual_tokens_cli_refusal` already looks only at the `flag` and `profile` sources, so the 280 default can never trigger it. Keep it that way.
- **Reuse T-0132's second-client path.** It builds the client only when the budgets differ, and `Session.aclose` closes it (O-3). Add no new client-building code.
- **R-e is untouched.** Desk sessions from turn 2 on usually carry two or more images in pass 2, so the 280 crop applies mainly on the first coordinate turn of a session. In the A/B every turn was fresh (pass-2 images: `{1: 162}` and `{1: 154}`). Say so in the docs/02 delta. Do not "fix" it here: H-T132-2 confirmed R-e.
- **The `grounding` line code path** and the `Grounding` dataclass shape are unchanged. Only the values change.
- **No characters-per-token arithmetic** (B10).
- The implementer never edits `tests/`. No heredocs to get around a blocked Write, and never export `GIT_DIR` or `GIT_WORK_TREE` for test runs.
- **Landmine:** `T.fake_clients` records every `VllmClient` into `calls.vllm_kwargs`. With A5-approved, `[-1]` is the crop client, and R1 handles that. If an implementation constructs the crop client *before* the main client, `session.llm is built.made[0]` reddens. Build the main client first, as at BASE.
