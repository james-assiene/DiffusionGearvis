## Goal

At c94f529 the T-0136 detector tolerates thin changes per 8×8 cell (rule 3′: at most `UNDERLINE_ROWS` = 2 rows, inside a pointer's row band, at any x).
- **The hole.** A one-glyph change, such as a price digit, a count, or ▸→▾, changes only 3–4 array rows. When those rows straddle a cell-row boundary, each half is 2 rows or fewer, so both halves are tolerated and the change reads `no visible change`.
- **Measured cost.** On T-0136's test split it lost 3/51 change groups (0.059, bar 0.05). In real Chromium it loses 1–3 of 16 vertical offsets per kind (regime below).
- **This task.** It replaces rule 3′ with rule 3″, which measures thinness over the vertical run of changed rows in a cell column, across cell boundaries. Rule 3″ only ever counts more than 3′ does. It re-tunes on dev only and measures A2-5's bars on a fresh probe page that no tuner has seen. That page holds every 0–15 px vertical offset of each small-change kind, plus long and two-line underlines at the same offsets.
- **Unchanged for the user.** `--action-outcome` stays off by default. In opted-in sessions the label text and vocabulary are unchanged; only which of the 12 strings a given frame pair yields can change.

**B-2. Rule 3″ (replaces 3′ in A2-3; per H-T153-1, default shown).**
- **Run marking.** For each cell column, mark array row y when that column holds a changed pixel in row y. Changed means after rule 2's thresholds and before rule 3's count, so cells under `MIN_CELL_PIXELS` contribute marks too.
- **Runs.** A *run* is a maximal set of marked rows in which successive marked rows are at most `RUN_GAP_ROWS + 1` apart. Its height is last − first + 1.
- **Tolerance.** A cell that rule 3 marks changed is tolerated only when both of these hold:
  - (i) rule 3′ tolerates it, unchanged;
  - (ii) every marked row inside the cell belongs to a run of height ≤ `UNDERLINE_ROWS`.
- **`RUN_GAP_ROWS`** is a new calibrated integer in {1, 2, 3, 4}. The premise is 2: it bridges the `+`→`−` crossing bar and stays below the line gap of two-line links.

## Implementation notes

- **Pixel-first:** no DOM in the detector. Offsets, families and `changes` rects are for labellers and tests only.
- **Vectorise.** Take `rows_hit` per cell column over the full height (`padded.reshape(gh*c, gw, c).any(axis=2)`), find the runs with a cumulative-sum or diff pass over the bridged mask, then map run heights back to cells. Keep it inside A2-6's budget.
- **Thresholds.** Marks use rule 2's thresholds as they stand, so a HOVER_DELTA-thinned half (B-1) is not fixed by the rule shape. Report it; do not lower HOVER_DELTA below its dev band to chase it.
- **Expected cost of the fix.** An underline that JPEG ringing widens to 3 rows across a boundary used to be tolerated by luck (2+1). Under 3″ it now counts. The U-* sweeps measure exactly this.
- **Labelling order.** The labels commit precedes any detector run on page c, and the constants commit precedes any test run. The reviewer checks both from commit order.
- **Hooks:** the implementer never edits `tests/`. No heredocs into the repo, and never export `GIT_DIR`/`GIT_WORK_TREE`. CPU only, loopback only. No browser builds during a scheduled demo.

## Open questions

- **H-T153-1 (rule shape). Default: (a) rule 3″,** vertical runs per cell column with gap bridging, gated by 3′ so the change is monotone.
  - **Why:** it is the smallest generalisation of 3′. It closes straddles at every offset, keeps 1–2-row underlines and two-line links tolerated, and its effect is provable against c94f529 (B-N).
  - **Alternatives:**
    - (b) thinness of the change's bounding box within the band: rejected. A two-line link's box spans both lines, and unrelated changes in one band merge.
    - (c) rule 3′ on two grids offset by half a cell, tolerated only when both tolerate: equivalent for contiguous runs, cheaper to state. It bridges gaps only inside a cell.
    - (d) the height of connected components: most faithful, but it needs a labelling pass (scipy is not a dependency) and still splits `+`→`−`.
- **H-T153-2 (page-c split). Default: stratified alternation by class × family.**
  - **Why:** dev sees the mechanism at some offsets, and test still holds about half of every family at offsets no tuner saw.
  - **Alternative:** hold out whole families (3 of the 6 S-SMALL families to test). That is a stronger generalisation claim, with less dev evidence.
- **H-T153-3 (s-ghost). Default: not addressed.** It stays stress and report-only, measured per offset, and documented in B-9.
  - **Why:** the ghost border's side edges are tall in every cell. A thin-column tolerance would also hide the gated focus outline at the click, and HOVER_DELTA above 40 loses the icon recolour (dev band 32–64).
  - **Alternative:** a separate task after a desk check, if ghost buttons matter on T-0138's suite.
- **H-T153-4 (if the bars fail). Default: stop and ask James.** No re-tune against test, and c94f529's rule stays on main (group B is not merged).
- **H-T153-5 (who runs the eval). Default: as H-T136-A2b-5.** The reviewer and the verifier run `uv run pytest tests/eval/test_t0153_calibration.py -q -m gpu -rA -s` on CPU under the hook's token, without `/launch`. It spends no GPU time and writes nothing under `artifacts/`.
- **H-T153-6 (re-running T-0136 D). Default: no.** D's A/B result is about c94f529's label. Any later task that makes `--action-outcome` a default re-measures at its own tip.
