# T-0082b — Pass-2 replay: run pass-2 cells against the stored pass-1 rows of an earlier artifact

**Status:** done (2026-10-10; verified at 8fe86eb; merged with T-0084a on main); planned 2026-10-09 · **Blast radius:** medium (one reviewer) · **Branch:** `T-0082b-twopass-replay` from `main` after T-0082a
merges · **Depends on:** T-0082a.

## Goal
Measure the `</cc>` strip on the engine without sending pass 1 again. The driver gets a replay mode that:
- reads a pinned earlier artifact;
- re-routes its stored pass-1 texts with the current router (T-0082a `rescore`);
- sends only the pass-2 requests of the given cells, built exactly as a live run would build them.

Every pass-2 result is then paired with the original draft. No new pass-1 sample is drawn, so the stage-1 gate does not apply.

## Acceptance criteria
1. **Interface.**
   - `TwoPassConfig(..., pass1_from: Path | None = None, pass1_sha256: str | None = None)`.
   - CLI `scripts/gpu/cd_toolcall.py --pass1-from PATH --pass1-sha256 HEX --cell …`.
   - A new locked script `scripts/locked/t0082_replay.sh --stage dev|test --pass1-from … --pass1-sha256 …`. It follows the t0080 pattern:
     refusals, `make plugin-wheel`, engine-only `services/vllm.sh`, `/health`, the real exit code, `nvidia-smi … || true`.
   - Its out-dir is `logs/t0082-replay-<stage>-<SHA>`, refused if it exists, so a stage runs once per SHA. No `selection-dev.json` is needed.
2. **Refusals before any socket (exit 2, nothing sent):**
   - the artifact sha ≠ `--pass1-sha256`;
   - the artifact's `stage` ≠ `--stage`;
   - the artifact has `stopped` set;
   - a pass-1 row with an `error`;
   - any regime field differing from the current one: system-prompt sha, tools sha, cases sha, `versions_lock_sha256`, `model_revision`,
     `tokenizer_sha256`, or the calibration file shas of the cells' arms;
   - `rescore`'s refusals (T-0082a criterion 10);
   - a dirty tree or commit mismatch (`hardstop.check_tree`).
3. **No pass 1.**
   - The fake server receives zero pass-1-shaped requests: the request count equals Σ over cells of the routed cases' pass-2 requests, plus
     pickers and flushes.
   - The new artifact's pass-1 rows are the re-scored stored rows. They carry `replayed_from` (the sha) and keep their original `wall_ms` and
     prefix fields.
4. **Same requests as live.**
   - Each pass-2 body equals what `pass2_body(pass1_body(case, …), …)` gives for that case in a live run at this commit.
   - Seeds come from the stored `token_ids` and the re-routed `draft_call_text`.
   - Cell order follows R-W `williams_orders(k)`, indexed by the routed count.
   - All of the T-0080b and T-0081b stops apply unchanged: engine, CS, loud error, `join_error`, `seed_*`.
5. **Downstream unchanged.** `derive`, `select` and `report` run on a replay artifact with no code path specific to replay. The regime line
   names the replayed artifact and its sha, and says that pass-1 walls come from that artifact's boot.
6. **Negative.**
   - Live runs are identical to main: bodies, rows, counts.
   - `scripts/locked/t0080_toolcall.sh` is unchanged and its rows stay green.
   - `select`'s rule, tolerances and order are unchanged.
   - Unchanged: `plugin/**`, `conductor/**`, `contracts/**`, `decoding/**`, `toolcall/**`, `thresholds.py`.
   - Loopback only.

## Implementation log (implementer, 2026-10-09, branch `T-0082b-impl` from 78b5698)
- `twopass.py`: `TwoPassConfig.pass1_from`/`pass1_sha256` (default `None`). `run` calls `_replay_source` after `_knobs`/`_cases` and
  before the artifact is opened (so before any socket); it raises `ValueError` on: only one of the two given, a sha mismatch, no regime line
  or no trailer, another `stage`, `stopped` on any line, a pass-1 `error`, a difference in `REPLAY_REGIME_KEYS` (system prompt, tools,
  cases shas) or `REPLAY_VERSION_KEYS` (`versions_lock_sha256`, `model_revision`, `tokenizer_sha256`, against `_runner._versions(None)`),
  a calibration sha of a base arm the cells use (an arm outside the cells is not compared), a `rescore` refusal, and pass-1 case ids that are
  not this stage's cases at `limit` in order (R4). The rows are `rescore(p1_rows, tools, cases)` + `replayed_from` (R7). `_loop` takes
  them as `replayed` and uses the stored row instead of `state.pass1`; the pass-2 body is still built from `pass1_body` and `_Run.pass2`
  is unchanged. A dirty tree or commit mismatch is the existing `check_tree` exit-2 result. The replay regime gains `pass1_from`,
  `pass1_sha256` and `pass1_source` (commit, run id, start, limit, cells); a live regime gains nothing. `render_markdown` adds one line per
  replay regime naming the source and its sha and saying the pass-1 (and e2e) walls come from that artifact's boot (R5).
- `scripts/gpu/cd_toolcall.py`: `--pass1-from`/`--pass1-sha256` (both or neither, else exit 2); `REPLAY_CELLS` (R2, written out) unless
  `--cell`; `--selection` refused on a replay; after a replay no `selection-dev.json` is written at either stage (R6) and the exit code is
  the run's. Live paths unchanged.
- `scripts/locked/t0082_replay.sh` (new, mode 644 as `t0080_toolcall.sh`): the t0080 pattern with `--stage`, `--pass1-from`,
  `--pass1-sha256`; refuses a missing flag or file and a sha mismatch (`sha256sum`, R1) before the git/port/container checks; out-dir
  `logs/t0082-replay-<stage>-<SHA>`, refused if it exists; passes no `--cell` and no `--selection`. `t0080_toolcall.sh` is byte-identical.
- Read-only check of the real T-0082c source (`logs/t0080-toolcall-test-0dc9134/…-toolcall-test.jsonl` regime): cells are exactly
  `REPLAY_CELLS`, both calibrations recorded, `limit` null, so the locked script's defaults match it. Whether the other regime fields still
  match at the replay's commit is the driver's refusal to make, not checked here.

## Rulings (2026-10-09/10)
- **R9 (F1; orchestrator).** A calibration entry that is **absent** from the source for an arm the replay uses is accepted. The regime
  records it under `calibration_absent_in_source: [arms]`. A **present** entry whose sha differs is still refused. Pass-1 rows do not depend
  on calibration; only the T-0082c pairing (criterion 7) does, and it uses arms the source actually ran. Test rows cover both directions on
  a stage-1-shaped source replayed under `REPLAY_CELLS`.
- **R10 (F2; HUMAN, 2026-10-10: "warm the cache first"). Amends criterion 3.**
  - Before a case's first pass-2 request, the replay sends exactly one **warm-up**: the case's own `pass1_body` with `max_tokens: 1`. That
    is the identical prompt pass 1 had, so the engine's prefix cache is in its live state.
  - Each warm-up is logged as a row `{"pass": "warmup", "case", "wall_ms", prefix counters}`. It is excluded from `derive`, `select` and
    every policy table, and counted in the trailer.
  - Only routed cases get a warm-up. No-tool cases send nothing.
  - "No pass 1" now means: no pass-1-shaped request other than these warm-ups, which carry `max_tokens` 1 and are never scored.
  - The report shows pass-2 walls by position within a case (first cell after the warm-up vs later) as a check.
- **R11 (F3; orchestrator).** `pass1_max_tokens` and `enable_thinking` join the refused regime keys. `pass2_max_tokens`, `whitespace` and
  `max_states` are recorded, not refused; T-0082c's pairing compares them.
- **R12 (F4; orchestrator).** The missing-trailer refusal and the case-order (R4) refusal are pinned by the test-author. `--selection` with
  a replay stays refused. That is harmless and needs no row.

## Implementation log, R9–R12 (implementer, 2026-10-10, on b9c5a8b)
- R9: `_replay_source` records an arm whose calibration entry is absent from the source in the regime's `calibration_absent_in_source`
  (always present on a replay, `[]` when none). A present entry with another sha is still refused.
- R10: `_Run.warmup` sends the case's `pass1_body` with `max_tokens` 1 (a shallow copy; nothing else changed) before a routed case's
  first pass-2 request, on a replay only. It writes a `{"pass": "warmup", "case", "error", "wall_ms", prefix counters}` row after the
  case's pass-1 row. An `http_error`/`timeout` on a warm-up is an engine stop, as on pass 1; no row pins this. The trailer gains
  `warmup_requests` on a replay only. `derive`, `select` and the tables read only `pass` 1/2, so warm-ups are outside them with no new
  code. `report` gains `pass2_wall_ms_by_position` (`first`/`later` `_dist` over the pass-2 rows in artifact order per case) and
  `render_markdown` one line. This report key and markdown line also appear for live artifacts, because it is the comparison T-0082c needs;
  live runs (bodies, rows, trailer) are unchanged.
- R11: `pass1_max_tokens` and `enable_thinking` are added to `REPLAY_REGIME_KEYS` (current values `PASS1_MAX_TOKENS` and `True`).
- R12: no code change.
- **Blocked, 8 rows red: a test-fake defect.** `tests/cd/fakes/vllm_server.py::_handle` treats every POST without CD keys and with
  `max_tokens == 1` as an E9 flush (`self.flushes`) and returns before `self.requests.append`/`self.script`. An R10 warm-up has exactly
  that shape, so it never reaches `srv.requests` or `sc.sent`. The red rows: `test_no_pass1_shaped_request_but_one_warmup_per_routed_case`,
  `test_each_warmup_precedes_its_cases_first_pass2_request`, `test_the_request_count_is_the_pass2_hand_count`,
  `test_a_calibration_of_an_arm_outside_the_cells_does_not_refuse`, `test_r9_an_absent_calibration_entry_is_accepted_and_recorded` (the
  replay is accepted and records `["perstep_mar_qargmax"]`; only the request count is short by the 5 warm-ups), and the three `test_cli_*`
  rows that call `_warmup_cases`. Suggested fix for the test-author: treat a body as a flush only when it carries no case text
  (`ts.case_of(body) is None`, the flush prompt), so a warm-up is recorded and scripted like pass 1.
