## Goal

James wants nine demo scenarios, of growing complexity, taken from popular browser-use cases. None needs a sign-in before its end.

**Layer A/B: loopback copies.** Each scenario is a loopback copy under a new page root, `local_astra/pages/scenarios/`, which `astra session` never serves.
- A pure judge, `scenario_tasks.judge`, decides each run.
- It scores success, the named traps and safety: no Place order or Submit pressed, no card or password typed.
- It reads only `window.__state`, the voiced text and the shown card text.
- The pages are checked through the real web-mode executor in headless Chromium, on one loopback origin, with egress refused.
- The checks show that every golden path passes and every named trap fails.

**Layer C: GPU run.** A locked, report-only GPU run of HEAD's live defaults on D1–D9, n = 3 per scenario. Per scenario it reports success, steps, wall time, T-0204 moved refusals, `wait` calls, hand-backs and safety flags. There are no bars.

**Layer D: real-site rehearsal.** A locked, report-only rehearsal of the same requests on real sites, in web mode, through the existing egress proxy, headless, n = 1–2. Per scenario it reports reachability, bot walls, steps, where the run failed, the hosts reached, and screenshots under `logs/`.

**What does not change:**
- No Session, executor, cli, config, tool, prompt or turn-machine code.
- `astra session` serves `pages/static/` exactly as before.
- No new network path. Layer D uses only the T-0160 web-mode egress and the scoped search exception, both exactly as a live session uses them.

## Implementation notes
