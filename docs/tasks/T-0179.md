### Group B: one fresh retry after a degenerate abort, then the honest clip (CPU)

**B-1. When to retry.** All of the following must hold:
- `degeneracy_guard` is on;
- a T-0142 or T-0142b trip happened in a `generate` (step 1) or `tool_step` request;
- no answer commit of the tripped attempt was submitted to the machine (thought commits only);
- this machine request id has not already been retried for degeneracy;
- the attempt is still current. An abort or barge-in wins, and nothing is sent.

Out of scope, unchanged: ReGround pass 2, `tool_repair`, prefill, the captioner, and the T-0172 `announce_reask` request, which keeps T-0172 B5.

**B-2. The resend.**
- The tripped attempt is already aborted. Release it, then issue a fresh id under the same machine request id.
- Log a note: `{"what": "degenerate request: retrying once", "request_id", "failed_attempt_id", "attempt_id", "phase", "step"?, "segment"}`.
- Log a new `llm.request` with the identical `Prompt` and options; the body equals the first attempt's except for the attempt id.
- Send no seed and add no sampling option. A per-request seed is HTTP 400 in vLLM 0.29.0, and the engine is unseeded, so the resend is fresh sampling (H-T179-2).
- Use fresh accumulators.
- Keep one live generate at a time (P4): the resend goes out only after the release.

**B-3. A clean retry.** The turn continues exactly as if the retry were the first attempt.
- The turn line's extras gain `degenerate_retries: 1`; the key is absent when there was no retry.
- `degeneracy_guard.tripped` counts both tripped requests, as T-0142b A5 defines it.

**B-4. Exactly once.** If the retry trips too, the turn ends the T-0142 way: `tool_loop_end = "degenerate"`, then `LlmError`. That makes exactly 2 engine requests for that machine id. In addition, the B-6 clip plays.

**B-5. Bounded latency.**
- The retry shares the machine's `llm_timeout`, which is never re-armed or extended (the T-0172 rule).
- If the timer fires during the retry, the turn ends through the existing timeout row: no clip from this task, and no third request.
- At most one degenerate retry per machine request id. At most 3 engine requests per step, counting a T-0171 resend; the two retries are independent.

**B-6. The honest clip.** On the B-4 end only, T-0178's clip mechanism plays `PlayClip(kind="lost_thread")` after `hud.error`.

- It is a pre-rendered asset (`<data_dir>/clips/lost_thread.s16le`), played with `source=""`. It never enters history, the `astra.spoken` text or `TtsSpeak.source`.
- `ClipKind` gains `"lost_thread"`. The emission rides on whatever field or row T-0178 adds for `out_of_steps`; the test-author pins its shape from T-0178's merged code.
- With no asset installed, it plays zero-length, under the existing clip honesty rule. The turn line records `system_clip: "lost_thread"` either way.

The clip asset is rendered by `scripts/render_clips.py` into the data dir; that supersedes H-T179-3's "commit it".
