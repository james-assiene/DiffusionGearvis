## Goal

Every session that shares a screen sends its images at 1120 soft tokens per image unless the user says otherwise, in `off`, `dry_run` and `live`.
- `grounding_of` resolves the main budget as the `--visual-tokens` flag, else the profile's `visual_tokens`, else 1120 (`"default"`), in every mode.
- `--visual-tokens 280` restores the old cost.
- ReGround resolution, the pass-2 budget and everything live-specific are unchanged.
- Group B measures, at 280 against 1120 on the 5090, what the change costs a conversational screen question and how much reading it buys. The result is report-only.

## Implementation notes

- **Unconditional (H-T183-1).** The budget is one per-request field set on the client (`llm_client.py:266`).
  - On text-only bodies it encodes nothing, and text prefix-cache blocks are keyed on tokens.
  - A frames-only default would need per-request logic in `llm_client.py`/`session.py`, both owned elsewhere, and it could split a prefill from its generate.
  - P0 guards this.
- **Prefix cache.** The budget is constant per session, so prefill, generate and history images agree.
- **The window.** Worst case is 4 × ~1092 ≈ 4.4k image tokens, inside `fit` against 14 336. In `dry_run` with the loop, the T-0132 A6 step k > 1 gap now applies at 1120 too. It fails loudly; P1 measures it.
- **Chunked prefill.** `--max-num-batched-tokens 4096` fits one 1120 image plus a typical prompt. Multi-image turns are split over scheduler steps, as live has done since T-0132, and B measures the latency.
- **The captioner (H-T183-3)** keeps the session budget. Its input is the full frame and its output is searchable memory text; it runs only after 10 s idle and is aborted on onset.
- **Landmines.**
  - Never route the budget through `LlmOptions`/`vllm_xargs`.
  - Do not add it to `Regime`.
  - Refusals happen before anything is constructed.
  - The default is printed on the tools line.
