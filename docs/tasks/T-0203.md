## Goal

**Evidence.** Over the three sessions there were 75 executed `type_at` calls with `press_enter`:
- 21 came back with no `navigated` key. `navigated_since` returned `None`: a main-frame navigation request was still pending at the read, and nothing had committed since the mark. These calls returned in 244–877 ms.
- 13 came back `False`. Four of them are on Amazon, took 500–670 ms, and repeat the pre-search after-frame:
  - 203137 seq 8581, 10118 and 18583;
  - 201813 seq 17300.

  After seq 18583 the model typed the same search again, and that one navigated.
- 41 came back `True`.
- Two `click_at` calls also had no key (203137, 617 and 915 ms).

The model then said "I cannot see the search results yet", or typed the search again. In 203137 (t2) it re-typed several times, until T-0137's repeat guard refused it.

**Root cause (confirmed in source at 4e64375c).** `PlaywrightDriver.settle()` (`runtime.py`) waits for `domcontentloaded` and then two animation frames on the active page. While a navigation request is pending, the old document is still the active page's document. It has already loaded, so the wait returns at once, and the read and the screenshot happen before the commit. T-0200's blank check does not catch this, because the frame is not one flat colour.

The driver already knows:
- that the navigation is pending: that is the `None` from `navigated_since`;
- when a committed document has not reached `domcontentloaded` yet (`_PageNavigation.awaiting_dcl`).

**What changes.**
- When the driver can tell that the action's navigation is still in flight, the action follows it before the screenshot:
  1. wait for the commit, driven by the driver's own listeners;
  2. then wait for that document's `domcontentloaded` and two animation frames;
  3. all bounded by `NAV_FOLLOW_S` and the call's remaining budget.
- The executor then reads `navigated` again, so the response says "new page loaded" when the page committed.
- An Enter action that read `False` checks once more, synchronously, after its screenshot. If a navigation started during the screenshot, it is followed and the screen is captured again.
- An action that does not navigate keeps BASE's driver calls. No fixed wait is added anywhere.

## Acceptance criteria

### Group A — `PlaywrightDriver.follow_navigation` (runtime.py; nothing calls it until B)

- **A1. The method.** `async def follow_navigation(self, mark: object, timeout_s: float) -> FollowResult`, where `FollowResult = Literal["none", "loaded", "ended", "timeout"]`, exported.
  - The navigations it follows are:
    - requests of the active page's main frame that started **after `mark`**;
    - commits after `mark` whose document has not reached `domcontentloaded` yet.
  - When the active page became active after `mark`, all of its requests count.
  - It returns `"none"` at once, with no Playwright call and no await on the page, when:
    - there is nothing to follow;
    - `mark` is not this driver's mark, or comes from another generation;
    - there is no active page.
- **A2. It waits for the commit, not a timer.**
  - The wait is woken by the driver's existing listeners: `request`, `requestfinished`, `requestfailed`, `framenavigated`, `domcontentloaded` and `download`. It does not poll.
  - After the commit it waits for the new document's `domcontentloaded` and evaluates `_RAF2`, each bounded by the time left.
  - A navigation that replaces the document during that wait is waited for again while time remains (a redirect, or a reload like the T-0200 WAF case). This uses the same `_navigated_away` rule as `settle()`.
  - The result is `"loaded"`.
- **A3. It ends when the navigation ends without a commit.** It returns `"ended"`, within one event-loop turn of the event that ended it, when:
  - the followed request fails (`requestfailed`);
  - or a download starts on the page;
  - or the page closes.

  Afterwards `navigated_since(mark)` is `False`, not `None`.
- **A4. It is bounded.**
  - It always returns within `timeout_s` + 0.1 s.
  - When it returns `"timeout"`, `navigated_since(mark)` is still `None` (never a guessed `False`).
  - A Playwright `Exception` inside it ends it with `"timeout"` if time is up, otherwise `"ended"`. It never propagates.
  - `CancelledError` propagates.
- **A5. A stale entry costs nothing.** A main-frame request that started before `mark` and never finished makes `follow_navigation` return `"none"` immediately. `navigated_since` keeps T-0174's answer (`None`), byte-for-byte.
- **A6. Nothing else moves (negative).** These are unchanged:
  - `settle()`;
  - `navigation_mark()`'s observable use;
  - `navigated_since()`'s answers for every T-0174 row;
  - `main_frame_urls()`;
  - the listeners' effects on `commits`, `requests` and `awaiting_dcl`;
  - the launch arguments;
  - every existing unit and browser row.

  The only script it evaluates is `_RAF2`, so T-0174's `test_no_new_page_script` stays green when the method is exercised. No CDP call.

### Group B — executor wiring (executor.py; after Merge T-0202-b and Merge T-0203-a)

- **B1. Follow after the settle.** This applies to an executed `click_at`, `type_at` or `press_key`, including the overview-frame click/type and the start-page `goto`.
  - The executor calls `follow_navigation` once when:
    - the T-0174 mark was taken;
    - the read after the settle (`_navigated`) gives no `bool` or gives `True`;
    - the driver's class has `follow_navigation`.
  - The timeout argument is `min(NAV_FOLLOW_S, deadline − now)`.
    - `deadline` is T-0200's (`ACTION_TIMEOUT_S − CAPTURE_RESERVE_S` from the call start).
    - `NAV_FOLLOW_S = 3.0` is a module constant, read at call time.
  - It then calls `navigated_since` once more. That second answer is `resolved["navigated"]` (the key is set only from a `bool`).
  - The order is: settle → front (T-0198) → navigated read → follow → navigated re-read → checkout read (T-0192 A4) → capture.
- **B2. The late-start check (Enter only).** An action that sent Enter checks once more after its capture when its navigated answer was `False`.
  - "Sent Enter" means `type_at` with `press_enter`, or `press_key` whose chord contains `Enter`.
  - The check is one more synchronous `navigated_since(mark)`. If that answer is not `False`, the executor:
    1. calls `follow_navigation` with what is left of the shared follow budget, never past `deadline`;
    2. reads `navigated` again;
    3. makes a second checkout read; `resolved["checkout"]` is the OR of the two reads;
    4. captures again through `_capture("action", deadline)`, so T-0200's blank re-capture still applies.
  - Only the kept (second) capture is registered (`_own`, `_extents`, `_latest`, `frame_after`). The first capture's phash is not an own frame: a `click_at` carrying it is refused.
  - If the re-capture's first screenshot raises, the first capture is kept and registered, and the outcome is still `executed`.
- **B3. Budget.**
  - The two follows share `NAV_FOLLOW_S` in total per call.
  - No follow, re-read or re-capture turns an executed action into `failed` or `timeout`: a `follow_navigation` that raises `Exception` is swallowed, and the capture keeps T-0200's reserve.
  - One `execute()` still takes at most `ACTION_TIMEOUT_S`.
- **B4. Cancellation.** A `CancelledError` in either follow propagates. Nothing is registered, and `latest_frame` is unchanged.
- **B5. Note.** Each follow that did not return `"none"` calls `on_note` (T-0200's hook) with exactly this, and nothing else:
  `{"what": "live frame: followed navigation", "path": "action", "result": "loaded"|"ended"|"timeout", "late": bool, "waited_ms": int}`
  - no URL, host, title or phash;
  - a raising `on_note` is swallowed;
  - no new `resolved` key.
- **B6. Negative: actions that do not navigate are unchanged.** These keep BASE's exact driver call sequence, `ToolOutcome`, `resolved`, bytes, phash and timing (no sleep, no `follow_navigation` call):
  - a `click_at`/`type_at`/`press_key` whose first read is `False` and that sent no Enter;
  - every `scroll`, `wait` (T-0202), `page_overview` and `google_search`;
  - every action on a driver class without `follow_navigation`;
  - dry-run and `off`.

  An Enter action that reads `False` twice adds exactly one synchronous `navigated_since` call and no Playwright call. T-0202 B10's same-document `t0202_slow_results.html` row is unchanged.
- **B7. Spec change, not a test workaround (supersedes T-0174 B1-1b (c)).** A navigation pending at the after-settle read is followed. The key is absent only when it is still pending after the follow, or the driver cannot follow.
  - `test_t0174_navigated_browser.py::test_navigation_pending_at_read_is_absent` is re-pinned by the test-author: the held response is released only after `NAV_FOLLOW_S` (monkeypatched small), and the key stays absent.
  - A sibling row releases it inside the budget and gets `True`.
- **B8. Real Chromium on loopback.** All rows use T-0203's own delayed loopback server.
  1. Native form, Enter on the search box (`type_at` + `press_enter`), results served after 600 ms:
     - the after-frame's results region is the results colour, not the search page;
     - `resolved["navigated"] is True`;
     - wall time ≤ 0.6 s + 1.5 s;
     - the row first shows at BASE (follow disabled) that the after-frame lacks the results.
  2. `click_at` on a link to the same delayed page: the same three assertions.
  3. A 302 to the delayed results page: followed, `True`, results shown.
  4. A response held past `NAV_FOLLOW_S` (monkeypatched to 0.5 s):
     - `executed` within `NAV_FOLLOW_S` + 1.5 s;
     - no `navigated` key;
     - one note with `result: "timeout"`.
  5. A navigation that fails (a target outside `allowed_origins`, aborted by the route): `"ended"` in ≤ 0.3 s, and `navigated` is `False`.
  6. Negative: Enter in a box whose `keydown` calls `preventDefault`, and a click on an inert area:
     - the Playwright-level spy (`wait_for_load_state`, `evaluate`, `screenshot`) records exactly BASE's calls;
     - `follow_navigation` is never awaited.

## Implementation notes

- **Pixel-first.** The follow reads only:
  - what the driver's own page listeners recorded;
  - Playwright's `wait_for_load_state`;
  - the `_RAF2` evaluate.

  It uses no CDP.
- **Wake-up, not polling.** Sync listeners wake the follow through an `asyncio.Event` or a future owned by the driver. Never `asyncio.sleep` polling.
- **The mark gains a request-sequence watermark** (`_NavigationMark` lives in `runtime.py`). Entries recorded before it are not followed (A5).
- **Registration.** B2 needs a capture that is kept or discarded before it is registered. Build and register the `Frame` once, from the kept capture.
- **Checkout reads.** The checkout read stays after the last follow. B2's second read is ORed, because `main_frame_urls()` drains.
- **`NAV_FOLLOW_S`** was chosen, not measured. It reuses T-0200's 3 s action cap. The worst case stays inside `ACTION_TIMEOUT_S` = 8 s because every follow is clipped to `deadline`. Do not raise `ACTION_TIMEOUT_S`.
- **Tests.** No tautological asserts. Expected pixels come from the fixture colours, chosen by hand.

- **Browser rows:** Playwright and Chromium from `services/versions.lock`, headless, 1280×800, not web mode, loopback only; a server delay of 600 ms.
- **Suites:** the fast suite, serial and with `make fast-parallel`. `make browser` once, with its wall time beside BASE's (same box, load < 2, clean tree).
