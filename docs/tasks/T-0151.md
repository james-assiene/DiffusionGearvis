## Goal

**What T-0150 showed.** Arm B's step 1 carried two images, the overview and then the live frame. S4 went from 0/20 to 20/20, but S5 ("add the cheapest item to the cart") went from 13/20 to 0/20.
- The model clicked at model units y ≈ 935: the tea towel button's position in the overview. The executor read that against the live screen.
- The model located the button correctly. Overview y 935 maps to page y 1141; arm A's correct click after scrolling was at page y 1140. The only defect was which image the coordinates referred to.

**The human ruling (James, 2026-10-24).** On long pages, step 1 sends only the whole-page picture: one image and one coordinate system. A step-1 coordinate action on it is read in overview coordinates and translated: overview → page → scroll the target into view → act at the viewport point. From step 2 on, normal screen frames return. The cap is about 2 screens.

This task adds `Session(overview_frame=True)`, opted into with `astra session --overview-frame` or the profile key `overview_frame`. It is live only and off by default. When on, at most once per turn and at step 1 only:
- **Capture:** the session takes T-0150's whole-page capture.
- **Placement:** when the page is more than 1.05 and at most 2.0 screens tall, the overview **replaces** the current frame in the step-1 request, followed by a fact label.
- **Coordinates:** the executor registers the overview as an **overview frame**, an own frame with page geometry. A `click_at`/`type_at` on it is translated to page coordinates, scrolled into view and dispatched at the viewport point.

What does not change:
- tools stay v1, and nothing new is spoken or stored;
- off is byte-identical to BASE;
- a locked 2-arm A/B (arm A the live default, arm B the default plus `--overview-frame`) then decides adoption.

**Measured scope (planner, 2026-10-24, at e124573).**
- **Setup:** headless Chromium 156 through Playwright 1.64.0, 1280×800, DSF 1, the real `BrowserToolExecutor` and `PlaywrightDriver`, loopback start-page server, n = 1 per probe.
- **deals.html:** content 1220 CSS px (1.525 screens). The overview is 838×798, so 1 overview px is 1.53 CSS px (x and y), and 1 model unit is 1.28 CSS px in x and 1.22 in y. Each "Add to cart" button is 120.6×41.2 CSS px: 78.9×26.9 overview px, or 94×34 model units (94×51 on a live frame). The tea towel button's centre is at overview units (160, 933), page y 1138.
- **A 2.0-screen page** (a scratch copy of deals with two more deals and `min-height:1600px`): content 1600, overview 640×800, 1 overview px = 2.0 CSS px, 1 model unit = 1.60 CSS px in y. A button is 60.3×20.6 overview px, or 94×26 model units. The 16 px body text becomes 8 px and the 20 px headings 10 px. The PNG is legible to the planner; the model's reading at 1120 tokens is not measured.
- **2.8 screens** (2236 px): the overview is 456×800, buttons 14.7 overview px tall, and body text about 5.7 px. This is why the cap is 2.0.
- **Token cost (an estimate, not a measurement):** the processor resizes images to the token budget, so an overview costs about the same as a frame (T-0150 P7: 1,116 tokens). One token then covers about 37 CSS px on a side at 1.525 screens and about 43 at 2.0, against about 31 for a 1280×800 frame. Effective precision is therefore about 1.2× coarser at 1.5 screens and 1.4× at 2.0. The observed GPU click error was 2 model units (935 against the 933 centre), well inside the button's ±17-unit half-height.
- **The translation works in real Chromium, using existing driver methods only.**
  - Clicking deals.html at overview (160, 933) and at (160, 935): page y 1138/1141, one `scroll_by(0, 420)`, `settle()`, `scroll_y` = 420 (clamped to content − viewport, and still 420 after 300 ms), click at viewport y 718/721. Both gave cart `["cotton tea towel"]`.
  - On the 2.0-screen page, unclamped scrolls landed exactly at 484 and 800 after `settle()`, and the click added the intended item.
- **Reach:** as T-0150's P8, only S4 and S5 (deals.html) get an overview; S1–S3 fit. No S1–S5 page exceeds 2.0 screens, so the A/B does not exercise the cap; CPU and browser tests do.

## Acceptance criteria

### Group A1 — executor (CPU and browser)

**A1-1. Registration (`BrowserToolExecutor.overview_frame_of(key) -> Frame | None`).**
- It reads the overview named by an executed `page_overview`'s `resolved["overview"]` from the same once-only store as `overview_of`: whichever reads first takes it.
- It returns the frame and registers it as an **overview frame** only when all of these hold:
  - the capture was not clipped;
  - the captured image's CSS width equals the viewport width;
  - the driver's generation and `page_serial` are the capture's;
  - `latest_frame` is still the own frame that was latest when the capture was taken.
- Otherwise it returns `None` and the frame is dropped.
- **The registered geometry:** generation, image width and height, page serial, page width and height in CSS px (the captured size), viewport height, the capture's `content_height`, and the phash of the latest own frame at capture.
- **Kept apart:**
  - the overview frame is in a registry of its own, never in `_own`, `extent_of` or `latest_frame`;
  - the registry is capped like `_MAX_OVERVIEWS`;
  - its phash is salted as own frames are (T-0140 A3).
- `overview_of` (the T-0140/T-0150 path) is unchanged and never registers anything.

**A1-2. Mapping.**
- A `click_at`/`type_at` whose frame geometry (phash, `WINDOW`, width and height) is a registered overview frame of the current generation is planned against the page: `P = (to_pixels(x, page_width_css), to_pixels(y, page_height_css))`.
- Argument validation, the guard, control characters and `bad coordinates` are as at BASE.

**A1-3. Refusals before dispatch** (`refused`, nothing dispatched):
- **Stale picture:** `latest_frame` is no longer the frame recorded at capture: `the screen changed since the whole-page picture; take a new frame` (`OVERVIEW_STALE`).
- **Page changed size:** a metrics read before dispatch fails, or its `content_height` or `viewport_height` differs from the capture's: `the page changed since the whole-page picture; take a new frame` (`OVERVIEW_PAGE_CHANGED`).
- **Existing rules:** the closed, restart, page-serial and frame-page rules exactly as for screen frames, with the same reasons.

**A1-4. Scroll, check, act.** With `S` the current `scroll_y`, `H` the viewport height and `C` the content height:
- **Target in view** (`S ≤ P_y < S + H`): no scroll.
- **Otherwise:** exactly one `scroll_by(0, dy)` with `dy = clamp(P_y − H/2, 0, C − H) − S`, then `settle()`.
- **The moved-page check:** two metrics reads that must be equal, with an unchanged `content_height` and `S' ≤ P_y < S' + H`. If the check fails, the outcome is `failed` with `the page did not scroll to the point; nothing was clicked` (`OVERVIEW_NOT_REACHED`). Nothing is clicked, and the post-action frame is captured (`frame_after`), because the scroll was dispatched.
- **The action:** click at `(P_x, P_y − S')`; for `type_at` the text and Enter follow as at BASE. Then `settle()` and capture.
- **`resolved`:** `x_px`, `y_px` (the viewport point dispatched), `page_y_px`, `scrolled_px` (signed `S' − S`), `frame_after` and the BASE event keys.

**A1-5. Action strings (echo).**
- **Without a scroll:** exactly the BASE strings. With `echo="model"` they are in the call's own overview units (T-0134 A2, "never converted back"); with `"pixels"` they are the viewport pixels dispatched.
- **With a scroll:** the BASE string prefixed by `scrolled down by N px and ` or `scrolled up by N px and `, where `N = |S' − S|` as an int.
- **Example:** echo model on deals gives `scrolled down by 420 px and clicked at (160, 935)`.

**A1-6. Pixel-first.** Geometry comes only from the CDP layout metrics and the captured image size; no page text, DOM, title or URL is read.

**A1-7. Probe (browser, real Chromium).** On deals.html:
- `overview_frame_of`, then `click_at(160, 933)` and, on a fresh page, `click_at(160, 935)`. Each is `executed` with `scrolled down by 420 px and clicked at (160, 93x)`, `scroll_y` 420 afterwards and `window.__state.cart == ["cotton tea towel"]`.
- `click_at(160, 308)` (the teapot) is `executed` with no scroll prefix and cart `["ceramic teapot"]`.

**A1-8. Negative.**
- **Unchanged for screen frames:** every BASE behaviour of the executor (action strings, `resolved`, refusals, `latest_frame`, `extent_of`, `overview_of`); the T-0111c, T-0134 and T-0140 executor and browser rows stay green unedited.
- **Byte-identical over BASE_A1..HEAD:** `computer/runtime.py`, `computer/fence.py`, `toolcall/**`, `conductor/**`, `contracts/**`, `tests/fakes/**`, `pages/**` and `services/**`.

### Group A2 — session, cli, config, docs (CPU)

**A2-1. `Session(overview_frame=True)` refuses misuse.** It raises `ValueError` in each of these cases:
- the kit's mode is not `live`;
- with `auto_overview=True`;
- with a kit offering `page_overview`;
- with `reground=True`, because pass 2 crops the current frame around the call's point, which on an overview frame is in another coordinate system.

**A2-2. Trigger and capture: T-0150 A1, reused.**
- **Same mechanics:** the same moment (after the live snapshot lands and the unlabelled step-1 prompt is built), the same chaining with `_live_snap`, the same `AUTO_OVERVIEW_TIMEOUT_MS` bound and timeout note, once per turn (the over-long retry re-uses it), and outside the model's tool path.
- **Refused before capture** (nothing dispatched): the final user message has no `ImagePart` (a blind turn, or a frame riding on a history image), or more than one `ImagePart` (a T-0059 multi-frame turn: one image, one coordinate system).
- The `max_images` refusal does not apply, because nothing is added.

**A2-3. The decision.** Each turn that sends step 1 gets exactly one outcome:
- **`shown`:** the capture is `executed` with an image, `resolved["screens"] ≤ OVERVIEW_FRAME_MAX_SCREENS` (2.0, in `session.py`), and `overview_frame_of(key)` returns a `Frame`.
- **`too_tall`:** screens > 2.0. The picture is read through `overview_of` and discarded, never registered.
- **`fits`:** the capture fitted.
- **`failed`:** an executor `failed`, the timeout, an exception, or an image-less outcome or a `None` registration.
- **`refused`:** the session's A2-2 refusals and the executor's own.

Every outcome except `shown` sends step 1 byte-identical to the same turn with `overview_frame=False`.

**A2-4. Placement.**
- **The step-1 request as sent** is `swap_newest_image(unlabelled, overview)`, then `label_current_image(…, OVERVIEW_FRAME_LABEL.format(screens=s))`. Its final user message therefore carries exactly one image, the overview, followed by the label, and no live frame.
- **The label** is exactly: `[This screenshot is the whole web page, about {screens:.1f} screens tall, scaled down to fit; the browser screen shows only part of it. click_at and type_at coordinates refer to this image, and the browser scrolls to the point before it clicks.]`
- **No T-0134 label** is placed on that request, and its record has no `live_label` key. This holds with `LiveFeedback` on or off; the overview label is placed either way.
- **Retry and repair:** the over-long retry and the repair of step 1's call (which re-sends `pass1_prompt`) carry the same overview and label.
- **`turn.loop_base` and `unlabelled_prompt`** keep the live frame and never hold the overview.
- **Nowhere else:** the overview is in no step ≥ 2 request, prefill, caption request, history, `Episode`, HUD message or continuation.

**A2-5. Identity and freshness.**
- **Registration:** the session registers the overview under its capture identity in `_frame_geometry`, with the geometry's phash being the executor's. It never enters the turn's frames, the turn line's `frames`, history or an `Episode`.
- **The step-1 call:** its `frame` and `frame_identity` are the overview's (newest image as sent).
- **B9 refuses as stale only if:** `frame_identity` is not the browser's newest own frame **unless** all three of these hold: the call is at loop step 1; `frame_identity` is this turn's overview identity; and the browser's `latest_frame` capture identity is still the live frame the overview replaced.
- **Everything else** is the BASE B9 rule with `FRESHNESS_REASON`. That includes a step ≥ 2 call carrying the overview identity, and an overview identity after a takeover snapshot.

**A2-6. Step 2.**
- **What it shows:** the B8 screen as at BASE, built from `loop_base` with `show_current_image` and the T-0134 label.
- **Payload and label:** the settled step-1 payload says `screenshot: "updated"`, and the label opening is `LABEL_UPDATED`, whatever the action did. The image the model saw at step 1 was the overview, so the next image always differs from it.
- **The step-1 action string** reaches the continuation exactly as the executor returned it.

**A2-7. Never spoken, never stored.** These reach no `TtsSpeak`, history, HUD message, `Episode` or `machine.events()`, and no narration is added:
- `OVERVIEW_FRAME_LABEL`;
- the overview image;
- the capture's action string.

**A2-8. Logging.**
- **Turn line:** with `overview_frame=True`, every live turn line gains `overview_frame: {"shown", "fits", "too_tall", "failed", "refused"}`. The counts sum to 1 on a turn that sent step 1 and to 0 otherwise.
- **Request record:** every `llm.request` carrying the overview gains `overview_frame: {"phash", "screens", "width", "height"}` (generate, retry and step-1 repair).
- **Tool records:** a step-1 call on it has `"frame_kind": "overview"` in its `tool.call` record, and its `tool.result` carries the executor's `resolved` as at BASE.
- **Off:** no key is added. There is no new span or log kind.

**A2-9. cli and config.**
- **Config:** `config.LIVE_DEFAULT_OVERVIEW_FRAME = False` and the profile key `overview_frame: bool | None = None`, with TOML booleans only. These are refused at load:
  - the key with `tools != "live"`;
  - the key together with `auto_overview = true`, `page_overview = true` or `reground = true`.
- **Flags and resolution:** `--overview-frame` / `--no-overview-frame`. `cli.overview_frame_of(profile, args, mode) -> OverviewFrame(overview_frame, overview_frame_from)`, with sources `flag`, `profile` and `default`.
- **Exit 2, before anything is built:**
  - outside a resolved `live` mode, naming `live`;
  - the key of a live profile whose mode `--tools` overrode;
  - on together with the auto overview, the page overview or ReGround from any source, naming both.
- **Wiring:** `Session` gets `overview_frame=True` only when on; off passes no keyword.
- **Startup line:** in live only, `astra session: overview frame: off (default)` / `on (flag)` / `on (profile)`, right after the `auto overview` line and before the regime line, `--dry-run` included.
- **Tools:** `tools_version` stays v1.

**A2-10. Docs.** One `docs/02-architecture.md` §5 paragraph, `**Spec delta (T-0151).**`, covering A1-1…A2-9. It must state:
- the measured geometry and precision, with their regime;
- the 2.0 cap and the normal-frame fallback above it;
- the deliberate exception to T-0140's "never an own frame";
- the B9 exemption;
- the prefix-cache effect: step 1 diverges at the image, so it re-prefills about 1.1k overview tokens plus the suffix instead of T-0150's frame plus overview;
- that inner scroll containers are not covered;
- that headed Chromium may flash at the start of every long-page turn.

**A2-11. Negative.**
- **Off (the default):** request bodies, turn lines, session-log records, executor action strings and HUD messages are byte-identical to BASE_A2 in every mode.
- **Unchanged behaviour:** the T-0150 `--auto-overview` and T-0140 `--page-overview` behaviour. All T-0150 and T-0140 session, cli and differential rows stay green, unedited except the Q-2 re-pins.
- **Frozen files:** `LIVE_TOOL_GUIDANCE` (768a973b…), `tools_v1.json` (bbfc53cc…) and `tools_v1_overview.json` (8048bdb7…) are unchanged.
- **Byte-identical over BASE_A2..HEAD:**
  - `toolcall/**`, including `loop.py`;

  - `turn_machine.py`, `speech_gate.py`, `tool_executor.py`, `prompt_builder.py`, `llm_client.py` and `degeneracy.py`;

- Adoption is checked first, and boundaries compare with a 1e-9 tolerance.

## Implementation notes

- **Facts, not instructions.** The only new model-facing text is `OVERVIEW_FRAME_LABEL` and the scroll prefix of the action string, and both describe what happened or what the image is.
  - `LIVE_TOOL_GUIDANCE` stays frozen, and so does its "scroll to see the rest of the page" sentence. The tools stay v1, and `click_at`'s "a point of the attached screen frame" covers the overview frame.
  - If the A/B gives `no change`, that is the finding.
- **No new loop helper.** `loop.swap_newest_image` then `loop.label_current_image` produce A2-4 exactly. If the multi-frame rule cannot be expressed with them, stop and report; do not edit `loop.py`.
- **Order inside `_run_generate`:**
  1. `unlabelled`;
  2. the decision, once per turn, cached on `_TurnLog` (keep the `Frame`, because the store reads once);
  3. if `shown`: swap, then the overview label, and skip `_live_label` for this request;
  4. otherwise: `_live_label` as at BASE.

  The retry rebuilds `unlabelled` with `drop=1` and re-swaps.
- **Reuse T-0150's capture.** Factor its capture-and-chain into a helper the two modes share. The T-0150 rows are the guard: unedited and green. The two modes are mutually exclusive (A2-1), so one `_TurnLog` cache may serve both, as long as the turn-line keys stay per mode.
- **Registration path.** Call `overview_frame_of` through `getattr`, as `overview_of` is called today; `LiveBrowser` (`session.py`) does not change. For `too_tall`, call `overview_of(key)` to drop the picture.
- **B9.** `_live_stale_frame` is a staticmethod today; it may take the turn. Keep the BASE check for every call outside A2-5's three conditions.
- **Executor.**
  - Keep the overview's capture-time metrics, CSS size and latest-own-frame phash beside its frame in the store, so registration needs no new driver call.
  - Do the A1-4 scroll and click inside the same `ACTION_TIMEOUT_S` block as other actions. Use `_read_metrics` for every read, never `page.evaluate`.
  - `scroll_by` is a mouse wheel at the current pointer position, as the `scroll` tool uses it. An inner scroll container under the pointer would swallow it; the post-scroll check turns that into `OVERVIEW_NOT_REACHED`.
- **Precision is the model's, not the executor's.** At 1.5 screens one model unit is about 1.2 CSS px. The executor adds no snapping or target search. Pixel-first: no DOM lookup to "help" the click.
- **Prefix cache.** The prefill holds the live frame; step 1 swaps it, so the engine re-prefills from the image: the overview (about 1.1k tokens) plus the suffix. B3 prices it. Do not drop the live frame from the prefill: `loop_base`, B9 and step 2 need it.
