## Goal
A pure module, `local_astra/toolcall/native.py`, that the eval and later the conductor import without torch. It:
- parses a native draft (the text after `<|tool_call>`) into the same `{"name", "arguments"}` call the JSON path produces, so the
  unchanged `score.schema_valid`/`score.exact` score both formats;
- names the draft's tool;
- builds the OpenAI `tools` request field.

## Acceptance criteria
1. **`parse_call(text) -> dict | score.ParseFailure`** (QN4).
   - **Accepted shape:** `\s*call:NAME{ARGS}<tool_call|>\s*`, where NAME = `[A-Za-z_][A-Za-z0-9_]*`.
   - **ARGS:** empty, or bare-identifier `key:VALUE` pairs joined by `,`, with optional whitespace around `{ } [ ] , :`.
   - **VALUE** is one of:
     - `<|"|>…<|"|>`, verbatim up to the next delimiter;
     - `true`, `false` or `null`;
     - a JSON number (an int when it has no fraction or exponent, otherwise a float);
     - `{ARGS}`;
     - `[VALUE,…]`.
   - Key order is free.
   - **Distinct failure reasons:** `empty`, `no call prefix`, `bad name`, `no close`, `text after call`, `multiple calls`, `duplicate key`,
     `bare value`, `unterminated string`, `malformed arguments`.
   - It never raises on any `str`.
2. **Oracle agreement.**
   - For every schema-valid v1 call, `parse_call(template rendering)` equals the call, with types preserved.
   - The arguments agree with the vendored vLLM `_parse_gemma4_args` once scalars are rendered to raw text.
3. **`draft_name(draft_call_text) -> str | None`.** Returns the v1 name in `\A\s*call:NAME\{`. Anything else gives None.
4. **`tools_field(tools) -> list[dict]`** = `[{"type": "function", "function": decl} for decl in tools.declarations]`, in file order. The result
   is pure and deep-copied.
5. **Constants.** Exports `TOOL_CALL_OPEN = "<|tool_call>"`, `TOOL_CALL_CLOSE = "<tool_call|>"` and `STRING_DELIM = '<|"|>'`. They equal
   `router.TAGS["native"]` and the tokenizer pieces of ids 48, 49 and 52 (checked in the cd test).
6. *Negative.*
   - The `toolcall/**` import fence holds: no `local_astra.decoding`, torch, numpy or outlines.
   - `router.py`, `score.py`, `tools.py` and `tools_v1.json` are byte-identical.
   - `route()` output is unchanged for every input.

## Rulings at activation (orchestrator, 2026-10-09, from the test-author's report at 08ff8a4)
- **B1 (reason precedence).** An invalid bare token (`01`, `+1`, `1.`, `.5`, `NaN`, an unquoted word, a quoted `"up"`) is `bare value`. A
  structural break (an empty value, a missing `,`, an extra `}`) is `malformed arguments`. The existing rows that accept either reason
  stay as they are.
- **B2 (precedence for unclear inputs).**
  - The absence of a complete `<tool_call|>` anywhere wins: `no close`. This covers truncated arguments (`call:click_at{x:1,`) and a partial
    close tag.
  - A name that does not match NAME (`call:click-at{`) is `bad name`.
  - An extra `}` before the close is `malformed arguments`.
  - The test-author adds one row each.
- **B3.** `multiple calls` is pinned for a second `<|tool_call>call:…` after the close, as the template renders consecutive calls.
  Sufficient.
- **B4 (whitespace).**
  - `parse_call` allows whitespace between NAME and `{`, and between the final `}` and `<tool_call|>` ("around `{ }`"), but none after
    `call:`.
  - For consistency, **`draft_name` is amended to `\A\s*call:NAME\s*\{`**, so `call:scroll {` gives `scroll`. The test-author adds rows.
  - The template never emits any of this whitespace.
- **B5.** The caller removes the stop text before `parse_call`; a left-over `<|tool_response>` is `text after call`. Note for T-0084c: the
  driver passes the answer channel without the stop.
- **B6.** `[]` is accepted.
- **Process note.** The test-author tried to validate its expectations against a throwaway reference `native.py`. `protect_paths` and
  `guard_bash` blocked that, and it did not work around them. The implementer's first green run is therefore the first validation, and the
  reviewer should look hardest at the hand-written expectations.

## Implementation log
- 2026-10-09, implementer (branch `T-0084b-impl` from `T-0084b-native-parser` at 628cccf). New
  `local_astra/toolcall/native.py`: `TOOL_CALL_OPEN`/`TOOL_CALL_CLOSE`/`STRING_DELIM`, `REASONS` (the ten reasons),
  `parse_call`, `draft_name`, `tools_field`. Imports: `copy`, `functools`, `re`, `sys`, `typing`, plus
  `toolcall.tools` and `toolcall.score.ParseFailure`. `parse_call` precedence: `empty` → `no call prefix` (after
  leading whitespace) → a string-aware scan of the rest that pairs `<|"|>` from the left (`unterminated string` for
  an unpaired delimiter, `no close` when no `<tool_call|>` lies outside a string) → `bad name` (`NAME\s*\{` must
  match right after `call:`) → the arguments, left to right, by an iterative parser with an explicit stack (no
  recursion limit; `[`×200 000 with a close is `malformed arguments`, balanced 200 000-deep nesting parses) →
  after the final `}` and whitespace the close must follow (`malformed arguments` otherwise, B2's extra `}`) → the
  tail: empty, `multiple calls` if it starts with `<|tool_call>` (B3), else `text after call` (B5). A bare token
  runs to whitespace, `{ } [ ] , :` or the start of `<|"|>`/`<tool_call|>`/`<|tool_call>`; it is `bare value`
  unless it is `true`/`false`/`null` or a JSON number (int without fraction/exponent, else float); an empty value
  position, a missing `,`, a non-identifier key and a trailing `,` are `malformed arguments` (B1). Two choices the
  tests do not pin: an integer literal longer than `sys.get_int_max_str_digits()` is `bare value` (so `int()` can
  never raise), and `1e999` parses to `float("inf")` as `json.loads` would. `draft_name` uses
  `\A\s*call:NAME\s*\{` (B4) against the names of `tools.load()` (cached). `tools_field` deep-copies each
  declaration. One tension for the reviewer: B2 says the absence of a complete close wins, but the pre-existing
  row `call:google_search{query:<|"|>weather` expects `unterminated string`; the implementation reports
  `unterminated string` first (the implementation note scans `<|"|>` before structural characters), so that row and
  B2's truncated-argument and partial-close rows all hold.

## Ruling B7 (orchestrator, 2026-10-09, from the implementer's report at 59e9dfb)
B2's "the absence of a complete `<tool_call|>` wins" is amended. **`unterminated string` takes precedence over `no close`**, because the
string scan runs first (as the implementation notes require) and an open `<|"|>` swallows any later close. This is the row pinned at 08ff8a4
(`call:google_search{query:<|"|>weather` → `unterminated string`). B2's other rows (truncated arguments, partial close) are unaffected and
still give `no close`.
Process note: `guard_bash` treats `<`/`>` inside an inline `python -c` string as a redirection. The implementer built probe strings with
`chr(60)`/`chr(62)` to run them. The hook misfired on content rather than enforcing a policy; this is surfaced to the human and added to the
hook follow-ups.
