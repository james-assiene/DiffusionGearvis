# T-0020 — Prompt budget enforcement with the engine's own count, and recovery from a 413/400

**Status:** merged 2026-09-14 (ccad38a; implementation 66c6f02 → cce6ad9 → c5169bd; review + confirmation; 42 task tests; rulings A1–A10)· **Blast radius:** medium · **Depends on:** T-0005 (merged), T-0007 (the session that handles the response)

## Goal
The prompt builder has a declared budget (`Budget.max_prompt_tokens`, 24 000) that nothing
enforces and that exceeds the serving window (`--max-model-len 16384`, T-0014). T-0005 ruling B10
deleted the previous "enforcement" because it was an unmeasured 4-chars/token guess, wholly
untested, and unreachable. After this task the budget is real: it is derived from the engine's
own token count (the prefill's `usage.prompt_tokens`, or a tokenizer the engine agrees with — see
B5/B12 on `stream_options`), it is **below** the serving window, and an over-long prompt has a
recovery path instead of killing the turn.

## Acceptance criteria
1. `Budget.max_prompt_tokens` default is strictly less than the `--max-model-len` in
   `services/vllm.sh`, read from that file by a test — the strict xfail
   `tests/unit/test_prompt_builder.py::test_the_declared_prompt_budget_fits_inside_the_serving_window`
   flips to a pass and its marker is removed.
2. Trimming order is B2's, applied to a **measured** count: oldest history turns first, then
   aged images (each degrading to its caption), then memory hits; never the system message, the
   current turn, or the current frame. Each step is a test with a hand-computed expectation.
3. The count is the engine's, not a local guess: no `chars / 4`, no second tokenizer, unless a
   contract test proves it agrees with `usage.prompt_tokens` on the diffusion path.
4. A 400/413 for an over-long prompt from the engine is handled in `conductor/session.py`: one
   retry after the builder trims one more history turn, then `HudError` + `CommitHistory` — never
   a dead turn with no message.
5. The over-long case is logged in `TurnRecord.extras` with the count and what was trimmed, so a
   later "why did it forget X" has an answer.

## Rulings

- **A1 (2026-09-14, tests landed c8cedc8; implementation queues behind T-0028 for `session.py`).** B2's step (2) (age history images to captions) is unreachable if step (1) drops whole history turns first. Ruling: the ladder is cost-ordered — a history turn's *pixels* go before the turn itself (oldest pixels first, each falling back to its caption per B3), and only then do whole turns go, oldest first; the memory block trims after history pixels and before history turns. Step (2) therefore gets its own test (owed by the test-author before /implement).
- **A2.** The seam is as the tests fix it: `PromptBuilder.fit(*, history, frame, assists, transcript, tutor, memory_hits, frame_text, resolve, measure, drop_history_turns) -> FitResult(prompt, tokens, fits, trimmed)`; extras keys `prompt_over_budget`, `prompt_error_status`, `prompt_tokens`, `prompt_trimmed`.
- **A3.** Pre-emptive trimming stands: a prefill count over the budget trims before the request goes out; the 400/413 path is the fallback for a count the engine did not report (`prefix_tokens == 0` means not reported).
- **A4.** Which status vLLM returns for an over-long prompt is measured by the gpu probe in `tests/contract/test_over_long_prompt_error.py` at group B; until then 400 and 413 are treated alike.
- **A5.** `Budget.max_prompt_tokens` is set so that budget + the profile's `max_tokens` for the answer stays strictly below `--max-model-len` (16384); the number is the implementer's, the bound is the test's. Headroom for the answer is part of the bound.
- **A6 (2026-09-14, review of 66c6f02; REVISE both).** The engine reports one count for the prefix (`PrefillHandle` carries no per-image/per-message cost), so per-rung savings cannot be measured; the implementation therefore trimmed to the floor on a one-token overshoot (100 % of the history for +1 token). Ruling: pre-emptive trimming spends exactly one rung — the oldest history turn's pixels — and sends; the already-implemented 400/413 retry escalates (one more rung, `drop_history_turns=1`) and then errors loudly. Test-author pins the magnitude: at `budget + 1` the sent prompt keeps every history message and loses exactly one image; at a second rejection the turn errors. `fits=False` at the floor is still sent (the engine's verdict is the authority) and recorded in the extras.
- **A7 (test-author).** `tests/fakes/llm.py` returns the same `prefix_tokens` for every prefill, so the per-turn reset of `_prefix_tokens` is unobservable (deleting it stays green): give the fake a per-prefill sequence and pin that a previous turn's over-budget count does not trim a later, fitting turn.
- **A8 (implementer).** The headroom docstring attributes 2048 to a bench that has not run; say it is a chosen headroom pending a bench, with the regime it will be measured under. The `delivered` guard is an equivalent mutant (the real client raises before the first yield) and stays as defence.
- **A9 (2026-09-14, revision c5169bd).** `test_only_the_engines_reported_count_can_trim_before_the_request` (pre-A6) asserts `history_messages(sent) < 4` for a 32768 count on the same fixture where the A6 row asserts `== 4` for 14337; with one engine count and no per-rung cost model the magnitude cannot change the rung, so the old row's assertion is aligned with A6 (all four history messages kept, one image fewer; its other three assertions stand). Accepted from the revision: pixels are spent by history *position* (`prefix(spent_images=…)`), the floor is "the last copy of the current frame's pixels is never spent", and the retry escalates by the dropped turn alone (`max_rungs = 0 if drop_history_turns else 1`). Second correction on this task; a review follows, not a third patch.
- **A10 (2026-09-14, confirmation review; implementation approved, one pin owed).** The floor rule (the last copy of the current frame's pixels is never spent) is unpinned: with one history turn on an unchanged screen the mutated rung is a silent no-op that records "over budget, nothing trimmed". One row with `copies == 1` closes it; the task merges when it lands. Recorded, no change: after a trim the sent prompt diverges from the prefilled prefix at the degraded message (a near-total prefix-cache miss to save one image — the ruling's choice); `prompt_tokens` reads `0` in the extras when the engine never reported a count.
- **A11 (2026-09-14, /launch probe).** The live engine rejects a ~250 k-token prompt with a 4xx in {400, 413} in 0.17 s (pre-scheduling; VRAM unchanged). The row does not print which; the test-author adds the print so `.claude/rules/gpu-services.md` can record the exact status (A4 stays: both treated alike).
