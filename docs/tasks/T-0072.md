# T-0072 — CD per-call cost: device-side δ\* scan, cached stop ids, class-weight pass-through, an op-count budget

**Status:** done (merged at c6574b5; status corrected 2026-10-23 from 'in progress', T-0147 audit: no implementation in flight) · earlier: in progress · **Blast radius:** high (decode-loop math and `cd/sampler.py`; two reviewers) · **Branch:** `T-0072-cd-perf` ·
**Depends on:** T-0067 merged into `T-0062-perstep-cd` (origin: T-0067 ruling S13 and both T-0067 reviews)

## Goal
Every constrained denoise call currently pays for a constrained MAP and δ\*. The T-0067 host cannot see convergence
without a sync (S13). T-0065's `budget.delta_star` loops over L in Python, at about 10 torch ops per position.
Reviewer B counted 166 dispatched ops for a stock call against 709 at CL 16 and 1 207 at CL 64 with CD, which puts
roughly 3 000 launches per constrained slot per call at CL 256. That threatens B13's ≤15 % budget (T-0062 decision
8, T-0071 criterion 2).

This task makes that cost log-depth in L without changing a single output bit:
- δ\* becomes a device-side boolean scan over the per-position transitions.
- The stop-id tensor is cached per device.
- Class weights that are already computed are passed through instead of recomputed.
- A CPU op-count budget and a tier-2 microbench hook give T-0071 something to measure against.

T-0065's numerics (two passes, compensated arithmetic, the fp32 bars) and T-0066's exactness are not touched.

## Acceptance criteria
1. **δ\* scan, bit-identical.** `budget.delta_star` keeps its signature (T-0065 R1). It returns `states` and `empty`
   bit-identical (`torch.equal`, same dtype, shape and device) to a frozen copy of the pre-change implementation on:
   - every T-0063 cut automaton (BFCL under JSON and pretty whitespace, Sudoku), at buckets 64, 128 and 512
   - hand-built NFAs with parallel overlapping labels, non-singleton start sets and negated classes with ids outside U
   - L ∈ {0, 1, 2, 3, 63, 64, 65, 255, 256}
   - a stop id at position 0, at L−1, absent, and repeated
   - a set that dies mid-canvas
   - ids after the first stop that would kill the set if they were consumed

   It also agrees with `tests/cd/oracle/enumerate.py`'s δ (independent oracle; T-0065 criterion 7).
2. **δ\* is log-depth and sync-free.** At bucket 128 on CPU it issues ≤ 160 dispatched ops at L 256 and no more than
   the L 64 count + 40 (`TorchDispatchMode`); zero synchronizing calls (T-0065 criterion 8 spy); at L 256 and bucket
   512 no single allocation exceeds 256 MiB (T-0065 criterion 8 / R7).
3. **Stop ids cached.** After the first call on a (device, stop-id tuple), `delta_star` builds no tensor from host data
   (no `torch.tensor`/`as_tensor` of Python data, no H2D copy; spy). A different stop-id tuple on the same device gets
   its own tensor, never a stale one.
4. **Pass-through.** New keyword-only parameters, each defaulting to today's behaviour:
   `emission.log_transfer(..., *, class_mass=None)`, `marginals.constrained_marginals(..., *, class_mass=None)`,
   `draw.joint_draw(..., *, generator, class_log_weights=None)`, `mapdecode.constrained_map(..., *, class_max=None)`.
   - With a precomputed value supplied, outputs are bit-identical to calls without it, and the generator state
     afterwards is identical; the function issues no op on an `[L, V]` tensor for that quantity (op count).
   - `cd/sampler.py` computes `class_max` once per call and reuses it across its L_eff candidates.
   - No positional parameter or return type of T-0065 R1, T-0066 R1 or T-0067 S1 changes.
5. **Whole-call op budget.** One `end_projection` constrained call through T-0067's CPU stand-in
   (`tests/cd/fakes/diffusion_sampler.py`), one constrained plus one unconstrained slot, bucket 128, at CL 64 and
   CL 256. CD-added dispatched ops (wrapper total minus the inner stock call) ≤ 40 % of the pre-change count at
   CL 256. The test-author measures the pre-change counts on the merge base and they are recorded as ruling U1 before
   implementation, with the red run as evidence. The threshold is never edited afterwards.
6. *Negative:* T-0067 criteria 3, 4, 7 and 9 stay green unedited (zero ops on the fast path, mixed-batch
   bit-identity, loud failures in ≤ 2 calls, no host syncs); every T-0065 and T-0066 test module passes unedited,
   including `test_core_compensated.py`, the fp32 bars and the χ²/MAP exactness rows; no compensated or two-pass code
   path is removed, reassociated or compiled (T-0062 decision 10).
7. **Tier 2** (container, `-m gpu`, `/launch`, no engine boot), with `torch.set_float32_matmul_precision("high")` set
   globally: criterion 1's rows hold on CUDA; the δ\* scan's median time is ≤ the frozen sequential δ\*'s at buckets 64
   and 128 (256 and 512 reported only); the probe emits the JSON breakdown of note 6, which T-0071 criterion 1 consumes.
8. **Deferred, recorded, not built:** skipping MAP/δ\* on calls the lagged reports prove non-converging (note 5).

## Implementation notes
1. **δ\* as a scan.** Per position, form the boolean transition matrix `[B, B]` from `edge_src/edge_dst/edge_ok`;
   non-consumed positions are the identity. Compose with the up-sweep's pairwise, odd-carry structure
   (`tree.up_sweep`), then apply the start vector. The product is left-to-right. Chunk to stay under 256 MiB at bucket
   512 (`[L/2, B, B]`). A float matmul then `> 0` is exact for 0/1 inputs even under TF32 or bf16x3 (a sum of
   non-negative terms is zero only if every term is); CUDA has no integer `bmm`. No `.item()`, `.any()` into Python,
   or `.nonzero`.
2. **Stop cache:** a module-level dict keyed by `(device, tuple(stop_ids))`, filled lazily; on CUDA the one-time build
   is outside the per-step path, and T-0067's loud-failure paths must not depend on it existing.
3. **Pass-through** is identity plumbing: the precomputed value is the object the function would have computed, so
   bit-identity is automatic. Do not recompute a "cheaper" variant.
4. **The MAP chunk loop.** `mapdecode.max_matmul`'s batch-group loop (`CHUNK_ELEMS = 1<<22` in `semiring.py`) also
   grows with L. Max-plus is exact under any grouping, so a mapdecode-local larger group under the cap is allowed if
   criterion 5 needs it. `log_matmul` and its compensated path are not touched.
5. **Why the skip is deferred.** Only `end_projection` could skip, and it is not the B13 gate arm (`perstep_mar` is);
   the per-step arms need the MAP every call. The host learns of a commit ≤ 2 calls late (≤ 1 on CPU), so it can prove
   non-convergence only for a few calls per canvas, and every skip decision falls on T-0067 criteria 4, 7 and 9.
   Revisit only if T-0071's microbench shows `end_projection` MAP time matters; that would be its own task.
6. **Microbench hook.** The probe prints one JSON line per bucket (64/128/256/512) with a component breakdown
   (`class_max`, MAP sweep, δ\* scan vs sequential, stop-id build) and the regime fields T-0071's formatter requires
   (container digest, commit). T-0071's `scripts/gpu/cd_microbench.py` may import it; this task does not touch it.
7. **Landmines:** TF32 (T-0065 notes); an exception inside the engine loop kills EngineCore, so T-0067 S9's guards stay
   around anything new in `sampler.py`; `plugin/` is excluded from mypy, but ruff applies.

## Implementation (implementer, 2026-09-30; revised after review A)
Achieved op counts on CPU with torch 2.13.0+cpu, seed 0, n = 1 (U1's regime, U1 unchanged). δ\* on BFCL `live_simple_2-2-0` JSON at bucket 128 with stops (1, 50, 106):
L 64 = 94 ops and L 256 = 102 ops (limits ≤ 160 and ≤ L64 + 40). CD-added ops per whole call, max over calls 2–5: BFCL@128 CL 64 = 483 and
CL 256 = 741 (limit ≤ 1493); Sudoku@64 CL 64 = 449 and CL 256 = 518 (limit ≤ 1135).
- **MAP chunking (note 4).** `mapdecode.max_matmul` groups with `MAP_CHUNK_ELEMS = 4 × CHUNK_ELEMS` = 2^24 elements, which is
  64 MiB in fp32. The broadcast sum is reduced in the same statement, so one such temporary is live at a time. Every chunk still
  reduces the whole `m` axis in one `amax`. The earlier `16 ×` was 256 MiB, not 64, and held two temporaries (review A).
- **δ\* scan memory (note 1).** The scan runs on the `n_states × n_states` block, so its cost does not depend on the bucket;
  padded states have no edges, and position 0 is always consumed. Leaves are fp32 0/1 from the start, and products are
  thresholded in place (`gt_`). Positions are taken in chunks of 32 MiB of leaves (`_SCAN_CHUNK_BYTES`), so live transients are
  at most about 1.5 × 32 MiB plus the `O(L·E)` edge masks, for any L. There is one chunk up to L 1134 at 86 states and L 512 at
  128 states.
- **Measured (CPU, spy on live storages).** δ\* at S 511, L 256, bucket 512: largest tensor 31.9 MiB, peak live 53.0 MiB.
  `max_up_sweep` at L 256, bucket 128: peak live 88.5 MiB (56.0 MiB before this task).
