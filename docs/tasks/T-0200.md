## Goal

Evidence: on Amazon every after-frame had phash `17018eb51f4f7b3d` and the step-image identity `capture:5f150fe372dae6ca374cc1ee66965f0c` was byte-identical across home, search results and reload; on Photopea the `click_at (488,396)` after-frame had the same uniform hash and James saw black in "What I see"; the model said "the screen is blank"; the fresh turn-start frame 30 s later (seq 4188) was fine. Reproduced with Gearvis's own stack (`BrowserToolExecutor(web=True, headless=False)`, `goto` amazon, `settle`, `screenshot`): a pure-white 6758-byte JPEG right after `settle()`, the real homepage (194305 B) 3 s later (`scratchpad/shotcheck/gearvis_amazon.py`). Plain headed Playwright on the new driver (595.99.02) screenshots fine, so the driver is not the cause.

Confirmed in source at c9e145ec:
- `PlaywrightDriver.settle()` (`runtime.py:821`): up to 3 rounds of popup adoption, `wait_for_load_state("domcontentloaded", 2000 ms)` and two `requestAnimationFrame`s; **no paint signal**, and a navigation starting after it returns (the AWS WAF token reload) is not seen.
- `BrowserToolExecutor._capture` (`executor.py:1362`) takes one screenshot; callers: `execute()`'s after-frame, the guarded-type stop capture, the overview-frame path, `frame()` (step-1/onset frames and T-0187's fresh frame, cut at the session's `LIVE_FRAME_TIMEOUT_MS = 3000`).
- The session reuses `latest_frame` as the next step image when its phash equals `resolved["frame_after"]` (`session.py:4195`), so a uniform after-frame **is** the step image, repeats as one identity across pages, and feeds T-0137/T-0136 false "no change" facts.

After this task every own capture whose pixels are near-uniform (any colour) is taken again after a short wait, up to a bounded budget; the first non-uniform capture, or the last when the budget is spent, is the frame and the only one registered. Normal pages cost nothing extra. One session-log note per re-taken capture, no URL. Rejected: re-settling on a navigation (cannot see the WAF reload), an FCP/`readyState` wait (runs page script, still passes challenge docs and canvas apps).

## Acceptance criteria

1. **Blank, on pixels only.** Pure exported `blank_frame(img) -> bool`, median ≤ 5 ms on a 1280×800 q85 JPEG (decode in reduced/draft mode if needed; James 2026-10-29: the visible speed of computer use is the main selling point, so a normal page must not pay for this): 8-bit luma, box-downscaled to `BLANK_GRID_W = 64` px wide (aspect kept); blank iff `max - min ≤ BLANK_LUMA_RANGE = 8`. True for uniform white, black, grey and #2b2b2b 1280×800 JPEGs at q85; false for a white page with one 14 px dark text line, a 1 px dark hairline, every existing fake screenshot (`fake_jpeg`, `jpeg_bytes`, `scene_jpeg` with content, `page_jpeg`) and a #f0f0f0 skeleton on white. Reads no DOM, text, URL or title; calls no driver method.
2. **Re-capture loop.** On a blank capture `_capture` waits `BLANK_RECAPTURE_INTERVAL_S = 0.1` and screenshots again until non-blank or the budget is spent; the kept frame is the first non-blank or else the last; at most `1 + ceil(budget / interval)` screenshots; constants module-level, read at call time.
3. **Budgets.** Action paths (after-frame, guarded-type stop, overview-frame): up to `BLANK_RECAPTURE_ACTION_S = 3.0`, stopping once less than `CAPTURE_RESERVE_S = 1.0` remains of `ACTION_TIMEOUT_S`. `frame()`: up to `BLANK_RECAPTURE_FRAME_S = 1.5`. A blank-forever driver with `ACTION_TIMEOUT_S = 1.0` and a 0.7 s settle yields `executed`, never a timeout failure.
4. **Identity.** Only the kept capture is registered (`_own`, `_extents`, `_latest`); `resolved["frame_after"] == latest_frame.phash`; an intermediate blank capture is not an own frame (a `click_at` carrying its phash is refused); the kept extent comes from metrics reads bracketing the kept screenshot, exactly today's two reads on the no-re-capture path.
5. **Normal pages unchanged (negative).** Non-blank first capture: one `screenshot()`, no sleep, no note, the same driver call sequence, `ToolOutcome`, `resolved`, bytes, phash and extent as BASE; every existing executor test passes unchanged.
6. **Uniform page bounded (negative).** Always-uniform driver: `execute()` returns `executed` within `ACTION_TIMEOUT_S` with bounded screenshots; `frame()` returns the last capture within `BLANK_RECAPTURE_FRAME_S + 0.5 s`; both registered as before.
7. **Nothing else moves (negative).** During the loop only `screenshot()` (and `layout_metrics()` if present); no settle, `bring_to_front`, `focused_field`, `main_frame_urls`, `navigated_since` or input; `navigated`/`checkout` keep their read points; T-0198 fronting count and order unchanged; `full_page_screenshot` never re-captured; launch arguments unchanged — the headed window shows the real page live as before.
8. **Failure inside the loop** (amended 2026-10-29, orchestrator: a WAF-style reload can destroy the page mid-loop). A re-capture screenshot raising `Exception` counts as one blank attempt: the loop waits the interval and tries again within the budget; when the budget is spent the last successful capture is kept (still `executed`); the first screenshot raising propagates as BASE; `CancelledError` propagates with nothing registered and `latest_frame` unchanged.
9. **Log.** `BrowserToolExecutor.on_note: Callable[[dict[str, Any]], None] | None = None`; each capture that took more than one screenshot calls it once with exactly `{"what": "live frame: blank capture retaken", "path": "action"|"frame", "captures": int, "blank": bool, "waited_ms": int}` — no URL, host, title, phash or exception text; a raising `on_note` is swallowed; `cli.py` wires it (live only) to the session's current log (`_CurrentSessionLog(session).record("note", data, session_ms=clock.now_ms)`); no `resolved` key added.
10. **Real Chromium, loopback.** A page painting nothing for 1.5 s then content gives a non-blank `frame()` after `open()` and a non-blank after-frame for a click navigating to it (one note each); a page that stores a `sessionStorage` token and `location.reload()`s after 800 ms (WAF-shaped) gives a non-blank after-frame; a white page gives a blank frame within the bound; a normal page gives no note and one screenshot.

## Implementation notes

- Pixel-first: the decision uses screenshot bytes only; no FCP, `readyState` or DOM check; nothing new runs in the page.
- No new `Driver` method, no `runtime.py` change; the loop uses `screenshot()` and optional `layout_metrics()`.
- `_capture` takes a per-call budget and absolute deadline (`execute()` knows its `ACTION_TIMEOUT_S` end; `frame()` passes its own); `asyncio.sleep` (cancellable); never catch `CancelledError` or the enclosing timeout's cancellation.
- Build and register the `Frame` once, from the kept capture; phash salt, `_retired`, `_MAX_OWN_FRAMES` unchanged.
- `navigated`/`checkout` are read before the capture as now; a navigation during the loop is seen by the next action's checkout read (T-0192); add no reads.
- Constants "chosen, not measured"; `frame()`'s 1.5 s because `LIVE_FRAME_TIMEOUT_MS = 3000` lives in `session.py` (T-0199).
- No tautological asserts (`.claude/rules/tests.md`). The note carries no URL (T-0111g B15, T-0192).
