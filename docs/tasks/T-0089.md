# T-0089 — Turn-machine rows and invariants for a tool turn

**Status:** done 2026-10-12 (verified at f24e397; rulings T1–T15) · **Blast radius:** high (turn machine; two reviewers) · **Branch:** `T-0089-tool-turn-machine` from `main`
· **Depends on:** nothing (concurrent with T-0087, T-0088 and T-0090; disjoint files). Umbrella `T-0080d.md`.

## Goal
The pure machine learns a tool turn:
- a pass-1 `llm.done` may carry a tool draft;
- a repairable draft starts exactly one repair request after pass 1 has finished;
- a valid call is executed only when the turn completes uninterrupted and its spoken prefix has drained;
- every interruption, error and disconnect cancels the call.

No row changes for an `llm.done` without a tool.

## Acceptance criteria
1. **Contracts.**
   - **Draft.** `contracts/turn.py::ToolDraft` has:
     - `call_id`;
     - `status: valid | repairable | refused`;
     - `name: str | None`, `arguments: dict | None`, `reason: str | None`;
     - `source: draft | repair`.
     Validators: `valid` ⇒ name and arguments are set; `repairable` ⇒ name is set and source is `draft`; source `repair` ⇒ status is not
     `repairable`.
   - **Event.** `events.LlmDone` gains `tool: ToolDraft | None = None`.
   - **Commands.**
     - `ToolRepairStart(request_id, draft_request_id, call_id)`;
     - `ToolExecute(call_id, turn_id, name, arguments, source)`;
     - `ToolCancel(call_id, reason)`, where `reason` is one of `interrupted | takeover | error | disconnected | refused | repair_failed |
       repair_timeout`.
   - **Timer.** `TimerName` gains `tool_repair`.
   - **State.** `MachineState` gains `tool` (the pending call: id, status, source) and `tool_repairs`, both in `_PER_TURN_RESET`.
     `TurnPolicy.tool_repair_timeout_ms = 3000`.
2. **Rows** (added to the docs/02 §4 table by T-0092):
   - **R1.** THINKING or SPEAKING, `LlmDone(active, tool.status=valid)`: the call becomes pending; then today's row runs, with
     `ToolExecute` placed before the history command.
     - THINKING with nothing committed: `ToolExecute`, then `CommitHistory(user_only)`, then IDLE.
     - SPEAKING: execution is deferred to `_maybe_complete`.
   - **R2.** THINKING or SPEAKING, `LlmDone(active, tool.status=repairable)`, with `tool_repairs == 0`:
     - `llm_done` stays false;
     - `active_generate` becomes `"{turn_id}-repair"`;
     - emit `ToolRepairStart`;
     - arm `tool_repair`;
     - cancel `llm_timeout`.
   - **R3.** `LlmDone(repair id, tool.status=valid)`: as R1, with source `repair`.
   - **R4.** `LlmDone(repair id)` with any other tool, or with none: emit `ToolCancel(repair_failed)`; set `llm_done`; complete as today.
     Never a second repair.
   - **R5.** `LlmDone(active, tool.status=refused)`: emit `ToolCancel(refused)`; the rest as today.
   - **R6.** A `Tick` at or past `tool_repair` in THINKING or SPEAKING: `LlmAbort(repair)`, `ToolCancel(repair_timeout)`, `llm_done`, then
     complete as today.
   - **R7.** `LlmError(repair id)`: `ToolCancel(repair_failed)`, `llm_done`, then complete as today. The spoken prefix keeps playing; the
     turn is **not** failed.
   - **R8.** Every row that interrupts, fails or disconnects (`_interrupt`, THINKING takeover, `_fail_turn`, `tts.error` in a speaking
     state, `client.disconnected`) emits `ToolCancel` with its reason when a call is pending or under repair.
     - The existing `LlmAbort` on `active_generate` covers the repair.
   - **R9.** `LlmCommit` from the repair request is never voiced.
   - **R10.** A repair id is never stale-ignored by the `request_id` checks. A pass-1 `LlmDone` arriving after the repair started is
     stale.
3. **Invariants** (`tests/unit/test_turn_invariants.py`, Hypothesis stateful; architecture §4; never weakened):
   - **P1.** At most one `ToolExecute` per `turn_id`. Its `call_id`, name and arguments are those of a `valid` draft of that turn.
   - **P2.** No `ToolExecute` in a turn that entered INTERRUPTED, took a THINKING takeover, ended by an error, tts.error or disconnect row,
     or hit `tool_repair`.
   - **P3.** `ToolExecute` appears only in a command tuple whose resulting state is IDLE and which also holds that turn's
     `CommitHistory`. So it is never emitted while that turn has queued or unplayed utterances.
   - **P4.** At most one active generate plus at most one prefill, with the repair included (existing §4 invariant). `ToolRepairStart`
     is never emitted while another generate id is live.
   - **P5.** At most one `ToolRepairStart` per turn.
   - **P6.** No `TtsSpeak.source` ever contains text from a `tool` commit or from any commit of a repair request (it extends "never
     tts.speak uncommitted").
   - **P7.** Liveness: from any state with a repair in flight, a `Tick` past its deadline followed by `playback.drained` reaches IDLE.
   - **P8.** Every pending call ends in exactly one of `ToolExecute` or `ToolCancel`.
   - **P9.** *Negative, differential.* For random event sequences whose `LlmDone`s carry no `tool`, `step` returns exactly what a frozen
     copy of `main`'s `turn_machine.py` returns.
4. **Executor totality.** `conductor/executor.py` has a named handler for each new command, so `UnknownCommand` stays unreachable. Until
   T-0092 the handlers are inert (one session-log `note`, no effect). Nothing before T-0092 constructs `LlmDone.tool`.
5. *Negative.* Unchanged: every existing row in `test_turn_edges.py`, `test_turn_frames.py` and the turn-machine table tests, unedited.
   The module stays pure (no asyncio, time or I/O; the existing purity guard).
   - **Amended (ruling T1).** Three pins in `test_turn_frames.py` assert that the contracts did not change at all, which criterion 1
     contradicts. The test-author widens exactly these, and by exactly T-0089's additions; no other row in that file changes:
     - `test_every_existing_machine_state_field_keeps_its_name_type_and_default` (adds `tool`, `tool_repairs`);
     - `test_every_existing_turn_policy_field_keeps_its_name_and_default` (adds `tool_repair_timeout_ms`);
     - `test_the_event_and_command_contracts_are_byte_identical_to_main[events.py, commands.py]` becomes: every class on `main` is
       unchanged, and the only additions are `LlmDone.tool` and the three tool commands.

## Implementation notes
- Keep the dispatch shape: one handler per event family and flat `if` chains. Deferral lives in `_maybe_complete`; cancellation in
  `_interrupt`, `_fail_turn`, `_on_tts_error`, `_on_client_disconnected` and the THINKING takeover. Each emits `ToolCancel` only when
  `state.tool` is set.
- The machine never validates a call. It trusts `ToolDraft.status`, which the session computes (T-0091/T-0092).
- `ToolExecute` comes before `CommitHistory` and `ScheduleSummary` in the tuple. `hud.state` stays last (criterion 21 of T-0003).
- A duration is never computed from two clocks. The `tool_repair` deadline is computed from the `LlmDone`'s `t_ms` only.

## Ruling after implementation (orchestrator, 2026-10-11, at 1ea025f)
- **T8.** The base model in `tests/unit/test_turn_invariants.py` says any accepted `LlmError` ends in IDLE (criterion 14 widened by
  A5/A9). R7 and T5 are explicit exceptions while a repair is live: an `LlmError` with the repair id, or with `request_id=None`, cancels
  the call (`repair_failed`) and leaves speech running.
  - `ToolTurnModel` exempts exactly that case from the base postcondition, and only when a repair was live before the event. In its
    place it requires:
    - `ToolCancel(repair_failed)` and `LlmAbort` on the repair id;
    - no `ToolExecute` in that turn;
    - completion on the next `playback.drained`.
  - The base `TurnMachineModel` is unchanged. It never draws a repair, so criterion 14 keeps its full force there.
  - This narrows the invariant by the task's own row, not to make a test pass. The human accepted R7 with T-0080d's defaults.

## Rulings after review (orchestrator, 2026-10-11; reviewer A APPROVE implementation, reviewer B REQUEST CHANGES, at fd12d85)
- **T9. Correction to T8.**
  - If playback had already drained before the repair failed (`before.playback_drained`), R7's "complete as today" ends the turn
    at once. The model then requires IDLE with the completion commands, `ToolCancel(repair_failed)`, `LlmAbort` on the repair, and no
    `ToolExecute`.
  - Otherwise T8 stands: the state is unchanged and the turn completes on the next drain.
  - T8's assertion failed a correct implementation, and seed 1 reproduces it.
- **T10. P9 must reach the rows T-0089 rewrote.**
  - The P9 strategy gains recipes that drive to SPEAKING (an answer commit on the live id), to PAUSED, and to a completed turn
    (`llm.done` and `playback.drained` in both orders).
  - It asserts minimum visit counts per run (SPEAKING, PAUSED, a toolless `llm.done` accepted in SPEAKING, a completed turn), or adds
    `@example`s that guarantee them.
  - **Mutants it must kill:**
    - a toolless `llm.done` in SPEAKING without `CancelTimer(llm_timeout)`;
    - `ScheduleSummary` dropped when nothing was played;
    - timers before the flush (A3);
    - a `CommitHistory` forced on a toolless THINKING `llm.done`.
- **T11. P3 is enforced. Never execute in a tuple that speaks.**
  - **The gap.** The machine marks playback drained once and never resets it. So a drain followed by a final `llm.done` that flushes a
    held clause can emit `TtsSpeak` and `ToolExecute` in one tuple. The tool then runs while speech is unplayed, against P3 and H5.
    Today's session never produces that order (it marks a drain only after `llm_done`), but the machine must not rely on it.
  - **Rule.** In a turn with a pending valid call, a completion whose tuple contains a `TtsSpeak` does not complete. `playback_drained`
    becomes false, and the turn completes, and executes, on the next `playback.drained`. Toolless turns are unchanged (P9).
  - **Model.** It asserts that no `ToolExecute` tuple contains a `TtsSpeak`.
  - **Existing row.** `test_r1_guard_width_drain_before_done_executes_on_done` is amended accordingly. It is the reviewer's trace with the
    sentence segmenter.
- **T12. The T1 contract pin is exact.** It compares each main class's `model_json_schema()` plus its validators
  (`__pydantic_decorators__`) and `model_config`, so an alias or an added validator on a main class is caught.
- **T13. Rows for the surviving mutants.**
  - **R3:** the source is stamped `repair`, even when the repair's draft says `draft`.
  - **T7:** the pending `call_id` wins over a repair draft that carries another id.
  - **Timer cleanup:** `CancelTimer(tool_repair)` after a barge-in during a repair, and after R3, R4 and R7.
  - **T6 on resume:** a clause held while paused during a repair is spoken at resume.
  - **History on execute:** an executed call with an empty transcript still emits `CommitHistory` in its tuple.
- **Note for T-0091/T-0092.** Keep the session's drain gate (`session.py`, "drain only once `llm_done`"); T11 makes the machine safe
  regardless.
- **T14 (test-author's questions at 9434f37).**
  - **T11 widened. A drain counts only if no speech came after it.** In a turn with a pending valid call, `playback.drained` covers only
    what was spoken before it.
    - **The trace.** THINKING; `playback.drained` with nothing played; an answer commit that speaks; then `LlmDone(valid)`.
    - **The rule.** That `LlmDone` must not execute. The turn completes and executes on the next `playback.drained`.
    - **Mechanism.** Use existing state if it can express this. Otherwise add exactly one `MachineState` field, `spoken_after_drain:
      bool = False`, in `_PER_TURN_RESET`, and the test-author widens the T1 pin by that field.
    - **Toolless turns are unchanged** (P9), including main's behaviour on this trace.
    - **Row.** `test_p3_a_drain_before_any_speech_does_not_cover_the_speech_after_it`.
  - **T9 in PAUSED.** Confirmed: T9 applies to SPEAKING only. In PAUSED a toolless `llm.done` never completes, so T8's "state
    unchanged" stands there; the turn completes after the resume and the drain.
  - **T2 again.** The test-author updates `TURN_MACHINE_SHA256` after the T11/T14 implementation.
- **T15 (at bab8732). T14 by event order, not by text.**
  - **The gap.** A drain left over from turn 1 (marked before a `tts.error` ended it) can arrive while turn 2 is THINKING. If its
    `played_text` happens to equal turn 2's later `spoken_text`, c236d19 executes before turn 2's answer has played. The text comparison
    cannot tell a stale drain from a fresh one.
  - **Mechanism.** T14's fallback field is adopted: `MachineState.spoken_after_drain: bool = False`, in `_PER_TURN_RESET`.
    - Every `TtsSpeak` sets it.
    - `playback.drained` clears it.
    - A completion with a pending valid call executes only if it is false. T11's rule still applies.
    - The `played_text == spoken_text` test is removed.
  - **P9 amendment.** P9 compares commands exactly. It compares state exactly too, except for T-0089's own fields (`tool`,
    `tool_repairs`, `spoken_after_drain`), which main lacks. This does not weaken the guard on behaviour: every command that main
    emits must still be identical. The test-author widens the T1 pin by this field and updates the sha pin after the implementation.
  - **Follow-up for T-0092.** `PlaybackDrained` carries no turn or run id, so a stale drain can also end a toolless turn early (main's
    behaviour). T-0092 should give drains a run id and drop stale ones in the session.

## Note (2026-10-12, from the T-0092d review)
- **Criterion 1's "the pending call: id, status, source".** The code stores the whole `ToolDraft` in `MachineState.tool`. R1/R3 need its
  `name` and `arguments` to emit `ToolExecute`, and the T1 pin fixed the type. The code is authoritative.
- **`turn_machine.py:631`.** A pass-1 `repairable` with `tool_repairs != 0` gives `ToolCancel(repair_failed)`. This is unreachable: after
  the repair starts, a pass-1 `llm.done` is always stale (R10). It is consistent with R4: there is never a second repair.
