## Definitions (normative)
- **Where.** Only `live._judge(body)` (shared by `classify` and `repair_verdict`). The rules apply only to a draft that is **not** `valid` and
  whose name (parsed, or `native.draft_name` for a draft that does not parse) is `press_key`, `click_at` or `type_at`.
- **Value scan for a draft that does not parse.** On the text after `call:NAME{`: closed `<|"|>…<|"|>` spans are skipped as values, never
  searched for keys; an unterminated string ends the scan, as does the first `<tool_call|>`/`<|tool_call>` outside a string (first call only);
  a key is an identifier in key position (after `{` or `,`, optional whitespace) followed by `\s*:\s*`; first occurrence of each key only; a
  value is a closed string (→ `str`) or a bare token ended by `,`, `}`, whitespace or `<` (JSON literal if it is one, else raw text); a bare
  token running into the end of the body (a length cut) gives no value. For a draft that parses, the values are the parsed `arguments`.
- **Alias normalisation** of a string combo: squash (`re.sub(r"\s+", "", s).casefold()`), split on `+`, map each whole part through
  {`esc`→`escape`, `return`→`enter`, `control`→`ctrl`, `del`→`delete`, `up`→`arrowup`, `down`→`arrowdown`, `left`→`arrowleft`,
  `right`→`arrowright`}, rejoin with `+`. `cmd` is not mapped. Whole parts only (`pageup` untouched). Compared with the squashed list entries
  read from `tools.load()`, never hard-coded.
- **H-T99d (press_key).** Stays `repairable` only if the read-back `combo` is a `str` whose normalised form is in the list. Otherwise
  `refused`: reason **`"no combo"`** when no combo can be read (missing key, unterminated string, length cut); **`"combo not in enum"`**
  otherwise (a string not in the list; a non-string — number, list, null; a bare token).
- **H-T99e (click_at, type_at).** A read-back `x`/`y` is in range if it is an integer (an `int` that is not a `bool`, or a `float` with
  `is_integer()`, as jsonschema counts) with 0 ≤ v ≤ 999. If either read-back coordinate is not in range → `refused`, reason **`"coordinate out
  of range"`** (non-integers, strings, negatives, > 999, bare raw text). A missing or unreadable coordinate does not trigger the rule (today's
  verdict stands).
- **Verdict shape.** `Verdict("refused", name, arguments_or_None, reason, query_problem)`; name and arguments kept when present. The three
  reasons are module constants exported from `live`.

## Rulings on the test-author's ambiguities (orchestrator, 2026-10-15; tests at ace1a4b)
- **V1.** The three reason constants are pinned by value and must be exported in `live.__all__`; their names are the implementer's choice.
- **V2.** For a draft that does not parse, the refused verdict's `arguments` is `None`; name and reason are kept (the scanned values decide,

- **V5.** An empty bare token gives no value.
- **V6.** The cd parity row's pending marker is bound to a name (`T0100_PENDING`) because `check_pending` collects with the cd guard closed;
  the test-author removes it with the others at activation.

## Ruling V7 (orchestrator, 2026-10-15; implementation at 9f61ce6)
A bare token also ends at `{`, `[` and `]` (in addition to `,`, `}`, whitespace and `<`), and the scan stops at the call's own closing brace
(depth 0). This is what V4 (top-level keys only) requires and what the cd parity oracle does (`[^,{}\[\]\s<]*`); the Definitions' terminator
list is amended accordingly. Consequence: `x:5]` reads as 5. Follow-up noted (not this task): `session._judge_tool` logs `parse =
verdict.reason` when `arguments is None`, so a refused non-parsing draft logs e.g. `parse="combo not in enum"` rather than the parser's reason.
