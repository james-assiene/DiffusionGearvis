## Goal

The plugin publishes the real denoising trajectory of every DiffusionGemma request. It goes out as
a loopback ZeroMQ PUB stream of `astra.canvas.step` frames. Each frame carries:
- the post-renoise canvas;
- the argmax;
- an exact stability mask;
- the phase;
- on a commit, the committed ids.

The frames are read out of `DiffusionGemmaRequestStates` with **no host synchronisation on the
sampler thread**, and the tap costs ≤ 3 % (B16). A model-state factory wraps what
`super().custom_sampler()` returned instead of replacing it, so T-0015's image shim and the stock
path are untouched. This factory is the outer layer of T-0069's Tap(CD(stock)).

The task also yields the first real recorded trajectory (`artifacts/canvas/`, for T-0011c) and the
plugin-on boot reference that T-0069 criterion 4 needs. It implements docs/12 §2 and docs/07 §5
milestone 0, without the acceptance mask and the entropy (criterion 6).

Out of scope: the conductor relay (T-0011b), the HUD panel (T-0011c), per-position entropy (its own
task, with its own B16 run), constrained decoding and any write to logits (T-0062/T-0069), and
`versions.lock` bumps.

**Tier 1a**

1. **Interception (unchanged; T-0069 criterion 2).**
   - `make_model_state_cls(base, *, tap)` returns a subclass whose `custom_sampler(s)` calls super
     and returns `(TapSampler(inner, …), second)`.
   - `inner` and `second` are the identical objects super returned.
   - If super returns `None`, it returns `None`; if super raises, the same exception object
     propagates.
   - The factory works over any base, including a two-level wrapper base (the
     `make_cd_model_state_cls(...)` shape).
   - *Negative:* the plugin never constructs a `DiffusionSampler` and never names `EntropyBound`,
     `gen_config`, `t_min`, `t_max`, `embed_weight` or `shard_indices`.
2. **Transparency (unchanged).** Over the runner's probe list, the wrapper has the same attributes
   as the inner sampler (`hasattr` parity) and returns the same objects. *Negative:* the wrapper has
   no public attribute the inner lacks; in particular, no `remove_request` and no `states`.
3. **No host sync on the sampler thread (S8).** Run 200 wrapped calls (suppressed, publishing and
   commit calls) with the consumer blocked. The tap must not sync on anything it reads.
   - These are syncs: `.item`, `.tolist`, `.numpy`, `np.asarray`, `bool()`, `int()`, `float()`,
     `.nonzero`, `.cpu()`.
   - A `.to` or `copy_` counts only when it moves device→host *and* blocks.
   - A same-device `.to` is not a sync, and neither is a `non_blocking` copy into the tap's pinned
     buffer.
   - Values are read only on another thread, after it awaits the event recorded after the copy.
   - Liveness rows show the spy fires on each listed op and on a blocking D2H copy.
4. **Rate limit before any device read; no commit lost (rewritten, R5).**
   - With a host clock, 1 kHz offered and `hz=30`: ≤ 31 D2H bundles per second per request, plus
     ≤ 1 at release.
   - Ten times the offered rate does not raise that count.
   - Host buffers are allocated when the sampler is wrapped, never during a call.
   - Every commit is published **exactly once**, with `phase="commit"`, its `step`, and
     `committed_tokens` equal to the inner `sampled_token_ids` row cut at `num_sampled`.
   - That happens no later than the slot's next publishing call or its release (S11), whichever
     comes first.
   - The decision to publish a commit never reads `num_sampled` on the host (it is a device tensor,
     R4).
   - Suppressed calls issue no D2H copy. Per-call device work writes only tap-owned buffers and has
     a fixed size, independent of history length and step count.
   - *Adversarial:* two commits in one rate window → both are published, or `commit_overrun`
     increments. Never silent.
5. **The tap is inert.**
   - (a) `out is inner_out`, and nothing the tap reads is written; the spies refuse in-place ops and
     `__setitem__`.
   - (b) **Catch-all, shaped like S9:**
     - The inner call is never wrapped, so its exceptions propagate as the same object.
     - The tap's work before and after delegating is guarded separately. A raise before still runs
       the inner exactly once; a raise after still returns the inner output.
     - Each raise increments the counter and logs one traceback per exception type per process.
     - The call's buffers go back to the pool: 1000 injected raises leave the pool size unchanged.
     - The affected slots are latched off until their next occupant, and a tap that does not raise
       never trips the latch.
     - The publisher thread guards each frame separately (S14).
     - Nothing ever raises into the engine loop, because that kills EngineCore.
   - (c) A full queue drops the oldest frame, counts it, and never blocks.
   - (d) Dummy and profile calls, slots with no `req_id`, and `_warmup_` request ids publish
     nothing.
6. **Honesty (unchanged).**
   - `AstraCanvasStep` gains real `canvas`, `argmax`, `stable` (hex, MSB-first),
     `phase ∈ {denoise, commit}` and `committed_tokens`.
   - `accepted` and `entropy` become optional and are `None` on every plugin frame.
   - *Negative:* no field is filled with a proxy. In particular, `canvas == argmax_canvas` is never
     sent as `accepted`.
7. **`stable` is exact (unchanged).** Bit p is set iff `history[h][p] == history[0][p]` for all
   h < ST **and** `history_len ≥ ST`. The mask is zero until then, and padded to whole bytes.
8. **Framing (unchanged).**
   - One PUB message per frame, in two parts: the topic, then a msgpack payload that validates as
     `AstraCanvasStep`.
   - The endpoint comes from `ASTRA_TAP_ENDPOINT`; anything other than `tcp://127.0.0.1*` or
     `ipc://` is refused.
   - Bounded `SNDHWM`, `LINGER 0`, `NOBLOCK`.
9. **Identity is fixed when the frame is staged (rewritten, R6).**
   - `req_id` comes from the model state's `add_request`, and options from `extra_args`; either may
     arrive first.
   - A frame's `(request_id, canvas_idx, epoch)` is fixed when its copy is staged, and is never
     looked up again at drain time.
   - *Adversarial:* free the slot and let a new request take it between staging and draining. Each
     occupant's frames carry its own id and its own payload (the payloads differ), and the new
     occupant starts at `canvas_idx` 0. No frame pairs one occupant's id with the other's data.
   - A `req_id` that is re-added after preemption continues its `canvas_idx` without going
     backwards (bounded tombstones, as in S10).
10. **Wheel and imports.**
    - The wheel contains every `astra_vllm_plugin.*` module.
    - Third-party imports, found by walking the AST, are all on an image-module list, and
      criterion 11 checks that list in the image.
    - torch is imported only lazily or behind the backend seam.
    - *Negative:* the plugin never imports `local_astra`.

## Implementation notes

- **Where the data is.**
  - Per slot: `canvas`, `argmax_canvas`, `step`, `accepted_canvas_history` (`[ST, CL]`) and
    `accepted_canvas_history_len`.
  - `is_encoder_phase` is mutated by the compiled step, so after the call it is never the phase.
  - The batch-to-slot map (`idx_mapping_np`) and the prefill/decode split (`cu_num_logits_np`,
    `num_draft_tokens == 0`) are host numpy and free to read.
  - `max_steps` is `diffusion_states.max_denoising_steps`.
- **A design that satisfies R5 (allowed, not required).** A tap-owned device latch keeps, per slot,
  a commit counter and the last committed row. It is written on every decode call with fixed-size
  `where`/`index_copy` ops and carried in each bundle. The publisher emits a commit frame when the
  counter moves and derives `canvas_idx` from it. Release stages the slot's latch (S11). Reduce
  `stable` on the device; never ship `[ST, CL]`.
- **CUDA landmines (PROGRESS 2026-10-01/02).**
  - Assigning a Python scalar into a CUDA tensor (`t[i] = <python scalar>`) is a host-to-device
    sync.
  - Inductor syncs while it compiles, so warm up before turning on sync-debug.
  - Allocate the pinned pools when the sampler is wrapped.
- **Identity.**
  - `request_id` is vLLM's `req_id`, which T-0011b joins on.
  - The plugin never detokenises: `text_preview` stays `None`, and it emits no
    `astra.canvas.commit`.
  - The tap is on by default with no xargs, so this does not depend on T-0017.
- **Order on the branch.** Build the tap (tiers 1–2) first, then the harness. Merge waits for
  tier 3.
- **Decisions.**
  - **R1–R3 (2026-09-13):**
    - the API is the one the tests fix;
    - the protocol amendment stands (the drift in `hud/src/protocol.js` is T-0011c's first row);
    - pyzmq goes in `dev`.
  - **R4.**
    - The A/A′ control is the first half versus the second half of the tap-off samples.
    - The verdict is `not_resolvable` when `control_pct ≥ |delta_pct|`.
    - **Answered:** `num_sampled` is the device int32 `DiffusionSampler._num_sampled` (vendored
      `diffusion_sampler.py:371-375, 450-457, 575-577`). The host cannot read it without a sync, so
      the old criteria 3 and 4 collided.
  - **R5 — spec change.**
    - "The commit step is forced through the rate limiter" is impossible without a sync. It becomes
      "every commit is published exactly once, lagged".
    - The fake now matches reality.
    - The named rows change because the spec changed, not to accommodate the implementation.
  - **R6 — spec change.**
    - Dropping frames that were queued before their slot was freed would also drop the final
      commit that S11 stages at release, and T-0011b needs that commit.
    - Identity is fixed at staging instead.
    - The new row checks both id and payload, which is strictly stronger.
  - **R7.**
    - S8 and S9 from T-0067 become criteria 3 and 5(b).
    - There is no forced EOS and no "preemption ends the request": a passive tap never alters
      generation.
  - **R8 — fixture sharing.**
    - The test-author copies `tests/fixtures/cd/vllm_v0_29_0/` (`T-0062-perstep-cd` @ e10bcd0) to
      the neutral path. The vendored files and manifest stay byte-identical, and the MANIFEST names
      both consumers.
    - **The merge of main into `T-0062-perstep-cd`** (T-0069's precondition) does three things in
      its merge commit:
      1. `git rm -r tests/fixtures/cd/vllm_v0_29_0`.
      2. Repoints the importers that `git grep -n 'fixtures[./]cd[./]vllm_v0_29_0'` finds:
         `tests/cd/fakes/diffusion_sampler.py` and four `tests/cd/unit` modules. This is a
         mechanical rename. The evidence is `make cd-test` on the provenance and model-state
         modules.
      3. Keeps the `cd` and `stock` groups together under one `[dependency-groups]`, then runs
         `uv lock`.
    - The byte-identical helpers and index hunks merge cleanly.
    - Tier 1b exists because the hand-written fake encoded a false premise (that `num_sampled` is
      host-readable). The real code is the oracle; the fake stays for speed.
  - **R9 — where the composition lives.**
    - The **single** composition expression lives in
      `model.py::AstraDiffusionGemma.get_model_state_cls`. It imports lazily, is cached, and returns
      `make_model_state_cls(DiffusionGemmaModelState, tap=…)`.
    - Changing that expression to
      `make_model_state_cls(make_cd_model_state_cls(DiffusionGemmaModelState), tap=…)` is T-0069's
      one edit.
    - T-0011 neither imports nor anticipates `cd`.
  - **R10 — one wire shape per phase (human, 2026-10-02; amends criteria 4 and 6).**
    - A `denoise` frame carries **all three** of `canvas`, `argmax`, `stable` and no
      `committed_tokens`. A `commit` frame carries `committed_tokens` and **none** of the three rows,
      whether it was published on its own call or lagged. The contract (`AstraCanvasStep`) enforces
      both shapes; the HUD draws the closed canvas from `committed_tokens`.
    - A commit frame's `step` is the step the canvas had reached when it committed (the pre-reset
      value), not the post-call value: on stock v0.29.0 a commit resets `step` to 0 and re-inits the
      canvas with noise. The fake must match stock here.
    - `tests/unit/test_hud_hello_replay.py` (T-0043's, done) builds a pre-amendment frame and is
      updated to the R10 shape by the test-author.
  - **R11 — final frames are protected (human, 2026-10-02; amends criterion 5(c)).** A full queue
    drops its oldest *non-release* bundle. A release bundle (S11 flush) is dropped only when the queue
    holds nothing else, and then counts in `commit_overrun` as well as `dropped`.
  - **R12 — the counters reach the run (human, 2026-10-02; amends criterion 14).** At each release
    the tap logs one line with the request's `req_id` and the tap's counters (`submitted`,
    `published`, `dropped`, `errors`, `commit_overrun`). The tier-3 driver parses those lines from
    the engine log and requires `commit_overrun == 0`, in addition to the commit-count comparison.
  - **R13 — review round 1 (orchestrator, 2026-10-02).** `drain` must read a bundle's identity and
    kind before its buffer returns to the pool (criterion 9; both reviewers reproduced the swap).
    The tap's CUDA events must not spin a core (`blocking=True` or `query()` polling). "The four
    explicit flags" in criterion 14 are those `.claude/rules/gpu-services.md` names:
    `--attention-backend`, `--diffusion-config`, `--max-num-seqs`, `--override-generation-config`.
  - **R14 — consequences of R10–R12 (orchestrator, 2026-10-02, from the round-1 test-author's
    questions).**
    - Step range: a `denoise` frame has `0 ≤ step < max_steps`; a `commit` frame, whose step is the
      pre-reset value, has `1 ≤ step ≤ max_steps` (a canvas closed by the step cap commits at
      `max_steps`). Criterion 14's "`step < max_steps`" reads per phase this way.
    - A commit frame's `committed_tokens` is non-empty (a commit means `num_sampled > 0`).
    - R11 with a queue holding only release bundles and an incoming step bundle: the incoming step

## Implementation log (implementer, 2026-10-02, branch `T-0011-canvas-tap-impl`)

Phase 1 only: tiers 1a and 1b, the pure `local_astra/bench/b16_tap.py`, and the tier-3 driver
`scripts/gpu/b16_tap.py` (written, **never run**). Tiers 2–3 not run.

- **Bundle.** One D2H bundle per request per publishing call: a single int32 row
  `[step, num_sampled, latch(count, len, step, row[CL]), canvas[CL], argmax[CL], stable[CL]]`
  (`4·CL + 5` scalars), copied `non_blocking` into a whole pooled pinned buffer
  (`queue_size + 2` of them, allocated in `CanvasTap.attach`, i.e. when `custom_sampler` wraps),
  followed by one event. A release stages the same layout with the latch only (S11).
- **Latch.** The R5 design from the notes above: per slot, a device commit counter and the last
  committed row, written on every decode call that has a live row with fixed-size
  `index_select`/`where`/`index_copy_`; reset with `zero_()` when a new occupant binds.
- **A lagged commit frame carries no `canvas`/`argmax`/`stable`.** Those rows of the commit call
  were never copied (the call was suppressed), so the frame has `phase="commit"`, the latched
  `step` and `committed_tokens`, and nothing else. To allow that, the contract makes `canvas`,
  `argmax` and `stable` optional (validated against `canvas_length` when present), with `phase`
  defaulting to `denoise` and `committed_tokens` to `()` (a denoise frame with committed tokens is
  refused). This also keeps `tests/unit/test_hud_hello_replay.py`'s pre-amendment construction
  valid. A commit at a publishing call is that call's own frame, with every row.
- **canvas_idx.** The bundle carries the occupant's counter; the consumer adds the request's base,
  resolved at the occupant's first bundle from a bounded per-request table (4096), which is how a
  re-added request continues. `commit_overrun` also counts a commit whose only carrying bundle was
  evicted from a full queue (that bundle is in `dropped` as well).
- **Fake defect reported, not worked around in tests:** `FakeHostBuffer.__init__` sets
  `self._owner = _owner or self`, which calls `FakeHostBuffer.__bool__` → `item()` → `_read`. So
  slicing a pooled host buffer (`buf[0:w]`) raises "host buffer read before the CUDA event…" when
  the buffer has a copy pending, and when element 0 is zero it silently makes the view its own
  owner (copy/read thread bookkeeping then misses the pooled buffer). The implementation copies
  into and reads whole buffers, so it never slices one; the fake should say
  `_owner if _owner is not None else self`.

### Round 2 (implementer, 2026-10-02)

- R13: `drain` takes a bundle's kind and identity before the buffer returns to `_free`; CUDA events
  are `torch.cuda.Event(blocking=True)`.
- R10/R14: the contract enforces one shape per phase and the per-phase step range. The tap clones
  every slot's `step` on the device after the rate limit and before delegating (fixed size, no host

  lagged, is rowless and built from the latch. If that pre-call clone raises, the call's live
