## Goal

S4 ("find the cheapest item") is 0/20 in every run so far.
- **What T-0140 showed:** offered a `page_overview` tool, the model never called it in 100 turns. It answers in one step from the six deals visible at 1280×800 and never suspects the page continues.
- **The ruling (James, 2026-10-24, option 1):** when the page is taller than the screen, the session shows the whole-page picture on its own.

This task adds `Session(auto_overview=True)`, opt-in through `astra session --auto-overview` or the profile key `auto_overview`, live only and off by default. When on, at most once per turn:
- **Capture:** after the turn's live frame has landed, and before the step-1 request is sent, the session itself calls the browser executor's existing `page_overview` capture.
- **Placement:** when the capture returns a picture (content > 1.05 screens), the step-1 request carries it, with T-0140's `OVERVIEW_LABEL`, immediately before the current frame.
- **What does not change:**
  - The model's tool list stays `tools_v1.json`, so the A/B isolates "seeing the page".
  - Nothing is spoken or stored.
  - Off is byte-identical to BASE.

A locked 2-arm A/B then decides whether it becomes the default: arm A is the live default, arm B is the default plus `--auto-overview`.

**Measured scope (planner, 2026-10-24).** Measured in headless Chromium at 1280×800 through CDP `Page.getLayoutMetrics`, on the start-page server:

| page | content height (CSS px) | screens |
|---|---|---|
| `/` | 800 | 1.000 |
| `/search.html?q=mugs` | 800 | 1.000 |
| `/demo/shop.html` | 800 | 1.000 |
| `/demo/contact.html` | 800 | 1.000 |
| `/demo/deals.html` | 1220 | 1.525 (matches T-0140 P6) |

- **Who gets an overview:** only S4 and S5, which both start on deals.html. S1, S2 and S3 always get `fits`.
- **Consequence for the guards:**
  - Arm B's step-1 bodies on S1–S3 are byte-identical to arm A's (AC A3), so any S1–S3 difference is sampling noise.
  - S5 ("add the cheapest item to the cart", 14/20 in T-0140 arm A) is the only non-S4 task that sees the picture. It is the guard that can move.

## Acceptance criteria

### Group A — session, cli, config, docs (CPU)

**A1. Trigger and capture.** With `auto_overview=True` in live, for each turn whose step-1 (generate) request is built:
1. **When:** after the pending live snapshot has landed (as `_run_generate` waits today), and after the unlabelled step-1 prompt is built, the session decides once whether to capture.
2. **Refused before capture, nothing dispatched** (T-0140 A8, R-s):
   - the final user message of the step-1 prompt has no `ImagePart` (a blind turn, or a frame riding on a history image): `refused`;
   - the prompt plus one overview would exceed `prompts.budget.max_images` (4; docs/03 prompt builder "≤ 4 images per prompt"): `refused`.
3. **Otherwise:**
   - The session awaits `LiveBrowser.execute(ToolInvocation(name="page_overview", arguments={}, frame=None, ...))`, the T-0140 A3 executor path unchanged (fit at 1.05×, clip at 4 screens, the moved-page `failed`, never an own frame).
   - The wait is bounded by `AUTO_OVERVIEW_TIMEOUT_MS` on the session clock. On expiry the capture is cancelled, the outcome is `failed`, and step 1 is sent without an overview.
4. **At most one capture per turn:** the over-long (400/413) retry re-uses the turn's result and never captures again. Steps ≥ 2, ReGround pass 2, the prefill and the captioner never capture.
5. **No overlap with `frame()`:** a live snapshot requested while the capture runs waits for it (the B6 chaining).
6. **Outside the model's tool path:** no `ToolDraft`, no `tool.call`, `tool.execute` or `tool.result` record, no tool card, no HUD message, and no machine event.

**A2. Placement.** When the outcome is `executed` with `resolved["overview"]` and `overview_of` returns a `Frame`:
- **Where:** the step-1 request sent is `loop.place_overview(labelled_prompt, frame, OVERVIEW_LABEL.format(...))`.
  - That is `[…, overview ImagePart, OVERVIEW_LABEL, current frame ImagePart, T-0134 screen label (when on), …transcript]` (T-0140 A7).
  - The current frame stays the newest image, so `_sent_identity`, `frame_identity` and B9 freshness key on it.
- **Retry:** the over-long retry's request carries the same overview again (same frame, same label).
- **Repair:** the repair of step 1's call re-sends `pass1_prompt` and therefore carries it. That is intended: it is the same step's request.
- **Nowhere else:**
  - the overview is in no step ≥ 2 request, no ReGround pass-2 body, no prefill, no caption request, no history, no `Episode`, no HUD message and no continuation;
  - `turn.loop_base` and `unlabelled_prompt` never hold it, **including with the T-0134 label off** (`LiveFeedback(False, False)`).
- **Never registered:** the overview's phash never enters the turn's frames, `_frame_bytes`, `_frame_geometry` or history.
- `fits`, `failed` and `refused` send step 1 exactly as with `auto_overview=False`.

**A3. Fits is a no-op.** On a page that fits, the step-1 body, and every later body of the turn, is byte-identical to the same scripted turn with `auto_overview=False`. Only the turn line differs, by A5's key.

**A4. Never spoken, never stored** (T-0140 A9; CLAUDE.md "store only what was spoken").
- `OVERVIEW_LABEL`, the overview image and the executor's action string never reach a `TtsSpeak`, history, the HUD, an `Episode` or `machine.events()`.
- No narration is added, and the speaking policy is unchanged.

**A5. Logging (A10-like).**
- **Turn line:** with `auto_overview=True`, every live turn line gains `auto_overview: {"shown", "fits", "failed", "refused"}` (ints). `shown` counts the step-1 placement once, whatever retries or repairs re-send it.
  - The four sum to 1 on a turn that sent step 1, and to 0 on a turn that never did (for example a barge-in before `LlmStart`).
  - `refused` counts the session's A1.2 refusals and the executor's own `refused` (closed, unavailable, page changed).
  - `failed` counts the executor's `failed`, the A1.3 timeout, and an `executed` outcome whose `overview_of` gives no `Frame`.
- **Request record:** every `llm.request` whose prompt carries the overview has T-0140's key, `overview: {"phash", "screens", "clipped", "width", "height"}`. That covers the generate, its retry and the step-1 repair.
- **Notes:** a timeout writes one `note`, `{"what": "auto overview timed out", "timeout_ms"}`. No other note carries executor text: an exception's text can carry a URL (B15).
- With it off, no key is added. There is no new span and no new log kind.

**A6. Offering it (cli, config).**
- **Config:** `config.LIVE_DEFAULT_AUTO_OVERVIEW = False` and the profile key `auto_overview: bool | None = None`.
  - Only TOML booleans are accepted; anything else is a load refusal (the `page_overview_refusal` pattern).
  - The key with `tools != "live"` is a load refusal naming `live`.
  - `auto_overview = true` together with `page_overview = true` is a load refusal naming both.
- **Flags and resolution:** `astra session --auto-overview` / `--no-auto-overview`. `cli.auto_overview_of(profile, args, mode) -> AutoOverview(auto_overview, auto_overview_from)` resolves the flag, else the key, else the default; sources are `flag`, `profile` and `default`.
- **Refusals at startup:**
  - outside a resolved mode of `live`, the flag exits 2 naming `live`;
  - so does the key of a live profile whose mode `--tools` overrode (O-A2 Q7);
  - the auto overview and the resolved `page_overview`, both on from any source, exit 2 naming both, before anything is constructed.
- **Wiring:** `Session` receives `auto_overview=True` only when on. When off, cli passes no keyword, so off builds call `Session` exactly as at BASE.
- **Startup line:** in live only, `astra session: auto overview: on (flag)` / `off (default)` / `on (profile)` is printed right after the `page overview` line and before the regime line, in `--dry-run` too.
- **Tools unchanged:** the kit's `tools_version` stays v1's (bbfc53cc…) with auto overview on.

**A7. `Session` refuses misuse.** `Session(auto_overview=True)` raises `ValueError` when the kit's mode is not `live`, and when the kit offers `page_overview`.

**A8. Default and constants.** `AUTO_OVERVIEW_TIMEOUT_MS = 2_000` lives in `session.py`. It is chosen, not measured: the T-0140 capture took 43–80 ms on deals (n=5, load 1.0, O-A1-11). `session.OVERVIEW_MAX_SCREENS` still equals `executor.MAX_OVERVIEW_SCREENS`.

**B5. Decision rule (proposed; H-T150-1).**

  - S4(B) − S4(A) ≥ 5 (of 20);
  - success(B) ≥ success(A) − 3 (of 100);

  - else `no change`.
- Boundaries compare with a 1e-9 tolerance.

## Implementation notes

- **Facts, not instructions.** No new model-facing text. The label is T-0140's `OVERVIEW_LABEL` verbatim, `LIVE_TOOL_GUIDANCE` is frozen, and the tool list stays v1. If the A/B gives `no change`, that is the finding.
- **The base must never hold the overview.** At step 1 the session keeps `unlabelled` as the turn's `loop_base` and as pass 2's crop source. `_judge_tool` sets `loop_base = unlabelled if unlabelled is not None else prompt`, so the prompt without label and without overview must be what arrives as `unlabelled`, with the label on or off. `pass1_prompt` (the request as sent) does carry it, and that is why the step-1 repair re-sends it.
- **Order inside `_run_generate`:**
  1. build `unlabelled`;
  2. decide refusal or capture, once per turn, cached on `_TurnLog`;
  3. `_live_label`;
  4. `place_overview`.

  The over-long retry rebuilds `unlabelled` with `drop=1` and re-places the cached frame. `overview_of` reads only once, so keep the `Frame`.
- **The call** is `self._live().execute(ToolInvocation(call_id=f"{turn_id}-auto-overview", turn_id=…, name="page_overview", arguments={}, source="draft", frame=None))`.
  - `source="draft"` is used only because `contracts/**` is frozen; the executor's overview path reads only `call_id`.
  - Do not route it through `_run_execute`: that publishes a tool card and settles a loop result.
- **No overlap:** the executor is not locked, and the full-page capture resizes the viewport (O-A1-2). A concurrent `frame()` could capture the resized page. Chain the capture with `_live_snap` as `_live_snapshot` chains snapshots.
- **Prefix cache:** the frame is in the prefilled prefix, and the overview goes in before it. So step 1 re-prefills from the current frame on: about 1,092 tokens for the frame, about 1,116 for the overview, plus the suffix. That is expected for an opt-in, and B3 prices it.
  - Do not move the overview after the frame: `_sent_identity`, B9, the label and the B8 swap key on "the newest image is the current frame".
  - Do not put it in the prefix: `prompt_builder.py` is frozen.
- **Multi-frame turns** (T-0059, up to 3): `place_overview` inserts before the newest image. With 2 frames that gives `[f1, "[screen 2]", overview, label, f2]`. Keep the A7 rule, and let the test-author pin the layout. Open question Q-3.
- **Budget:** `fit()` and `prompt_tokens` are computed without the overview. The existing 400/413 retry is the only recovery, so add no token logic (T-0140 O-A2 Q10).
- **Defaults live in `cli`** (T-0132 R-f). `Session` acts only when `auto_overview=True`.
