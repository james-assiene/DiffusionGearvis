# Review findings — verification swarm of 2026-09-11/12

Nine adversarial reviewers checked every decision-bearing claim in docs 01–09 and the `.claude/` configuration against primary sources (vLLM `main` @ 988d9b6 and tag v0.29.0, HF configs and chat template, the DiffusionGemma tech report PDF, Kyutai/NVIDIA/GStreamer/PipeWire/KDE/xdg-desktop-portal source, Claude Code docs read as raw text, and the `diffgemma-fa` repository at bf14e76). This document records what was wrong, what was changed, and what is left for James to decide. Sources are in each reviewer's area section; the docs themselves have been corrected in place.

## 1. Verdict summary

No architectural decision was fatally wrong. Twelve claims were wrong, nine overstated, and two of the wrong ones change plans: the constrained-decoding speed claim (it was a misread of the repo's own results) and the vLLM memory configuration (it would not have booted). Two design elements were unworkable as written: the browser-owns-audio/Conductor-does-AEC split, and the "owner-voice check before STT" gate. Several parts of the Claude Code configuration would not have enforced anything inside subagent worktrees.

## 3. vLLM plugin path (doc 07 §5.4)

Feasible with changes. `custom_sampler(sampler)` is a method of the **ModelState** (`DiffusionGemmaModelState`), reached through the model's `get_model_state_cls()` staticmethod, so the plugin is a two-level subclass: model → `get_model_state_cls` → state → `custom_sampler` wrapping `super().custom_sampler(sampler)`'s result. The runner calls `sampler(logits, input_batch)` with two positional arguments and expects a `SamplerOutput`; it also calls `sampler.add_request(req_index, prompt_len, sampling_params)` (where `extra_args` is read) and `ModelState.remove_request(req_id)` (where per-slot state is reset; slots are LIFO-reused). `__call__` is eager Python; only `_softcap_logits`, `_compute_num_rejected` and `_compiled_sample_step` are compiled (`dynamic=True`), so a host-side branch plus a tensor op before the compiled step is safe if the logits stay contiguous fp32. Emission is `argmax_canvas`, so a per-position mask does not guarantee acceptance; a joint draw must overwrite `argmax_canvas`, `canvas` and `draft_tokens[slot, :CL]` coherently after the step. `-inf` masks produce `0·(−inf) = NaN` entropy and the request runs all 48 steps — the finite sentinel must also survive `÷ temp` (use ≤ −1e20, not −1e30). Multimodal-processor registration is inherited by subclasses; register under a **new** architecture name and point `--hf-overrides '{"architectures": [...]}'` at it rather than overwriting. Plugins load in every process; `VLLM_PLUGINS=""` disables silently. Any installed package exposing a `vllm.logits_processors` entry point forces the V1 model runner, which rejects diffusion models — a `services/versions.lock` rule. Allocate plugin buffers in the constructor (before `profile_run`). SGLang's `--dllm-algorithm` is in-package discovery, not out-of-tree, and its DiffusionGemma path was not locatable. The one-hour smoke test is in doc 07 §5.

## 5. Perception and desktop (docs 02, 04, 06)

`pipewiresrc path=` is deprecated → `target-object=<pipewire-serial>`. Restore tokens work on GNOME and KDE; on wlroots they are opt-in (`XDPW_PERSIST_MODE`); persistence is keyed by portal app-id, so the daemon needs one (`app-org.local_astra.Perception.service` + `.desktop`, or `org.freedesktop.host.portal.Registry.Register`) or GlobalShortcuts fails. `glupload → cudaupload` from a DMA-BUF is **not** GPU-resident on desktop NVIDIA (EGLImage memory takes the system-copy path; only PBO memory uses GL interop) — the corrected chain is `glupload ! glcolorconvert ! cudaupload`, to be measured, and for v1 the CPU path (`videoconvert ! videoscale ! jpegenc` at ≤ 2 fps, negotiating plain `video/x-raw` so NVIDIA dma-bufs are never CPU-mapped) is the default. `nvjpegdec` does exist on desktop (NVDEC JPEG) but CPU `jpegparse ! jpegdec` is simpler at 10 fps. KWin does **not** implement `ext-foreign-toplevel-list-v1`; KDE's mechanism is `org_kde_plasma_window_management` (or a resident KWin script pushing `windowActivated` over D-Bus). GNOME still needs a Shell extension (Introspect is sender-allowlisted). KDE remains the easier reference desktop, with `zkde_screencast_unstable_v1` as a dialog-free capture source. Portal `cursor_mode=4` (metadata) keeps the cursor out of OCR/VLM pixels. Tauri/WebKitGTK `getUserMedia` is off by default and NVIDIA rendering bugs are documented — one more reason audio does not live in the frontend, and a plain web page is preferred over Tauri for v1. screenpipe and live-vlm-webui facts confirmed. Florence-2 stays for background OCR (DiffusionGemma OCR of a dense screen costs 1–2 s of the live GPU and returns no boxes) — but see the scope alternative in §9.

## 6. Tech report, dual-branch, duplex (docs 08, 01 §7, 04 §6)

Table 3 numbers, the §3.5 quote, shared weights, 7.8M SC params, ~84 experts per canvas, 13.56 ms/step, ~12 effective steps and the per-sequence causal flag are all confirmed; the "route requests dynamically… hybrid decoding" sentence is in §1 (not §3.5); the Gemma 4 column is "AR (MTP)" and the no-think columns (DG-AR 57.5/67.2/58.3/79.1/95.7 vs TD 50.8/64.6/60.6/77.9/94.5) are the relevant ones for an opener. Corrections applied to doc 08: the thinking toggle breaks the shared prefix (see §2); AR TTFT is transcript prefill + one step and AR speed is ~35 tok/s at the doc's own step time; a second *diffusion* branch costs ~2.7 GB transient (an AR branch almost nothing); the SC MLP is applied to every request with draft tokens, so a patch must exclude AR slots in `prepare_inputs`, the sampler split and the scheduler; NVFP4 AR quality is unmeasured; the E4B interim is incoherent unless its text conditions the diffusion branch — and "A conditions B" (start B ~0.4 s after A with A's first sentence appended) removes the consistency classifier and may remove the need for the patch. Go/no-go experiment: remap the NVFP4 checkpoint to Gemma 4 layout, serve as AR in vLLM, compare against Table 3 on a 30-item slice and against TD on Screen-QA; measure contradiction rate. MoshiRAG injects a *projected embedding* of retrieved text into the temporal transformer input (a trained side-channel), not the inner-monologue text stream; the Kyutai RL "text tokens control interactivity" line is the paper's premise, not a finding; GPT-Live's floor decision is server logic over partial transcripts (the "single model decides timing and content" framing fits TML, not GPT-Live).

## 7. Constrained decoding (doc 07)

Audit corrections: the speed claim is withdrawn (see §1); the accuracy-parity arm was +31 % slower; whitespace-tolerant arms ranged −8.6 % to +29 %; all arms ran 48 fixed steps on one canvas; the Sudoku collapse is not evidence about masking (every constrained variant collapsed) — the clean anti-mask evidence is BFCL `mask-sample` (schema-valid 0.300); |S| = 59 excludes the 11 header states (~72 with them, bucket 128); README line/test counts are stale (9,561 impl / 19,450 test lines; ~598 test functions); the random-token emission fact is JAX-only; the header grammar `100·Σ_name{1,8}·107·101` is the *empty thought block of non-thinking mode* — a thinking-mode thought with content is outside the language, which conflicts with "tool calling works best in thinking mode"; `b_L` needs `R = min(max_tokens − emitted, max_model_len headroom) − canvas_length` per block; the complement-cancellation defect triggers on confident tokens inside a negated class's stored set, not "narrow classes"; SPEC §3.7's constrained-SC variant was never built. Length bounding: the stop criterion averages entropy over **all** 256 positions and checks argmax stability over all positions (vLLM and HF), pad is not special, `max_tokens` never shrinks the canvas — so a deterministic tail *does* lower the criterion; but stock short answers already stop in 3–5 steps, the lever exists only when the model intends a long answer, under J0 nothing changes the step count, and a `{EOS, pad}` tail (0.69 nats/position) exceeds the 1.28-nat budget — the tail must be pad-only. `length_bounded(N)` is a 3-state automaton with per-position edge masks, not N+2 states. Tool-call grammars: 3 tools × 2 args ≈ 70–85 states; 5 × 4 ≈ 200–250 (too expensive live). Port: ~470 executable JAX lines → 700–900 torch, plus 400–600 plugin lines; `reference.py` ports for free; `associative_scan`/`donate_argnums` are not used; ship max-plus MAP (fp32-safe) first because the sum-product path is fp64-only and the 5090's fp64 rate is 1/64. The decisive length experiment (transformers, one afternoon) is in doc 07 §5.

## 9. Decisions for James (scope and architecture) — **taken on 2026-09-12**

The devil's-advocate and architecture reviewers converged on a smaller v1. James accepted items 1–6 (browser-tab-first perception as *sequencing*: native daemon in M2+), confirmed D11 (thinking always on), and the docs now reflect them. Kept here as the record of what was proposed.

1. **Start the Conductor from Unmute's `unmute_handler.py` (651 lines: pause-probability end-of-turn, interrupt-on-STT-while-speaking, vLLM streaming, word rechunking) rather than from scratch**, keeping our pure turn machine as the module that replaces its logic once we iterate on turn policy. Vision, perception and memory are additive there. Pipecat is the alternative if we go CPU-STT + smart-turn (it has Pocket TTS, Silero, smart-turn and image frames; no Kyutai STT service).
2. **v1 perception as a browser tab (`getDisplayMedia` → JPEG at 1 fps over the existing WebSocket)**, with the portal + CPU-GStreamer path as M2+ and CUDA interop only if a measured need appears.
3. **Memory-lite**: SQLite + FTS5 with `(ts, jpeg, title)` on scene change and DiffusionGemma writing caption+OCR paragraphs when idle; attach top-3 JPEGs for the brain to re-read; embeddings only if recall fails.
4. **Plain web page, not Tauri**, for the HUD (`chromium --app=…`, kept above by a KWin rule).
5. **L1 + fillers for v1**; owner check, wake word, assistant backchannels after barge-in works on speakers.
6. **Both subprojects after the demo video exists.** Constrained decoding first if one (it is the diffusion-specific trick and the oracle exists), starting with `length_bounded(N)` at |S| ≤ 128; dual-branch gets one evening (the AR-mode remap + B14).
7. **Show what diffusion buys**: a split HUD (spoken summary | full artifact | tok/s meter), a "think first at 700 tok/s" scene, an "explain and rewrite this function" scene, and a side-by-side with Gemma 4 12B (audio-native, AR, ~7–8 GB), which would otherwise win every latency metric.
