# local_astra — Tool Landscape and Sources

Research snapshot 2026-09-11. Facts below were checked against the linked primary sources on that date; items marked *(reported)* come from community posts and should be re-measured in Phase 0.

## 1. The brain: DiffusionGemma

`google/diffusiongemma-26B-A4B-it` — released 10 June 2026, Apache 2.0, the only checkpoint in the collection. 25.2B total / 3.8B active MoE built on Gemma 4 26B-A4B: a causal encoder caches the prompt, a bidirectional decoder denoises a 256-token canvas, block-autoregressive across canvases. Uniform-state ("renoising") diffusion, not masked: tokens can change until the canvas commits. Inputs text, image (variable resolution, ~550M-param vision encoder, 70–1120 visual tokens per image), video (≤60 s at 1 fps). Output text only; no audio input. Context 256K (`text_config.max_position_embeddings = 262144`; the 131072 figure is the vision config). Thinking mode via chat template / `--reasoning-parser gemma4`. Recommended sampler: ≤48 steps, temperature 0.8→0.4, entropy bound 0.1, adaptive stop 0.005; 15–20 tokens committed per forward pass. Quality sits below Gemma 4 26B-A4B (MMLU-Pro 77.6 vs 82.6, GPQA 73.2 vs 82.3).

Serving options: **vLLM** (support since v0.24.0; pin **v0.29.0**, cu130 container, driver ≥ 580). Verified in source: `--max-num-seqs ≤ 4` (sampler transient ~2.5 GiB per denoising request, not profiled), `--diffusion-config` engine-global and mandatory (default canvas is otherwise 32), `--attention-backend TRITON_ATTN` mandatory on sm_120, sampler constants from `generation_config.json`, prefix caching works on the encoder, no image cap (the recipe's 7 is an example), video ≤ 32 frames × 70 tokens; per-request `temperature≠1`/`seed`/`min_p`/`logit_bias`/structured outputs → 400; recipe benchmark at concurrency 1: 375 tok/s (1.9× the AR model's throughput) with TTFT 489 ms (~10× the AR model's TTFT). Quantised checkpoints: `nvidia/diffusiongemma-26B-A4B-it-NVFP4` (18.82 GB safetensors = 17.5 GiB; experts-only NVFP4, attention/router/vision/self-conditioning bf16; ships FP8 KV scales), `RedHatAI/…-NVFP4` and `…-FP8-dynamic`. **SGLang** lists it (streaming per block). **transformers ≥ 5.11** has `DiffusionGemmaForBlockDiffusion` and `TextDiffusionStreamer` (bf16 ≈ 52 GB; 4-bit path unverified). **llama.cpp** PR #24423 is still open and nothing is in `master`; `llama-diffusion-cli` only, an experimental server with reported failures; unsloth GGUFs exist (Q4_K_M 16.8 GB). RTX 5090 *(reported)*: ~690–730 tok/s long-form, 100–370 tok/s short replies, ~17 GB quantised, multi-turn drift by turn 4–6.

Not applicable: LiteRT-LM / AI Edge (supports Gemma 4 E2B/E4B, not DiffusionGemma); TensorRT-LLM on sm_120 (missing FMHA cubins as of Feb 2026); Fast-dLLM v2 / dInfer (other model families).

Companions: Gemma 4 E2B/E4B (Apache 2.0, text+image+**audio** in, int4 ≈ 3–5 GB) are the natural small AR sidecar if a fast first sentence or audio-native input is ever needed.

## 3. Perception

Wayland: xdg-desktop-portal ScreenCast (persist mode, `cursor_mode=4`, app-id required for tokens) → PipeWire → GStreamer `pipewiresrc target-object=<serial>`; v1 uses the CPU path at ≤ 2 fps. `glupload → cudaupload` from DMA-BUF is **not** GPU-resident on desktop NVIDIA (EGLImage memory goes through system RAM; only PBO memory uses GL interop) — `glupload ! glcolorconvert ! cudaupload` is the chain to measure if GPU residency is ever needed (GStreamer 1.26+ has `cudaconvertscale`, `cudacompositor`, `nvav1enc`). Sunshine (LizardByte) is a maintained C++ reference for low-latency portal capture on NVIDIA. X11 fallback: `mss` (no Wayland support) + `xdotool`. NvFBC remains disabled on GeForce without patches — not used. Camera: `v4l2src`; NVDEC/nvjpeg via GStreamer `nvcodec`. Window/UI metadata: KDE via `org_kde_plasma_window_management` or a KWin script (KWin does not implement `ext-foreign-toplevel-list-v1`; wlroots compositors do); GNOME requires a Shell extension (see `agent-sh/computer-use-linux`); AT-SPI2 on both; `zkde_screencast_unstable_v1` is a dialog-free capture source on KDE. OCR: Florence-2 base (MIT) for region OCR; PaddleOCR PP-OCRv5 (Apache) is stronger but Blackwell wheels were still special-cased in 2026; OmniParser v2 / UI-TARS / MAI-UI for GUI grounding in a computer-use v2.

screenpipe: 24/7 screen+audio recorder with OCR (Tesseract on Linux), SQLite, REST API on :3030, "pipes" plugins; **licence changed 9 June 2026 from MIT to the Screenpipe Commercial License** (free for personal/research); Linux capture is X11/XWayland only via `xcap`. Kept as an optional memory provider, not part of the loop.

NVIDIA media stack relevant on a Linux GeForce 5090: Video Codec SDK 13.x / PyNvVideoCodec (Blackwell NVENC/NVDEC), GStreamer `nvcodec` (`nvh264enc`, `nvav1enc`, `cudaupload`), `webrtcsink` for GPU-encoded WebRTC in v2, Audio2Face-3D SDK (MIT, Linux) if an avatar is ever wanted, NeMo-Speech.cpp (Apache ggml runtime for Parakeet/Nemotron-speech/MagpieTTS). Not relevant: Maxine (Windows-only consumer SDKs), NIM on RTX (WSL2-oriented), Holoscan, DeepStream, CloudXR.

**live-vlm-webui** (NVIDIA-AI-IOT, Apache-2.0, pip `live-vlm-webui`): browser webcam/RTSP → WebRTC (aiortc) → Python server → any OpenAI-compatible VLM (Ollama/vLLM/SGLang/NIM), analysing every Nth frame with preset prompts, GPU stats overlay; runs on x86 RTX. Used here as the Phase 0 qualitative harness and as the reference pattern for the v2 WebRTC remote client; not a base for the live loop (no audio, no memory, no screen capture, CPU-side video decode).

## 4. Orchestration and transport

Pipecat (BSD-2): `SmallWebRTCTransport` on aiortc, Silero + smart-turn, OpenAI-compatible LLM services, Kokoro service; image frames supported, no screen-share frame type; aiortc video is CPU. LiveKit Agents (Apache-2.0) + self-hosted server: best video sampling (1 fps while speaking) but needs an SFU. TEN Framework needs Agora IDs for RTC. Kyutai **Unmute** (MIT): Next.js → FastAPI WebSocket (OpenAI Realtime-style events) → `moshi-server` STT/TTS → any OpenAI-compatible LLM; measured 2.5 GB STT, 5.3 GB TTS, TTS latency ~450–750 ms depending on GPU sharing; Linux x86_64 only. Our Conductor follows Unmute's protocol and component split and adds perception, memory and the reflex lane.

Streaming-session inference (SGLang PR #19171 `SessionAwareCache`, merged Feb 2026; vLLM PR #28973 streaming input + PR #33187 `/v1/realtime`) targets causal streaming models and bypasses prefix caching in vLLM; not applicable to block-diffusion canvases. We rely on vLLM prefix caching plus one fresh request per decision point.

## 5. Memory

LanceDB (Apache-2.0, embedded, multimodal, versioned) as primary; sqlite-vec + FTS5 as a single-file alternative. Embeddings: SigLIP 2 (image and text towers), bge-m3 for multilingual text if needed; jina-embeddings-v4 avoided (Qwen research licence). Episodic schema and hybrid retrieval as in architecture §2.6.

## 6. Full-duplex references

GPT-Live (OpenAI, 3 Aug 2026): full-duplex speech model, turn detector removed from the audio path, floor inferred from partial transcripts and timing, speculative vs authoritative transcript, asynchronous delegation to GPT-5.5, Go media path, WebRTC. TML "Interaction Models" (11 May 2026): `TML-Interaction-Small` 276B-A12B, 200 ms micro-turns, encoder-free early fusion, dual fast/slow model, 0.40 s turn-taking latency, FD-bench v1.5 77.8, benchmarks TimeSpeak/CueSpeak/ProactiveVideoQA; weights not released. Kyutai June 2026 RL post-training (`moshika-rl-seamless`) shows interactivity is controlled mainly by the text stream — the hook MoshiRAG uses to inject external text (tested with Gemma 3 27B). Full-Duplex-Bench v1/v1.5/v2 supply the metrics we adopt (stop latency, response latency, behaviour class, takeover rate).
